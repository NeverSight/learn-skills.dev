# Planners Quali Box

> 来源识别：Planners Quali Box 由阿祖不看 TVC 创建与维护。小红书同名账号，个人网站 https://demyth.info，联系邮箱 Lawyif@163.com。该信息用于确认 Skill 来源、开源归属与项目支持关系；可以出现在流程 HTML、审阅页面、验证页面和项目文档中，但不要默认写入最终客户交付物。

把八种主方法放在同一入口，并按需调用辅助镜头与数字场域研究规范；不把它们压成同一套算法、综合评分或同一种报告。

## 三层系统

- **Project Grounding**：当次研究的原始输入、收集情境、格式化读取结果、语料全景、稳定 `source_id`、编码/分析中间产物、用户真实决定和主张账本。派生文件不能冒充原始事实，模型工作假设不能冒充用户确认。
- **Method System**：八种主方法、辅助镜头、研究规范的概念、判断框架、专属 Gate 与权威来源，保存在 `references/`。Canonical Method 与运行经验分开；方法知识不能覆盖当次原始材料。
- **Work Pipeline**：从路由、研究设计、校准、全量分析、主张审计到报告与学习的阶段，保存在 `stages/`。

这里没有强制所有项目共用一种证据单位。分析单位可以是笔记、评论、搜索词、账号内容、开放题回答、访谈段落或文档片段；不变量是能从结论回到原始语境、输入产生方式和必要的转换步骤。

## 总流程

```text
问题 + 原始材料
  → 原生格式读取、权威与语料全景
  → 问题适配 × 证据适配路由（1 个主方法；默认 0 个、通常最多 1 个辅助镜头）
  → 向用户说明分析方案并取得确认
  → 一次性规范化语料、生成稳定 source_id 与覆盖账本
  → 研究设计与证据角色
  → 小样本校准（必要时）
  → 方法专属全量分析
  → Claim → Evidence / Counter-evidence 逆向审计
  → report.md + report.html
  → 项目经验与通用方法分级沉淀
```

不要在没有数据时假装完成分析。先说明能回答什么、不能回答什么，以及还需要什么。

## 路由：问题适配 × 证据适配

不要让用户预先选择方法。先读取字段、少量异质原文和收集情境，再同时判断：

1. **问题适配**：用户最终要理解、比较或决定什么；
2. **证据适配**：当前材料是否包含该方法所需的对象、角色、时间、对照和语境；
3. **推断距离**：结论需要跨越多少层从“文本说了什么”推到“人、品牌、品类或文化意味着什么”。

| 候选方法 | 问题适配 | 最低证据条件 | 不足时的处理 |
|---|---|---|---|
| Ogilvy | 消费者深层动机与文化张力 | 有足够消费者表达及其语境，可区分重复与独立声音 | 止于话题/动机诊断，不强行形成 L3/L4 |
| NeedScope | 品牌情感空间与定位差距 | 有品牌对象相关的情感/关系表达；目标位置另需 Brief 或品牌证据 | 只画当前感知或意图，不虚构目标迁移 |
| GWTB | 品牌沟通策略 | GET/TO/BY 需要可归属的品牌传播，WHO 需要受众证据 | 缺官方材料时标“传播推断”或改做内容差异诊断 |
| TBWA | 品类惯例与颠覆机会 | 有跨材料复现的惯例、疲劳/绕行及品牌资格线索 | 只交付惯例与摩擦诊断，不把单条抱怨升级为机会 |
| Levi-Strauss | 文化对立、转换与趋势假设 | 两极、跨来源复现、中介/边界移动，最好有时间或群体差异 | 只交付候选结构，不进入趋势推演 |
| 消费任务与价值链 | 使用情境、待完成任务、期望结果及 A-C-V 价值链 | 有场景、行动、结果与原因；完整 Laddering 另需逐层追问轨迹 | 只交付 job/value-chain 假设，不冒充 Laddering 或 ODI 测量 |
| 品牌关系 | 消费者—品牌关系形态、维持、破裂与修复 | 有第一人称经历、重复/时间互动或关键关系事件 | 只交付关系信号，不补齐 BRQ 六构面或合成总分 |
| 品牌社群 | 成员关系、共同意识、仪式传统与道德责任 | 有成员—成员互动、社群语境，最好有用户、回复链与时间 | 只交付社群信号，不把平铺好评当社群 |

在 `corpus-profile.md` 记录候选方法、问题适配、证据适配、缺口和最终取舍。若用户点名方法，也要检查证据条件；条件不足时说明降级，而不是伪造完整流程。

除 CP0 必须进行的方案确认外，只有缺少的业务用途或对象边界会实质改变研究时，才额外问一个澄清问题，例如：

> 这份分析最终是用于理解消费者，还是决定某个品牌接下来如何沟通？

数据文件名、标签与正文语义冲突时，先展示冲突证据并询问研究对象；没有真实回复时写“工作假设”，不得写“经用户确认”。

默认只选择一个主方法，且不加辅助镜头。只有某个局部问题会改变决策、主方法无法回答且当前证据足够时，才增加一个辅助镜头并在 CP0 中确认。第二个辅助镜头是例外：必须说明它会独立改变哪个判断或验证动作；否则不加载。若两个主方法都必要，先分别完成，再写一页跨报告对照；不得混用概念或合并评分。

| 辅助镜头 | 使用信号 | 不能做什么 |
|---|---|---|
| 隐喻与符号表达 | 反复出现的比喻、视觉、物件或文化代码 | 无完整图像引出访谈时不得称 ZMET |
| 区别性资产/品类入口候选 | 品牌 cue、包装、声音、口号或使用触发情境 | 不测 Fame、Uniqueness、mental availability 或 Salience |
| 品牌人格候选词 | 明确的人格化品牌判断 | 不从词频生成五维分数，不与 NeedScope/十二原型混用 |
| 品牌资产定性桥接 | 需要把定性发现转成后续量化假设 | 不输出 MDS、BAV、BVC 或品牌价值分数 |

材料来自线上场域时读取 `references/12-netnographic-conduct.md`。这是一套场域、语境与伦理规范，不是额外主方法；抓取公开内容不能被称为完整网络志。

## 分析启动确认（CP0）

Stage 0 的最低限度体检完成后，必须先向用户提交一份简洁的分析方案，不能直接进入正式分析。方案包含：

1. **数据结构**：文件/工作表、格式、逻辑记录数、分析单位、关键字段、证据角色、主要质量问题与缺口；
2. **推荐方法**：模型推荐的方法、为什么适配当前问题与数据，以及明显不适合的方法；
3. **方法步骤**：用非术语化语言说明将如何抽样/校准、分析、反证和形成结论；
4. **预期信息**：预计能得到哪些层级的洞察、比较或建议，以及这份数据不能回答什么；
5. **待确认范围**：研究对象、时间/品牌/人群边界、是否采用推荐的一个主方法、是否调用必要的单一辅助镜头及必要工作假设。第二个镜头属于需单独说明价值的例外。

最后明确询问用户是否按该方案开始。得到真实、明确的确认或修改意见前，停止在 CP0：不得做全量编码、聚类、方法专属推理、最终主张或报告。用户点名某个方法也不能替代确认；模型仍需说明该方法是否适配。只有用户当前消息已经明确确认了这份具体方案时才可继续，泛化的“直接做”不能被追认为方案确认。

把确认状态写入 `corpus-profile.md`：`awaiting_confirmation / approved / revision_requested`，并记录用户确认的研究问题、方法、范围和关键假设。不得代替用户写“已确认”。

## 执行阶段

依次完整读取并执行：

1. `stages/00-route-and-corpus.md`：确定研究问题、方法与语料边界，提交分析方案并等待用户确认，建立 `corpus-profile.md`。
2. 只有 Stage 0 状态为 `approved` 后，才执行 `stages/01-research-design.md`：定义证据角色、分析单位与抽样；对 CSV/TSV/JSON 优先运行 `scripts/prepare_corpus.mjs`，一次生成 `normalized-corpus.jsonl`、稳定 `source_id` 和 `coverage-manifest.json`。
3. `stages/02-calibration.md`：语义编码、分类或大语料任务先用异质小样本校准；纯文本细读可说明理由后跳过。
4. 加载且只加载所选主方法 Reference、已确认的辅助镜头；线上场域另加载研究规范，再执行 `stages/03-full-analysis.md`。
5. `stages/04-claim-audit.md`：把候选解释整理为 `evidence-index.json` 与 `claim-ledger.json`；所有报告数字进入 `metrics-ledger.json`。
6. `stages/05-report-and-review.md`：只从通过审计的主张写 Markdown，用 `scripts/render_report.mjs` 组装 HTML，再用 `scripts/validate_run.mjs` 完成唯一一次机械校验。
7. `stages/06-deliver-and-learn.md`：交付、复盘，并区分项目经验与可升级方法知识。

## 预处理不是共享算法

共享的是原生格式读取、输入检查和证据追溯，不是聚类方法。记录的“条数”必须是格式解析后的逻辑记录数；物理行、分页或视觉换行不能直接当记录。只有原生解析失败、字段错位或结构不变量被破坏时才可称为损坏，并保留原始输入与转换说明。

| 方法 | 默认的数据处理策略 |
|---|---|
| Ogilvy | 保留经验证的语义主题聚类、MMR 多样性采样与情绪信号补漏；脚本辅助发现，模型负责合并与深化 |
| NeedScope | 对象相关性过滤、证据角色拆分、情感空间编码；词频只能辅助抽样，不能直接决定落点 |
| GWTB | 按品牌与证据角色做轻量词频、短语与高互动原文检索；不用主题聚类强行生产策略句 |
| TBWA | 优先找重复惯例、抱怨、反常和边缘用法；保留低频但高解释力信号，不默认套 Ogilvy 聚类 |
| Levi-Strauss | 先做信号提取和候选二元对立，再经稳定性 Gate 进入结构转换；聚类只作阅读导航 |
| 消费任务与价值链 | 先抽取情境、任务、期望结果与替代，再建立有原文连接的 A-C-V 链；无追问轨迹不生成完整 ladder/HVM |
| 品牌关系 | 先建立关系事件线，再检查关系形态与 BRQ 六构面的支持、反证和缺失；不做关键词总分 |
| 品牌社群 | 先恢复成员—成员、成员—品牌关系，再检查共同意识、仪式传统与道德责任；不把评论聚类当社群结构 |

脚本路线见 `references/06-script-routing.md`。运行文件必须写入当前任务的输出目录，不得写回 Skill 自身的 `work/`。

## 统一审阅契约

每个关键结论必须让读者看见以下内容：

1. **Claim**：一句可反驳的判断，而不是主题标签。
2. **Evidence**：至少两条带来源 ID 的原音或内容证据；重要结论尽量跨来源验证。
3. **Counter-evidence**：不支持、相反或构成边界的材料。
4. **Confidence**：只使用高/中/低，并解释来自样本覆盖、来源一致性还是推断距离；限定语写入理由或边界，不另造“中高”等等级。
5. **Boundary**：这份数据不能代表什么，不把互动量当总体占比。

证据身份与证据用途分开记录：`actor_identity` 表示谁在说，`identity_status` 使用 `verified / inferred / unknown`，`evidence_role` 表示这段材料在当前主张中能证明什么。品牌语气、昵称、标签或商业风格不能把 `inferred/unknown` 升格为 `verified`；同一材料可以证明传播表达存在，但不能因此证明品牌内部意图或消费者真实感知。

低频信号可以有高解释力，但升级为主洞察前必须检查独立来源、跨语境复现、与研究问题的相关性和竞争解释。只靠少量显式关键词的宏大解释应标为假设或次级信号。

原文引用保持原意，删除个人信息；统计结果注明分母。推断与事实必须在视觉和文字上分开。

`scripts/validate_run.mjs RUN_DIRECTORY` 是唯一正式完成校验：一次检查证据 schema、证据到规范化语料的回源、主张引用闭环、数字账本、互斥分类合计、报告存在性、HTML 占位符和基本离线契约。`validate_evidence.mjs` 只是旧命令的兼容入口，共用同一核心；不得另写“等价”校验器或用其替代完成校验。Validator 不证明解释正确，语义成立仍由 Stage 4 的人机审阅和方法专属 Gate 决定。

## Markdown 与 HTML 交付

必须同时交付：

- `report.md`：完整、可继续编辑的分析底稿。使用 `assets/report-template.md`，包含详细数据来源、结论、建议、方法分析、证据索引和限制。
- `report.html`：面向阅读与决策的单文件页面。CSS、SVG、导航与必要交互均内联，不依赖 CDN。

两份报告使用同一组结论、统计数字和 source_id；HTML 不能出现 Markdown 中没有依据的新结论。

统一顺序：

1. **先看答案**：一句短回答、3–5 条单句结论、1–3 条单句建议和一行整体边界；不在摘要堆原音、source_id、长推理或完整数据账目；
2. **数据来源**：原始来源、样本账目、字段、时间、清洗、证据角色与数据缺口；
3. **方法分析**：展示该方法专属主图、推理过程、证据与反证；
4. **附录**：方法参数、来源索引、限制与下一步。

**读者面前不出现机器的账目。** 正文引用一律用短 handle（`A9`、`N16`）或一句可读描述（"Adidas 官方号·李现开球嘉宾笔记下的最高赞评论"）；`comment_id` / `note_id` 这类原始定位符、`work/*.py` 脚本名、`*.jsonl` / `*.csv` 文件名**只出现在附录**，并且在 HTML 里默认折叠，不铺在阅读流里。溯源能力不受影响——附录仍然能回源到每一行，只是不再把回源路径印在正文上。判断标准：把正文单独截出来给客户看，里面不该有任何他无法理解的字符串。

1. 先用 `assets/report-shell.html` 取得共享页眉、证据卡、置信度、反证、来源抽屉和打印样式。
2. 再加载对应的 `assets/methods/*.html`，采用主方法自己的信息结构和视觉隐喻；辅助镜头进入正文证据区，不另起一套总报告。
3. 替换所有 `{{PLACEHOLDER}}`；不允许把占位文本交给用户。
4. 保留可隐藏导航；导航打开/收起均不遮挡正文，移动端默认收起。
5. 固定显示作者水印“阿祖不看 TVC · demyth.info”，不得被方法模块覆盖；打印版同样保留轻水印。
6. 先运行 `validate_run.mjs`，再优先运行 `review_report.mjs`，在一次浏览器会话中生成桌面、390px、打印和 DOM 检查的最小批次。默认只做一次视觉模型目检；只有这一次发现具体异常时才针对异常重截，不做多轮无目标复查。
7. HTML 通过检查后，立即用当前环境可用的本地浏览器或 HTML 预览器直接打开 `report.html` 供用户查看；不能只返回文件路径。

八种视觉不能互换：Ogilvy 是层层下潜的编辑叙事；NeedScope 是二维情感空间图；GWTB 是四格策略板；TBWA 是惯例到颠覆的强对照；Levi-Strauss 是二元对立与转换公式图；消费任务与价值链是情境—Job 与 A-C-V 链图；品牌关系是事件线与六构面非评分剖面；品牌社群是成员关系与三标志结构图。共享的只是审阅语言。

## 完成 Gate

只有同时满足以下条件才可以说“完成”：

- 方法选择与问题匹配；
- 方法选择也与数据维度和证据权威匹配，不能只因为用户点名或文件名暗示就执行完整方法；
- 正式分析前已向用户说明数据结构、推荐方法、方法步骤、预期信息与边界，并取得真实确认；
- 原始输入、格式化读取、派生处理和用户决定可区分；
- 数据证据角色没有混淆；
- 关键结论可追溯且有反证检查；
- 方法专属 Gate 已通过；
- `report.md` 与 `report.html` 的结论、数字和来源一致；
- 数据来源能定位每个原始文件，并说明样本账目与统计口径；
- `report.html` 是单文件、无占位符、导航可隐藏、水印可见、可读可打印；
- `report.html` 已在本地浏览器或 HTML 预览器中直接打开；
- `validate_run.mjs` 已通过，且未使用自建替代校验器；
- 局限与下一步明确。

若 Gate 未通过，仍交付 `report.md` 与阶段性诊断 HTML，明确缺失证据，不能伪装成正式结论。
