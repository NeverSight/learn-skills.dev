Decompose one requirement that bundles several independently testable capabilities into a small module table with stable ids, one-way dependencies, and a build order, approved before any spec or design is written. Use when a request names distinct capabilities with their own consumers or data (identity, billing, notifications, reporting), when acceptance criteria cluster into groups that could ship and be verified separately, or when the user asks how to architect or split a system. Do not use for a single capability; go straight to its design. Do not use to chart open decisions or split a spec into tickets; that is effort-charting.
