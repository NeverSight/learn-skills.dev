Diseñe el contrato de una API HTTP o RPC antes de implementarla: forma del recurso, un formato de error, validación de límites, paginación, nomenclatura e idempotencia correcta para las llamadas que cambian de estado. Utilícelo al crear o remodelar puntos finales, al definir los tipos de solicitud y respuesta entre un frontend y un backend o entre servicios, o cuando los reintentos, los duplicados o los tiempos de espera en una escritura requieran una respuesta deliberada. No lo utilice para una interfaz de módulo en proceso; esa es una cuestión de «seam».
