Entwerfen Sie den Vertrag einer HTTP- oder RPC-API, bevor Sie sie implementieren: Ressourcenform, ein Fehlerformat, Grenzvalidierung, Paginierung, Benennung und korrekte Idempotenz für zustandsverändernde Aufrufe. Verwenden Sie dieses Muster, wenn Sie Endpunkte erstellen oder umgestalten, die Anfrage- und Antworttypen zwischen einem Frontend und einem Backend oder zwischen Services definieren oder wenn Wiederholungsversuche, Duplikate oder Timeouts bei einem Schreibvorgang eine gezielte Antwort erfordern. Nicht für eine In-Process-Modulschnittstelle verwenden; das ist eine Frage der Nahtstellen.
