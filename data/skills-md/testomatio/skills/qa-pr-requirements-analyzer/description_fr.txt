Analysez le contexte d'une pull request (titre, description, commentaires, problèmes liés, schémas/images joints) pour comprendre l'intention d'origine, vérifier la portée par rapport au ticket lié, faire apparaître les ambiguïtés et les cas limites, et produire un résumé structuré des exigences avec des critères d'acceptation testables. Utilisez cette compétence lorsque l'utilisateur souhaite comprendre CE QUE un PR est censé faire (pas seulement quel code a changé), vérifier si le PR correspond à son ticket/tâche lié ou générer des critères d'acceptation à partir du contexte du PR/ticket plutôt qu'à partir du code.
