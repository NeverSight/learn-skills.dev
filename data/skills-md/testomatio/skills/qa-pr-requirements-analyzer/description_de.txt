Analysieren Sie den Kontext einer Pull-Anfrage – Titel, Beschreibung, Kommentare, verknüpfte Probleme, angehängte Schemata/Bilder –, um die ursprüngliche Absicht zu verstehen, den Umfang anhand des verknüpften Tickets zu überprüfen, Unklarheiten und Randfälle aufzudecken und eine strukturierte Anforderungszusammenfassung mit überprüfbaren Akzeptanzkriterien zu erstellen. Verwenden Sie diese Fähigkeit, wenn der Benutzer verstehen möchte, WAS ein PR tun soll (nicht nur, welcher Code geändert wurde), prüfen möchte, ob der PR mit dem verknüpften Ticket/der verknüpften Aufgabe übereinstimmt, oder Akzeptanzkriterien aus dem PR/Ticket-Kontext und nicht aus dem Code generieren möchte.
