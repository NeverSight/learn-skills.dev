JumpServer v4-Authentifizierung und Verbindungstokens: Duale Authentifizierung (REST-Bearer + Django-Formular-Login-jms_sessionid-Cookie), MFA/TOTP-Verarbeitung (mfa_required-Erkennung sowohl in Code- als auch in Fehlerfeldern, der Challenge-Endpunkt, automatisches TOTP von otp_secret im Vergleich zum injizierten otp_prompt-Callback), Verbindungstoken-Erstellung (SSH web_cli / SFTP web_sftp, KoKo-Port 2222, JMS-{id} Konto), HTTP-Wiederholung und Fehlerklassifizierung (401 bis AuthError, APIError mit status_code). Verwenden Sie diese Option immer dann, wenn der Benutzer Anmeldefehler, MFA-Eingabeaufforderungen, WebSocket-Ablehnungen (fehlendes Cookie), Verbindungs-Token-Fehler oder 401/APIError meldet oder Code benötigt, der sich anmeldet oder Token erstellt, auch wenn er nur „Anmeldung nicht möglich“ sagt. CLI zuerst (jms config add validiert Anmeldeinformationen); Verwenden Sie JMSSession / create_connection_token für programmatische Sitzungen.
