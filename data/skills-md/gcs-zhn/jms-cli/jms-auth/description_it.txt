Autenticazione JumpServer v4 e token di connessione: doppia autenticazione (REST Bearer + Django form-login jms_sessionid cookie), gestione MFA/TOTP (rilevamento mfa_required su entrambi i campi di codice e di errore, endpoint di sfida, TOTP automatico da otp_secret rispetto al callback otp_prompt inserito), creazione di token di connessione (SSH web_cli / SFTP web_sftp, porta KoKo 2222, account JMS-{id}), tentativi HTTP e classificazione degli errori (da 401 a AuthError, APIError con status_code). Da utilizzare ogni volta che l'utente segnala errori di accesso, richieste MFA, rifiuti WebSocket (cookie mancante), errori di token di connessione, 401/APIError o necessita di codice che acceda o crei token, anche se dice solo "impossibile accedere". Prima la CLI (jms config add convalida le credenziali); utilizzare JMSSession / create_connection_token per sessioni programmatiche.
