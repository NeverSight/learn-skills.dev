Аутентификация JumpServer v4 и токены подключения: двойная аутентификация (носитель REST + файл cookie jms_sessionid для входа в форму Django), обработка MFA/TOTP (обнаружение mfa_required как в полях кода, так и в полях ошибок, конечная точка вызова, автоматический TOTP из otp_secret по сравнению с введенным обратным вызовом otp_prompt), создание токена подключения (SSH web_cli / SFTP web_sftp, порт KoKo 2222, JMS-{id}), повторная попытка HTTP и классификация ошибок (от 401 до AuthError, APIError с status_code). Используйте всякий раз, когда пользователь сообщает об ошибках входа в систему, запросах MFA, отклонениях WebSocket (отсутствует файл cookie), ошибках токена подключения, 401/APIError или ему нужен код, который входит в систему или создает токены, даже если они говорят только «невозможно войти в систему». Сначала CLI (конфигурация jms проверяет учетные данные); используйте JMSSession/create_connection_token для программных сеансов.
