Authentification JumpServer v4 et jetons de connexion : double authentification (REST Bearer + cookie jms_sessionid de connexion au formulaire Django), gestion MFA/TOTP (détection mfa_required sur les champs de code et d'erreur, le point de terminaison du défi, TOTP automatique depuis otp_secret vs le rappel otp_prompt injecté), création de jeton de connexion (SSH web_cli / SFTP web_sftp, port KoKo 2222, JMS-{id}), nouvelle tentative HTTP et classification des erreurs (401 vers AuthError, APIError avec status_code). À utiliser chaque fois que l'utilisateur signale des échecs de connexion, des invites MFA, des rejets WebSocket (cookie manquant), des erreurs de jeton de connexion, une erreur 401/APIError ou a besoin d'un code qui se connecte ou crée des jetons, même s'il dit seulement « impossible de se connecter ». CLI d'abord (l'ajout de configuration jms valide les informations d'identification) ; utilisez JMSSession / create_connection_token pour les sessions programmatiques.
