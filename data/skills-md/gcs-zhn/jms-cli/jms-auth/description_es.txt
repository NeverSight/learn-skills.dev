Autenticación JumpServer v4 y tokens de conexión: autenticación dual (REST Bearer + cookie jms_sessionid de inicio de sesión de Django), manejo de MFA/TOTP (detección de mfa_required en los campos de código y de error, punto final de desafío, TOTP automático de otp_secret frente a la devolución de llamada otp_prompt inyectada), creación de token de conexión (SSH web_cli / SFTP web_sftp, puerto KoKo 2222, Cuenta JMS-{id}), reintento HTTP y clasificación de errores (401 a AuthError, APIError con status_code). Úselo siempre que el usuario informe fallas de inicio de sesión, solicitudes de MFA, rechazos de WebSocket (falta cookie), errores de token de conexión, 401/APIError o necesite un código que inicie sesión o cree tokens, incluso si solo dice "no se puede iniciar sesión". CLI primero (jms config add valida las credenciales); utilice JMSSession / create_connection_token para sesiones programáticas.
