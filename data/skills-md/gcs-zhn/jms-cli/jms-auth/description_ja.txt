JumpServer v4 認証と接続トークン: 二重認証 (REST ベアラー + Django フォームログイン jms_sessionid cookie)、MFA/TOTP 処理 (コードとエラー フィールドの両方での mfa_required 検出、チャレンジ エンドポイント、otp_secret と挿入された otp_prompt コールバックからの自動 TOTP)、接続トークンの作成 (SSH web_cli / SFTP web_sftp、KoKo ポート) 2222、JMS-{id} アカウント）、HTTP 再試行およびエラー分類（401 から AuthError、APIError と status_code）。ユーザーがログインの失敗、MFA プロンプト、WebSocket の拒否 (Cookie の欠落)、接続トークンのエラー、401/APIError を報告する場合、または「ログインできない」というだけの場合でも、ログインまたはトークンを作成するコードが必要な場合は常に使用します。最初に CLI (jms config add が資格情報を検証します)。プログラムによるセッションには JMSSession / create_connection_token を使用します。
