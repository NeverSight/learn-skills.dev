Backend terminale jms-cli (SSH / WebSocket): BackendType e connect(), semantica exec SSH (scadenza complessiva, recv_exit_status, stderr mai mescolato in stdout), protocollo marcatore exec WS (doppio marcatore __JMSDONE + codice di uscita __JMSRC, frame binari, drenaggio dopo ogni esecuzione), keepalive (trasporto SSH 30 secondi / frame di testo PING a livello di applicazione WS ogni 30 secondi, mai WS opcode 0x9), PTY interattivo (Ctrl+] per uscire, sincronizzazione ridimensionamento SIGWINCH) e aggiunta di nuovi backend (register_backend / AbstractTerminal / _AUTO_SEQUENCE). Da utilizzare ogni volta che exec va in timeout o si blocca, quando l'output WS analizza comportamenti anomali, le sessioni si interrompono in base al battito cardiaco, si accede a sessioni interattive, si aggiunge un backend del protocollo o si scrive codiceexecue(). Prima la CLI (jms exec/jms login); utilizzare l'API della libreria connect() per terminali incorporati.
