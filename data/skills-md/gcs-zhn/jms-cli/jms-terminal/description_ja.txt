jms-cli ターミナル バックエンド (SSH / WebSocket): BackendType および connect()、SSH 実行セマンティクス (全体の期限、recv_exit_status、stderr が stdout に混合されない)、WS 実行マーカー プロトコル (二重 __JMSDONE マーカー + __JMSRC 終了コード、バイナリ フレーム、各実行後のドレイン)、キープアライブ (SSH トランスポート 30 秒 / WS アプリケーション レベルの PING テキスト)フレームは 30 秒ごとに更新され、WS オペコード 0x9 は使用されません）、インタラクティブ PTY (Ctrl+] で終了、SIGWINCH のサイズ変更同期)、および新しいバックエンドの追加 (register_backend / Abstractterminal / _AUTO_SEQUENCE) が行われます。 exec のタイムアウトまたはハング、WS 出力解析の誤動作、ハートビートでのセッションのドロップ、インタラクティブ セッションのログイン、プロトコル バックエンドの追加、execute() コードの作成時に使用します。 CLI が最初 (jms exec / jms ログイン);組み込み端末には connect() ライブラリ API を使用します。
