backends de terminal jms-cli (SSH / WebSocket) : BackendType et connect(), sémantique d'exécution SSH (délai global, recv_exit_status, stderr jamais mélangé dans stdout), protocole de marqueur d'exécution WS (double marqueur __JMSDONE + code de sortie __JMSRC, trames binaires, drain après chaque exécution), keepalive (transport SSH 30 s / trames de texte PING au niveau de l'application WS toutes les 30 s, jamais Opcode WS 0x9), PTY interactif (Ctrl+] pour quitter, synchronisation de redimensionnement SIGWINCH) et ajout de nouveaux backends (register_backend / AbstractTerminal / _AUTO_SEQUENCE). À utiliser chaque fois que l'exécution expire ou se bloque, que l'analyse de la sortie WS se comporte mal, que les sessions s'interrompent en cas de battement de cœur, que vous vous connectez à des sessions interactives, que vous ajoutez un backend de protocole ou que vous écrivez du code exécuté (). CLI d'abord (jms exec / jms login) ; utilisez l'API de la bibliothèque connect() pour les terminaux intégrés.
