jms-cli-Terminal-Backends (SSH/WebSocket): BackendType und connect(), SSH-Exec-Semantik (Gesamtfrist, recv_exit_status, stderr wird nie in stdout gemischt), WS-Exec-Markerprotokoll (doppelter __JMSDONE-Marker + __JMSRC-Exit-Code, binäre Frames, Drain nach jeder Ausführung), Keepalive (SSH-Transport 30 Sekunden / WS-PING-Textrahmen auf Anwendungsebene alle 30 Sekunden, nie WS-Opcode 0x9), interaktives PTY (Strg+] zum Beenden, SIGWINCH-Größensynchronisierung) und Hinzufügen neuer Backends (register_backend / AbstractTerminal / _AUTO_SEQUENCE). Wird immer dann verwendet, wenn exec eine Zeitüberschreitung erfährt oder hängen bleibt, sich die WS-Ausgabeanalyse nicht richtig verhält, Sitzungen bei Heartbeat abgebrochen werden, sich interaktive Sitzungen anmelden, ein Protokoll-Backend hinzugefügt wird oder Execute()-Code geschrieben wird. CLI zuerst (jms exec / jms login); Verwenden Sie die Bibliotheks-API connect() für eingebettete Terminals.
