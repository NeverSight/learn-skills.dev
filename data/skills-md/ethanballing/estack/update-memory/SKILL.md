# Update memory

1. **Discover destinations.** Resolve the current project and governing instructions, existing memory conventions, ownership, privacy, and maintenance rules. Read only relevant records and accessible session evidence; avoid unrelated project memory. Work with existing layouts even without `.agents/` or prior workspace initialization. Use [memory policy](references/memory-policy.md) for ownership, evidence, handoffs, or conflicts.
2. **Select the delta.** Identify important new requirements, facts, corrections, accepted decisions and reasons, reusable failed approaches, progress, outputs, verification limits, blockers, and next actions. Compare against the authoritative records. Exclude already captured information, trivial chatter, secrets, unsupported conclusions, and anything the user declined to save. Finish with a small justified change set or a no-change result.
3. **Update owners.** Freshly read affected files and edit narrowly. Preserve intervening changes, evidence, and useful provenance; correct clearly superseded current wording. Create a useful supporting record only when ownership and maintenance authorization clearly allow it. Classify new records by purpose: durable conclusions, internal support, or actual user deliverables. Use justified files/directories and concise discovery routes under [memory policy](references/memory-policy.md#placement-and-discovery). Follow an established owner outside `.agents/` rather than moving it. If a necessary owner is ambiguous, report the gap and ask only when needed to proceed.
4. **Maintain continuation selectively.** When useful, refresh the established handoff, defaulting to `.agents/HANDOFF.md`. Keep focus, owner pointers, exact next action, blockers, pending decisions/approvals, and coverage limits. Update an index only when navigation changed. Detailed knowledge and task records remain authoritative; handoff is a continuation map, not a duplicate summary or transcript.
5. **Verify and report.** Reread meaningful edits against the accessible evidence, check introduced links/anchors and affected ownership rules, and inspect for unrelated changes. Briefly report changed files, saved context, unsaved conflicts/history gaps, and a useful next action. If nothing warrants persistence, state why without touching files merely to log invocation.

Capture may happen mid-task; completion is not required. Preserve governing and safety instructions: do not rewrite them without approval. Operate within existing conventions; do not audit the whole directory, relocate existing resources, scaffold or redesign the workspace, or invoke another skill as a dependency. Never automatically commit, push, merge, change Git configuration/index/tracking, execute a backlog, manage workers, compact/reset/start sessions, or close/settle a thread. Conversation-transfer `handoff` output and provider history APIs are optional and separate from durable memory.
