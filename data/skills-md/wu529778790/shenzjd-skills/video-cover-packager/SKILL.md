# Video Cover Packager

把一份视频素材（脚本/大纲/字幕/逐字稿/音频/视频）包装成所选平台可直接使用的完整发布方案：封面标题、平台标题、作品描述、平台标签，确认后再生成封面创意方向与生图。

## Overview

方法参考 [jennie-dingding-cover-packager](https://github.com/JennieWei/jennie-dingding-cover-packager)：先判断"这期内容真正值得点击的是什么"，再决定"画面怎样让观众一眼看懂"。一次只处理一期内容。

固定交付四部分：

1. **封面包装**：精简包装简报、标题推导、3 个有策略差异的封面标题、推荐分行、3-5 个创意主题方向、封面预审、平台尺寸适配。
2. **平台标题**：只为用户选择的平台生成。
3. **作品描述**：默认一套供所有所选平台共用（含 YouTube）。
4. **平台标签**：只为用户选择的平台生成。

流程：`包装简报 → 标题策略 → 封面标题 → 平台标题 → 封面主题 → 封面预审 → 作品描述 → 平台标签 → 待用户确认 → 生图 → 标题合成出成品封面`。

## When to Use

- User provides a video script/transcript/audio and wants cover titles + publish copy
- User mentions 封面包装 / 视频包装 / 发布方案 / 标题 / 标签 for one episode of content
- User wants cover art direction (creative scenes) before generating the actual cover image
- User says "给这期视频做封面标题描述标签"

**When NOT to Use:**
- Batch packaging of multiple episodes（一次只处理一期）
- 用户只想剪辑视频或做字幕（不在范围内）
- 纯文章/图文（无视频素材）的标题创作

## Core Pattern

### Step 1: 素材与平台确认

最低输入：一份本期素材 + 至少一个目标平台（小红书/抖音/视频号/B站/YouTube，可多选）。

- 缺素材时请用户提供脚本、大纲、字幕、逐字稿、音频、视频或完整说明；音频/视频无法转写时明确说明限制，不假装理解。
- 素材和平台齐全时默认直接执行（A 模式），不让追问成为阻塞；用户想控制方向可最多回答 2 个问题（给谁看/看完做什么），或提供账号资料定制语气（B/C 模式）。
- 用户已提供标题/封面时先审查，给出"保留/局部修改/重做"结论；未经允许不替换已确认内容。

### Step 2: 提炼包装简报

从素材事实中提炼，用最多 6 项展示：一句话主题、目标人群与场景、痛点/观看理由、结果/冲突/反转/证据、内容类型、最合适的用户动作。内容事实优先，账号资料只做校准。

### Step 3: 标题推导与生成

先完成推导链：`内容事实 → 独特结果 → 人群动机 → 单一点击承诺 → 主策略+备选策略 → 压缩 → 兑现检查`，再生成 3 个有真实策略差异的封面标题 + 1 个推荐 + 2-3 行分行排版 + 各平台标题。

主策略从下表选 1 个、备选 1 个，从对应公式池内部生成至少 8 个候选后淘汰：

| 策略 | 适合内容 | 代表公式 |
|---|---|---|
| 判断选择型 | A vs B、怎么选、值不值 | `[好的特质] VS [坏的特质] 如何区分`；`你到底要不要 [话题]` |
| 痛点避坑型 | 踩坑、纠错、损失 | `[领域] 这 [N] 件事千万别做`；`[不想要的结果] 的最根本原因` |
| 身份代入型 | 人群明确，"说的就是我" | `给 [一群人] 的一个忠告`；`没有 [资源]，也能 [结果]` |
| 结果清单型 | 教程、清单、可收藏 | `[结果] 的 [N] 个技巧`；`如何不 [讨厌的事] 就能 [结果]` |
| 体验反转型 | 亲测、复盘、前后变化 | `我如何在 [时间] 内 [结果]`；`从 [不想要] 到 [想要]` |
| 好奇缺口型 | 反常识、内幕、认知升级 | `[一群人] 不会告诉你的建议`；`为什么 [大家都觉得好的事] 其实有害` |
| 互动测试型 | 测一测、你是哪种 | `测测你的 [属性]`；`[N] 秒看出你是哪种 [人群]` |
| 数字锚定型 | 数据、效率、对比 | `[N] 分钟完成 [原来要 N 小时的事]`；`靠 [方法] 拿到 [数字结果]` |

只向用户展示主/备策略与所引公式的采用原因。优先选具体结果、真实反转、可视觉化的表达，不默认抓"别再……/你还在……"式泛焦虑。

### Step 4: 封面创意与预审

建立"标题承诺 → 内容功能 → 可见输入 → 人物动作 → 可见输出"的因果简报，内部发散至少 8 个方向后只展示 3-5 个。每个方向要有：一个可记住的核心视觉引擎、明确的人物角色、可见的输入—动作—输出闭环。

封面必须同时通过四项检查：

| 检查 | 问题 |
|---|---|
| 语义准确 | 画面是否表达内容真正完成的功能（而非主题名词字面具象化）？ |
| 因果可见 | 看得到输入、人物动作和输出吗？ |
| 高概念 | 是否用意外但准确的物理机制放大价值？ |
| 低视觉噪音 | 标题、核心物件、人物动作形成单一视觉流吗？ |

淘汰：无因果的相关场所、普通空间加道具、宏大写实但语义薄弱、空背景、信息堆叠。写实度不是质量等级——真人 IP 可只保持面部真实，其余按账号历史封面采用轻 3D/玩具/剪纸/舞台化表达。

### Step 5: 描述与标签

- 描述：一套精简、自然、有观看理由的通用描述，全平台共用（含 YouTube）。
- 标签：只为所选平台生成；不凑无关热词；活动标签必须用户明确提供。

### Step 6: 输出发布包

固定章节顺序：`包装简报 → 标题策略与公式 → 封面标题 → 分平台标题 → 封面主题方向 → 封面预审与核对 → 精简作品描述 → 分平台标签 → 待确认`。隐藏公式池、完整推导链、内部候选与评分过程；不输出未选平台的空章节。

### Step 7: 用户确认后生图

用户明确确认标题和主题方向后才进入生图。固定真人 IP 先执行清晰人脸参考图闸门（参考图必须真实传入图片工具，做不到时说明限制）；无固定 IP 可直接生成。生成后按预审清单质检。

### Step 8: 标题合成出成品封面

AI 生图模型渲染中文易出乱码，封面文字**一律后期合成**，不让模型直接画字：

1. 生图 prompt 强制"无文字无水印"，底图顶部预留标题空间（主体居中偏下）。
2. 底图质检通过后，用 skill 自带脚本把确认的标题合成上去：

**同方向差异化**：生图 prompt 不允许原样复用上一次的文本。同一创意方向再次生图时，必须轮换至少两个视觉变量——构图（居中/三分法/对角线/特写/远景）、视角（平视/俯视/微仰）、光线（清晨柔光/午后高光/黄昏暖光/室内布光）、背景时代或材质（舞台/轻 3D/剪纸拼贴/玩具广告）——使同方向的多次生成在保留核心视觉引擎的前提下呈现明显差异。

```bash
python3 scripts/add-title.py --image 底图.png \
  --title "第一行|第二行" --out 成品封面.png \
  [--stroke "#E65A14"] [--fill "#FFFFFF"] [--top 0.07] [--width 0.92]
```

脚本按 Quick Reference 的排版规范自动排：标题块宽约 92%、顶部安全边 7%、描边阴影计入安全边、多行按字数分配宽度。生成后必须查看成品图再交付：标题无乱码、不被人物/物件遮挡、描边色与画面协调；描边色优先呼应底图主色（如人物服装色）。

## Quick Reference

### 调用示例

```bash
# 用户请求示例（对话中直接说，不需要真的执行命令）
使用 video-cover-packager。
平台：抖音、小红书。
方式：A，直接包装。
素材：本期字幕文件 subtitles.txt
```

### 平台规则速查

| 平台 | 标题 | 标签 | 封面 |
|---|---|---|---|
| 小红书 | 3 个，约 20 字，身份代入/低门槛/收藏理由 | 5-8 个 | 3:4 竖版 |
| 抖音 | 2 个，约 30 字，工具/冲突/效率/判断 | 4-6 个 | 3:4 封面排版优先 |
| 视频号 | 2 个，清楚稳重，适合社群转发 | 3-5 个 | 竖版（沿用 3:4） |
| B站 | 2 个，完整交代对象/方法/结论 | 3-6 个 | 16:9 横版 |
| YouTube | 2 个，保留核心搜索词，用素材主要语言 | 3-5 个强相关 | 16:9 横版 |

### 3:4 竖版两行大标题默认占比

无账号模板时：标题外轮廓宽约画布 90%-93%、高约 31%-34%；顶部安全边 6%-8%、左右各 4%-5%（从描边阴影最外缘计算）。标题配色按本期背景明暗、人物服装、核心物件动态选择，不固定色板。

### 硬性规则

- 不编造素材中不存在的数字、结果、功能、价格、背书或合作。
- 同一期视频多平台默认同一封面标题、创意主题、IP 和核心配色，只按比例重新构图（不是简单裁切）。
- 用户确认标题后锁定文字、分行、字号、位置、颜色、描边；修改时只解锁指定项。
- 真人图片只用用户本人或确认有权使用的素材。

## Common Mistakes

- **批量处理多期内容** — 本 skill 一次只包装一期；多期拆成多次任务。
- **从"画什么"开始想封面** — 先解决"为什么值得点开"（标题承诺），再决定画面机制；否则产出无语义的摆拍图。
- **把主题名词字面具象化当创意**（如"AI 工具"就画个机器人）— 画面必须表达内容完成的功能，形成输入—动作—输出闭环。
- **机械凑"稳/冲突/悬念"三个标题** — 3 个候选必须有真实策略差异，公式核心心理机制要保留，不能事后硬套。
- **输出全部内部过程** — 公式池、推导链、候选淘汰、评分是内部工作；用户只见结论与理由。
- **未经确认直接生图** — "直接给结果"≠直接生图；文字发布包与封面预审确认后才生图。
- **给未选择的平台生成空标题/标签章节** — 只输出所选平台。
- **把竖版封面直接裁成横版** — 每个平台比例需重新分配标题、人物和场景空间。
- **让 AI 生图模型直接画中文标题** — 必出乱码；生图只出无字底图，标题用 `scripts/add-title.py` 后期合成。
- **只交付底图就当完成** — 底图不是成品；标题合成、查看核验后才算交付封面。
