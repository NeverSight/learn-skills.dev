# korean-humanizer

> "AI가 쓴 한국어는 읽으면 티가 난다. 이 skill은 그 티를 걷어낸다 — 의미는 그대로 두고 표현만."

## 출력 계약

이 스킬을 호출하면 아래 형식의 Markdown 교정 결과 문서를 반환한다. `## Humanized`와 `## 주요 변경 (최대 5개)`는 결과 문서의 고정 섹션 이름이다. 첫 섹션에는 교정문 전체, 둘째 섹션에는 변경 설명을 채운다. 원문이 짧거나 변경이 없어도 이 문서 형식을 유지한다. 첫 줄은 `## Humanized`로 시작한다. 사용자가 본문만·전체 diff·다른 형식을 명시한 경우에는 그 형식으로 반환한다. 도메인이나 게시 위치 지정은 교정할 글의 맥락이며 반환 형식을 바꾸는 요청이 아니다.

**기본 포맷 (compact):**

두 제목은 `## Humanized`와 `## 주요 변경 (최대 5개)`를 그대로 사용한다. 괄호와 숫자를 생략하지 않는다.

응답을 작성할 때 먼저 `## Humanized`와 `## 주요 변경 (최대 5개)` 두 제목으로 틀을 만들고, 각 제목 아래에 교정문과 변경 설명을 채운다. 마지막에는 실제 출력의 첫 줄과 변경 목록 앞줄이 이 두 제목인지 확인한다.

````markdown
## Humanized

[다듬어진 텍스트 전체]

## 주요 변경 (최대 5개)
- "X" → "Y" (이유: 공허한 강조어 / 판에 박힌 개시 / ...)
- ...

(변경이 5개를 초과하면 마지막 줄에 "+N개 더 — '전체 diff로 보여줘'라고 하면 모두 표시" 추가)

*마음에 안 드는 변경이 있으면 알려주세요 — 되돌리거나 다시 다듬겠습니다.*
````

- 사용자가 "전체 diff로 보여줘"라고 하면 모든 변경점을 상세히 나열한다. 기본은 compact.
- 보존 판단이 중요했던 경우 `- "X" 유지 (이유: 학술 도메인 정형 표현 / 고유명사 / brand preserve)`처럼 최대 1개까지 적어도 된다. 변경·유지 설명을 합쳐 목록은 최대 5개다. 유지 설명을 덧붙이기 위해 여섯 번째 항목을 만들지 않는다.
- 같은 사용자와의 **첫 번째 응답에 한해** 템플릿의 안내를 글자 그대로 붙인다 — `*마음에 안 드는 변경이 있으면 알려주세요 — 되돌리거나 다시 다듬겠습니다.*` 두 번째 응답부터는 생략(고정 멘트 자체가 AI 티가 됨).

사용자가 본문만 또는 다른 형식을 명시하면 해당 요청을 우선한다.


## 목적

한국어 AI 생성 텍스트에는 반복적으로 나타나는 AI 티가 있다. 과도한 강조어, 공허한 형용사, 번역체, "것이다 / 이러한 / 해당" 과다, 판에 박힌 개시·마무리 문구, 불필요한 연결어, 강제된 3항 나열 같은 것들. 이 skill은 그 패턴을 찾아 **의미를 바꾸지 않고 표현만 자연스럽게** 다듬는다.

사용 대상:
- 이메일 / 메신저 / DM
- LinkedIn / X / 블로그 / 브런치 포스트
- 뉴스레터 / 고객 커뮤니케이션
- YouTube 스크립트 / 팟캐스트 원고
- 제품 카피 / 마케팅 문구
- GitHub Issue / PR / 커뮤니티 제안 답변

## 핵심 원칙

- **의미 불변.** 팩트 / 숫자 / 고유명사 / 인용문 / 링크는 절대 바꾸지 않는다. 오직 **표현**만 손본다. 행위·결과의 범위를 보존한다. 경험·시도·참여를 해결·완료·성공으로 바꾸지 않는다. 원문에 없는 신규성·순위·성과를 보태지 않는다. 추상적인 개선을 정밀도·속도·비용 같은 특정 개선 방향으로 좁히지 않는다.
- **정보량 보존.** 원문의 핵심 주장·근거·예시·조건·추정·확신을 보존한다. 중복과 장식적 표현을 덜어 문장이 짧아지는 것은 허용한다. 문자 수 비율은 검토 지표이며, 정보 보존 여부로 판단한다.
- **자연스러운 문장.** 어색한 어휘와 명사형·수동형·번역체를 평이한 한국어 문장으로 고친다. 필요하면 문장 전체를 다시 구성하고 중복 문장을 합친다. 주장 사이의 연결과 정보는 유지한다.
- **삭제보다 치환.** AI 티가 보이면 먼저 약하게 바꾸거나 자연스러운 말로 치환한다. 의미가 없는 짧은 표현은 덜어낸다. 문장 전체는 고유한 정보·감정·호흡·전환·인사·맺음 기능이 없거나 다른 문장에 그대로 남을 때만 삭제하거나 합친다. 요약·다음 행동·맺음말을 요청받았으면 그 역할을 유지한다.
- **필요한 만큼 교정.** 수정량은 고정 비율로 제한하지 않는다. 글 전체에서 어색한 표현을 찾아 자연스럽게 고친다. 문맥상 자연스러운 부분은 유지한다. 변경 개수를 채우기 위해 손대지 않는다.
- **이모지의 역할.** 이모지는 개수보다 역할로 판단한다. 제거해도 정보·감정·농담·구분 기능이 유지되면 삭제한다. 홍보·성장·성과 문장 끝의 상투적인 🚀·✨·🔥는 기본적으로 제거한다. LinkedIn이나 마케팅이라는 이유만으로 유지하지 않는다. 사용자가 유지를 요청했거나 제거하면 의도한 뉘앙스가 달라지는 경우에는 남긴다.
- **자연스러운 말투.** 원문의 개성과 친근함은 살리되 어색한 동사 결합이나 중복을 사람다운 표현으로 취급해 남기지 않는다.
- **종결어미 톤 보존 (한국어 humanize 핵심).** Raw의 종결어미(~합니다체 / ~해요체 / ~다체 / 반말)와 도메인 디폴트를 함께 본다. 발화체 도메인(YouTube / 팟캐스트 / 강의 인사말)에서는 **~다체 글말체 사용 금지**. 격식 글·캐주얼·발화체는 raw 어미를 strict 보존, 글말체 도메인(블로그/에세이/마케팅)만 ~다체 자유. 한 글에 어미가 섞이면 raw 우세 어미로 통일. 상세는 `references/ko-ai-signals.md` #9-A.
- **보존 규칙 우선.** 의미·팩트·숫자·고유명사·인용·링크·발화체 어미는 Brand voice와 개인 목록보다 우선한다. 충돌하면 해당 치환을 생략하고 이유를 알린다.
- **개인화 우선.** 사용자가 명시한 금지어 / 선호어 목록이 있으면 카탈로그보다 **먼저** 적용한다. **Brand voice profile** (방식 D, `examples/brand-voice-*.md`) 이 있으면 그보다도 더 우선.

## 워크플로우

교정 전에 스킬 루트의 `references/ko-ai-signals.md`를 실제로 읽는다. MCP 등으로 스킬 파일을 응답 본문에 받았으면 디스크에서 찾지 말고 같은 응답에 포함된 `references/ko-ai-signals.md` 내용을 읽는다. 카탈로그를 아직 읽지 않았으면 4단계로 넘어가지 않는다. 이미 같은 세션에서 읽었다면 재사용한다. 읽을 수 없으면 그 한계를 알리고 완료한 교정으로 소개하지 않는다.

### 1단계. 입력 확인

- 입력이 **한국어**인지 확인. 영어 / 다른 언어면 이 skill은 적용하지 않고 사용자에게 알린다.
- 단순 오탈자 / 문법 교정 요청이면 맞춤법 검사기(예: 부산대 맞춤법 검사기, Naver 맞춤법) 또는 별도 proofreading skill로 안내한다.
- 코드 / 기술 문서 / 법률 문서면 격식이 의도된 것이므로 적용하지 않는다.

### 1.5단계. 도메인 확인

텍스트나 사용자 지시에서 용도가 분명하면 해당 도메인과 원문 말투로 바로 진행한다. `brand=` / `금지=` / 도메인 명시가 있으면 함께 반영한다.

용도를 잘못 판단하면 의미·존댓말·보존 영역이 달라질 때만 필요한 정보를 한 번 질문한다. 확신이 낮아도 원문을 보수적으로 다듬을 수 있으면 원문 말투를 유지한다.

참고 글은 선택 사항이다. 사용자가 참고 글을 제공하면 종결어미 / 문장 길이 / 어조를 세션 범위 Brand voice로 처리한다. 참고 글이 없으면 카탈로그 기본값으로 진행하며, 제공 여부를 다시 묻지 않는다.

### 2단계. 도메인 / 톤 / 보존 영역 확인

- 확정된 도메인, 우세 종결어미, 격식 레벨을 기록한다.
- **발화체 도메인(YouTube / 팟캐스트 / 강의 / 라이브)으로 판단되면 종결어미를 절대 변경하지 않는다.** ~해요체 raw는 ~해요체로, ~합니다체 raw는 ~합니다체로 그대로 둔다. ~다체 글말체로 바꾸는 것은 이 도메인에서 금지.
- 팩트 / 숫자 / 고유명사 / 인용문 / 링크 / 제품명 / 일정 / 금액은 보존 영역으로 표시하고 건드리지 않는다.
- 시제·진행·지속·존재, 가능성·능력·허용, 부정·인과·대조·조건·예외를 파악한다. `있다·것·수·접속사`는 금지어가 아니라 검토 대상이다. 구체적인 축소·보존 기준은 카탈로그의 `간결하게 다듬는 여섯 기준`을 따른다.
- Brand voice / personal list 가 있으면 이 단계에서 먼저 적용 우선순위를 확정한다.

### 3단계. 카탈로그 로드

`references/ko-ai-signals.md` 를 읽고, 도메인 우선순위가 높은 항목부터 스캔한다. 12 카테고리:

1. 강조어 남발
2. 공허한 형용사
3. 과격식 / 번역체
4. "것이다" / "이러한" / "해당" 과다
5. 판에 박힌 개시 / 마무리
6. 수동태 / 모호한 주어
7. 불필요한 연결어
8. 과도한 parallelism / 3항 나열
9. 존댓말 레벨 불일치
10. 이모지 남발
11. 단정 회피 / 과한 hedging
12. AI 고빈도 어휘

완료 조건: 카탈로그 본문을 읽어 해당 도메인의 후보와 보존 예외를 확인했다.

GitHub Issue / 외부 제안 답변에서는 카탈로그의 감사 표현 안내도 참고한다. 교정 요청에는 원문에 없는 운영 질문이나 서비스 조건을 추가하지 않는다. 답변 작성·운영 판단까지 요청받은 경우에만 필요한 확인 질문을 별도로 한다.

### 4단계. 자연스러운 한국어로 교정

- 글 전체를 읽고 판에 박힌 시작·끝, 과한 명사형·수동형·번역체, 추상어의 연쇄를 평이한 문장으로 바꾼다. 낱말 몇 개를 치환하고 끝내지 말고, 각 문장이 실제로 읽기 편해졌는지 확인한다.
- 이미 자연스러운 표현과 의도된 전문용어는 유지한다. 카탈로그는 문맥에 맞게 적용하고, 사용자가 쓴 적 없는 경험·사례·감정은 추가하지 않는다.
- 표의 "치환 후보"는 문맥을 확인한 뒤 선택한다. 추정·가능성·조건·정도·경험의 범위를 보존한다. 원문 근거 없이 수치나 사례를 넣지 않는다. 단, 학술 / 뉴스 / 이메일처럼 격식이 필요한 도메인은 딱딱함 전체가 아니라 **불필요한 격식**만 줄인다.
- 채팅 / 리뷰 / YouTube 는 너무 매끈하게 만들지 않는다. raw 의 말투, 생략, 감정 강도는 보존한다.
- 팩트 / 숫자 / 고유명사 / 링크는 절대 변경 X.
- **삭제 후보도 먼저 보존 가능성을 확인한다:** 인사 / 마무리 / 연결어라도 도메인상 역할이 있으면 짧게 다듬어 남긴다. 예: 이메일의 감사, 뉴스레터의 인사, YouTube의 호흡용 멘트.
- **다음은 AI 티가 아니므로 제거하지 않는다:** 존칭 수식어("보내주신", "말씀하신"), 주격 조사("은/는"), 대조·양보 연결어("다만", "하지만", "그런데"), 격식 이메일의 주어 대명사("저희", "우리").

### 5단계. 의미·자연스러움 검토 후 출력

- 결과에 새로 생긴 신규성·순위·성과 표현은 원문 근거와 대조한다. 근거가 없으면 중립적인 지칭으로 바꾼다.
- 원문의 주장·근거·조건을 결과와 대조한다. 숫자·날짜·고유명사·링크·인용과 추정·확신이 유지됐는지 확인한다.
- 줄이거나 합친 부분을 원문과 대조한다. 시제·진행 상태·가능성·능력·허용·논리 관계나 글쓴이의 목소리가 달라졌거나 새 행동·감정·상황이 생겼으면 해당 교정을 되돌린다.
- 읽기 편하게 고친 뒤에도 평가의 정도·비교 범위·가능성과 실제 경험의 구분을 보존한다. 단순한 표현을 고를 때 원문에 없던 부정적 의미나 사용 경험이 생기지 않는지 확인한다. 성능·감각에 대한 강한 평가는 자연스러운 정도 표현으로 옮기며 장식적 홍보 수식과 구분한다.
- 확신의 정도, 효과·감정의 크기, 비교 우위의 정도를 구분해 보존한다. 비교 우위의 정도를 판단의 확신만 나타내는 말로 바꾸지 않는다. 확신 표현을 효과의 양으로 바꾸지 않는다. 구체적인 성능·감각·비교 평가의 강한 정도는 같은 강도의 자연스러운 표현으로 옮긴다. 예를 들어 매우 우수하다는 평가를 꽤 괜찮다는 평가로 낮추지 않는다.
- 변경 이유는 적용한 범주와 실제 수정만 설명한다. 원문 표현의 등장 횟수나 품질 점수를 숫자로 덧붙이지 않는다.

교정만 요청받은 경우 결과와 변경 설명은 원문 표현의 수정·보존에 한정한다. 원문에 없는 수신자·발송 상황·문장 혼입을 추측하거나 운영·발송 조언을 덧붙이지 않는다. 그런 조언은 사용자가 답변 작성이나 발송 판단까지 요청했을 때만 제공한다.
- 구체적인 성능·수치·위험·일정의 정도와 가능성은 보존한다. 장식적인 홍보 수식과 반복 강조는 평이하게 줄인다.
- 같은 뜻의 의무·변화 표현과 보조동사가 겹치면 단순한 동사 표현으로 정리한다. 인접 문장에서 같은 사건·요청·이유를 반복하면 한 번만 전달하도록 합치거나 역할을 나눈다. 연락 목적·불가피한 사유·양해 요청처럼 서로 다른 정보는 모두 남긴다. 단어만 달라진 반복도 확인한다.
- 변경 이유는 원문에서 확인한 정보와 실제 수정만 설명한다. 원문에 없는 상황이나 시점을 가정해 이유를 만들지 않는다.
- 전체 결과를 다시 읽는다. 조사·정도 부사·비교 표현의 결합이 자연스러운지 확인한다. 어색한 표현이 남아 있고 보존 규칙 안에서 더 자연스럽게 고칠 수 있다면 고친다.
- 짧아졌다는 이유로 군더더기를 되살리지 않는다. 정보가 빠졌다면 그 정보만 복원한다.
- 존댓말과 발화체 어미를 보존한다. 자연스러운 원문이라 변경이 없으면 본문을 유지하고 주요 변경에 변경 없음과 이유를 적는다.

교정문을 처음부터 다시 읽고, 겹치는 의무·변화 표현과 같은 사건의 반복을 정리한다. 원문과 문장별로 대조해 정보·평가의 정도·조건을 확인한 뒤, 두 제목과 변경 목록·첫 응답 안내를 앞의 출력 계약 템플릿과 대조한다. 이 검토를 마친 한 개의 최종 응답만 출력한다.

최종 응답을 작성하기 직전에 스킬 루트의 `SKILL.md`(MCP로 받았으면 받은 SKILL.md 내용)에서 `## 출력 계약`부터 `## 목적` 앞까지 다시 읽는다. 이 단계는 교정 기준을 다시 적용하기 위한 것이 아니라, 긴 카탈로그를 읽은 뒤 실제 응답 틀을 확인하기 위한 것이다. 사용자가 형식을 따로 지정하지 않았다면 그 계약의 두 제목·최대 5개 변경 목록·첫 응답 안내를 채운 응답으로 완료한다.

## 사용자 커스터마이징 (Personal List + Brand Voice)

humanize 결과를 자기 톤에 맞추려면 사용자의 금지어 / 선호어 / 유지어 목록을 활용한다. **네 가지 입력 방식**을 지원하며, 어느 쪽이든 카탈로그보다 **먼저** 적용한다.

> **방식 A/B/C 는 그때그때 즉석 입력**, **방식 D 는 영구 brand voice profile**. D 가 가장 강하고, 같은 단어가 여러 룰에 걸리면 윗줄이 이긴다 (D > A/B/C > 카탈로그).

### 방식 A. 인라인 한 줄 (가장 빠름)

사용자 메시지에 `금지=...; 선호=A→B; 유지=...` 형식이 보이면 즉시 파싱해서 적용한다.

```
/korean-humanizer 금지=활용,매우,다양한; 선호=유용하다→쓸만하다, 사실상→실제로; 유지=결과적으로

[다듬을 텍스트]
```

**파싱 규칙**:
- 키 별칭: `금지`/`ban`/`avoid`, `선호`/`prefer`, `유지`/`keep` (대소문자 무시).
- 항목 구분: 쉼표 `,` (또는 `;` / 공백). 영문 콤마와 한글 콤마 모두 허용.
- 선호 매핑: `A→B` / `A->B` / `A => B` 모두 동일하게 해석.
- 따옴표는 선택. `"활용"` 도 `활용` 도 동일.
- 같은 메시지에서 일반 자연어 본문과 섞여 있어도 첫 줄(또는 명시된 키 뒤)을 우선 파싱.

### 방식 B. 자연어 한 줄

형식이 부담스러우면 그냥 말로 지시해도 된다.

```
"활용", "매우" 빼고, "유용하다"는 "쓸만하다"로 바꿔서 다듬어줘:
[텍스트]
```

자연어로 지시받은 항목은 같은 세션 내 후속 humanize 에도 유지한다.

### 방식 C. 파일 (영구 저장)

`examples/personal-list.md`는 작성 예시이며 자동 적용하지 않는다. 개인 설정은 별도 파일에 저장하고 `personal=파일경로`로 지정한다. 지정한 파일만 읽으며, 경로는 스킬 루트 기준 상대 경로 또는 절대 경로다. MCP로 받아 스킬 루트가 없으면 상대 경로는 같은 응답에 포함된 동봉 파일로만 해석하고, 사용자 파일은 절대 경로로 읽는다. 파일을 읽지 못하면 적용하지 않았음을 알린다. SKILL.md 하단의 주석 밖 `## My personal list`에 사용자가 직접 작성한 목록도 적용한다. 주석과 예시 블록은 설정으로 취급하지 않는다.

```markdown
## My personal list
- 금지: "활용", "매우", "다양한"
- 선호: "쓸만하다" (over "유용하다"), "실제로" (over "사실상")
- 유지: (자동 치환에서 제외할 단어)
```

### 방식 D. Brand voice profile (영구 / 가장 우선)

매번 같은 *브랜드 톤* / *작가 톤* 으로 다듬고 싶으면 brand voice 프로필을 등록한다. Mode A/B/C 가 단어 리스트 위주라면, Brand voice 는 **frontmatter (preserve / ban / prefer / ending_default / emoji_policy / length_bias) + 자유 형식 톤 가이드** 로 더 풍부한 톤을 잡는다.

- 템플릿: [`examples/brand-voice-template.md`](examples/brand-voice-template.md)
- 케이스 스터디: [`examples/brand-voice-toss-style.md`](examples/brand-voice-toss-style.md) (짧고 직설), [`examples/brand-voice-essayist.md`](examples/brand-voice-essayist.md) (길고 사변)

```
/korean-humanizer brand=examples/brand-voice-toss-style.md

[다듬을 텍스트]
```

또는 자연어로:

> Toss 풍 brand voice 로 다듬어줘:
> [텍스트]

같은 세션에선 한 brand voice 만 활성화. 두 개 필요하면 별도 세션.

### 환경별 관리

- **Claude Code / OpenCode / Codex**: 네 방식 모두 사용 가능. 매 세션 인라인 한 줄 (방식 A) 권장, 영구화는 별도 파일을 만든 뒤 `personal=파일경로`로 지정 (방식 C), brand voice 는 `examples/brand-voice-<name>.md` 저장 후 호출 시 path 명시 (방식 D).
- **Agensi MCP**: 스킬 파일은 MCP 응답으로만 받고 디스크에 저장하지 않는다. 방식 A·B를 권장하고, 방식 C·D는 사용자의 절대 경로 파일이나 동봉 예시(`brand=examples/brand-voice-toss-style.md`)를 지정한다. SKILL.md 하단 `## My personal list`는 편집할 수 없다.
- **Claude.ai (Cowork)**: 세션 내 인라인 / 자연어 입력으로 즉시 반영. 영구 반영은 GitHub의 SKILL.md를 받아 편집한 뒤 재업로드(Agensi MCP로 불러온 스킬은 편집할 수 없음). Brand voice 파일도 첨부 가능.
- **ChatGPT / Cursor / Gemini**: GitHub 저장소의 `PROMPT.md` 를 system prompt / Cursor Rule 에 붙여 넣고 personal list 줄을 직접 추가하거나 매 메시지 인라인으로 지정. Brand voice 는 PROMPT.md 뒤에 brand voice 파일의 frontmatter + 본문을 그대로 이어붙이면 된다.

### 적용 순서

1. **Brand voice (방식 D)** — 영구 brand 톤. 가장 우선.
2. **Personal list (방식 A/B/C)** — 즉석 / 영구 사용자 리스트.
3. **도메인 우선순위** — 도메인 디폴트 / 금지 변경 영역 / 종결어미 톤을 먼저 반영.
4. **12 카테고리 카탈로그** — 도메인-가중치 매트릭스 (`references/ko-ai-signals.md`)에서 문맥상 어색한 표현을 자연스럽게 교정.
5. 의미·정보·말투 보존과 자연스러움을 검토한 뒤 기본 형식으로 출력.

보존 규칙 안에서 같은 단어가 여러 룰에 걸리면 윗줄이 이긴다. 예: brand voice 의 `preserve: ["딥다이브"]` 가 카탈로그의 일반 치환을 막는다.

## 다른 skill / 도구와의 연계

- **카피라이팅 skill 체이닝**: LinkedIn writer, newsletter writer 같은 생성형 skill의 **마지막 단계**에서 korean-humanizer를 호출하도록 해당 skill의 SKILL.md를 업데이트.
  - 업데이트 지시 예: "최종 출력 전 korean-humanizer skill을 실행해서 AI 티 제거"
- **fact-checker와 함께**: 외부 공개 전 권장 순서 → (1) 생성 → (2) fact-checker → (3) korean-humanizer.
- **prompt-master와 비교**: prompt-master는 *프롬프트*를 다듬고, humanizer는 *생성된 결과물*을 다듬는다.

## 트리거하지 않는 경우

- 단순 오탈자 / 문법 교정만 필요한 경우 (proofreading 도구 / skill이 적절).
- 내부 메모, 기술 문서, 코드 주석 등 자연스러움보다 정확성이 우선인 텍스트.
- 법률 / 규제 / 공식 문서 (격식이 요구됨).
- 영어 / 일본어 / 중국어 등 한국어가 아닌 텍스트.
- 사용자가 명시적으로 "원문 그대로" 요청.
