테스트 케이스를 설계하기 전에 먼저 고위험 비즈니스 경로와 필요한 검증 어서션(oracle)을 식별하십시오. 요구 사항 문서, 코드 차이점, 기존 테스트 케이스, 그리고 컨텍스트를 분석하여 재무, 권한, 상태 머신, 동시성, 비동기 동작, 데이터 일관성 등과 같은 고위험 영역을 찾아내십시오. 각 위험에 대해 businessPath, requiredAssertions, suggestedTestLayers, 그리고 coverage gap을 출력하십시오. 위험이 명확해지기 전에는 비즈니스 테스트 케이스를 작성하지 마십시오. 해당되지 않음: 비즈니스 테스트 케이스 작성, 테스트 코드 작성, 제품 코드 수정.

항상 사용자의 언어로 응답하십시오.
