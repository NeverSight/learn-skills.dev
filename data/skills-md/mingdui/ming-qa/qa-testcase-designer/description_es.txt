Después de que se complete el análisis de riesgos y antes de escribir el código de prueba, genera casos de uso empresariales en chino y espera la confirmación del usuario. Esta es la única puerta manual obligatoria en todo el proceso de QA; una vez confirmado, el caso de uso no se puede modificar. Partiendo del contexto, el análisis de riesgos y el índice de casos de uso existente, genera un test‑cases.json que contenga solo acciones empresariales (excluyendo verificaciones técnicas como Maven/compilación/instalación), genera test‑cases.html para la revisión del usuario, ejecuta una revisión cruzada de triple modelo, sintetiza los comentarios y modifica antes de enviarlo para confirmación. Después de la confirmación, promueve al repositorio de conocimiento a largo plazo. No aplicable: escribir código de prueba, ejecutar pruebas, revisión de código.
