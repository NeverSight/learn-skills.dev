La phase d'examen indépendant est l'avant‑dernière étape du processus QA. Après que le qa‑test‑runner a terminé son exécution, le code lui‑même est examiné sous un angle indépendant — en vérifiant l’architecture, la sécurité, la correction de la concurrence, la cohérence des données, le risque de régression et les lacunes de couverture des tests — sans être influencé par les conclusions de l’exécuteur. Cela génère code‑review.json (contenant des constats classés par gravité et des contraintes de disponibilité), qui, avec la porte assert‑code‑review, constitue la preuve de la revue de code, remise au qa‑report‑generator pour être intégrée dans le rapport final. Les problèmes de sécurité P0/P1, les défauts de logique financière, les vulnérabilités d’autorisations et les risques d’incohérence des données sont marqués comme bloquants. Non applicable : génération de cas de test, exécution de tests, modification du code produit (sauf demande explicite de l’utilisateur), génération du rapport.
