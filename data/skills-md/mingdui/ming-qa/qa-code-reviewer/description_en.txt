The penultimate step of the QA process is the independent review phase. After the qa‑test‑runner has finished executing, the code itself is reviewed from an independent perspective—checking architecture, security, concurrency correctness, data consistency, regression risk, and test‑coverage gaps—without being influenced by the executor’s conclusions. The output is code‑review.json (including severity‑graded findings and readiness constraints), which together with the assert‑code‑review gate constitutes the code‑review evidence, handed to the qa‑report‑generator to be incorporated into the final report. P0/P1 security issues, financial‑logic defects, permission vulnerabilities, and data‑inconsistency risks are marked as blocking. Not applicable: generating test cases, executing tests, modifying product code (unless the user explicitly requests), and report generation.
