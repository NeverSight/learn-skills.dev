將 git 工作樹的變更轉換為乾淨的 Conventional Commits：讀取 diff、執行倉庫自己的檢查、按路徑暫存、將不相關的變更拆分成獨立的提交、撰寫訊息，並驗證最終結果。使用情境：(1) 使用者想提交、保存進度、記錄 WIP 或完成已完成的任務，(2) 工作樹混雜了不相關的變更，應該成為分別的提交，(3) 某項變更破壞了既有用法，需要讓發佈工具偵測，(4) 使用者提到：commit、commit this、commit my changes、save progress、WIP commit、conventional commit、commit message、git add、staged、untracked、BREAKING CHANGE、feat!、Co‑Authored‑By、pre‑commit hook、「split this into commits」。包含保密資訊與建構輸出排除的暫存規則、`bumpv` 用來判斷 MAJOR 版本的 breaking‑change 標記、hook 與 amend 規則，以及確認提交後沒有附加歸屬資訊的檢查。適用於任何 git 倉庫與任何堆疊；倉庫自己的檢查與文件化慣例即為接合點。不是發佈工具、也不是變更日誌產生器，亦不涉及 push 或 pull request 流程。
