Transformez les changements d’un arbre de travail git en commits conventionnels propres : lisez le diff, exécutez le contrôle propre au dépôt, indexez par chemin, séparez les changements non liés en commits distincts, rédigez le message et vérifiez ce qui a été appliqué. Utilisez‑le lorsque : (1) l’utilisateur veut commit, sauvegarder sa progression, enregistrer un WIP ou finaliser une tâche terminée, (2) un arbre de travail mélange des changements non liés qui devraient devenir des commits séparés, (3) une modification casse l’usage existant et les outils de release doivent le voir, (4) l’utilisateur mentionne : commit, commit this, commit my changes, save progress, WIP commit, conventional commit, commit message, git add, staged, untracked, BREAKING CHANGE, feat !, Co‑Authored‑By, pre‑commit hook, « split this into commits ». Applique les règles d’indexation qui excluent les secrets et les sorties de build, les marqueurs de breaking‑change que `bumpv` lit pour choisir une version MAJOR, les règles de hook et d’amend, ainsi qu’une vérification post‑commit garantissant qu’aucun trailer d’attribution n’a été ajouté. Tout dépôt git et toute pile ; le contrôle propre au dépôt et les conventions documentées sont la jonction. Ce n’est pas un outil de release, ni un générateur de changelog, ni un flux de push ou de pull request.
