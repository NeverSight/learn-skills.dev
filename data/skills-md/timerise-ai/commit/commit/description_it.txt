Trasforma le modifiche in un albero di lavoro git in Conventional Commits puliti: leggi il diff, esegui il controllo specifico del repository, aggiungi al staging per percorso, separa le modifiche non correlate in commit distinti, scrivi il messaggio e verifica ciò che è stato applicato. Usa quando: (1) l'utente vuole fare commit, salvare i progressi, registrare un WIP o concludere un compito terminato, (2) un albero di lavoro mescola modifiche non correlate che dovrebbero diventare commit separati, (3) una modifica rompe l'uso esistente e gli strumenti di rilascio devono vederla, (4) l'utente menziona: commit, commit this, commit my changes, save progress, WIP commit, conventional commit, commit message, git add, staged, untracked, BREAKING CHANGE, feat!, Co‑Authored‑By, pre‑commit hook, "split this into commits". Trasporta le regole di staging che escludono segreti e output di build, i marcatori di breaking‑change che `bumpv` legge per scegliere una release MAJOR, le regole di hook e amend, e un controllo post‑commit che nessun trailer di attribuzione sia stato aggiunto. Qualsiasi repository git e qualsiasi stack; il controllo specifico del repository e le convenzioni documentate sono il punto di integrazione. Non è uno strumento di rilascio, né un generatore di changelog e né un flusso di push o pull request.
