Git 작업 트리의 변경 사항을 깔끔한 Conventional Commits 로 변환합니다: diff를 읽고, 저장소 고유의 검사를 실행하며, 경로별로 스테이징하고, 관련 없는 변경을 별도의 커밋으로 분리하고, 메시지를 작성하고, 적용된 내용을 확인합니다. 사용 상황: (1) 사용자가 커밋을 하거나 진행 상황을 저장하고, WIP를 기록하거나 완료된 작업을 마무리하고 싶을 때, (2) 작업 트리에 서로 관계 없는 변경이 섞여 있어 별도 커밋으로 나누어야 할 때, (3) 변경이 기존 사용을 깨뜨려 릴리즈 도구가 이를 인식해야 할 때, (4) 사용자가 “commit”, “commit this”, “commit my changes”, “save progress”, “WIP commit”, “conventional commit”, “commit message”, “git add”, “staged”, “untracked”, “BREAKING CHANGE”, “feat!”, “Co-Authored-By”, “pre-commit hook”, “split this into commits” 등과 같은 표현을 언급할 때. 비밀 파일과 빌드 출력물을 제외하는 스테이징 규칙, `bumpv` 가 읽어 메이저 릴리즈를 결정하는 BREAKING‑CHANGE 마커, 훅 및 amend 규칙, 그리고 커밋 후 속성 트레일러가 포함되지 않았는지 확인하는 검사를 포함합니다. 모든 Git 저장소와 모든 스택에 적용 가능하며, 저장소 자체 검증과 문서화된 규칙이 경계점(seam)입니다. 릴리즈 도구도 아니고, 체인지로그 작성기도 아니며, 푸시나 풀 리퀘스트 흐름도 아닙니다.
