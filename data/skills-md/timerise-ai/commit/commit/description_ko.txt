git 작업 트리의 변경 사항을 깔끔한 Conventional Commits 로 전환합니다: diff를 읽고, 리포지토리 고유의 검사를 실행하고, 경로별로 스테이징하고, 관련 없는 변경을 별개의 커밋으로 나누고, 메시지를 작성하며, 적용된 내용을 확인합니다. 사용 상황: (1) 사용자가 커밋하고 싶거나 진행 상황을 저장하거나 WIP를 기록하거나 완료된 작업을 마무리하려 할 때, (2) 작업 트리에서 서로 관련 없는 변경이 섞여 있어 별도 커밋이 필요할 때, (3) 변경 사항이 기존 사용을 깨뜨려 릴리즈 도구가 이를 인식해야 할 때, (4) 사용자가 다음과 같은 말을 할 때: commit, commit this, commit my changes, save progress, WIP commit, conventional commit, commit message, git add, staged, untracked, BREAKING CHANGE, feat!, Co‑Authored‑By, pre‑commit hook, “split this into commits”. 비밀 정보와 빌드 결과물을 제외하는 스테이징 규칙, `bumpv`가 읽어 MAJOR 릴리즈를 선택하도록 하는 BREAKING‑CHANGE 표식, 훅 및 amend 규칙, 그리고 커밋 후에 attribution trailer가 남지 않았는지 확인하는 검사를 포함합니다. 모든 git 리포지토리와 모든 스택에 적용 가능하며; 리포지토리 고유의 검증과 문서화된 규약이 경계점입니다. 릴리즈 도구도, changelog 작성기도, 푸시나 풀 리퀘스트 흐름도 아닙니다.
