将 git 工作区的更改转化为符合 Conventional Commits 规范的干净提交：读取 diff，执行仓库自带的检查，按路径暂存，将不相关的改动拆分为独立的提交，编写提交信息，并验证实际提交内容。适用场景：(1) 用户想要提交、保存进度、记录 WIP 或完成已完成的任务；(2) 工作区混合了不相关的更改，需要拆分为多个提交；(3) 某项改动破坏了已有用法，需要让发布工具检测到；(4) 用户提到：commit、commit this、commit my changes、save progress、WIP commit、conventional commit、commit message、git add、staged、untracked、BREAKING CHANGE、feat!、Co‑Authored‑By、pre‑commit hook、“split this into commits”。遵循的暂存规则会排除机密信息和构建产出，BREAKING CHANGE 标记会被 `bumpv` 读取用于决定 MAJOR 版本，包含钩子和 amend 规则，并在提交后检查没有出现署名尾注。适用于任何 git 仓库和任意技术栈；仓库自己的检查和文档化约定是关键切入点。它不是发布工具、也不是 changelog 生成器，更不是 push 或 pull request 流程。
