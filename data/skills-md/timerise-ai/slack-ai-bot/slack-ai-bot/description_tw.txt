在 Next.js App Router 應用中使用 Chat SDK 與 AI SDK 建立雙向 Slack AI 機器人：使用者在頻道提及或私訊機器人，LLM 會根據其應用帳號範圍的工具回應，應用程式自行在頻道張貼報告，且風險操作會放在「批准／取消」按鈕後，點擊結果會回傳給應用程式。適用情境：(1) 新增一個能回答產品資料問題並為提問使用者執行動作的 Slack 助理；(2) 應用程式必須向 Slack 推送訊息並回應按鈕點擊（人為環節審批、草稿後發送）；(3) 審核現有的 Slack 機器人，該機器人漏掉追蹤、重複回覆或無法辨識使用者；(4) 使用者提及：Slack bot、AI Slack assistant、two‑way Slack、@mention bot、app_mention、thread follow‑up、onSubscribedMessage、Slack interactivity、block_actions、Approve button、Block Kit 按鈕、response_url、Slack OAuth install、users:read.email、x‑slack‑signature、「bot 停止在串中回覆」、「無法匹配你的 Slack 帳號」、「操作逾時」等情況。具備從 Slack 電子郵件到應用使用者的身份橋接、使用者範圍的工具、可抵禦雙點擊的單次授權審批、3 秒 ack 規則、無伺服器狀態陷阱，以及 Markdown 轉 mrkdwn 的轉換器，並提供 31 個測試。Next.js App Router 可部署於 Vercel 或任何 Node 主機；store、auth、model 與 domain 工具皆為可插拔介面。此說明不是 Chat SDK 的 API 參考，也不是 Slack 頻道閱讀器。
