Build a public catalog of Agent Skills in a Next.js App Router site, generated at build time from each skill repository's own files: a sync script that mirrors SKILL.md, README.md, CHANGELOG.md, provenance.md and evals/ into the repository, a loader that reads rules, releases and the provenance ledger from them, a catalog page with search and category filter, one page per category and per skill, the agent eval results (newest run per agent and prompt, failing runs included), JSON-LD, sitemap entries and a content validator. Use when: (1) a site should list the Agent Skills an organization publishes on GitHub, with install commands, rules, versions and agent eval results, (2) skill pages show an old version after a release, or an eval run never appears on the page, (3) adding agent eval results, prompts or a provenance ledger to existing skill pages, (4) the user mentions: skills catalog, Agent Skills page, skill directory, SKILL.md, skills.sh, npx skills add, evals/prompts.md, eval results, agent evals, Claude Code, Codex CLI, Gemini CLI, skills:sync, sync.json, raw.githubusercontent.com, provenance.md, CHANGELOG.md, Keep a Changelog, TechArticle, SoftwareSourceCode. Carries a sync that reads every file of a skill at one commit and swaps the mirror in whole, a loader that never fetches, an eval parser that rejects a malformed run with its reason instead of dropping it, and a validator that fails the tests on it. Next.js App Router; where the skills come from is a seam (GitHub or local checkouts) and the section layout it reads is one table. Not a way to write a skill, not an eval runner and not a package registry.
