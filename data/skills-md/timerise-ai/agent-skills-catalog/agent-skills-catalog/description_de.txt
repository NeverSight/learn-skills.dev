Erstelle einen öffentlichen Katalog von Agent Skills in einer Next.js App‑Router‑Site, die zur Build‑Zeit aus den jeweiligen Skill‑Repository‑Dateien generiert wird: ein Sync‑Skript, das SKILL.md, README.md, CHANGELOG.md, provenance.md und evals/ in das Repository spiegelt, ein Loader, der Regeln, Releases und das Provenance‑Ledger daraus liest, eine Katalog‑Seite mit Suche und Kategoriefilter, eine Seite pro Kategorie und pro Skill, die Agent‑Eval‑Ergebnisse (der neueste Lauf pro Agent und Prompt, fehlgeschlagene Läufe eingeschlossen), JSON‑LD, Sitemap‑Einträge und einen Inhalts‑Validator. Verwende es, wenn: (1) eine Site die Agent Skills, die eine Organisation auf GitHub veröffentlicht, mit Installationsbefehlen, Regeln, Versionen und Agent‑Eval‑Ergebnissen auflisten soll, (2) Skill‑Seiten nach einem Release eine alte Version zeigen oder ein Eval‑Lauf nie auf der Seite erscheint, (3) Agent‑Eval‑Ergebnisse, Prompts oder ein Provenance‑Ledger zu bestehenden Skill‑Seiten hinzugefügt werden sollen, (4) der Benutzer Begriffe wie skills catalog, Agent Skills page, skill directory, SKILL.md, skills.sh, npx skills add, evals/prompts.md, eval results, agent evals, Claude Code, Codex CLI, Gemini CLI, skills:sync, sync.json, raw.githubusercontent.com, provenance.md, CHANGELOG.md, Keep a Changelog, TechArticle, SoftwareSourceCode erwähnt. Enthält einen Sync, der jede Datei eines Skills bei einem Commit liest und den Spiegel komplett austauscht, einen Loader, der nie fetcht, einen Eval‑Parser, der einen fehlerhaften Lauf mit seinem Grund zurückweist, anstatt ihn zu verwerfen, und einen Validator, der die Tests daran scheitern lässt. Next.js App‑Router; woher die Skills kommen, ist ein Seam (GitHub oder lokale Checkouts) und das Layout der Sektion, das er liest, ist eine Tabelle. Nicht eine Möglichkeit, einen Skill zu schreiben, kein Eval‑Runner und kein Paket‑Register.
