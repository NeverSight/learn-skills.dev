在 Next.js App Router 站点中构建一个公开的 Agent 技能目录，该目录在构建时根据每个技能仓库的文件生成：一个同步脚本将 SKILL.md、README.md、CHANGELOG.md、provenance.md 和 evals/ 镜像到仓库中，一个加载器从中读取规则、发布信息和 provenance 账本，一个带有搜索和类别过滤的目录页面，每个类别和每个技能都有单独的页面，展示代理评估结果（每个代理和提示的最新运行，包含失败的运行），以及 JSON‑LD、站点地图条目和内容校验器。使用场景：(1) 站点需要列出组织在 GitHub 上发布的 Agent 技能，包括安装命令、规则、版本和代理评估结果；(2) 技能页面在发布之后仍显示旧版本，或评估运行从未出现在页面上；(3) 为已有技能页面添加代理评估结果、提示或 provenance 账本；(4) 用户提到：skills catalog、Agent Skills 页面、skill directory、SKILL.md、skills.sh、npx skills add、evals/prompts.md、eval results、agent evals、Claude Code、Codex CLI、Gemini CLI、skills:sync、sync.json、raw.githubusercontent.com、provenance.md、CHANGELOG.md、Keep a Changelog、TechArticle、SoftwareSourceCode。实现方式包括：一次提交读取技能的所有文件并整体替换镜像的同步、从不进行网络请求的加载器、在遇到格式错误的评估运行时返回错误原因而非直接丢弃的评估解析器，以及在验证时使测试失败的校验器。Next.js App Router；技能的来源是一个接缝（GitHub 或本地检出），其读取的章节布局为单表格。此方案不涉及编写技能、评估运行器或包注册中心。
