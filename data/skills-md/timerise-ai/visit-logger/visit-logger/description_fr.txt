Enregistrez qui a ouvert quoi, d’où et sur quel appareil, côté serveur dans une application Next.js App Router : une adresse IP, une géolocalisation edge et une empreinte du navigateur analysée pour chaque véritable affichage de page d’une ressource partagée ainsi que pour les moments clés du cycle de vie (demande de lien de connexion, compte créé, connexion), stockés dans Postgres/Supabase ou Firestore, regroupés en sessions, avec des annonces de première ouverture et des panneaux d’historique administrateur. Utilisez‑le lorsque : (1) les ventes, le support ou le propriétaire doivent savoir si et quand quelqu’un a ouvert une démo, une proposition, un devis, un rapport ou un lien partagé, (2) l’on souhaite connaître le lieu et l’appareil « signé depuis » lors de l’inscription, (3) l’utilisateur évoque : journal de visites, suivi des visiteurs, journaliser les visites dans la base de données, en‑têtes de géolocalisation, x‑vercel‑ip‑city, x‑forwarded‑for, cf‑ipcountry, analyse de l’agent utilisateur, userAgent(), isBot, type d’appareil, « qui a ouvert le lien », « le client a ouvert la démo » ping Slack, historique des visites, dernière activité, lieu d’inscription. Applique le filtre de vues de page qui exclut les pré‑chargements et les Server Actions, la détection de bots pour ce que la liste du framework ne couvre pas, la correspondance de visiteurs répétés sécurisée contre NULL, le régulateur d’annonces par visiteur, des résumés honnêtes avec troncature, et le piège de première connexion Supabase. Next.js App Router sur Vercel ou Cloudflare ; le stockage est une jointure. Ce n’est pas de l’analytique produit, ni un suivi côté client, ni un gestionnaire de consentement.
