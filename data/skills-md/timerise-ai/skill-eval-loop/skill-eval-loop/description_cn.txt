强化代理技能的自动评估：将每次评估运行的结果与从代理自身日志中读取的固定保真度评分标准对照评分，针对每个偏差的根本原因修复技能，发布补丁版本，让该版本重新运行评估，并循环此过程直至所有代理获得满分。使用场景：  
1）技能的评估全部 “通过”，但代理仍对其模板进行补丁、重写测试、扩展默认值或跳过交接；  
2）技能拥有一个评估工作流，在每次发布时运行 Claude Code、Codex 和 Gemini；  
3）用户提出：基于评估修复技能、评估循环、迭代至满分、评分评估运行、评分标准、代理偏差、“根据最近评估修复技能”、 “循环至满分”、 “2:1 多数”。  

系统携带评分标准、三个代理的日志读取器、偏差根因表、发布配方和停止规则。技能仓库应包含 CHANGELOG、标记发布和 `evals/` 文件夹；使用 GitHub Actions 和 gh CLI。此方案不提供编写新技能的方式，也不改变评估框架的方式。
