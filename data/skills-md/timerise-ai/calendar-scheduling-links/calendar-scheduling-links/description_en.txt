Build self-hosted scheduling links in a Next.js App Router app: a public booking page per host and event type, weekly availability with date overrides, buffers, minimum notice, daily limits and a rolling horizon, one-on-one and group event types, Google Calendar and Microsoft 365 busy-time sync and event write-back, confirmation e-mails with an ICS invite, reminders, reschedule and cancel by a private link, signed webhooks and an embeddable widget. Use when: (1) a team wants its own Calendly-style booking pages instead of a per-seat subscription, (2) an app needs "book a time with me" links for coaches, advisors, sales or support, (3) an existing scheduling module double-books, drifts across DST, sends stale reminders or duplicates calendar events, (4) the user mentions: scheduling link, booking page, Calendly alternative, Calendly clone, Cal.com alternative, event types, availability rules, date overrides, buffer time, minimum notice, daily limit, round robin, time slots, free busy, freeBusy, calendarView, Google Calendar sync, Outlook sync, Microsoft Graph subscription, watch channel, ICS invite, METHOD:REQUEST, SEQUENCE, reschedule link, cancel link, embed widget, booking webhook, double booking, DST, exclusion constraint, btree_gist, pg_cron. Carries one pure slot engine that the page and the write both call, a per-host lock with a Postgres exclusion constraint, side effects as leased idempotent jobs, sealed OAuth tokens, signed state and channel tokens, and 53 unit tests plus a store contract run on Supabase and the Firestore emulator. Next.js App Router on Vercel; Supabase by default, Firestore behind the same SchedulingStore seam. Not payments, not team round robin in this release, not a video meeting service.
