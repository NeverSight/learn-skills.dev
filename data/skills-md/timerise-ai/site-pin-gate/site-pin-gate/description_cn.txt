在代理/中间件层为整个 Next.js 站点放置一个共享 PIN 门：通过一个环境变量启用，一个自包含的解锁页面会设置基于 HMAC 的 HttpOnly Cookie，站点本身保持不变。使用场景：(1) 预上线、测试、客户预览或投资人预览站点需要对公众和爬虫隐藏且不想添加用户账户；(2) 需要审计 middleware.ts 或 proxy.ts 中已有的 PIN 或密码门；(3) 用户提到的关键词：site PIN、password‑protect the site、access code、pre‑launch gate、coming‑soon lock、staging password、SITE_PIN、“hide the site behind a PIN”、“lock the preview deployment”、“temporary password page”。该方案携带相对于请求来源解析的返回路径、303 解锁重定向、由服务器端密钥生成的 Cookie 令牌、常数时间比较、以尝试配额限制并在超出时返回 429 并带 Retry‑After 的机制，以及管理这些的套件。适用于 Next.js App Router、proxy.ts 或 middleware.ts；尝试存储是一个接缝点，可用共享存储替代内存存储。它不是用户认证，也不是按路由的授权。
