プロキシ／ミドルウェア層から、Next.js サイト全体の前に共有 PIN ゲートを設置します。1 つの環境変数で有効化し、自己完結型のアンロックページが HMAC 派生の HttpOnly クッキーを設定するだけで、背後のアプリは一切変更しません。

### 使用シーン
1. プレローンチ、ステージング、クライアントプレビュー、投資家プレビューといったサイトを、ユーザーアカウントを増やさずに一般公開やクローラーから隠したいとき。  
2. `middleware.ts` や `proxy.ts` に既に実装されている PIN／パスワードゲートを監査したいとき。  
3. ユーザーが次のような語句で要件を表現しているとき（例: site PIN、サイトをパスワード保護、アクセスコード、プレローンチゲート、coming‑soon ロック、ステージングパスワード、`SITE_PIN`、"hide the site behind a PIN"、"lock the preview deployment"、"temporary password page"）。

### 主な機能
- リクエストのオリジンを基にしたリターンパスを保持し、アンロック成功時に **303** リダイレクトで返す。  
- サーバーサイドシークレットで生成したトークンをキーにした Cookie（HttpOnly）を発行。  
- トークン比較は定数時間で行い、タイミング攻撃を防止。  
- 試行回数に上限を設け、超過した場合は **429** レスポンスと `Retry-After` ヘッダーで応答。  
- これらを管理するテストスイートも同梱。

### 実装上の留意点
- 対象は **Next.js App Router**、`proxy.ts` または `middleware.ts`。  
- 試行情報の保存はシーム（境界）として扱われ、インメモリ実装の代わりに共有ストア（例: Redis 等）を差し替えることが可能。  
- ユーザー認証やルート単位の認可とは別概念であり、あくまでサイト全体を一時的に隠すための機構です。
