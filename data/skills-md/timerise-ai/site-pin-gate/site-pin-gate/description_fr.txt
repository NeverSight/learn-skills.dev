Mettez une porte à code PIN partagé devant l'ensemble d'un site Next.js depuis la couche proxy/middleware : une variable d'environnement l'active, une page de déverrouillage autonome définit un cookie HttpOnly dérivé d'un HMAC, et l'application derrière reste intacte. Utilisez‑le lorsque : (1) un site de pré‑lancement, de staging, d'aperçu client ou d'aperçu investisseur doit être caché du public et des robots d'indexation sans ajouter de comptes utilisateurs, (2) une porte PIN ou mot de passe existante dans middleware.ts ou proxy.ts nécessite un audit, (3) l'utilisateur mentionne : PIN du site, protéger le site par mot de passe, code d'accès, porte de pré‑lancement, verrou d'arrivée prochaine, mot de passe de staging, SITE_PIN, « cacher le site derrière un PIN », « verrouiller le déploiement d'aperçu », « page de mot de passe temporaire ». Elle transporte le chemin de retour résolu par rapport à l'origine de la requête, la redirection 303 de déverrouillage, le token de cookie indexé par un secret côté serveur, des comparaisons en temps constant, un budget de tentatives répondant 429 avec Retry‑After, et la suite qui les contient. Next.js App Router, proxy.ts ou middleware.ts ; le magasin de tentatives est une couture, de sorte qu'un magasin partagé peut remplacer celui en mémoire. Ce n’est pas une authentification utilisateur et pas une autorisation par route.
