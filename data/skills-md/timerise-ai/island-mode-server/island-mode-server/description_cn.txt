构建一个本地备用服务器，保持站点在 Firestore 中切片的实时双向 RxDB 副本，在云不可达时接管局域网终端的服务，并在重新连接后将离线工作冲刷回去。适用场景：（1）实体场所（店铺、健身房、诊所、仓库）必须在互联网中断期间继续接受预约、调动库存和切换硬件；（2）自助终端或员工 PWA 必须自行在云 API 与本地 API 之间切换；（3）现有离线服务器需要审计：重新连接时的冲刷导致库存双计数、副本停止拉取、故障转移永远找不到目标盒子；（4）用户提到的关键词：岛屿模式、离线备用服务器、LAN 故障转移、本地副本、与 Firestore 双向同步的本地服务器、“互联网断网时站点仍能运行”、replicateFirestore、rxdb/plugins/replication-firestore、serverTimestamp 检查点、_offlineCreated、_locallyModified、syncedIds、FieldValue.increment、heartbeat 定时任务、apiBaseUrl、HMAC 设备认证、island.local、avahi。实现包括三层复制架构、每次云写入所需的检查点戳、按 ID 拆分的库存增减折叠、基于客户端生成 ID 的幂等摄取、离线限制的员工令牌备用、心跳与状态链路，以及覆盖关键逻辑的 17 条 vitest 测试用例。参考实现使用 Node/NestJS 本地服务器与 Firestore 云端，并以 Next.js 路由处理器作为 API；HTTP 框架、身份提供者（IdP）和词汇表在 architecture.md 中作为可插拔点。该方案不是读取缓存、不是站点间的多主同步，也不适用于除 Firestore 之外的云数据库。
