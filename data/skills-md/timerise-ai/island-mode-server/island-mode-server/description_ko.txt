현장에 설치하는 폴백 서버를 구축하십시오. 이 서버는 사이트의 Firestore 일부를 실시간 양방향 RxDB 복제본으로 유지하고, 클라우드에 접근할 수 없을 때 LAN 단말에 서비스를 제공하며, 재연결 시 오프라인 작업을 플러시합니다. 사용 사례: (1) 물리적 현장(매장, 체육관, 클리닉, 창고)에서 인터넷 장애 중에도 예약을 받고, 재고를 이동하고, 하드웨어를 전환해야 할 때, (2) 키오스크 또는 직원 PWA가 클라우드 API와 로컬 API를 자체적으로 전환해야 할 때, (3) 기존 오프라인 서버에 감사를 수행해야 할 때: 재연결 플러시가 재고를 이중 계산하거나, 복제본이 데이터를 가져오지 않거나, 폴백이 장치를 찾지 못하는 경우, (4) 사용자가 언급한 키워드: island mode, offline fallback server, LAN failover, on‑prem replica, local server with two‑way sync to Firestore, “the site keeps working when the internet is down”, replicateFirestore, rxdb/plugins/replication-firestore, serverTimestamp checkpoint, _offlineCreated, _locallyModified, syncedIds, FieldValue.increment, heartbeat cron, apiBaseUrl, HMAC device auth, island.local, avahi. 세 가지 복제 계층, 클라우드 쓰기마다 필요한 체크포인트 스탬프, ID 별 재고 변동 접기, 클라이언트 생성 ID를 키로 하는 멱등적 인제스트, 오프라인 제한 직원 토큰 폴백, 하트비트 및 상태 체인, 그리고 신뢰가 중요한 로직을 검증하는 17개의 Vitest 테스트 스위트를 포함합니다. 레퍼런스 API로 Node/NestJS 로컬 서버와 Firestore 클라우드, 그리고 Next.js 라우트 핸들러를 사용합니다; HTTP 프레임워크, IdP, 용어 정의는 architecture.md에 명시된 접점(seam)입니다. 읽기 전용 캐시가 아니며, 사이트 간 멀티마스터 동기화도 아니고, Firestore 외의 클라우드 데이터베이스를 위한 것이 아닙니다.
