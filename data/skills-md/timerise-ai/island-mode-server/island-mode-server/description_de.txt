Erstelle einen On-Premise‑Fallback‑Server, der eine Live‑Zwei‑Wege‑RxDB‑Replik eines Teilbereichs von Firestore für einen Standort hält, bei unerreichbarer Cloud die LAN‑Terminals übernimmt und offline erstellte Arbeiten bei Wiederverbindung zurückflusssiert. Verwendung bei: (1) Ein physischer Standort (Laden, Fitnessstudio, Klinik, Lager) muss während eines Internetausfalls Buchungen entgegennehmen, Lagerbestände bewegen und Hardware schalten können, (2) Kiosk‑ oder Mitarbeitenden‑PWAs müssen eigenständig zwischen einer Cloud‑API und einer lokalen API umschalten, (3) Ein bestehender Offline‑Server benötigt Audits: ein Wiederverbindungs‑Flush, das Bestände doppelt zählt, eine Replik, die das Pullen einstellt, ein Failover, das die Box nie findet, (4) Der Nutzer nennt: Island‑Modus, Offline‑Fallback‑Server, LAN‑Failover, On‑Prem‑Replik, lokaler Server mit Zwei‑Wege‑Sync zu Firestore, „der Standort funktioniert weiter, wenn das Internet ausfällt“, replicateFirestore, rxdb/plugins/replication-firestore, serverTimestamp‑Checkpoint, _offlineCreated, _locallyModified, syncedIds, FieldValue.increment, Heartbeat‑Cron, apiBaseUrl, HMAC‑Device‑Auth, island.local, avahi. Enthält die drei Replikations‑Ebenen, den Checkpoint‑Stempel, den jeder Cloud‑Write benötigt, das pro‑ID‑Stock‑Delta‑Ausklappen, idempotente Aufnahme, die auf client‑generierten IDs basiert, das offline‑gesteuerte Mitarbeitenden‑Token‑Fallback, die Heartbeat‑ und Status‑Kette sowie einen 17‑Test‑Vitest‑Suite für die vertrauenskritische Logik. Node/NestJS‑lokaler Server und Firestore‑Cloud mit Next.js‑Route‑Handlern als Referenz‑API; das HTTP‑Framework, IdP und Vokabular sind Nahtstellen in architecture.md. Kein Lese‑Cache, kein Multi‑Master‑Sync zwischen Standorten und nicht für eine andere Cloud‑Datenbank als Firestore.
