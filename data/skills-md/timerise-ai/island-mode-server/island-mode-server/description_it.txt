Costruisci un server di fallback on‑premise che mantenga una replica RxDB a due vie in tempo reale della porzione di Firestore di un sito, che riprenda a servire i terminali LAN quando il cloud è irraggiungibile e che flussi il lavoro offline al riconnettersi. Usa quando: (1) un sito fisico (negozio, palestra, clinica, magazzino) deve continuare a prendere prenotazioni, spostare scorte e attivare hardware durante un’interruzione di internet, (2) le PWA di chiosco o del personale devono passare autonomamente da un’API cloud a un’API locale, (3) un server offline esistente necessita di audit: un flush al riconnettersi che conta due volte le scorte, una replica che smette di tirare, un failover che non trova mai la box, (4) l’utente menziona: modalità isola, server di fallback offline, failover LAN, replica on‑prem, server locale con sync bidirezionale a Firestore, “il sito continua a funzionare quando internet è giù”, replicateFirestore, rxdb/plugins/replication-firestore, checkpoint serverTimestamp, _offlineCreated, _locallyModified, syncedIds, FieldValue.increment, cron di heartbeat, apiBaseUrl, autenticazione dispositivo HMAC, island.local, avahi. Include i tre livelli di replica, il timbro di checkpoint richiesto da ogni scrittura cloud, il fold‑out per il delta di stock per ID, l’ingestione idempotente indicizzata da ID generati dal client, il fallback del token staff soggetto a offline, la catena di heartbeat e status, e una suite di 17 test vitest per la logica critica di fiducia. Server locale Node/NestJS e Firestore cloud con gestori di route Next.js come API di riferimento; il framework HTTP, IdP e vocabolario sono i punti di integrazione in architecture.md. Non è una cache di lettura, non è sync multi‑master tra siti, e non è destinato a un database cloud diverso da Firestore.
