Создайте локальный резервный сервер, который поддерживает живую двухстороннюю реплику RxDB части Firestore сайта, берёт на себя обслуживание LAN‑терминалов, когда облако недоступно, и сбрасывает офлайн‑работу обратно при восстановлении соединения. Используйте, когда: (1) физический объект (магазин, спортзал, клиника, склад) должен продолжать принимать бронирования, перемещать товар и управлять оборудованием во время интернет‑отключения, (2) киоски или PWA для персонала должны автоматически переключаться между облачным API и локальным API, (3) существующий офлайн‑сервер нуждается в аудите: сброс при повторном подключении, который удваивает учёт товара, реплика, которая перестаёт вытягивать данные, отказ, который никогда не находит коробку, (4) пользователь упоминает: режим острова, офлайн‑резервный сервер, LAN‑отказ, локальная реплика, локальный сервер с двусторонней синхронизацией с Firestore, «сайт продолжает работать, когда интернет выключен», replicateFirestore, rxdb/plugins/replication-firestore, checkpoint serverTimestamp, _offlineCreated, _locallyModified, syncedIds, FieldValue.increment, heartbeat‑cron, apiBaseUrl, HMAC‑аутентификация устройства, island.local, avahi. Включает три уровня репликации, маркер контрольной точки, необходимый для каждой записи в облаке, разборку изменения количества товара по каждому ID, идемпотентную загрузку, ключируемую клиентскими ID, резервный токен персонала, ограниченный офлайн, цепочку heartbeat и статуса, а также 17‑тестовый набор vitest для критически важной логики. Node/NestJS локальный сервер и Firestore‑облако с обработчиками маршрутов Next.js в качестве эталонного API; HTTP‑фреймворк, IdP и словарь являются швами в architecture.md. Не кэш чтения, не мульти‑мастер синхронизация между сайтами и не для облачной базы данных, отличной от Firestore.
