Construye un servidor de respaldo on‑premise que mantenga una réplica RxDB bidireccional en vivo de la porción de Firestore de un sitio, tome el control de los terminales LAN cuando la nube no sea accesible y envíe de vuelta el trabajo offline al reconectar. Úsalo cuando: (1) un sitio físico (tienda, gimnasio, clínica, almacén) debe seguir aceptando reservas, moviendo stock y controlando hardware durante un corte de internet, (2) los PWAs de kiosco o del personal deben alternar entre una API en la nube y una API local por sí mismos, (3) un servidor offline existente necesita auditoría: un “flush” al reconectar que duplica el conteo de stock, una réplica que deja de extraer datos, un failover que nunca encuentra la caja, (4) el usuario menciona: modo isla, servidor de respaldo offline, failover LAN, réplica on‑prem, servidor local con sincronización bidireccional a Firestore, “el sitio sigue funcionando cuando internet está caído”, replicateFirestore, rxdb/plugins/replication-firestore, marca de tiempo serverTimestamp checkpoint, _offlineCreated, _locallyModified, syncedIds, FieldValue.increment, cron de heartbeat, apiBaseUrl, autenticación HMAC de dispositivo, island.local, avahi. Lleva los tres niveles de replicación, el sello de checkpoint que necesita cada escritura en la nube, el pliegue de delta de stock por ID, ingestión idempotente basada en IDs generados por el cliente, el token de personal fallback gated offline, la cadena de heartbeat y estado, y una suite de 17 pruebas vitest para la lógica crítica de confianza. Servidor local Node/NestJS y nube Firestore con manejadores de rutas Next.js como API de referencia; el framework HTTP, IdP y vocabulario son puntos de extensión en architecture.md. No es una caché de lectura, no es sincronización multi‑master entre sitios, y no es para una base de datos en la nube distinta de Firestore.
