Construye una integración de correo de InboxParse en una aplicación Next.js con App Router: un cliente tipado solo del lado del servidor para la API V1, un receptor de webhook firmado, una sincronización programada que almacena cada correo, haya llegado o no un webhook, y respuestas enviadas solo después de que una persona apruebe el texto exacto. Úsalo cuando: (1) una aplicación necesite recibir, almacenar, buscar o responder correos de buzones Gmail o IMAP conectados a InboxParse, (2) al añadir o auditar un endpoint de webhook de InboxParse, trabajo de sincronización o flujo de envío y respuesta, (3) al alimentar el correo a una función de IA sin permitir que el autor del correo lo controle, (4) al llamar directamente a la API de InboxParse para correos, hilos, búsqueda, buzones, etiquetas, contactos, webhooks o uso, (5) el usuario menciona: InboxParse, inboxparse.com, API de correo, email-to-LLM, parsear correos, webhook de correo, X-InboxParse-Signature, whsec_, ip_ API key, INBOXPARSE_API_KEY, email.received, email.ai_processed, ai.suggested_response, /api/v1/emails, rate_limit_exceeded. Incluye los hechos que la referencia de la API omite, verificados contra la implementación: las entregas llevan IDs, nunca el correo, se reintentan hasta 5 veces y se desactiva la suscripción después de 10 fallos; la firma cubre el cuerpo crudo sin marca de tiempo; el cursor de listado pagina únicamente por sent_at. Next.js App Router; la interfaz InboxStore es la unión, por lo que Postgres, Supabase o Firestore mantienen el estado. No es un servidor de correo, no es una UI de cliente de correo, y no es el servidor MCP de InboxParse.
