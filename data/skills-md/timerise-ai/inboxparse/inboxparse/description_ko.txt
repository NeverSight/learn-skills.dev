Next.js App Router 앱에서 InboxParse 이메일 통합을 구축합니다: V1 API용 타입이 지정된 서버 전용 클라이언트, 서명된 웹훅 수신기, 웹훅 도착 여부와 관계없이 모든 이메일을 저장하는 스케줄된 동기화, 그리고 정확한 텍스트가 담당자에 의해 승인된 후에만 전송되는 회신 기능을 포함합니다. 사용 사례: (1) 앱이 Gmail 또는 IMAP 메일함에서 InboxParse와 연결된 이메일을 수신, 저장, 검색 또는 답변해야 할 경우, (2) InboxParse 웹훅 엔드포인트, 동기화 작업 또는 전송·회신 흐름을 추가하거나 감시할 경우, (3) 이메일 작성자가 흐름을 좌우하지 않도록 이메일을 AI 기능에 전달해야 할 경우, (4) 이메일, 스레드, 검색, 메일함, 라벨, 연락처, 웹훅 또는 사용량에 대해 InboxParse API를 직접 호출해야 할 경우, (5) 사용자가 다음을 언급할 때: InboxParse, inboxparse.com, email API, email-to-LLM, parse emails, email webhook, X-InboxParse-Signature, whsec_, ip_ API key, INBOXPARSE_API_KEY, email.received, email.ai_processed, ai.suggested_response, /api/v1/emails, rate_limit_exceeded. API 레퍼런스에 누락된 사실을 구현과 대조하여 반영합니다: 배달은 이메일 자체가 아닌 ID를 포함하고, 최대 5회 재시도되며 10번 실패 시 구독이 비활성화됩니다; 서명은 타임스탬프 없이 원본 본문을 커버합니다; 리스트 커서는 sent_at만을 기준으로 페이지를 구분합니다. Next.js App Router; InboxStore 인터페이스가 경계 역할을 하므로 Postgres, Supabase 또는 Firestore가 상태를 보관합니다. 이는 메일 서버도 아니고, 이메일 클라이언트 UI도 아니며, InboxParse MCP 서버도 아닙니다.
