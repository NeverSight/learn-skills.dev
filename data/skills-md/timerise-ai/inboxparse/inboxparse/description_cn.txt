在 Next.js App Router 应用中构建 InboxParse 邮件集成：为 V1 API 提供类型化的仅服务器端客户端、签名的 webhook 接收器、定时同步（无论 webhook 是否到达都存储每封邮件），以及仅在人员批准确切文本后才发送的回复。使用场景：(1) 应用必须接收、存储、搜索或回复来自 Gmail 或已连接 InboxParse 的 IMAP 邮箱的邮件；(2) 添加或审计 InboxParse webhook 端点、同步任务或发送与回复流程；(3) 将邮件输入 AI 功能且不让邮件作者控制；(4) 直接调用 InboxParse API 获取邮件、线程、搜索、邮箱、标签、联系人、webhook 或使用情况；(5) 用户提及：InboxParse、inboxparse.com、email API、email-to-LLM、parse emails、email webhook、X-InboxParse-Signature、whsec_、ip_ API key、INBOXPARSE_API_KEY、email.received、email.ai_processed、ai.suggested_response、/api/v1/emails、rate_limit_exceeded。包括 API 文档未提及但经实现验证的事实：投递携带 ID，永不携带邮件内容，最多重试 5 次，失败 10 次后禁用订阅；签名覆盖原始 body 且不包含时间戳；列表游标仅基于 sent_at 分页。使用 Next.js App Router；InboxStore 接口是关键接点，状态由 Postgres、Supabase 或 Firestore 保存。不是邮件服务器，也不是邮件客户端 UI，更不是 InboxParse MCP 服务器。
