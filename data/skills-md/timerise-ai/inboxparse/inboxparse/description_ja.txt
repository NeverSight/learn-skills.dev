Next.js App Router アプリで InboxParse メール統合を構築します：V1 API 用の型付けされたサーバー専用クライアント、署名付き Webhook 受信者、Webhook が届いたかどうかにかかわらずすべてのメールを保存するスケジュール同期、そしてテキストが本人に承認された後にのみ送信される返信。使用シナリオは次の通りです。(1) アプリが Gmail や IMAP のメールボックス（InboxParse に接続）からメールを受信、保存、検索、または返信する必要があるとき、(2) InboxParse の Webhook エンドポイント、同期ジョブ、送信・返信フローを追加または監査するとき、(3) メールの送信者が制御できない形でメールを AI 機能に渡すとき、(4) メール、スレッド、検索、メールボックス、ラベル、連絡先、Webhook、使用量などに直接アクセスするために InboxParse API を呼び出すとき、(5) ユーザーが以下の用語を言及したとき：InboxParse、inboxparse.com、email API、email-to-LLM、parse emails、email webhook、X-InboxParse-Signature、whsec_、ip_ API key、INBOXPARSE_API_KEY、email.received、email.ai_processed、ai.suggested_response、/api/v1/emails、rate_limit_exceeded。API リファレンスに記載されていない事実を実装と照合しながら保持します：配信はメール本体ではなく ID を保持し、最大 5 回再試行し、10 回失敗した後にサブスクリプションを無効化します；署名はタイムスタンプなしで生のリクエストボディ全体をカバーします；リストカーソルは sent_at のみでページングします。Next.js App Router を使用し、InboxStore インターフェースがシームとなるため、状態は Postgres、Supabase、または Firestore に保持されます。メールサーバーでもメールクライアント UI でもなく、InboxParse MCP サーバーでもありません。
