Next.js の App Router アプリで InboxParse メール統合を構築する: V1 API 用の型付けされたサーバー専用クライアント、署名付き webhook 受信機、Webhook の有無に関わらずすべてのメールを保存するスケジュール同期、そして正確なテキストが担当者に承認された後にのみ送信される返信。使用シーン: (1) アプリが Gmail や IMAP のメールボックス（InboxParse に接続）からメールを受信、保存、検索、または応答する必要があるとき、 (2) InboxParse webhook エンドポイント、同期ジョブ、送信・返信フローの追加または監査を行うとき、 (3) メールの送信者が結果を操作できないようにしつつ、メールを AI 機能に供給したいとき、 (4) メール、スレッド、検索、メールボックス、ラベル、連絡先、webhook、使用状況などに直接 InboxParse API を呼び出すとき、 (5) ユーザーが言及するキーワード: InboxParse、inboxparse.com、email API、email-to-LLM、parse emails、email webhook、X‑InboxParse‑Signature、whsec_、ip_ API キー、INBOXPARSE_API_KEY、email.received、email.ai_processed、ai.suggested_response、/api/v1/emails、rate_limit_exceeded。API 参照に記載されていない事実を伝える（実装と照合済み）: 配信はメール本体ではなく ID を持ち、最大 5 回リトライされ、10 回失敗すると購読が無効化される；署名はタイムスタンプなしで生のリクエストボディ全体をカバーする；リストカーソルは sent_at のみでページングする。Next.js App Router を使用し、InboxStore インターフェースがシーム（境界）となるため、PostgreSQL、Supabase、Firestore のいずれかで状態を保持する。メールサーバーでもメールクライアント UI でもなく、InboxParse の MCP サーバーでもないことに注意。
