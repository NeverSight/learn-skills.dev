Construisez une intégration d’email InboxParse dans une application Next.js App Router : un client serveur‑only typé pour l’API V1, un récepteur de webhook signé, une synchronisation planifiée qui stocke chaque email que le webhook soit arrivé ou non, et des réponses envoyées uniquement après qu’une personne ait approuvé le texte exact. Utilisez‑la quand : (1) une appli doit recevoir, stocker, rechercher ou répondre à des emails depuis Gmail ou des boîtes IMAP connectées à InboxParse, (2) ajouter ou auditer un point de terminaison webhook InboxParse, une tâche de synchronisation ou un flux d’envoi et de réponse, (3) alimenter un email dans une fonctionnalité IA sans laisser l’auteur de l’email le diriger, (4) appeler directement l’API InboxParse pour les emails, threads, recherche, boîtes aux lettres, labels, contacts, webhooks ou usage, (5) l’utilisateur mentionne : InboxParse, inboxparse.com, API email, email‑to‑LLM, parse emails, email webhook, X‑InboxParse‑Signature, whsec_, ip_ API key, INBOXPARSE_API_KEY, email.received, email.ai_processed, ai.suggested_response, /api/v1/emails, rate_limit_exceeded. Porte les faits que la référence d’API laisse de côté, vérifiés contre l’implémentation : les livraisons portent des IDs, jamais l’email, sont retentées jusqu’à 5 fois et désactivent l’abonnement après 10 échecs ; la signature couvre le corps brut sans horodatage ; le curseur de liste pagine uniquement sur sent_at. Next.js App Router ; l’interface InboxStore est la jonction, donc Postgres, Supabase ou Firestore détient l’état. Ce n’est pas un serveur de messagerie, pas une UI client email, et pas le serveur MCP d’InboxParse.
