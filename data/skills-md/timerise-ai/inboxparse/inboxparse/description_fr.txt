Construisez une intégration d’e‑mail InboxParse dans une application Next.js App Router : un client typé uniquement serveur pour l’API V1, un récepteur de webhook signé, une synchronisation planifiée qui stocke chaque e‑mail qu’un webhook soit arrivé ou non, et des réponses envoyées uniquement après qu’une personne ait approuvé le texte exact. Utilisez‑la lorsque : (1) une application doit recevoir, stocker, rechercher ou répondre à des e‑mails provenant de Gmail ou de boîtes IMAP connectées à InboxParse, (2) vous ajoutez ou auditez un point de terminaison webhook InboxParse, un job de synchronisation ou un flux d’envoi et de réponse, (3) vous alimentez une fonctionnalité IA avec des e‑mails sans laisser l’auteur de l’e‑mail le diriger, (4) vous appelez directement l’API InboxParse pour les e‑mails, les fils de discussion, la recherche, les boîtes aux lettres, les libellés, les contacts, les webhooks ou l’usage, (5) l’utilisateur mentionne : InboxParse, inboxparse.com, API e‑mail, email‑to‑LLM, parse emails, webhook e‑mail, X‑InboxParse‑Signature, whsec_, clé API ip_, INBOXPARSE_API_KEY, email.received, email.ai_processed, ai.suggested_response, /api/v1/emails, rate_limit_exceeded. Fournit les faits que la référence de l’API omet, vérifiés par rapport à l’implémentation : les livraisons portent des IDs, jamais l’e‑mail complet, sont retentées jusqu’à 5 fois et désactivent l’abonnement après 10 échecs ; la signature couvre le corps brut sans horodatage ; le curseur de liste pagine uniquement sur sent_at. Next.js App Router ; l’interface InboxStore est le point d’attache, ainsi Postgres, Supabase ou Firestore conservent l’état. Ce n’est pas un serveur de messagerie, ni une interface client e‑mail, ni le serveur MCP d’InboxParse.
