Создайте интеграцию электронной почты InboxParse в приложении Next.js с App Router: типизованный клиент, работающий только на сервере, для API версии V1, подписанный приёмник webhook, запланированную синхронизацию, которая сохраняет каждое письмо независимо от того, пришёл ли webhook, и ответы, отправляемые только после одобрения текста человеком. Использовать, когда: (1) приложение должно получать, хранить, искать или отвечать на письма из Gmail или IMAP‑ящиков, подключённых к InboxParse, (2) нужно добавить или проверить endpoint webhook InboxParse, задачу синхронизации или поток отправки и ответа, (3) требуется передать письмо в AI‑функцию, не позволяя автору письма управлять процессом, (4) необходимо напрямую вызывать API InboxParse для писем, веток, поиска, ящиков, меток, контактов, webhook‑ов или статистики использования, (5) пользователь упоминает: InboxParse, inboxparse.com, email API, email-to-LLM, parse emails, email webhook, X‑InboxParse‑Signature, whsec_, ip_ API key, INBOXPARSE_API_KEY, email.received, email.ai_processed, ai.suggested_response, /api/v1/emails, rate_limit_exceeded. Содержит факты, которые не указаны в справочнике API, проверенные по реализации: доставки содержат идентификаторы, но не тело письма, повторяются до 5 раз и отключают подписку после 10 неудач; подпись покрывает сырое тело без временной метки; курсор списка пагинирует только по полю sent_at. Next.js App Router; интерфейс InboxStore является точкой интеграции, поэтому состояние хранится в Postgres, Supabase или Firestore. Это не почтовый сервер, не UI почтового клиента и не сервер MCP InboxParse.
