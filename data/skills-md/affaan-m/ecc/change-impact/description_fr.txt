Effectuez une analyse d’impact fondée sur des preuves avant de modifier le code, les données, les interfaces ou les documents de gouvernance, puis comparez l’impact prévu avec le diff réel après mise en œuvre. Cela couvre les chemins d’appel, les données et le schéma, les contrats d’API, les tests, la documentation, les ADR, le déploiement, la migration et le retour en arrière. À utiliser pour les changements inter-modules ou à haut risque, les migrations de bases de données, l’authentification, les interfaces publiques, les questions de rayon d’impact, les vérifications pré‑modification et l’alignement post‑implémentation.
