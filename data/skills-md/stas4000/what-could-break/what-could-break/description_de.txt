Finde heraus, was eine Änderung außerhalb ihres eigenen Diffs beschädigen könnte, und beweise dann die eine Tatsache, die sie sicher macht, indem du echten Code ausführst statt einen Aufsatz zu schreiben.

Verwende es vor jeder mehrdatei‑Editierung oder einer Änderung an einem gemeinsam genutzten Pfad (API‑Payload, Konfiguration, gespeicherte Daten, ein Client, den andere Apps lesen, eine Prompt‑ oder Richtliniendatei), wenn du gefragt wirst „Was könnte das beschädigen?“ oder „Auswirkungsradius von X“, bei einem kleinen Diff, dem du nicht vertraust, oder wenn eine Aufgabe etwas über bestehenden Code behauptet („X behandelt bereits Y“, „mach X einfach öffentlich“), bevor du gegen diese Behauptung planst.

Bitte antworte immer in der Sprache des Benutzers.
