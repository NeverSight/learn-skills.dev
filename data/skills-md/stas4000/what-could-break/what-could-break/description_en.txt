Find what a change could break outside its own diff, then prove the one fact that makes it safe by running real code instead of writing an essay. Use before any multi-file edit or an edit to a shared path (API payload, config, stored data, a client other apps read, a prompt or policy file), when asked 'what could this break' or 'blast radius of X', for a small diff you do not trust, or when a task asserts something about existing code ('X already handles Y', 'just make X public') before you design against that assertion.
