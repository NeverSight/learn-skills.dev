# 한글 표백제

개발자가 실제로 쓰는 용어와 자연스러운 한국어로 문서를 편집한다. 한국어 문법 검사, 번역투 교정, 작성 스타일 검사의 핵심 원칙을 이 스킬 안에서 함께 적용한다. 다른 한국어 스킬을 별도로 불러올 필요는 없다.

## 편집 기준

- 사용자 지시와 지정 용어를 우선하고, 그다음 프로젝트 용어집과 기존 관례를 따른다. 기준이 없으면 해당 분야에서 자연스러운 표현을 선택한다.
- 의미를 보존한다. 사실, 수치, 예시, 인과관계, 부정, 조건, 제한, 의무 수준을 바꾸지 않는다. 가능성을 보장으로, 목표를 구현 완료로, 구현을 운영 적용으로 바꾸지 않는다.
- 용어만 교체하지 않는다. 각 문단을 읽고 주체·동작·대상이 명확한 문장으로 다듬는다. 문장 분리나 순서 조정은 의미와 논리 관계가 유지될 때만 한다.
- 영어를 일괄 선호하지 않는다. 개발자가 영어로 주로 쓰는 개념은 영어를 쓰고, 일반 설명과 문장 구조는 자연스러운 한국어로 쓴다. 불필요한 한영 병기를 반복하지 않는다.
- 같은 개념은 같은 용어로 쓴다. 서로 다른 개념이나 코드 식별자를 표기 통일을 이유로 합치지 않는다.
- 추상적인 비유나 번역투는 문맥에 드러난 실제 처리·구성요소·조건으로 풀어 쓴다. 원문에 없는 요구사항이나 근거를 보충하지 않는다.
- 기술적으로 유효한 용어도 문맥에서 모호하면 구체화한다. 특정 단어를 문서 전체에서 금지하거나 무조건 치환하지 않는다.
- 설명문은 기존의 일관된 종결형을 유지한다. 불필요한 피동, 명사 나열, 과도한 쉼표를 줄이되 모든 문장을 짧고 단조롭게 만들지는 않는다.

## 통합 검토 항목

세 관점을 함께 적용한다. 문법과 의미 보존을 우선하고, 문체 개선과 표기 통일이 이 기준을 덮어쓰지 않게 한다.

- **문법**: 맞춤법, 띄어쓰기, 조사·어미, 시제·호응, 문장부호. 상세 판단이나 교정 이유가 필요하면 [문법 기준](references/grammar.md)을 읽는다.
- **문체**: 문장부호, 띄어쓰기, 명사화, 어휘·지시 표현, 문장 구조, 번역투. 해당 문제가 있으면 [문체 기준](references/naturalness.md)을 읽는다.
- **일관성**: 어조, 용어, 숫자·단위, 목록, 인용·강조, 날짜·시간, 링크·참조. 문서 전체나 여러 파일을 편집하면 [일관성 기준](references/consistency.md)을 읽는다.

전체 윤문 요청에서는 세 범주를 모두 검토한다. 맞춤법만 요청받으면 문체 재작성까지 확대하지 않는다. 세 참고 문서는 이 스킬에 포함되어 있으며 원본 스킬을 따로 설치하거나 원격에서 불러올 필요가 없다.

## 상세 리뷰와 참고 자료

- 전체 문서를 검토할 때는 [상세 규칙과 예외](references/detailed-rules.md)를 읽고 문법·문체·일관성의 세부 항목까지 확인한다.
- 분석이나 수정 이유를 요청받으면 [상세 보고 방법](references/review-report.md)에 따라 위치, 원문, 수정안, 근거, 예외를 기록한다. 표기 빈도와 항목 수는 확인한 경우에만 제시한다.
- 보고 형식은 [전체 분석 예시](examples/analysis.md)를 참고한다. 예시의 용어와 스타일 선택을 다른 문서의 기본값으로 강제하지 않는다.
- 수정하지 않은 항목과 확인이 필요한 항목도 구분한다. 상세 보고를 요청받았을 때 짧은 변경 요약만으로 검토를 마치지 않는다.

## 작업 순서

1. **범위와 보호 대상을 확인한다.** 지정한 장·절·파일만 수정한다. 전체 편집이면 목차, 제목, 표, 그림 설명, 용어집도 포함한다. 파일 편집 요청이면 실제 파일에 반영한다. 단순 검토 요청이면 수정안을 제시한다.
2. **문서 구조와 용어를 파악한다.** 편집 전 [용어와 사례](references/terminology-and-examples.md)를 읽는다. 문맥을 살펴 대표 표기와 예외를 작업용 용어표로 정한다. 용어표를 문서에 새로 삽입할 필요는 없다.
3. **모든 문단을 차례로 읽고 수정한다.** 긴 문서는 절 단위로 나눠 처리하고 완료 범위를 기록한다. 잘린 도구 출력이나 검색 결과만으로 읽었다고 판단하지 않는다. 제목, 목록, 표의 각 셀도 문맥과 함께 읽는다.
4. **의미를 대조한다.** 수정 전후의 주장, 조건, 예외, 인과관계와 주체를 비교한다. 기술적 의미가 불명확하면 추측해서 바꾸지 않는다. 뜻을 유지할 수 있는 표현만 고치고, 해소가 필요한 모호함은 따로 알린다.
5. **문서 전체의 표기를 점검한다.** 같은 개념의 한영 혼용, 대소문자, 띄어쓰기, 제목·목차 불일치를 검색한다. 검색은 검토를 보조하는 수단이며 문단별 독해를 대신하지 않는다. 범위 밖의 불일치는 임의로 수정하지 않는다.
6. **문법과 파일을 검증한다.** 용어를 바꾼 뒤 조사·서술어 호응·띄어쓰기·맞춤법·구두점을 문장 단위로 다시 읽는다. diff를 확인하고 보호 대상이 그대로인지 검사한다. 파일 형식에 맞는 구조·링크 검사를 수행한다.
7. **간결하게 보고한다.** 수정한 파일과 범위, 대표적인 변경, 실제 수행한 검증을 알린다. 미검토 범위를 숨기거나 구조 검사만으로 의미 보존·화면 표시까지 검증했다고 말하지 않는다.

## 용어와 문법 판단

- 특정 영문 용어 목록을 모든 문서에 강제하지 않는다. 독자층, 분야의 관용적 표현, 문서에서 정의한 개념을 바탕으로 한국어와 영어 중 적절한 표기를 선택한다.
- 같은 단어도 일반적인 뜻과 전문적인 뜻을 구분한다. 전문 용어로 쓰인 경우에만 해당 분야의 표기를 적용한다.
- 용어표에는 개념, 선택한 표기, 허용할 예외를 기록한다. 설명문의 역할 이름과 실제 코드 식별자는 표기가 달라도 오류가 아닐 수 있다.
- 영문 뒤의 조사는 실제 읽는 발음을 기준으로 문장 안에서 확인한다. 영문 마지막 글자에 따른 기계적 조사 치환은 하지 않는다. 발음이 모호하면 자연스러운 한국어 명사를 덧붙이는 방법도 고려한다.
- 문법상 오류와 문체 취향을 구분한다. 수량·단위 표기, 보조 용언 띄어쓰기처럼 허용되는 표기를 근거 없이 오류로 처리하지 않는다.

## 파일 보존

- 별도 요청이 없으면 코드 블록, 코드 주석, 인라인 코드, API·식별자, 명령어, 경로, URL, 인용 원문을 보존한다. 주변 설명을 고치다가 코드까지 바꾸지 않는다.
- HTML에서는 script, style, DOM ID, 링크 대상, 클래스와 문서 구조를 보존한다. 다이어그램은 설명용 라벨만 필요에 따라 수정하고 노드·연결·방향은 유지한다. 접근성 설명도 편집 범위에 포함하되 기능 속성은 보호한다.
- Markdown에서는 링크 대상과 코드 fence를 보존한다. Word·PDF 등 형식별 편집·렌더링이 필요하면 해당 형식 스킬을 함께 사용한다.
- 문서 전체 문자열 치환으로 기술 용어, 조사, HTML 또는 식별자를 수정하지 않는다. 문맥이 확인된 텍스트 구간에만 변경을 적용한다.
- 요청하지 않은 기술 내용 보강, 문서 재구성, 디자인 변경은 하지 않는다. AI 생성 확률이나 자의적인 문체 점수도 기본 결과에 포함하지 않는다.
