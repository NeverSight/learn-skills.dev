Récupérez les données chiffrées par le ransomware C3RB3R / Cerber (extension de fichier .L0CK3D, note de rançon read‑me3.txt) sur Synology (DSM), ext4 (anciens volumes QNAP, Linux installé manuellement, etc.) ou NAS Btrfs sans clé : utilisez les anciens extents laissés par le copy‑on‑write de Btrfs pour restaurer le fichier original octet par octet et vérifiez bloc par bloc avec les sommes de contrôle Btrfs ; pour les fichiers qui ont été complètement écrasés et dont les anciens extents ont été libérés, découpez la partie texte non chiffrée selon le schéma de chiffrement C3RB3R (un marqueur de pied de page de 588 octets), et récupérez les membres des fichiers .xlsx/.docx/.zip corrompus et reconstruisez les PDF ; si la récupération est réellement impossible, effectuez du carving de fichiers sur le dispositif de blocs pour récupérer les anciens extents libérés. Chaque fois qu’un utilisateur mentionne NAS / Synology / « black Synology » victime de rançon, .L0CK3D, read‑me3.txt, C3RB3R, Cerber, « fichier chiffré à récupérer », « pas de sauvegarde, pas de snapshot, comment sauvegarder », « le fichier ne s’ouvre pas mais je veux voir son contenu », « fichier supprimé à récupérer », « le disque a encore des fichiers résiduels », « file carving », même si Btrfs ou les extents ne sont pas mentionnés, cette compétence doit être appliquée. Elle couvre la détection CoW / NoCoW, les effets de génération de snapshots de sous‑volume (lastsnap), le réassemblage précis de l’arbre d’extent, l’inférence inter‑extent pour les gros fichiers, le carving de fichiers, les statistiques, l’exportation, la vérification et le reporting. Elle comprend également la technique à haut rendement « recherche d’index inversée du carving par ID de conteneur » (l’ID de l’en‑tête du conteneur correspond au nom du répertoire du dépôt Synology Drive ; listez toutes les versions historiques du document sur le disque par ID, puis filtrez par longueur originale — test de récupération de 65 sur 74 fichiers .osheet) et la méthode de récupération du texte en clair pré‑ransomware depuis la corbeille Synology / les snapshots @sharesnap. Utilisez‑le pour la récupération de ransomwares de fichiers .L0CK3D sur volumes Synology/Btrfs/ext4 sans la clé. Le scénario le plus économiseur de temps est également couvert : « fichier situé dans le dossier de synchronisation Synology Drive » (le dépôt Git de Drive conserve le texte en clair pré‑ransomware, permettant une reconstruction en minutes des données de feuilles de calcul, voir references/synology-drive.md).
