Recupera dati su Synology (DSM), volumi ext4 (vecchi volumi QNAP, Linux installato manualmente, ecc.) o NAS Btrfs che sono stati criptati dal ransomware C3RB3R / Cerber (estensione file .L0CK3D, file di riscatto read‑me3.txt) senza una chiave: utilizza le vecchie estensioni lasciate da Btrfs copy‑on‑write per ripristinare i file originali byte‑per‑byte e verificarli blocco‑per‑blocco con i checksum di Btrfs; per i file che sono stati completamente sovrascritti e le cui vecchie estensioni sono state rilasciate, ritaglia la porzione di testo non criptata secondo il pattern di crittografia C3RB3R (un marcatore di 588 byte alla fine), e recupera componenti da file xlsx/docx/zip danneggiati e ricostruisci PDF; se il recupero è impossibile, esegui il carving dei file sul dispositivo a blocchi per recuperare le vecchie estensioni rilasciate. Ogni volta che un utente cita NAS / Synology / “black Synology” ricattato, .L0CK3D, read‑me3.txt, C3RB3R, Cerber, frasi come “file encrypted want to recover”, “no backup no snapshot how to save”, “file won’t open but want to see its contents”, “file deleted want to retrieve”, “disk still has residual files”, “file carving”, anche se non si menzionano Btrfs o estensioni, questa competenza deve essere utilizzata. Copre il rilevamento CoW / NoCoW, gli effetti algebrici degli snapshot di sottovolume (lastsnap), la ricostruzione precisa dell’albero delle estensioni, l’inferenza cross‑extent per file di grandi dimensioni, il carving dei file, statistiche, esportazione, validazione e reportistica. Include anche la tecnica ad alto rendimento del “carving indice reverse‑lookup per ID contenitore” (l’ID dell’intestazione del contenitore corrisponde al nome della cartella del repository Synology Drive; elenca tutte le versioni storiche del documento sul disco per ID e filtra per orig_len – ha salvato 65 su 74 file .osheet), oltre a un metodo per recuperare gli originali in testo chiaro pre‑ransomware dal Cestino di Synology/@snapshots sharesnap. Usa per il recupero da ransomware di file .L0CK3D su volumi Synology/Btrfs/ext4 senza la chiave. Copre inoltre lo scenario più efficiente in termini di tempo in cui il file si trova in una directory di sincronizzazione Synology Drive (il repository Git di Drive conserva il testo chiaro pre‑ransomware, consentendo una ricostruzione a livello di minuti dei dati dei fogli di calcolo; vedi references/synology-drive.md).
