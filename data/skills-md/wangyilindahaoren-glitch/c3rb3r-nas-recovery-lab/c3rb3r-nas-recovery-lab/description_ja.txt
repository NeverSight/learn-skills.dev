Synology（DSM）、ext4（旧QNAPボリューム、手動でインストールしたLinuxなど）またはBtrfs NASで、C3RB3R／Cerber ランサムウェア（ファイル拡張子 .L0CK3D、身代金要求メモ read‑me3.txt）により暗号化されたデータを鍵なしで復元する方法：Btrfs のコピーオンライトが残した古いエクステントを使用して元のファイルをバイト単位で復元し、Btrfs のチェックサムで各ブロックを検証する；完全に上書きされ古いエクステントが解放されたファイルについては、C3RB3R 暗号化方式（588 バイトのトレーラーマーカー）に従って暗号化されていない平文部分を切り出し、破損した xlsx／docx／zip ファイルからコンポーネントを救出し、PDF を再構築する；それでも復元できない場合は、ブロックデバイス上でファイルカービングを実行して解放された古いエクステントを取得する。ユーザーが NAS／Synology／“black Synology” がランサム化された、.L0CK3D、read‑me3.txt、C3RB3R、Cerber、 「file encrypted want to recover」や「no backup no snapshot how to save」などのフレーズを言及した場合、たとえ Btrfs やエクステントが言及されていなくても、このスキルを適用すべきである。内容は CoW／NoCoW の検出、サブボリュームスナップショット生成（lastsnap）の効果、エクステントツリーの精密再構築、大容量ファイルのクロスエクステント推論、ファイルカービング、統計、エクスポート、検証、レポート作成を網羅する。さらに “container ID によるカービングインデックス逆検索” という高効率手法（コンテナヘッダー ID が Synology Drive リポジトリのフォルダー名と一致し、ID でディスク上のすべての文書の履歴版を列挙し、orig_len でフィルタリング——74 件の .osheet ファイルうち 65 件を救出したテスト）や、Synology のごみ箱／@sharesnap スナップショットからランサムウェア発生前の平文オリジナルを取得する方法も含む。鍵なしで .L0CK3D ファイルのランサムウェア復旧に Synology／Btrfs／ext4 ボリュームで使用する。また、ファイルが Synology Drive の同期フォルダ内にある最も時間効率の良いシナリオもカバーし（Drive の Git リポジトリがランサム前の平文を保持しているため、数分単位でスプレッドシートデータを復元可能、参照：references/synology-drive.md）。
