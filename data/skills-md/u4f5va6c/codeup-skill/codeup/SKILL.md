# 云效开发工作流

以 ProjeX 工作项追踪需求，以 Codeup 合并请求交付代码；先解析真实资源和能力，再操作。GitHub 术语可以作为交流习惯，API、ID、状态和权限必须使用云效原生语义。

## 本次任务

- [ ] 读取项目约定，确定目标组织、项目、仓库和本次授权范围。
- [ ] 按 [执行环境与凭据入口](references/access.md#按执行环境选择凭据入口) 确认本机的调用方式，再执行需要鉴权的命令。
- [ ] 按任务加载下述参考，查明工具及必要元数据。
- [ ] 执行请求的操作；写操作返回不确定时先回读核对。
- [ ] 验证结果，交付资源链接、提交 SHA、检查结果和未完成事项。

读取仓库现有 `AGENTS.md` / `CLAUDE.md`、`docs/agents/issue-tracker.md`、`docs/agents/domain.md`；只有存在时才读 `docs/agents/triage-labels.md`。遵循项目的词汇、提交格式和验收规则。配置缺失时仍可做明确目标的查询；只补问会影响操作的缺失信息。

在本会话首次访问云效前读取 [访问与工具选择](references/access.md)，选定并复用实际执行环境的凭据入口。切换主机、用户、容器、远程环境或目标组织，以及鉴权失败时重新确认；手机或桌面客户端所在位置不决定服务器的凭据来源。

## 资源身份

明确本次涉及哪些对象，不要求每个只读任务收集整套配置：

- 云效部署类型与 API 接入点；中心版还需 `organizationId`。
- ProjeX `projectId` / `spaceId` 与工作项类型；它们不等于 Codeup 仓库 ID。
- Codeup 仓库 ID、完整路径及真实 Git remote；默认分支从仓库读取。
- 工作项 API `id` 与展示 `serialNumber` 分别保存；MR `localId`、`bizId` 不互换。
- CI 结果绑定仓库、分支和确切提交 SHA，不能只看某流水线最近一次成功。

同一 ProjeX 项目可能跨多个仓库，同一仓库也可能服务多个项目。无配置时用工作项/仓库详情核对归属；同名资源不能作为唯一定位依据。

## 工具使用与边界

默认通过本机凭据入口调用新版 `aliyun devops`；已知缺口按 [固定调用规则](references/access.md#固定调用规则) 使用 Skill 脚本或指定 API。ProjeX Markdown 评论直接用随包脚本，其他常规操作继续走 CLI。脚本与 CLI 复用同一本机凭据来源，原生命令示例也须套用注入入口。已有且身份与目标匹配的官方 MCP 可沿用；参数以当前 `--help` 或工具 schema 为准。

本地 checkout、commit、fetch、push 使用 Git。API 认证成功不代表 SSH/HTTPS Git 凭据已配置。

延续用户已经授予的操作权限，目标清楚时直接完成必要工作。创建 MR、发布工作项、发送评论、合并、触发发布各有不同作用范围；仅要求查询或评估不构成对这些操作的授权。对缺少授权的外部动作，先准备具体可审阅的内容，再询问；不得把本 Skill 的安装视为发布、合并或生产部署授权。

404 可能是资源、路由或可见性问题；403 应核对身份、令牌范围和项目成员权限。不要通过切换组织、扩大权限或绕过评审门禁来“修好”失败。

## 完成条件

汇报实际完成的工作，附服务端返回或已验证的 URL / ID。分别说明“本地测试通过”“CI 通过”“已合并”“已部署”“业务验收完成”。缺少对应证据时保留为未验证。

文档基于 2026-10-10 的官方资料；命令清单与项目字段会变化，参考文件中的发现步骤优先于记忆。
