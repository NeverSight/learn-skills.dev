Utilisez‑le lorsque vous documentez une API HTTP, les charges utiles des messages, les contrats de file d’attente, les DTO, les formats de fichiers ou les webhooks – ou lorsque vous rédigez la référence API d’une campagne legacy, ou lorsque les appelants demandent constamment ce que signifie un champ ou quelles erreurs un point de terminaison renvoie. Il encode les quatre niveaux de détail, le catalogue DTO‑first, les types de fil avec des ancres source, la règle « one‑home » de la spécification générée, ainsi que la sémantique omission‑vs‑null. Utilisez‑le chaque fois qu’une interface machine doit être documentée pour ses appelants, même si personne ne parle de « doc API ».
