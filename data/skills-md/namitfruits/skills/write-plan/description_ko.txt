특정 기능을 위한 실행 계획 문서(plan doc)를 작성한다 — 이전 채팅에서 제시하고 작업 ID를 확정한 뒤, 고정된 7섹션 프레임(Problem·Goal·Mental model·Probe·Decisions·Design·Phases—Probe는 선택 사항)으로 파일을 구성하고 🤖/👤 기호를 사용하여, 진행 상황에 따라 체크한다. 사용자가 “계획 수립”, “X에 대한 계획 작성”, “계획 저장”, “doc plan 생성”, “코드 작성 전에 X 설계” 등이라고 말할 때 혹은 코드 수정 전에 계획이 필요한 충분히 큰 요구사항이 있을 때 사용한다. 프로젝트 컨벤션(CLAUDE.md / AGENTS.md / docs 디렉터리)을 읽어 **바인딩**—디렉터리, ID 체계, 원본 문서, 검증 명령—을 가져오고, **문서 형식은 이 스킬에 따른다**. `verify.py`를 포함한다 — 섹션 프레임을 lint하고, `P → D → DS → phase` 흐름을 확인하며, `DS`를 커버하고, 체크/상태를 표시한다.
