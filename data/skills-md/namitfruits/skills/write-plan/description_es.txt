Escribe un documento de plan de implementación (plan doc) para una característica — preséntalo en el chat anterior, cierra el ID de la tarea, genera el archivo siguiendo una plantilla fija de 7 secciones (Problem · Goal · Mental model · Probe · Decisions · Design · Phases — Probe opcional) con los símbolos 🤖/👤, y marca con ticks hasta donde se haya avanzado. Se utiliza cuando el usuario dice “planificar”, “escribir plan para X”, “guardar el plan”, “crear doc plan”, “diseñar X antes de codificar”, o cuando una solicitud es lo suficientemente grande como para requerir un plan antes de modificar código. Lee la convención del proyecto (CLAUDE.md / AGENTS.md / carpeta docs) para obtener **binding** — carpeta, sistema de ID, documento fuente, comando de verificación — y **la forma del documento sigue esta habilidad**. Incluye `verify.py` — lint de la estructura de secciones, cadena `P → D → DS → phase`, cubre `DS`, tick/estado.
