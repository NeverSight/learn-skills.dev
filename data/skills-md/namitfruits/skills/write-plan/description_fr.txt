Rédiger un document de planification de déploiement (plan doc) pour une fonctionnalité — présenté dans le chat précédent, valider l’ID de la tâche, créer le fichier selon un cadre fixe de 7 sections (Problem · Goal · Mental model · Probe · Decisions · Design · Phases — Probe facultatif) avec les symboles 🤖/👤, puis cocher au fur et à mesure. Utilisé lorsque l’utilisateur dit « lập kế hoạch », « viết plan cho X », « lưu lại plan », « tạo doc plan », « thiết kế X avant de coder », ou lorsqu’une requête est suffisamment importante pour nécessiter un plan avant de modifier le code. Lire les conventions du projet (CLAUDE.md / AGENTS.md / répertoire docs) pour obtenir les **bindings** — répertoire, système d’ID, document source, commande de vérification — et la **forme du document doit suivre cette compétence**. Inclure `verify.py` — lint du cadre de sections, fil conducteur `P → D → DS → phase`, couvrir `DS`, cocher le statut.
