Concevoir l'UI en prototype HTML cliquable comme une vraie application. La compétence de lecture du système de design est fournie (DESIGN.md, fichier token CSS, composants du projet) ainsi que les écrans existants ; s’il n’y a pas de système de design, afficher la liste des designs de getdesign pour que l’utilisateur en choisisse un ; si la demande est vague, poser une question avec des réponses préétablies ; organiser la demande soit en écran unique soit en flux : pour un écran, rechercher une solution selon le contexte d’utilisation, créer deux options A/B en parallèle, sans demander de choisir ; pour un flux, le diviser en plusieurs écrans, afficher le tableau des écrans dans le chat, chaque écran correspondant à une page, créer en parallèle. Chaque page dans `.design/NNN-slug/` est générée par un agent secondaire suivant une liste de six étapes ; le lien est disponible dès le démarrage de la génération, la page ouverte affiche automatiquement la nouvelle version à chaque étape terminée, en cas d’interruption elle reprend à l’étape où elle s’est arrêtée. La page possède un data‑panel pour ajuster les données (variables), un config‑panel pour régler la configuration (ajustement : rôle, mise en page, épaisseur), une barre d’outils pour changer d’option ou d’écran, tailles desktop / tablet / mobile, clair / sombre. Les commentaires entraînent une correction directe de la page jusqu’à achèvement. La sortie est vérifiée avec le code (`check.mjs`) avant la remise. Produire uniquement le HTML, ne pas modifier le code du projet. `--auto` pour ne pas s’arrêter pour poser des questions. Utiliser lorsqu’un utilisateur dit « concevoir l’écran X », « concevoir le flux X », « réfléchir à des options d’affichage », « faire un prototype », « mockup interactif », « améliorer l’interface de la page Y », « design this screen », « design this flow », « prototype », « show me options », ou fournit un besoin UI et un système de design.
