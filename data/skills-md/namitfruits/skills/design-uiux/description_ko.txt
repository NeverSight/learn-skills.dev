UI를 실제 앱처럼 클릭 가능한 HTML 프로토타입으로 설계합니다. 디자인 시스템을 읽는 기술은 제공된 (DESIGN.md, CSS 토큰 파일, 프로젝트 컴포넌트) 및 현재 화면을 사용합니다; 디자인 시스템이 없으면 getdesign의 디자인 목록을 출력해 사용자가 선택하도록 합니다; 모호한 요구는 미리 준비된 답변 문장으로 질문합니다; 과제는 한 화면인지 한 흐름인지 구분합니다: 한 화면이라면 사용 상황에 맞는 방안을 찾고, A/B 두 가지 방안을 병렬로 구축하며 선택을 묻지 않습니다; 한 흐름이라면 화면을 여러 개로 나누어 채팅에 화면 표를 출력하고, 각 화면을 하나의 페이지로 하여 병렬로 구축합니다. `.design/NNN-slug/` 안의 각 페이지는 여섯 단계 목록에 따라 하위 에이전트가 생성합니다; 시작과 동시에 링크가 제공되고, 현재 열려 있는 페이지는 단계가 완료될 때마다 자동으로 새 버전을 표시하며, 중단된 경우 중단된 단계부터 계속합니다. 페이지는 data‑panel(변수)로 데이터를 조작하고, config‑panel(역할, 레이아웃, 두께 등)으로 설정을 조정하며, 툴바로 방안이나 화면을 전환하고, 데스크톱/태블릿/모바일, 라이트/다크 모드를 전환합니다. 피드백은 해당 페이지를 바로 수정해 완료합니다. 출력물은 전달 전에 코드(`check.mjs`)로 검증합니다. HTML만 제공하고 프로젝트 코드는 수정하지 않습니다. `--auto` 옵션을 사용하면 질문을 멈추지 않습니다. 사용자가 “화면 X 설계”, “흐름 X 설계”, “표시 방안 생각”, “프로토타입 만들기”, “클릭 가능한 목업”, “페이지 Y UI 개선”, “design this screen”, “design this flow”, “prototype”, “show me options” 라고 말하거나 UI 요구사항과 디자인 시스템을 제공할 때 사용합니다.
