Разработать UI в виде интерактивного HTML‑прототипа, кликабельного как реальное приложение. Навыки чтения design‑system предоставляются (DESIGN.md, файл токенов CSS, компоненты проекта) и текущий макет; если design‑system отсутствует, вывести список дизайнов из getdesign для выбора пользователем; если запрос неоднозначный, задать уточняющий вопрос с готовыми вариантами ответа; задача может быть одной страницей или потоком: одна страница — искать решение согласно сценарию использования, построить два параллельных варианта A/B без запроса выбора; поток — разбить на отдельные страницы, вывести таблицу страниц в чате, каждая страница — отдельный файл, построить параллельно. Каждая страница находится в `.design/NNN-slug/` и создаётся дочерним агентом по шестишаговому плану; ссылка появляется сразу при начале создания, открытая страница автоматически показывает новую версию после завершения каждого шага, при прерывании продолжает с того места, где остановилась. Страница имеет data‑panel для переменных, config‑panel для настройки (тюнинг: роль, компоновка, толщина), toolbar для смены варианта или страницы, режимы desktop / tablet / mobile, светлая / тёмная темы. При замечаниях править непосредственно эту страницу до завершения. Вывод проверяется кодом (`check.mjs`) перед передачей. Указывать только HTML, не менять код проекта. `--auto` отключает остановки для вопросов. Использовать, когда пользователь говорит «разработать страницу X», «разработать поток X», «придумать варианты отображения», «сделать прототип», «интерактивный мокап», «улучшить интерфейс страницы Y», «design this screen», «design this flow», «prototype», «show me options», или предоставляет UI‑требования и design‑system.
