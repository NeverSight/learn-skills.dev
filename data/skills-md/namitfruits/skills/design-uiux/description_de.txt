Entwerfe UI zu einem klickbaren HTML-Prototyp wie eine echte App. Die Fähigkeit, das Designsystem zu lesen, wird bereitgestellt (DESIGN.md, CSS‑Token‑Datei, Projekt‑Komponenten) und vorhandene Bildschirme; gibt es kein Designsystem, dann zeige die Designliste von getdesign zur Auswahl durch den Nutzer; bei unklaren Vorgaben frage mit vordefinierten Antwortmöglichkeiten; strukturiere die Aufgabe als einzelnen Screen oder einen Flow: ein einzelner Screen bedeutet, eine Lösung für die Nutzungssituation zu finden, erstelle parallel zwei Varianten A/B, ohne nach Auswahl zu fragen; ein Flow wird in einzelne Screens aufgeteilt, zeige eine Screen‑Tabelle im Chat, jeder Screen ist eine Seite, erstelle parallel. Jede Seite im Verzeichnis `.design/NNN-slug/` wird von einem Unter‑Agenten nach einer Sechs‑Schritte‑Liste erstellt; Link ist sofort beim Starten der Erstellung verfügbar, die geöffnete Seite zeigt automatisch die neue Version, sobald ein Schritt abgeschlossen ist; bei Unterbrechung fortsetzen ab dem letzten Schritt. Die Seite hat ein data‑Panel zum Anpassen von Daten (Variablen), ein config‑Panel zum Anpassen der Konfiguration (Feinabstimmung: Rolle, Layout, Stärke), eine Toolbar zum Wechseln der Variante oder des Screens, Desktop/Tablet/Mobile‑Ansicht, Hell/Dunkel‑Modus. Feedback bedeutet, die Seite direkt zu korrigieren, bis sie fertig ist. Die Ausgabe wird mit Code (`check.mjs`) geprüft, bevor sie übergeben wird. Nur HTML ausgeben, keinen Projektcode ändern. `--auto` um nicht nachzufragen. Verwenden, wenn der Nutzer sagt „design screen X“, „design flow X“, „überlege Anzeigeoptionen“, „erstelle Prototyp“, „klickbarer Mockup“, „verbessere UI von Seite Y“, „design this screen“, „design this flow“, „prototype“, „show me options“ oder ein UI‑Requirement und ein Designsystem bereitstellt.
