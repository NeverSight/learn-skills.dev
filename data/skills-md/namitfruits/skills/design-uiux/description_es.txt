Diseña UI como prototipo HTML clicable, como una aplicación real. Habilidad para leer el sistema de diseño proporcionado (DESIGN.md, archivo token CSS, componentes del proyecto) y la pantalla actual; si no hay sistema de diseño, imprime la lista de diseños de getdesign para que el usuario elija uno; si la solicitud es ambigua, pregunta con una frase predefinida con respuesta. Organiza la solicitud como una pantalla o un flujo: una pantalla implica buscar una solución según el caso de uso, crear dos opciones A/B en paralelo, sin preguntar al usuario; un flujo implica dividirlo en pantallas, imprimir una tabla de pantallas en el chat, cada pantalla una página, crear en paralelo. Cada página en `.design/NNN-slug/` la construye un agente secundario siguiendo una lista de seis pasos; el enlace está disponible al iniciar la creación, la página abierta muestra automáticamente la nueva versión cada vez que se completa un paso; si se interrumpe, continúa desde el paso donde quedó. La página tiene data‑panel para variables, config‑panel para configuración (ajustes: rol, disposición, grosor), barra de herramientas para cambiar la opción o la pantalla, tamaños desktop / tablet / mobile, modo claro / oscuro. Los comentarios se corrigen directamente en esa página hasta completarla. La salida se verifica con código (`check.mjs`) antes de entregar. Genera solo HTML, no modifiques el código del proyecto. `--auto` para no detenerse a preguntar. Se usa cuando el usuario dice "diseña pantalla X", "diseña flujo X", "piensa en una opción de visualización", "haz un prototipo", "mockup clicable", "mejora la interfaz de la página Y", "design this screen", "design this flow", "prototype", "show me options", o proporciona un requisito UI y un sistema de diseño.
