UI を実際のアプリのようにクリックできる HTML プロトタイプに設計する。デザインシステムを読むスキルは（DESIGN.md、CSS トークンファイル、プロジェクトのコンポーネント）と現在の画面が提供される；デザインシステムがない場合は、getdesign のデザイン一覧を表示してユーザーに選択させる；要件が曖昧なときは、用意された回答文で質問する；課題は単一画面かフローかで構成する：単一画面の場合は使用シナリオに沿って解決策を探し、A/B の二つの案を並行して作成し、選択を尋ねない；フローの場合は画面を分割し、チャット内に画面表を表示し、各画面をページとして並行して作成する。各ページは `.design/NNN-slug/` ディレクトリ内に、6 歩のリストに従ってサブエージェントが作成する；リンクは作成開始時にすぐに生成され、ページが開かれている間はステップが完了するたびに新しいバージョンが自動的に表示され、途中で中断した場合は中断したステップから再開できる。ページには data-panel（変数）でデータを操作し、config-panel（role、レイアウト、太さなどの調整）で設定を操作し、ツールバーで案や画面を切り替え、デスクトップ／タブレット／モバイル、ライト／ダークモードを切替える。フィードバックがあれば、そのページを直接修正して完了させる。成果物は配布前にコード（`check.mjs`）で検証する。HTML を指示し、プロジェクトのコードは変更しない。`--auto` を付けると質問を止めない。ユーザーが「画面 X を設計」「フロー X を設計」「表示案を考える」「プロトタイプを作る」「クリックできるモックアップ」「ページ Y のインターフェイスを改善」「design this screen」「design this flow」「prototype」「show me options」あるいは UI 要件とデザインシステムを提示したときに使用する。
