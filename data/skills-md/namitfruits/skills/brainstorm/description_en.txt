Communicate with the user to clarify what they really want — only clarify, not analyze. Start by restating the prompt so the user can correct any misunderstandings, ask about the current state (what the system has, what it lacks), then break the prompt into modules — the main modules are taken directly from the words in the prompt (e.g., “appointment app with reminders and payment” becomes Appointment · Reminder · Payment); if the main modules need something that is missing (e.g., permissions require login) ask the user if they want additional modules — let the user **tick-select features** for each module — the ticked items define the scope — finalize the overall picture, then go through each module: the user narrates first, the agent asks about the goal and any gaps (what · who · when · what is returned · a real example) until a clear image is formed, then restate it in your own words for the user to confirm. Ask with pre‑written answer choices; ask about the goal, don’t dig into pain points; don’t finalize numbers, don’t explore error cases, don’t write user stories — that is for the later analysis step. Create a folder `.brainstorm/NNN-slug/` containing a brief file `brief.md` according to `templates/brief.md` and a checklist file `checklist.md` according to `templates/checklist.md`: each iteration continues until every item of the step is closed, the checklist adds new items when a new module or feature appears, and if interrupted read the checklist to resume. Include `templates/modules.md` (suggested features for common modules) and `scripts/verify.py` to lint the brief and checklist. Use this when the user says “brainstorm”, “let’s think about what I want”, “clarify the idea”, “interview me”, “clarify requirements”, or provides a feature list like “I want to do A, B, C” without specifying what each entails.
