# 代码设计规范

## 目的与边界

让代码的职责、依赖、状态和协作关系清楚，使当前需求可靠落地、后续修改可控。设计目标是结果，设计原则是判断依据，设计模式是可选工具；不把模式数量、接口数量、目录层数当作质量指标。

适用于面向对象、函数式、过程式及混合代码。优先使用语言原生能力与项目已有机制，函数、模块、闭包、数据类型或组合均可表达设计，不强制使用类。

面向用户默认用中文大白话，先说具体问题和影响，再解释必要术语。直说方案缺陷，但批评方案与证据，不贬低人。不得承诺绝对正确或零风险。

遵守当前用户范围、项目 AGENTS.md 和现有架构约定。读取最近作用域规则；项目要求的认知、文档或维护流程仍需执行。本技能不授权全仓重构、引入新依赖、修改公共协议、提交、推送或部署；按当前任务授权处理。只读审查不转成代码修改；只要求方案时交付方案。

## 按任务选深度

- **设计/方案**：明确约束，建立责任与依赖安排，比较最简单方案和必要备选，给出落地与验证步骤。
- **审查**：沿真实调用链检查；按影响报告具体问题、证据和修复建议，不自动改代码。
- **实现/重构**：在授权范围内修改，保持既有行为或明确列出获准的行为变化，并完成相应验证。
- **小范围改动**：只检查受影响的职责、契约和边界，不生成完整架构报告。

缺少信息时，先读取代码、调用方、测试和配置。只有缺口会改变业务行为、兼容性或工作范围时才询问；其余采用符合项目的最小方案，并说明重要假设。

## 按需读取

- 评估职责、依赖、抽象或设计质量时，读 [目标与原则](references/goals-and-principles.md)。
- 出现对象创建、组合或行为协作问题时，读 [模式决策](references/pattern-decisions.md) 中相关条目；不逐项套完 23 种模式。
- 处理跨模块、异步、公共接口或结构重构时，读 [工作流程与验证](references/workflow-and-validation.md)。
- 对边界拿不准，或检查本技能是否误用时，读 [案例与自检](references/examples-and-self-check.md)。

## 核心执行规则

### 1. 从行为和证据出发

找出入口、调用方、数据/状态所有者、外部依赖和关键测试。说明当前行为、期望行为及必须保持的约束。路径名、类名和目录数量不能独立证明职责混乱。

每个主要职责至少能回答：负责什么、输入输出是什么、谁拥有状态、谁调用它、什么变化会影响它。对无状态小函数可简写；复杂流程可用表格或简图。

### 2. 按变化原因划分职责

把经常一起变化的逻辑放近；把因不同规则、外部技术或生命周期而变化的逻辑适当隔离。一个职责可有多个方法，一个方法也可协调多个步骤。复杂度不能仅靠行数判断。

业务决策应有明确归属。界面负责交互与展示；流程协调者负责次序；底层能力负责机制。此划分是判断方向，具体落点以项目约定为准，不强加固定分层。

### 3. 优先最小充分设计

先评估直接函数/模块、现有工具和已有抽象是否足够，再考虑新接口或模式。禁止为没有证据的未来变化、只有名字相似的代码、纯转发层或模式展示而扩张结构。

新增抽象必须能说明：隔离哪种真实变化、边界契约是什么、减少什么重复决策或风险、增加多少理解成本。不机械要求先存在两个或三个实现。

### 4. 模式必须有采用理由和退出条件

采用模式时，说明：当前触发问题 → 最简单替代 → 采用收益 → 新增成本 → 何时可简化或移除。调用关系或代码外形相似，不等于符合模式语义。

既有模式不合理时可以简化，不为了规范统一复制坏设计。局部改善应保留正确边界，避免在小任务里迁移整套架构。

### 5. 把行为契约纳入设计

检查输入、结果、错误、状态变化、资源释放、并发与异步结果归属。公开接口与持久化格式的兼容性优先于表面整洁。对真实涉及的边界做验证，不把每项风险都扩成任务。

### 6. 用证据验收

验证修改后的行为和责任边界。复用项目检查命令，按风险选测试；不为低影响改动增加只复述实现的测试，不为绿灯删除有效失败测试。静态检查通过不能代替实际业务行为验证。

不得用主观分数掩盖未知，不把未执行检查写成通过。每条问题区分：已证实缺陷、设计风险、可选改进。最后检查范围是否扩大、抽象是否有收益、状态是否有唯一权威来源。

## 交付要求

按任务大小缩放，不强制生成模板文档。复杂任务应能从结果中看到：

1. 具体问题与代码证据，及对修改、运行或排错的影响。
2. 最终职责与依赖安排；关键状态、规则和资源由谁负责。
3. 实际采用的原则/模式及理由；简单做法足够时直接说明。
4. 修改内容或可执行方案，行为与兼容性边界。
5. 实际验证结果、未覆盖部分和必要后续。

审查发现按影响排序，提供准确文件位置，不用违反 SOLID 代替故障路径或维护后果。无实质问题时如实说明，无需制造重构建议。
