镜头拆解：将完成的视频拆分为每个镜头的分析表——时长、镜头类型、类别、摄像机运动以及每个镜头的视觉构图。

分工已根深蒂固：**“能量”通过代码量来衡量**（剪辑点来源于 ffmpeg 场景检测，时长是剪辑点之间的差值，运动量是每帧差异的中位数）。模型只判断它真正需要判断的少数内容（镜头类型/类别/摄像机运动/构图/节奏），每一次判断都会立即由代码验证——**它可能声称有平移、倾斜、抖动，但测量显示几乎没有运动，因此会被直接阻止**。

观看素材采用 Contact Sheet 方式（每个镜头的第一帧和最后一帧拼接成大图；一个屏幕展示数十个镜头，A/B 对比即可看出摄像机运动），而不是逐帧滚动。系统会检测遗漏或多余的剪切点；使用 recut 插入或删除剪切点，自动重新编号并重新计算时长；手动调整边界会导致质量门未通过。

输出 shots.json + Markdown 镜头列表 + **单页交互式拆解报告**：内嵌播放器（在播放时同步高亮镜头，点击镜头可跳转），镜头节奏条，可搜索、可过滤、可排序的镜头表格（列表视图和卡片视图，起始和结束关键帧并排呈现，点击缩略图放大），镜头类型、类别、摄像机运动、出现角色的分布，质量门，导出 JSON。单个文件零依赖，双击即可离线打开。

所有 15 项质量门均由脚本确定性检查。

零依赖，零 API 密钥；仅需 node 和 ffmpeg。
