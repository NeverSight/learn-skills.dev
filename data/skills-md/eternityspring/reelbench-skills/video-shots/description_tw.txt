鏡頭分割：將完成的影片拆分成每個鏡頭的分析表——每個鏡頭的時長、鏡頭大小、類別、相機運動與畫格。  
勞動分工已根深蒂固：**工作由程式碼完成**（剪切點來自 ffmpeg 場景偵測，時長為剪切點之差，運動量為每幀差異的中位數）。模型只決定少數必須決定的項目（鏡頭大小／類別／相機運動／畫格／節奏），每個決策即時由程式碼協調——**宣稱的推‑拉‑平移‑傾斜但測得幾乎靜止，門檻直接阻擋**。  
檢視方式遵循聯絡表（對每個鏡頭，將第一幀與最後一幀各放入大型圖像；每畫面約二十個鏡頭，a/b 比較顯示相機運動），而非逐一翻閱。缺失的剪切與多餘的剪切透過重新剪裁加入或裁剪，並自動重新編號與重新計算時長；手動調整的邊界若未通過門檻則被拒絕。  
輸出：`shots.json` + Markdown 鏡頭表 + **單頁互動式鏡頭分割報告**：內嵌播放器（在播放時同步標示當前鏡頭，點擊鏡頭可跳轉）、鏡頭節奏條、可搜尋、篩選、排序的鏡頭表（列表／卡片檢視，起始與結束關鍵影格並排，點擊縮圖放大）、鏡頭大小、類別、相機運動、出現角色、品質門檻的分布、導出為 JSON。單一檔案，零相依，可離線雙擊開啟。  
所有 15 項品質門檻均由腳本以確定性方式檢查。  
零相依，無 API 金鑰——僅需 Node 與 ffmpeg。
