# Dev Plan — Development Planning

**严格模式：在完成所有规划阶段之前，禁止写代码、禁止直接修改文件、禁止直接修改文件、禁止跳过需求采访。**

## 激活时行为

收到 `/dev-plan` 后，立即进入第1阶段。不要先解释流程，直接开始提问。

---

## 阶段流程

### 第1阶段：需求采访

通过多轮对话收集需求信息。每轮最多提问 **2~3个问题**，逐步确认以下内容：

#### 项目背景
1. 项目是做什么的？
2. 当前架构是什么？
3. 本次涉及哪些模块？

#### 目标
4. 用户真正想解决什么问题？
5. 为什么要做这件事？
6. 最终效果是什么？

#### 范围
7. 本次明确要做什么？
8. 本次明确不做什么？
9. 哪些模块/文件/配置不能修改？

#### 参考资料
10. 是否有设计文档？
11. 是否有参考实现？
12. 是否有历史方案？

#### 交付
13. 最终交付什么？
14. 完成标准是什么？
15. 如何验证成功？

**规则：每轮最多2~3个问题，逐步推进，禁止一次性列出所有问题。**

---

### 第2阶段：任务说明书

收集足够信息后，生成《任务说明书》：

```
## 任务说明书

### 项目背景
[概述项目及当前状态]

### 任务目标
[本次要实现的具体目标]

### 实施范围
[明确包含的内容]

### 非目标范围
[明确不包含的内容]

### 受保护区域
[禁止修改的模块、文件、配置]

### 输入资料
[设计文档、参考实现、历史方案等]

### 输出结果
[最终交付物]

### 完成标准
[什么状态算完成]

### 验证方式
[如何验证成功]

### 待确认事项
[仍需用户确认的内容]
```

**等待用户确认后方可进入第3阶段。**

---

### 第3阶段：实施计划

用户确认任务说明书后，生成《开发任务计划》：

```
## 开发任务计划

### 方案概述
[整体技术方案简述]

### 涉及模块
[需要改动的模块列表]

### 修改文件
[需要修改的文件列表]

### 新增文件
[需要新增的文件列表]

### 风险分析
[潜在风险及应对措施]

### 实施步骤
Step 1: [具体步骤]
Step 2: [具体步骤]
Step 3: [具体步骤]
...

### 回滚方案
[如果出现问题如何回退]

### 验证方案
[每步完成后如何验证]
```

**等待用户确认后方可进入第4阶段。**

---

### 第4阶段：验收清单

用户确认实施计划后，生成《验收清单》：

```
## 验收清单

### 功能验收
- [ ] [功能点1]
- [ ] [功能点2]

### 回归验证
- [ ] [现有功能不受影响]

### 编译验证
- [ ] [项目可正常编译]

### 单元测试
- [ ] [新增测试覆盖]
- [ ] [现有测试通过]

### 人工验证
- [ ] [手动验证步骤]

### 风险检查
- [ ] [已识别风险已规避]

### 完成判定
[如何判定整体完成]
```

**等待用户确认后方可进入第5阶段。**

---

### 第5阶段：开始实施

**只有同时满足以下条件时，才能写代码：**

- [ ] 任务说明书已确认
- [ ] 开发计划已确认
- [ ] 验收清单已确认

**否则继续提问，不得开始编码。**

---

### 第6阶段：交付报告

实施完成后，输出：

```
## 交付报告

### 已完成项
[列出已完成的内容]

### 未完成项
[如实列出未完成的内容，不得隐瞒]

### 修改文件
[列出所有修改过的文件]

### 验证结果
[验收清单各项目的验证结果]

### 风险说明
[实际遇到的风险及处理情况]

### 后续建议
[后续优化或待办事项]
```

---

## 全局规则

| 规则 | 描述 |
|------|------|
| 每轮限制 | 每轮最多2~3个问题 |
| 禁止跳步 | 不得跳过任何阶段 |
| 禁止提前编码 | 未到第5阶段不得写任何代码 |
| 需要确认 | 进入下一阶段前必须得到用户确认 |
| 诚实报告 | 第6阶段不得隐瞒失败项 |

---

## 每轮结尾格式

每次提问后，在末尾附上当前进度：

```
---
📋 当前阶段：第X阶段 — [阶段名称]
✅ 已收集：[简要列出已知内容]
⏳ 待收集：[本阶段还缺少的信息]
```
