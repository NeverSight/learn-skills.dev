# 功能分析文档生成

## 触发方式

用户输入 `/dev-analysis` 或明确要求：

- "分析一下这个功能"
- "生成 XX 模块的文档"
- "帮我理解这段代码"
- "整理一下这个功能的文档"

## 核心原则

本 Skill 仅负责以下三件事：

1. **理解代码**
2. **解释代码**
3. **沉淀文档**

禁止输出以下内容：

- Bug 分析
- 风险分析
- 技术债务
- 代码质量评价
- 重构建议
- 优化建议

## 工作流程

### 第一阶段：需求确认

不要立即分析代码。先向用户确认必要信息，每次最多提问 3 个问题。

需要确认的内容：

1. **分析目标**：学习代码 / 补充文档 / 项目交接 / 新成员培训 / 功能梳理
2. **功能范围**：具体要分析的功能或模块名称
3. **代码位置**：相关目录或文件路径
4. **输出位置**：文档保存目录，例如 `docs/{模块名}/`

信息不足时继续提问，直到可以开始分析。

### 第二阶段：代码阅读

根据确认的范围阅读代码，重点分析：

- **模块结构**：目录结构、模块关系、文件职责
- **调用关系**：入口、调用链、关键对象、核心流程
- **数据流**：输入来源、数据处理、输出结果、状态变化
- **配置依赖**：配置文件、参数、资源文件、第三方依赖

### 第三阶段：文档生成

按照 [TEMPLATE.md](TEMPLATE.md) 生成标准功能文档。

输出位置：

```
docs/{模块名称}/README.md
```

如果文件已存在：

- 保存为 `docs/{模块名称}/README-v2.md`
- 或询问用户是否更新原文档

## 输出要求

- 必须根据实际代码生成
- 不得编造不存在的逻辑
- 不得猜测
- 无法确认的信息标记为：
  - `【待确认】`
  - `【代码中未发现】`

## 完成后的输出

分析完成后，向用户输出：

1. **已分析文件**
2. **文档保存位置**
3. **功能摘要**

方便开发人员快速查看。
