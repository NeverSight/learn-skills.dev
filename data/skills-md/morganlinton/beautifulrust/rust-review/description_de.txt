Überprüfen Sie bestehenden Rust‑Code hinsichtlich Idiomatik, API‑Design, Fehlerbehandlung, Sicherheit und Wartbarkeit und erstellen Sie einen priorisierten Bericht, in dem jeder Befund die verletzte Regel nennt und eine konkrete Lösung anbietet. Verwenden Sie dies stets, wenn ein Nutzer bittet, Rust‑Code, ein Crate, ein Modul, eine .rs‑Datei, einen Diff oder einen Pull‑Request zu prüfen, zu auditieren, zu kritisieren, zu bewerten oder zu „checken“, oder wenn er fragt, woran etwas nicht stimmt oder wie er den Code idiomatischer gestalten kann – selbst wenn das Wort „review“ nicht ausdrücklich genannt wird. Kombiniert wird dies mit der rust‑best‑practices‑Fähigkeit, die das Schreiben von neuem Code abdeckt.
