Entwerfen und prüfen Sie Softwarearchitekturen von den geschäftlichen Treibern über Systemgrenzen, Kompromisse, Laufzeitverhalten, Evolution und Architekturpraxis. Verwenden Sie dies, wenn Sie eine Greenfield‑ oder Zielarchitektur auswählen, modulare Monolithen und Service‑Formen vergleichen, verteilte Konsistenz, Replikation, Partitionierung, Koordination, Reihenfolge, Transaktionsisolierung oder Fehlverhalten entwerfen, die Evidenz für die Architektur‑Fitness definieren oder eine konsequente Architektur‑Review erleichtern. Verwenden Sie es nicht für Reverse Engineering, API‑Vertragssemantik, Datenplattform‑Design, Implementierung, Infrastrukturbetrieb, Sicherheitslebenszyklus oder Migrationsausführung; leiten Sie diese an die benannten Fachkompetenzen weiter.
