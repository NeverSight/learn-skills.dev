Operare, configurare, effettuare benchmark e risolvere i problemi dei server di inferenza vLLM: distribuzione Docker e Kubernetes, configurazione del modello consapevole della quantizzazione (parallelismo tensoriale, cache KV), servizio API compatibile con OpenAI, benchmark di throughput e latenza, ottimizzazione del batching continuo, operazione GPU e aggiornamento/rollback. Utilizzare quando si distribuisce o si esegue un server vLLM (vllm serve, vllm/vllm-openai), dimensionando un modello e la sua cache KV per GPU, selezionando quantizzazione e parallelismo, servendo tramite endpoint /v1, misurando il throughput o la latenza del servizio, ottimizzando il batching o diagnosticando guasti GPU, OOM o di avvio in una distribuzione vLLM. Non utilizzare per l'addestramento del modello, il fine‑tuning, la progettazione di set di valutazione o la metodologia di selezione del motore (cioè ml‑engineering), né per l'operatività dello stack llama.cpp con modelli GGUF (cioè llama‑cpp); altri motori di inferenza (TGI, Ollama, Triton) sono fuori ambito.
