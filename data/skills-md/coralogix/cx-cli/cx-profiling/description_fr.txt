Interrogez les données de profilage continu de Coralogix avec l’interface en ligne de commande `cx profiling` — trouvez quels services utilisent le plus de CPU ou de mémoire, quels types de profils un service possède, par quels critères les profils peuvent être filtrés, quand l’utilisation a picé et quel pod ou quelle version en est la cause, ainsi que quels chemins de code et fonctions un service consomme en CPU ou en mémoire (graphes en flamme). Utilisez cette commande lorsque l’utilisateur demande « quels services utilisent le plus de CPU », « principaux consommateurs de mémoire », « à quoi le service X consacre‑t‑il son CPU », « fonctions chaudes », « graphe en flamme pour un service », « pourquoi ce service utilise‑t‑il autant de CPU », « allocations de mémoire par fonction », « pic de CPU par pod », « quelle version a augmenté le CPU », « profilage continu », « données de profilage », ou souhaite explorer les profils d’un service. Pour connaître la quantité de CPU ou de mémoire qu’un service ou un pod utilise et savoir s’il est saturé, utilisez plutôt `cx-service-catalog`.
