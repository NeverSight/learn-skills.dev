Tuning consigliativo di Kafka solo a scopo informativo per Confluent Cloud o Confluent Platform in base alla priorità: latenza, throughput, disponibilità o durabilità. Da utilizzare quando ci si richiede di dimensionare un topic pianificato o di ottimizzare un cluster, topic, producer o consumer esistente per un obiettivo quantificato, ad esempio ridurre la latenza p99 o evitare scritture riconosciute perse. Analizza la configurazione in sola lettura e raccomanda modifiche, compromessi e validazione; l'amministratore le applica. NON attivare per: cluster WarpStream o Apache Kafka solo OSS; authoring, tuning o debugging di Flink SQL o UDF (usare confluent-cloud-flink-sql o flink-udf); tuning di Kafka Connect; nuova implementazione client Java/Python (usare developing-kafka-java-client o developing-kafka-python-client); sviluppo di Kafka Streams/KStream/KTable (usare kafka-streams-programming); o pipeline CDC, Tableflow o Iceberg (usare confluent-cloud-cdc-tableflow).
