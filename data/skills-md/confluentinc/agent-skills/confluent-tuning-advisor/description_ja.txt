優先順位: レイテンシ、スループット、可用性、または耐久性に基づく、Confluent Cloud または Confluent Platform 向けの助言のみの Kafka チューニング。計画中のトピックのサイズ決定や、既存のクラスター、トピック、プロデューサー、コンシューマーを、p99 レイテンシの低減や確認済み書き込みの喪失なしといった定量的目標に合わせて調整する場合に使用します。設定を読み取り専用で検査し、変更、トレードオフ、検証を推奨します；管理者がそれらを適用します。以下の場合には起動しないでください: WarpStream または Apache Kafka OSS のみのクラスター；Flink SQL または UDF の作成、チューニング、デバッグ（confluent-cloud‑flink‑sql または flink‑udf を使用）；Kafka Connect のチューニング；新しい Java/Python クライアント実装（developing‑kafka‑java‑client または developing‑kafka‑python‑client を使用）；Kafka Streams/KStream/KTable の開発（kafka‑streams‑programming を使用）；または CDC、Tableflow、Iceberg パイプライン（confluent‑cloud‑cdc‑tableflow を使用）。
