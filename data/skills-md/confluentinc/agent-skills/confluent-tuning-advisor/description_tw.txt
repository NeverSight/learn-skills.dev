僅提供建議性的 Kafka 調校，適用於 Confluent Cloud 或 Confluent Platform，依優先順序為：延遲、吞吐量、可用性或持久性。當需要為計畫中的 topic 估算規模或為現有叢集、topic、producer 或 consumer 調校至具體目標（如降低 p99 延遲或避免遺失已確認的寫入）時使用。僅以唯讀方式檢視設定，並建議變更、權衡與驗證；由管理員實際執行。請勿在以下情況觸發：WarpStream 或僅使用 Apache Kafka OSS 的叢集；Flink SQL 或 UDF 的編寫、調校或除錯（請使用 confluent‑cloud‑flink‑sql 或 flink‑udf）；Kafka Connect 調校；新 Java/Python 用戶端實作（請使用 developing‑kafka‑java‑client 或 developing‑kafka‑python‑client）；Kafka Streams/KStream/KTable 開發（請使用 kafka‑streams‑programming）；或 CDC、Tableflow、Iceberg 管線（請使用 confluent‑cloud‑cdc‑tableflow）。
