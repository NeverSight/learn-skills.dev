앱(특히 웹앱)을 스트레스 테스트한다 — 신뢰성을 확인하고, 정상 경로를 꼼꼼히 살피며, 문제 상황을 만들어 보고, 다양한 신규 사용자 패널을 운영하고, 코드 내 버그를 찾아낸다 — 에이전트 브라우저, API 스크립트 혹은 두 가지를 모두 이용해. 사용자가 버그, 엣지 케이스, 난점 등을 찾고 싶을 때, 앱을 고장 나게 하거나 UX·API를 견고하게 만들고 싶을 때, 흐름을 QA하고 싶을 때, 출시 혹은 온보딩 QA를 진행하고 싶을 때, 실제 사용자를 혼란스럽게 하는 부분을 테스트하고 싶을 때, 다양한 사용자나 페르소나를 시뮬레이션하고 싶을 때, 혹은 사용자가 발견하기 전에 문제를 잡아내고 싶을 때 활용한다 — 사용자가 단순히 “앱을 써봐”, “이걸 테스트해”, “API를 호출해”, “뭘 깨지는지 확인해” 라고만 말해도 마찬가지다.
