Stressare le app (soprattutto le webapp) — confermare l'affidabilità, setacciare i percorsi felici, creare scompiglio, far operare un panel di utenti nuovi e distinti e cacciare i bug nel codice — tramite browser agente, script API o entrambi. Usare ogni volta che l'utente vuole trovare bug, casi limite, nodi, rompere un'app, rafforzare l'UX o le API, fare QA di un flusso, eseguire QA di lancio o onboarding, testare cosa confonde gli utenti reali, simulare utenti o personas diversi o intercettare problemi prima che li incontrino gli utenti — anche se dicono solo “prova l'app”, “testa questo”, “colpisci l'API” o “vedi cosa si rompe”.
