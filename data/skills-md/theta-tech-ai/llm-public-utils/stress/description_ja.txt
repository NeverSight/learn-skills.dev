アプリ（特にウェブアプリ）をストレステストし、信頼性を確認し、ハッピーパスをくまなく検証し、意図的に問題を起こし、さまざまな初回ユーザーのパネルを実行し、コード中のバグを追いかけます――エージェントブラウザ、API スクリプト、あるいはその両方を使用して。ユーザーがバグやエッジケース、結び目、アプリの破損、UX や API の強化、フローの QA、ローンチやオンボーディングの QA、実際のユーザーを混乱させる要因のテスト、異なるユーザーやペルソナのシミュレーション、あるいはユーザーが気付く前に問題を捕まえる必要があるときに、（たとえ「アプリを試すだけ」「これをテストするだけ」「API を叩くだけ」「何が壊れるか見るだけ」でも）いつでも使用してください。
