Effectuer des tests de résistance sur les applications (en particulier les webapps) — confirmer leur fiabilité, explorer les chemins heureux, semer le chaos, réunir un panel d’utilisateurs novices distincts et traquer les bugs dans le code — via un navigateur agent, des scripts API ou les deux. Utilisez-le chaque fois que l’utilisateur veut trouver des bugs, des cas limites, des nœuds, casser une application, renforcer l’UX ou les API, QA un flux, lancer ou effectuer un QA d’onboarding, tester ce qui perturbe les utilisateurs réels, simuler différents utilisateurs ou personas, ou détecter les problèmes avant les utilisateurs — même s’ils se contentent de dire « essayez l’app », « testez ceci », « interrogez l’API » ou « voyez ce qui se casse ».
