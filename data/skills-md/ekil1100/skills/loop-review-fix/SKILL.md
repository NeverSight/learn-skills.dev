# 迭代检视修复

目标：用有界循环把已知改动修到可交付；不为了循环而制造意见。

## 触发边界

- 只 review、只检视、明确不要改：只给检视意见。
- 要求修复、处理 findings、检视后继续改：执行循环。
- 用户未指定轮数时最多 50 轮。

## 每轮流程

1. 触发可用的 subagent 检视当前状态，等待并读取 review 结果：让 subagent 读取相关文件、diff 和失败输出，优先找正确性、需求偏差、回归、安全/隐私、schema/格式、验证缺口。
2. 如果当前环境没有可用 subagent，则由当前 agent 完成同等 review。
3. 形成意见：每条必须具体、可执行、能指向文件或行为；无意见就停止。
4. 修复意见：只改本轮有依据的问题，保留无关用户改动，沿用现有项目模式。
5. 验证：跑最窄有用检查，如测试、lint、类型、渲染或结构化校验；跑不了就说明原因并人工复核。
6. 基于新状态进入下一轮。

## 停止条件

- 本轮无问题。
- 达到最大轮数。
- 遇到需要用户决策的阻塞。

## 最终回复

简明说明实际轮数 `N / MAX`、review 来源与结果、修改文件、关键修复、验证结果、无法执行的检查和剩余事项；没有剩余事项就写“无”。
