Estimez la durée d’une tâche de codage en vous basant sur l’historique mesuré de l’utilisateur plutôt que sur l’intuition. Utilisez cette compétence chaque fois que quelqu’un demande une estimation, une ETA, un planning ou une date limite pour une fonctionnalité, un bug, une refactorisation, une migration, un script ou une enquête — « combien de temps cela prendra-t-il », « donnez‑moi une estimation », « combien d’heures cela représente », « cela peut‑il être livré aujourd’hui », « est‑ce un travail d’une journée », « combien de jours pour l’ensemble de l’épopée », « que dois‑je dire au client », « estimez ce ticket », « dimensionnez cela » — et également lorsque la demande est sceptique (« est‑ce réaliste », « pourquoi cela a pris trois jours »). Utilisez‑la également pour le mécanisme derrière les estimations : configurer ou calibrer l’estimation, reconstituer le registre des tâches à partir des transcriptions Claude Code passées, enregistrer les réels d’une tâche terminée (« enregistrez cette tâche », « consignez‑ça », « ajoutez‑cela au registre »), et relancer le calibrage ou vérifier si les estimations passées étaient correctes. Activez‑la même si le mot « estimation » n’apparaît jamais — une question sur la charge de travail ou la durée d’une tâche fait appel à cette compétence.

Veuillez toujours répondre dans la langue de l’utilisateur.
