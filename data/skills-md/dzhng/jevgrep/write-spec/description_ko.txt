큰 기능을 specs/ 내의 feature 디렉터리 아래에서 독립적으로 검증 가능하고 사람에게 검토 가능한 슬라이스로 나눕니다. 사전 질문이 필요하거나, API 시메, 브라우저에서 재생 가능한 체크포인트, HTML 시각화, 스크린샷 게이트, 단계별 구현 계획, 재귀적인 fog‑of‑war 재분할, 혹은 슬라이스하기 전 레퍼런스 구현·베스트 프랙티스에 대한 사전 조사 등이 요구되는 위험하거나 다단계 기능 작업에 사용합니다. 이는 프로젝트의 검증 하니스와 스크린샷 게이트(브라우저 체크포인트)와 짝을 이루며, [refactor‑clean](../refactor-clean/SKILL.md) (구현된 스펙을 검토해 계획이 단일 소유자 아키텍처를 설명하도록 하고, 기능이 억지로 끼워넣어지지 않게 함), [screenshot‑critique](../screenshot-critique/SKILL.md) 및 [compare‑screenshots](../compare-screenshots/SKILL.md) (시각적 게이트), 그리고 코드 리뷰 단계(각 슬라이스가 적용되기 전에 감사)를 포함합니다.
