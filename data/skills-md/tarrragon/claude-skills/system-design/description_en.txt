When receiving a requirement for a new system, new feature, or service upgrade, the system design process includes: inventorying requirements, estimating capacity from the business side, deciding based on change cost whether to finalize / implement now / postpone, the trigger indicators for postponed design, covering backend, frontend, and infrastructure, and includes feature flags, A/B testing, external API revisions, mobile app releases, and changes that require scaling before going live. Triggers: system design, overdesign, when to scale, feature flag, A/B test, launch plan, app release, hot update.
