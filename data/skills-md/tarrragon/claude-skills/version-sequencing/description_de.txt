Planung der Versionssequenz – nachdem die Spezifikationen abgeschlossen sind, die ausstehende Entscheidungsliste in eine Versionssequenz konsolidieren (ein Integrationstest pro Version) und dann das erste Versions‑Ticket öffnen. Enthält mehrstufige Review‑Abschlussprüfungen, Auswahl der geteilten Achse, ausstehende „blockedBy“-Bindungen an die Version und das zuerst Öffnen von Grundlagentickets. Die Sequenz ist eine Reihenfolge, kein Gate; sie bindet nicht an vollständiges Agile. Trigger‑Wörter: Versionsplanung, Versionssequenz, Reihenfolge der Integrationstests, geplante Version, Ticket‑Planung, Meilenstein, Roadmap. Verwenden, wenn die Spezifikationen fertig sind, bevor das erste Implementierungs‑Ticket geschrieben wird. NICHT verwenden für die Planung von Wellen innerhalb einer einzelnen Version (Version‑Bootstrap verwenden).
