新しい Linux システム（VM または物理）をインストールする際や、Linux/macOS システムの問題をトラブルシューティングするための標準化された診断プロトコルです。核心となる方針は、視覚的な推測に頼らず、権威ある状態情報を読み取ることです。まずプラットフォームの座標（ディストリビューション／アーキテクチャ／パッケージマネージャ）を特定し、症状に応じた対応する権威ある情報源を参照します。対象は、SSH 接続失敗、端末出力の文字化け、サービスの停止または再起動ループ、プロセスは存続しているがサブシステムが停止している状態、権限拒否、パッケージマネージャの失敗、ディスク容量不足・ファイルシステムの読み取り専用、音声が出ない、VT のブラックスクリーン、OOM による強制終了、そして障害をプッシュ通知に変換することです。

トリガー例：Linux のインストール、新規 VM、ファーストブート検証、SSH が接続できない、接続拒否、接続タイムアウト、端末文字化け、`systemctl status`、`journalctl`、サービス失敗、再起動ループ、プロセスは生きているが応答なし、誤解を招く `pgrep`、Permission denied、EACCES、Operation not permitted、コマンドが見つからない、パッケージが見つからない、dpkg ロック、pacman DB ロック、部分的アップグレード、未束縛変数、ポータブルシェルスクリプト、bash 3.2、タイムアウトが見つからない、コンテナで sudo がない、期限切れキーリング、PATH が適用されていない、ディスク容量不足、ファイルシステムが読み取り専用、OOM、exit 137、`dmesg`、ブラックスクリーン、getty、`chvt`、音声なし、`wpctl`、DNS 解決失敗、マシンが応答しない、サービスアラート、OnFailure、ntfy、ハートビート監視、Linux インストール、Linux デバッグ、systemd、権威ある状態情報。
