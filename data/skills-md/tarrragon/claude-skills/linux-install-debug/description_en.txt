Standardized diagnostic protocol for installing a new Linux (VM or physical) or troubleshooting Linux/macOS system issues. The core discipline is to read authoritative state, not rely on visual guesses: first determine the platform coordinates (distribution / architecture / package manager), then consult the corresponding authoritative source based on the symptoms. Covers SSH not connecting, garbled terminal output, service failed or restart loop, process alive but subsystems dead, permission denied, package manager failures, disk full and filesystem read‑only, silent audio, VT black screen, being killed by OOM, and turning failures into push alerts. Triggers: installing Linux, new VM, first‑boot verification, ssh not connecting, connection refused, connection timeout, garbled terminal, systemctl status, journalctl, service failed, restart loop, process alive but unresponsive, pgrep deceiving, permission denied, EACCES, operation not permitted, command not found, unable to locate package, dpkg lock, pacman db lock, partial upgrade, unbound variable, portable shell script, bash 3.2, timeout not found, container without sudo, expired keyring, PATH not picked up, disk full, filesystem read‑only, OOM, exit 137, dmesg, black screen, getty, chvt, no sound, wpctl, DNS resolution failure, machine unresponsive, service alert, OnFailure, ntfy, heartbeat monitoring, linux install, linux debug, systemd, authoritative state.
