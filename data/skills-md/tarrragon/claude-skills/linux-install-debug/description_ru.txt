Стандартизированный диагностический протокол для установки новой системы Linux (VM или физической) или устранения проблем Linux/macOS. Основная дисциплина — читать авторитетное состояние и не полагаться на визуальные догадки: сначала определить координаты платформы (дистрибутив, архитектура, менеджер пакетов), затем обратиться к соответствующим авторитетным источникам по симптомам. Охватывает сбои подключения SSH, искажённый вывод терминала, неудачные сервисы или циклы перезапуска, процессы, которые живы, но подсистемы мертвы, отказ в доступе, сбои менеджеров пакетов, заполненный диск и файловая система только для чтения, беззвучный звук, чёрный экран VT, завершение из‑за OOM и преобразование сбоев в push‑уведомления.  

Триггеры: установка Linux, новая VM, проверка при первом запуске, ssh не может подключиться, отказ в соединении, тайм‑аут соединения, искажённый терминал, systemctl status, journalctl, сервис не запущен, цикл перезапуска, процесс жив, но не отвечает, вводящий в заблуждение pgrep, отказ в доступе, EACCES, операция не разрешена, команда не найдена, невозможно найти пакет, блокировка dpkg, блокировка базы pacman, частичное обновление, необъявленная переменная, переносимый shell‑скрипт, bash 3.2, не найден timeout, контейнер без sudo, просроченный keyring, PATH не унаследован, диск заполнен, файловая система только для чтения, OOM, exit 137, dmesg, чёрный экран, getty, chvt, нет звука, wpctl, сбой разрешения DNS, машина не отвечает, оповещение сервиса, OnFailure, ntfy, мониторинг heartbeat, установка linux, отладка linux, systemd, авторитетное состояние.
