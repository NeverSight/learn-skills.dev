TDD end‑to‑end guidance tool.

Use for:
1. Start the TDD process for a new feature (Phase 0‑4)
2. Advance to the next TDD stage
3. Phase 1 SOLID principle‑driven functional decomposition analysis
4. View current TDD progress and stage status
5. Assess whether Phase 4 refactoring is needed and evaluate 3b split
6. Link requirement documents (Spec/UC) to the testing process
7. Batch test design for the start of a new project
8. Red‑light test stub strategy (static language compilation passes)
9. Implement ticket split boundary determination (test turning green acceptance point)
10. Test ↔ UseCase traceability matrix

Use when: starting new feature development, entering any TDD phase, needing SOLID split guidance, needing to confirm the current TDD stage, needing to make a Phase 4 exemption judgment, writing tests starting from spec/UC, planning batch tests for a new project, red‑light test fails to compile and requires a stub, judging whether ticket split granularity is reasonable, confirming whether tests cover UC scenarios.

Triggers: tdd, test, red light, green light, stub, split granularity, test coverage, traceability, spec‑to‑test, UC‑to‑test, batch testing, new project testing, test turns green, Phase 0, Phase 1, Phase 2, Phase 3, Phase 4, refactor evaluation, outside‑in, outer‑ring red light, on‑device, real‑device verification, wip tag.
