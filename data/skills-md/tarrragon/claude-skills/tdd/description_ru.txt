Инструмент полного руководства по процессу TDD. Применяется для: (1) Запуск процесса TDD для новой функции (фазы 0‑4); (2) Переход к следующей стадии TDD; (3) Анализ функциональной декомпозиции в фазе 1, основанный на принципах SOLID; (4) Просмотр текущего прогресса TDD и статуса стадии; (5) Оценка необходимости рефакторинга в фазе 4 и оценки разбивки 3b; (6) Связывание документов требований (Spec/UC) с процессом тестирования; (7) Проектирование пакетных тестов для старта нового проекта; (8) Стратегия заглушек для тестов с «красным светом» (успешные статические компиляции языка); (9) Реализация интерпретации границы разбивки тикетов (точка принятия, когда тест переходит в «зеленый»); (10) Матрица трассируемости Тест↔UseCase. Применять, когда: начинается разработка новой функции, происходит вход в любую фазу TDD, требуется руководство по разбивке по SOLID, необходимо подтвердить текущую стадию TDD, нужно решить о свободе от фазы 4, пишутся тесты на основе спецификации/UseCase, планируется пакетное тестирование нового проекта, компиляция «красного» теста падает и нужна заглушка, оценивается целесообразность гранулярности разбивки тикетов, подтверждается покрытие тестами сценариев UseCase. Триггеры: tdd, test, red‑light, green‑light, stub, split granularity, test coverage, traceability, spec‑to‑test, UC‑to‑test, batch testing, new project testing, test turning green, Phase 0, Phase 1, Phase 2, Phase 3, Phase 4, refactoring assessment, outside‑in, outer‑ring red‑light, on‑device, real‑device verification, wip tag.
