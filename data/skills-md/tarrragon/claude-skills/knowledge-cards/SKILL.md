# Knowledge Cards（知識卡生命週期）

知識卡是內容體系的原子抽象層：一張卡承載一個術語的核心概念、讓文章用連結取代行內解釋、讓解釋只寫一次被全體引用。本 skill 標準化卡片的完整生命週期——從「這個詞該不該有卡」到「模組級的缺卡 audit」——讓建卡動作在任何模組、任何批次都走同一套判斷標準。

---

## 生命週期六站

| 站      | 核心問題               | 關鍵判斷標準                                                                                                                                                                                                                                      |
| ------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 判斷標準  | 這個術語該有卡嗎？     | 教學需求：目標讀者群裡最不熟悉的那端能不能理解；出現頻率只是輔助訊號                                                                                                                                                                          |
| 1′ 壓力 | 這段內容該搬進卡嗎？   | 內容壓力：文章某段的概念展開會過長、砍掉範例或推導讀者就接不住——跨篇可用就拆卡、見「內容壓力是第二個建卡入口」段                                                                                                                              |
| 2 落點  | 卡住在哪個目錄？       | 概念的主要領域歸屬；一卡一住址、跨模組用連結不重複建卡。同一個對象已經在兩篇各自被分解過（兩套階段表 / 欄位組）時，卡層通常就是該收斂到的住址——理由是欄位與成員的定義本來就是卡的責任、而卡是可被多篇引用的獨立短頁，章節各自沿用卡的語彙、只保留自己的判讀。**不要用入連數當理由**：入連數量的是整頁被引用幾次，而要選載體的對象是頁裡那組成員，一次實測章節的整頁入連是卡的一倍多、而那些引用沒有一條是為了拿欄位定義 |
| 3 撰寫  | 卡片長什麼樣？         | 四段結構（定義 / 概念位置 / 訊號與例子 / 判讀方式）＋首段與概念位置段鄰卡連結                                                                                                                                                                 |
| 4 登記  | 卡片在哪些地方要現身？ | collection index 分類表＋lint 工具的作用域清單——兩者都是必經註冊點                                                                                                                                                                            |
| 5 回填  | 文章怎麼接上卡？       | 每篇文章該術語第一次出現處連卡、後續裸用                                                                                                                                                                                                      |
| 6 Audit | 存量模組的缺口在哪？   | 詞頻掃描 × 缺卡判定矩陣 → 優先序 → 批次建卡                                                                                                                                                                                                   |

## 缺卡判定矩陣（速查）

術語處理分三級：行內展開（正文 1-2 句定義）、連卡、裸用。判定用兩軸——**術語在本文的角色**（主線 / 支撐 / 背景）×**是否在本文的前置知識基線內**（基線＝模組讀者定位 ∪ 閱讀路線中前置篇章教過的主線術語）。**基線取的是讀者的知識存量，讀者定位在這裡供應的是他讀過哪些前置篇章，不是他有能力理解到什麼程度**——把「讀者是專業人士」這種能力宣稱直接算進基線，它會膨脹到涵蓋整個領域的名詞，缺卡判定因此永遠不觸發，而不觸發與「檢查過、沒有缺口」在報告上同形：

| 術語角色 | 基線外                        | 基線內                     |
| -------- | ----------------------------- | -------------------------- |
| 主線     | 行內展開＋連卡                | 行內展開（本文就是在教它） |
| 支撐     | **連卡（卡不存在 → 先建卡）** | 連卡（預設）或裸用         |
| 背景     | 連卡                          | 可裸用                     |

「支撐 × 基線外 × 無卡」就是缺卡的精確定義。文章越深、越多術語落入基線、行內解釋自然遞減；連卡密度不遞減——它是空降讀者（搜尋直達深度篇）的回路。

## 內容壓力是第二個建卡入口

教學需求（站 1 判斷標準）從讀者缺口出發；**內容壓力**從寫作現場出發——文章寫到「這個概念展開會讓本段過長、判斷標準裝不進表格格、但砍了讀者接不住」時、這個壓力本身就是建卡訊號。兩個入口指向同一個動作、判斷標準互補。

- **範例是卡片的正當組成**：概念加範例一起住進卡片、文章引用卡片承接論證——範例住在卡裡讓每篇文章自然短、細節搬家而非消失。
- **拆卡對象限支撐與背景概念**：主線概念（本篇論證繞著它轉）必須行內展開、外部化會讓讀者跳出去讀卡、論證線斷裂——缺卡判定矩陣的主線列優先於內容壓力入口。
- **壓縮內容遷就容器在出口之外**：判斷標準裁成殘語、範例被砍是違規；出口是延伸段（本篇專屬）或拆卡（跨篇可用）、內容量不是可裁的變數。

## 註冊點清單（漏一個都不報錯）

新卡片或新卡片目錄需要在數個彼此獨立的註冊點現身、漏掉任何一個都不產生錯誤訊號：

1. **Collection index 分類表**——目錄的索引頁要列出這張卡（實測發現過整批卡運作正常、文章連得到、只有索引層看不見它們）
2. **Lint 工具的作用域清單**——frontmatter 必填檢查跟卡片結構檢查（鄰卡連結 / orphan）通常是**兩個獨立的目錄清單**、都要登記。作用域外的目錄跑檢查會得到零 error——那是「沒被看」不是「沒問題」、檢查通過的假象比沒檢查更危險
3. **上層入口**——新建卡片目錄時、模組首頁或站台首頁的對應分類段要同步
4. **Weight 編號帶**——新卡接續該目錄的既有編號帶、不隨手給不撞號的值

## 跟其他寫作流程的分工

本 skill 管卡片的生命週期（判斷標準 / 落點 / 登記 / 回填 / audit）。卡片內文的字句層品質（正向陳述、中性 register、地區用語）屬單篇寫作方法的範疇——專案若有對應的寫作 skill、批次建卡後的字句層自審套用該 skill 的 keyword bank；批次多輪審查的 frame 規劃屬 review 流程 skill。三者疊加、互不取代。
