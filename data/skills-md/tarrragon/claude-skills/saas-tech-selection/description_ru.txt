Соглашение об интервью по проектированию и отбору при инициализации SaaS‑репозитория: после закрепления сначала пройти ворота модели доставки (хостинговая платформа / вертикальный SaaS / автоматизация офисного экосистемы / BaaS / полухостинговый CMS / собственная разработка), только после того как собственная разработка утверждена, выводить функции и риски из пользовательских операций (BDD), разбивать домен и события (DDD) согласно SRP / OCP, затем привязывать технические измерения к скелету домена для пошаговой проверки, прикладывать к каждому измерению несокрываемый базовый уровень защиты и формировать записи о проектных решениях и рекомендации по скелету. Триггеры: инициализация репозитория, новый проект, запуск нового сервиса, выбор SaaS, выбор технологий, стек технологий, решение о самостоятельной разработке, хостинговая платформа, Shopify, Wix, Firebase, WordPress, Apps Script, DDD, разбивка домена, событийно‑ориентированное, event storming, BDD, сценарии поведения, инвентаризация пользовательских операций, выбор базы данных, выбор очереди, решение об использовании Redis, решение об использовании k8s, архитектура MVP, скелет репозитория, старт проекта, оценка стека, интервью по отбору, интервью по архитектуре.
