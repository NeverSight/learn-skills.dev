Accord d'entretien de conception et de sélection lors de l'initialisation d'un dépôt SaaS : après l'ancrage, passer d'abord la porte du modèle de livraison (plateforme hébergée / SaaS vertical / automatisation de l'écosystème bureautique / BaaS / CMS semi‑hébergé / solution auto‑construite), et ce n’est qu’une fois la solution auto‑construite établie que l’on dérive les fonctionnalités et les risques à partir des opérations utilisateur (BDD). Ensuite, découper les domaines et les événements selon le SRP / OCP (DDD), rattacher les dimensions techniques sous le squelette du domaine pour une vérification point par point, garantir que chaque dimension possède une base de protection non contournable, et produire les enregistrements de décisions de conception ainsi que les recommandations de scaffold.

Déclencheurs : initialisation du dépôt, nouveau projet, lancement d’un nouveau service, sélection SaaS, sélection technologique, stack technologique, décision de construire en interne, plateforme hébergée, Shopify, Wix, Firebase, WordPress, Apps Script, DDD, découpage de domaine, pilotage par événements, event storming, BDD, scénarios comportementaux, inventaire des opérations utilisateur, choix de base de données, choix de file d’attente, utilisation de Redis, utilisation de K8s, architecture MVP, scaffold du dépôt, démarrage du projet, évaluation du stack, entretien de sélection, entretien d’architecture.
