Protocolo de entrevista de diseño y selección para inicializar un repositorio SaaS: después de establecer el ancla, pasar primero por la puerta del modelo de entrega (plataforma hospedada / SaaS vertical / automatización del ecosistema de oficina / BaaS / CMS semi‑hospedado / auto‑construido); solo una vez que se haya establecido la auto‑construcción derivar características y riesgos de las acciones del usuario (BDD), dividir dominios y eventos (DDD) según SRP / OCP, luego adjuntar las dimensiones técnicas bajo el esqueleto del dominio y verificar cada ítem, cada dimensión con una línea base protectora no opcional, y producir registros de decisiones de diseño y recomendaciones de andamiaje.  

Desencadenantes: inicialización del repositorio, nuevo proyecto, lanzamiento de nuevo servicio, selección de SaaS, selección de tecnología, stack tecnológico, decidir si auto‑construir, plataforma hospedada, Shopify, Wix, Firebase, WordPress, Apps Script, DDD, segmentación de dominios, orientado a eventos, event storming, BDD, escenarios de comportamiento, inventario de operaciones de usuario, selección de base de datos, selección de cola, decidir si usar Redis, decidir si usar K8s, arquitectura MVP, andamiaje del repositorio, inicio del proyecto, evaluación de stack, entrevista de selección, entrevista de arquitectura.
