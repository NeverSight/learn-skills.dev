Directives de conception de l'architecture Riverpod Provider — injection de dépendances, ségrégation d'interface, règles de fournisseur de câblage obligatoire et d'association de tests de câblage, faisabilité des tests. Utilisation pour : (1) concevoir de nouvelles classes ViewModel/Notifier, (2) vérifier que l'injection de dépendances du Provider et le câblage racine de l’application sont corrects, (3) associer les tests de câblage lors de la déclaration d’un fournisseur de câblage obligatoire avec `throw UnimplementedError`, (4) configurer `ProviderScope.overrides` dans les tests, (5) détecter une utilisation incorrecte de `ref.read/watch` ou lorsqu’une ProviderException déclenche une exception. À utiliser lorsque : le code implique Riverpod Provider, Notifier, ViewModel, câblage DI, conception d’override, ou que le lancement de l’application affiche un écran d’erreur de provider.
