Riverpod Provider architecture design guidelines — dependency injection, interface segregation, mandatory‑wiring provider and wiring test pairing rules, test feasibility. Use for: (1) designing new ViewModel/Notifier classes, (2) reviewing whether Provider dependency injection and app‑root wiring are correct, (3) pairing wiring tests when declaring a mandatory‑wiring provider that throws UnimplementedError, (4) configuring ProviderScope.overrides in tests, (5) detecting incorrect use of ref.read/watch or when a ProviderException triggers an exception. Use when: the code involves Riverpod Provider, Notifier, ViewModel, DI wiring, override design, or the app starts with a provider error screen.
