# Test Assertion Design

斷言設計判斷概念框架。職責：識別「此斷言設計是否合理」，提供跨語言判斷標準。不提供測試寫法或重構步驟。

## 斷言品質三問

設計或審查斷言時，依序回答三個問題。任一問題答「否」即進入對應的類型判斷：

| 問題 | 判斷標準 | 「否」時對應類型 |
|------|---------|----------------|
| 確定性 | 同一程式碼在任何執行環境下，pass/fail 結果一致？ | 類型 1–6（確定性失效） |
| 聚焦性 | 此測試案例只驗證一個行為面向？ | 類型 8–9（設計問題） |
| 隔離性 | 此測試不依賴其他測試建立的狀態或執行順序？ | 類型 7（隔離違反） |

確定性問題細分兩種處置：類型 1–4 屬環境依賴 flaky 族，處置為隔離執行環境或改用差值；類型 5、6 雖同樣呈現確定性症狀，但依〈判斷軸〉歸屬斷言設計族，處置依個別設計原則（等待最終狀態／固定可控隨機源），不套用類型 1–4 的環境隔離做法。

聚焦性的面向計數：行為面向以規格逐條列出的驗收宣告為單位，一條宣告一個面向；同一條宣告內列舉的多項條件仍屬同一面向，斷言數依類型 9 隨條件數成比例。驗收宣告未提及的屬性不構成本測試案例的面向，對它的斷言不放入本測試案例。

## 確定性斷言的基礎形態（無問題，作為對比基線）

以下 4 種確定性斷言類型符合三問標準，可直接放功能測試套件：

| 確定性類型 | 說明 |
|-----------|------|
| 功能正確性 | 輸出值直接比對固定預期值 |
| 邏輯不變式 | 驗證數學/邏輯關係（a < b、rate < 1.0），兩側均非環境依賴值 |
| 結構驗證 | 驗證欄位存在、型別正確、陣列長度 |
| 資源清理 | 驗證洩漏偵測差值（前後 count 差值 = 0），用差值而非絕對值 |

選用哪一種確定性類型，依預期值所對應的規格宣告語句形態決定：宣告某結構顯示或不顯示者，以結構驗證斷言該結構存在與否，不以長度或筆數代替——「長度為 0」在「顯示但內容為空」時同樣成立，驗不到「不顯示」；宣告上限、下限或大小關係（「最多」「至少」「不超過」）者，以邏輯不變式斷言該關係，不以某個符合關係的固定值代替；宣告具體值者（「顯示前 20 筆」「共 3 筆」），以功能正確性比對該值。

功能正確性的預期值必須取自 spec 條文或 UC 預期結果，並依 `.claude/skills/tdd/references/test-object-catalogue.md`〈三、契約欄位表〉斷言來源欄的格式記錄出處；預期值取自現有實作執行結果者不屬此類，屬 characterization test，依 `.claude/skills/tdd/references/test-object-catalogue-starting-points.md` 起點 B 標記，不可與 spec/UC 來源的斷言混記同一類型。

## 9 類型問題斷言分類決策表

### 判斷軸

9 類型問題依問題本質分為兩族（partition，互斥）：

- **環境依賴 flaky 族**（類型 1–4）：斷言結果受執行環境影響，核心問題是「確定性」
- **斷言設計族**（類型 5–9）：斷言內容設計不當，核心問題是「驗什麼」

此分族與斷言品質三問為不同視角且邊界不完全重疊：三問是初篩症狀分流（任一問答否即先歸入對應症狀組，類型 5、6 會先被「確定性」問題篩出）；分族才是依問題本質與處置方式的最終歸類（類型 5、6 因處置屬「驗什麼」而非「環境隔離」，最終歸斷言設計族）。讀者判斷處置時以分族為準。

**歸類判準**：判斷某斷言命中哪個類型，以〈問題類型表〉「識別信號」欄逐一核對是否成立為準；「問題本質」欄是描述該類型問題性質的定義句，用於理解問題屬於哪一種成因，不作為判準本身——定義句的用語在不同類型間可能語意相近甚至重疊，只有識別信號欄描述的具體特徵可操作判定「命中」或「不命中」。例外：類型 9 的識別信號數量門檻僅為篩檢用途，命中後仍須依聚焦性段複判行為面向數，見〈問題類型表〉後方〈類型 9 識別信號與聚焦性的關係〉。

**同時命中多個類型的識別信號時**：代表該斷言同時存在多個獨立問題，應逐一套用各類型對應的設計原則分別處置，不擇一而捨棄其餘。核對前先確認每個候選類型的識別信號**確實成立**——例如類型 5 的識別信號要求「斷言位置在觸發事件之後但等待機制之前」，若斷言已透過 `await` 等待該值產生完成，斷言位置即在等待機制之後，此信號不成立，不計入「同時命中」。

### 問題類型表

| 類型 | 問題本質 | 識別信號 | 設計原則 | 來源 |
|------|---------|---------|---------|------|
| 1. 計時硬門檻 | 使用單次計時值與絕對毫秒數比較作為 pass/fail | 計時差值對比 `N ms` 常數 | 受機器負載影響；功能測試套件禁用；效能門檻移至隔離執行環境 | 實證驗證 |
| 2. 高精度浮點 | 浮點計算結果用超過 2 位小數精度斷言 | `toBeCloseTo(x, numDigits)` 其中 numDigits 超過 2 | IEEE 754 浮點路徑在跨 JIT 環境下末位數字不保證一致；超過 2 位精度需附確定性計算理由 | 實證驗證 |
| 3. 相對計時比較 | 以兩次執行時間的差距或倍數比較驗證快取效果 | `secondRunTime < firstRunTime * K` | 相對計時同樣受 GC/JIT 影響；改用快取命中率或物件參考等價（identity equality）驗證——被驗證對象對外承諾「重複取得同一實例」時用參考等價，只承諾「不重算」（結果值相同、不保證同一實例）時用命中率 | 實證驗證 |
| 4. 記憶體絕對值 | 用堆積記憶體使用絕對上限作為 pass/fail | `heapUsed < N MB` 在功能測試套件 | 記憶體使用受 GC 時機影響；改用前後差值偵測洩漏（差值 = 0）而非絕對上限 | 實證驗證 |
| 5. 非同步時序 | 斷言非同步操作尚未完成時的中間狀態 | 斷言位置在觸發事件之後但等待機制之前；結果隨執行速度改變 | 等待最終狀態再斷言；等待機制因框架而異但「等完成再斷言」原則跨語言一致 | W1-024 推導 |
| 6. 亂數輸出 | 斷言由不可控隨機源驅動的特定輸出值 | 斷言依賴具體的隨機生成值（特定 ID、特定排序、特定分組） | 隨機源必須可控；斷言驗證演算法行為（分佈特性、邊界條件），不斷言特定隨機輸出。例外：驗收條件明確要求輸出不可預測（如安全權杖）時，隨機源不替換，斷言只驗可觀測格式屬性（長度、字元集） | W1-024 推導 |
| 7. 測試隔離違反 | 測試依賴其他測試建立的副作用或特定執行順序 | 測試單獨執行通過但全套件執行失敗；測試順序改變影響 pass/fail | 每個測試自建前置條件，teardown 還原所有共享狀態；隔離違反問題跨語言同形 | W1-024 推導 |
| 8. 快照過度覆蓋 | 快照比對整體輸出結構，非業務相關的格式變更觸發 false positive | 修改一個不相關欄位或樣式，整個快照紅燈 | 快照粒度匹配驗證意圖；業務邏輯驗收用欄位/屬性斷言。全結構快照只在規格另有「偵測輸出格式非預期變更」的驗收條件時設置，與欄位/屬性斷言並存、互不替代；無此條件時不保留全結構快照 | W1-024 推導 |
| 9. 斷言過度集中 | 單一測試案例驗證多個行為面向，前面的斷言失敗遮蔽後面的 | 一個 test case 驗 10 個以上屬性，或測試名稱難以用單一行為描述 | 一測試案例一行為面向；斷言數量與被測行為的複雜度成比例，不與輸出結構大小成比例 | W1-024 推導 |

**類型 9 識別信號與聚焦性的關係**：例外——識別信號「10 個以上屬性」是量的門檻，用於篩出待複判的候選，命中門檻不代表最終判定過度集中，須依〈斷言品質三問〉聚焦性段複判行為面向數：(1) 屬性或條件全部歸屬同一條驗收宣告者，即使總數逾門檻仍屬同一行為面向，斷言數依條件數成比例，不判過度集中；(2) 屬性橫跨兩條以上驗收宣告（多個行為面向）者，判過度集中，不論總數是否達門檻。

**類型 6 隨機源替換後的斷言對象**：依預期值的來源分流。

- 以測試內指定的固定序列替換隨機源，且預期輸出可由驗收條件規定的對應規則從該序列推導者，屬功能正確性，可比對具體輸出值；此時斷言不依賴隨機生成值，不命中類型 6。
- 以固定種子驅動實際亂數演算法、預期值取自執行結果者，屬 characterization，依〈確定性斷言的基礎形態〉標記，與功能正確性測試分開；其預期值綁定亂數演算法實作，函式庫升級可能整批改變。
- 驗收條件只規定格式或分佈、未規定對應規則者，只斷言該性質，不比對具體值（聚焦性）。

**類型 8 與確定性斷言基礎形態的關係**：兩條分類軸不互斥。〈確定性斷言的基礎形態〉開宗明義為「無問題，作為對比基線」，四種類型回答的是「這個斷言該用哪一種比對邏輯」；類型 8 屬於問題類型表，其設計原則要求「快照粒度匹配驗證意圖」，回答的是「斷言粒度該用全結構快照還是逐一欄位」。兩者回答不同問題：決定採用欄位/屬性斷言只解決粒度問題，粒度內每一個欄位斷言仍依既有判準「選用哪一種確定性類型，依預期值所對應的規格宣告語句形態決定」，從功能正確性、邏輯不變式、結構驗證、資源清理中選一種。例如驗收條件為兩欄位間的大小關係時（如本檔前述 a < b 例），該欄位斷言取邏輯不變式形態，而非把邏輯不變式當成與欄位/屬性斷言並列、可互相替代的另一個選項。

## 判讀範例

以下範例依 `.claude/skills/skill-design-guide/references/chained-examples.md` 之三段鏈式格式，校準本檔判斷概念中曾出現分歧的決策點。

### 聚焦性：行為面向如何計數（斷言品質三問）

【輸入】

```
規格片段：「查詢清單」功能的驗收條件為一句宣告：「回傳的清單依建立時間新到舊排序」。
```

【產出】

```
形態：決策表

面向判定表
判斷點                                                   | 結果
-----------------------------------------------------------|----------------------
本情境涉及幾句獨立的驗收宣告                               | 1 句（僅排序）
「排序」宣告是否可再拆成獨立子宣告（如筆數、欄位存在性）   | 否，原句未提及，不可外加
本情境的行為面向數                                         | 1
建議斷言數                                                 | 1（僅驗排序關係）
```

【驗證】

```
Q 驗收宣告是否明確提及筆數與欄位存在性？            預期：否（原句只講排序）
Q 若另外斷言回傳筆數與每筆欄位是否存在，是否合格？   預期：否（不是本情境驗收宣告要求的面向，不放入本測試案例）
Q 若驗收條件改為「依建立時間排序、僅含未封存項目、每筆含 id 與名稱」三句，行為面向數是多少？ 預期：3（每句獨立宣告各對應一個面向）
```

### 判斷軸：識別信號欄為判準，同時命中時逐一處置

【輸入】

```
斷言運算式（原題）：expect(await timer.elapsed, lessThan(Duration(seconds: 2)))
對照變體：expect(timer.elapsedSoFar, lessThan(Duration(seconds: 2)))，其中 timer 尚未停止、elapsedSoFar 為同步存取「計時仍在進行中」的目前累計值（無 await，計時尚未結束）
```

【產出】

```
形態：決策表

識別信號逐一核對表
判斷點                                                          | 原題（已 await） | 對照變體（未停止、無 await）
-----------------------------------------------------------------|-------------------|------------------------------
類型1識別信號「計時差值對比 N ms 常數」是否成立                    | 是                | 是
類型5識別信號「斷言位置在觸發事件之後但等待機制之前」是否成立      | 否（已 await 等到值產生，位置在等待機制之後） | 是（計時器尚未停止即斷言，位置在等待機制之前）
本斷言應歸入的類型                                                | 僅類型1（計時硬門檻） | 類型1與類型5並存，兩者皆須處置
```

【驗證】

```
Q 判斷是否命中的依據是「問題本質」欄還是「識別信號」欄？                          預期：識別信號欄
Q 「問題本質」欄的定義句（如類型5「斷言非同步操作尚未完成時的中間狀態」）可否單獨作為判準？   預期：否，僅描述問題性質，須以識別信號欄的具體特徵逐一核對是否成立
Q 原題 expect(await timer.elapsed, lessThan(Duration(seconds: 2))) 是否同時命中類型1與類型5？   預期：否，類型5識別信號因斷言已 await 而不成立，僅命中類型1
Q 對照變體同時命中類型1與類型5，應擇一歸類還是兩者併行？                          預期：兩者併行，問題並存，逐一套用各自設計原則（類型1：移至隔離效能環境；類型5：等待最終狀態再斷言），不擇一捨棄其中之一
```

### 類型 9：斷言數量與複雜度的比例判準

【輸入】

```
規格片段：某資料轉換規則的驗收條件為一句宣告，內含五項獨立篩選條件。
```

【產出】

```
形態：決策表

斷言過度集中判定表
判斷點                                          | 結果
----------------------------------------------------|----------------------
本測試案例驗證的行為面向數                         | 1（單一轉換規則）
斷言數量的計算基準                                 | 依驗收宣告內部列舉的獨立條件數（本例 5 項），每項配一個斷言
斷言數量隨條件數增加是否構成「過度集中」           | 否，數量與複雜度成比例
外加驗證另一句驗收宣告（另一行為面向）的斷言       | 是過度集中，應移至驗證該面向的另一個測試案例
```

【驗證】

```
Q 12 個斷言若全部對應同一句驗收宣告內部列舉的條件，是否合格？    預期：是（數量隨條件數增加成比例，不判過度集中）
Q 若其中 2 個斷言驗證的是另一句驗收宣告，是否合格？              預期：否（跨面向混驗即為過度集中，應拆為獨立測試案例）
Q 判斷「過度集中」的依據是斷言總數還是涵蓋的行為面向數？          預期：行為面向數（斷言總數本身不是判準）
```

### 類型 8：快照粒度是否匹配驗證意圖

【輸入】

```
規格片段：某報表功能的驗收條件為「總計欄位須等於各分項加總」；規格未另外要求偵測輸出格式的非預期變更。
```

【產出】

```
形態：決策表

快照粒度判定表
判斷點                                      | 結果
------------------------------------------------|----------------------
驗收條件的驗證意圖                             | 業務邏輯正確性（總計等於分項加總）
是否另有「偵測非預期格式變更」的獨立驗收條件   | 否
本情境應採用的斷言形態                         | 欄位/屬性斷言
是否保留全結構快照                             | 否（無獨立格式監測意圖時，全結構快照只會在無關欄位變動時誤報）
```

【驗證】

```
Q 驗收條件是否明確要求偵測輸出格式的非預期變更？    預期：否
Q 本情境該用全結構快照還是欄位斷言？                預期：欄位斷言
Q 若規格另加一句「輸出格式不應在未經審核下變動」，判定是否改變？  預期：是，新增獨立的全結構快照作格式監測用途，與欄位斷言並存，兩者驗證不同意圖，互不替代
```

### 類型 6：一般隨機與密碼學安全隨機的策略分歧

【輸入】

```
規格片段：情境甲，某功能產生驗證碼字串，驗收條件要求「產生的字串符合固定格式與長度」；情境乙，某功能產生安全權杖，驗收條件要求「權杖不可預測」。
```

【產出】

```
形態：決策表

隨機源測試策略判定表
判斷點                            | 情境甲（一般用途隨機） | 情境乙（安全屬性隨機）
------------------------------------|------------------------|---------------------------
是否可替換為可注入的固定隨機源      | 是                     | 否（替換會使安全屬性測試失去意義）
斷言對象                            | 驗收條件要求的格式與長度（隨機源已替換，結果可重現） | 可觀測格式屬性（長度、字元集），不斷言具體值
判斷依據                            | 驗收條件只要求格式正確  | 驗收條件明確要求「不可預測」，替換隨機源即繞過被驗證的安全屬性本身
```

【驗證】

```
Q 情境甲是否應替換為可注入的固定隨機源？          預期：是
Q 情境乙是否應替換為固定種子？                    預期：否（會使「不可預測」的驗收條件失去測試意義）
Q 情境乙的斷言對象是什麼？                        預期：格式屬性（長度、字元集），不是具體輸出值
Q 判斷該採哪一策略的依據是什麼？                  預期：驗收條件是否明確要求「不可預測」這項安全屬性；有此要求即不可替換隨機源
```

### 元件執行期行為：狀態集與內容政策如何轉為驗證

【輸入】

```
元件契約表片段（已定義）：
  狀態 | 內容政策
  -----|--------------------------------
  空   | 顯示空狀態提示文字，不顯示清單容器
  正常 | 顯示清單內容，最多顯示 20 筆
```

【產出】

```
形態：決策表

斷言設計對應表
狀態 | 判斷點                                 | 對應斷言類型（依本檔〈確定性斷言的基礎形態〉）
-----|-------------------------------------------|--------------------------------------------
空   | 畫面是否只顯示空狀態提示、不顯示清單容器   | 結構驗證
正常 | 清單容器顯示筆數是否小於等於 20            | 邏輯不變式（上限關係，非固定值）
```

【驗證】

```
Given 資料來源回傳空清單
When  畫面渲染完成，狀態轉為「空」
Then  畫面只含空狀態提示文字，清單容器不存在於畫面樹中
And   斷言對應【產出】表「空」列的結構驗證：內容政策宣告「不顯示清單容器」，依〈確定性斷言的基礎形態〉選用段「宣告某結構顯示或不顯示者，以結構驗證斷言該結構存在與否，不以長度或筆數代替」，不斷言清單容器「長度為 0」

Given 資料來源回傳 25 筆項目
When  畫面渲染完成，狀態轉為「正常」
Then  清單容器顯示的筆數不超過內容政策上限（目前上限為 20）
And   斷言對應【產出】表「正常」列的邏輯不變式：內容政策宣告「最多顯示 20 筆」，依同段「宣告上限、下限或大小關係者，以邏輯不變式斷言該關係，不以某個符合關係的固定值代替」，不斷言「筆數等於 20」
```

## 不在範圍聲明

此 skill 提供判斷概念，以下內容屬下游層級，不在此 skill 範圍：

| 不在範圍的內容 | 所在層級 |
|--------------|---------|
