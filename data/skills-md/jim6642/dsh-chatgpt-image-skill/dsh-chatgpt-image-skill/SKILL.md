# DSH 桌面生图与固定聊天

先阅读 [README](README.md) 了解边界和人工准备步骤。已有机器人环境无需重新配置账号或重置聊天。

## 执行顺序

1. 诊断现有 DSH GUI、其真正使用的后台、桥接和 MCP；不要只凭端口名判断桌面版/网页版。保留白名单、角色卡、历史和启动方式。
2. 用户在自己登录的桌面 ChatGPT **Chat** 手动上传参考图并确认识别；不要求提供 Cookie、密码或登录凭据。不擅自换 Edge、Work 或另一个账号。
3. 用 `scripts/probe-desktop.mjs` 只读检查本机 CDP 页面是否兼容。此代码针对实测 Electron 页面结构，不是所有 ChatGPT 客户端的通用协议。运行环境或工具禁止操作目标应用时停止该自动化，说明限制，不换旁路绕过。
4. 按 README 创建本地配置，用 `scripts/check-binding.mjs` 验证唯一聊天名称；默认只检查，`--open` 才选择现有聊天。没有唯一匹配时停止，绝不另建聊天。
5. 用户授权生图后，独立验证生成脚本落盘，再接入桥接及 MCP。接入代码参考 [references/integration.md](references/integration.md)，按实际版本适配，不整体覆盖现有配置。
6. 分开证明 MCP `tools/list` 含工具、**实际 DSH 会话 schema** 含工具、模型调用工具、图片生成、QQ 发送和读回；前一层成功不代表后一层成功。
7. 检查私聊与群聊。原有“群聊仅真实 @ 触发”、会话令牌、白名单、静默、限流及发送队列都应保留。

## 必须保留的行为

- 使用 `spawn/execFile` 参数数组，提示词不拼 shell；调试端口仅本机可访问。
- 固定会话名唯一且保持可见。当前示例按标题选择，conversationId 仅记作人工核对字段，**没有通过内部路由验证 ID**，不得宣称已按 ID 强绑定。
- 每次提示词带随机唯一请求标记，按包含标记的消息块取图；仅接受该消息完成后的唯一生成图及消息 ID，读取字节前再次校验。历史图片加载出新的 DOM/blob 不能作为本轮出图证据，禁止整页取图兜底。
- 同一固定聊天同时只允许一个生成任务。锁冲突直接报忙，不并发生图。
- 外层超时大于内层；实际失败或超时不自动再画一次，避免已经出图却重复生成。
- `qq_generate_image` 是生成并发送工具，成功后不要再 `qq_send_image`。普通发送已有图片不能冒充 AI 生图。
- 验收按真实链路描述；未做真人 QQ 验收时只报告离线测试通过。自动化不能保证角色永不漂移、永久保留参考图或跨版本兼容。

## 排错及分享

按 [references/troubleshooting.md](references/troubleshooting.md) 从日志定位层级。只对明确未执行任何工具的参数解析错误考虑一次原请求重试，不对超时、未知发送结果或已有副作用的请求重试。

对外分享从空目录整理示例；不要复制运行中的 config、state、日志、图片、聊天数据库、用户目录或 Git 历史。先运行 `npm test` 和 `npm run privacy`，再查看 Git 将提交的全部文件和作者信息。扫描只作辅助，不承诺检查出所有隐私。未经用户请求不创建开机启动项，不发布他人的账号与会话信息。
