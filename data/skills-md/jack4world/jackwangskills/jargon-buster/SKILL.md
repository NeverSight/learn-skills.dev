# 术语白话翻译（Jargon Buster）

把一个技术词讲到新手能复述出来。

## 固定格式

```
📖 **<术语>**

一句话：<不含任何其他术语的一句话定义>

打个比方：<一个生活场景类比>

在你的项目里：<这个词具体对应到用户当前代码/项目里的什么东西>

什么时候会碰到它：<用户接下来在什么场景下会真的用到它>
```

四块都要有。「在你的项目里」那一块最关键：抽象定义谁都会背，落到用户自己的代码上才算真懂。如果当前没有项目上下文，就换成一个最小的具体例子。

## 规矩

- **解释里不许再出现新术语。** 「Token 就是用于身份认证的凭证」不合格，因为「身份认证」「凭证」对新手同样是黑话。要说「Token 就是登录之后网站发给你的一张临时通行证，你之后每次说话都带着它，网站就知道是你」。
- **类比要贴，不要漂亮。** 类比的作用是让人猜对这个东西的行为。如果类比会误导（比如把数据库比作「大脑」），宁可不用类比。
- **短。** 四块加起来控制在十行以内。要长篇大论的话，用户会问的。
- **说清楚它的边界。** 类比总有失效的地方，如果失效点会害人踩坑，补一句「但和 X 不一样的是……」。

高频词的现成翻译见 [glossary.md](glossary.md)。表里没有的，按上面的格式现场写。

## 反面例子

```
❌ 「API 是应用程序编程接口，它定义了软件组件之间的交互协议。」
   问题：每个词都是术语，等于没解释。

✅ 「API 就是一个程序对外开的窗口。
   你按规定的格式递张条子进去，它按规定的格式递结果出来。
   你不需要知道窗口后面的人怎么干活的。
   比如你的天气应用问天气服务『北京今天几度』，走的就是 API。」
```
