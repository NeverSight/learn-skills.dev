Risolvi conflitti e fusioni quando più rami sono aperti su un repository contemporaneamente: i file hotspot che ogni modifica deve toccare (manifesti del registro, un singolo campo di versione, configurazione dello strumento condiviso, un modulo di test aggregato, output di build tracciato), unione-vs-recompute-vs-rebuild come tre diverse risoluzioni corrette, artefatti generati che non devono mai essere uniti, serializzazione non deterministica che rende ogni ramo in conflitto, identificatori rinumerati che git non può mostrarti e perché un'unione automatica pulita non è un test positivo. Da utilizzare quando si riorganizza o si unisce un ramo di lunga durata, si risolvono indicatori di conflitto, si rivede un commit di unione, si decide cosa un repository dovrebbe impegnare o generare o impostare un repository che riceverà contributi paralleli.
