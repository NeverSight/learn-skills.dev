Verwenden Sie dies, wenn Sie entscheiden müssen, ob Sie eine Funktion extrahieren, ein Interface einführen, eine neue Klasse erstellen, einen Helfer hinzufügen, ein Modul aufteilen, einen Plugin‑Hook hinzufügen oder ein Stück Code verallgemeinern; wenn Sie einen Pull‑Request prüfen, der eine neue Abstraktion vorschlägt; wenn ein gemeinsamer Helfer immer mehr Flag‑Parameter bekommt; wenn Sie Duplikate haben und unsicher sind, ob Sie diese extrahieren sollen; oder wenn eine bestehende Abstraktion sich falsch anfühlt, Sie aber nicht benennen können, warum. Lösen Sie es auch aus, wenn der Nutzer fragt „Soll ich das extrahieren?“, „Ist das die richtige Abstraktion?“, „Ist das übertrieben?“, „Ist das genug DRY?“, „Soll ich das verallgemeinern?“, „Soll ich hier ein Interface hinzufügen?“, oder „Ist das eine voreilige Abstraktion?“. Diese Fähigkeit liefert ein Entscheidungsverfahren; sie wird von writing‑good‑code und refactoring‑and‑reviewing‑code referenziert und kann auch eigenständig verwendet werden.
