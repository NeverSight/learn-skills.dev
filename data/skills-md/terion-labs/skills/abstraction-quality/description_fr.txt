Utilisez lorsqu’il s’agit de décider d’extraire une fonction, d’introduire une interface, de créer une nouvelle classe, d’ajouter un helper, de diviser un module, d’ajouter un point d’extension (plugin hook) ou de généraliser un morceau de code ; lors de la révision d’une pull request qui propose une nouvelle abstraction ; lorsque un helper partagé accumule des paramètres de drapeaux ; quand vous avez des duplications et n’êtes pas sûr de devoir les extraire ; ou lorsqu’une abstraction existante semble inappropriée mais que vous ne pouvez pas en identifier la raison. Déclenchez également lorsque l’utilisateur demande « devrais‑je extraire cela ? », « est‑ce la bonne abstraction ? », « est‑ce trop sur‑ingénierie ? », « c’est‑il suffisamment DRY ? », « devrais‑je généraliser cela ? », « devrais‑je ajouter une interface ici ? » ou « est‑ce une abstraction prématurée ? ». Cette compétence fournit une procédure de décision ; elle est référencée par écrire‑un‑bon‑code et refactoring‑et‑revue‑de‑code, et peut aussi être utilisée seule.
