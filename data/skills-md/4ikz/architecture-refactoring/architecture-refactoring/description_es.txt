Úselo cuando una base de código existente se resiste al cambio: archivos que deben editarse juntos en módulos no relacionados, dependencias circulares o entre capas, módulos divinos, estados mutables compartidos, modelos de persistencia que se filtran a través de fronteras, cambios rápidos, pruebas que arrancan infraestructura no relacionada o arquitectura que sigue a la deriva. Audita el sistema actual con evidencia concreta, define límites de propiedad y dependencia y migra gradualmente preservando el comportamiento. Se activa incluso cuando el usuario no dice "arquitectura" o "refactorización", por ejemplo "limpiar esto", "desenredar esto", "por dónde debería empezar", "seguimos rompiendo cosas" o "hacer que esto sea más fácil de cambiar". No lo utilice para diseños totalmente nuevos, cambios de nombre mecánicos, formateo, actualizaciones de dependencias o limpieza puramente estilística.
