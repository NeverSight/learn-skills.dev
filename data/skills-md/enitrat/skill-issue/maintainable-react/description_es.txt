Principios para escribir, refactorizar y revisar código React para que siga siendo mantenible — resistiendo la abstracción prematura (el “componente demonio”), manteniendo el flujo de datos evidente y colocando el estado y los efectos en el lugar correcto. Úsalo al escribir o refactorizar un componente o hook de React, decidir si extraer o reutilizar uno, revisar React para su mantenibilidad, recurrir a useEffect, elegir dónde vive el estado o desenredar el paso de props y la sobre‑abstracción.
