Regole e modelli per scrivere una documentazione SDK completa e di alta qualità per librerie pubbliche su Vocs (vocs.dev). Copre l'architettura della documentazione, il tono narrativo, le guide per l'utente, i riferimenti API e gli output leggibili dagli agenti di Vocs (llms.txt, percorsi Markdown, MCP). Uso quando: (1) Scrivere o revisionare la documentazione per un SDK/libreria pubblico, (2) Creare pagine di riferimento API per hook/funzioni/classi, (3) Scrivere guide introduttive o tutorial, (4) Strutturare un sito di documentazione da zero, (5) Revisionare la qualità e la coerenza della documentazione, (6) Configurare o impostare un sito di documentazione Vocs per un SDK.  

Per favore, rispondi sempre nella lingua dell'utente.
