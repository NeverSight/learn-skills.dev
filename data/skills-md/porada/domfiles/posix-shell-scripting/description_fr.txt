Écrire, examiner, auditer, refactoriser et diagnostiquer le code et la configuration POSIX `sh`. Utilisez‑le chaque fois que le code doit s’exécuter sous un shell POSIX ou qu’une migration cible POSIX `sh`.

Utilisez‑le pour les fichiers `.sh`, les points d’entrée `#!/bin/sh`, les commandes sans extension, les bibliothèques sourcées, les hooks, les fragments de démarrage, les fragments de shell générés et tout autre code shell sans dialecte de shell identifiable.

Ne l’utilisez pas lorsque la sortie demandée n’est que du code pour un shell non POSIX.

Veuillez toujours répondre dans la langue de l’utilisateur.
