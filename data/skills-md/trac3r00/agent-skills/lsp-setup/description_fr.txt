Configurez un serveur de langage (LSP) pour un langage spécifique afin que les outils de l’éditeur/agent — diagnostics, aller‑à‑la‑définition, recherche de références, renommage — fonctionnent. Utilisez‑le lorsque vous devez : configurer le LSP, installer ou mettre en place un serveur de langage, corriger « no LSP server configured » / « server not installed », choisir entre les serveurs (basedpyright vs pyright vs ty vs ruff), ou câbler .codex/lsp‑client.json / .opencode/lsp.json. Configuration du serveur de langue. Routes par extension de fichier vers references/<language>/README.md pour le serveur intégré exact, commandes d’installation par OS (macOS/Linux/Windows), extraits de configuration pour les deux fichiers de configuration, options d’initialisation, alternatives et dépannage. Fournit les scripts : detect‑lsp.ts (analyse un projet pour détecter les langages + l’état d’installation/configuration de chaque serveur) et verify‑lsp.ts (exécute un vrai cycle de diagnostics). Couvre typescript, python, go, rust, c/c++, java, kotlin, c#/razor, swift, ruby, php, dart, elixir, zig, lua, bash, yaml, terraform, haskell, julia.
