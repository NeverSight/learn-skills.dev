URLパスを検査し、動的セグメント（数値ID、UUID、スラッグ、日付）を読みやすいエイリアスに統合するプロジェクトレベルのパスクリーニングルールを提案、テスト、順序付け、適用します。ユーザーが「clean the paths」や「normalize URLs」「group similar pages」「too many distinct paths」「/users/123 and /users/456 are the same page」「set up path cleaning」と言ったとき、あるいは Web 分析やパスの分解が数千のほぼ同一 URL に分散している理由を尋ねたときに使用します。正規表現構文（re2）、エイリアスプレースホルダーの規約、ルールの順序付け、テストワークフロー、そして path‑cleaning‑rules‑update MCP ツールによるルール適用について説明します。
