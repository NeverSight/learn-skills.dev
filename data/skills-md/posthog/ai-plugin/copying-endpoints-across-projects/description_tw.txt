將 PostHog 端點（已儲存的 HogQL/insight 查詢，以 API 路由形式公開）複製到同一組織內的其他專案，或在同一專案中以新名稱複製。適用於使用者想要複製端點、將端點從測試環境提升至正式環境、在其他工作區複製端點的查詢／變數／新鮮度設定，或克隆端點以進行迭代的情境。與功能旗標與實驗不同，端點沒有原生的跨專案複製工具——此技巧涵蓋讀取後重新建立的流程（endpoint-get 然後 endpoint-create）、所需的活躍專案切換、名稱衝突檢查，以及安全的預設行為（在目標端點留下未實體化的資料，並透過 endpoint-run 驗證）。不包括編輯端點版本（請參閱 managing‑endpoint‑versions）或從頭開始創建全新端點（請參閱 creating‑an‑endpoint）。
