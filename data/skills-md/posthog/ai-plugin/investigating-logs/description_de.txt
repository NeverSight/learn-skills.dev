Untersuchen Sie Protokolle in einem PostHog‑Projekt: Verifizieren Sie, ob ein Service oder ein Deployment gesund ist, erklären Sie einen Fehlerschub, triagieren Sie einen Vorfall oder verstehen Sie, was ein Log‑Stream aussagt. Verwenden Sie dies, wenn der Nutzer „die Logs prüfen“ möchte, fragt, ob ein Service, Deployment, Release oder eine Änderung funktioniert bzw. etwas kaputt gemacht hat, warum Fehler zunehmen oder was sich geändert hat, oder die Ursache von im Log sichtbaren Fehlermeldungen wissen will. Leitet die Logs‑MCP‑Tools (Service‑Übersicht, Mustermining, Vorher‑Nachher‑Muster‑Diff, gruppierte Zählungen, Facetten, Rohzeilen) weiter, sodass Untersuchungen von Zusammenfassungen statt von Rohzeilen oder handgeschriebenem SQL über die Log‑Tabelle starten.
