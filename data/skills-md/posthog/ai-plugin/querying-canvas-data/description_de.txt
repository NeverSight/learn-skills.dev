Bringen Sie PostHog‑Daten korrekt in ein Canvas: das vom Host injizierte `ph`‑SDK (loadInsight, query, capture, state, connectors, openExternal, navigate), die Datenhierarchie (zuerst gespeicherte Insights, dann typisierte Abfrage‑Knoten, zuletzt Inline‑HogQL), Nachvollziehbarkeit (insight‑basierte Metriken verlinken ihr gespeichertes Insight in PostHog; Ad‑hoc‑Abfragen zeigen die exakt ausgeführte Abfrage), ergebnisbezogene Formen je Insight‑Typ, progressive Laden‑Prozesse pro Abfrage, Verkabelung von Datumsbereichen, Live‑Daten von Drittanbietern über die eigenen Verbindungen des Viewers (ph.connectors) und Ereigniserfassung aus einem Canvas. Verwenden Sie es immer, wenn ein Canvas Metriken, Diagramme, Tabellen, beliebige PostHog‑Daten oder Daten von GitHub bzw. einem MCP‑Server anzeigt oder Analyse‑Events senden muss.
