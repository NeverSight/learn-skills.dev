URL パスを検査し、プロジェクトレベルのパスクリーニングルールを提案・テスト・順序付け・適用して、動的セグメント（数値 ID、UUID、スラッグ、日付）を読みやすいエイリアスに統合します。ユーザーが「パスをクリーンにして」「URL を正規化して」「類似ページをグループ化して」「パスが多すぎる」「/users/123 と /users/456 は同じページだ」「パスクリーニングを設定して」などと言ったとき、または Web アナリティクスやパスの内訳が数千のほぼ同一 URL に分散している理由を尋ねたときに使用します。正規表現構文（re2）、エイリアスプレースホルダーの規約、ルールの順序付け、テストワークフロー、そして path‑cleaning‑rules‑update MCP ツールによるルール適用について解説します。
