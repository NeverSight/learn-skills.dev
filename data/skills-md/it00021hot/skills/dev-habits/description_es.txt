Escribe código, modifica código, revisa, refactoriza, discute soluciones, verifica y entrega—la constitución de ingeniería inter‑proyecto que debe leerse antes de un commit de Git, y que también regula la colaboración entre personas y agentes; la habilidad a nivel de proyecto es un suplemento, no un reemplazo, y ambas deben leerse. Al definir o modificar una API o un contrato IPC, manejar límites de serialización, escribir registros, solucionar problemas, crear tablas y realizar migraciones de bases de datos, gestionar seguridad y claves, escribir pruebas, afinar el rendimiento o la concurrencia, escribir o modificar funciones no triviales, decidir sobre la propiedad de tipos y módulos, primero lee las referencias especificadas en la lista de control de acceso. Esta prescribe formas de trabajo, calidad de código, seguridad, pruebas, datos, solución de problemas de registros y métodos de comunicación, sin dictar la pila tecnológica; los conflictos se resuelven según una jerarquía de arbitraje—los acuerdos específicos del proyecto siempre tienen precedencia, y la seguridad y el cumplimiento no pueden ser anulados.
