코드를 작성하고, 코드를 수정하고, 리뷰하고, 리팩터링하고, 해결책을 논의하고, 검증하고 배포하는—이것들은 Git 커밋 전에 반드시 읽어야 하는 교차 프로젝트 엔지니어링 규범이며, 사람과 에이전트 간 협업도 규정한다; 프로젝트 수준의 스킬은 보조일 뿐 대체가 아니며, 양쪽 모두 읽어야 한다. API 또는 IPC 계약을 정의하거나 수정하고, 직렬화 경계를 처리하며, 로그를 작성하고, 트러블슈팅을 수행하고, 테이블을 생성하고 데이터베이스 마이그레이션을 진행하며, 보안 및 키를 다루고, 테스트를 작성하고, 성능이나 동시성을 튜닝하고, 비정형 함수를 작성하거나 변경하거나 타입 및 모듈 소유권을 결정할 때는 먼저 접근 제어 목록에 명시된 참고 자료를 읽어야 한다. 이는 작업 방식, 코드 품질, 보안, 테스트, 데이터, 로그 조사, 커뮤니케이션 방법을 규정하지만 기술 스택을 강요하지 않는다; 충돌은 중재 계층에 의해 해결되며—프로젝트별 합의가 항상 우선하고, 보안과 컴플라이언스는 절대 무시될 수 없다.
