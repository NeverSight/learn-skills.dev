# 开发习惯与协作约定（工程宪法）

本文件是用户的工程宪法：跨所有项目生效，同时约束人与 agent 的协作方式。规则以方括号短名定义身份，跨规则引用写作『先读后写』；废除全局编号——身份是名字不是位置，插入新规则不会让引用失效。分域条款按「门禁表」在对应动作前必读。冲突按「仲裁阶梯」裁决。

## 用户画像

- 后端为主的全栈工程师：Go、Rust 为后端主力，TypeScript 做前端，Python 做脚本、数据处理与 AI 工具。
- 编码习惯：Go 遵循 Go 社区规范与惯用语，gofmt 强制；注释极少化、命名自解释、错误处理显式；配置外置。
- 追新：新技术与最新稳定版依赖优先，版本号明确。
- 洁癖：零冗余、零死代码；反感无用抽象层、兜底分支和无意义默认值，错误该暴露就暴露。
- 单一路线：一个问题一个解决方案。
- 国际化：文档双语优先，文案与错误信息走 i18n 资源。

## 仲裁阶梯

冲突时的裁决顺序，从高到低：

| 层级 | 内容 | 覆盖关系 |
| --- | --- | --- |
| T0 不可覆盖 | 安全与合规（[security.md](references/security.md)） | 高于一切，项目约定不得覆盖 |
| T1 | 项目自身约定：仓库 README、AGENTS.md、项目级 skill、既有代码风格、依赖清单（go.mod、Cargo.toml、package.json）里实际使用的技术栈 | 高于本 skill 的 T3 与未定级内容；不得降低 T0 与 T2 |
| T2 硬性 | 代码质量、传输契约、日志、测试、数据、性能并发、做事与交流方式 | 项目约定不得降低 |
| T3 默认范式 | 工程形态、Git 格式、工程设施选配 | 可被项目约定覆盖 |

章节标题标注该节默认层级；个别规则层级不同时在规则行内单独标注。安全条款永远 T0——项目要求 SQL 拼接、要求日志打明文密钥，也不执行。

## 做事方式（T2 硬性）

- **[先读后写]** 动手前先读目标文件及直接依赖（类型定义、配置、调用方、测试），以现有写法和目录结构为准。
- **[不臆造]** 不猜 API、路径、字段名、依赖名、配置项，查不到就明说不知道。对齐第三方或参照实现（竞品、开源标杆）时，先读它的源码提取真实规格（参数、交互、语义）再动手，不凭截图或印象猜。
- **[方案先行]** 非平凡改动先讲方案：1–3 句说明改什么、影响哪些文件、怎么验证；琐碎改动直接做。
- **[范围最小化]** 只动达成目标所必需的行，不重排无关格式、不碰无关文件；仅两个例外：本次触碰的函数按『触碰即净』做最小清理、被烂结构挡路按『重构让路』先行，均须与功能改动分开提交；例外之外不顺手重构。
- **[死代码上报]** 范围之外发现死代码、重复逻辑、无用导出、注释掉的旧代码：指出来问要不要清，不擅自扩大改动。
- **[机制根治不打补丁]** 方案选机制性根治，不接受"加个超时、重试、兜底先把问题挡住"式修复，先找根因一次做对。
- **[要最优不要成本话术]** 方案讨论禁止按"最便宜、投入产出比"排序，不以工作量为由降级方案；产品未上线时不写兼容旧数据的回退分支、不做最小可用版本——兼容分支和临时实现是永久留在代码里的债；真要分期只讲技术依赖顺序。
- **[搜索用 rg]** 文件内容搜索一律优先 rg，确认环境没有 rg 才回落 grep。
- **[改完必验证]** 跑构建、类型检查、lint 和相关测试再交付；跑不了就明说"未验证"及原因。
- **[验证不过度]** 验证到"针对性测试全绿"为止，完成『改完必验证』要求的构建、类型检查、lint、相关测试即交付；用户没要求时不追加烟囱测试、GUI E2E、重复构建等额外验证轮次。对照实验类排查用户通常自己会做。
- **[诚实报告]** 分别写清成功、失败、跳过、未验证，不虚构运行结果。

## 代码质量（T2 硬性）

- **[零冗余]** 无用的函数、变量、import、配置项、注释掉的代码块，直接删而不是留——历史交给版本控制；适用范围限本次改动与『触碰即净』所及，更远处按『死代码上报』处理。
- **[单一职责]** 一个文件只干一件事，超出就拆文件；同一段逻辑出现两次就抽出来，第三次直接封装成独立模块。
- **[不加无用抽象]** 不要用户没要求的接口、基类、工厂、配置项、feature flag、策略模式或预留扩展点。
- **[禁无依据兜底]** 不写"以防万一"的空 catch、无意义默认值、重复校验、过度防御的错误吞掉；错误该暴露就暴露。显式容错设计（超时、熔断、重试上限、降级）允许且鼓励，但必须配套：带日志（级别见『日志级别语义固定』）、有明确上限、写清触发条件；无依据防御与无上限重试都禁止。
- **[单一路线]** 一个问题一个解决方案，只给一条推荐路线，不并排摆多套方案让挑。
- **[注释纪律]** 命名自解释优先，默认零注释；只有「不写会被误用」才写，且压到 ≤2 行的行为契约。领域知识（抓包口径、接口参数、协议形态）归项目文档（如 docs/*.md），不进代码注释。细则（允许写什么、禁止写什么、触发场景）见 [clean-code.md](references/clean-code.md)『注释极少化』；命名准确，不缩写、不用无意义词汇。
- **[禁魔法值]** 状态码、错误码、阈值、容量与批大小、重试次数、位标志、正则与字符集等字面量一律提取为命名常量或枚举，不裸写；0、1、-1、循环下标等自解释值除外；传输契约相关的字面量格式另按 [api-contract.md](references/api-contract.md) 执行。
- **[工具链报错清零]** 遵循目标语言社区规范与其格式化、静态检查工具链，格式化与检查交给工具自动执行，报错清零再交付；强制配置见文末「机械条款与强制配置」。
- **[格式化不回滚]** 格式化工具只改排版、不改代码逻辑；大范围重排（包括动到没改过的文件）是工具的正常行为，不是需要恢复的事故。对格式化产生的变化禁止回滚——git restore、checkout、revert 或整文件贴回旧内容都是文件级操作，会把格式化之后进入工作区的其他改动（包括其他会话的未提交修改）一并撤销；要调整结果就改格式化配置或做精确编辑（对齐『改代码用精确编辑』）。发现 fmt 改了逻辑就是工具或配置有问题，停下来报告，不悄悄恢复原状。
- **[错误处理按项目约定]** 按项目既有约定处理错误：包装时带上下文并保留原始错误链路，不用 panic 走业务流程。
- **[调试残留清零]** console.log、println!、dbg!、fmt.Println、print 等调试残留交付前清零；排查期间加的临时日志交付前删除或转正为正式日志。
- **[不擅自引依赖]** 不擅自引入新框架、新依赖或新技术栈，确有必要先说明理由并征得同意；选定后按『依赖来源审查』执行。

## 自动化与交付边界（T2 硬性）

- **[不碰用户活跃环境]** 不自动操作用户在用的应用、窗口或账号（点击、移动鼠标、切会话、删会话）。用户自己开着 dev 会话或服务实例（dev server、开发中的应用等）时一律不可调试——CDP、computer-use 等任何自动化手段都不行，自动化调试只针对自己启动的实例。需要配合时（抓包、复现）写成清晰步骤清单交用户手动执行。自动化测试只针对自己创建的实例、会话与数据；清理只按自己创建时记录的 ID，绝不按标题或名称模糊匹配删除，绝不在用户活跃实例上并发跑自动化。
- **[交付后不盯流水线]** push 触发 CI 或发版后报告一句"已推送，流水线已触发"即收尾，不轮询监控；用户自己在 CI 网页看结果，只有被明确要求排查失败时才去看。
- **[改代码用精确编辑]** 对源码文件的修改一律通过精确编辑完成；python 等脚本只做只读分析（数据统计、日志解码）——脚本盲改不可见、易切坏结构。

## 交流方式（T2 硬性）

- **[中文交流]** 中文回答；技术标识符、日志、报错原文保留不翻译。
- **[先结论后细节]** 先给结果和改动清单，再讲原理与取舍。
- **[标注不确定]** 不确定就标注假设与不确定点；引用外部事实附来源链接。
- **[不擅自不可逆操作]** 不执行 commit、push、发布、删数据、改 CI 等不可逆或对外可见操作，除非明确要求。
- **[审查分级输出]** 审查结论按 阻断、建议、提示 三级输出，先列阻断项；每条注明依据的条款 slug；没有阻断项就明说"无阻断项"，不凑数。

## Git 与变更记录

- **[commit message 规范]**（T3 默认范式，可被项目覆盖） Conventional Commits 格式，摘要一行说清做什么，正文写为什么；分支命名与合并策略随项目约定。
- **[变更描述带验证]**（T2） 提 PR 或写变更说明必须包含：改了什么、影响哪些文件、怎么验证（对齐『方案先行』与『改完必验证』）；交付报告同样按此结构。

## 沉淀工作流（T2 硬性）

- **[沉淀工作流]** 新约定只能来自真实踩坑，不来自想象。落地时先归入对应章节，再判定强制方式：可机械检的先在 templates/ 或 scripts/ 落工具、再写条款；条款必须带触发场景，防止后来者当噪音删掉。

## 机械条款与强制配置

可机械钉死的条款必须变成工具配置，不靠自觉。表内未列的条款靠门禁阅读与审查执行；可机械检而暂无低噪声配置的登记进「已知缺口」行，不许沉默：

| 条款 | 强制方式 | 配置位置 |
| --- | --- | --- |
| 『调试残留清零』 | lint 报错 | templates/ts/eslint.config.mjs、templates/rust/lints.toml、templates/go/.golangci.yml（forbidigo） |
| 『前端禁 any』 | type-aware lint 报错 | templates/ts/eslint.config.mjs |
| 『错误处理按项目约定』 | clippy deny | templates/rust/lints.toml |
| 『工具链报错清零』 | 格式化与静态检查 | templates/go/.golangci.yml、templates/rust/rustfmt.toml、templates/ts/eslint.config.mjs |
| 『外部输入不可信』『查询参数化』 | lint 加审查 | templates/go/.golangci.yml |
| 『函数只做一件事』『嵌套限深』『参数收敛』 | lint 提醒档（warn 级加放宽阈值，防为拆而拆造碎片函数） | templates/go/.golangci.yml、templates/rust/lints.toml、templates/rust/clippy.toml、templates/ts/eslint.config.mjs |
| 『禁魔法值』 | lint 加审查 | templates/go/.golangci.yml（mnd）；Rust、TS 无低噪声通用 lint，审查兜底 |
| 『可变不外泄』『依赖无环』TS 侧 | 审查兜底（gochecknoglobals 会误伤 Go 哨兵错误；import/no-cycle 需选装 eslint-plugin-import） | templates/ts/eslint.config.mjs 内注释选配段 |
| 『整型 ID 字符串化』『传输字段 camelCase』 | 边界 schema 校验 | 无通用 lint，靠项目选定的 schema 校验库兜底（见『契约两端同源』） |
| 本仓库自身（frontmatter、slug、引用、门禁登记、模板配置存在性） | CI | .github/workflows/check-skills.yml 调 scripts/check-all.sh |
