Evidence‑based code quality review and cleanup are divided into two scopes: a diff‑level track (cleaning up AI “flavor” after writing code or before committing—comment slop, over‑defensiveness, over‑abstraction, hallucinated APIs, duplicated logic, vague naming, test theater, deletion‑first converging to the minimal patch) and a repository‑level track (maintenance‑type technical debt, architecture findings, testing/dependency/configuration audits, and release‑readiness prechecks before public release, open‑sourcing, v1.0/package publishing). Triggers: deslop, removing AI flavor, cleanup or review of recent changes, pre‑commit self‑check, PR diff quality, technical‑debt/quality/architecture audits, pre‑open‑source checks, Scorecard, REUSE. Not intended for correctness bug debugging, pure security penetration testing, or designing future solutions; design trade‑offs and rollout order are left to the pilot, with the target repository’s own review/ownership guidelines taking priority.
