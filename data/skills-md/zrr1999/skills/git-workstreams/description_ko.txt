Git/GitHub를 사용하여 변경 작업 흐름의 체크아웃/워크트리 토폴로지, 종속 브랜치/PR 스택, 그리고 통합 전달 경계를 조직합니다: 정규화된 저장소를 식별하고 기본적으로 소유 워크트리와 함께 일반 구현을 격리합니다; 명시적인 PR 요청도 기본적으로 워크트리 사용을 허용합니다. 사용자의 명시적인 엔드포인트에 따라 순차적으로 진행합니다: 정규화된 저장소는 기본적으로 Draft PR이 되고, 비정규화된 저장소는 커밋, 푸시, PR에 대한 로컬 결정만 기본으로 합니다. main/master에서 안전하게 릴리즈하고 기존 PR 충돌, CI, 로컬 커밋/푸시를 따라갑니다. 워크트리 생성, 마이그레이션, 안전한 정리, “브랜치가 이미 체크아웃됨”, 구현 완료 후 Git 전달, 스택형/종속 PR 분할, `gh stack`을 사용해 스택을 생성, 보기, 동기화, 구현하는 경우, PR 병합 충돌, 체크 실패, 병합 가능하도록 수정, 커밋되지 않거나 푸시되지 않은 수정 처리에 적용됩니다. 이는 Git 토폴로지와 전달만 관리하며 도메인 구현이나 프로젝트 설계를 장악하지 않습니다; `gh stack`의 정확한 구문은 로컬 `--help`에서 확인할 수 있습니다. 기본 전달은 메인 작업공간 브랜치의 암묵적 전환, Ready, merge, retarget, release, 또는 force‑push를 허용하지 않습니다.
