Usar Git/GitHub para organizar la topología de checkout/worktree de una corriente de trabajo de cambios, su pila de ramas/PR dependientes y un límite de entrega unificado: identificar repositorios estandarizados y, por defecto, aislar implementaciones ordinarias con un worktree propietario; las solicitudes de PR explícitas también, por defecto, permiten worktrees. Proceder secuencialmente según el punto final explícito del usuario, con los repositorios estandarizados por defecto a borradores de PR y los repositorios no estandarizados por defecto a decisiones locales para commit, push y PR. Liberar de forma segura desde main/master, y dar seguimiento a los conflictos de PR existentes, CI y commit/push local. Aplicable a la creación de worktree, migración, limpieza segura, “rama ya revisada”, entrega de Git después de que la implementación esté completada, división de PR apilados/dependientes, usar `gh stack` para crear, ver, sincronizar o integrar una pila, y manejar conflictos de merge de PR, verificaciones fallidas, corregirlas para que sean fusionables, o corregir cambios no confirmados o no enviados. Solo gestiona la topología y entrega de Git, sin asumir la implementación del dominio o el diseño del proyecto; la sintaxis exacta de `gh stack` se obtiene del `--help` local. La entrega predeterminada no autoriza el cambio implícito de la rama principal del área de trabajo, Ready, merge, retarget, release o force‑push.
