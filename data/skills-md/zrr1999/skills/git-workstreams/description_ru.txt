Используйте Git/GitHub для организации топологии checkout/worktree потока изменений, его зависимого стека веток/PR и единой границы поставки: определите нормализованные репозитории и по умолчанию изолируйте обычные реализации в их принадлежном worktree; явные запросы PR также по умолчанию допускают worktree. Затем действуйте согласно явному конечному пункту пользователя, при этом нормализованные репозитории по умолчанию используют Draft PR, а ненормализованные репозитории — локальные решения для commit, push и PR. Выполняйте безопасный релиз из main/master; учитывайте существующие конфликты PR, CI и локальные commit/push. Применимо к созданию worktree, миграции, безопасному очищению, «ветка уже проверена out», доставке Git после завершения реализации, разбиению стековых/зависимых PR, использованию `gh stack` для создания, просмотра, синхронизации или завершения стека, а также обработке конфликтов слияния PR, неудач проверок, исправлению до состояния mergeable и исправлению незакоммиченных или непушенных изменений. Он управляет только топологией Git и поставкой, не беря на себя реализацию домена или проектный дизайн; точный синтаксис `gh stack` можно узнать из локального `--help`. Доставка по умолчанию не разрешает неявное переключение основной ветки рабочей области, Ready, merge, retarget, release или force‑push.
