Use Git/GitHub to organize the checkout/worktree topology of a change workstream, its dependent branch/PR stack, and a unified delivery boundary: identify normalized repositories and, by default, isolate regular implementations with the owning worktree; explicit PR requests also default to allowing a worktree. Then proceed according to the user’s explicit endpoint, with normalized repositories defaulting to Draft PRs and non‑normalized repositories defaulting to local decisions for commit, push, and PR. Release safely from main/master; follow existing PR conflicts, CI, and local commit/push. Applicable to worktree creation, migration, safe cleanup, “branch already checked out,” Git delivery after implementation is complete, splitting stacked/dependent PRs, using `gh stack` to create, view, sync, or land a stack, as well as handling PR merge conflicts, checks failures, fixing until mergeable, and fixing uncommitted or unpushed changes. It only manages Git topology and delivery, without taking over domain implementation or project design; the exact syntax of `gh stack` can be discovered from the local `--help`. Default delivery does not authorize implicit switching of the main work area branch, Ready, merge, retarget, release, or force‑push.
