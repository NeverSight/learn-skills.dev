استخدم Git/GitHub لتنظيم طوبولوجيا السحب/شجرة العمل لتدفق التغيير، ومجموعة الفروع/طلبات السحب التابعة له، وحدود التسليم الموحدة: حدد المستودعات المعيارية وبشكل افتراضي عزل التنفيذات العادية مع شجرة العمل المالكة؛ طلبات السحب الصريحة أيضاً تُفترض أنها تسمح بشجرة عمل. ثم تابع وفقًا لنقطة النهاية الصريحة للمستخدم، مع تعيين المستودعات المعيارية لتصبح طلبات سحب مسودة بصورة افتراضية، والمستودعات غير المعيارية تُعطى قرارات محلية للالتزام، والدفع، وطلب السحب. أطلق الإصدار بأمان من main/master؛ وتبع تعارضات طلب السحب الحالية، وCI، والالتزام/الدفع المحلي. ينطبق ذلك على إنشاء شجرة العمل، والترحيل، والتنظيف الآمن، و«الفرع مستخرج بالفعل»، وتسليم Git بعد إكمال التنفيذ، وتقسيم طلبات السحب المتراصة/التابعة، واستخدام `gh stack` لإنشاء أو عرض أو مزامنة أو دمج مجموعة، وكذلك التعامل مع تعارضات دمج طلب السحب، وفشل الفحوصات، وإصلاحها حتى تصبح قابلة للدمج، وإصلاح التغييرات غير المرتكبة أو غير المدفوعة. إنه يدير فقط طوبولوجيا Git والتسليم، دون تولي تنفيذ المجال أو تصميم المشروع؛ يمكن اكتشاف الصياغة الدقيقة لـ `gh stack` من خلال `--help` المحلي. التسليم الافتراضي لا يسمح بالتبديل الضمني لفرع مساحة العمل الرئيسية، أو Ready، أو الدمج، أو إعادة التوجيه، أو الإصدار، أو الدفع القسري.
