Git/GitHub を使用して、変更作業フローの checkout/worktree トポロジー、その依存ブランチ/PR スタック、そして統合デリバリ境界を整理します。正規化されたリポジトリを特定し、デフォルトで所有する worktree に通常の実装を分離します。明示的な PR リクエストもデフォルトで worktree の利用を許可します。その後、ユーザーの明示的なエンドポイントに従って進めます。正規化されたリポジトリはデフォルトで Draft PR とし、正規化されていないリポジトリはコミット、プッシュ、PR のローカル決定をデフォルトとします。main/master から安全にリリースし、既存の PR コンフリクト、CI、ローカルのコミット/プッシュに従います。worktree の作成、移行、安全なクリーンアップ、「ブランチがすでにチェックアウトされている」状態、実装完了後の Git デリバリ、スタック化された/依存する PR の分割、`gh stack` を使用したスタックの作成、表示、同期、または着地、さらに PR マージコンフリクト、チェック失敗の処理、マージ可能になるまでの修正、未コミット・未プッシュの変更の修正にも適用できます。これは Git のトポロジーとデリバリのみを管理し、ドメイン実装やプロジェクト設計を奪うものではありません。`gh stack` の正確な構文はローカルの `--help` で確認できます。デフォルトのデリバリは、メイン作業領域ブランチの暗黙的な切替、Ready、マージ、リターゲット、リリース、または force‑push を許可しません。
