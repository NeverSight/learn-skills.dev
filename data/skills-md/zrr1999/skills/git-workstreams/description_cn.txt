使用 Git/GitHub 来组织变更工作流的检出/工作树拓扑、其依赖的分支/PR 栈以及统一的交付边界：识别标准化仓库，并默认在拥有工作树的情况下隔离常规实现；显式的 PR 请求也默认允许使用工作树。然后按照用户明确的终点进行操作，标准化仓库默认使用草稿 PR，非标准化仓库默认在本地决定提交、推送和 PR。安全地从 main/master 发布；遵循现有的 PR 冲突、CI 和本地提交/推送。适用于工作树创建、迁移、安全清理、“分支已检出”、实现完成后的 Git 交付、拆分堆叠/依赖 PR、使用 `gh stack` 创建、查看、同步或落地堆叠，以及处理 PR 合并冲突、检查失败、修复直至可合并、以及修复未提交或未推送的更改。它仅管理 Git 拓扑和交付，不接管领域实现或项目设计；`gh stack` 的确切语法可通过本地 `--help` 查询。默认交付不授权隐式切换主工作区分支、Ready、合并、重新定位、发布或强制推送。
