Usa Git/GitHub per organizzare la topologia di checkout/worktree di un flusso di lavoro di modifica, il suo stack di branch/PR dipendente e un confine di consegna unificato: identifica i repository normalizzati e, per impostazione predefinita, isola le implementazioni regolari con il worktree di proprietà; le richieste PR esplicite consentono di default anche un worktree. Prosegui quindi secondo il punto finale esplicito dell'utente, con i repository normalizzati che di default generano PR in bozza e i repository non normalizzati che di default lasciano decisioni locali per commit, push e PR. Rilascia in sicurezza da main/master; segui i conflitti PR esistenti, CI e i commit/push locali. Applicabile alla creazione, migrazione e pulizia sicura del worktree, al “branch già checkout”, alla consegna Git dopo il completamento dell'implementazione, alla suddivisione di PR impilati/dipendenti, all'uso di `gh stack` per creare, visualizzare, sincronizzare o atterrare uno stack, nonché alla gestione dei conflitti di merge PR, dei fallimenti dei controlli, della correzione finché non sia mergabile, e alla correzione di cambiamenti non committati o non pushati. Gestisce solo la topologia e la consegna di Git, senza assumersi l'implementazione del dominio o la progettazione del progetto; la sintassi esatta di `gh stack` può essere scoperta dal `--help` locale. La consegna predefinita non autorizza lo switch implicito del branch dell'area di lavoro principale, Ready, merge, retarget, release o force‑push.
