Avancez les tâches transversales, les décisions de conception logicielle et l’orchestration déléguée qui nécessitent le contexte du projet pour atteindre les normes de finalisation dans le périmètre autorisé : clarifiez les objectifs nécessaires, examinez les projets existants ou de référence, sélectionnez la tranche vérifiable minimale, déterminez les limites des modules/interfaces/états, séparez les dépendances et organisez le travail en briefs bornés. Applicable aux requêtes telles que « quelle est la prochaine étape du projet », « planifier les changements après comparaison avec les projets de référence », « comment diviser les modules/interfaces », « comment arbitrer les options de refactorisation », « comment phaser le déploiement », « assigner à des sous‑agents », « rédiger un brief exécutable », « comment planifier le travail parallèle/dépendances », etc. N’utilisez pas cela pour des modifications ponctuelles avec des limites claires qui ne nécessitent pas d’avancement du projet, de jugement de conception ou d’orchestration déléguée ; lors de la création ou de la mise à jour d’EVOLUTION.md, utilisez la compétence « evolution » de zendev. Pour les livrables qui se limitent à la sélection de technologies/outils ou à une chaîne d’outils Python, utilisez « tech‑preferences » ; pour la documentation d’API, les audits de qualité, les flux de travail Git, la flotte SSH ou les tâches Zellij, utilisez directement la compétence spécialisée correspondante.
