# Writing style

让文章保留作者的问题意识和判断依据，同时补足理解所需的解释。新文章从组织内容时考虑风格；已有文章默认在原结构上局部修订。

## 使用

写作前读取 [风格规范](references/style.md)，再按文体选读 [样文与编辑示例](references/examples.md)。样文是证据，其中标为编辑建议的文字不是作者认可的原话。

- 从请求、原稿和仓库约定确认读者、具体问题、已有知识与交付范围。能从材料判断时直接推进；只有会改变文章主张或受众的重要缺口才询问。
- 新写文章时，先确定读者需要理解的机制和作者实际作出的取舍，再组织大纲。改写已有文章时，默认保留章节、顺序、例题、论证路径和个人叙述；“改写／润色／按我的风格”本身不授权重构全文。只有用户明确要求重写结构，或局部修订确实无法解决问题时，才提出具体的结构调整供用户选择。
- 改写前辨认原文的事实、条件、推导、个人经历与偏好。保留有用信息和真实声音；已验证的错误应修正并在交付说明中解释，不能因“忠实原文”保留错误。
- 起草后分别检查内容和表达。公式用代数或符号计算验证；命令、版本与时效性结论按任务需要读取实际代码、运行结果或一手资料。发现无法核实的关键内容，明确缺口，不补造事实。
- 按项目规则完成内容格式和构建检查。检查通过只能证明对应项目，不代表文风已获作者认可。

## 交付与反馈

写文件时正文只保留面向读者的内容，修改原因和验证结果放在交付说明。只要求正文时直接给正文；要求解释修改时，提供有位置的前后对照，不能以“只输出正文”为由省略说明。

本 skill 不授权扩大改写范围、发布文章或修改外部系统。第三方引文保持原意与出处，不套作者口吻；作者的 AI 辅助来源说明应保留。

后续反馈先作为具体修改意见处理。仅在用户明确要求更新本 skill 时调整规范；生成稿和未经确认的修改建议不能自动变成作者样文。案例用于帮助判断，不要求每次复刻其句式、术语或结构。
