Construisez, créez et déployez des Goldsky Subgraphs — des API GraphQL hébergées sur des données on‑chain. Utilisez‑les lorsqu’un utilisateur veut créer, générer, écrire ou déployer un subgraph ; concevoir un schéma/entités ; écrire ou corriger des gestionnaires de mapping AssemblyScript ; configurer subgraph.yaml (gestionnaires, modèles, instantané/no‑code depuis l’ABI) ; mettre en place des points de terminaison GraphQL, des tags ou des webhooks ; optimiser un subgraph lent (eth_calls, entités immuables) ; ou mettre en pause/reprendre un subgraph. Déclencheurs : « build/deploy/scaffold un subgraph », « write a mapping », « design a schema », « subgraph.yaml », « instant subgraph », « combine/compose/merge multiple subgraphs », « cross‑chain subgraph », « optimize indexing speed », « too many eth_calls », « pause/resume subgraph ». Pour un subgraph qui échoue, est bloqué, génère des erreurs ou ne se déploie pas, utilisez /subgraph‑doctor (l’optimisation d’un subgraph sain relève d’ici, pas du doctor). Pour migrer hors The Graph, utilisez /subgraph‑migrate. Pour diffuser les données brutes de la chaîne vers une base de données sans GraphQL, utilisez /turbo‑builder.
