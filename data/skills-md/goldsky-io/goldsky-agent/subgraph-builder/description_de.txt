Bauen, authorisieren und deployen Sie Goldsky Subgraphs — gehostete GraphQL‑APIs über On‑Chain‑Daten. Verwenden Sie dies, wenn der Benutzer ein Subgraph erstellen, scaffolden, schreiben oder deployen möchte; ein Schema/Entitäten entwerfen; AssemblyScript‑Mapping‑Handler schreiben oder reparieren; subgraph.yaml konfigurieren (Handler, Vorlagen, Instant‑/No‑Code aus ABI); GraphQL‑Endpunkte, Tags oder Webhooks einrichten; einen langsamen Subgraph optimieren (eth_calls, unveränderliche Entitäten); oder einen Subgraph pausieren/fortsetzen. Auslöser bei: „build/deploy/scaffold a subgraph“, „write a mapping“, „design a schema“, „subgraph.yaml“, „instant subgraph“, „combine/compose/merge multiple subgraphs“, „cross-chain subgraph“, „optimize indexing speed“, „too many eth_calls“, „pause/resume subgraph“. Für einen Subgraph, der fehlschlägt, stecken bleibt, Fehler wirft oder nicht deployt werden kann, verwenden Sie /subgraph-doctor (Optimierung eines gesunden Subgraphen gehört hierher, nicht zum Doctor). Für die Migration von The Graph verwenden Sie /subgraph-migrate. Für das Streamen von rohen Kettendaten in eine Datenbank ohne GraphQL verwenden Sie /turbo-builder.
