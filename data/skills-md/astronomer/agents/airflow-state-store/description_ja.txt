Airflow 3.3 の AIP-103 キー/値ストア (`task_state_store`、`asset_state_store`) とクラッシュ セーフな `ResumableJobMixin` を使用して、再試行および DAG 実行後もタスクとアセットの状態を保持します。ユーザーがタスク状態ストア、タスク内のチェックポイント設定、再試行後の状態の保持、ワーカーのクラッシュ後も存続するジョブ ID、ウォーターマーク、アセットのメタデータ、再開可能なタスク、クラッシュセーフなオペレーター、または「Airflow 3.3 の新機能」について質問する場合に使用します。また、タスク内調整状態に変数または XCom を使用する DAG を読み取るときにも積極的に使用します。アンチパターンにフラグを立てて、代わりに task_state_store またはasset_state_store を推奨します。また、外部システムにジョブを送信してその終了を待機する DAG (Databricks、Snowflake、BigQuery、Redshift、Spark、dbt Cloud、EMR、AWS Batch など) をレビューするときに積極的に使用します。これは、1 つの送信して待機するオペレーターであるか、別個の送信タスクとセンサー/ポーリング タスクに分割されているかに関係ありません。これには、「wait_for_termination」、「deferrable」、「durable」、実行/ジョブ ID をポーリングする手動センサー、および送信 + センサーの分割を 1 つのタスクに折りたたむかどうかが含まれます。 「task_state_store」/「asset_state_store」/「ResumableJobMixin」状態永続化部分には Airflow 3.3 以降が必要です。 submit+poll アーキテクチャのガイダンス自体は、どの Airflow バージョンにも適用されます。3.3 より前の DAG の場合は、このスキルをスキップしないでください。
