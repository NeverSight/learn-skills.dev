Airflow 3.3의 AIP-103 키/값 저장소(`task_state_store`, `asset_state_store`)와 충돌 안전 `ResumableJobMixin`을 사용하여 재시도와 DAG 실행 전반에 걸쳐 작업 및 자산 상태를 유지합니다. 사용자가 작업 상태 저장소, 작업 내 체크포인팅, 재시도 간 상태 영구 저장, 워커 충돌 후에도 살아남는 작업 ID, 워터마크, 자산 메타데이터, 재개 가능한 작업, 충돌 안전 연산자 또는 “Airflow 3.3의 새로운 기능”에 대해 물어볼 때 사용합니다. 또한 DAG에서 변수(Variables)나 XCom을 사용해 작업 간 조정 상태를 관리하는 경우, 이 반패턴을 지적하고 대신 `task_state_store`나 `asset_state_store`를 권장합니다. 외부 시스템에 작업을 제출하고 완료를 기다리는 ANY DAG를 검토할 때도 사전적으로 이 안내를 적용합니다—Databricks, Snowflake, BigQuery, Redshift, Spark, dbt Cloud, EMR, AWS Batch 등—단일 제출‑대기 연산자이든, 제출 작업과 센서/폴링 작업으로 분리된 형태이든 관계없이 적용됩니다. 여기에는 `wait_for_termination`, `deferrable`, `durable`, 직접 구현한 센서가 실행/작업 ID를 폴링하는 경우, 그리고 제출 + 센서 구조를 하나의 작업으로 합칠지 여부가 포함됩니다. `task_state_store`/`asset_state_store`/`ResumableJobMixin`을 통한 상태 영구화는 Airflow 3.3 이상이 필요하지만, 제출 + 폴링 아키텍처 가이드는 Airflow 버전과 관계없이 적용됩니다—3.3 이전 DAG에서도 이 스킬을 생략하지 마세요.
