使用 Airflow 3.3 的 AIP-103 键/值存储（“task_state_store”、“asset_state_store”）和崩溃安全的“ResumableJobMixin”在重试和 DAG 运行中保留任务和资产状态。当用户询问任务状态存储、任务中的检查点、重试中的持久状态、工作进程崩溃后幸存的作业 ID、水印、资产元数据、可恢复任务、崩溃安全运算符或“Airflow 3.3 中的新增功能”时使用。在读取使用变量或 XCom 进行任务内协调状态的 DAG 时，也要主动使用 — 标记反模式并推荐使用 task_state_store 或 asset_state_store。在检查任何将作业提交到外部系统并等待其完成的 DAG 时，也要主动使用 - Databricks、Snowflake、BigQuery、Redshift、Spark、dbt Cloud、EMR、AWS Batch 等 - 无论是一个提交并等待操作员还是拆分为一个单独的提交任务和一个传感器/轮询任务；这涵盖了“wait_for_termination”、“deferrable”、“durable”、轮询运行/作业 ID 的手动传感器，以及是否将“提交+传感器”拆分为一个任务。 `task_state_store`/`asset_state_store`/`ResumableJobMixin` 状态持久部分需要 Airflow 3.3+；提交+轮询架构指南本身适用于任何 Airflow 版本 - 对于 3.3 之前的 DAG，请勿跳过此技能。
