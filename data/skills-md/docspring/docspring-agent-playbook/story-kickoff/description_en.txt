Investigates a ticket before any code is written. Has a short path for mechanical changes. Otherwise records the exact code it investigates, checks the ticket's claims against the code, maps callers, existing data and the behavior other code, clients and customers rely on with bounded read-only investigators, then writes a plan whose regression tests each state how they fail on the parent commit and which marks only real judgment calls for the user. Builds test-first, checks the result against every recorded decision before the PR, hands off to the team's review process, and turns what that review found into new lessons. Use when the user says "start work on ENG-123", "pick up this issue", "let's do this ticket", "work on issue 42", "plan this before building it" or "investigate before coding". Not for reviewing a branch or PR that already exists (pr-review or second-opinion-review).
