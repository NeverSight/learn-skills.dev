Utilisez lorsque vous devez appliquer les meilleures pratiques de codage sécurisé Java — notamment la validation des entrées non fiables, la défense contre les attaques d’injection avec des requêtes paramétrées, la réduction de la surface d’attaque via le principe du moindre privilège, l’application d’algorithmes cryptographiques robustes, la gestion sécurisée des exceptions sans exposer de données sensibles, la gestion des secrets à l’exécution, l’évitement de la désérialisation non sécurisée, et le codage de la sortie pour prévenir les XSS. Cela doit être déclenché pour des requêtes telles que : Réviser le code Java pour le codage sécurisé ; Trouver les risques de validation d’entrée dans le code Java ; Réviser le code Java pour les vulnérabilités d’injection ; Améliorer la gestion sécurisée des erreurs dans les services Java ; Renforcer le code Java contre les failles de sécurité courantes.
