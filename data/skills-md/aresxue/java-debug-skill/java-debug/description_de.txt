Java-Remote-Breakpoint-Debugging. Verwendet einen internen JDI‑Client (Zero‑Dependency‑Fat‑Jar, HTTP‑Server‑Modus, keine tmux/sleep‑Abhängigkeit), um sich an den JDWP‑Port einer entfernten JVM anzuhängen; die KI setzt eigenständig Breakpoints, sammelt Aufrufstapel und lokale Variablen, wertet Ausdrücke aus und führt Einzelschritte aus, um die Ursache zu finden. Im Vergleich zu jdb: SUSPEND_EVENT_THREAD friert nur den betroffenen Thread ein statt der gesamten JVM, die Interaktion erfolgt über strukturiertes JSON, und ein Breakpoint‑Treffer liefert automatisch Stack + Lokale zurück.
