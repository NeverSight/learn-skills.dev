Setzen Sie Authentifizierung, Ratenbegrenzung, IP‑Beschränkungen, Header‑Regeln oder eine benutzerdefinierte Antwort vor einen ngrok‑Endpunkt mithilfe einer Traffic‑Policy, ohne den Anwendungscode zu ändern. Deckt das Erfordernis einer Anmeldung (OAuth/OIDC), das Sperren auf bestimmte IPs, das Blockieren oder Verweigern von Anfragen, das Zurückgeben einer Wartungsseite oder einer benutzerdefinierten Antwort sowie das Einfügen oder Entfernen von Headern ab. Verwenden Sie dies, wenn der Nutzer den Endpunkt schützen, absichern, drosseln oder eine API‑Gateway‑Schicht hinzufügen möchte. Verwenden Sie dies, wenn der Nutzer sagt: „add auth to my ngrok URL“, „require Google login“, „rate limit my endpoint“, „restrict by IP“, „block a path“ oder „put up a maintenance page“.
