(alamops) Enquête approfondie d’une fonctionnalité ou d’un changement avant que quiconque ne le planifie ou le code. Déploie en parallèle des agents de recherche en lecture seule sur la base de code (points d’entrée, chemins frères, conventions de test, mode de fonctionnement de l’application), l’historique Git et la documentation en direct des bibliothèques, puis exécute de petites expériences “scratchpad” pour prouver ce que la lecture seule ne suffit pas à établir. Enregistre ce que nous savons / avons prouvé / supposons / devons demander, ainsi qu’un inventaire complet de chaque appelant, point de propagation et surface de données existantes, dans `docs/plans/<slug>-investigation.md`. À utiliser lorsque l’utilisateur souhaite enquêter ou rechercher un changement avant de le construire, cartographier son rayon d’impact, trouver chaque site d’appel qu’une migration doit toucher, ou répondre à une question de faisabilité — cette bibliothèque, cette version ou cette approche fonctionnera‑t‑elle réellement ici — avant de s’engager. Phase 1 de `implement`, exécutable seule ; accepte `--no-spikes`. Lecture seule sur le code source. Pas destiné au débogage d’un bug en direct ou d’une page lente, à l’explication du code existant, à un prototype autonome dont le numéro constitue le livrable, ou à la construction de la fonctionnalité (implement).
