(alamops) führt ausschließlich die Codierungsarbeit eines genehmigten Implementierungsplans aus, mit parallelen Sub‑Agenten, die nie kollidieren. Es legt einen Branch an und protokolliert das Basis‑SHA, prüft, dass keine zwei Aufgaben in einer Welle dieselbe Datei besitzen, gibt jedem Aufgaben‑Agenten ein eigenständiges Briefing mit einer Keine‑TODO‑Vollständigkeitsklausel, hält Wellen‑Barrieren, isoliert unvermeidbare gemeinsam genutzte Dateien in Worktrees, leitet den gemeldeten Rest in die nächste Welle weiter und committet pro Welle einen Checkpoint. Verwenden, wenn der Nutzer einen Plan übergibt (`docs/plans/<slug>.md`, ein `write-plan`‑Output oder eine Aufgabenaufteilung mit Dateizuständigkeit) und den Auftrag auf das Schreiben von Code beschränkt – nur den Code, den ich selbst prüfe und teste, nur die Codierungswellen ausführen, diese Aufgaben ohne Tests ausbreiten – oder diese Fähigkeit namentlich verlangt. Ein einfaches „execute this plan“ ohne solche Beschränkung gehört zu `implement`, das den Plan durch Review und Tests bis zum grünen Status führt. Phase 4 von `implement`, eigenständig ausführbar. Nicht zum Schreiben des Plans (write‑plan) oder für eine einzelne, gezielte Änderung.
