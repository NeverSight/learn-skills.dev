(alamops) Caza de bugs adversarial de extremo a extremo en una aplicación en ejecución. Conduce la app real como un usuario hostil, confundido o impaciente — entradas basura y de límite, envíos dobles, pasos fuera de orden, botón de retroceso y recarga a mitad del flujo, sesiones expiradas, dos pestañas sobre el mismo registro, red inestable, parámetros de URL manipulados — para provocarle excepciones, estado corrupto, pérdida de datos o dejar la UI colgada. Observa la consola, la red y los logs del servidor, no solo la vista. Luego reproduce cada hallazgo de forma determinista, rastrea la causa raíz en el código, escribe una prueba de regresión e2e *fallida*, corrige el defecto y demuestra que la suite pasa a verde. Úsalo siempre que el usuario diga “rompe mi app”, “intenta romperla”, “caza bugs”, “bug bash”, “barrido QA”, pruebas exploratorias / adversariales / caos / mono / fuzz, “encuentra bugs usándola de verdad”, “haz clic por ahí y ve qué explota”, o solicite una prueba e2e para que un bug no vuelva. Se ejecuta solo contra objetivos locales/dev/staging que el usuario controla. No es para revisar un diff (code‑review), desarrollar una funcionalidad (implement) ni para triagear errores de producción desde Sentry.
