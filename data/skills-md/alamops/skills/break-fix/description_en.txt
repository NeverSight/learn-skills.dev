(alamops) Adversarial end-to-end bug hunt on a running app. Drives the real app like a hostile, confused, or impatient user — junk and boundary input, double-submits, out-of-order steps, back-button and refresh mid-flow, expired sessions, two tabs on one record, flaky network, tampered URL params — to make it throw, corrupt state, lose data, or strand the UI. Watches console, network and server logs, not just the viewport. Then reproduces each finding deterministically, traces the root cause in code, writes a *failing* e2e regression test, fixes the defect, and proves the suite goes green. Use whenever the user says break my app, try to break it, bug hunt, bug bash, QA sweep, exploratory / adversarial / chaos / monkey / fuzz testing, "find bugs by actually using it", "click around and see what explodes", or asks for an e2e test so a bug can't come back. Runs only against local/dev/staging targets the user controls. Not for reviewing a diff (code-review), building a feature (implement), or triaging production errors from Sentry.
