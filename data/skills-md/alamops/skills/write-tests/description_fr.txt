(alamops) Rédige les tests dont un changement a besoin — unitaires, d’intégration et e2e chaque fois qu’il implique un flux visible par l’utilisateur ou franchit une frontière de processus. Utilisez‑le chaque fois que l’utilisateur demande que des tests soient écrits, ajoutés ou retapissés — pour les changements sur leur branche par rapport à main, un nouveau point de terminaison, un module sous‑testé, ou un flux e2e — dans n’importe quel framework (jest, vitest, pytest, Playwright, Cypress…). Fonctionne à partir d’une décomposition des tests d’un plan, d’un diff de branche, ou d’un module ou flux nommé ; répartit les agents partitionnés par module testé ; étend le harnais et les fixtures existants ; couvre les critères d’acceptation ainsi que les chemins négatifs et les états d’échec ; garde les e2e déterministes ; enregistre « e2e non applicable » comme une décision explicite ; et prouve que chaque nouveau test s’exécute et peut échouer, signalant de vrais défauts du produit au lieu de plier les tests pour qu’ils passent. Phase 6 de `implement`, exécutable seule ; accepte `--no-e2e`. Pas destiné à exécuter ou réparer une suite qui échoue (test‑loop), à chasser les bugs sur une application en cours d’exécution (break‑fix), ou à développer la fonctionnalité (implement).
