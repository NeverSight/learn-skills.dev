(alamops) schreibt die Tests, die ein Change benötigt — Unit-, Integrations- und End‑zu‑End‑Tests, wann immer ein benutzer‑sichtbarer Ablauf vorliegt oder eine Prozessgrenze überschritten wird. Verwende es immer dann, wenn der Nutzer um das Schreiben, Hinzufügen oder Nachtragen von Tests bittet — für Änderungen auf seinem Branch gegenüber main, einen neuen Endpoint, ein wenig getestetes Modul oder einen End‑zu‑End‑Ablauf — in jedem Framework (jest, vitest, pytest, Playwright, Cypress …). Arbeitet aus einer Test‑Aufschlüsselung eines Plans, einem Branch‑Diff oder einem benannten Modul bzw. Ablauf; verteilt Agenten, die nach zu testendem Modul partitioniert sind; erweitert das bestehende Harness und Fixtures; deckt Akzeptanzkriterien plus negative Pfade und Fehlerzustände ab; hält End‑zu‑End‑Tests deterministisch; protokolliert „e2e not applicable“ als explizite Entscheidung; und beweist, dass jeder neue Test läuft und fehlschlagen kann, reale Produktdefekte meldet, anstatt Tests zu verbiegen, damit sie bestehen. Phase 6 von `implement`, eigenständig ausführbar; akzeptiert `--no-e2e`. Nicht zum Ausführen oder Fixen einer fehlschlagenden Suite (test‑loop), Bug‑Jagen in einer laufenden App (break‑fix) oder zum Implementieren des Features (implement).
