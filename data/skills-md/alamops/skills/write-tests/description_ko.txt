(alamops) 작성하는 테스트는 변경 사항에 필요한 — 유닛, 통합, 그리고 e2e 테스트로, 사용자가 볼 수 있는 흐름이 있거나 프로세스 경계를 넘을 때마다 작성한다. 사용자가 테스트 작성, 추가 또는 보강을 요청할 때마다 사용한다 — 브랜치와 메인 간의 변경, 새로운 엔드포인트, 테스트가 부족한 모듈, 혹은 e2e 흐름 등— 어떤 프레임워크든(jest, vitest, pytest, Playwright, Cypress…) 상관없다. 계획의 테스트 분해, 브랜치 차이, 혹은 명명된 모듈·흐름에서 동작한다; 테스트 대상 모듈별로 파티션된 에이전트들을 퍼뜨린다; 기존 하네스와 픽스처를 확장한다; 수용 기준과 부정 경로·실패 상태를 모두 포괄한다; e2e를 결정적으로 유지한다; ‘e2e 적용 불가’를 명시적 결정으로 기록한다; 그리고 새로운 테스트가 실행되고 실패할 수 있음을 증명하여, 테스트를 통과시키기 위해 억지로 만들지 않고 실제 제품 결함을 보고한다. `implement`의 단계 6으로, 독립 실행 가능하고 `--no-e2e`를 허용한다. 테스트 스위트를 실행하거나 수정하는 경우(test‑loop), 실행 중인 앱에서 버그를 찾는 경우(break‑fix), 혹은 기능을 구현하는 경우(implement)에는 사용하지 않는다.
