(alamops) `docs/plans/<slug>.md`에 분해 가능한 구현 계획을 작성합니다 — 목적, 파일:라인 앵커가 포함된 기반 컨텍스트, 접근 방식 및 기각된 대안, 각 작업이 파동 형제와 겹치지 않는 파일을 소유하도록 하는 작업 분해, 레이어별 테스트 작업과 명시적인 e2e 결정 및 실행 레시피, 실행 파동, 블래스트 반경, 열려 있는 가정, 그리고 모든 잠재적 후속 작업을 배정하는 완성도 원장. 존재할 경우 `investigate`/`grill` 출력에 기반하고, 없을 경우 읽기 전용으로 스스로 근거를 마련한 뒤 부담되는 질문을 먼저 합니다. 승인을 위해 계획을 제시하고 코드를 변경하지 않으며; `implement`와 `execute-plan`은 이를 그대로 실행할 수 있습니다. 사용자는 구현 계획을 작성하거나 초안을 만들 때, 코딩 전에 무언가를 구축하는 방법을 계획할 때, 변경을 병렬 작업으로 나눌 때, 또는 사양을 실행 계획으로 전환할 때 이 명령을 사용합니다. `implement`의 3단계이며 독립적으로 실행 가능합니다. 제품 PRD(to‑prd), 인간에게 보여지는 엔지니어링 티켓(create‑tasks), 실제 구현(implement)에는 사용하지 않으며.
