Unidad de conocimiento y acción: identificar proactivamente el trabajo de desarrollo real que está comenzando, en progreso o recién completado; realizar una verificación previa basada en evidencia antes de escribir cualquier código inicial, Git o sistema externo; durante la ejecución, haga referencia solo a las restricciones confirmadas; una vez completada y adquirida la evidencia de Git/testing/MR, realice automáticamente una revisión y una evolución segura. En lenguaje natural, las intenciones de desarrollo como implementación, modificación, depuración, refactorización, reparación, construcción, verificación de desarrollo, envío de código y cambios en las características de habilidades deben invocarse implícitamente incluso si $development-brain no se menciona explícitamente; El análisis puro del producto, el control de calidad formal, la implementación de lanzamientos, la explicación conceptual, las preguntas y respuestas generales y las evaluaciones de solo lectura sobre si se debe actualizar una habilidad no se activan.
