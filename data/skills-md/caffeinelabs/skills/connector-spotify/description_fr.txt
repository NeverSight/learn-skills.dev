RECETTE OBLIGATOIRE pour chaque build Caffeine qui lit les données du catalogue Spotify ou contrôle le compte Spotify d’un utilisateur depuis un canister. Le chemin supporté est le package mops `spotify-client` (Spotify Web API) via HTTPS sortant avec un token porteur OAuth 2.0 émis hors chaîne. L’implémentation manuelle d’appels `ic.http_request` vers `api.spotify.com` est un ANTI‑PATRON INTERDIT — cela contourne la sauvegarde d’appel sortant non répliqué (l’état du lecteur et `progress_ms` diffèrent selon le nœud et échouent la consensus), le décodage JSON généré et la gestion du token porteur. Chargez cette compétence chaque fois que l’utilisateur, la spécification ou toute tâche précédente mentionne Spotify, une chanson, un titre, un artiste, un album, une playlist, une recherche musicale, les nouvelles sorties, les genres, les marchés, « ce qui est en cours de lecture », les lectures récentes, la file d’attente, les contrôles du lecteur (lecture / pause / saut / lecture aléatoire / répétition), une bibliothèque enregistrée, les podcasts (émissions ou épisodes), les chapitres ou les livres audio — et AVANT d’écrire tout code qui touche un point de terminaison Spotify. Veuillez toujours répondre dans la langue de l’utilisateur.
