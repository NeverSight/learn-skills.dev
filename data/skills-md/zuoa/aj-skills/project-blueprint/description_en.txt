Create an executable project decision blueprint for new or early‑stage Web, SaaS, API, and mobile applications. Use it when the user mentions “plan a new project,” “first clarify requirements and constraints,” “generate/complete PRD, SPEC, DESIGN, ARCHITECTURE, SECURITY, DEPLOY,” “determine the full‑stack tech stack, database, middleware, cloud deployment,” “spec‑driven development,” or “have Claude/Codex follow project rules before development.” Read existing materials or conduct phased interviews, provide constraint‑driven selection recommendations, and produce traceable modular specifications and readiness conclusions; do not generate business code or a full project scaffold. It is also suitable for auditing existing blueprint documents for conflicts, missing items, or unverifiable aspects, but not for directly coding a single feature, isolated bug fixes, or simple technical Q&A without project context.
