Créez un plan de décision de projet exécutable pour les applications Web, SaaS, API et mobiles nouvelles ou en phase de démarrage. Utilisez-le lorsque l'utilisateur mentionne « planifier un nouveau projet », « clarifier d'abord les exigences et les contraintes », « générer/terminer PRD, SPEC, DESIGN, ARCHITECTURE, SECURITY, DEPLOY », « déterminer la pile technologique complète, la base de données, le middleware, le déploiement cloud », « développement axé sur les spécifications » ou « demander à Claude/Codex de suivre les règles du projet avant le développement ». Lire les documents existants ou mener des entretiens par étapes, fournir des recommandations de sélection fondées sur des contraintes et produire des spécifications modulaires traçables et des conclusions sur l'état de préparation ; ne générez pas de code métier ni d'échafaudage de projet complet. Il convient également à l'audit de documents de conception existants à la recherche de conflits, d'éléments manquants ou d'aspects invérifiables, mais pas au codage direct d'une seule fonctionnalité, de corrections de bugs isolés ou de simples questions et réponses techniques sans contexte de projet.
