Guide de philosophie de conception logicielle basé sur « A Philosophy of Software Design » de John Ousterhout. Utilisez cette compétence lors des revues de code, des discussions d’architecture, de la conception d’API, des décisions de décomposition de modules, de l’orientation du refactoring, de l’analyse de complexité, des améliorations de nommage et de commentaires, ainsi que de la conception de la stratégie de gestion des erreurs. Déclenchez-le lorsque l’utilisateur mentionne « le code est trop complexe », « comment diviser les modules », « conception d’interface », « réduire le couplage », « modules profonds/superficiels », « fuite d’information », « gestion des erreurs », « lisibilité du code », « philosophie de conception », « réduire la complexité », « éliminer les erreurs », ou des sujets similaires. Déclenchez-le également pour toute revue de code où un retour sur la qualité du design est demandé.

Veuillez toujours répondre dans la langue de l’utilisateur.
