Erstellen Sie evidenzbasierte Software‑/Produkt‑Roadmaps aus Repository‑Status, Tickets, Ideen, Auditergebnissen oder Nutzerzielen – priorisieren und sequenzieren Sie Arbeit über Jetzt/Als Nächstes/Später, Meilensteine, Abhängigkeiten, Risiken und Übergaben. Verwenden Sie dies, wenn nach einer Roadmap, Feature‑Roadmap, technischer Roadmap, Release‑Plan, Meilenstein‑Plan, Priorisierung des Backlogs, Sequenzierung, was als Nächstes zu bauen ist oder zur Umwandlung von Verbesserungs‑/Ideen‑/Brainstorming‑/Design‑Diskussions‑Ergebnissen in eine Ausführungssequenz gefragt wird. Nicht zur Implementierung von Code oder zum Erstellen von PR‑Level‑Plänen.
