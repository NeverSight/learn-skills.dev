يكتب مواصفات التصميم لمستند PRD المعتمد (هيكل المعلومات، تدفقات المستخدم، جرد الشاشات، ومواصفات الحالة والتفاعل لكل شاشة)، مع إعادة استخدام مكتبة المكونات الحالية للمشروع أولاً وتتبع كل شاشة إلى معرف متطلب PRD. يتم اتباع نهج خفيف افتراضيًا: ملف design‑spec.md واحد، ومواصفات كاملة فقط لأكثر 2‑3 شاشات حيوية، مع تفويض WCAG 2.2 AA إلى مراجعة‑التصميم. يُستخدم لـ "write a design spec"، "map the user flows"، "screen inventory with states"، أو "IA and screen states for this feature". لا يكتب أي كود واجهة مستخدم. ليس مخصصًا لنقد تجربة المستخدم لواجهة موجودة (استخدم review‑design)، أو نظام الرموز البصرية (استخدم product‑design‑tokens)، أو إنشاء نماذج وتصميمات بطل (استخدم codex‑imagegen).
