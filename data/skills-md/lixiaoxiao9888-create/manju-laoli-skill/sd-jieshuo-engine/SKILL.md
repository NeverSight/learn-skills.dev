# sd-jieshuo-engine · 解说叙事类专精引擎（赛道③）

## 一、角色定位

为**赛道③ 解说叙事类**（历史事件 / 历史人物介绍 / 科普知识解说）提供完整规则集。它**不产出**一整套新流程——上游锁系统、投喂格式、机检脚本的权威仍在总控；本引擎负责的是**"解说类怎么用这套流程"的适配口径**。

一句话概括本引擎存在的理由：

> **解说类的"台词"不是对白，是旁白。** 剧情演绎靠"对白 + 表演 + 情节"承载信息；解说叙事靠"旁白/解说词 + 画面注释 + 字幕"承载信息。同一套规则按剧情对白建模，会**系统性写错解说类**——语速口径错、篇幅卡口误判、分镜单位错、资产约束错位。本引擎的全部规则都从这个前提生长出来。

## 二、与总控和套装的关系

- **赛道来源**：本引擎只在总控〇·0 赛道分流锁**选定 ③ 解说类**时挂载。赛道未选定时不激活。
- **进入方式**：完整流程从总控 **short-drama-director** 进入；总控锁系统（〇·0 赛道 → 〇·1 素材来源 → A·模型 / B·画幅 / C·交付 / D·段缝）先锁定，再进入剧本层。
- **与其他子技能的关系**：
  - 与 `sd-script-engine` 是**叠加**关系（**不替代 sd-script-engine**）——解说类的"脚本"本质是**旁白稿（VO Script）**而非对白剧本；本引擎定义旁白稿的结构、写作法、与画面的映射，`sd-script-engine` 的「来源登记」纪律照常执行（历史 / 科普题材对信源分级要求尤其高）。
  - 与 `sd-recon-engine`：**素材来源锁 ③ 对标 / ④ 热点**时照常挂载采风引擎先出《对标情报卡》；历史 / 科普题材的**史实与信源纪律**由本引擎 §七 强化（T1 史料可直接引用画面，T2 讨论仅作口头转述）。
  - 与 `sd-asset-engine`（资产）/ `sd-storyboard-engine`（分镜）/ `sd-feed-engine`（投喂）/ `sd-qc-engine`（质检）是**下游传递**关系——**场景风格一致 > 人物一致**的资产口径、旁白句→画面的分镜口径、C14 配额豁免必须逐阶段传递。
- **不拥有**：锁系统（〇·0/〇·1/A/B/C/D）、七段式投喂格式、H3 格式、资产编号、机检脚本——这些权威都在总控；本引擎只提供"解说类怎么用这些"的适配口径。

## 三、触发词与进入

**触发词**：解说、拉片、盘点、逐帧拆解、口播影评、历史人物、历史事件、科普、冷知识、知识区、"一口气看懂"、纪录片解说、口播知识。

**用户直接说触发词时**，若尚未在完整管线中，先声明一句：

> 完整制作（资产、分镜、视频）请从总控 `short-drama-director` 进入；赛道请先按总控〇·0 确认（1 国内剧 / 2 海外剧 / 3 解说类 / 4 其他）。本引擎负责解说叙事类的规则集。

**进入前提**：已确认赛道为 ③ 解说类，且已明确**子类型**（历史人物志 / 历史事件战役 / 科普知识解说，三选一）。子类型未定时，先停下追问——三类共用一套骨架，但**钩子与情绪动线不同**（见 §五）。

## 四、赛道定义：解说叙事类（③）与剧情演绎类（①）的本质差异

| 维度 | ① 国内剧（剧情演绎） | ③ 解说叙事类（本引擎） |
|---|---|---|
| **信息载体** | 对白 + 表演 + 情节 | **旁白/解说词 + 画面注释 + 字幕** |
| **声音结构** | 台词为主（≥70%），VO/OS ≤30%、60~80 字/分钟封顶 | **旁白即主体（80~100%）**，对白可为零；字数按解说语速单独计 |
| **人物** | 角色连续表演、跨段一致性、FACS 表情 | **可无固定角色**；人物以"历史形象/插画形象/影像素材"出现，无需连续表演 |
| **分镜逻辑** | 剧情节拍 → 镜长 | **旁白句 → 画面**：一句旁白配 1~2 个画面 |
| **台词字段** | `台词：【角色（语气）："…"】` 锁口型 | 解说词走**画外 VO**，不锁口型；出现对白时（采访/史料引述）才用台词字段 |
| **视觉素材** | 场景资产图 + 角色 4View + 道具 | **时代场景 + 示意图/地图/图文卡 + 插画人物 + 纪实影像（标注）** |
| **资产一致性** | 角色跨镜一致是硬约束 | **场景风格一致 > 人物一致**；人物可单镜出现 |
| **质量门** | 首镜锚定、摆位必入画、人物账 | **声画信息差检查、旁白句-画面映射、史实/科普正确性、金句结尾** |
| **爆款公式** | 冲突→反转→爽点→情绪闭环 | **钩子→拆解/叙事→揭秘/Wow→升华**（详见 §五） |

**判定信号（写进 track-routing §二）**：解说 / 拉片 / 盘点 / 逐帧拆解 / 口播影评 / 历史人物志 / 历史事件 / 科普 / 冷知识 / 知识区 / "一口气看懂" / 纪录片式旁白。

## 五、三大子类型与对应爆款公式

### A. 历史人物志（人物介绍）

- **情绪动线模型**（0~100%）：反差人设钩子（0~10%）→ 出身与困顿（10~30%）→ 关键转折/高光（30~65%）→ 跌落/结局（65~85%）→ 历史评价与金句升华（85~100%）。
- **底层爆款叙事公式**：`极致人设反差 + 出身逆境/微光 + 2~3 个关键转折 + 命运结局 + 后世评价金句`
- 钩子示例："48 岁还是流氓，54 岁就当了皇帝"；"他一生只打过一场仗，却让匈奴十年不敢南下"。

### B. 历史事件/战役/朝代

- **情绪动线模型**：悬念结果前置（0~10%）→ 背景与起因（10~35%）→ 过程层层拆解（35~70%）→ 关键人物决策（70~85%）→ 影响与遗留（85~100%）。
- **底层爆款叙事公式**：`结果悬念前置 + 因果链逐层拆解 + 关键决策点 + 影响/遗产升华`
- 钩子示例："澶州城下一纸盟约，让两国和平了一百二十年——但签它的皇帝，差点不敢过河。"（仅示范句式，**史实以资料为准**）

### C. 科普/知识解说

- **情绪动线模型**：反常识/痛点钩子（0~10%）→ 生活场景切入（10~25%）→ 知识拆解 3~5 步（25~70%）→ Wow Moment（70~85%）→ 价值升华/生活应用（85~100%）。
- **底层爆款叙事公式**：`反常识结论 + 身边事切入 + 类比拆解(3~5步) + Wow时刻 + 应用升华`
- 钩子示例："你手机电池不耐用，可能不是电池的错——是你在用错误的方式充电。"

> **三层结构叙事（历史类推荐骨架）**：宏观环境（国际局势/经济）→ 国家层面（现实考量/反应）→ 个人层面（人物决策/回忆录）。适用于把宏大历史落到"人"的身上。

## 六、旁白稿（VO Script）写作规范（核心）

解说叙事类的"台词"是**旁白**，与剧情对白完全不同：

1. **语速口径**：解说旁白基准 **`4.5~6.5 字/秒`**（快于剧情对白 3.5~6，因无口型限制且信息密度是卖点）；关键金句/爆点句放慢到 **3~4 字/秒**留发酵空间；**镜长 = 旁白字数 ÷ 语速 + 画面缓冲 0.3~0.8s**。
2. **句式铁律**：短句为主（**单句 ≤25 字**）；一句一个信息点；善用设问（"为什么？"）、排比、对仗；**禁书面腔**（"该事件对后世产生了深远影响"→"这事，改变了后来几百年的走向"）。
3. **类比优先**：陌生概念必须类比（科普中国口径："黑洞就像一个宇宙下水道，连光都逃不掉"）。
4. **减负原则**（御史房口径）：**人名能不出就不出**（用"那个守城的将军"代替生僻人名）；地名/官职/年份只保留影响理解的关键 2~3 个；数字要具象化（"捐了 35 万"→"相当于他蹬三轮车绕地球 X 圈"——**数字换算须可追溯**）。
5. **钩子写法**（前三句）：冲突式 / 结果前置 / 悬念式 / 反常识式，任选其一，**≤15 字/句**，落在 0~3s。
6. **金句收尾**：结尾必有 **1 句可截图分享的升华句**（黑底金句同款），与开篇钩子呼应。
7. **声画信息差纪律（解说版 VO 法则）**：旁白负责"讲因果/讲规律/讲人物内心"，画面负责"给证据/给场景/给过程演示"——**允许画面配合旁白（画面是注释不是复述）**，但**禁止旁白念画面里已经大字写出的内容**（字幕与旁白不重复）；**把旁白删掉，画面信息量不得减少**。

> **与总控 `short-drama-director/references/vo-os-weaving.md` 的关系**：本引擎 §六 是解说类的**专门口径**；总控 VO 三纪律中的「篇幅钢性卡口」与「五类正当用途」**对解说类不适用**（解说类旁白即主体），但「VO 冷漠审视法则」的**内核（不复述画面）**必须保留，已在 §六.7 落地为「声画信息差纪律」。

## 七、画面与素材规范（AI 生产适配）

1. **时代场景优先于人物**：历史题材以"时代空镜 + 器物 + 建筑 + 服饰"建立可信年代感；每集 1 套场景风格母版（色温/胶片颗粒/服饰款式锁定），**场景风格一致性是解说类第一资产约束**。
2. **人物出现方式**：插画/历史画风人物（**避免写实真人脸红线**与"像不像本人"争议）；同一人物出现 **≤2 个形象版本**（正面像 + 全身像）即可，**不做跨镜连续表演**。
3. **示意图/地图/图文卡**：战争推进、路线、数据对比用动画地图/示意图/图文卡（可 AI 生成或后期）；**大字标题/金句卡是解说类标配**（"黑底金句"保留）。
4. **纪实影像/史料**：引用真实照片/影像时，画面上**标注来源**（延续 `sd-recon-engine` 信源分级纪律，**T1 史料可直接引用画面，T2 讨论仅作口头转述**）。
5. **防止 AI 幻觉现代元素**：历史场景提示词**必须带时代锚**（年份 + 光源类型 + 服饰 + 建筑），先出静态参考帧锁定画风再动（沿用 `asset-first-pipeline` 的 P2 资产先于分镜）。
6. **素材形态（M0/M1/M2）照常适用**：本包不持有图——素材形态由总控 `short-drama-director/references/asset-delivery-modes.md` 判定，解说类不例外。

## 八、分镜与投喂适配（解说版）

- **分镜单位 = 旁白句**：每句旁白 → 1~2 个画面；镜长由字数倒推（§六.1）。
- **七段式投喂写法**：解说词走 **`声音：` 段（画外·旁白（VO））**，台词字段为 `台词：无。`；**不锁口型、不写 FACS 表情**；画面段写场景/物件/过程演示，人物出现才写姿态。
- **⚠️ C14 画外声配额豁免（本引擎最关键的一条 · 必须显式声明）**：解说类是**全片 VO**，总控 `short-drama-director/references/vo-os-weaving.md` 的 **"VO+OS ≤30%、60~80 字/分钟"卡口对赛道③ 不适用**，替换为 §六.1 的解说语速与 §六.7 的声画信息差纪律。**`validate_prompt.py` 必须按赛道分流**——出稿机检加 **`--track 3`**：对赛道③ 稿件**整体豁免 C14 三项篇幅 WARN**（OS 镜数 / VO 镜数 / VO+OS 字数），**保留 C14 三项 FAIL 红线**（声画分离 / 写进台词字段 / 使用 `{}` 字符），并改判 **C14n 旁白-画面映射**。误报会让整包机检失效，故必须显式声明。豁免口径的唯一权威在本引擎，机检实现落在总控 `scripts/validate_prompt.py`（参数 `--track 1|2|3|4`），使用手册见 `sd-qc-engine/references/machine-check-manual.md`。
- **篇幅与语速是语义项、机检不判**：解说稿的字数/语速（`4.5~6.5 字/秒`、单句 ≤25 字）与**金句结尾存在性**、**声画信息差**（旁白不复述画面）由 `sd-qc-engine` 人工/AI 语义复核，不写成机检断言——机检只兜底 C14n 旁白-画面映射这一条可机械判定项。
- **版本适配**：解说类无对白——2.5 走官方音效字符（`<>`）；2.0 以文字声音描述写音效；**环境声 / 史料氛围音按版本契约写**。
- **段缝（D 锁）照常适用**：多段解说任务仍按 D 锁三选一衔接；**段末不写接续尾行**（【接续状态】2026-10-09 全包废止，机检 C11 反转为残留拦截）。

## 十、跨阶段交接（本引擎的主要输出）

锁稿或跨阶段传递时，**必须**携带：

```
赛道: ③ 解说类
子类型: 历史人物志 | 历史事件战役 | 科普知识解说
旁白稿: VO Script（每句旁白的镜长预算已倒推）
场景风格母版: 色温 / 胶片颗粒 / 服饰款式（跨集复用）
信源: T1 史料清单 / T2 讨论清单（沿用 sd-recon-engine 分级）
C14 豁免: 已声明赛道③ → validate_prompt 不触发 VO 篇幅告警
金句: 结尾升华句（与开篇钩子呼应的那一句）
```

**下游纪律**：

- `sd-asset-engine`：**场景风格一致 > 人物一致**；人物做"插画形象"而非"跨镜连续表演资产"。
- `sd-storyboard-engine`：分镜单位 = 旁白句；每句旁白 → 1~2 个画面；不写 FACS 表情。
- `sd-feed-engine`：解说词走 `声音：` 段，台词字段 `台词：无。`；C14 豁免随稿传递。
- `sd-qc-engine`：**按赛道③ 改判 C14**（不判 VO 篇幅超配额）；核对旁白句-画面映射与金句结尾存在性。

## 十一、禁止越界

- **不**替代 `sd-script-engine` 的六阶段链，**不**另立剧本流程（本引擎只管"解说类怎么用这条链"）；
- **不**另立投喂格式、资产编号、机检脚本（权威在总控）；
- **不**把解说类的"全片 VO"口径回写污染剧情赛道（剧情赛道的 VO/OS ≤30% 卡口不动）；
- **不**在历史/科普题材里编造史实——**信源分级纪律（T1/T2）照常执行**，T2 讨论不得升格为事实；
- **不**用写实真人脸历史人物（红线边界同总控）；
- **不**越过赛道边界——剧情剧 / 海外剧任务不套本引擎。
