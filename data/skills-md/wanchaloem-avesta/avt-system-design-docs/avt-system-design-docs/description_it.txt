Creare un set di documenti di progettazione del sistema (README.md, docs/, plans/) a partire da un ambito TOR o da qualsiasi requisito di un sistema prima dell'inizio dello sviluppo, quindi verificare che i documenti siano corretti, funzionali, coerenti e contengano un ordine completo del flusso di lavoro. Utilizzare questa capacità ogni volta che l'utente ha bisogno di analizzare o progettare un sistema a partire dalle specifiche—che l'utente scriva il flusso di lavoro da solo, indichi una cartella con un file TOR o invii un'immagine di un diagramma di flusso o di un documento. Inoltre, ogni volta che l'utente menziona TOR, ambito, requisito, specifica, SRS, documenti di progettazione del sistema, analisi di sistema, elenco delle funzionalità, flusso di lavoro, modello di dati, specifica API, elenco delle schermate, piano di sviluppo, o chiede di “creare documentazione prima di avviare il sistema”, anche se non nomina esplicitamente la competenza o non usa il termine documentazione di progettazione, applicare questo approccio. Usarlo per l'analisi e la documentazione di progettazione a partire da un TOR, ambito o requisiti per qualsiasi tipo di sistema. Non usarlo per scrittura di codice, revisione di codice o documentazione di un sistema completato come i manuali utente.

Rispondere sempre nella lingua dell'utente.
