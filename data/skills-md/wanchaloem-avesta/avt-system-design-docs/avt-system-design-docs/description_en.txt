Create a system design documentation set (README.md, docs/, plans/) from the TOR or requirements of any system before starting development, then review that the documents are correct, actually usable, not contradictory, and that the workflow is complete. Use this skill whenever the user needs to analyze or design a system from specifications, whether the user types the workflow themselves, points to a folder containing a TOR file, or sends an image of a flowchart or document. And each time the user mentions TOR, scope of work, requirement, spec, SRS, system design documents, system analysis, feature list, workflow, data model, API spec, screen list, development plan, or asks to “create documentation before starting the system,” even if the user does not name the skill or use the term design documentation directly. Use for system analysis and design documentation from a TOR, scope, or requirements for any kind of system. Do not use for code writing, code review, or documentation of a completed system such as user manuals.
