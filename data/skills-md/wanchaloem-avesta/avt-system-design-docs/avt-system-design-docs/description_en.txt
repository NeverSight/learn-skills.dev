สร้างชุดเอกสารออกแบบระบบ (README.md, docs/, plans/) จากขอบเขตงาน TOR หรือ requirement ของระบบใดก็ได้ ก่อนเริ่มพัฒนา แล้วรีวิวว่าเอกสารถูกต้อง ใช้งานได้จริง ไม่ขัดกัน และลำดับการทำงานครบ ใช้สกิลนี้ทุกครั้งที่ผู้ใช้ต้องการวิเคราะห์หรือออกแบบระบบจากข้อกำหนด ไม่ว่าผู้ใช้จะพิมพ์ลำดับการทำงานมาเอง ชี้ไปที่โฟลเดอร์ที่มีไฟล์ TOR หรือส่งรูปภาพของผังงานหรือเอกสารมา และทุกครั้งที่ผู้ใช้พูดถึง TOR, ขอบเขตงาน, requirement, spec, SRS, เอกสารออกแบบระบบ, วิเคราะห์ระบบ, รายการฟีเจอร์, flow การทำงาน, data model, API spec, รายการหน้าจอ, แผนพัฒนา หรือขอให้ "ทำเอกสารก่อนเริ่มทำระบบ" แม้ผู้ใช้จะไม่ได้เรียกชื่อสกิลหรือไม่ได้ใช้คำว่าเอกสารออกแบบโดยตรง Use for system analysis and design documentation from a TOR, scope, or requirements for any kind of system. ไม่ใช้กับงานเขียนโค้ด รีวิวโค้ด หรือเอกสารของระบบที่พัฒนาเสร็จแล้ว เช่น คู่มือผู้ใช้
