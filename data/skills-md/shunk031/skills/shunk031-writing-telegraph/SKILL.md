# テレグラフ文体

## 大原則

- この skill は `shunk031-writing-kosshi` skill に依存するため、最初に同 skill を読み、主張と根拠の骨子を作るか、入力済みの骨子を確認する
  - 論点の階層、事実保持、引用、不足情報、句点の扱いは同 skill に委ねる
  - この skill は、骨子の各行を短くし、語句の関係を記号で示す
- 同じ階層の並列関係と、根拠を一段下に置く構造は崩さない

## 文体

- 各行は、一読で意味が取れる長さまで短くする
  - 文脈から分かる主語を省き、助詞や文末の `である`、`です` は、省いても語句の関係が明確な場合だけ省く
  - 短い見出しや分類ラベルには名詞句を使い、説明行には意味を明確にするために必要な述語を残す
  - 一行で扱う内容は一つに絞る
  - すべての行を体言止めにそろえず、名詞句、述語を残した短い表現、短い文を役割に応じて使い分ける
    - `〜を使用する` は `〜を使用`、`〜が増加した` は `〜が増加` のように、動作や状態が明確なら文末を縮めてよい
    - `使用モデル`、`性能向上` のような名詞だけでは関係が分からない場合は、助詞や述語を残す

### 例: 文脈から分かる語を省く

入力:

```markdown
- 週次レポートでは、CSV の収集だけを API 化し、集計ロジックはスプレッドシートに残す
  - 現在の手作業は一回あたり 5.5 時間かかる
  - API 化後は、担当者がチェックとコメント追記に集中できる
```

出力:

```markdown
- CSV 収集を API 化・集計はスプレッドシートを維持
  - 現在: 一回 5.5 時間の手作業
  - API 化後はチェックとコメント追記に集中
```

### 例: 説明に必要な動作と状態を残す

入力:

```markdown
視覚エンコーダには事前学習済みの ViT を使用する。学習時にはエンコーダのパラメータを固定する。変更後、NDCG は 3.8 ポイント増加した。
```

出力:

```markdown
- 視覚エンコーダ: 事前学習済み ViT を使用
- 学習時: エンコーダのパラメータを固定
- NDCG: 3.8 ポイント増加
```

## 記号

- 記号は、語句間の関係を短く示せる場合だけ使う
  - `→` は処理の順序や、値・状態の変化に使う
  - `➜` は直前の内容を受けて、前提から帰結、問題から次の焦点、比較から解釈へ進む箇所に置く
  - `⇔` は双方向の対応、`↓` は下段へ進む処理や変換に使う
  - `vs.` は対比、`:` はラベルと内容、`/` は並列・併記に使う
  - 記号だけで関係が曖昧になる場合は、短い日本語で書く

### 例: 手順と値の変化を `→` で示す

入力:

```markdown
検索処理では、入力を正規化してから候補を検索し、最後に再ランキングする。再ランキングによって NDCG は 0.374 から 0.412 に上がった。
```

出力:

```markdown
- 検索処理: 入力 → 正規化 → 候補検索 → 再ランキング
- NDCG: 0.374 → 0.412
```

### 例: 比較から結論へ進む

入力:

```markdown
新手法の NDCG は 0.412、ベースラインは 0.374 だった。一方で、新手法の推論時間は 18%増えた。精度向上と推論時間増加の釣り合いはまだ検証していない。
```

出力:

```markdown
- 新手法: 精度向上 / 推論時間増加
  - NDCG: ベースライン 0.374 vs. 新手法 0.412
  - 推論時間: +18%
  - ➜ 精度と推論時間の釣り合いは未検証
```
