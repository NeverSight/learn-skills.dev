Handeln Sie bei einem fehlerhaften Callidescope‑Lauf — einem projektspezifischen Gate, das einen Stack überschreitet, der das Limit dieses Projekts übertrifft, einem Breiten‑Gate, einem Gate, das keine eigenen Projektdateien gelesen hat, einem veralteten, festgeschriebenen Bericht, einer nicht lesbaren tsconfig, einem Lauf, der nichts nachverfolgte, oder einer abgelehnten Befehlszeile bzw. Konfiguration. Verwenden Sie dies, wenn Callidescope oder ein abgeleitetes Gate‑Ziel mit einem Nicht‑Null‑Exit endet, wenn ein Stack in einer Änderung tiefer geworden ist, wenn entschieden werden muss, ob ein fehlschlagendes Gate eine Code‑Korrektur oder eine Limit‑Korrektur erfordert, wenn das maximumDepth bzw. maximumBreadth eines Projekts ausgewählt oder verschoben wird, wenn ein ausgegebenes maximumDepth nicht mit der vom Gate bewerteten Zahl übereinstimmt, wenn ein festgeschriebener Bericht nicht mit einem frischen Lauf übereinstimmt, wenn eine deklarierte Einstiegspunkt‑Adresse zu nichts oder zu mehreren Auflösungen führt, wenn ein nachverfolgtes Projekt keine eigene callidescope.config.ts besitzt oder eine, bei der ein Feld fehlt, oder bevor man auf maximumDepth zurückgreift, um einen fehlgeschlagenen Check zu bestehen.
