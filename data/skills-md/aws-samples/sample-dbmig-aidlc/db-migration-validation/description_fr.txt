Phase de validation et de tests d'une migration de base de données AI-DLC. À utiliser après l'approbation de la construction ou lorsque l'utilisateur demande de valider, tester, réconcilier ou vérifier une migration de base de données — pour prouver que la cible convertie se comporte de la même manière que la source. Charge les données de test (chargement unique via dbmig pour dev/test, ou consomme les données déjà chargées via AWS DMS), rapproche le nombre de lignes et exécute les tests d'équivalence générés par LLM pour les fonctions/procédures/packages — même entrée → même valeur de retour (fonctions) et même effet net (procédures) — exécutés dans une transaction annulée. Vous (Kiro) générez les spécifications de test à partir de données réelles échantillonnées. Les échecs sont enregistrés pour un suivi (mode silencieux) ou une invite (mode interactif). Écrit des artefacts dans migrations/<project>/03-validation/.
