Перенести экземпляр Kestra 1.3 и его потоки в Kestra 2.0: предрейсовый аудит с отчётом о готовности и оценкой сложности, обновление сервера (миграции базы данных, Docker/Helm), миграция потоков через CLI с помощью kestra-migrate, а также пошаговые переписывания шаблонов, которые CLI не может автоматизировать (ForEach/ForEachItem → Loop, условия триггеров → when/dependsOn, pluginDefaults → Policies). Использовать, когда пользователи хотят обновить или мигрировать на Kestra 2.0, спросить, готов ли их экземпляр к 2.0, упомянуть kestra-migrate или его предупреждения, либо сообщить о потоках, не прошедших парсинг после обновления до 2.0. Для миграций ИЗ других оркестраторов (Airflow) использовать migrate-airflow-kestra.
