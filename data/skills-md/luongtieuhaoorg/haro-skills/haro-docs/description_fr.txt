Gérez la structure de la documentation du projet en utilisant le modèle Atomic Content Blocks. Utilisez‑le lorsque l’utilisateur veut initialiser une structure de documentation pour un nouveau projet, organiser la documentation existante, agrég­er des documents complets (BRD, PRD, SAD, FSD, …) à partir de blocs de contenu existants, examiner de façon critique un problème/fichier via des réviseurs subagents, ou gérer la mémoire de connaissances du projet via remember/knowledge. Exécutez /haro-docs sans arguments pour analyser le projet et choisir la prochaine action. Avant d’agir sur une commande, lisez intégralement son fichier commands/*.md — n’agissez jamais de mémoire.

Veuillez toujours répondre dans la langue de l’utilisateur.
