Evaluar si un diseño se ajusta a los principios modernos de la ingeniería de software: complejidad y carga cognitiva, economía del cambio, corrección de los límites y legibilidad para los agentes. Utilícelo cuando el usuario pregunte si un diseño, un límite de módulo, una API, un flujo de datos, un documento de diseño o una forma de cambio son sólidos, se mantienen o resisten el escrutinio: un juicio basado en principios, no una puerta de fusión. Cuasiincidente: utilice la revisión de código para realizar una revisión exhaustiva, teniendo en cuenta la cobertura, de un «diff», un plan o un ámbito de paridad.
