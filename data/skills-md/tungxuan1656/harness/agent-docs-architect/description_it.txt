Progetta o verifica il sistema di conoscenza del repository rivolto agli agenti per un progetto software. Utilizzalo quando un utente deve decidere quali documenti di prodotto, dominio, architettura, integrazione, dati, sicurezza, affidabilità, esecuzione, riferimento generato o navigazione un repository necessita; i loro percorsi, nomi, proprietà, modalità di lettura e contratti di manutenzione; o come tale sistema debba cambiare in base allo stadio del progetto, topologia, stack, integrazioni, rischi e coordinamento. Usalo prima di redigere un set di documentazione multi‑documento. Accoppialo con agent‑docs‑writer per creare documenti approvati. Non usarlo per scrivere un documento già selezionato o per prendere decisioni non approvate su prodotto o architettura.

Rispondi sempre nella lingua dell'utente.
