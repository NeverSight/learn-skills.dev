풀 리퀘스트의 HTML 리뷰 맵을 생성합니다—어떤 부분이 변경되었는지, 리뷰어가 각 판단을 내리기 위해 정확히 어떤 라인을 확인해야 하는지, 코드를 읽어야 할 순서, 그리고 변경 사항이 영향을 미치지 않은 코드에 어떤 영향을 미치는지—리뷰어가 판단하기 전에 변경 사항을 설명할 수 있도록 합니다. 대상은 Rails와 Elixir/Phoenix이며, Phoenix LiveView 앱이나 Rails 또는 Phoenix JSON API(Next.js와 같은 별도 클라이언트 유무와 상관 없음)를 지원합니다. 변경 사항을 평가하기보다 이해해야 할 때마다 사용하십시오: PR이나 브랜치가 무엇을 하는지, 큰 diff에서 어디서 시작해야 하는지, 실제로 중요한 파일은 무엇인지, 변경이 어떤 문제를 일으킬 수 있는지, 프론트엔드와 백엔드가 아직 일치하는지, 혹은 다른 사람 작업에 대한 리뷰어를 빠르게 파악시켜야 할 때—비록 그들이 "리뷰 맵"이나 "워크스루"라는 용어를 사용하지 않더라도. Claude Code에서는 `/accountable-review:review-map`으로, Codex에서는 `$review-map`으로 호출하며, 옵션으로 PR 번호, URL, 브랜치 또는 diff 범위를 전달할 수 있습니다. 페이지 형식은 하나이며, 이를 선택하는 플래그는 없습니다. 노력 수준은 별도로 지정합니다: `--effort high`가 기본값이며 페이지가 작성되기 전에 실행 자체의 분석을 반증하려 시도하고, `--effort low`는 그 과정을 건너뜁니다. `--mentor` 옵션은 변경 사항보다는 스택에 익숙하지 않은 리뷰어를 위한 것으로, 체크포인트 내부에 프레임워크 프리머를 추가하고 페이지의 다른 부분은 그대로 유지합니다. `--output <dir>`을 지정하면 실행이 비대화형이 되며, 페이지가 `<dir>/index.html`에 포터블 정적 HTML 형태로 저장됩니다(이는 CI가 페이지를 생성하는 방식입니다). 리뷰 코멘트나 승인 판단을 게시하기 위한 용도는 아닙니다.
