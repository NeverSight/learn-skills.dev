构建一个 Pull Request 的 HTML 审查映射——展示更改内容、审阅者需要做出的判断以及对应的精确代码行、阅读代码的顺序、以及更改波及的未被触及的代码——使审阅者能够在评判之前解释该更改。目标平台为 Rails 和 Elixir/Phoenix——包括 Phoenix LiveView 应用或 Rails、Phoenix 的 JSON API，是否配有如 Next.js 的独立客户端均可。在需要理解而非打分的场景下使用：询问 PR 或分支的作用、在大型差异中从何处入手、哪些文件真正重要、更改可能导致的破坏、前后端是否仍保持一致，或需要让审阅者快速了解他人的工作——即便他们从未提及“审查映射”或“walkthrough”。在 Claude Code 中使用 `/accountable-review:review-map`，或在 Codex 中使用 `$review‑map`，可选传入 PR 编号、URL、分支或 diff 范围。只有一种页面形态，且没有标志可以选择它。努力级别另行设置：`--effort high` 为默认，会在写入页面前尝试否定运行自身的分析；`--effort low` 则跳过此步骤。`--mentor` 用于对技术栈不熟悉的审阅者：在检查点中加入框架入门介绍，并获取一个积分，其余页面内容保持不变。使用 `--output <dir>` 可使运行非交互式：页面会写入 `<dir>/index.html` 作为可移植的静态 HTML，而不是发布，这正是 CI 生成页面的方式。此工具不用于发布审查评论或批准 verdict。
