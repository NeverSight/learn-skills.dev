プルリクエストの HTML レビューマップを作成します — 何が変更されたか、レビューアが各判断を下す際に必要な正確な行、コードを読む順序、そして変更が触れていないコードに及ぼす影響 — これによりレビューアは評価する前に変更を説明できます。対象は Rails と Elixir/Phoenix です — Phoenix LiveView アプリ、Rails または Phoenix の JSON API、Next.js のような別クライアントの有無にかかわらず対応します。変更を評価するのではなく理解したいときに使用してください：PR やブランチが何をするのか、大きな diff のどこから手を付けるべきか、実際に重要なファイルはどれか、変更が何を壊す可能性があるか、フロントエンドとバックエンドが依然として合致しているか、あるいは他者の作業をレビューアに素早く把握させる必要がある場合 — たとえ「レビューマップ」や「ウォークスルー」という言葉を使わなくてもです。Claude Code では /accountable-review:review-map、Codex では $review‑map で呼び出し、オプションで PR 番号、URL、ブランチ、または diff 範囲を渡します。ページの形は一つだけで、フラグで選択できるものはありません。実行レベルは別に設定できます：--effort high がデフォルトで、ページを書き出す前に実行の分析結果を検証しようとします。--effort low はその検証をスキップします。--mentor は変更自体ではなくスタックに不慣れなレビューア向けです：チェックポイント内にフレームワークの入門情報を加え、ページの他の部分は変更しません。--output <dir> を指定すると実行は非対話的になり、ページは <dir>/index.html にポータブルな静的 HTML として書き出され、公開されることはありません。これは CI が生成する方法です。レビューコメントや承認判断を投稿する用途では使用しません。
