建立一個 Pull Request 的 HTML 評審地圖——顯示哪些變更、審查者必須作出的判斷（並附上確定每項判斷的精確行號）、閱讀程式碼的順序，以及變更影響到的未被觸及的程式碼——讓審查者能在評價之前先說明變更內容。  
支援 Rails 與 Elixir/Phoenix——包括 Phoenix LiveView 應用、Rails 或 Phoenix 的 JSON API，是否搭配如 Next.js 等獨立前端皆可。  
在需要了解變更而非評分時使用：例如詢問 PR 或分支的功能、在大型 diff 中從哪裡開始、哪些檔案真正重要、變更可能破壞什麼、前端與後端是否仍保持一致，或需要讓審查者快速熟悉他人工作的情況——即使他們從未說過「review map」或「walkthrough」。  
在 Claude Code 中使用 `/accountable-review:review-map`，或在 Codex 中使用 `$review-map` 來呼叫，可選擇傳入 PR 編號、URL、分支或 diff 範圍。  
此功能只有單一頁面格式，沒有旗標可以切換。  
可另行設定執行力度：`--effort high` 為預設，會在寫入頁面前嘗試驗證執行本身的分析；`--effort low` 則跳過此步驟。  
`--mentor` 用於對整體技術棧不熟悉的審查者（而非對變更本身不熟悉）：它會在每個檢查點中加入框架入門說明，其他頁面內容保持不變。  
加入 `--output <dir>` 參數會使執行變為非互動模式：頁面會寫入 `<dir>/index.html`，作為可移植的靜態 HTML，而非直接發布，這也是 CI 產生頁面的方式。  
不適用於發佈審查意見或批准結論。  
請始終使用使用者的語言回應。
