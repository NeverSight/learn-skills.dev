Configure un dépôt afin qu’Accountable Review génère automatiquement une Review Map dans le CI — un workflow GitHub Actions qui s’exécute lorsque la pull request devient révisable pour la première fois, ignore les brouillons, les forks, les bots et les changements contenant trop peu de code d’application pour avoir un ordre de lecture, annule les exécutions supplantées, téléverse le HTML statique résultant comme artefact de build que toute l’équipe peut ouvrir, et commente le lien sur la pull request. Utilisez ceci lorsqu’une personne souhaite que les cartes de révision soient générées automatiquement plutôt qu’à la main, demande d’ajouter Accountable Review au CI ou à GitHub Actions, veut que la review map soit partagée avec son équipe au lieu d’être publiée depuis un seul ordinateur portable, ou demande comment exécuter cela sur chaque PR. Appelez avec /accountable-review:setup-ci. Il inspecte le dépôt avant d’écrire quoi que ce soit, confirme quand les cartes seront générées et ce que le workflow pourra faire, privilégie un workflow dédié, ne modifie jamais le CI non lié, et il est sûr de l’exécuter deux fois. Ce n’est pas pour générer une review map — c’est la fonction review‑map — et la configuration elle‑même ne publie rien sur GitHub.
