向 Homenet2MQTT（h2m）配置中添加设备实体（气候/灯光/传感器/风扇/开关等）以及所需的自动化/脚本的方法论。主要依据是已经应用的示例配置和厂商库预设（discovery.match、count 参数、$repeat）；只有那些无法通过这两者解释的设备才通过逆向工程原始 RS485 包来处理。图库片段中的自动化/脚本（周期轮询、总线代理响应、门铃/电梯序列、复合 TX 包生成）是实体行为的一部分，因此不能只是迁移实体后停下来。由于 HomeNet 总线往往只有在被操作时才产生流量，流程中包含一步明确要求用户操作墙面面板、开关或遥控器，用户提供的厂商/型号名称用作搜索优先级的提示，但示例并非仅凭名称固定。它用于以下请求，例如“清理未匹配的包”“添加一个匹配该包的实体”“仅根据该包创建实体”“使用图库预设增加加热器/灯光”“附加配置中不存在的设备”“该包未被捕获——我应该操作什么？”“添加周期轮询以更新状态”“添加自动门铃开门/电梯呼叫序列”“直接发送包以验证灯实际打开”等。对于不知道 h2m 地址或如何启用 Agent API 并获取令牌的用户，请从连接步骤开始引导（references/connection-setup.md）。h2m 通过 REST（`/api/v1/agent`）和 MCP（`/api/v1/agent/mcp`）公开相同的领域逻辑，因此如果客户端有 MCP 工具就使用 MCP；如果只能使用 shell，则使用脚本，并遵循 references/interfaces.md 中的表面特定差异。当拥有发送包的权限时，遵循以下顺序：仅预览以验证生成的指令确实能够驱动设备 → 用户批准并明确目标、十六进制、顺序、间隔 → 批准的单次/序列发送 → 确认真实设备操作。
