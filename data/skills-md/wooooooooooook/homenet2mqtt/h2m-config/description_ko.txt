Homenet2MQTT (h2m) 구성에 장치 엔티티(클라이밋/조명/센서/팬/스위치 등)와 필요 자동화/스크립트를 추가하는 방법론. 주요 참고는 이미 적용된 예시 구성과 벤더‑갤러리 프리셋(discovery.match, count 파라미터, $repeat)이며, 이 두 가지로 설명할 수 없는 장치는 원시 RS485 패킷을 역공학하는 방법으로 처리한다. 갤러리 스니펫에 포함된 자동화/스크립트(주기적 폴링, 버스 프록시‑응답, 초인종/엘리베이터 시퀀스, 복합 TX 패킷 생성)는 엔티티 동작의 일부분이므로 엔티티를 복사만 하고 끝내서는 안 된다. HomeNet 버스는 보통 작동될 때만 트래픽을 생성하기 때문에, 과정에 사용자가 월패드, 스위치, 리모컨을 작동하도록 명시적으로 요구하는 단계가 포함된다. 사용자가 제공한 벤더/모델 명은 검색 우선순위를 위한 힌트로만 사용되며, 이름만으로 예시를 고정시키지는 않는다. 이는 “매치되지 않은 패킷 정리”, “이 패킷에 맞는 엔티티 추가”, “패킷만으로 엔티티 생성”, “갤러리 프리셋으로 히터/조명 확장”, “구성에 없는 장치 연결”, “패킷이 캡처되지 않았을 때 무엇을 작동해야 할까?”, “상태 업데이트를 위한 주기적 폴링 추가”, “자동 초인종 열림/엘리베이터 호출 시퀀스 연결”, “패킷을 직접 전송해 조명이 실제로 켜지는지 확인” 등과 같은 요청에 사용된다. h2m 주소를 모르거나 Agent API를 활성화하고 토큰을 얻는 방법을 모르는 사용자는 연결 단계부터 안내한다(references/connection-setup.md). h2m은 REST(`/api/v1/agent`)와 MCP(`/api/v1/agent/mcp`)를 통해 동일한 도메인 로직을 제공하므로, 클라이언트에 MCP 도구가 있으면 MCP를 사용하고, 셸만 사용할 수 있으면 스크립트로 작업하며, surface‑specific 차이는 references/interfaces.md를 참조한다. 패킷 전송 권한이 있을 때는 다음 순서를 따른다: 생성된 명령이 실제로 장치를 움직이는지 미리 확인 → 대상, 헥스, 명령, 간격을 공개한 뒤 사용자 승인을 받음 → 승인된 단일/시퀀스 전송을 실행 → 실제 장치 동작을 확인.
