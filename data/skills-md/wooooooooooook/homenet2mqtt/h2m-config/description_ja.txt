デバイスエンティティ（気候／照明／センサー／ファン／スイッチなど）と、必要なオートメーション／スクリプトを Homenet2MQTT（h2m）設定に追加する方法論。主な参照はすでに適用された例設定とベンダーギャラリープリセット（discovery.match、count パラメータ、$repeat）であり、これら二つで説明できないデバイスのみを、RS485 生パケットのリバースエンジニアリングにフォールバックして扱う。ギャラリースニペットにあるオートメーション／スクリプト（定期ポーリング、バスプロキシ応答、ドアベル／エレベータシーケンス、複合 TX パケット生成）はエンティティの動作の一部であるため、エンティティを移すだけで完了しない。HomeNet バスは操作が行われたときにのみトラフィックを生成することが多いため、プロセスにはユーザーに壁パッド、スイッチ、リモコンなどを実際に操作させるステップが含まれ、ユーザーが提供するベンダー／モデル名は検索優先度のヒントとして使用されるが、例は名前だけに固定されていない。これらは「未一致パケットのクリーンアップ」「このパケットに一致するエンティティを追加」「パケットだけでエンティティを作成」「ギャラリープリセットでヒーター／ライトを拡張」「設定にないデバイスを添付」「パケットが取得できない—何を操作すべきか？」、「定期ポーリングを追加して状態更新」「自動ドアベル開閉／エレベータ呼び出しシーケンスを追加」「パケットを直接送信してライトが実際に点灯するか確認」などのリクエストに使用される。h2m のアドレスや Agent API の有効化、トークン取得方法が分からないユーザーには、接続手順（references/connection-setup.md）から案内する。h2m は同じドメインロジックを REST（/api/v1/agent）と MCP（/api/v1/agent/mcp）で公開しているので、クライアントに MCP ツールがあれば MCP を、シェルしかない場合はスクリプトを使用し、インターフェースの違いは references/interfaces.md に従う。パケット送信権限がある場合の検証フローは、プレビュー → 送信先・hex・順序・間隔を指定したユーザー承認 → 承認された単体／シーケンス送信 → 実機の動作確認、となる。
