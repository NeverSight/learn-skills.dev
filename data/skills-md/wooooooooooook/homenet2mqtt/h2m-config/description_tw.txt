Homenet2MQTT (h2m) 方法論，用於在設定中新增裝置實體（climate / light / sensor / fan / switch 等）以及必要的自動化/腳本。主要參考已套用的範例設定與廠商畫廊預設（discovery.match、count 參數、$repeat）；僅對那些無法以這兩者說明的裝置，才退回使用原始 RS485 封包逆向工程。畫廊片段的自動化/腳本（定期輪詢、總線代理回應、門鈴/電梯序列、複合 TX 封包產生）屬於實體的行為之一，不能只搬移實體就完成。由於 HomeNet 總線往往只有在被操作時才產生流量，請加入一步，特別要求使用者操作牆面面板、開關或遙控器，並使用使用者提供的廠牌/型號作為搜尋優先級的提示，但不要僅依名稱決定範例。此方法用於以下請求，例如「清理未匹配的封包」、「新增與此封包匹配的實體」、「僅從封包建立實體」、「使用畫廊預設增加暖氣/燈光」、「附加配置中未出現的裝置」、「封包未捕獲，我該操作什麼？」、「新增定期輪詢以更新狀態」、「附加自動門鈴開啟/電梯呼叫序列」、「直接發送封包以驗證燈真的會開」等。對於不知道 h2m 位址或如何啟用 Agent API 以及取得 token 的使用者，請從連線步驟 (references/connection-setup.md) 引導他們。h2m 透過 REST (`/api/v1/agent`) 與 MCP (`/api/v1/agent/mcp`) 暴露相同的領域邏輯，若客戶端有 MCP 工具則使用 MCP；若僅有 shell，則以腳本操作，介面差異請參考 references/interfaces.md。若您有發送封包的權限，僅在確認產生的指令確實能驅動實體裝置時才執行以下流程：預覽 → 向使用者揭露目標、十六進位、指令、間隔後取得同意 → 同意的一次性/序列傳送 → 驗證實體裝置運作。
