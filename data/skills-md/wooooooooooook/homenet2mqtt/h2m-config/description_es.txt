Metodología para añadir entidades de dispositivos (climate/light/sensor/fan/switch, etc.) y las automatizaciones/scripts necesarios a una configuración de Homenet2MQTT (h2m). La base principal es la configuración de ejemplo ya aplicada y los presets de la galería del fabricante (discovery.match, parámetro count, $repeat); solo los dispositivos que no pueden explicarse con esos dos se manejan recurriendo a la ingeniería inversa de paquetes RS485 crudos. Las automatizaciones/scripts en los fragmentos de la galería (sondeo periódico, respuestas sustitutas del bus, secuencias de timbre/elevador, generación de paquetes TX compuestos) forman parte del comportamiento de la entidad, por lo que no basta con mover la entidad y detenerse. Como el bus HomeNet suele generar tráfico sólo cuando se está operando, el proceso incluye un paso que pide explícitamente al usuario manipular un panel de pared, interruptor o control remoto, y el nombre del proveedor/modelo suministrado por el usuario se usa como pista para la prioridad de búsqueda, pero el ejemplo no está fijado únicamente por el nombre. Se utiliza para solicitudes como “limpiar paquetes no coincidentes”, “añadir una entidad que coincida con este paquete”, “crear una entidad solo a partir del paquete”, “incrementar calefactores/luces usando el preset de la galería”, “adjuntar un dispositivo que no está en la configuración”, “el paquete no se está capturando—¿qué debo operar?”, “añadir sondeo periódico para que el estado se actualice”, “añadir una secuencia automática de apertura de timbre/llamada de ascensor”, “enviar el paquete directamente para verificar que la luz realmente se enciende”, etc. Para los usuarios que no conocen la dirección de h2m o cómo habilitar la Agent API y obtener un token, guíalos desde el paso de conexión (references/connection-setup.md). h2m expone la misma lógica de dominio vía REST (`/api/v1/agent`) y MCP (`/api/v1/agent/mcp`), por lo que si el cliente dispone de una herramienta MCP utilizas MCP; si sólo está disponible una shell trabajas con scripts, y las diferencias específicas de la capa se describen en references/interfaces.md. Cuando tengas permiso para enviar paquetes, sigue la secuencia: vista previa solo para verificar que el comando generado realmente mueve el dispositivo → aprobación del usuario que aclare objetivo, hex, orden, intervalo → transmisión aprobada única o en secuencia → confirmar la operación del dispositivo real.
