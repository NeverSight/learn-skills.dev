Методика добавления сущностей устройств (климат/освещение/датчик/вентилятор/выключатель и т.д.) и необходимых автоматизаций/скриптов в конфигурацию Homenet2MQTT (h2m). Основой служит уже применённая примерная конфигурация и пресеты из галереи поставщиков (discovery.match, параметр count, $repeat); только устройства, которые нельзя объяснить этими двумя средствами, обрабатываются путём обратного анализа сырых пакетов RS485. Автоматизации/скрипты из фрагментов галереи (периодический опрос, ответы‑подделки шины, последовательности звонка в дверь/вызова лифта, генерация составных пакетов TX) являются частью поведения сущности, поэтому её просто переместить и остановить нельзя. Поскольку шина HomeNet часто генерирует трафик только во время эксплуатации, процесс включает шаг, в котором явно просят пользователя активировать настенный блок, переключатель или пульт дистанционного управления, а имя поставщика/модели, предоставленное пользователем, используется как подсказка для приоритетов поиска, однако пример не фиксируется исключительно по имени. Оно применимо для запросов типа «очистить не соответствующие пакеты», «добавить сущность, соответствующую этому пакету», «создать сущность только из пакета», «увеличить количество обогревателей/осветителей с помощью пресета из галереи», «подключить устройство, отсутствующее в конфигурации», «пакет не захватывается — что мне управлять?», «добавить периодический опрос для обновления состояния», «добавить автоматическую последовательность открытия дверного звонка/вызова лифта», «отправить пакет напрямую, чтобы проверить, действительно ли свет включается» и т.п. Для пользователей, не знающих h2m‑адрес или того, как включить Agent API и получить токен, следует вести их от шага подключения (references/connection-setup.md). h2m предоставляt одинаковую бизнес‑логику через REST (`/api/v1/agent`) и MCP (`/api/v1/agent/mcp`), поэтому если у клиента есть MCP‑инструмент, используйте MCP; если доступен только командный интерпретатор, работаете со скриптами, а различия, зависящие от среды, описаны в references/interfaces.md. Когда получено разрешение отправлять пакеты, следуйте последовательности: предварительный просмотр для проверки, что сгенерированная команда действительно перемещает устройство → одобрение пользователя, уточняющее цель, hex‑значение, порядок, интервал → одобренная передача одиночного/последовательного пакета → подтверждение работы реального устройства.
