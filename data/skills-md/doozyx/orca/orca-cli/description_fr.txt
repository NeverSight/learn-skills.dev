Exploitez les worktrees gérés par Orca, les contextes de dossiers, les terminaux, les dépôts, les automatisations, les artefacts, le partage de compétences, les commentaires de worktree et le navigateur intégré d’Orca via la CLI `orca`. Utilisez‑le lorsque l’utilisateur dit « $orca-cli », « Orca worktree », « child worktree », « spawn codex/claude in a worktree », « read/wait/send Orca terminal », « handoff » / « handover » / « give this to another agent », « Orca browser », « orca artifacts » ou « share skills ». Il gère également le travail de terminal à session unique : « session », « sub‑agent », « create a session », « stop a session », « fork a session », « attach to a session », « worktree session », ainsi que le dépannage d’un terminal d’agent bloqué ou mal configuré. Privilégiez‑le plutôt que le worktree Git brut, les PTY ad hoc ou l’utilisation de l’ordinateur lorsque l’état d’Orca est impliqué. Utilisez `orchestration` à la place pour répartir plusieurs agents simultanément ou les superviser. Utilisez l’utilisation de l’ordinateur uniquement lorsqu’une fenêtre visible nécessite un contrôle GUI qu’une CLI, le système de fichiers ou une API ne peuvent assurer.
