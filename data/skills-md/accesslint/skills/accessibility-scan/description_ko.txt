한 페이지, 자동화 계층 — 라이브 페이지에 웹 접근성(a11y) 규칙 엔진을 실행하여 기계적으로 감지할 수 있는 모든 위반을 찾습니다. URL을 전달하거나, 설정 대상 이름(e.g. `accesslint:accessibility-scan dev`)을 전달하거나, 아무 것도 전달하지 않으면 `accesslint.config.json`의 기본 대상을 사용합니다. 디버깅 가능한 Chrome을 보장하고, CDP를 통해 @accesslint/core 엔진을 실행하여 실시간 DOM WCAG 2.2 위반 목록을 반환하며, 각 위반은 해당 DOM 선택자와 소스 `file:line`에 근거합니다. 찾을 뿐, 수정하지는 않습니다. ‘이 페이지가 접근 가능한가’, ‘이 URL에서 a11y 확인’, ‘대비와 대체 텍스트 문제 찾기’, 또는 UI 변경을 검증할 때 사용합니다. 키보드와 스크린 리더 직접 검사는 `accessibility‑inspect`를, 전체 사이트나 제품 검사는 `accessibility‑audit`를, 커밋되지 않은 변경 또는 브랜치와의 차이를 비교하려면 `accessibility‑diff`를 사용하십시오.
