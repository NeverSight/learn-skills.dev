1ページ、Automated Tier — ライブページに対してウェブアクセシビリティ（a11y）ルールエンジンを実行し、機械的に検出できるすべての違反を特定します。URL、設定ターゲット名（例: `accesslint:accessibility-scan dev`）を渡すか、何も渡さなければ `accesslint.config.json` のデフォルトターゲットが使用されます。デバッグ可能な Chrome を保証し、CDP 上で @accesslint/core エンジンを実行し、ライブ DOM の WCAG 2.2 違反項目の作業リストを返します。各違反は DOM セレクタとソース `file:line` に紐付けられています。検出のみで編集は行いません。‘このページはアクセシブルか’、‘この URL の a11y をチェック’、‘コントラストや alt テキストの問題を探す’、あるいは UI 変更の検証に使用してください。キーボードやスクリーンリーダーによるハンズオンチェックには `accessibility-inspect` を、サイト全体や製品全体のチェックには `accessibility-audit` を、未コミットの変更やブランチとの差分を取るには `accessibility-diff` を使用します。
