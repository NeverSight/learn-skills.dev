Una página, nivel automatizado — ejecuta el motor de reglas de accesibilidad web (a11y) contra una página en vivo y localiza cada violación que pueda detectar mecánicamente. Pasa una URL, un nombre de objetivo de configuración (p. ej. `accesslint:accessibility-scan dev`), o nada para usar el objetivo predeterminado de `accesslint.config.json`. Garantiza un Chrome depurable, ejecuta el motor `@accesslint/core` sobre CDP y devuelve una lista de trabajo de violaciones WCAG 2.2 en el DOM en vivo, cada una vinculada a su selector DOM y origen `file:line`. Localiza; no edita. Úsalo para “¿es esta página accesible?”, “comprobar a11y en esta URL”, “encontrar problemas de contraste y texto alternativo”, o para verificar un cambio de UI. Para revisiones manuales con teclado y lector de pantalla usa `accessibility-inspect`; para un sitio o producto completo usa `accessibility-audit`; para comparar con cambios no confirmados o una rama usa `accessibility-diff`.
