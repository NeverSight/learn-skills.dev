# manga-forge — 自然言語から漫画原稿を焼くスキル

ユーザーの一言から、**完成した漫画ページのPNG**を出すところまでを担当する。

```
ユーザーの指示
  ↓ ① ストーリーを書く（このスキルの仕事）
  ↓ ② OMNY にコマ割りを設計する（このスキルの仕事・最重要）
  ↓ ③ scripts/forge.sh で焼く（作画は codex に委譲）
  ↓ ④ 回収（collect.sh）
  ↓ ⑤ 全ページを目で見て検品する（このスキルの仕事）
  ↓ ⑥ 納品（deliver.sh・ユーザー希望の場所へ）
page1.png ... pageN.png
```

## 🚨 作業前に必ず読むもの

1. **[`docs/pitfalls.md`](docs/pitfalls.md)** — ハマりどころ全集。**ここを読まずに始めると同じ穴に落ちる**
2. **[`prompts/ndm-v10.md`](prompts/ndm-v10.md)** — OMNY の書き方の全仕様（スキーマ・コマ割りパターン集・フキダシ9種）。**OMNYを書く前に必ず読む**
3. **[`omay/standard.omay.yaml`](omay/standard.omay.yaml)** — 作画側に渡す規則。中身を知っておくとネームの精度が上がる

## ① ストーリー

- ページ数のデフォルトは **2〜5ページ**。指定があればそれに従う。10ページ程度までは一度に焼ける
- 1ページ = **3〜6コマ**が目安
- 「◯ページ目」の区切りを立てて、**起承転結＋見せ場**（キメ台詞・感情の着地）を設計する
- ユーザーの指定が薄いときは、直近の文脈・会話から題材を拾ってよい

## ② OMNY の設計（このスキルの本体）

`prompts/ndm-v10.md` のスキーマに従って YAML を書く。要点：

- コマ割りは **A4（210×297mm）基準の絶対座標**。id は右上→左下の読み順
- 🚨 **ページ間でコマ割りのパターンを変える**。全ページ同じ骨格（大トップ→右→左→大ボトム等）は禁止。隣り合うページで同じパターンにしない
- セリフは必ず `bubbles` 配列。**1フキダシ20〜40文字**、長い台詞は分割する
- フキダシの形を `shape` で指定する（normal / thought / square / caption / flash / uniflash / wobbly / whisper / handwritten）
- 全コマに背景詳細度 `bg` を付ける（-1/0/1/2）。**1ページ内に 0/1/2 が混ざっているのが良い状態**。全コマ 2 は禁止、bg:2 は1ページ2コマまで
- 🧍 **人物センター原則**：会話コマは人物をコマ中央に大きく置き、フキダシを人物の右→左に振り分ける。フキダシが顔に重なるときは**フキダシ側を退避**させる（人物を隅に逃がさない）
- 心の声は `monologue: true` のフラグだけで表す。**テキストに括弧「（）」を書かない**（括弧ごと絵に描かれる）
- キメ台詞・感動の着地は「顔のアップ」の大コマにして、`action` に明記する
- `materials` に必要な素材（人物・背景・小物）を列挙し、各コマの `assets` に対応付ける。素材が無くても `note` を指針に作画AIが自由デザインするので止まらない

⚠️ **bbox は「意図の伝達」であって「レイアウトの確定」ではない**（`docs/pitfalls.md` 罠6）。作画AIは構図の自然さを優先してコマ位置を調整する。それは正しい挙動なので、**ズレていても壊れてはいない**。ただしコマ座標を後工程で使う場合は完成原稿から実測すること。

OMNY は作品ごとにファイルとして保存する（`<日付>_<タイトル>.omny.yaml` など）。資産として残ると、画風の刷り直しや後工程に効く。

## ③ 焼く

```bash
./scripts/forge.sh -n <OMNYファイル> [-r <立ち絵1>] [-r <立ち絵2>] [-m "作品固有の追加指示"]
```

- `-r` のリファレンス画像は**最大3枚**が目安。増やしすぎると効きが薄れる
- `-m` には**画風の指定**や「このキャラの特徴は絶対に省略しない」といった作品固有の念押しを書く
- **timeout はページ数 × 120秒 + 余裕**を見る。10ページなら20分強
- page2 以降は page1 の **`session id` を名指しして** `codex exec resume <ID>` で続きを頼む（`forge.sh` が自動でやる）。`resume --last` は他の codex 呼び出しと混ざるので使わない（罠3）。だから焼いている最中に別の画像生成を並走させても大丈夫
- 画風を変えたいときは `omay/styles.md` の呪文を OMNY の `meta.style_notes` 先頭行に入れる

## ④ 回収

`forge.sh` が終わると `collect.sh` が自動で走り、`out/<作品名>/page1.png ...` に並ぶ。

⚠️ 作画AIは**頼まなくても同じページを描き直す**ことがある（罠5）。
`forge.sh` がページごとに描かれた画像を `takes.tsv` に記録しているので、`collect.sh` は各ページの**最後の1枚**を `pageN.png` に採用し、先の分を `rejected/` に分ける。
「画像が無いページがある」と出たら、そのページは宣言だけで終わっている（罠1）。検品では各PNG右上のページ番号（例「3/10」）も確かめる。

## ⑤ 検品（省略してはいけない）

**全ページを実際に開いて見る**。チェック項目：

- ページ欠けがない（ヘッダーの「N/M」）
- セリフが読める／キャラの取り違えがない
- 衣装・髪型がページ間で一貫している
- **季節・時間帯と服装・背景が矛盾していない**（罠9）
- フキダシの尻尾が話者を指している（caption・handwritten・`offscreen: true` は尻尾なし）
- 意図した無音コマが絵だけで成立している

軽微な文字のゆらぎは生成の性質として許容する。気になるページだけ**同じ OMNY で該当ページを再依頼**する（このとき演出指示を追加しない。素の再依頼のほうが直りやすい）。

## ⑥ 納品（検品が終わってから）

検品に合格した原稿をユーザーへ渡す。

- **ユーザーが置き場所を指定している場合**（「デスクトップに置いて」「~/manga に保存して」等）：

```bash
./scripts/deliver.sh -f out/<作品名> -t <指定先>/<作品名> -n <OMNYファイル>
```

  - `-n` でネーム（OMNY）も一緒に納品して資産として残す
  - 納品先に前回の納品物があるとスクリプトが止まる。**上書きしてよいかユーザーに確認してから** `--force` を付ける
- **指定が無い場合**はコピーせず、`out/<作品名>/` をそのまま納品場所として扱う
- どちらの場合も最後に必ず報告する：
  - 完成ページの一覧（フルパス）
  - 検品サマリ（チェックリストの結果・再生成したページがあればその旨）
- 🚨 検品（⑤）を通す前に納品しない。`rejected/` の画像（自主リテイク前の版。罠5）を混ぜない

## 補足

### 画風を変える
`omay/styles.md` に12種の呪文がある（水彩絵本・クレヨン・ソフトパステル・色鉛筆・切り絵・水墨画・フェルト・ステンドグラス・木版画・油彩・ちぎり絵・リソグラフ）。
大きく変えたいときは **「画材＋支持体（紙）」を指定する**のがコツ。「アニメ塗り禁止」「中途半端にきれいにしない」と念押しすると振り切ってくれる。

### 素材を資産化する
一度デザインが決まったキャラ・背景・小物は、**画像として保存して次回のリファレンスに使う**と世界の一貫性が保たれる。詳しくは `docs/characters.md`。

### 失敗したら
ログ（`out/<作品名>/forge.log`）に `generated_images/<UUID>/...png` の行があるか見る。
無ければ**宣言だけで終わった**ケース（罠1）。同じコマンドで再実行してよい。
`session id` の行すら無いときは codex が起動できていない（罠11・ログイン切れ等）。**終了コード 0 を成功と判断しない**。
