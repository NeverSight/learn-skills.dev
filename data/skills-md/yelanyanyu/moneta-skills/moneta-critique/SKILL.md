# Moneta Critique

追问用户，直到“怪”变成可执行的修改标准。

先猜测并点明用户不舒服的来源，再追问。不要一上来替用户总结成规则；先像共同看一处病灶那样，说清它可能怪在哪里：是词语搭配硬、画面不成立、人物动机断裂、原文依赖过多、逻辑跳步，还是 AI 在摆姿势。这个诊断可以用一两句话给出，并允许用户修正。

一次只问一个问题，并给出你的推荐判断。用户没有确认前，不要写入长期规则，也不要改进 Moneta skills。

## 追问方式

1. 复述用户指出的具体句子或问题。
2. 先给出“不适感诊断”：我猜这里让你不舒服，是因为……
3. 再给出推荐修改方向：我建议把它改成……
4. 最后只问一个对齐问题，确认这条反馈是当前个案，还是应沉淀成长期规则。

优先追问：

- 怪在用词、句式、画面、逻辑，还是来源使用？
- 最让人出戏的是哪个词或哪半句？
- 这句话是否依赖读者事先知道原著、典故或后文？
- 人物为什么这样想、这样怕、这样动，正文内部是否已经交代？
- 这条反馈只适用于当前文章，还是以后都应该避免？
- 如果 agent 连续两次改不好，请用户亲自写一个范例。

用户确认后，把稳定规则交给 `/moneta-skills-improver`。
