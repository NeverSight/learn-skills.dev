# Things ワークフロー

macOS の Things 3 と AppleScript で連携する。スクリプトはこの Skill の `scripts/` にある。

## 起動条件と実行ゲート（最優先）

この Skill が読み込まれたこと、ファイルやスクリプトを参照したことは、Things の操作依頼でも実行許可でもない。ユーザーが Things に対する具体的な操作（検索・作成・完了・移動）を明示的に依頼した場合にだけ、このワークフローを開始する。

- 依頼が説明・相談・Skill の確認だけなら、AppleScript や `osascript` を書かず、実行せず、通常の文章で回答する。
- 具体的な操作がまだ不明なら、先に何をしたいかを質問する。推測で検索や作成を始めない。
- `osascript` のコマンドを提示・生成するだけでなく、実行もユーザーの明示的な操作依頼がある場合に限る。
- 実行前に、対象・変更内容・引数を確定する。完了・移動・作成などデータを変更する操作は、内容を表示してユーザーの確認を得るまで実行しない。

## 基本方針

- Things の既存データを変更する操作（完了・移動）は、実行前に対象と変更内容を表示し、ユーザーの確認を取る。
- タスク名だけで対象を特定できない場合は、候補を表示して追加情報を求める。同名タスクを推測で操作しない。
- 作成先・移動先が指定されていない作成タスクは Inbox に入れる。
- 日付、プロジェクト、エリア、タグを勝手に作らない。存在しない名前を指定された場合は、作成前に確認する。
- AppleScript のエラー、権限エラー、Things が未インストールの場合は、成功したと報告せずエラー内容を伝える。

## 検索

ユーザーの語をそのまま1回検索するだけでなく、文脈に応じて表記揺れ・自然な言い換え・略称も検索する。ただし、意味が広がりすぎる語は勝手に追加せず、必要なら検索範囲を確認する。

```bash
osascript "$(dirname "$SKILL_PATH")/scripts/search.applescript" "検索語" "言い換え" "略称"
```

`$SKILL_PATH` が使えない環境では、Skill の実際のディレクトリを指定する。出力は `ID<TAB>タイトル<TAB>プロジェクトまたはエリア`。重複を除き、タイトル・ID・所属を確認して候補を示す。

検索結果にプロジェクト所属のタスクが含まれる場合は、そのプロジェクトのタスク一覧も取得し、完了・未完了などの状態が分かる範囲で要約して提示する。プロジェクト名が確定したら次を使う。

```bash
osascript "$(dirname "$SKILL_PATH")/scripts/project-summary.applescript" "プロジェクト名"
```

これは読み取り操作なので確認なしで実行できるが、検索結果を根拠に完了・移動・編集を始めてはいけない。変更は別途依頼と確認が必要。

## 作成

自然言語から次の情報を抽出する。

- title（必須）
- notes（任意）
- when / deadline（任意）
- tags（任意）
- list（プロジェクトまたはエリア、任意）

実行例：

```bash
osascript "$(dirname "$SKILL_PATH")/scripts/create.applescript" \
  --title "タスク名" \
  --notes "補足" \
  --list "プロジェクト名"
```

作成前に、抽出した内容と登録先を表示して確認する。作成結果として Things の ID を記録する。

## 完了

まず検索して対象の ID を確定する。その後、確認してから実行する。

```bash
osascript "$(dirname "$SKILL_PATH")/scripts/complete.applescript" "ThingsのID"
```

## 移動

まず対象と移動先の存在を確認する。移動先はプロジェクトまたはエリアに限る。

```bash
osascript "$(dirname "$SKILL_PATH")/scripts/move.applescript" \
  "ThingsのタスクID" \
  "移動先の名前"
```

確認後に実行し、実行後に対象の所属を再検索して結果を確認する。

## 失敗時

- `Not authorized` などが出た場合は、macOS の「システム設定 → プライバシーとセキュリティ → オートメーション」で pi が Things を操作できるようにする。
- Things の AppleScript API で対応できない操作は、URL Scheme や Shortcuts に切り替えず、まず制約として説明する。

## 入出力と停止条件

入力は明示された操作、対象、作成内容、移動先である。出力は検索・要約結果、または確認後に実行した変更と事後確認結果とする。対象が一意でない、変更内容が確定していない、確認を拒否された、AppleScriptが非ゼロ終了した場合は停止し、推測で再実行しない。読み取り操作と変更操作を報告上も分離する。
