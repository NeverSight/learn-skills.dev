## 网文拆书与仿写分析 (deconstruct)

### 触发关键词
帮我拆书、拆书稿、分析这本书为什么火、拆解这本书的结构、学习这本书的写法、仿写这本书、拆黄金三章、分析爽点节奏、对标书分析、拆解爆款、这本书的钩子怎么设计、拆解人物关系、分析伏笔回收、拆解节奏、拆书报告

### 不适用场景（明确排除）
- ❌ 直接续写/改写原作、生成同人 → 转 `sumeru-write`（且必须使用原创设定）
- ❌ 把原作换名字、换地名后当自己的作品 → 拒绝，并说明侵权风险
- ❌ 要求"照着这本书写一本一样的" → 只能提供结构模板与差异化方案
- ❌ 分析盗版资源、提供原文下载 → 不参与

### 核心原则

**拆结构，不拆句子；学方法，不搬名字。**

拆书输出的是「结构模板 + 可验证参数 + 差异化方案」，不是「换皮文本」。任何进入报告的原文连续片段不超过 12 字，原作角色名/地名/专有名词不得出现在报告正文。

### 工作流程

```
输入（单文件/章节目录/片段）
    ↓
[1] 机械统计（脚本，必跑）
    → analyze-book.py → .sumeru/deconstruct/structure.json + 拆书数据报告.md
    ↓
[2] 结构拆解（模型，基于数据）
    → 十二维分析：开篇 / 人物功能位 / 节奏爽点 / 结构伏笔 / 语言视角
    → 每条结论必须有数据或章节位置支撑
    ↓
[3] 抽象化改写
    → 角色替换为 [主角] [对手] [导师]，地名替换为 [初始势力] [高层地图]
    → 情节替换为「动作 + 结果 + 代价」的功能描述
    ↓
[4] 输出拆书报告
    → 拆书报告_《[作品代称]》.md
    ↓
[5] 原创性检查（脚本，必跑）
    → check-derivative.py
    → 未通过必须改写后重跑
    ↓
[6] 生成仿写方案（可选）
    → 保留结构比例，替换世界观/人物关系/冲突类型
```

### 命令

```bash
# 1. 结构统计
python3 skills/sumeru-deconstruct/scripts/analyze-book.py --file 参考书.txt
python3 skills/sumeru-deconstruct/scripts/analyze-book.py --chapters reference/chapters

# 2. 原创性检查（报告写完后必跑）
python3 skills/sumeru-deconstruct/scripts/check-derivative.py \
  --source 参考书.txt \
  --output 拆书报告_某书.md \
  --forbid "原作主角名,原作地名"
```

### 输出内容

**用户可见输出（当前工作目录）**
- `拆书数据报告.md`：机械统计（章节字数、对话占比、钩子分布、视角、重复短语）
- `拆书报告_《作品代称》.md`：完整结构拆解 + 抽象化模板 + 仿写方案

**中间数据（`.sumeru/deconstruct/`）**
- `structure.json`：逐章统计数据
- `derivative-check.json`：原创性检查结果（`passed` 必须为 `true`）
- `derivative-check.md`：可读检查报告

### 拆书报告结构

1. **一句话结论**：靠什么留住读者（≤80 字）
2. **结构骨架**：阶段 / 章节范围 / 核心目标 / 主要冲突 / 阶段末变化
3. **黄金三章拆解**：初始状态 → 打破 → 变量 → 小试 → 钩子
4. **爽点与节奏曲线**：用钩子分布、字数分布、爽点间隔支撑
5. **人物功能位**：导师/伙伴/对手/红颜/工具人，出现与转化节点
6. **伏笔台账**：埋设章 / 回收章 / 跨度 / 回收方式
7. **可复用结构模板**：全部使用占位符，不出现原作专名
8. **仿写方案（差异化）**：保留什么、替换什么、禁止什么
9. **风险与不建议模仿的点**

详细维度与模板见 `references/deconstruct-framework.md`。

### 数据解读口径

| 指标 | 偏低 | 健康区间 | 偏高 |
|------|------|----------|------|
| 单章字数（起点） | <2500 | 3000-5000 | >6000 |
| 单章字数（番茄） | <1500 | 2000-3000 | >4000 |
| 对话占比 | <10% | 15%-35% | >45% |
| 平均段长 | <30 字 | 50-150 字 | >300 字 |
| 章末悬念占比 | <30% | 50%-80% | 100%（疲劳） |

数据用于发现问题，不用于给作品打分；类型不同，健康区间不同。

### 与下游 Skill 的衔接

- → `sumeru-outline`：只传「结构模板 + 节奏参数 + 功能位配置」，不传原作专名与具体情节
- → `sumeru-topic`：可作为同类型市场验证参考，不能作为选题创意的唯一来源
- → `sumeru-write`：只传「钩子类型配比、对话占比、段句长参数」
- → `sumeru-review`：拆书结论可作为节奏审查的参照基线

**禁止**：把拆书报告直接当大纲用；把原作角色关系图换名后直接用；把原作章节标题改一个字后复用。

### 产物与验收标准（Definition of Done）

| 验收项 | 标准 | 校验方式 |
|--------|------|----------|
| 数据完整 | 章节数、总字数、逐章字数、钩子分布齐全 | `structure.json` 字段完整 |
| 结论有据 | 每条结构结论都有章节位置或数据支撑 | 抽查报告 |
| 抽象化彻底 | 报告正文不含原作角色名/地名/专有名词 | `check-derivative.py --forbid` 无命中 |
| 无原文复制 | 最长连续重合 ≤12 字 | `check-derivative.py` 通过 |
| 模板可执行 | 仿写模板能指导写出不同的故事 | 人工检查占位符 |
| 差异化明确 | 至少给出 3 处必须替换的设定 | 检查报告「仿写方案」 |
| 风险提示 | 明确指出不建议模仿的点 | 检查报告「风险」 |
