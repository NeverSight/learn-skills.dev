Revisione del progetto per i backend Motoko esistenti: giudicare se il codice è ben progettato, non come scriverlo. Copre le invarianti codificate in tipi (varianti su testo, campi correlati, case_sodors), disciplina dello stato stabile e transitorio in caso di migrazione avanzata, struttura dei file (types.mo/lib/mixins/main.mo) e risultati classificati in base alla gravità (Blocker/Warning/Note). Da utilizzare durante la revisione, il controllo, la critica o il refactoring di file .mo esistenti o quando viene richiesto un feedback sulla revisione del codice su un contenitore Motoko. NON utilizzare per scrivere nuovo codice Motoko o correggere errori del compilatore (writing-motoko), creare file di migrazione (migrating-motoko-actors) o distribuire.
