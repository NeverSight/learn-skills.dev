Règles pour le code du canister sur un moteur cloud (sous-réseau CloudEngine, par exemple OpenCloud). Les cartouches du moteur contiennent 0 cycle : n'attachez jamais les cycles que vous avez calculés : supprimez les clauses `(with cycles = …)` (échec : IC0504). Les appels entre sous-réseaux doivent être avec attente limitée et sans cycle (« (with timeout = N) », « Call::bounded_wait ») ou rejetés : « Les appels avec attente illimitée et les appels avec cycles ne sont pas autorisés vers les sous-réseaux CloudEngine ». Les appels HTTPS utilisent le wrapper ordinaire et sont gratuits ; jamais via le proxy : aucune transformation ne s'applique (« Les répliques ont eu des réponses différentes ») et son budget s'écoule dans InsufficientCycles : déplacez l'appel, ne rechargez pas. Les appels inter-sous-réseaux porteurs de cycle passent par la cartouche proxy du moteur : XRC et le seuil ECDSA/Schnorr et vetKD (Bitcoin, Ethereum, VetKeys) ; encoder manuellement les arguments ; les assistants ic-vetkeys et ic-cdk attachent des cycles. Les clés dérivées appartiennent au proxy. À utiliser lors de l'écriture ou du débogage du code de la cartouche du moteur, de la signature ou de la dérivation de clés, ou sur ces erreurs. Ne PAS utiliser pour déployer un proxy (déploiement sur moteur cloud).
