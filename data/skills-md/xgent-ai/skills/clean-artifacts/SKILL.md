# clean-artifacts · 清理过程文件

清理评审、采集和测试留下的过程文件，解决反复进入 Git 的问题，并区分工作树、当前版本和历史对象的占用。没有仓库参数时使用当前项目；多个仓库只处理用户指定的集合，逐仓核对。

## 范围与约束

- **按用途判定，不按名字或大小猜删。** 目录叫 `logs`、文件被忽略、文件很旧或图片很大，都不能单独证明可清理。先找生成工具、报告或采集清单，区分可清理、必须保留和用途不明。
- **保留独有内容与续接能力。** 源码、业务数据、设计稿、目标图、测试基线和 fixtures 保留。UI 评审的目标包、报告、修复记录、`capture.md`、各位评审原文、`judge.md`、`round.json`、packet 和循环索引默认保留；不能整目录删除 `.ui-captures/`，不改分数、证据 hash、目标或轮次来掩盖缺证。活动进程正在写入的日志、复审仍依赖的截图保留原位置，取消 Git 跟踪可以保留其本地副本。需要跨机共享或审计的证据遵从仓库约定。
- **已有授权覆盖的确认集合直接处理。** 用途不明、会损失独有内容或影响现有证据要求的项保留，完成其他项后再请用户决定。命令因脏文件、占用或冲突拒绝时重新核对，不自动加 `--force`，不批量 `git clean -fdx`。
- **当前版本清理不等于历史瘦身。** 默认执行当前版本清理，保留本地文件；“仅盘点”不改工作树、索引、引用或配置。“回收磁盘”才处理本地文件，先确认可丢弃或已有核验过的仓外副本。“仓库太大”本身不授权改写历史或强推。

## 1. 盘点并形成实际清单

1. 读取目标仓规则，确认 Git 仓根、worktree/共享 Git 目录、工作树与暂存区改动。记录候选文件占用及 `git count-objects -vH`；必要时测 Git 目录的实际磁盘占用。非 Git 目录仍可盘点和处理获准的本地文件，不执行索引或历史操作。
2. 从报告、采集清单和生成工具定位范围。UI 评审优先查 `<前缀>.ui-captures/r<n>/` 内的实拍 PNG、运行 `.log` 和 `logs/` 下已确认的控制台、请求、服务日志；其他测试产物必须先核实来源。不要把同目录的状态文件、基线图或手工附件并入清单。
3. 用 Git 枚举已跟踪、未跟踪和已忽略的候选；包含已经从工作树删除、仍留在提交中的历史路径。路径列表用 NUL 分隔或结构化参数，避免按空格、换行或 shell 通配符拆文件名。检查候选自身的已暂存和未暂存改动、符号链接及仓外指向，不跟随链接删除外部文件。
4. 按实际文件或同用途的小组列出：路径、用途依据、文件数量/大小、Git 跟踪状态、是否被引用/占用、建议动作与保留原因。体积不足以解释仓库大小、或用户指定历史瘦身时，再按 [历史瘦身](references/history-cleanup.md) 盘点历史；只读任务在仓外临时副本分析，不在原仓生成分析文件。

## 2. 清理当前版本

1. 对确认不需进入版本库的文件补齐目标仓 `.gitignore`，复用已有有效规则。规则限定实际产物路径；不加全仓 `*.png`、`*.log`，不忽略整个评审目录。用 `git check-ignore --no-index -v -- <路径>` 检查已跟踪文件对应的忽略规则，不能把“当前仍跟踪”误判为规则无效。
2. 已跟踪文件默认只从索引移除，保留本地内容。先对同一份确认清单 dry-run，再执行；只含具体文件，不含混有状态、报告或源码的目录。可把仓根相对路径写成仓外 NUL 清单：

   ```bash
   git --literal-pathspecs rm -n --cached --pathspec-from-file="/仓外/已确认路径.nul" --pathspec-file-nul
   git --literal-pathspecs rm --cached --pathspec-from-file="/仓外/已确认路径.nul" --pathspec-file-nul
   ```

   命令在仓根执行，清单必须来自上一步已核实且获准的文件；空清单不执行。有未确认的暂存内容时排除该文件，不用强制移除来绕过检查。`--cached` 的语义见 [Git 文档](https://git-scm.com/docs/git-rm)。
3. 未跟踪或已忽略的文件：默认保留本地并阻止再次入库。用户要求回收磁盘时，确认无活跃写入、无继续评审依赖，再逐项删除已确认可丢弃的文件；独有或仍需保存的材料先复制到仓外指定位置并核对内容，保留恢复路径。移到同一磁盘的归档不算释放磁盘空间。
4. 回读 `git diff --cached --name-status`、`git diff -- .gitignore` 和 `git status`，确认本次新增的索引变更只有清单内文件；保留原有暂存内容，不全仓重新 add。没有提交授权时留下可审阅的变更，不自动提交或推送。

## 3. 核验与交付

- 对照清单复查：已取消跟踪的文件不在索引中，本地保留的内容未变；应保留的报告、目标、评审原文和状态仍可读；删除的文件确实不存在；忽略规则覆盖本轮产物。
- 分别给出取消跟踪、保留本地、已删除、仓外归档和待决定的数量/大小，以及 `.gitignore` 和暂存变更。实际测量前后工作树与 Git 存储占用，不把候选大小之和当成释放量。
- 历史没有改写时明确写“历史对象仍在，旧提交和已有克隆体积未因此缩小”。用户需要历史瘦身时，先完成 [历史瘦身](references/history-cleanup.md) 的分析、备份及具体方案；涉及新授权的确认放在这些准备完成之后，已有明确授权不重复询问。

调用示例：

```text
$clean-artifacts 仅盘点当前仓库误入 Git 的截图和日志。
$clean-artifacts /path/to/repo，清理已跟踪的 UI 过程文件，保留本地。
$clean-artifacts /path/to/repo，只回收已结束评审中不再需要的本地日志。
$clean-artifacts /path/to/repo，分析截图和日志造成的历史体积，并准备历史瘦身。
```
