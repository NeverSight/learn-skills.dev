Connect an app’s logs/telemetry to the portal’s “Logs and Monitoring” service: collector wiring (container stdout / file tail / in‑app direct push), write identity (service‑account token exchange or long‑term access key), `observability.ingest` scope, `/svc/observability/v1/ingest/...` ingest endpoint, `app_<your_key>_<stream_name>` stream naming and a unified log‑field specification across apps. For any task that involves “I want my service’s logs visible in Logs and Monitoring”, “connect collector / fluent‑bit / Docker log driver”, “log write returns 401 / 403 / scope is empty”, “writes succeed but nothing shows up in the UI / stream not found”, “a single error is split into dozens of records / cannot tell which one is the error”, be sure to use this skill first—even if the user only says “hook up the logs”. Use when wiring an app’s logs or telemetry into the portal observability service: collector setup, ingest credentials and scope, stream naming, log field conventions, and the classic failures (empty scope, 403 on write, 401 on query, records that never show up).
