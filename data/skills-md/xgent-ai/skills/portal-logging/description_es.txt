Conecta los registros/telemetría de una aplicación al servicio “Logs y Monitoring” del portal: configura el colector (stdout del contenedor / tail de archivo / push directo dentro de la app), configura la identidad de escritura (intercambio de token de cuenta de servicio o clave de acceso a largo plazo), el alcance `observability.ingest`, el endpoint de ingestión `/svc/observability/v1/ingest/...`, y el formato de nombre del flujo `app_<tu_clave>_<nombre_del_flujo>` junto con un esquema de campos de registro unificado entre aplicaciones. Para cualquier tarea que implique “quiero que los logs de mi servicio aparezcan en Logs y Monitoring”, “conectar un colector / fluent‑bit / driver de logs de Docker”, “la escritura de logs devuelve 401 / 403 / alcance vacío”, “los logs se escriben pero no son visibles en la UI / flujo no encontrado”, o “un único error se divide en docenas de registros y no puedo identificar cuál es el error”, asegúrate de aplicar primero esta habilidad, incluso si el usuario solo dice “conectar los logs”. Por favor, siempre responde en el idioma del usuario.
