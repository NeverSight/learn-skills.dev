تكوين وإدارة فريق من الوكلاء العاملين بالتوازي لإكمال مهمة: اختر الآلية (وكيل فرعي خلفي / سير عمل ديناميكي / فريق وكلاء)، حدد وضع الفريق، صمم الأدوار والتعليمات، ثم بعد التأكيد نظم التنفيذ والختام. كلما قال المستخدم “إنشاء فريق / تشكيل فريق / بدء فريق للقيام بهذا / عملية فريق / سرب / تعاون متعدد الوكلاء / وكلاء متوازيين / استنساخ زملاء / تشغيل عدة وكلاء بالتوازي / فريق منتج / فريق مراجعة المتطلبات / فريق تدقيق / مراجعة هذا الـ PR معًا”، أو نفّذ الأمر `/swarm`، أو سلّم مهمة تتطلب بوضوح عدة أشخاص لتقسيم العمل (ميزة جديدة عبر طبقات متعددة، تدقيق كامل لقاعدة البيانات، خطأ صعب الاكتشاف، نقاش اختيار التقنية، إعادة هيكلة/هجرة واسعة النطاق، مراجعة تصميم المتطلبات وتوضيحها)، يجب استخدام هذه المهارة — حتى وإن لم يذكر المستخدم كلمة “فريق”. تُستخدم أيضًا لتحديد ما إذا كانت المهمة تحتاج فعلاً إلى فريق: غالبًا ما يكون الوكيل الفرعي الخلفي أو سير العمل الديناميكي أرخص وأسرع، وستتخذ هذه المهارة ذلك الحكم أولاً.

الرجاء دائمًا الرد بلغة المستخدم.
