Se utiliza para corregir brechas de UI según el informe de revisión de aceptación de UI; no es para la revisión inicial de UI, la gestión de revisión de código ni el desarrollo de interfaces sin un informe. Después de verificar cada elemento con capturas de pantalla y objetivos, corrige y realiza auto‑pruebas; cuando aparezca una advertencia de estancamiento, rediseña el enfoque, envía el registro y luego vuelve para una nueva revisión.
