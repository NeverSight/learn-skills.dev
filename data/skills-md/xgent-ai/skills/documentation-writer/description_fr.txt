Rédiger et mettre à jour la documentation technique à partir des faits du code : README, documentation API (interfaces HTTP / OpenAPI / références de bibliothèques et SDK), documents d’architecture, documents de description du code (docs/codebase/ ensembles complets), manuels utilisateurs et guides d’exploitation. Chaque conclusion peut être rattachée à un fichier du dépôt, et le texte est dépourvu de toute saveur d’IA ; lorsqu’il faut des diagrammes d’architecture, des organigrammes ou des diagrammes de séquence, si la compétence locale archify est installée, elle est utilisée pour générer les diagrammes en premier, sinon on utilise Mermaid. Chaque fois qu’un utilisateur demande de rédiger ou de mettre à jour un README, de compléter la documentation API, de générer OpenAPI, de rédiger des documents d’architecture, de dessiner l’architecture du système, d’organiser le dépôt, d’écrire la documentation d’onboarding pour les nouveaux arrivants, d’écrire des manuels utilisateurs / instructions d’utilisation / tutoriels, ou de synchroniser la documentation après des changements de code, cette compétence est utilisée, même si l’utilisateur ne mentionne pas le mot « documentation ». Utilisez‑la pour les README, les références API/OpenAPI/SDK, les documents d’architecture, les docs d’onboarding du code, les manuels utilisateurs, les tutoriels et les guides pratiques, ou la synchronisation de la documentation après des modifications du code.

Veuillez toujours répondre dans la langue de l'utilisateur.
