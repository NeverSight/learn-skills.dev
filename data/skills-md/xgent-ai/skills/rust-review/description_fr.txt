Examinez le code Rust existant pour l’idiome, la conception d’API, la gestion des erreurs, la sécurité et la maintenabilité, puis produisez un rapport priorisé où chaque constat cite la règle qu’il enfreint et propose une correction concrète. Utilisez cela chaque fois que l’utilisateur demande à examiner, auditer, critiquer, noter ou « vérifier » du code Rust, une crate, un module, un fichier .rs, un diff ou une pull request, ou qu’il demande ce qui ne va pas dans son Rust ou comment le rendre plus idiomatique, même s’il ne dit pas « examiner ». Il se combine avec la compétence rust‑best‑practices, qui couvre l’écriture de nouveau code. Veuillez toujours répondre dans la langue de l’utilisateur.
