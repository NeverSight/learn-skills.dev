# Use Rustify Docs

用 Rustify Docs 交付可阅读、可部署的静态站点。文档站让读者找到答案并完成操作；Landing Page 让目标客户第一眼理解价值、愿意继续了解并采取行动。

## 实现与设计边界

- 面向站点作者，在用户的目标项目工作；不要求克隆或修改 Rustify UI 仓库。默认采用静态 HTML/CSS 的 DOM 路径，纯内容站不编译站点 Rust、不加载 wasm，也不需要 Node、Tailwind CLI 或 Makepad。只有具体的交互组件或 demo 需求才选 components 模板与 DOM islands；不预建 GPU 路径。
- 保留用户的产品事实、品牌、已有设计和技术选择。普通创建、局部修改不扩成框架开发、整站迁移、后端、统计服务或发布。仅咨询时只读。
- **实际调用 impeccable 做设计**：从当前技能目录找到并读取其 `SKILL.md`，按其流程执行；文档面选择 Read，营销落地页选择 Persuade。Rustify 自身的 Theme Studio 外观不约束客户站点。
- **Landing Page 必须实际调用 ui-loop**：读取当前可用的 `ui-loop/SKILL.md` 并执行其流程，不能用本文件的检查表代替调用。impeccable 负责设计方向与实现；落地页按用户要求接续 ui-loop，不以通用自检轮数上限跳过所需迭代。
- 找不到上述依赖时先说明缺少哪个 skill、影响哪个阶段及如何补齐；继续可独立完成的内容与构建，不擅自安装、不声称已调用，缺少 ui-loop 时不能宣布 Landing Page 设计验收完成。

## 确定站点与入口

1. 读目标项目的 AGENTS、README、PRODUCT、DESIGN、工具链配置及相关计划，核对工作树和现有站点。确定工作目录、文档站 / Landing Page / 两者组合、受众、语言、品牌素材、部署 base，以及本次主要行动的真实目标。
2. 文档站确认读者要完成的任务与现有内容；Landing Page 确认卖给谁、解决什么问题、有什么可用证据、希望客户下一步做什么。可从材料查明的先查；会改变价值主张或 CTA 的缺项才询问，先推进不依赖答案的工作。不得虚构客户、评价、数据或产品能力。
3. 创建或配置前读 [Rustify Docs 作者契约](references/rustify-docs.md)，核对实际 CLI 的 `--version`、`--build-info` 和 `--help`。复用现有版本和项目入口；安装、组件配对、主题、落地页配置按该参考执行，不猜不存在的参数或配置键。
4. 现有站点只改对应源文件、配置与资源；新站用 `rustify-docs new` 创建到新目录或空目录。先说明内容 / components 选择及依据，再落地最小完整路径。

## 文档站

- 按读者任务组织入门、操作指南、参考和必要解释；导航服务于这些任务，不照搬源码目录。首页需要引导时用 `layout: home`，正文用默认文档布局。
- 先打通一条真实阅读路径：入口 → 快速上手 → 可执行示例 → 深入参考。代码、API、命令和输出须从实际资料核对，避免占位指南和失效链接。
- 配好标题、description、侧栏分组、标题层级、图片替代文本与站内链接。既有仓库混放计划、评审和私密资料时，用 `content.include` 明确选择发布源；不把导航隐藏当作不发布。
- 在实际页面检查阅读宽度、代码与表格滚动、移动导航、键盘与焦点。对本次涉及的搜索、复制代码、主题或多语言覆盖主路径及空 / 错状态；不为目录对称补未要求的语言或组件。

## Landing Page：先吸引，再让行动成立

使用 Markdown 的 `layout: landing`；它保留品牌与 hero，移除文档导航、搜索、侧栏和目录。没有 `--template landing`。只有要加载第三方脚本、表单、iframe 或透传参数时，才声明命名 profile 并用 `landing:` 选择。

先依据受众建立有辨识度的视觉方向与内容顺序：首屏价值主张和主 CTA、能解释产品的真实视觉、支持承诺的证据、必要异议解答及后续行动。按产品选择区块，不机械堆砌特性卡片，也不以夸张文案弥补价值不清。

**首个可运行版本完成后，实际进入 ui-loop，并把以下目标随页面上下文一起交给它。** 使用运行页面的真实桌面和移动首屏截图；首屏通过后仍检查整页与行动路径。

| 检查 | 可观察的通过条件 |
| --- | --- |
| 第一眼的价值 | 按约 5 秒的首次扫读自检，能说出面向谁、提供什么价值、下一步是什么；不用读完整页才明白。 |
| 视觉吸引力 | 主标题、产品视觉与 CTA 形成清楚焦点；排版、留白、色彩与构图体现品牌和产品特征。说明吸引目标客户的具体理由。 |
| 可信度 | 视觉展示实际产品或明确的概念表达；证明材料可追溯，没有伪造 logo、客户评价或收益数字。 |
| 行动路径 | 一个明确的主转化目标；CTA 文案说明行动及收益，点击可到达真实目的地。表单及成功 / 失败反馈符合本次实际接入。 |
| 移动与无障碍 | 移动首屏仍有价值与主要行动；无横向溢出，正文与控件可读可用，键盘焦点可见，减弱动态偏好得到尊重。 |

同时完整执行 ui-loop 的 typography、whitespace、visual_hierarchy、color、motion、micro_interaction、responsive、originality 检查。实际查看其要求的获奖参考，记录来源与可借鉴之处；不凭搜索摘要或代码认定视觉效果，不复制参考品牌和承诺。

发现差距就改源文件、更新运行产物并复验，直到 ui-loop 各维度和上述目标都无可见改进。动效服从内容与可用性，不为检查项强加动画。缺页面、参考或交互证据时保留缺项；不能把受阻、预算耗尽或自评分数当作达标。5 秒检查是设计自检，实际客户吸引力和转化率需另有真实用户或投放证据。

落地页的 `index`、`search`、`ai` 默认均为 false；根据推广目标明确处理，SEO 获客需要时显式开启 `index: true`，不能因为叫 Landing Page 就一律禁止收录。表单、统计与托管策略见作者契约；没有真实接收端不能声称已收集线索或完成转化集成。

## 验证与交付

- 按目标项目现有入口执行受影响检查；通常运行 `rustify-docs check --deny-warnings`、`rustify-docs build`，再用 `rustify-docs preview` 验收生产输出。`dev` 用于编辑预览，不能代替最终构建。
- 浏览器确认展示的是最新产物，记录入口、视口、主路径、必要截图、console 与失败请求。覆盖本次涉及的导航 / CTA、资源、移动布局、404、主题及语言；子路径部署核对 URL、base、资源和深链。
- Landing Page 另验 profile 的按页 CSP、表单 / iframe 和所用参数透传；未配置这些能力则不强行新增。有广告脚本时确认其失败不会阻断主要内容与原生表单。真实提交、发送通知或生产发布须在已有授权内进行。
- build、lint 或单测不替代浏览器验收。未能打开页面时明确写「未在浏览器中验证」，说明原因及解除条件，不宣布 UI 或 ui-loop 通过。
- 交付源文件和构建输出位置、启动命令、实际检查结果与未验证项；Landing Page 附首屏截图、ui-loop 的参考与差距处置结论。没有真实转化数据时只报告设计和功能验收，不承诺转化提升。
