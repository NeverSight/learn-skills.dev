Vollautomatisierte Sicherheits‑Review‑Pipeline für ein Code‑Repository. Verwende diese Fähigkeit immer dann, wenn der Nutzer bittet, ein Repo auf Sicherheitsprobleme zu prüfen, ein Sicherheitsaudit durchzuführen, Schwachstellen in einer Codebasis zu finden, eine Sicherheitsbewertung vorzunehmen, nach OWASP Top 10‑ und OWASP API Top 10‑Problemen zu suchen, nach Geheimnissen oder offengelegten Anmeldeinformationen zu scannen, Abhängigkeiten auf CVEs zu prüfen oder die Architektur auf Sicherheitslücken zu analysieren. Auslösen auch bei lockeren Formulierungen wie „kannst du dieses Repo auf Sicherheitsprobleme prüfen“ oder „run security on this“. Diese Fähigkeit orchestriert sieben aufeinanderfolgende Phasen: Geheimnis‑Scanning, Architekturanalyse, Abhängigkeits‑CVE‑Scanning mit Erreichbarkeitsvalidierung, OWASP‑Analyse auf Code‑Ebene, Validierung der Befunde und Erstellung des Abschlussberichts. PoC‑Generierung (mit optionaler Laufzeitvalidierung via Docker) ist über das Flag `--poc` optional aktivierbar. Zusätzlich wird das Prüfen eines einzelnen Pull‑Request‑Diffs auf Sicherheitsprobleme unterstützt (`--pr`‑Flag) – Auslöser bei Formulierungen wie „review this PR for security issues“ oder „security review this diff before merge“ – ein schneller, diff‑bezogener Modus, der nicht voraussetzt, dass das Repository zuvor gescannt wurde.
