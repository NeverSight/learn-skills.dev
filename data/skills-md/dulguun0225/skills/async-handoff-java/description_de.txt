Die Java‑Checks, die die Asynchronous‑Handoff‑Regeln zum Fehlschlagen des Builds bringen — welches Tool setzt jede Direktive für Java, Spring Boot, Spring for Apache Kafka, ArchUnit, Error Prone, Jackson, jOOQ, Flyway, Maven, JUnit, jqwik, Testcontainers und Toxiproxy durch — sowie die Broker‑Auswahl (Apache Kafka im KRaft‑Modus, wobei Redpanda und AutoMQ namentlich verboten sind), die Outbox‑Bibliotheks‑Auswahl, die einmalige Gate‑Verdrahtung und die benannten Lücken, in denen diese Toolchain keinen Check hosten kann. LÄDT IMMER ein Java‑Repo zusammen mit dem async‑handoff‑Skill, bevor ihr eine Nachricht veröffentlicht, eine Queue oder einen Broker‑Client hinzufügt, einen In‑Process‑Event‑Bus, einen Executor‑Submit, einen @Async‑ oder @Scheduled‑Task, eine abgefragte Tabelle oder ein ausgehendes Webhook verwendet. Jeder Check hier, außer den Broker‑ und Outbox‑Auswahlen, ist einem Direktiven‑ID zugeordnet, das in async‑handoff lebt; die Composite‑Shape‑Checks befinden sich in shapes.md.
