Les vérifications Java qui font échouer les règles d’async‑handoff lors de la compilation — quel outil applique chaque directive sur Java, Spring Boot, Spring for Apache Kafka, ArchUnit, Error Prone, Jackson, jOOQ, Flyway, Maven, JUnit, jqwik, Testcontainers et Toxiproxy — ainsi que le choix du broker (Apache Kafka en mode KRaft, avec Redpanda et AutoMQ interdits par leur nom), le choix de la bibliothèque d’outbox, le câblage du gate unique et les lacunes nommées où cette chaîne d’outils ne peut appliquer aucune vérification. TOUJOURS charger dans un dépôt Java le skill async‑handoff, avant de publier un message, d’ajouter une file d’attente ou un client broker, un bus d’événements en‑processus, un submit d’executor, une tâche @Async ou @Scheduled, une table sondée ou un webhook sortant. Chaque vérification ici, à l’exception des sélections de broker et d’outbox, est indexée par un identifiant de directive qui vit dans async‑handoff ; les vérifications de forme composite se trouvent dans shapes.md.
