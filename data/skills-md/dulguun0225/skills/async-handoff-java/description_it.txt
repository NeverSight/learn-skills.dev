I controlli Java che fanno fallire le regole di handoff asincrono nella build — quale strumento fa rispettare ogni direttiva su Java, Spring Boot, Spring per Apache Kafka, ArchUnit, Error Prone, Jackson, jOOQ, Flyway, Maven, JUnit, jqwik, Testcontainers e Toxiproxy — più la scelta del broker (Apache Kafka in modalità KRaft, con Redpanda e AutoMQ vietati per nome), la scelta della libreria outbox, il cablaggio del gate una tantum e le lacune nominate dove questa catena di strumenti non può ospitare alcun controllo. CARICARE SEMPRE in un repository Java insieme alla skill async‑handoff, prima di pubblicare un messaggio, aggiungere una coda o un client broker, un event bus in‑processo, una sottomissione a executor, un task @Async o @Scheduled, una tabella pollata o un webhook in uscita. Ogni controllo qui, eccetto le scelte del broker e dell'outbox, è associato a un ID direttiva che vive in async‑handoff; i controlli a forma composita sono in shapes.md.
