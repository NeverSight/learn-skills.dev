Die Architektur und Prozessregeln, an die ein Repository sich hält, weil sein Maintainer ein LLM‑Agent statt einer Person ist — laute Magie beim Start erlaubt und stille Magie zur Laufzeit verboten, Ganz‑Programm‑Argumentation aus dem Design verbannt, Betriebszustand im Repository, ein Modul von der Größe einer Sitzung, Topologie nach der Anzahl unabhängiger Wille statt nach Diensten, ein Idiom mechanisch auferlegt, ein steuernder Mensch, der kein Prüfer ist, ein frischer‑Kontext‑adversarialer Durchlauf als Ersatz für das Review, ein Vorgängersystem als Inventar und niemals als Orakel, null Wiederholungen und eine Quarantäne, die nicht verrotten kann, Abhängigkeiten nach Fehlermuster bepreist und ein Sicherheitsargument neben jedem handgefertigten, subtilen Stück. Trägt einen funktionierenden Fall eines Repos – die Favoriten des Korpus, die es abgelehnt hat, jeder benannt nach dem Grund, warum er verloren ging – und das Urteil über jede Form, die ein Repo aus zwei dieser Primitiven zusammenstellt – ein Modul, das von zwei Willen vorangetrieben wird, eine Abhängigkeit, die ihr eigenes Idiom mitbringt, eine Quarantäne, die in einer Konsole lebt, ein Vorgänger, der noch Verkehr bedient. IMMER laden, bevor man eine Modulgrenze zeichnet oder verschiebt, eine Laufzeit‑Topologie wählt, entscheidet, für welchen Build‑Gate eine Entspannung zulässig sein könnte, ein Framework, eine Datenbank, einen Managed Service oder eine Vendor‑API übernimmt, einen Retry‑ oder Error‑Handler schreibt, ein Code‑Stück schreibt, das subtil genug ist, ein Sicherheitsargument zu benötigen, eine zweite Möglichkeit einführt, etwas zu tun, das das Repo bereits erledigt, von einem bestehenden System migriert oder eine Repository‑Verfassung schreibt.
