Die Java‑Checks, die die Cache‑Regeln zum Fehlschlagen des Builds führen — welches Werkzeug erzwingt jede Direktive in Java, Spring Boot, ArchUnit, Error Prone, Jackson, Maven, JUnit, Testcontainers und Toxiproxy — sowie die Auswahl des Cache‑Engines (Valkey, wobei Redis 7.4 bis 7.8 namentlich verboten ist), das einmalige Gate‑Wiring und die benannten Lücken, in denen diese Toolchain keinen Check hosten kann. LÄDT IMMER ein Java‑Repo zusammen mit der Caching‑Fähigkeit, bevor ein Cache, ein Memo, ein Loading‑Cache, eine Caching‑Annotation, ein Ablauf oder ein Cache‑Engine hinzugefügt wird. Jeder Check hier, außer der Engine‑Auswahl, ist an eine Direktiven‑ID gebunden, die in der Caching‑Fähigkeit lebt.
