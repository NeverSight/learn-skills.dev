Les vérifications Java qui font échouer les règles de cache lors de la compilation — quel outil applique chaque directive sur Java, Spring Boot, ArchUnit, Error Prone, Jackson, Maven, JUnit, Testcontainers et Toxiproxy — ainsi que le choix du moteur de cache (Valkey, avec Redis 7.4 à 7.8 interdit par nom), le câblage du gate ponctuel, et les gaps nommés où cette chaîne d’outils ne peut héberger aucune vérification. CHARGEZ TOUJOURS dans un dépôt Java en même temps que la compétence de mise en cache, avant d’ajouter un cache, un mémo, un cache à chargement, une annotation de cache, une expiration ou un moteur de cache. Chaque vérification ici, sauf le choix du moteur, est associée à un identifiant de directive qui vit dans la compétence de mise en cache.
