I controlli Java che fanno fallire le regole della cache durante la compilazione — quale strumento applica ogni direttiva su Java, Spring Boot, ArchUnit, Error Prone, Jackson, Maven, JUnit, Testcontainers e Toxiproxy — più la scelta del motore di cache (Valkey, con Redis 7.4‑7.8 vietato per nome), il cablaggio del gate una tantum e i gap nominati dove questa catena di strumenti non può ospitare alcun controllo. SEMPRE carica in un repository Java insieme alla competenza di caching, prima di aggiungere una cache, una memo, una cache a caricamento, un’annotazione di caching, una scadenza o un motore di cache. Ogni controllo qui, eccetto la scelta del motore, è associato a un ID direttiva che vive nella competenza di caching.
