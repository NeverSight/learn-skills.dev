Das Logging, die Metriken und Alarmierungsregeln für ein Java‑Backend auf Spring Boot, für ein ausgerolltes System, das zwischen Vorfällen von niemandem beobachtet wird – eine typisierte Logging‑Fassade mit Domänentypen, die per Typ nicht geloggt werden können, kompiliert‑geprüfte Ereignis‑ und Metrikkataloge, Korrelation‑Felder, die durch sichtbare Wrapper etabliert und explizit bei jedem Fork eines virtuellen Threads erfasst werden, begrenzte Kardinalität von Metrik‑Labels und verbindliche Alarmierungsregeln, die jeweils einen Feuer‑Test enthalten. Der ‑javaagent‑Bytecode‑Weaving‑Pfad, rohe Logger‑APIs mit freiformigen Nachrichten, Regex‑PII‑Bereinigung in der Pipeline, pro‑Benutzer‑ oder pro‑Request‑Metrik‑Labels, Dashboards als primäre Oberfläche und ungetestete Alarmierungsregeln sind namentlich verboten, jeweils mit einer Prüfung, die den Build fehlschlagen lässt. IMMER laden, bevor eine Log‑Zeile, eine Metrik, ein Tag, eine Alarmierungsregel oder ein Fan‑Out, das loggt, hinzugefügt wird, und bevor Telemetrie verkabelt oder ein Logging‑Backend ausgewählt wird.
