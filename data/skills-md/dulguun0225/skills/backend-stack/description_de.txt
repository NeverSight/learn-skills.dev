Wie man einen Backend‑Stack für ein Repository auswählt, dessen Code von LLM‑Agenten geschrieben und von niemandem Zeile für Zeile gelesen wird — bewerten Sie Kandidaten danach, was ihr Build verweigern kann zu liefern, statt danach, was sie Ihnen erlauben zu formulieren, zählen Sie die unabhängigen Durchsetzungshosts, die ein Stack bietet, statt seiner Typ‑System‑Funktionen, bevorzugen Sie einen Stack, bei dem der falsche Aufruf gar nicht geschrieben werden kann, gegenüber einem, bei dem er geschrieben und dann markiert wird, bewerten Sie die Schwere des Codes (Corpus Gravity) als Kosten, die der Gewinner trägt, statt als Grund für seinen Sieg, und betrachten Sie die Bedienbarkeit als Veto, nicht als entscheidendes Kriterium. Dieser Fähigkeitssatz trägt ein eigenes Praxisbeispiel: Java mit Spring Boot Web MVC, jOOQ und PostgreSQL, mit den Verlierern auf Sprachebene — C#/.NET, Kotlin, Go und TypeScript, jeweils mit dem Grund, warum sie verloren haben — plus das Urteil zu jeder Konstellation, die eine Organisation aus Stack‑Entscheidungen zusammensetzt — ein zweiter Stack neben dem ersten, eine zweite Sprache innerhalb eines Repositories und ein abgelehnter Kandidat, der dennoch als Abhängigkeit auftaucht.
