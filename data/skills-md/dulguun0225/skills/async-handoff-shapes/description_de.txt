Die sechs Regeln für Formen, die aus asynchronen Übergaben statt aus einem Publish und einem Subscription zusammengesetzt sind, in jeder Sprache — eine verpflichtende Flussdefinition mit höchstens einem irreversiblen Schritt, der letzte ist, ein kompensierendes Ziel pro reversiblen Schritt, das toleriert, dass die Vorwärtswirkung nie eingetreten ist, ein begrenztes Timeout für jeden wartenden Schritt, das über sein eigenes Timer‑Ziel abgewickelt wird, ein ausgehender Webhook als signierter Verbraucher mit allowlisted‑Host und ohne Redirects, ein eingehender Webhook, der in den Outbox schreibt und keine Arbeit in der Anfrage verrichtet, sowie ein Claim‑Check, dessen Objekt die Nachricht überlebt. IMMER laden, bevor Sie eine Saga, einen Prozess‑Manager, eine Orchestrierung über Services, einen Kompensations‑ oder Undo‑Pfad, einen Business‑Timer oder Timeout, einen ausgehenden oder eingehenden Webhook oder eine zu große Nutzlast für den Transport schreiben. Installieren Sie parallel zu async‑handoff, dessen dreißig Direktiven jede hier genannte Regel zugrunde legt; gibt an, welche Art von Prüfung jede Regel benötigt, wobei das Tool im passenden Stack‑Skill (async‑handoff‑java) benannt wird.
