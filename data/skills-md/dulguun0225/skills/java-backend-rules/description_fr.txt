La constitution de la plateforme pour un backend Java sous Spring Boot Web MVC, jOOQ et PostgreSQL — les règles qui lient chaque ligne de code du dépôt, chacune avec une porte de construction nommée. Reactive WebFlux, JPA et Hibernate, Spring Data JDBC et la famille JdbcTemplate, le CRUD d’enregistrements attachés de jOOQ, les chaînes SQL brutes, un DSLContext injectable, des pools de threads fixes pour le travail des requêtes, StructuredTaskScope, un sémaphore supplémentaire sur le pool de connexions, les lectures d’horloge murale dans le code du domaine, les limites de longueur `octet_length` et `varchar(n)` dans les migrations, `create trigger` et `create function` dans les migrations, et les annotations Spring silencieuses à l’exécution — injection de champs, @Transactional, @Scheduled, @Async, @Cacheable — sont interdites par leur nom, chacune avec la vérification qui fait échouer la construction. CHARGEZ TOUJOURS avant d’écrire une requête, une transaction, un fan‑out en requête, une migration Flyway, une tâche planifiée ou un test sur cette pile, avant de choisir une bibliothèque de persistance, de concurrence, de JSON ou de nullité pour cela, et avant de créer un fichier de construction ou de figer la version de Java ou de Spring Boot pour un nouveau dépôt.
