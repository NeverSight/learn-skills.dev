# 网页故事动画（会自己画出来的动画）

用代码在浏览器里实时画出来的故事动画：分镜运镜、角色表演、转场、配乐、配音和字幕、自动连播，最后能录成视频发出去。不限于手绘水彩，同一套方法做过四种风格：

| 参考作品 | 风格 | 技术 | 值得抄的点 |
|---|---|---|---|
| 《追星星的小狐狸》The Living Storybook | 钢笔线 + 水彩 + 米色纸绘本，6 章 7 分钟 | React + TS + 自研 Canvas/SVG 引擎，esbuild 单文件 | 景深层、挂在台词上的镜头、中文旁白 + 英文对白双语字幕、墨水怪物、纸页撕裂 |
| 《女娲补天》 | 中国神话水墨，古朴东方色，结尾青绿设色 | 单文件 HTML，一张全屏 canvas | 预渲染世界层 + 逐笔显现、压感笔带、白描肖像、火焰纹、相机关键帧路径、古琴/古筝配乐、章节卡 |
| 《墨水宇宙 · 汴河码头》（清明上河图） | 工笔 + 水墨淡设色，绢本 | 单文件，Canvas2D 场景 + WebGL2 流体墨 | 斜投影城市、白描 → 设色两阶段、倒影层、两节骨骼 IK 的人群、船/柳/旗/鸟/炊烟、画质自动降级、页面内截图与 15 秒录制 |
| 《今晚，有人敲门吗？》（万圣节） | 夜晚绘本，暖灯冷月，英文 + 中文字幕 | 单文件，一张全屏 canvas | 光的语法（别人的光暖、主角的光冷）、抖线角色、一次轻互动（让主角画）、灯笼河、手部特写收尾 |

## 0. 先定下来
- **剧本先交给 GPT 写三轮**（便宜、质量好）：①“我要设计一个创意手绘动画，请设计一个剧本，要求治愈、有吸引力、有传播价值”；②让它站在挑剔观众和动画导演角度批判并给修改版；③让它按修改版出分镜图（每格标景别、画面、台词）。拿到剧本和分镜再开工。
- 时长：每章时长和总时长；开头 5 秒内出主角 + 悬念；每章有起因/发展/意外/高潮/收尾，至少一次惊人的视觉变化。
- 观众只做：开始、暂停/继续、声音、重播、跳章。强制互动改成自动的魔法动画；最多保留一次可选的轻互动（如“让 Mia 画”），不点也能自动继续。
- 每章 4–7 个设计过的镜头（远/中/特写/插入/低机位），禁止一个匀速平移撑一章。
- 选风格：先按上表找最接近的参考，整片只用一种画风和一套色彩语法。
- 扩展已有项目：先读全引擎，不重建、不改前面章节，保持角色造型和画风；新章节放进独立模块。
- 长任务被中断后，先看文件修改时间和会话记录，接着已有进度做，不重做。
- 用户电脑上的项目文件夹是权威版本：动手前先读里面的最新代码（尤其是用户自己改过的 TTS 脚本），不要读 `.env`。

## 1. 技术选型
- **React + TS 引擎**：章节多、要导入配音和字幕面板、会长期扩展的作品（小狐狸）。
- **单文件 HTML + 一张全屏 canvas**：一两分钟到几分钟的短片（女娲、敲门、汴河）。DOM 只放开始按钮、字幕、控制条；不用外部图片、字体、CDN，全部程序化绘制。
- **WebGL2**：只用在 Canvas2D 做不好的地方，比如墨在水里晕开、落墨成河（汴河）。必须有 Canvas2D 兜底，并且能按帧率自动降档。
- 共同骨架：可暂停的故事时钟 → 时间轴（绝对时间 cue + 挂在台词上的 cue）→ 相机 → 分层绘制 → 转场层 → 音频。所有动画都由故事时间算出来（无状态或预先积分），这样跳章、重播、录制都能复现同一画面。

## 2. 通用架构
```
clock(可暂停, scale)  timeline/cues  camera(关键帧路径)  layers(景深/预渲染)
reveal(逐笔显现)  actors(角色)  transitions  audio(音乐/环境/配音)  subtitles
```
- **Cue**：`c(t, act, args)` 用章内绝对时间；`on(lineId, offset, act, args)` 挂在某句台词上，跟着真实音频时间走。某句录长了，后面的镜头自动顺延。
- **相机**：关键帧 `[t, x, y, z, rot?, ease?]` 插值；镜头切换跟台词走；手机竖屏 base 取 `max(W/880, H/1320)`。
- **景深层**（小狐狸）：sky .12 / far .35 / back .62 / mid 1 / actors 1 / fore 1.38，纵向视差 ≈0.12；同一平面（海面 + 地平线 + 远岛）放同一层。不用 mix-blend-mode。
- **预渲染世界层 + 逐笔显现**（女娲、汴河）：静态画面先画进离屏层（世界坐标），播放时按进度 p(0..1) 显现笔画；动态元素每帧画。长卷场景按视口回收离屏层，下一场要近看的区域提前按近景精度画好并钉住。
- **TEMPO**：剧本按舒缓节奏写，播放时时间 ×k、速度 ÷k；用户嫌慢只改它，然后重新生成配音。

## 3. 风格配方

### 3.1 手绘水彩绘本（小狐狸）
- 钢笔变宽墨线 + 多层变形多边形水彩 + 颜料颗粒 + 边缘积色；画面 1–3 秒内多笔同时扫出（按 x / y / 放射排序）。
- 场景分前/中/远景，元素要丰富（多种树、花、石、蘑菇、光柱、萤火虫…）；山用中点位移做真实山峰 + 背光面，别用正弦波。
- **水彩低 alpha 叠层会偏紫**（8 位预乘 alpha 把绿通道舍入为 0）：合并淡层 `k=ceil(MIN_ALPHA/alpha)`，`alpha'=1-(1-alpha)^k`，`layers'=layers/k`，MIN_ALPHA≈0.06；用像素值检查（R>G 且 B 高 = 偏紫）。
- 要更鲜艳：提高调色板饱和度，再提高天空/远景 alpha；不要大面积紫/粉带。
- 常见穿帮：硬边矩形 wash（改成多个软椭圆）、广角露出画板底部白纸（地面加深并向下延伸）、海面左侧竖直硬边。

### 3.2 水墨神话（女娲补天）
- 米纸底 + 墨色为主，古朴东方色（赭、朱、石青、石绿）只点在关键处；结尾“天被补好”时整卷转为青绿山水设色，作为情绪高潮。
- **笔**：Catmull-Rom 重采样 → 带压感收尖、毛边的变宽笔带；湿墨晕染用多椭圆不规则 blob；动态小线条用简化折线。
- **山**：一层一层画山脉进预渲染层，近浓远淡，留白当云雾。**水**用“水图”式线描波纹；**火**用火焰纹舌状色块 + 卷曲尖端 + 墨线勾边。
- **人物**：全身像以身高 100、脚在原点为局部单位；近景肖像用白描侧脸（单位：头顶到下巴 ≈220），长发和飘带随时间飘动。神兽（共工、黑龙、神鳌）用沿头部路径的脊柱跟随。
- 天裂：像旧瓷开片的裂纹；落石、碎片用无状态函数（由时间算位置）。

### 3.3 工笔 + 水墨城市长卷（清明上河图 · 汴河码头）
- **斜投影**画建筑：屋顶（悬山/歇山，举折曲线、翘角、筒瓦、正脊、鸱吻）、开间、斗拱、勾栏、彩楼欢门、凉棚、货棚、虹桥、华表。
- **两阶段成画**：每个元素记录 `prog`（墨线描出比例）和 `fillA`（设色程度）。开场“落墨”：一滴墨落纸 → 晕成河势 → 岸与桥从墨里显出 → 沿岸勾出街市（白描）→ 逐步淡设色。
- **淡设色**：矿物颜料先去饱和、再兑绢色，纸色始终透出来；只在视觉中心点几处浓的暖红、赭黄、石青绿（整体雅、局部活）。
- **倒影层**：水面附近的元素按水面镜像再画一遍，加波纹扰动；河面多边形做遮罩。
- **人群**：每人是“脚底原点 + 朝向 face(±1，可过渡表示转身)”；手臂用两节骨骼 IK 贴住扁担、桨把；动作是 `u/d`（动作内时间/总长）驱动的姿态函数；道具单独画。
- **生活感**：船夫划桨推动船身（预先积分，可回放）、撑篙货船、酒旗随风、炊烟、柳条从根到梢相位滞后、落叶落水随流、鸟群跟领头曲线飞。按时间线编排小故事（如桥上孩子与母亲），保证切到某个镜头几秒内一定看得到。
- **WebGL2 流体墨**：dye + curl + pressure 的稳定流体，把世界事件（落墨、船桨、落叶）转成 splat；不支持时 Canvas2D 平涂水色 + 半透明倒影兜底；帧率不足自动降画质档位。
- 调试入口：地址加 `#d` 开自由镜头、缩放、拖时间。

### 3.4 夜晚绘本（万圣节 · 今晚，有人敲门吗？）
- **光的语法**：别人的光是暖橙 `#FFB347` 一族，主角自己的光是冷白 `#FFF3D6` 一族；全片按这个分配，情绪自然就出来了。
- 角色用“抖线”（boiling line：轮廓每隔几帧轻微重绘）表现手绘感；主角 Mia + 黑猫 Boo 全片同一造型。
- 叙事节奏：书自己画出小镇 → 角色走过一家家亮灯的门 → 走到镇子边缘 → 主角自己画出一座房子 → 灯笼升空连成一条河 → 最后一盏灯落到一扇为她留着的门前 → 手部特写：想敲门，门已经开了。
- 一次轻互动（“Let Mia draw · 让 Mia 画”按钮或拖动画线），不操作也会自动完成；交互光晕用跟随指针的水彩光圈。
- 双语字幕：英文在上、中文在下；canvas 上的中文不小于 16 CSS px。

## 4. 角色与表演（通用）
- 分件绘制：头、眼、眉、耳、尾、四肢独立，表情和姿势是参数；全片同一造型。说话时口型跟音量。
- 流体角色（墨怪）用径向点弹簧轮廓：压扁/拉伸/融化/聚合/变巨（不是 CSS scale）。走进纸洞用缩小 + 前移 + 淡出。
- 人群和路人用姿态函数 + IK，不要贴图循环；每个动作有开始、过程、收尾。

## 5. 转场
- 章与章：卷边翻页 → 纸上印出章节卡（至少停 1.5s）→ 下一章在白纸上画出。章节卡在 cover 开始时锁定，只由 turn/light 消费。
- 高潮收尾：金光铺满 → 章节卡 → 化开。同章换场景：canvas 湿笔刷 dab 毛边擦除。
- 纸页撕裂/穿越：冻结旧页 + evenodd 洞 + 纤维/卷边/阴影，镜头推进穿洞。
- 水墨片：墨晕化开/收拢做转场，章节卡用竖排书法标题 + 朱印。
- 结尾：整本书合上，或镜头拉远成整幅长卷。

## 6. 配音：豆包语音（火山引擎语音合成 2.0）
**不假装生成过音频，不虚构 API 调用**；密钥只走环境变量或项目根目录 `.env`，永不读取、打印或提交。

### 接口
- `POST https://openspeech.bytedance.com/api/v3/tts/unidirectional`
- 头：`X-Api-Key: <新版控制台 API Key>`（不是 appid/access token）、`X-Api-Resource-Id: seed-tts-2.0`、`X-Api-Request-Id: <uuid>`、`Content-Type: application/json`。
- 体：
```json
{"user":{"uid":"living-storybook"},
 "req_params":{"text":"…","speaker":"zh_female_vv_uranus_bigtts",
  "audio_params":{"format":"pcm","sample_rate":24000,"speech_rate":-10},
  "additions":"{\"context_texts\":[\"用温柔的年轻女声讲睡前故事…\"],\"disable_markdown_filter\":true,\"explicit_language\":\"en\",\"post_process\":{\"pitch\":2}}"}}
```
  `additions` 是 JSON 字符串；`context_texts` 用自然语言描述语气；英文句加 `explicit_language: en`；`post_process.pitch` 调音高。
- 响应：按行的 JSON 块，`data` 是 base64 的 s16le PCM（也兼容 RIFF 包装），拼接；`code` 为 0 或 20000000 正常，其他即报错；不足 0.25s 视为没合成出来。

### 音色与语气（同一个 voice，靠 context/pitch 区分角色）
- 中文旁白：默认 `zh_female_vv_uranus_bigtts`（可用 `DOUBAO_SPEECH_VOICE_TYPE` 覆盖），speech_rate -10，context“用温柔的年轻女声讲睡前故事，语速慢一点，轻轻的，像在对一个孩子说话。”
- 角色英文对白：rate 0，pitch +2，language en，context 写角色年龄和性格（如 “young, bright, curious girl in a picture book”）。
- 小生物叫声：pitch +8，context “tiny creature, only a soft, round, cute sound, not a sentence”；另生成叫声库 `v-boop / v-eep / v-coo / v-giggle …`。
- 神话旁白可换成沉稳、古雅的语气描述；宣传片旁白用“自信、温暖、清亮，像跟朋友分享好消息，语速自然”，rate 0。

### 脚本 `tools/tts/doubao.py`（只用 Python 标准库）
- `python3 tools/tts/doubao.py`：从剧本解析旁白 → 逐句合成 → 切首尾静音 → 按剧本时间放上时间线，上一句超长才顺延（句间留 0.36s 气口）→ 整章音频 + 按真实开始时间重写 `.lrc` → 打包成 data URL 模块。
- `--dialogue`：逐句生成角色对白和叫声库；`--dry` 只打印计划；`--force` 忽略缓存。
- 逐句 PCM 缓存（key = 文本 + 音色 + 语速 + context + pitch + 语言 + resource 的 sha256），重跑不重复计费。
- 其他用途（如宣传片旁白）写一个小脚本 import `doubao`，复用 `load_env` / `speak`，逐句输出 wav + `lines.json`（含每句时长）。
- 编码：macOS 用 `afconvert -f m4af -d aac -b 64000`；Linux 用 `ffmpeg -c:a aac -b:a 64k`。重新生成后必须重新构建。

### 网络与执行位置
- 云端会话访问 `openspeech.bytedance.com` 常被白名单拦（CONNECT 403）。不要绕过代理；最稳的是**让用户在自己电脑终端里跑脚本**（`.env` 在那里），跑完再把生成的音频取回来用。

### 页面端同步
- 旁白优先级：用户导入 > 页面旁 `narration/chN.*` > 内置包 > 浏览器朗读。有录音时，录音 currentTime 就是章节时钟。
- 对白：每句先量真实时长再排时间（不重叠，超长顺延）；双语字幕上英下中，按音频起止显示；可导出实际播放时间轴。
- 浏览器语音兜底：speak 前先 `speechSynthesis.resume()`，否则暂停过会吞句。

## 7. 配乐与环境声（全部 Web Audio 实时生成）
- 治愈绘本：毛毡钢琴（正弦 + 轻八度，快起慢收），每拍至多一个音，五声音阶级进、常留空；暖长音垫底，低音只在小节头；卷积长混响。音乐 level≈0.2，说话时压到 0.42。
- 中国神话：古琴/古筝拨弦（快衰减 + 轻滑音）、低沉鼓点只在关键动作、长持续音垫底；高潮再加厚。
- 夜晚绘本：夜风底噪一直在（不关），远处的门铃、笑声、风铃点缀。
- 环境声整体 ≈0.42，暴雨也别拉满；配音永远优先于音乐。

## 8. 构建
- 单文件交付：esbuild 打包或直接手写单 HTML。**内联 JS 时用函数形式 `.replace('</body>', () => ...)`**，否则压缩代码里的 `$'` `$&` 被当替换模式导致白屏。
- 内置配音用 AAC 64k data URL 打包。发布前对压缩产物再跑一次报错检查。

## 9. 录制与传播
- **页面内**：截图按钮（右下角加朱红印章）、录制 15 秒按钮：`canvas.captureStream(60)` + 音频目标节点合流 → `MediaRecorder`，优先 `video/mp4;codecs=avc1`，不支持再退 webm 并提示；提供 16:9 / 9:16 画幅切换。
- **无头抓帧**（做预览动图和宣传片）：Playwright `page.clock.install()` 后用 `clock.run_for(整数毫秒)` 逐帧推进并截图，帧率稳定、可复现（`run_for` 只收整数）。长距离跳时间用 `clock.fast_forward`。无头 WebGL（SwiftShader）很慢，按帧计数推进的页面要用小视口（如 800×450）实时截图，再用 ffmpeg `framerate` 插帧做成延时。
- 带烧录字幕的素材做二次剪辑时，先裁掉字幕区域。
- **竖屏宣传片**（1080×1920）：上方大标题 + 中间圆角画框放 16:9 片段（背景用同片段模糊压暗铺满）+ 下方字幕跟配音逐句同步；竖构图的片段可以整屏铺满。旁白逐句用豆包生成，按每句真实时长排场景；音乐压到 -10dB 左右，整片响度约 -16 LUFS。
- 封面图：直接截动画里最好看的一帧做底，标题放在留白处；X 文章封面用 5:2。

## 10. 验证（必须实际跑）
Playwright 无头 Chromium（`--autoplay-policy=no-user-gesture-required`）：
1. 整片/单章：跳章、`clock.scale` 快进，按间隔截图 → contact sheet 逐张看；核对实际时长。
