# 猎人字体设计 · Hunter Front Design

把风格要求变成可复查的轮廓规则，再变成真实字体。网格、样张、字体文件和试排页面都必须指向同一版本；概念图不能冒充字体文件的实际效果。

## 开始与范围

- 先读现有设计依据、源文件、确认记录和构建方法。区分已认可母版、候选参数、已被替代方案；不能为了迁就旧轮廓反写规范。
- 新项目明确用途、目标字号、语言与字符清单、字重/字宽、平台和交付格式；记录逐字原创、开源骨架改造或混合制作路线。先做用户要的范围，不把单字重自动扩成多字重或多语种家族。“完整”指约定字符与功能，不指整个 Unicode。
- 核心流程与按需专项一起构成完整项目流程。使用[专项生产、工具与验证](references/specialist-workflows.md)的可编辑源构建、家族、屏显、文字塑形、原创中文控制字、竖排、可变、彩色、专业符号与子集工具；逐项取得当前字体证据。技术样本验证工具可用，不替代造型认可、整库语言审校或真实目标平台验收。
- 按[覆盖范围与按需专项](references/coverage-and-specialties.md)识别本项目是否涉及正文小字、多样式家族、斜体、其他文字、竖排、可变/彩色、专业符号或网页子集，并在规则表列出适用项与完成证据。工具不足的必需项记为未检/待补，不能写成不适用；单一工程报告通过不能代替项目全部必需关卡。
- 中文标题字先明确逐字原创或开源骨架定制路线；用户选择实用整库时，读 [中文衍生字库与覆盖核验](references/cjk-derived.md)，执行对应的许可、汉字结构、明确码点和中文试排检查。单一衍生项目的验证不代表所有中文造字路线都已验证。
- 复用已有确认，不重复问许可。新设计按下节先选样；“做完整字体”本身不等于已选方案。用户选定后按授权推进，将尚未确认的细节标为候选。工程通过不等于审美获批。

## 按设计阶段组织工作

工具嵌入设计过程，不把项目编排成先跑完工具、再看造型的流水线。已有认可母版从对应阶段续做；一轮修订只重跑受影响关卡，涉及轮廓时仍按 3.5 节复审。

| 阶段 | 输入与动作 | 产出与进入下一步的条件 |
| --- | --- | --- |
| 需求与制作路线 | 用途、目标尺寸、字集、参考、平台与权利范围 | 范围和路线可执行；已有确认直接沿用 |
| 参考研究与测量 | 识别骨架、比例和特殊结构；有参考才校准和测量 | 来源、置信度及未知项明确；数值作为候选依据 |
| 三案选样 | 按第 0 节生成可比较的初步效果 | 用户选定，或有明确跳过／代选授权 |
| 规则与真实控制字 | 第 1–2 节：规则、源网格、试验字体、目标字号 | 风格规则能落到真实轮廓；关键结构先验证 |
| 分组扩字与排版 | 第 3 节：关联字族、数字、标点、附标；先边距后字偶 | 约定字符和功能展开，变更依赖已复查 |
| 整套光学审校 | 第 3.5 节：全覆盖、放大与实际字号、正反白和混排 | 问题回源修正；保留例外和未解决项有记录 |
| 工程验收与校样 | 第 4–5 节：通用验收、交互试排、自动技术字样册 | 报告、字体、试排与字样册哈希一致；失败回到负责阶段修正 |
| 封装与字体交付 | 源码、字体、版权与许可填写／写入／检查、清单和使用说明 | 按工程参考回读各格式；开源底字归属与许可保留；用户审美确认与未测平台分别报告 |
| 展示设计与交付（按需） | 第 6 节：技术展示海报、使用场景海报、整组复核 | 真实字体排版，字体特性决定场景和构图；用户已要求时直接执行 |
| 修订与版本维护 | 工程参考的版本维护：源、导出、副本、回归与更新说明；清理按已有授权范围执行 | 当前源可重建交付版，旧证据与新版分明，使用中的其他项目依赖得到保留或同步 |

### 参考测量与统一参数

有图片／字体参考时读 [参考测量、校准与项目参数](references/measurement-and-targets.md)，使用 `scripts/measure_reference.py`。先用已知字体在相近尺寸校准像素读数，再区分直接测得、代理推算和未知项；缺少 H/x/n 等控制字时不补造数据。没有参考的原创设计跳过参考校准，直接在真实控制字阶段建立设计参数。

用 [项目参数示例](assets/font-targets.example.json) 建立项目自己的 `font-targets.json`：约定码点、目标度量及容差、塑形样本、光学例外和参考测量文件。它与设计规则表互补，供验收和技术字样册共同读取；项目绘制代码读取已选定的相关参数。不得把实测值自动当成用户确认值，或把某字体的数值、双字重、3% 拉伸和固定字偶数量变成默认要求。

开源衍生是可选路线：按该参考的候选比较流程核对许可、字符覆盖、可用轴与真实字样，骨架优先、数值辅助。继承字形明确归属；特殊结构可按授权补绘，逐字原创仍沿原流程。不因加入工具就强制选开源底字或改用某种许可。

## 0. 确认风格，再提供三案选样

新字体设计的默认顺序是：**需求 → 确认风格 → 三种初步效果 → 用户选定 → 设计规则与真实控制字 → 扩字、封装与试排**。

1. **确认风格**：用简短问题或选项明确用途与风格倾向；用户已经明确的风格直接沿用，不重复确认。风格确定后仍要提供三案，不能把风格词当成已经选定的字形方案。
2. **实际生成三案**：使用可用的图像生成能力，返回 A/B/C 三张初步字体概念效果图，不以三段文字描述代替。三案都遵守已确认的风格，在骨架比例、字宽、曲率、端头或字形性格上形成可见区别；不靠更换背景、颜色或场景充数。此时只做足以判断方向的样字，不提前制作三套完整字库。
3. **让三案可比较**：使用相同样字和短语、相同画幅与简洁背景、接近的可见字高；按任务覆盖必要的大小写、数字或特殊结构，不为凑比较扩大字符范围。逐张检查样字是否清楚、是否确有差异，修正乱码或缺字后再展示。每案附一两句说明，指出主要差异与适用气质。
4. **等待选定**：明确标注“概念效果，尚非可安装字体”，邀请用户选 A/B/C，也可明确组合某些特征或要求重做。可以推荐并说明理由，但用户选定前停在选样阶段，不自行替选后批量扩字。普通的完整制作授权不跳过此步骤；用户明确要求跳过选样或授权代选时，说明采用的方向后继续。
5. **落实所选方向**：保存三案、所选编号及用户要求保留的特征，再进入下列设计规则、真实轮廓网格和控制字验证。把概念效果转化为可实现的几何规则；生成图不证明字符覆盖、字距或字体工程已完成。

已有用户选定的方案或认可母版时沿用记录；局部修字、继续扩字、补封装或追加应用海报不重新开启三选一。用户明确要求重新探索设计方向时才回到此阶段。

## 1. 先写设计原则

用 [设计规则模板](assets/design-rules-template.md) 在项目中建立规则表。每项写明：**风格意图 → 结构约束/候选数值 → 控制字 → 检查方式 → 光学例外与确认状态**。

必须先考虑：

- em/UPM、基线、大写线、x-height、上下伸部、超出补偿、网格单位。
- 字宽分组与宽高比；区分字面宽、占位宽、笔画等重和等宽字体。比例字不强制 I/M 同宽，等宽数字也不要求每个数字的黑色字面同宽。
- 竖横笔画、曲线/斜笔重量、交汇减重；端头、切角、衬线或无衬线规则。
- 外轮廓的平直段、侧壁、转角起止和切向；内白的形状、面积、内角与最窄处；开口位置、方向与目标尺寸下的可读性。
- 大小写、数字、标点、货币/数学/编辑符号、附标的相互关系；边距、重心、视觉居中与行距余量。

内外圆角不是简单套同一半径，也不一定等于“外半径减笔画厚度”。用同组母字比较转角附近的黑度、内白和直线长度。统一的是造型逻辑，光学校正可不同。方正、短转角只是某些项目的风格，不是本 skill 对所有字体的默认造型。

用户明确要求**几何等线宽**时，将其写为硬约束，和“视觉等重”分开：主字级共用笔宽，不为 S/B/P/R/e/8 等私自减细；空间不足先调整骨架、比例、字腔或转折位置。次级字级可整体等比缩放，须单列；交汇处的黑色面积也不能冒充单笔厚度。用源参数和实际导出的直、斜笔法线截面及曲线径向截面核对，单看设计常量不足以证明成稿等线宽。未选择几何等线宽的字体仍按其光学校正规则判断。

## 2. 网格控制字先于批量扩字

读 [结构分组与反复修订经验](references/design-review.md)，选覆盖直线、碗部、斜线、交叉、开口、腰部、肩部、上下伸部的控制字。可从 `H O B D P R C G Q S N X / n o a e g m r s u / 0 2 5 6 8 9 / & ? €` 取样，不固定数量。

1. 有参考的字符逐个标出来源；没有直接参考的标为规则推导。既有参考不只比较最显眼的一个单词。
2. 选样后的第一版源轮廓就出**源轮廓网格板**：相同 em 缩放、坐标和基线，保留真实字宽；标出参考线、字面框、占位与边距。初步概念图不冒充源轮廓；位图只有估测坐标时直说。
3. 同时出无网格单字、真实单词及目标字号。大图看接缝，实际字号看黑白节奏；必要时反白检查。
4. 记录问题属于哪条规则。允许超出、交汇减重、S 的上下不对称等光学例外；不以所有节点吸附、机械对称或像素相似率当验收。
5. 源稿形成后尽早导出小范围真实试验字体，用配套工具核对“参考 → 源轮廓 → 导出效果”。明确阶段后再扩展，不用好看的生成图替代此链路。

## 3. 扩展整套字符并维持统一

- 先列具体码点、字形与语言，再按结构组扩展：直线、闭合碗部、开口、斜笔、S/8 类；小写、数字和符号各自成组。小写不是缩小的大写，数字不是套现成圆体。
- 母字与共享部件保留依赖清单，例如 `O → Q/Ø/Ò…`、`S → Š/$/§`、`C → Ç/€`。依赖只是复查范围，不代表机械复制：€ 需要横杠出口，§、&、ß、æ/œ 常需独立处理。
- 每轮保存旧版，写实际修改范围和要保护的字形。修改共享规则后查所有派生字；确认“未变”用轮廓/度量/塑形数据比较，不能只比文件大小或字偶数量。
- 用 `Ss O0o B8b Dd Pp Qq Rr Uu` 等跨组同排检查家族感；全字符逐字翻页查漏，再看混排。保留 ©/® 外框、括号等必要语义结构，不把“统一”做成所有符号同形。
- 一轮反馈先修根因并核对影响，避免只修箭头指向的一点。已认可部分作为保护基线；若必须连带改变，说明具体原因和差异。

## 3.5 成稿后的深入整体光学审校（必做）

新字体或字形修订形成可交付成稿后、封装前，**必须对当前真实导出进行一次深入的整套光学字符检查**。不要等用户逐字指出问题；编译、几何断言、FontBakery 与浏览器载入通过都不能替代这一关。

按 [成稿整体光学审校流程](references/design-review.md#成稿整体光学审校必做) 执行：逐字覆盖约定字符及未编码替代字形，分结构组与跨组检查风格、比例、视觉中心、笔重、内腔、转角、端头、连接和字距；标点按语义位置分类，并与实际字母、数字混排。用同 em 的网格/无网格、放大细节、目标字号和较小一档、正反白审阅。不能只检查本轮修改字或一个全字母句。

将 [闭合字腔接竖笔与同类字形对齐](references/design-review.md#闭合字腔接竖笔与同类字形对齐) 列为专项检查：内腔相同不证明外侧折角完整或连接黑度协调；按已确认造型复查接头、同构字组的关键高度与内外转折。修复须保护主体笔宽、内腔与排版数据，保留有理由的结构和光学差异，不能把挖缺角或峰顶齐平当成所有字体的默认要求。

将 [斜笔粗细与同类笔画黑度](references/design-review.md#斜笔粗细与同类笔画黑度) 列为专项检查：沿斜笔有效长度复核有无意外渐细或增粗，并跨字母、数字和符号比较同类笔画的视觉黑度。结合多点法线测厚与实际字号审阅，保留有意的笔画对比与光学减重，不把所有斜笔机械设成同一厚度。

每次成稿主动执行 [字距专项审校](references/spacing-and-kerning.md)，无需用户另行提醒：先检查单字边距，再按相接轮廓覆盖小写局部留白、大小写边界、窄字与下伸部、标点、数字、附标、替代字及上下文；中文、竖排和复杂文字按本轮范围检查。逐场景记录已检、不适用或未检及原因。结合当前字形、目标字号和真实塑形决定收紧、放宽或保持；候选字偶、其他字体的数值和最短轮廓距离均不直接决定修改。

在项目 [规则与审校记录](assets/design-rules-template.md) 中记录覆盖清单、实际字体版本/哈希、逐组问题、已修正项、保留的光学例外与理由、尚未解决项及对应样张。发现问题要回源修正、同步导出与试排，再复看受影响组和整套混排；保留已认可部分的比较基线。不得把上下腰线、符号语义等有理由的差异机械居中或强制等厚。

仅改文档、封装或试排界面且字体字节未变时，可沿用同哈希成稿的审校记录，并验证改动本身；不能把旧字体的审校记录冒充新轮廓已审。

## 4. 工程、封装与安装验证

到导出阶段读 [工程与字体封装](references/engineering-packaging.md)。保留可编辑源和可重复构建方式；先边距后字偶，再验证实际需要的 OpenType 特性。TTF/OTF 必须真实编译，网页包装不能代替轮廓转换。

需要专项时先执行[专项生产参考](references/specialist-workflows.md)，共享 `FontData.shape_run()` 明确语言、脚本、方向、特性和轴；运行 `check_source.py`、声明范围的 `check_specialties.py`，并按项目使用 Fontmake、hinting、OTS/FontBakery 与真实渲染。新增必需项进入项目关卡；不能只运行通用脚本就结束。

按用途交付 TTF/OTF、WOFF2/WOFF；TTC/OTC、可变字体、彩色或旧式格式只在需要时增加专门检查。核对内部命名、版本、家族/样式关系、编码、度量、嵌入设置、实际轮廓类型和容器。建立文件清单与校验值，解压回读后再交付。

有中英文或其他本地化名称时，执行 [双语命名、写入与显示检查](references/bilingual-naming.md)：先核对项目资料和相关对话中的已确认名称，再按语言写入家族、样式及完整名称；保留英文名、PostScript 名和约定的内部标识。逐格式精确回读名称记录并同步字体副本、试排、字样册和 ZIP；改文件名或海报标题不算完成内部命名。

封装必做 [版权与许可：填写、写入和回读检查](references/copyright-and-license.md)：复用已确认的版权方、设计者和许可资料，在构建源中写入对应 `name` 字段，并逐字重、逐格式核对实际导出。开源底字保留原版权、许可及必要的归属文件，修改者署名另行追加；不把底字改造成独占原创声明。资料未定时记录待确认状态，继续可独立完成的审校，不虚构权利或将审校稿称为已完成正式发行验收。

常规静态轮廓字体使用 [通用验收与自动技术字样册](references/automated-checks-and-book.md) 中的 `scripts/check_font.py`，按同一 `font-targets.json` 输出可回读的 PASS/FAIL/INFO/SKIP。它只检查声明的工程范围；未执行的光学、平台或复杂文字检查不能随工程通过一并宣称完成。

分开报告四类证据：

| 关卡 | 完成证据 |
| --- | --- |
| 设计 | 规则、同尺度网格、无网格样张、全字符审校、确认与例外记录 |
| 字体结构 | 真实导出、编码/轮廓/度量检查、工程报告和未解决警告 |
| 塑形与试排 | 字偶/连字/附标实际结果、目标字号、大小写数字符号混排与缺字说明 |
| 平台与封装 | 容器回读、包内文件一致性、实际执行的安装/注册/应用验证 |

字体能被解析、浏览器能显示、进程内注册成功、系统已安装、目标软件兼容是不同事实。说明实际做到哪层，不把审校稿称为正式发行版。

## 5. 把试排工具作为每轮交付的一部分

读 [试排工具用法与边界](references/proof-tool.md)。可直接复制 `assets/proof-tool/` 离线导入字体；有构建字体时，优先运行：

```bash
python /absolute/path/to/hunter-front-design/scripts/create_proof.py "/project/fonts/Family-Heavy.ttf" "/project/proof-v001"
```

输出是完整本地工具，包含当前字体原件、真实 cmap、度量来源与 SHA-256。目标目录须不存在，防止覆盖旧审校证据。用项目已有含 fontTools 的 Python 环境运行；不依赖 SOLID A 目录。

试排页还需作为用户可直接打开的预览入口交付，按[试排预览交付规则](references/proof-tool.md#交付时展示试排预览)执行。

猎人品牌试排页打开即显示随包公众号二维码及下方一行「Created by AIGC创意猎人」；按[公众号与制作署名](references/proof-tool.md#公众号与制作署名)验证离线资源和侧栏可达性。该展示区只保留二维码和这一行署名；字体内部的版权与许可仍按封装流程保留、写入和检查。

自由试排提供输入、字号、行距、字间距、段距、宽度、对齐、字偶和连字开关；网格校样提供网格/参考线/边距辅助层。桌面滚动字样时，顶部、左侧和网格参数保持可操作；小屏另验可达性。修改辅助线不改变轮廓，实际字距修正应回到字体源。

后续字体项目默认沿用本 skill 当前试排模板与生成器：每个已覆盖字形右下角使用圆形放大镜图标，点击打开可滚动的悬浮放大校样。保留当前真实字形比例和参考层、关闭按钮、Esc、空白处关闭与焦点返回，以及自动铺满宽度、固定控制区和内容哈希缓存；按新项目更新字体、元信息和品牌素材。

交付前核对页面实际载入和下载的字节、字体版本与哈希，排除旧缓存；验证主要交互和实际字号。自动化可用时运行 [浏览器检查脚本](scripts/check_proof.cjs)，否则用当前可用浏览器操作并记录证据。不要为了工具截图重新设计页面。

在真实控制字阶段可生成阶段技术册；成稿验收后，用 `scripts/create_font_book.py` 和 `scripts/render_font_book.cjs` 自动生成同哈希字体的字符表、测量表、字号阶梯、字偶与功能对照和 PDF。按 [自动化工具说明](references/automated-checks-and-book.md) 验证载入字节、缺字、溢出与报告新鲜度，并实际看代表页。技术册不替代交互试排、源网格、逐字光学审校，也不直接冒充技术展示海报。

## 6. 完成后可选：字体宣传展示

字体设计、封装与试排交付完成后，询问用户是否需要技术展示海报和应用场景海报；**默认不自动生成**。用户已明确要求时直接执行，不再次问许可。进入海报阶段后，常规交付为**技术展示海报 6–8 张、使用场景海报 8–10 张**；在范围内按展示内容与场景差异确定具体张数，不重复询问已确定的数量要求。本次用户另有明确数量时按本次要求执行。比例、主题与用途服从本次要求，不把某个项目的 3:4 固化成通用默认值。

制作时读 [宣传海报流程](references/promotion-posters.md)：先规划各张的展示目的和版式差异，再用真实字体排出主文字；生成图只提供场景素材。画幅、标题净距与页脚节奏按构图分别安排，技术页标注须与当前轮廓对应；最后逐张检查并提供整组索引。制作海报不意味着授权发布或字体已成为正式发行版。

该阶段明确交付两类展示：技术展示围绕字符集、比例与网格、笔画／字腔、节点、字偶和字重展开；使用场景展示依据字体特性选择品牌、包装、空间、出版或数字界面等应用。技术字样册可提供真实数据与字样素材，两类海报仍需独立策划版式、制作并逐张复核，不能只把册页换背景充数。

**每个具体应用场景都必须结合当前字体的形态个性与内在特性生成效果。** 先在策划中写明“字体特性 → 场景适配理由 → 视觉构成动作 → 预期效果”，让比例、笔画、字腔、转角、开口、黑白关系或字间/数字节奏实际决定主文案、构图、材质、空间或信息组织。逐张核对这些特性是否在成品中可见；应用展示的选题与效果不能脱离这套字体来制作。技术字符表与网格仍以清晰、真实和可比较为先。

## 修订与交付

使用[交付计划](assets/delivery-plan.example.json)登记当前文件哈希、必需关卡及未检原因；`package_project.py` 验证输入和 ZIP，正式发行会拒绝未通过的必需项。旧字体及压缩包清理使用工程维护流程和 `retire_font_artifacts.py`，先核对授权、保留项与跨项目依赖。

最终交付按本次范围给出字体文件、源文件/构建入口、规则与字符清单、网格和无网格样张、试排工具、版本/变更与测试记录。完整发行包装见工程参考；没有确认的名称与分发许可不替用户决定。

每次字体交付（含修订与收尾）的最终回复，必须单独列出 **“打开试排预览”** 链接，指向本轮实际字体的可打开试排页；客户端支持预览时同时打开页面。ZIP、技术册 PDF、检查报告或截图不能代替交互试排入口，也不能只说“试排页在包内”。

交付前检查本轮反馈：可复用方法写回本 skill 对应资源；当前字体的数值、品牌意见和未认可造型只留项目。只对已验证内容报告完成，不因规则写入就宣称另一套字体也已验证。
