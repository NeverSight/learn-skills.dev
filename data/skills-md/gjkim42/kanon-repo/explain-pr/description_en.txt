Explain a PR's patches so the user understands them: the motivation and core idea, a before/after sample of what callers or users see, a flow diagram of that sample's path through the code with file:line citations, the facts a reader could miss, and where the PR description and the diff disagree. Use when the user says "explain-pr", or asks to explain, walk through, or help them understand a PR, a diff, or what a branch changes, including PRs written by an agent. Defaults to the PR for the current branch. This skill explains; it is not a review — it gives no verdict, changes no code, and posts nothing to the PR.
