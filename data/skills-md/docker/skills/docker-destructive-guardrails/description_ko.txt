이 기술은 Docker 명령을 실행하거나 권장하기 전에 사용하십시오. 여기에는 삭제, 초기화, 재설정 또는 상태를 되돌릴 수 없게 변경하는 모든 작업이 포함됩니다—사용자가 단순히 “정리”, “캐시 삭제”, “새로 시작”, “모두 삭제”, “전부 파괴”, “재설정”, “강제 제거”, “해제”와 같은 표현을 사용하더라도 적용됩니다. 보다 구체적인 기술에 포함되지 않은 일반적인 Docker CLI 파괴 작업을 다룹니다—`docker rm`, `docker rm -f`, `docker container prune`, `docker kill`, `docker system prune`, `docker rmi`/`docker image rm`, `docker image prune -a`, `docker network rm`, `docker network prune`, `docker builder prune`, `docker buildx rm`, `docker context rm`, 그리고 독립적인(Compose 비사용) `docker volume rm`/`docker volume prune`. 또한 다른 Docker 기술(Compose, sandbox, Desktop)에서 소유하는 파괴 명령도 포함합니다. 핵심 규칙—손실될 항목을 정확히 명시하고, 명시적인 확인을 받으십시오. 다만 제한적이고 불편함이 적은 1단계 컨테이너 정리 경우는 예외로 합니다.
