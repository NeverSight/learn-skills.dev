Usa questa abilità prima di eseguire o consigliare qualsiasi comando Docker che elimina, cancella, resetta o altera irreversibilmente lo stato — anche se l'utente dice semplicemente di “pulire”, “svuotare la cache”, “ricominciare da capo”, “cancellare tutto”, “annientarlo”, “reset”, “forzare la rimozione” o “smontare” le risorse Docker. Copre le operazioni distruttive generiche della CLI Docker non gestite da un'abilità più specifica — `docker rm`, `docker rm -f`, `docker container prune`, `docker kill`, `docker system prune`, `docker rmi`/`docker image rm`, `docker image prune -a`, `docker network rm`, `docker network prune`, `docker builder prune`, `docker buildx rm`, `docker context rm` e i comandi autonomi (non Compose) `docker volume rm`/`docker volume prune`. Include anche i comandi distruttivi gestiti da altre abilità Docker (Compose, sandbox, Desktop). Regola fondamentale — indica esattamente cosa verrà perso e ottieni una conferma esplicita prima, salvo le pulizie di contenitori di livello 1, limitate e a bassa frizione.

Rispondi sempre nella lingua dell'utente.
