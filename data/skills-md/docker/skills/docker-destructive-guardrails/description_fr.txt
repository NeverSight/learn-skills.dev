Utilisez cette compétence avant d'exécuter ou de recommander toute commande Docker qui supprime, efface, réinitialise ou modifie irréversiblement l'état — même si l'utilisateur se contente de dire « clean up », « clear the cache », « start fresh », « wipe everything », « nuke it », « reset », « force remove » ou « tear down » les ressources Docker. Cela couvre les opérations génériques destructrices de l'interface en ligne de commande Docker qui ne relèvent pas d'une compétence plus spécifique — `docker rm`, `docker rm -f`, `docker container prune`, `docker kill`, `docker system prune`, `docker rmi`/`docker image rm`, `docker image prune -a`, `docker network rm`, `docker network prune`, `docker builder prune`, `docker buildx rm`, `docker context rm`, ainsi que les commandes autonomes (hors Compose) `docker volume rm`/`docker volume prune`. Elle indexe également les commandes destructrices appartenant à d'autres compétences Docker (Compose, sandbox, Desktop). Règle principale — indiquer exactement ce qui sera perdu et obtenir une confirmation explicite au préalable, sauf pour les nettoyages de conteneur de Niveau 1, ciblés et à faible friction.  

Veuillez toujours répondre dans la langue de l'utilisateur.
