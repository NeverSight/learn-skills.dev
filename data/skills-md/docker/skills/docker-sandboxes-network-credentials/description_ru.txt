Используйте эту функцию при настройке того, к чему может обращаться контейнер Docker Sandboxes (`sbx`) в сети, или какие учётные данные он использует для аутентификации, даже если пользователь просто говорит, что хочет «разрешить агенту вызывать внутренний API», «заблокировать весь сетевой доступ», «дать агенту токен GitHub» или «использовать образ из частного реестра для песочницы». Охватывает команды `sbx policy init/allow/deny/ls/inspect/log/check/rm network` (глобальные и отдельные правила исходящего трафика для каждой песочницы, приоритет «отклонить» над «разрешить») и `sbx secret set/set-custom/ls/rm/import` (секреты сервисов, динамические секреты через --ref/--command и учётные данные для вытягивания из реестра с их областью действия — только запросы к хосту по умолчанию).
