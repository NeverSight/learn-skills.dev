Utilisez cette compétence lors de la configuration de ce qu’un bac à sable Docker Sandboxes (`sbx`) peut atteindre sur le réseau ou avec quelles informations d’identification il s’authenticate, même si l’utilisateur se contente de dire qu’il veut « laisser l’agent appeler une API interne », « bloquer tout accès réseau », « donner à l’agent un jeton GitHub » ou « utiliser une image de registre privé pour un bac à sable ». Couvre `sbx policy init/allow/deny/ls/inspect/log/check/rm network` (règles de sortie globales et par bac à sable, priorité du refus sur l’autorisation) et `sbx secret set/set-custom/ls/rm/import` (secrets de service, secrets dynamiques via --ref/--command, et identifiants de tirage de registre avec leur portée d’injection host-pulls-only-by-default).

Veuillez toujours répondre dans la langue de l’utilisateur.
