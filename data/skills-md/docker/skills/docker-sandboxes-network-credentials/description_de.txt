Verwenden Sie diese Fähigkeit, wenn Sie konfigurieren, worauf ein Docker Sandboxes (`sbx`) Sandbox im Netzwerk zugreifen kann oder mit welchen Anmeldeinformationen sie authentifiziert wird, selbst wenn der Nutzer nur sagt, er wolle „dem Agenten erlauben, eine interne API aufzurufen“, „den gesamten Netzwerkzugriff blockieren“, „dem Agenten ein GitHub‑Token geben“ oder „ein privates Registry‑Image für eine Sandbox verwenden“. Deckt `sbx policy init/allow/deny/ls/inspect/log/check/rm network` ab (globale und sandbox‑spezifische Egress‑Regeln, Vorrang von „deny“ vor „allow“) und `sbx secret set/set‑custom/ls/rm/import` (Service‑Secrets, dynamische Secrets via --ref/--command sowie Registry‑Pull‑Anmeldeinformationen mit ihrem standardmäßigen „nur‑Host‑Pulls“‑Injektionsbereich).
