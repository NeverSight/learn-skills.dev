Utilisez cette compétence lors de la création, de l’exécution, de la reconnexion, de la liste, de l’arrêt ou de la suppression de Docker Sandboxes (l’outil CLI autonome `sbx` qui fait tourner des agents de codage IA dans des micro‑VM isolées), même si l’utilisateur se contente de dire qu’il veut « exécuter Claude dans un sandbox », « isoler un agent de mon dépôt », « donner à un agent son propre clone git » ou « nettoyer les anciens sandboxes ». Cela couvre `sbx run`/`sbx create` (y compris les agents intégrés Claude, Codex, Cursor, Devin, Docker‑agent, Gemini, Opencode, Shell), le montage du répertoire de travail vs l’isolation `--clone`, les espaces de travail supplémentaires en lecture seule, la reconnexion via `--name`, `sbx ls`/`stop`/`rm`/`prune`, `sbx exec`, `sbx cp` et `sbx ports`.

Veuillez toujours répondre dans la langue de l’utilisateur.
