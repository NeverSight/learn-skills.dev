Utilisez cette compétence lors de la création, de l’exécution, du rattachement, de la liste, de l’arrêt ou de la suppression des Docker Sandboxes (l’outil en ligne de commande autonome `sbx` qui exécute des agents de codage IA dans des microVM isolées), même si l’utilisateur se contente de dire qu’il veut « exécuter Claude dans un sandbox », « isoler un agent de mon dépôt », « donner à un agent son propre clone git » ou « nettoyer les anciens sandboxes ». Cela couvre `sbx run`/`sbx create` (y compris les agents intégrés Claude, Codex, Cursor, Devin, Docker-agent, Gemini, Opencode, Shell), le montage bind du workspace versus l’isolation `--clone`, les espaces de travail supplémentaires en lecture seule, le rattachement via `--name`, `sbx ls`/`stop`/`rm`/`prune`, `sbx exec`, `sbx cp` et `sbx ports`.
