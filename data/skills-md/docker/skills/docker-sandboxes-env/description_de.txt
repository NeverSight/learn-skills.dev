Verwende diese Fähigkeit beim Erstellen, Planen oder Ausführen einer deklarativen `sbxenv.yaml`‑Datei für Docker‑Sandboxes (`sbx env create/run/plan/exec/rm`), selbst wenn der Benutzer nur sagt, er möchte „eine Sandbox‑Konfiguration einchecken“, „die Einarbeitung für eine Sandbox reproduzierbar machen“, „ein Setup‑Skript ausführen, bevor der Agent startet“ oder „Argumente für eine gemeinsame Sandbox‑Umgebung definieren“. Deckt das sbxenv.yaml‑Schema ab (schemaVersion, agent, kits, workspace/additionalWorkspaces, args, env, secrets, registries, bindings, mcp, ports, sandboxOptions), Host‑`lifecycle:`‑Befehle (initialize/postCreate/preRemove) und deren Genehmigungs‑Plan‑Modell, das Zusammenführen mehrerer Dateien (`-f`‑Style Deep‑Merge und die benutzer‑Level‑`.sbxenv.yaml`‑Basisschicht) sowie den Schreibschutz von Dateien (`sandboxOptions.writableEnvFiles`).
