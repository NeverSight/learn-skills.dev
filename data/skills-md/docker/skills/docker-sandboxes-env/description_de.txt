Verwende diese Fähigkeit beim Erstellen, Planen oder Ausführen einer deklarativen `sbxenv.yaml`‑Datei für Docker Sandboxes (`sbx env create/run/plan/exec/rm`), selbst wenn der Benutzer nur sagt, er möchte „eine Sandbox‑Konfiguration einchecken“, „das Onboarding für eine Sandbox reproduzierbar machen“, „ein Setup‑Skript ausführen, bevor der Agent startet“ oder „Argumente für eine geteilte Sandbox‑Umgebung definieren“. Deckt das sbxenv.yaml‑Schema (schemaVersion, agent, kits, workspace/additionalWorkspaces, args, env, secrets, registries, bindings, mcp, ports, sandboxOptions), die Host‑`lifecycle:`‑Befehle (initialize/postCreate/preRemove) und ihr Genehmigungs‑Plan‑Modell, das Zusammenführen mehrerer Dateien (`-f`‑Style Deep‑Merge und die benutzer‑Ebene `.sbxenv.yaml`‑Basisschicht) sowie den Schreibschutz von Dateien (`sandboxOptions.writableEnvFiles`).
