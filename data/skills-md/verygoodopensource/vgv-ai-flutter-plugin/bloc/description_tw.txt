在 Flutter/Dart 中使用 Bloc 進行狀態管理的最佳實踐，涵蓋 Cubit 與 Bloc 的比較、事件與狀態的命名、使用 Equatable 的密封類、以及 Page/View 的分離搭配 BlocProvider、BlocBuilder、BlocListener、BlocSelector。當撰寫、修改或審查使用 package:bloc、package:flutter_bloc 或 package:bloc_test 的程式碼時請遵循此規範。也適用於任何擴充自 Bloc 或 Cubit 的類別之測試，包括「為此 bloc 寫單元測試」、「測試我的 cubit」、「為 LoginBloc 添加測試」、對 bloc 依賴的 repository 進行 mock，以及斷言事件所發出的狀態。Bloc 與 Cubit 的測試必須使用 package:bloc_test 中的 blocTest() 搭配 package:mocktail，當被測試類別是 Bloc 或 Cubit 時，請優先使用此方式而非其他測試技巧。若有請求違背上述規則的情況，例如將一個 bloc 注入另一個 bloc 以讀取其狀態、在 widget 或 build 方法中直接呼叫 repository，或為需要事件轉換器（如 debounce）的功能保留 Cubit，也請遵循此規範。
