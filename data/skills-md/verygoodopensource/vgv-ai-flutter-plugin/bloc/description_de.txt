Best Practices für die Bloc‑Zustandsverwaltung in Flutter/Dart, die Cubit vs. Bloc, die Benennung von Events und States, versiegelte Klassen mit Equatable, die Aufteilung von Page/View mit BlocProvider, BlocBuilder, BlocListener und BlocSelector abdecken. Verwenden Sie dies, wenn Sie Code schreiben, ändern oder überprüfen, der package:bloc, package:flutter_bloc oder package:bloc_test verwendet. Außerdem verwenden Sie es für jeden Test einer Klasse, die Bloc oder Cubit erweitert, einschließlich „Schreibe die Unit‑Tests für diesen Bloc“, „Teste meinen Cubit“, „Füge Tests für LoginBloc hinzu“, das Mocken eines Repositories, von dem ein Bloc abhängt, und das Prüfen der Zustände, die ein Event ausgibt. Bloc‑ und Cubit‑Tests müssen blocTest() aus package:bloc_test zusammen mit package:mocktail verwenden, daher sollte dies dem allgemeinen Test‑Skill vorgezogen werden, sobald die zu testende Klasse ein Bloc oder Cubit ist. Verwenden Sie es ebenfalls, wenn eine Anforderung diesen Regeln widerspricht, z. B. das Injizieren eines Blochs in einen anderen, um dessen Zustand zu lesen, das Aufrufen eines Repositories aus einem Widget oder einer build‑Methode, oder das Beibehalten eines Cubits für ein Feature, das einen Event‑Transformer wie Debounce benötigt.
