Bonnes pratiques pour la gestion d'état Bloc dans Flutter/Dart, couvrant Cubit vs Bloc, la nomination des événements et des états, les classes scellées avec Equatable, la séparation Page/Vue avec BlocProvider, BlocBuilder, BlocListener et BlocSelector. Utilisez‑les lors de l’écriture, la modification ou la révision de code qui utilise package:bloc, package:flutter_bloc ou package:bloc_test. Utilisez‑les également pour tout test d’une classe qui étend Bloc ou Cubit, y compris « écrire les tests unitaires pour ce bloc », « tester mon cubit », « ajouter des tests pour LoginBloc », la simulation d’un dépôt dont dépend un bloc, et l’affirmation des états qu’un événement émet. Les tests Bloc et Cubit doivent utiliser blocTest() du package:bloc_test avec package:mocktail, il faut donc privilégier cela plutôt que la compétence de test lorsqu’une classe sous test est un Bloc ou un Cubit. Utilisez‑les également lorsqu’une demande contrevient à ces règles, comme injecter un bloc dans un autre pour lire son état, appeler un dépôt depuis un widget ou une méthode build, ou conserver un Cubit pour une fonctionnalité qui nécessite un transformateur d’événement tel que le debounce.
