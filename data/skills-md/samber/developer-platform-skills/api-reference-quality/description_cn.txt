在端点层面对已发布的 API 参考文档进行审计，与规范保持一致——确保每个操作、参数、响应码和错误都有文档说明，提供请求/响应示例，各语言代码片段保持统一，试用功能可用——并建立防止文档漂移的唯一真相入口（基于规范的生成、OpenAPI lint、契约测试、CI 中的代码片段一致性）。每当用户提到 API 参考文档、OpenAPI 文档完整性、未记录的端点或错误码、陈旧或漂移的文档、或文档 CI 门禁时使用——即使他们没有说“参考质量”。仅限端点层面的参考。不要用于门户信息架构和入职引导——改用 samber/developer-platform-skills@developer-portal-design。
