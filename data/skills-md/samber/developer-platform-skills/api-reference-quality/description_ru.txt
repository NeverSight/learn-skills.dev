Аудируйте опубликованную справку API на уровне эндпоинтов относительно её спецификации – каждый метод, параметр, код ответа и ошибка документированы, присутствуют примеры запросов/ответов, сниппеты кода для каждого языка находятся в паритете, функции «try‑it» работают – и внедрите механизмы контроля истинного источника, которые останавливают дрейф справки (генерация по спецификации, линтинг OpenAPI, контрактные тесты, паритет сниппетов в CI). Используйте это каждый раз, когда пользователь упоминает документацию справки API, полноту документов OpenAPI, недокументированные эндпоинты или коды ошибок, устаревшие или дрейфующие документы, или CI‑ворота для документации – даже если они никогда не говорят «качество справки». Только справка на уровне эндпоинтов. НЕ используйте для IA портала и онбординга – используйте samber/developer-platform-skills@developer-portal-design вместо этого.
