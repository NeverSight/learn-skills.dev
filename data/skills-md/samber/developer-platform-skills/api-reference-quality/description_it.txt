Auditare un riferimento API pubblicato a livello di endpoint rispetto alla specifica di superficie: ogni operazione, parametro, codice di risposta ed errore documentati, esempi di richiesta/risposta presenti, snippet di codice per linguaggio in parità, funzionalità "try‑it" operative – e installare i meccanismi di verità unica che fermano la deriva del riferimento (generazione guidata dalla specifica, lint OpenAPI, test contrattuali, parità degli snippet in CI). Utilizzare ogni volta che l'utente menziona documenti di riferimento API, completezza della documentazione OpenAPI, endpoint o codici di errore non documentati, documentazione obsoleta o in deriva, o gate CI per la documentazione – anche se non menzionano esplicitamente "qualità del riferimento". Riferimento solo a livello di endpoint. NON utilizzare per l'IA del portale e l'onboarding – utilizzare invece samber/developer-platform-skills@developer-portal-design.
