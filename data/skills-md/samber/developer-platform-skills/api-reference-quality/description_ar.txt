قم بتدقيق مرجع API المنشور على مستوى النقطة النهاية مقارنةً بسطح المواصفات — يجب توثيق كل عملية، ومعامل، ورمز استجابة، وخطأ، وتوفير أمثلة الطلب/الاستجابة، وتوافر مقتطفات الشيفرة لكل لغة بتوافق، وعمل ميزات “جرّب‑ذلك” (try‑it) — ثم تثبيت بوابات المصدر الوحيد للحق التي توقف انحراف المرجع (التوليد المستند إلى المواصفات، فحص OpenAPI، اختبارات العقود، توافق المقتطفات في CI). استخدم ذلك كلما ذكر المستخدم وثائق مرجع API، اكتمال وثائق OpenAPI، نقاط النهاية غير الموثقة أو رموز الأخطاء غير الموثقة، وثائق قديمة أو متحركة، أو بوابات CI للوثائق — حتى وإن لم يذكر مصطلح “جودة المرجع”. يجب أن يكون المرجع على مستوى النقطة النهاية فقط. لا تُستخدم لهذا التصميم المعلوماتي للبوابة وإجراءات الانضمام — استخدم samber/developer‑platform‑skills@developer‑portal‑design بدلاً من ذلك.
