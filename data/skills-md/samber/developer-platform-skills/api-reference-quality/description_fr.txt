Auditez une référence d’API publiée au niveau des points de terminaison par rapport à sa surface de spécification – chaque opération, paramètre, code de réponse et erreur documentés, exemples de requête/réponse présents, extraits de code par langage en parité, fonctionnalités try‑it fonctionnelles – et installez les garde‑fous de source de vérité qui arrêtent la dérive de la référence (génération guidée par la spécification, lint OpenAPI, tests de contrat, parité des extraits dans le CI). Utilisez‑le chaque fois que l’utilisateur mentionne la documentation de référence d’API, la complétude des docs OpenAPI, les points de terminaison ou codes d’erreur non documentés, les docs obsolètes ou dérivants, ou les garde‑fous CI de docs – même s’il ne parle jamais de « qualité de référence ».
