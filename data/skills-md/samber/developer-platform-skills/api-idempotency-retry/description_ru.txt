Разработайте поддержку idempotency-key и рекомендации по повторным запросам клиента для публичного API, чтобы интеграторы могли безопасно выполнять повторные попытки — вывод ключа и ограничение по вызывающему, TTL хранилища и окна повторов, атомарные механизмы захвата (уникальное ограничение БД, блокировка строк SERIALIZABLE, условные записи), отклонение запросов с несоответствием полезной нагрузки, обработка дубликатов в полёте, экспоненциальный backoff с jitter, бюджеты повторных попыток, распространение тайм‑аутов и значения по умолчанию повторов в SDK. Используйте, когда пользователь упоминает заголовок Idempotency-Key, дублирующие или двойные запросы, безопасные повторения POST, backoff или jitter — даже если он не использует слово «идемпотентность». НЕ используйте для того, что сигнализирует ответ об ошибке (samber/developer‑platform‑skills@api-error-design) или повторные попытки доставки веб‑хуков (samber/developer‑platform‑skills@webhook-platform-design).
