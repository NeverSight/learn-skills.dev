Assunzione da parte del datore di lavoro per ruoli di developer‑platform – Product Manager API, Ingegnere/Architetto di piattaforma, Ingegnere Partner/Integrazione. Prima disambigua “ingegnere di piattaforma”, poiché il termine indica prevalentemente le piattaforme interne per sviluppatori in altri contesti dell’industria. Calibra il punteggio in base all’archetipo aziendale (infra/API‑first, API pubblica aggiuntiva, ecosistema partner enterprise), segnala un modello di collasso di ambito distinto dalla tassonomia gatekeeper/trappola di DevRel, utilizza fonti da apidays, non dal pubblico interno‑IDP di PlatformCon, costruisce il loop dalla suddivisione interviste tra design API e design di sistema, e confronta la retribuzione con la scala generale di ingegneria/PM invece di un titolo di piattaforma su misura. Usa quando l’utente chiede come assumere un ingegnere di piattaforma, un product manager API o un ingegnere partner/integrazione, scrivere un annuncio o progettare un loop. NON utilizzare per la preparazione del candidato (samber/developer‑platform‑skills@developer‑platform‑career) o per assunzioni DevRel (samber/developer‑relations‑skills@devrel‑hiring).
