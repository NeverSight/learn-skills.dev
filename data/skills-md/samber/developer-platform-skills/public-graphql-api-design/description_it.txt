Progetta un'API GraphQL pubblica per sviluppatori di terze parti - il gate GraphQL-o-no, convenzioni dello schema (naming, nullabilità, interfaccia Node, tipi di input/payload), paginazione Relay cursor-connection, tipi di risultato di errore union/interfaccia, limiti di profondità e complessità come decisioni di progettazione, il confine di fiducia della federazione (solo il router è mai pubblico), e una politica di query persistenti che consente solo il traffico di prima parte. Usa ogni volta che l'utente menziona GraphQL, uno schema pubblico, connessioni Relay, limiti di profondità delle query, query persistenti, federazione, o GraphQL vs REST - anche se non dicono mai "progettazione API GraphQL". Solo livello di progettazione. NON usare per una revisione della superficie REST - usa invece samber/developer-platform-skills@public-api-design-review. Rispondi sempre nella lingua dell'utente.
