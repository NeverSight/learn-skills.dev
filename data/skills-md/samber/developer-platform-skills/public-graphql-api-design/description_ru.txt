Разработайте публичный GraphQL API для сторонних разработчиков — шлюз GraphQL‑or‑not, соглашения о схеме (наименования, допускаемость null, интерфейс Node, типы ввода/полезной нагрузки), пагинацию Relay cursor‑connection, типы результатов ошибок с объединениями/интерфейсами, ограничения глубины и сложности как решения по дизайну, границу доверия федерации (только роутер всегда публичный) и политику persisted‑query, разрешающую только трафик первой стороны. Используйте каждый раз, когда пользователь упоминает GraphQL, публичную схему, соединения Relay, ограничения глубины запросов, persisted‑queries, федерацию или сравнение GraphQL и REST — даже если они никогда не говорят «дизайн GraphQL API». Только слой дизайна. НЕ используйте для обзора REST‑поверхности — вместо этого используйте samber/developer‑platform‑skills@public‑api‑design‑review.
