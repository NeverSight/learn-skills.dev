為 API 定義版本化與棄用政策——版本方案選擇（URI 路徑、標頭、基於日期的帳號綁定，或刻意不使用版本），書面的破壞性變更定義，依受眾的棄用通知窗口，日落溝通（RFC 9745 棄用與 RFC 8594 日落標頭），在日落日期的執行方式（逐步前移或硬性截止），以及破壞性變更治理，將 REST 的版本與日落以及 GraphQL 的持續架構演進視為獨立政策。每當使用者提及 API 版本化、/v2、破壞性變更、棄用、日落日期或遷移窗口時，即使用此政策——即使他們未明言「版本化政策」。客戶端 SDK 的版本化採用純粹的 SemVer，屬於 samber/developer-platform-skills@sdk-portfolio-strategy。
