API のバージョニングおよび廃止ポリシーを定義する―バージョン方式の選択（URI パス、ヘッダー、日付ベースのアカウント固定、または意図的な無バージョン化）、書面による破壊的変更の定義、対象者別の廃止通知ウィンドウ、サンセットコミュニケーション（RFC 9745 Deprecation と RFC 8594 Sunset ヘッダー）、サンセット日での施行（フォールフォワード方式かハードカットオフか）、および破壊的変更のガバナンス。REST のバージョン管理とサンセット、GraphQL の継続的スキーマ進化は別々のポリシーとして扱う。ユーザーが API バージョニング、/v2、破壊的変更、廃止、サンセット日、または移行ウィンドウに言及した際は常に使用する—「バージョニングポリシー」と明示されなくても構わない。クライアント SDK のバージョニングは単純な SemVer とし、samber/developer-platform-skills@sdk-portfolio-strategy に属する。
