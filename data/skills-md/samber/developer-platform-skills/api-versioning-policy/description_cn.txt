定义 API 的版本控制和废弃政策——版本方案选择（URI 路径、请求头、基于日期的账户绑定，或故意不使用版本）、书面的破坏性更改定义、面向不同受众的废弃通知窗口、日落通信（RFC 9745 废弃和 RFC 8594 日落头部）、在日落日期的执行方式（向前迁移 vs 硬性截止），以及破坏性更改治理，其中 REST 的版本与日落以及 GraphQL 的持续模式演进被视为独立的政策。每当用户提及 API 版本控制、/v2、破坏性更改、废弃、日落日期或迁移窗口时都使用——即使他们从未说“版本控制政策”。客户端 SDK 的版本采用普通的 SemVer，归属于 samber/developer-platform-skills@sdk-portfolio-strategy。
