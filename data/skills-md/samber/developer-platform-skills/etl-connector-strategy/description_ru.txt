Планировать присутствие SaaS‑поставщика в качестве исходного коннектора на сторонних платформах ETL/ELT — проверка спроса до начала разработки, выбор платформы, где работают стэки данных клиентов, меню путей построения (список, управляемый платформой; коннектор SDK, поддерживаемый поставщиком; пользовательский open‑source tap), ранжированных по тому, кто несёт налог за обслуживание, аудит готовности к извлечению API продукта, честная оценка CDC (источники API поставляют псевдо‑CDC, а не лог‑базированный), цели сертификации и финансируемый план поддержки. Используйте каждый раз, когда пользователь упоминает каталог ETL или ELT, источник‑коннектор, интеграцию data‑pipeline или добавление CDC — даже если они никогда не говорят «стратегия коннектора». НЕ используйте для собственного входящего marketplace‑а поставщика — используйте samber/developer-platform-skills@connector-marketplace-strategy вместо этого.
