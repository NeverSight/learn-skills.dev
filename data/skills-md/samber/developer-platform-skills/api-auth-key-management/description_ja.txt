プラットフォームが自社のAPI利用者に対して提供するAPIキー認証インターフェースを設計する—プレフィックス+チェックサムの形式、ハッシュ化（復元不可）と暗号化（復元可能）保存の選択、ゼロダウンタイムでのローテーション（デュアルキー重複使用）、最小権限のスコーピング、個人・組織・サービスアカウント別の所有権、セルフサービスキー ダッシュボードの動作、そしてSOC 2／PCI‑DSS 4.0 のライフサイクルガバナンス。ユーザーがAPIキー、シークレットキー、キー プレフィックス、キー ローテーション、キー スコーピング、従業員退職後のキー失効について言及した際は必ず使用する—たとえ「APIキー管理」と明言しなくても構わない。提供側のみを対象とし、他ベンダーのAPIを利用するケースは除く。OAuth 認可サーバーの設計には使用しないでください—代わりに samber/developer-platform-skills@oauth2-provider-design を使用してください。
