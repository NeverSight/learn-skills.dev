Разработайте поверхность аутентификации с помощью API‑ключей, которую платформа предоставляет своим собственным потребителям API — формат ключа с префиксом и контрольной суммой, хранение в виде хеша (необратимого) или шифрования (обратимого), ротацию без простоя с наложением двух ключей, ограничение прав доступа по принципу наименьших привилегий, владение ключом индивидуально, для организации или сервисного аккаунта, поведение панели управления ключами в режиме самообслуживания, а также управление жизненным циклом в соответствии с SOC 2 / PCI‑DSS 4.0. Применять каждый раз, когда пользователь упоминает API‑ключи, секретные ключи, префиксы ключей, ротацию ключей, область применения ключей или отзыв ключей после увольнения сотрудника — даже если он явно не говорит «управление API‑ключами». Только со стороны поставщика, без использования API другого вендора. НЕ использовать для проектирования OAuth‑сервера авторизации — вместо этого использовать samber/developer-platform-skills@oauth2-provider-design.
