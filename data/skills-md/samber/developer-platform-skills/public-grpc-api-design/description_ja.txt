外部開発者向けにパブリックな gRPC インターフェースを設計する — gRPC をいつ使用すべきかのゲート（多くのプラットフォームは gRPC を内部に留め、REST やトランスコードされた JSON を公開している）、AIP の proto パッケージとバージョニング規則、buf の破壊的変更ゲートとその google.api.http の盲点、デフォルトで unary とするストリーミングの判断、google.rpc.Status エラーモデルとその HTTP マッピングの罠、トランスコーディングとゲートウェイアーキテクチャ（Connect‑RPC、grpc‑gateway、Envoy）、および外部認証と TLS。ユーザーが gRPC、protobuf または .proto ファイル、buf、Connect‑RPC、grpc‑gateway、あるいはパブリックエッジでの gRPC‑JSON トランスコーディングに言及した場合は必ず使用する — 「gRPC API 設計」と言及がなくても構いません。実装層ではなく設計層のみを対象とし、言語固有のサーバ実装は含めない。
