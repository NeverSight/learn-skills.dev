設計公共 API 向其使用者發布的速率限制政策——依據不同範式的計量模型（REST 請求計數 vs GraphQL 成本點）、層級與配額對突發數值、多租戶公平性、速率限制標頭（傳統 X-RateLimit-* 與 IETF RateLimit 欄位）、429 及 Retry-After 行為、企業與合作夥伴覆寫，以及變更通知規則。每當使用者提及速率限制、配額、節流層級、429 回應、噪音鄰居或提升限制的請求時，都應使用此政策——即使他們未明確說出「速率限制政策」。僅針對政策層面，不涉及閘道配置。請勿將其用於 429 錯誤回應結構——應使用 samber/developer-platform-skills@api-error-design。
