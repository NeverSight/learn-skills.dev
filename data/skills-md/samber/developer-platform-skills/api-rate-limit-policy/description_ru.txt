Разработайте политику ограничения скорости, которую публичный API публикует для своих потребителей — модель измерения в зависимости от парадигмы (подсчёт запросов REST vs баллы стоимости GraphQL), уровни и числа квот vs всплесков, справедливость в многопользовательской среде, заголовки ограничения скорости (устаревшие X-RateLimit-* vs поля IETF RateLimit), поведение при 429 и Retry-After, переопределения для предприятий и партнёров, а также правила уведомления об изменениях. Применяйте её каждый раз, когда пользователь упоминает ограничения скорости, квоты, уровни дросселирования, ответы 429, «шумных соседей» или запросы увеличения лимита — даже если они явно не используют термин «policy ограничения скорости». Только слой политики, без конфигураций шлюза. Не используйте её для оболочки ошибки 429 — вместо этого используйте samber/developer-platform-skills@api-error-design.
