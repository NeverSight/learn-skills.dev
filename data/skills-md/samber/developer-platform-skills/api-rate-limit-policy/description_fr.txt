Concevez la politique de limitation de débit qu’une API publique publie pour ses consommateurs - le modèle de comptabilisation selon le paradigme (comptage des requêtes REST vs points de coût GraphQL), les niveaux et les chiffres quota‑vs‑rafale, l’équité multi‑locataire, les en‑têtes de limitation de débit (X‑RateLimit‑* hérité vs champs RateLimit de l’IETF), le comportement 429 et Retry‑After, les dérogations pour les entreprises et les partenaires, ainsi que les règles de notification de changement. Utilisez chaque fois que l’utilisateur mentionne les limites de débit, les quotas, les niveaux de limitation, les réponses 429, les voisins bruyants ou les demandes d’augmentation de limite – même s’il ne dit jamais « politique de limitation de débit ». Couche de politique uniquement, pas de configuration de passerelle. NE PAS utiliser pour l’enveloppe d’erreur 429 – utilisez plutôt samber/developer-platform-skills@api-error-design.

Veuillez toujours répondre dans la langue de l’utilisateur.
