Определите портфолио языковых SDK публичного API — какие языки получат официальные SDK и в каком порядке, модель сборки: генерируемая против ручной, уровни официальной и сообществной поддержки с этапом продвижения, прекращение поддержки и окончание жизни SDK, а также отделение семантического версионирования SDK от версии API и графика релизов. Используйте это каждый раз, когда пользователь упоминает клиентские библиотеки, SDK, какие языки поддерживать в первую очередь, генератор SDK (Stainless, Fern, OpenAPI Generator), SDK сообществ или вывод SDK из эксплуатации — даже если они никогда не говорят «портфолио SDK». Стратегия портфеля только, а не эргономика отдельного SDK или публикация в реестре. НЕ используйте для решения, предлагать ли SDK как поверхность взаимодействия — вместо этого используйте samber/developer-platform-skills@api-integration-surface-strategy.

Всегда отвечайте на языке пользователя.
