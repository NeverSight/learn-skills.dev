صمم سطح الأخطاء لواجهة برمجة تطبيقات عامة بحيث يتمكن المدمجون من إصلاح الأخطاء بأنفسهم – تصنيف أخطاء قابل للقراءة آليًا (كتالوج مسطح، رمز/رمز فرعي، نطاق/سبب على طريقة Google)، غلاف تفاصيل المشكلة RFC 9457 مع أعضاء امتدادية، رسائل خطأ قابلة للتنفيذ، إشارة إلى إمكانية الإعادة (علم قابل للإعادة، Retry‑After)، وتوثيق أخطاء لكل نقطة نهاية مع تتبع Request‑ID. استخدم ذلك كلما ذكر المستخدم رموز أخطاء API أو تصنيف أخطاء أو RFC 9457 أو application/problem+json أو أجسام استجابة 4xx/5xx أو رسائل خطأ API مربكة – حتى وإن لم يقل "تصميم الأخطاء". لا تستخدمه لآليات إعادة المحاولة على جانب العميل – استخدم samber/developer-platform-skills@api-idempotency-retry – ولا للاتصال بالحوادث وصفحات الحالة – استخدم samber/developer-platform-skills@api-status-communication بدلاً من ذلك.
