設計公共 API 的錯誤介面，使整合者能自行修正——包括機器可讀的錯誤代碼分類（平面目錄、代碼/子代碼、Google 風格的領域/原因）、RFC 9457 problem-details 包裝（含擴充成員）、可執行的錯誤訊息、可重試性訊號（retryable 標誌、Retry-After），以及每個端點的錯誤文件與 request-ID 追蹤。每當使用者提到 API 錯誤代碼、錯誤分類、RFC 9457、application/problem+json、4xx/5xx 回應主體或令人困惑的 API 錯誤訊息時，都使用此設計——即使他們從未說過「錯誤設計」。不要用於客戶端重試機制——請使用 samber/developer-platform-skills@api-idempotency-retry；也不要用於事故與狀態頁面溝通——請使用 samber/developer-platform-skills@api-status-communication。
