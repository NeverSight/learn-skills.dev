Auditar una API REST pública existente o propuesta como una revisión de diseño basada en listas de verificación: nombres de recursos y URI, corrección de métodos HTTP y códigos de estado, consistencia en la nomenclatura de campos, elección del patrón de paginación, convenciones de filtrado/ordenación/selección de campos, un único sobre de error coherente y el riesgo de compatibilidad retroactiva según la Ley de Hyrum; cada hallazgo clasificado como Debe cambiar o Mejora según una regla citada, más el programa de revisión permanente (audiencia, disparadores de ciclo de vida, autoridad del revisor, linting, federación). Utilizar siempre que el usuario mencione una revisión de diseño de API, consistencia de API REST, nomenclatura de endpoints, estilo de paginación o gobernanza del diseño de API, incluso si nunca dice "revisión de diseño". NO usar para esquemas GraphQL; emplear samber/developer-platform-skills@public-graphql-api-design en su lugar.
