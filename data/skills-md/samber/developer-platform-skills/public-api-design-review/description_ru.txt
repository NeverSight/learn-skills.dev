Аудитировать существующий или предлагаемый публичный REST API как проверку по контрольному списку — названия ресурсов и URI, корректность HTTP‑методов и кодов статуса, согласованность имен полей, выбор паттерна пагинации, соглашения по фильтрации/сортировке/выбору полей, единый консолидированный объект ошибки и риск нарушения совместимости согласно закону Хайрума — каждое обнаружение классифицировать как «Необходимо изменить» или «Улучшение» со ссылкой на правило, плюс постоянная программа ревью (аудитория, триггеры жизненного цикла, полномочия рецензента, линтинг, федерация). Использовать каждый раз, когда пользователь упоминает ревью дизайна API, согласованность REST API, именование эндпоинтов, стиль пагинации или управление дизайном API — даже если он не говорит явно «ревью дизайна». Не применять к схемам GraphQL — использовать вместо этого samber/developer-platform-skills@public-graphql-api-design.
