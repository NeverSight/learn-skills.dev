기존 또는 제안된 공용 REST API 표면을 체크리스트 기반 설계 검토로 감사하십시오 – 리소스 및 URI 명명, HTTP 메서드와 상태 코드의 정확성, 필드 명명 일관성, 페이지네이션 패턴 선택, 필터링/정렬/필드 선택 규칙, 일관된 오류 래퍼, 그리고 Hyrum's Law 역호환성 위험 – 모든 발견을 반드시 변경해야 하는 항목 또는 개선 항목으로 규정된 규칙에 따라 구분하고, 검토 프로그램(대상, 라이프사이클 트리거, 검토자 권한, 린팅, 연합)도 포함합니다. 사용자가 API 설계 검토, REST API 일관성, 엔드포인트 명명, 페이지네이션 스타일, 또는 API 설계 거버넌스를 언급할 때마다 사용하십시오 – 비록 “설계 검토”라고 명시하지 않더라도. GraphQL 스키마에는 사용하지 마십시오 – 대신 samber/developer-platform-skills@public-graphql-api-design를 사용하십시오.
