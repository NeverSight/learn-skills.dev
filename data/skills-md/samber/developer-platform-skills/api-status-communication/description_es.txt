Diseña cómo una plataforma API comunica el estado y los incidentes a los consumidores externos: modelado de página de estado (el ciclo de vida del incidente de cuatro etapas, semántica de componentes degradados/parciales/críticos, granularidad de componentes), estado impulsado por monitoreo en lugar de una luz verde manual, canales de extracción y envío, cadencia y plantillas de actualización de incidentes, postmortems públicos para una audiencia de desarrolladores, informes públicos de SLA/SLO y avisos de ventanas de mantenimiento. Utilízalo siempre que el usuario mencione una página de estado, Statuspage, actualizaciones de incidentes, tiempo de actividad o informes de SLA, postmortems o mantenimiento programado, aunque nunca diga “comunicación de estado”. NO lo uses para avisos de depreciación y cambios incompatibles; usa samber/developer-platform-skills@api-versioning-policy en su lugar.
