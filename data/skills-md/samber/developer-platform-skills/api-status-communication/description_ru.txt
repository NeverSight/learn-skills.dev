Разработайте, как платформа API сообщает о статусе и инцидентах внешним потребителям — моделирование страницы статуса (четырёхэтапный жизненный цикл инцидента, семантика деградированных/частичных/критических компонентов, детализация по компонентам), статус, основанный на мониторинге, а не на вручную включаемом зелёном индикаторе, каналы pull и push, частота обновлений инцидентов и шаблоны, публичные постмортемы для аудитории разработчиков, публичная отчётность по SLA/SLO и уведомления о окнах технического обслуживания. Используйте каждый раз, когда пользователь упоминает страницу статуса, Statuspage, обновления инцидентов, время безотказной работы или отчётность по SLA, постмортемы или плановое обслуживание — даже если они не говорят явно «коммуникация статуса». НЕ используйте для уведомлений об устаревании и разрушающих изменениях — используйте samber/developer-platform-skills@api-versioning-policy.
