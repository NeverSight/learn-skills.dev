API 플랫폼이 외부 소비자에게 상태와 인시던트를 전달하는 방식을 설계하십시오 – 상태 페이지 모델링(4단계 인시던트 라이프사이클, 감소/부분/주요 구성 요소 의미, 구성 요소 세분화), 수동으로 초록불을 전환하는 대신 모니터링 기반 상태, 풀 및 푸시 채널, 인시던트 업데이트 주기 및 템플릿, 개발자 대상 공개 포스트모템, 공개 SLA/SLO 보고, 유지보수 창 공지. 사용자는 상태 페이지, Statuspage, 인시던트 업데이트, 가동시간 또는 SLA 보고, 포스트모템, 예정된 유지보수를 언급할 때마다 사용하십시오 – 비록 “상태 커뮤니케이션”이라고 명시하지 않더라도. 폐기 및 중단 변경 공지에는 사용하지 마십시오 – 대신 samber/developer-platform-skills@api-versioning-policy를 사용하십시오.
