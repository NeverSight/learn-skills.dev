Bevor irgendeine Entwicklerplattform‑, Public‑API‑ oder Integrationsarbeit begonnen wird – oder immer dann, wenn keine andere Plattform‑Skill ausgewählt wurde – leite die Aufgabe an die richtige Skill in samber/developer-platform-skills weiter oder sage eindeutig, dass keine passt, und bootstrappe dann oder setze den geteilten Plattform‑Kontext des Projekts fort. Wird bei jedem Start eines API‑ oder Plattformprojekts, bei jeder wiederkehrenden Plattform‑Überprüfung und immer dann ausgelöst, wenn das Routing unklar ist. Verwende es, wann immer der Nutzer einen Entwicklerplattform‑Kickoff, ein neues Public‑API‑Programm, eine Integrations‑Surface‑Roadmap, „welche Plattform‑Skill brauche ich“, „wo fange ich mit unserer Public API an“, Plattform‑Skill‑Routing oder ein wiederkehrendes Plattform‑Check‑In erwähnt – selbst wenn er nie eine Skill nennt oder um ein Routing bittet. Es umfasst das Design von REST, GraphQL und gRPC, Webhooks, SDKs, MCP, OAuth und API‑Keys, Rate‑Limits, Versionierung, Entwicklerportale, Dokumentation, Sandboxes, Marktplätze und Partner‑Strategie, sodass eine mehrdeutige Plattform‑Frage hier zuerst eingeordnet wird. Gibt eine Kurzliste und eine geordnete Skill‑Kette aus, nie das eigentliche Design.

Bitte immer in der Sprache des Nutzers antworten.
