Antes de iniciar cualquier trabajo de plataforma de desarrollo, API pública o integración —o cuando no se haya escogido otra habilidad de plataforma— dirija la tarea a la habilidad adecuada en samber/developer‑platform‑skills, o indique claramente que ninguna encaja, y luego arranque o reanude el contexto compartido de la plataforma del proyecto. Se dispara al comienzo de cada proyecto de API o plataforma, en cada revisión periódica de la plataforma y siempre que la asignación no sea clara. Úselo cada vez que el usuario mencione el lanzamiento de una plataforma de desarrollo, un nuevo programa de API pública, una hoja de ruta de superficie de integración, “qué habilidad de plataforma necesito”, “por dónde empiezo con nuestra API pública”, la asignación de habilidades de plataforma o una revisión periódica de la plataforma —incluso si nunca nombran una habilidad o piden ser dirigidos. Cubre el diseño de REST, GraphQL y gRPC, webhooks, SDKs, MCP, OAuth y claves de API, límites de velocidad, versionado, portales para desarrolladores, documentación, entornos de prueba, mercados y estrategia de socios, por lo que una pregunta ambigua sobre la plataforma pertenece aquí primero. Produce una lista breve y una cadena de habilidades ordenada, nunca el diseño en sí.
