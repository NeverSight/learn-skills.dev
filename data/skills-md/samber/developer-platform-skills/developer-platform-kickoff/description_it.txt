Prima di avviare qualsiasi lavoro su una piattaforma per sviluppatori, API pubbliche o integrazione – o ogni volta che non sia stata scelta un’altra competenza di piattaforma – indirizza il compito alla competenza corretta in samber/developer-platform-skills, oppure dichiara semplicemente che nessuna è adatta, quindi avvia o riprendi il contesto di piattaforma condiviso del progetto. Si attiva all’inizio di ogni progetto API o piattaforma, a ogni revisione periodica della piattaforma e ogni volta che il routing non è chiaro. Usalo ogni volta che l’utente menziona l’avvio di una piattaforma per sviluppatori, un nuovo programma di API pubbliche, una roadmap di integrazione, “quale competenza di piattaforma mi serve”, “da dove parto con la nostra API pubblica”, il routing delle competenze di piattaforma o un controllo periodico della piattaforma – anche se non nominano mai una competenza o chiedono di essere instradati. Copre la progettazione REST, GraphQL e gRPC, webhook, SDK, MCP, OAuth e chiavi API, limiti di velocità, versionamento, portali per sviluppatori, documentazione, sandbox, marketplace e strategia partner, quindi una domanda ambigua sulla piattaforma appartiene qui per prima. Produce un elenco breve e una catena di competenze ordinata, mai il design stesso.
