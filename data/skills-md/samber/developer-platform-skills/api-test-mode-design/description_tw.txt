設計公共 API 平台的測試/沙箱模式，使外部整合者能在不觸及真實金錢、訊息或資料的情況下進行建置與驗證——包括隔離架構（軟性測試模式切換與硬性獨立複本沙箱）、測試金鑰前綴、魔法測試值、模擬物件與角色、按需測試事件、確定性的時間操控、重置與種子、沙箱配額、濫用控制，以及升級至正式環境的流程。當使用者提及沙箱、測試模式、測試 API 金鑰、魔法或虛擬測試值、模擬 webhook 事件或示範資料時，即使未明確說明「測試模式」亦應套用此規則。此規則不適用於程式碼執行沙箱或單元測試 mock，也不要用於合作夥伴沙箱供應——那應使用 samber/developer-platform-skills@partner-app-onboarding。
