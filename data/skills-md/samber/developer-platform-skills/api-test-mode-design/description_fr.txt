Concevoir le mode test/sandbox d’une plateforme API publique afin que les intégrateurs externes construisent et valident sans toucher à l’argent réel, aux messages ou aux données — architecture d’isolation (commutateur de mode test souple vs sandbox séparé en copie dure), préfixage des clés de test, valeurs magiques de test, objets et personas simulés, événements de test à la demande, manipulation déterministe du temps, réinitialisation et alimentation initiale, quotas du sandbox, contrôles d’abus et passage en production. Utiliser chaque fois que l’utilisateur mentionne un sandbox, un mode test, des clés API de test, des valeurs magiques ou factices de test, des événements webhook simulés ou des données de démonstration — même s’il ne dit jamais « mode test ». Pas de sandboxing d’exécution de code ni de mock de tests unitaires. NE PAS utiliser pour la mise à disposition de sandbox partenaire — utiliser à la place samber/developer-platform-skills@partner-app-onboarding.
