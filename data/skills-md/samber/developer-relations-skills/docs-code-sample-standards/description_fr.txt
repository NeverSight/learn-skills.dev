Définit la politique que chaque exemple de code dans la documentation développeur doit respecter et audite un corpus d’exemples existant par rapport à celle‑ci, en renvoyant une file d’attente de corrections classées. Utilisez‑le chaque fois que l’utilisateur mentionne des exemples de code dans la documentation, des extraits de code, des exemples exécutables, des exemples qui ne compilent plus, des échecs de copier‑coller, des dérives d’extraits après une modification d’API, le test des exemples de documentation en CI, la parité des extraits SDK entre les langages, la responsabilité de la maintenance des exemples, ou qu’il demande pourquoi les exemples de leur documentation ne fonctionnent pas – même s’il se contente de dire que la documentation est cassée. Couvre l’anatomie des exemples, la sécurité du copier‑coller, les niveaux d’exécution, la source unique à partir du code testé et la parité des langages. Pas pour rédiger une page de démarrage rapide — utilisez samber/developer‑relations‑skills@developer‑quickstart‑guide.

Veuillez toujours répondre dans la langue de l’utilisateur.
