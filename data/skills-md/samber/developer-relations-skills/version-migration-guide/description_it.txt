Scrive o revisiona la guida di migrazione per una breaking change – cosa rompe, ordinato per raggio d'azione, con un segnale di rilevamento e codice prima/dopo per ogni voce, una timeline di deprecazione, il confine di copertura del codemod e verifica tramite un upgrade a freddo di un progetto reale. Da utilizzare ogni volta che qualcuno menziona una guida di migrazione, una guida di aggiornamento, una pagina di breaking‑changes, un bump di versione maggiore, “come informiamo gli utenti di v3”, un taglio di versione API, un avviso di deprecazione o sunset, o un codemod o build di compatibilità – anche se dicono solo che stanno rilasciando v2. Copre librerie, SDK, CLI, framework, API ospitate e runbook di schema. Non è per note di rilascio – usa samber/developer‑relations‑skills@changelog‑writing. Rispondi sempre nella lingua dell'utente.
