设计并验证陌生人在开源项目中完成首次合并贡献的路径——包括 CONTRIBUTING 文件、good‑first‑issue 队列、一个即使在冷启动时也能通过测试的 clone‑to‑passing‑tests 命令，以及首次 Pull Request 的审查和认可循环，并依据阻塞加权评分表进行评分。每当有人说“没有人给我的项目贡献代码”“写一份 CONTRIBUTING.md”“我们的 good‑first‑issues 没有人接手”“首次贡献者消失了”“贡献者入职”“首次 Pull Request 体验”或“我们怎样才能获得更多开源贡献者”时就使用——即使他们只是在抱怨一个冷清的仓库。不是 triage 系统设计——请使用 samber/developer‑relations‑skills@oss‑issue‑triage。也不是治理或 CLA 选择。
