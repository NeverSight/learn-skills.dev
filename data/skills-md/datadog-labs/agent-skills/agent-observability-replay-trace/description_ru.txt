Используется, когда разработчик хочет проитерировать ОДИН конкретный трассировочный запрос Agent Observability / LLM Obs, вывод которого ему не понравился — повторно запустить этот запрос против ЛОКАЛЬНОГО кода, увидеть лаконичную разницу между старым и новым выводом и выполнять цикл (изменить код → воспроизвести → сравнить), пока не будет удовлетворён результат. Вызывается как /agent-observability-replay-trace <trace-id> [изменения для теста]. Сигналы: «повторить эту трассировку», «итерировать по трассировке», «вывод этой трассировки неверен, исправьте и запустите снова», «перезапустить трассировку <id> с <изменением>», вставка идентификатора трассировки из UI Agent Observability с описанием того, что нужно исправить. Команда получает трассировку через datadog-llmo MCP или pup CLI, редактирует код, заново запускает приложение, чтобы создать НОВУЮ трассировку, и сравнивает две — без локального сервера, без браузера. Поддерживается для агентов, трассируемых с ddtrace / LLM Obs (Python‑первоклассный), с входными данными, сериализуемыми в JSON. Не использовать для: оценённых экспериментов или кнопки «Replay» в браузере (это agent-observability-replay-experiment), создания эксперимента из набора данных/CSV, написания оценщиков, выявления причины неудачных трассировок, а также для RUM/HTTP‑воспроизведения сессий.
