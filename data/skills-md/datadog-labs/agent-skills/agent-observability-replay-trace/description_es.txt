Úsalo cuando un desarrollador quiere iterar sobre UN trazado específico de Agent Observability / LLM Obs cuyo resultado no le gustó: volver a ejecutar ese trazado contra su código LOCAL, ver una diferencia concisa entre la salida anterior y la nueva, y repetir el ciclo (cambiar código → reproducir → diff) hasta estar satisfecho. Se invoca como `/agent-observability-replay-trace <trace-id> [cambios a probar]`. Señales: “reproducir este trazado”; “iterar sobre un trazado”; “la salida de este trazado es incorrecta, corrígela y vuelve a ejecutarla”; “re‑ejecutar trazado <id> con <cambio>”; pegar un ID de trazado desde la UI de Agent Observability con una descripción de lo que se debe arreglar. Obtiene el trazado mediante el MCP datadog‑llmo o la CLI pup, edita el código, vuelve a ejecutar la aplicación para generar un NUEVO trazado y compara los dos — sin servidor local, sin navegador. Para agentes trazados con ddtrace / LLM Obs (Python de primera clase), con entrada serializable en JSON. No lo uses para: experimentos puntuados o el botón “Replay” del navegador (eso es agent‑observability‑replay‑experiment), crear un experimento a partir de un conjunto de datos/CSV, escribir evaluadores, encontrar la causa raíz de trazados fallidos, o la reproducción de sesiones RUM/HTTP.
