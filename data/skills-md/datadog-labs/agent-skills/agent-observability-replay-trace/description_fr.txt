Utilisez lorsque un développeur veut itérer sur UNE trace spécifique d’Observabilité d’Agent / LLM Obs dont la sortie ne lui convient pas — relancer cette trace avec son code LOCAL, voir un diff concis entre l’ancienne et la nouvelle sortie, et boucler (modifier le code → rejouer → diff) jusqu’à satisfaction. Invocé sous la forme /agent-observability-replay-trace <trace-id> [changes to test]. Signaux : « replay this trace », « iterate on a trace », « this trace’s output is wrong, fix it and re‑run », « re‑run trace <id> with <change> » ; coller un ID de trace depuis l’UI d’Observabilité d’Agent avec une description de ce qu’il faut corriger. Il récupère la trace via le datadog‑llmo MCP ou le pup CLI, modifie le code, relance l’application pour émettre une NOUVELLE trace, puis compare les deux — aucun serveur local, aucun navigateur. Pour les agents tracés avec ddtrace / LLM Obs (Python en première classe), avec une entrée sérialisable en JSON. NE PAS utiliser pour : les Expériences notées ou le bouton « Replay » du navigateur (c’est agent‑observability‑replay‑experiment), créer une expérience à partir d’un jeu de données/CSV, écrire des évaluateurs, identifier la cause première de traces échouées, ou le replay de session RUM/HTTP.
