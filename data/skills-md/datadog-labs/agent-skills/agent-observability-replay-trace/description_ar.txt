يُستعمل عندما يرغب المطوّر في تكرار تعديل تتبُّع واحد محدد في مراقبة الوكيل / مراقبة LLM والتي لا تعجبه نتيجتها — بإعادة تشغيل ذلك التتبُّع على الشفرة المحلية، ورؤية فرق مختصر بين الإخراج القديم والجديد، والقيام بالدورة (تغيير الكود → إعادة التشغيل → المقارنة) حتى يرضى. يُستدعى كـ /agent-observability-replay-trace \<trace-id\> [التغييرات للاختبار]. الإشارات: "أعد تشغيل هذا التتبُّع"؛ "تكرار على تتبُّع"؛ "نتيجة هذا التتبُّع خاطئة، أصلحها وأعد تشغيلها"؛ "أعد تشغيل التتبُّع \<id\> مع \<change\>"؛ لصق معرف تتبُّع من واجهة مراقبة الوكيل مع وصف ما يجب إصلاحه. يقوم بجلب التتبُّع عبر datadog-llmo MCP أو pup CLI، يحرّر الشفرة، يعيد تشغيل التطبيق لإصدار تتبُّع جديد، ويقارن بينهما — دون خادم محلي أو متصفح. للوكلاء الذين تم تتبُّعهم باستخدام ddtrace / LLM Obs (Python أولية)، مع إدخال يمكن تسلسله إلى JSON. لا يُستخدم لـ: التجارب المُدرجة أو زر "إعادة التشغيل" في المتصفح (هذا متعلق بـ agent-observability-replay-experiment)، بناء تجربة من مجموعة بيانات/CSV، كتابة المُقَيِّمين، تحديد السبب الجذري للتتبُّعات الفاشلة، أو إعادة تشغيل جلسات RUM/HTTP.
