Verwenden, wenn ein Entwickler einen EINEN bestimmten Agent‑Observability / LLM‑Obs‑Trace erneut bearbeiten möchte, dessen Ausgabe ihm nicht gefällt – den Trace gegen seinen LOKALEN Code erneut ausführen, einen knappen Diff zwischen alter und neuer Ausgabe sehen und solange wiederholen (Code ändern → Replay → Diff), bis er zufrieden ist. Aufgerufen als **/agent-observability-replay-trace <trace-id> [zu testende Änderungen]**. Signale: „diesen Trace erneut ausführen“, „einen Trace iterieren“, „die Ausgabe dieses Traces ist falsch, behebe sie und führe ihn erneut aus“, „Trace <id> mit <Änderung> erneut ausführen“; Einfügen einer Trace‑ID aus der Agent‑Observability‑UI zusammen mit einer Beschreibung, was zu korrigieren ist. Es holt den Trace über das **datadog‑llmo MCP** oder die **pup‑CLI**, bearbeitet den Code, führt die Anwendung erneut aus, um einen NEUEN Trace zu erzeugen, und vergleicht die beiden – kein lokaler Server, kein Browser. Für Agents, die mit **ddtrace / LLM Obs** (Python First‑Class) getraced wurden, mit JSON‑serialisierbarem Eingabe‑Entry. **NICHT verwenden für**: bewertete Experimente oder den Browser‑„Replay“-Button (das ist **agent‑observability‑replay‑experiment**), das Erstellen eines Experiments aus einem Datensatz/CSV, das Schreiben von Evaluatoren, das Ursachenforschen fehlgeschlagener Traces oder RUM/HTTP‑Session‑Replay.
