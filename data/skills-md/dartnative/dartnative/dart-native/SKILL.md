# DartNative — Developer Guide

DartNative lets you write Dart with the Flutter widget API and renders it as
**real native views**: `Text` → `UILabel`/platform text, `ListView` →
`UITableView`/`RecyclerView`, `TextField` → `UITextField`, `AppBar` → a real
navigation bar (Liquid Glass on iOS 26), `BottomNavigationBar` → the native
tab bar. There is no rendering engine and no bridge: Dart drives the views
directly, and layout runs on Yoga (flexbox) with Flutter's sizing rules.

**The compatibility contract, honestly stated:** DartNative is *almost*
Flutter-compatible. Most widgets are identical or near-identical; some are
deliberately different where real native structure demands or enables it;
a few Flutter patterns are absent by design. The per-widget truth is
`docs/widgets.md` in this repo — consult it before assuming an API.

## Toolchain

```sh
dn create my_app     # scaffold a project
cd my_app
dn pub get           # fetches the prebuilt dartnative packages (dartpub.dev)
dn run               # build + launch on a connected device/simulator
```

`dn` is DartNative's CLI (get it at dartpub.dev). All familiar subcommands
work (`run`, `build`, `pub get`, hot reload during `run`). Building and
testing is free; a dartpub.dev subscription is needed to ship to production.

## App startup

```dart
import 'package:dartnative/dartnative.dart';
import 'dartnative_plugin_registrant.dart'; // generated by dn pub get

void main() {
  // MUST be the first line: registers the platform bindings and every
  // dartnative_* plugin's FFI symbols. Missing it = white screen, no crash.
  DartNativePluginRegistrant.registerAll();
  runApp(const MyScreen());
}
```

- Pass the root **screen** to `runApp` directly. Do **not** wrap it in
  `App(home: ...)` — `App` only provides theme/navigator inheritance and
  does not mount `home` natively (white screen). Use `App` only for a
  named-`routes:` map.
- Multi-screen apps register routes once: `registerRoutes({'/detail': (_) =>
  const DetailScreen()})`, then `Navigator.pushNamed(context, '/detail')`.
- The one import is `package:dartnative/dartnative.dart`. Never import
  `package:flutter/...` or `dart:ui` — DartNative ships its own painting
  and geometry types, and `dart:ui` is not part of the runtime. Read the
  device locale with `Platform.localeName` from `dart:io`.

**Why explicit registrations exist at all** — in Flutter the engine does
this invisibly: plugins self-register through GeneratedPluginRegistrant +
method channels, fonts are bundled by the build, and Skia IS the renderer.
DartNative has no engine layer: every capability is Dart talking to native
code over FFI, and FFI symbols must be LOADED before first use. So each
capability is one explicit, cheap registration in main() — and forgetting
one produces a characteristic symptom, never a crash:

| Forgotten | Symptom |
|---|---|
| `DartNativePluginRegistrant.registerAll()` | white screen (no bindings — nothing can render); a missing plugin symbol → that plugin's calls fail |
| `registerSkiaFactories()` | `CanvasSurface`/Skia painting renders nothing |
| `DartNativeFontRegistrant.registerAll()` | custom fonts fall back to system font; icon fonts render `?` |
| `SystemChrome.defaultStyle` | screens inherit device-default chrome (e.g. wrong status-bar icon color on the first frame) |

The full startup anatomy (the playground's main.dart is the canonical
reference):

```dart
void main() {
  DartNativePluginRegistrant.registerAll(); // ALWAYS, first: bindings +
                        // every dartnative_* plugin's FFI symbols. The file
                        // is generated from your pubspec on every dn pub
                        // get — add a plugin, done. No per-plugin setup.
  SystemChrome.defaultStyle = const SystemUiOverlayStyle(...); // app-wide
                        // chrome default; screens override in initState and
                        // the navigator restores this on pop
  registerSkiaFactories();                  // ONLY with dartnative_skia:
                        // enables CanvasSurface / Skia-backed painting
  DartNativeFontRegistrant.registerAll();   // ONLY with custom fonts
                        // (pubspec assets/fonts): registers them with the
                        // platform so fontFamily/IconData resolve (iOS)
  runApp(const HomeScreen());
}
```

Plugin-specific initializers (e.g. `Firebase.initializeApp()`,
`Sqlite.ensureInitialized()`) also live here, after `registerAll()`.

## The catalog, by porting relevance

Statuses from `docs/widgets.md` (the authoritative per-widget reference —
consult it for any param-level question).

### Ports unchanged — use as in Flutter

- **Layout**: `Row`, `Column`, `Flex`, `Expanded`, `Flexible`, `Spacer`,
  `Stack`/`Positioned`, `Padding`, `Container`, `ConstrainedBox`,
  `DecoratedBox`, `Align`/`Center`, `SafeArea`, `AspectRatio`, `Wrap`,
  `FractionallySizedBox`, `IntrinsicWidth`/`IntrinsicHeight`, `FittedBox`,
  `ColoredBox`, `IndexedStack`, `LayoutBuilder`, `Divider`, `Opacity`,
  `Visibility`, `IgnorePointer`/`AbsorbPointer`, `RepaintBoundary`,
  `ClipRRect`, `ClipOval`.
- **Text**: `Text`, `RichText`/`TextSpan`, `TextStyle`, `TextPainter`.
- **Scrolling**: `ListView` (+`.builder`), `SingleChildScrollView`,
  `GridView`, `CustomScrollView` with `SliverList`(+`.builder`),
  `SliverGrid`, `SliverToBoxAdapter`, `SliverPadding`,
  `SliverFillRemaining`, `SliverAppBar`.
- **Images**: `Image.network` (cached), `Image.asset`, `CircleAvatar`.
- **Animation — the full suite**: `AnimationController` (+ both ticker
  mixins), `CurvedAnimation`, `AnimatedBuilder`/`AnimatedWidget`,
  `FadeTransition`, `SlideTransition`, `ScaleTransition`, `SizeTransition`,
  `RotationTransition`, `AnimatedOpacity`, `AnimatedContainer`,
  `AnimatedSwitcher`, `Transform`. One diff: `controller.duration` is
  final — set it in the constructor, or pass `duration:` to
  `animateTo()` / `animateBack()`.
- **Theming**: `ThemeData.light()/.dark()`, `ColorScheme`, `TextTheme`
  (15 slots) — via `App(theme: ...)`. Explicit styles remain the common
  DartNative idiom, but ported `Theme`-based code has a target.
- **Input & focus**: `TextField` (see diffs), `FocusNode`, `Focus`,
  `FocusScope`, `TextEditingController`.
- **Controls**: `Switch`, `Slider`, `CircularProgressIndicator`,
  `LinearProgressIndicator`, `SegmentedControl`, buttons (`Button` with
  variants, `FloatingActionButton`, `BarButtonItem`), `Badge`, native
  menus.
- **State & misc**: `setState`, `ValueNotifier` + `ValueListenableBuilder`,
  `ScrollController`, `GestureDetector` (incl. `HitTestBehavior.translucent`
  — fully supported sibling-forwarding),
  `WidgetsBinding.instance.addPostFrameCallback`,
  `WidgetsBindingObserver` (`didChangeAppLifecycleState`,
  `didChangeMetrics`, `didHaveMemoryPressure`, registered with
  `WidgetsBinding.instance.addObserver`),
  `MediaQuery.of(context)` (`size`, `padding`, `viewInsets.bottom` live
  keyboard height, `devicePixelRatio`, `platformBrightness`,
  `textScaleFactor`), `SystemChrome` (orientations, overlay style,
  `defaultStyle`, status/navigation bar colors), `dartnative_intl` for
  l10n.

Layout parity is engineered: layouts land where Flutter puts them.

### Different on purpose — adopt the DartNative form

**`Scaffold`** — full surface: `appBar`, `body`, `backgroundColor`,
`bottomNavigationBar`, `bottomInputBar` (keyboard-attached bar — chat
inputs go HERE, never in `bottomNavigationBar`), `bottomAccessory` (strip
above the bottom bar; iOS 26 lowers it to the native tab accessory),
`floatingActionButton`,
`extendBody`, `extendBodyBehindAppBar`, `resizeToAvoidBottomInset`
(default true; the body resizes on the system keyboard curve), and
`brightness` — **declare it `Brightness.dark` on any dark-by-colors
screen** or system materials (keyboard, glass, scroll-edge fades) render
light on light-mode devices.

**`AppBar`** — full surface: `leading`, `title`, `actions` (arbitrary
widgets; `BarButtonItem` gives the default-padded action),
`automaticallyImplyLeading`, `showBackTitle`, `backgroundColor`,
`toolbarHeight`, `actionsPadding`, `subtitle`, `largeTitle` +
`largeTitleSize` (medium/large — native large-title collapse on iOS 26,
the M3 collapsing top app bar on Android), `searchBar` (the bar region
becomes the search pill: App Store in-place search on iOS 26, the real M3
search app bar on Android; `title` is skipped when set),
`titleGlassBackground` (default false), `actionsGlassBackground` (default
true — set false for self-decorated action widgets like avatars),
`brightness` (forces the bar's glass tone; iOS 26 only).

**`TextField`** — a real platform field. `InputDecoration` is
intentionally minimal (hint, `border: InputBorder.none`, content padding);
borders/fills come from a wrapping `Container`. Multiline growth via
`minLines`/`maxLines` works.

**`BottomNavigationBar`** — surface: `items`, `currentIndex`, `onTap`,
`iconColor`/`selectedIconColor`, label styles, `indicatorColor`,
`backgroundColor` (ignored on iOS 26 — the glass pill IS the background),
`scrollBehavior` (minimize/hide on scroll — lowers to a real
`UITabBarController` on iOS 26), `onSearchQueryChanged`; items support
`subtitle`, `enabled`, `activeIcon`, and `BottomNavigationBarItem.search()`
(the iOS 26 separated search pill).

**Navigation** — `Navigator.push(context, PageRoute(builder: (_) =>
Screen()))` (push always takes a Route) / `Navigator.pushNamed` (+
`registerRoutes`) / `pop`. `PageRoute(builder:, transition:, duration:,
settings: '/route-name')` with `RouteTransition.slideFromRight` (default) /
`.slideFromBottom` (modal) / `.slideFromLeft` / `.slideFromTop` / `.fade`.
No `PageRouteBuilder`/`transitionsBuilder` — drop custom transition
curves.

**Dialogs / overlays** — `showAlert(context:, title:, message:,
actions:)` → `Future<int>` (tapped index); `showActionSheet`;
`showModalSheet(context:, builder:)` (native detent sheet, Dart content);
`showModalBottomSheet` / `showDialog` (light-dismiss
cards); `showDatePicker`; `showMediaPicker`; `BottomSheet`.
`ScaffoldMessenger.showSnackBar` works (routes to the native toast).

**`CustomPaint`** — supported, painting through Core Graphics /
`android.graphics.Canvas`. `CanvasSurface` (optional `dartnative_skia`)
only for SkSL shaders (`RuntimeEffect`) and other GPU work.

**DartNative additions worth adopting during a port**: `FastList` /
`FastGrid` / `MasonryFastGrid` (native cell recycling; `itemCount` +
`itemBuilder`, `keepAliveCount` windowing, `onScroll`,
`FastListController.scrollToItem`) for long feeds; `GlassEffectContainer`
(`borderRadius`, `tint`, `interactive`, `brightness`) for real iOS 26
glass; `DynamicColor.colorScheme(brightness:)` for Material You;
`VideoPlayer` via `dartnative_video_player`.

### Not available — plan around these

| Missing | Porting move |
|---|---|
| `PageView` (not planned) | Restructure: `SegmentedControl`/tabs + `IndexedStack`, or a horizontal `FastList` |
| `NestedScrollView` (not planned) | `AppBar.largeTitle` covers the collapsing-header case natively; `CustomScrollView` + slivers for the rest |
| `TabBar` (the swipeable material one) | `SegmentedControl` or `BottomNavigationBar` |
| `Dismissible` | No swipe-to-dismiss rows yet |
| `SelectableText` | `Text(selectable: true)` — long-press to select and copy |
| `Offstage` ⚠️ | The offstage child is UNMOUNTED (state lost) — Flutter keeps it mounted. Use `IndexedStack` for state-preserving show/hide |
| `Theme.of` inheritance beyond `App(theme:)` | Pass styles explicitly where the theme object isn't enough |
| `InheritedWidget`/`Provider`/Riverpod | `signal<T>` + `.watch(context)`; `Provided<T>` for per-subtree values |
| `RenderObject`/`RenderBox` layer | Doesn't exist — Yoga computes frames natively |
| `MethodChannel` + plugins using one | FFI only: such plugins crash at launch (`Setting a message handler before the FlutterEngine has been run`). Swap for dartnative_* or FFI/pure-Dart equivalents |
| `WidgetsFlutterBinding.ensureInitialized()` | `DartNativePluginRegistrant.registerAll()` |
| `rootBundle.load` | `loadAssetBytes('assets/foo.json')` — sync, returns `Uint8List?` |

## State management

`setState` works as in Flutter. For shared state, the built-in signals:

```dart
class AppStore {
  final counter = signal<int>(0);          // observable field
  void increment() => counter.value++;
}
final store = AppStore();

// In build(): subscribes this element; rebuilds on change.
Text('${store.counter.watch(context)}');
```

Migration mapping: `context.watch<T>()` / `ref.watch(p)` →
`store.field.watch(context)`; `context.read<T>()` / `ref.read(p.notifier)` → the store
reference; `StateProvider` → `signal<T>`; `ProviderScope(overrides:)` →
`Provided<T>(value:, child:)`. Delete `ProviderScope`/`MultiProvider`
wrappers and `Consumer*` base classes. `ValueListenableBuilder` works
unchanged (or call `controller.watch(context)` inline).

## Platform powers (use them — they're the point)

- **Declare dark screens**: `Scaffold(brightness: Brightness.dark)` on
  dark-by-colors screens — system materials (keyboard, glass, scroll-edge
  effects) render in the declared trait; without it a light-mode device
  paints them light.
- **iOS 26 Liquid Glass**: a translucent `AppBar.backgroundColor` (alpha <
  1) opts into the real frosted bar; no color = the clear bar with the
  system scroll-edge ramp; `GlassEffectContainer` for glass anywhere.
  Everything no-ops cleanly pre-26 and on Android.
- **Search in the bar**: `AppBar.searchBar: SearchBar(...)` — the App Store
  in-place choreography on iOS 26, the real Material 3 search app bar on
  Android. `title` is skipped when set.
- **Large titles**: `AppBar.largeTitle` collapses natively on scroll (the
  system large title on iOS 26; the M3 collapsing top app bar on Android).
- **Chat input**: `Scaffold.bottomInputBar` — the bar rides the exact system
  keyboard curve, including interactive dismiss.

## Conventions that scale

Taken from the starter app; adopt them in any app you generate.

- **Every pushed route carries a registered name.** Add each screen to
  `registerRoutes`, then push it by name (`Navigator.pushNamed`) or by
  builder with the same name in `PageRoute(settings: '/name')`. On hot
  restart the stack is rebuilt from those names; a route without a
  registered name is dropped from the stack.
- **Notifier for tree shape, signal for a value inside one element.** A
  `ChangeNotifier` per concern (`AppRepository.notes..watch(context)`)
  rebuilds every watcher when the list of things changes; a `Signal` on a
  field (a note's text) repaints only the widget watching it. Do not add a
  state-management package; extend this pattern.
- **Themed screens declare their trait.** A themed `Scaffold` passes
  `brightness: palette.brightness` so native surfaces (keyboard, alerts,
  glass) follow the app theme, and reads colours from the palette rather
  than hardcoding them.
- **Drawer items are sections, not routes.** A drawer selects what the home
  screen renders in place; push a route only for secondary screens such as
  settings, or back would walk through destinations.
- **Screens never touch storage or the network directly.** They talk to
  state notifiers and services, which talk to SQLite and the API.
- **Per-install configuration** (keys, endpoints) comes from a bundled
  `.dnkeys` file read through `DnKeys.get` (`dartnative_keys`); features that
  need the network degrade to local behaviour when a key is absent.
- **Always the `dn` CLI**, never `flutter`: `dn pub get`, `dn run`,
  `dn build`.

## Common mistakes

1. `App(home: screen)` as root → white screen. Pass the screen to `runApp`.
2. Missing `DartNativePluginRegistrant.registerAll()` first in `main()` →
   white screen, no crash.
3. `bottomNavigationBar` used for a chat input → the keyboard covers it,
   as it covers a native tab bar. Keyboard-attached bars go in
   `bottomInputBar`.
4. A custom top bar inside `body` → the keyboard pushes it off-screen. Top
   bars belong in `Scaffold.appBar` (it's a real `UINavigationBar`, pinned
   by the OS). If you must, set `resizeToAvoidBottomInset: false`.
5. `setState` in `initState` → not mounted yet; schedule it.
6. Deferring work inside native callbacks (`onTap` etc.) with
   `Future.microtask` → may run a frame late (callbacks run synchronously
   inside the platform event, not on the event loop). Use `Timer.run`.
   Plain synchronous `setState` in the callback is fine and preferred.
7. Importing `package:flutter/...` or unaliased `dart:ui` → type conflicts.
   One import: `package:dartnative/dartnative.dart`.

## First-party plugins

All `dartnative_*`, all FFI (no method channels), installed like any pub
dependency + `dn pub get`. Reach for these before writing platform code or
keeping a Flutter plugin. Browse the current catalog on dartpub.dev/explore.

| Area | Plugins |
|---|---|
| Media | `dartnative_video_player` (AVPlayer/ExoPlayer, pre-caching), `dartnative_audio` (play, PCM streaming, record), `dartnative_camera`, `dartnative_media_picker`, `dartnative_lottie` (Core Animation Lottie), `dartnative_compressor` (image/video compression), `dartnative_image_crop`, `dartnative_svg` |
| Storage | `dartnative_sqlite`, `dartnative_shared_preferences`, `dartnative_secure_storage` (Keychain/Keystore), `dartnative_hive` (cache), `dartnative_path_provider` |
| Platform & system | `dartnative_system`, `dartnative_connectivity`, `dartnative_permissions`, `dartnative_share`, `dartnative_url_launcher`, `dartnative_splash`, `dartnative_background`, `dartnative_autostart_settings`, `dartnative_keys`, `dartnative_crypto` |
| Services | `dartnative_firebase` (core + FCM), `dartnative_notifications`, `dartnative_social_sign_in` (Sign in with Apple + Google), `dartnative_supabase`, `dartnative_revenuecat` (IAP/subscriptions), `dartnative_google_maps`, `dartnative_webview` (real WKWebView/WebView) |
| Intelligence | `dartnative_onnxruntime` (on-device inference, CoreML/NNAPI), `dartnative_supertonic_tts` (offline neural TTS — 31 languages) |
| Rendering | `dartnative_skia` (optional: `CanvasSurface`, SkSL shaders), `dartnative_intl` (l10n) |
