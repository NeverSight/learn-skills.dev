Auditez si le « code encore consommé » doit réellement rester, en vous concentrant sur les wrappers/facades, les couches de compatibilité, les API publiques obsolètes, les branches de défense, les solutions de repli, les valeurs par défaut, la configuration, les sources dupliquées et les points d’extension spéculatifs. Utilisez‑le pour le code qui est utilisé mais pas suffisamment nécessaire, le nettoyage de la compatibilité héritée, les encapsulations dépourvues de sens, la suppression du code défensif, le nettoyage sans exigences de compatibilité, les vérifications approfondies de nécessité et les requêtes du type « cela doit‑il encore exister ? » ; ne le traitez pas comme un simple outil de vérification de code inutilisé/mort.
