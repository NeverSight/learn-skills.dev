# Design Product Onboarding

## Contract

Onboarding helps a specific user reach value in context; it is not a tour of the interface. Remove unnecessary setup before adding explanation, and do not optimize completion at the expense of trust or realized value.

## Workflow

1. Define the target segment, triggering situation, job, prior knowledge, environment, entry channel, and first meaningful value event.
2. Map the current path with eligibility, required setup, decisions, permissions, dependencies, waits, errors, assistance, and abandonment points.
3. Separate steps required for value, safety, or compliance from steps serving internal data collection or optional education.
4. Design the shortest coherent path to value with progressive disclosure, useful defaults, contextual guidance, realistic content, and clear progress.
5. Handle roles, team invites, integrations, data import, empty states, interrupted sessions, failures, retries, and return visits.
6. Set expectations about automation, data use, permissions, limitations, time, cost, and irreversible effects before commitment.
7. Define activation, time-to-value, quality, retention, support, and trust measures with guardrails and exact instrumentation needs.
8. Prioritize changes and experiments by friction, evidence, impact, effort, and reversibility. State which segment each change serves.

## BuildBetter Acceleration

If BuildBetter MCP is available, search organization skills first. Use onboarding calls, signals, surveys, support evidence, account context, projects, and documents to identify friction and successful paths. Do not contact or enroll users without explicit approval.

## Output

Return segment and value event, current-state journey, friction evidence, target path, screens or states, content principles, exception handling, instrumentation, measures, and experiment backlog.

## Quality Gate

Reject onboarding that teaches every feature, requires value-irrelevant setup, obscures permissions or data use, treats completion as activation, or assumes one path fits incompatible segments.
