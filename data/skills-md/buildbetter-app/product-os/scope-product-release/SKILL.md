# Scope Product Release

## Contract

Cut breadth, automation, polish, scale, or variants before cutting the core outcome. A smaller release must still complete a real job for a defined user. Revisit the bet when the constraint changes materially.

## Workflow

1. Re-state the target user, situation, must-deliver outcome, success evidence, appetite, and fixed constraints.
2. Map the end-to-end journey and identify the thin coherent path that delivers value.
3. Classify scope as essential outcome, trust or safety, learning instrumentation, accelerator, edge case, or future option.
4. Explore reductions by segment, use case, channel, platform, geography, data type, automation, configuration, integration, scale, or service level.
5. Preserve accessibility, privacy, security, compliance, reliability, supportability, rollback, and measurement at the required risk level.
6. Split follow-ons by dependency and learning, not arbitrary phase labels.
7. Document cuts, consequences, manual operations, upgrade path, re-entry criteria, and who accepted each tradeoff.

## BuildBetter Acceleration

If BuildBetter MCP is available, search organization skills first. Use strongest customer evidence, project detail, triage, linked tickets, documents, and prior decisions to protect the core outcome and identify low-evidence scope. Do not alter project records without explicit approval.

## Output

Return the core outcome, thin journey, in-scope and out-of-scope tables, cut rationale, preserved quality gates, manual operations, dependencies, follow-ons, and release acceptance evidence.

## Quality Gate

Reject a release that cannot complete the job, creates unrecoverable trust debt, or hides essential work in an undefined later phase.
