# 数据安全规范与等保密评

依据：PartMe.AI「数据安全规范」「网络安全规范」「等保密评规范」。

## 一、明文存储检查（隐私字段必须加密）

身份证号、手机号、住址、银行卡等隐私字段**禁止明文入库**：

- 在框架层实现存储自动加密（如 Mybatis-Plus-Enhance 的字段加解密）
- 加密算法：优先国密 SM4（存储加密）、SM2（非对称/密钥交换）、SM3（摘要/签名）
- 密钥集中管理（配置中心/KMS），不得与密文同库存放

AI 行为：新建实体含手机号/证件号等字段时，主动提示并添加加密注解/转换器。

## 二、信息泄露检查（返回必须脱敏）

- 数据返回阶段脱敏：手机号 `138****5678`、身份证 `3301**********1234`、姓名 `张*三`
- 低权限用户不可越权获取高权限数据（配合接口安全技能的鉴权/数据权限）

AI 行为：写返回 DTO 时对敏感字段套脱敏工具/注解；写日志时**禁止**输出完整敏感字段。

## 三、登录与接口控制

- 单设备登录（新登录踢旧会话）
- 登录环境检测、异常登录检测（异地/非常用设备告警或二次验证）
- 接口鉴权：按框架使用注解（详见接口安全技能）

## 四、文件上传（与接口安全技能联动）

前端格式/大小白名单 → 后端类型检测+大小限制 → Nginx `client_max_body_size`。
接口鉴权与上传边界交给 **`codeguard-security-api`** 技能。安装：`npx skills add full-stack-skills/codeguard-skills --skill codeguard-security-api`。

## 五、等保密评（合规背景）

| 概念 | 说明 |
|---|---|
| **等保** | 网络安全等级保护，按系统重要程度分 5 级；测评对象含信息系统、云平台、数据资源 |
| **密评** | 商用密码应用安全性评估，法定义务；对象为关基、等保三级及以上系统等 |
| **关基** | 关键信息基础设施（公共服务、能源、交通、水利、金融、电子政务等） |

- 三级以上等保、关基、密评：每年至少评估一次
- 子方向：服务器安全、数据库安全、日志与数据**异机备份**

### 传输/存储机密性与完整性方案

| 要求 | 技术实现（团队方案） |
|---|---|
| 传输机密性/完整性 | Spring Gateway GlobalFilter 统一加解密与签名 |
| 存储机密性/完整性 | Mybatis-Plus-Enhance 字段加解密与签名 |

### 国密算法速查

| 算法 | 类型 | 用途 |
|---|---|---|
| SM2 | 非对称 | 签名、密钥交换（对标 RSA/ECC） |
| SM3 | 哈希 | 摘要/完整性（对标 SHA-256） |
| SM4 | 对称分组 | 数据存储/传输加密（对标 AES） |
| SM1 | 对称（硬件） | 密码卡/专用硬件场景 |

与数字签名的区别：哈希（SM3）只保证完整性；数字签名（SM2+SM3）额外保证不可抵赖与身份。

## 六、AI 自查清单

- [ ] 新增敏感字段已加密存储（SM4/框架注解）
- [ ] 返回值已脱敏；日志不含完整敏感字段
- [ ] 登录态有单设备/异常检测考虑
- [ ] 涉及等保三级/密评系统：传输与存储方案符合 GlobalFilter + Mybatis-Plus-Enhance 模式
- [ ] 备份策略提及异机备份

## 不适用范围（什么时候不该用）

- 主要问题是 API 鉴权、文件上传或依赖 CVE，应使用对应专用技能。
- 只知道算法名称，却缺少数据分类、密钥托管、威胁模型和监管范围。
- 需要用真实个人数据、生产密钥或明文密文对做演示。

## 标准 Workflow

### Step 1：数据发现与分级

列出数据类型、来源、主体、敏感级别、用途、保留期和监管范围。

### Step 2：跟踪生命周期

按采集、传输、处理、存储、返回、日志、备份、导出和销毁检查保护措施。

### Step 3：设计密码边界

选择算法前明确用途、模式、随机数/nonce、密钥生成、托管、轮换、版本化和恢复。

### Step 4：实施脱敏和最小化

区分展示脱敏、不可逆 tokenization、加密存储与日志红线；尽量减少数据采集和保留。

### Step 5：产出可审计证据

记录规则、配置、测试、密钥轮换演练、访问日志、备份恢复和剩余风险。

## Rules

1. 密钥与密文不得共库或共用同等权限边界。
2. 日志、trace、错误页和分析平台不得记录完整敏感值。
3. 脱敏规则必须根据使用者角色与业务必要性设计。
4. 算法合规不能替代密钥管理、访问控制和审计。

## Gotchas

1. **哈希不等于加密**：需要恢复原值的字段不能仅做哈希。
2. **确定性加密会泄露相等关系**：若为查询使用，要明确残余风险。
3. **密钥轮换需要版本字段和迁移路径**，否则旧数据可无法解密。
4. **备份与导出常被漏掉**：必须有独立加密、访问和销毁策略。
5. **测试数据不应复制生产真实值**，应使用合成数据。
6. **等保/密评是证据体系**：单一代码片段或算法选择不能证明合规。
