Metti su git e su un GitHub privato un progetto che ancora non usa git, senza includere dati del cliente: controlla la cartella (fuori da iCloud/OneDrive/Dropbox/Google Drive), elenca ciò che sarebbe inserito nel git segnalando password (.env), certificato A1 (.pfx), foglio di calcolo e file grande, propone il .gitignore, offre l’allarme di commit della sdd‑higiene‑dato prima del primo commit e committa e pubblica solo con l’OK esplicito per ogni fase. Parla con chi non ha mai usato git: un passo alla volta, con quello che è stato fatto, quello che viene ora e le opzioni per ogni decisione. Riprendi da dove si è interrotto (git senza commit, commit senza GitHub, invio fallito). Usa quando l’utente dice “pôr no git”, “criar o repositório”, “subir para o GitHub”, “este projeto não tem git”, o quando sdd‑new‑session o sdd‑checar‑ambiente dicono che il progetto non usa ancora git. Non cancellare la cronologia già trapelata, non effettuare il login su GitHub per l’utente e non automatizzare altri host (GitLab ecc.), fornisci solo i comandi.
