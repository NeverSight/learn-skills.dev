Lege ein Projekt, das noch kein Git verwendet, in ein privates GitHub‑Repository, ohne Kundendaten mitzunehmen: prüfe den Ordner (außerhalb von iCloud/OneDrive/Dropbox/Google Drive), liste auf, was ins Git aufgenommen werden würde, kennzeichne Passwortdateien (.env), A1‑Zertifikat (.pfx), Tabellen und große Dateien, schlage eine .gitignore‑Datei vor, biete den Commit‑Alarm von sdd‑higiene‑dato vor dem ersten Commit an und führe den Commit sowie das Veröffentlichen nur mit explizitem OK für jeden Schritt aus. Sprich mit Personen, die noch nie Git benutzt haben: ein Schritt nach dem anderen, mit dem, was bereits erledigt wurde, dem, was jetzt kommt, und den Optionen für jede Entscheidung. Setze dort dort an, wo du aufgehört hast (Git ohne Commit, Commit ohne GitHub, fehlgeschlagener Upload). Verwende das, wenn der Nutzer „pôr no git“, „criar o repositório“, „subir para o GitHub“, „este projeto não tem git“ sagt oder wenn sdd‑new‑session bzw. sdd‑checar‑ambiente melden, dass das Projekt noch kein Git verwendet. Lösche keinen bereits veröffentlichten Verlauf, logge den Nutzer nicht bei GitHub ein und automatisiere keinen anderen Host (GitLab etc.), gebe nur die Befehle aus.
