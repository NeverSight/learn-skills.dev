Installiert, mit dem ausdrücklichen Einverständnis des Benutzers, einen Commit‑Alarm (pre‑commit von Git), der den Commit ablehnt, wenn er einen gültigen CPF‑ oder CNPJ‑Wert mit Prüfziffer, eine Passwortdatei (.env), ein Zertifikat mit privatem Schlüssel (.pfx, .p12, .pem) oder ein neues Tabellenblatt findet; erklärt, warum und wie man das Problem behebt, nennt git commit --no-verify und beschreibt, wie man deinstalliert. Verwenden Sie ihn, wenn der Benutzer das Repository vor Kundendaten oder einem A1‑Zertifikat, das in Git gelangt, schützen möchte, beim Vorbereiten des Büro‑Rechners für die Arbeit mit SDD, oder wenn ein Commit von diesem Alarm abgelehnt wird. Er gilt nicht für Zeiträume (es wird keine Norm abgefragt oder berechnet). Er repariert nicht die Git‑Historie, widerruft kein Zertifikat, liest keine .xlsx‑Datei intern und gibt keinen rechtlichen Rat zu LGPD oder beruflicher Vertraulichkeit; um die Umgebung ohne Installation zu prüfen, verwenden Sie sdd‑checar‑ambiente.
