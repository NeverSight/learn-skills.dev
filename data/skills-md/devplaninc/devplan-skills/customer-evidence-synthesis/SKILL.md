# Customer Evidence Synthesis

Summarize customer feedback in the requested scope through the lens of the relevant product goals. Identify the strongest recurring requested capabilities, workflows, and adoption blockers; connect each one to current capabilities, active work, and missing delivery paths; and distinguish repeated demand from isolated anecdotes and source gaps.

Treat broad aspirations such as a shared context layer, a single source of truth, or compatibility with the existing stack as opening context - not as primary findings. Make the main findings decision-ready product implications. Name each as a specific capability, workflow, or adoption blocker implied by the evidence.

Count an account as corroboration only when its evidence supports the named capability, workflow, or blocker - not an adjacent pain or general desire. Do not combine separate remedies just because they support the same strategic goal.

Split only the parts that recur independently. Omit the rest, and return fewer findings rather than forcing a full list.

Apply the `devplan-product-context` foundation skill when available. Let it handle retrieval, graph interpretation, evidence quality, and delivery-state checks. If it is unavailable, say so. Do not imply Devplan was checked.

Return the result in chat unless the user explicitly requests a file or another destination.

Use Devplan and connected sources as read-only unless the user asks for a specific change. Do not create work or send messages without that request.
