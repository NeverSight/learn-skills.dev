# index-project

为项目初始化并持续维护跨 code agent 的 AI 上下文索引。使用同一输出契约，按现状选择一条路径：

- **初次索引**：无可靠索引或用户要求全量重建时，全量清点并创建文档；用户要求续扫时，按断点补齐未完成部分。
- **跟进索引**：从本次变化出发，只读取并更新受影响模块；既有索引未完成时，也先定向补齐受影响部分。

以 `AGENTS.md` 为唯一事实来源。不要依赖特定 agent 的专属工具、子代理、MCP 或状态目录；使用宿主提供的等价文件列举、搜索、读取和编辑能力完成流程。

代码或配置变更影响已记录的模块职责、入口、接口、依赖、关键文件或模块关系时，应主动调用本 Skill，在当前开发任务交付前同步受影响的模块与项目索引，无需等待用户另行要求。仅实现细节变化且索引仍准确时，不改写索引。

## 确定目标与加载流程

先确定项目根：用户明确指定的目录优先，否则使用当前工作目录。不要仅因当前目录位于某个祖先 Git 仓库中就擅自扩大目标范围。沿用项目约定的根与模块索引层级；用户明确仅维护根文档时，在根索引中记录模块信息。

| 判断条件 | 场景 | 必须加载 |
|---|---|---|
| 无根 `AGENTS.md` | 初次 | `references/first-index.md` |
| 用户要求续扫未完成索引或全量重建 | 初次（续扫/重建） | `references/first-index.md` |
| 既有索引存在缺口，且无法据本次变化定向补齐 | 初次（修复） | `references/first-index.md` |
| Agent 修改模块内容影响索引，或用户要求跟进项目变化 | 跟进 | `references/incremental-index.md` |

加载对应 reference 后再扫描或写文档。跟进时先利用本次任务已知的变化；只有现有证据不能确定必要覆盖范围或实际缺口无法定向补齐时，才加载 `references/first-index.md` 补充扫描。

## 公共约束

- 只创建或更新目标范围内根与模块的 `AGENTS.md`；不创建 `.claude/`、`.agents/`、`.opencode/` 或机器状态 sidecar。
- Git 项目优先用 Git 的已跟踪、未跟踪和忽略信息列举文件；非 Git 项目使用宿主可用的文件列举能力。始终遵守根和嵌套忽略规则，并默认跳过依赖、构建产物、缓存、日志、媒体、压缩包和二进制文件。
- 不把本 skill 生成的 `AGENTS.md` 当作源码新增项或模块文件清单内容。
- 大文件和二进制只记录路径，不读取内容。展示路径相对项目根；Markdown 和 Mermaid 中的本地文件链接相对所在文档，文档内跳转使用对应锚点。
- 先读后写并保留人工意图，合并已核实且不改变该意图的事实更新；只有存在无法依据现有证据或已授权目标解决的语义冲突时，才保留冲突部分并向用户确认，继续处理其他部分。
- 不擅自删除文件。模块被移除时先更新索引并报告残留文档；只有用户明确确认后才删除孤儿 `AGENTS.md`。

若项目没有自己的忽略规则，至少跳过：`node_modules/**`、`.git/**`、`dist/**`、`build/**`、`.next/**`、`__pycache__/**`、锁文件、日志、媒体、压缩包和常见二进制。核实构建和验证入口时，按需读取 `.github/` 中的工作流配置。

## 记录基线

开始源码索引核对前获取当前 UTC 时间，格式为 `YYYY-MM-DDTHH:mm:ssZ`；有可验证的项目级 Git 仓库时同时记录当前完整 HEAD，作为本轮候选起点。不要手写时间。续扫沿用已保存的原始起点；纯历史清理或状态格式整理不建立新起点。采用扫描开始时的起点，可让扫描期间的新变化仍落在下次检测范围内。

## 输出契约

按约定层级生成文档。仅根级模式只交付根文档，模块信息写入根索引；下列模块文档契约只适用于包含模块级索引的项目。

- **根 `AGENTS.md`**：项目愿景、架构总览、Mermaid 结构图、模块索引、运行与开发、测试策略、编码规范、AI 使用指引、文档最末的「索引状态」。图中模块节点在模块级模式下链接对应 `AGENTS.md`；仅根级模式使用根内已有模块锚点，无对应锚点时保留无链接节点。
- **模块 `AGENTS.md`**：相对路径面包屑、模块职责、入口与启动、对外接口、关键依赖与配置、适用时的数据模型、测试与质量、常见问题、相关文件清单。增量流程按标题定位，必须使用精确标题 `## 相关文件清单`；清单只列理解和维护模块所需的高信号文件，不得退化为大型仓库的完整文件 manifest。
- 测试策略、编码规范和 AI 指引只记录本项目已核实的事实与既有有效约束，不因补齐栏目新增审批、委派或验证流程。
- 根与模块正文维护当前事实，默认不创建或追加「变更记录」。职责、接口、依赖和约束变化直接更新对应小节；本轮变更与验证结果在主对话汇报，不写成正文或索引状态中的历史流水。
- 不适用或未发现的内容明确写“未发现”或省略可选小节，不编造入口、命令、接口或依赖。

### 索引状态快照

根文档最末只保留一份「索引状态」，字段原位更新且各出现一次，模块文档不复制全局状态。项目明确约定的索引范围等必要恢复字段也遵守此规则。

```markdown
## 索引状态
- 上次索引：<最近完整核对采用的 UTC 起点；尚未建立则写“无”>
- 基线提交：<对应完整 commit；尚未建立或非 Git 项目写“无”>
- 已知缺口：<尚未核实的源码事实或索引覆盖缺口；没有则写“无”>
- 扫描进度：<未完成时保存原始起点、已完成/待处理模块及阻塞原因；完成后只写“已完成”>
```

「已知缺口」只描述索引缺口，按模块或主题合并为定位信息与一句原因；产品待办、测试结果和 GUI 验收进度不属于此字段。需要这些背景时，在相关正文中指向已有任务或证据文档。

未完成进度只保存当前一份断点：原始起点由开始时取得的 UTC 时间和完整 HEAD（非 Git 为“无”）组成，每个模块仅保留当前状态，更新时替换旧值。多次续扫不更换起点、不累积每轮快照；完成后移除临时起点和模块列表。

仅在约定的索引范围核对完成后，将本轮原始起点提升为全局基线。局部更新、历史清理或字段归一均保留原全局时间与 commit，不追加局部更新时间；仍有待处理模块时保留其断点。现有内容准确、符合本输出契约且没有新的缺口或进度时，不改写文档、时间戳或基线。

### 整理旧记录

只整理本次维护范围的文档。历史中仍有效且仅在此处记载的职责、接口、约束和当前限制，先核实并合入对应正文；已有权威说明时保留指针，避免重复。已由 Git 或现有任务、证据文档承载的过程记录可移除。不能假定未提交记录已进入 Git；独有信息尚未妥善保留或无法确认可安全清理时，保留该部分并在摘要说明，不继续追加。用户明确要求保留的历史按其约定处理。

重复状态字段按可信的完整核对记录归一；缺少覆盖证据时保留可验证的旧基线，将不确定部分记为索引缺口，不用最新日期或当前 HEAD 冒充已完成核对。纯整理不触发全量扫描；需要补证时沿用定向核对规则。

## 结果摘要

在主对话说明：

- 初次或跟进，以及选择依据；
- 根和模块文档的新建、更新、跳过状态；
- 模块路径与一句话职责；
- 已列举文件数、实际读取内容的文件数、主要缺口和跳过原因；
- 跟进场景的变更清单、更新/跳过说明；无变化时明确说明未写文件；
- 未完成时说明停止原因、已落盘断点和推荐的下一步。
