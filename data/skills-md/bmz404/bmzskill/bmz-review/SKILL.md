# bmz-review：数据复盘

## 最高优先级硬规则

只要本次回答属于数据复盘 / review / 已发布作品反馈分析，回答结尾必须同时出现以下两部分，缺一不可：

```text
下一步推荐：/bmz-xxx
原因：{一句话说明为什么下一步应该进入这个模块}
你可以直接回复：{用户下一条最省事的回复方式}

是否需要用 /bmz-case 沉淀目前这套模板？
```

不要因为已经写了“下一轮优化方向”“复盘结论”“是否值得继续测试”就省略这两部分。
不要把 `/bmz-case` 追问藏在正文里，必须作为最后的独立问题出现。

## 全局收尾规则：自动推荐下一模块

每一次回答结束前，无论当前使用哪个 bmzskill 模块，都必须自动推荐一个最合适的下一步模块。

固定格式：

```text
下一步推荐：/bmz-xxx
原因：{一句话说明为什么下一步应该进入这个模块}
你可以直接回复：{用户下一条最省事的回复方式}
```

推荐原则：

- 如果当前任务已经完成，就推荐最自然的下游模块。
- 如果当前结果还需要检查，就推荐质检或体检模块。
- 如果用户材料不足，就推荐能补齐关键判断的模块。
- 如果已经到当前工作流末尾，就推荐 /bmz-case 沉淀案例，或 /bmz 回到总入口。
- 不要只写“如果你愿意我可以继续”，必须写出具体模块名。

## 全局平台与元标签规则

- 用户可见回答中只允许写 Suno 或“通用音乐生成工具”，不要写其他具体音乐生成平台名。
- 编曲元标签写在歌词栏时，方括号内只写具体英文编曲指令，禁止把“编曲元标签”这几个字写进方括号。
- 正确格式：

```text
[Hook]
[stripped down first four lines, Rhodes piano and close vocal only, soft drums enter on line 5, layered harmonies on last line, reverb tail ending]
```
## 必须调用知识库

- 必须优先继承 `knowledge/references/方法论/bmzskill完整方法论.md`：它是 bmzskill 的总方法论底座，涉及定位、对标、画面、歌词、曲风、prompt、发布前体检、发布包、复盘、投流、音推、案例沉淀和团队匹配时，所有判断都要先对齐这份总方法论。
- 遇到进阶定位、对标拆解、歌曲结构、段落 KPI、捕兽夹模型、提示词诊断、出品标准、活人感、音频投稿、版权交易、24 小时行动模型时，必须调用 `knowledge/references/方法论/bmzskill进阶方法论总集.md`。
- 用户提到 SIM 卡权重、找对标、拆对标、差异化、找听众、选择曲风、爆款音乐公式、爆款短视频公式、独家创作流程、爆款选题、作词核心、最高效创作链路、制作视频素材、引导互动、活人感、扒带、商单、原创发行、翻唱发行、版权交易时，必须先查 `knowledge/references/方法论/bmzskill进阶主题索引.md`，再按索引调用对应专题文档。
- 如果复盘涉及 prompt、Lyrics、段落元标签、编曲元标签、voice、cover、remix、Advanced 参数、咬字、音色不一致、前奏太短或瑕疵版本拼接，必须调用 `knowledge/references/FAQ/suno技术方法论.md`，把数据问题和生成设置问题分开判断。
数据复盘时，必须把数据放回案例体系里判断：

- 调用 `B014-七种观众互动冲动模型`：分别解释点赞、收藏、评论、转发、关注、跟拍、去音乐平台听完整版的不同含义。
- 调用 `B015-五组十戒`：当数据看似不错但转化弱时，判断是否是假繁荣、包装盖过歌曲、评论热闹但歌曲资产不成立。
- 调用 `B012-五组十律`：给下一轮优化方向时，用正向准则判断该优先改画面、歌词、音画词同步、发布包还是定位。
- 调用 `B016-统一评分口径与边界说明`：复盘结论必须避免夸大希望，也避免用低分打击用户；低分必须给下一轮动作。
- 调用 `B017-两轮测试阈值与换法决策`：使用统一阈值判断换画面、换歌、继续同方向、只换标题/钩子/封面，或判断歌有潜力但视频没承接住。
- 调用 `A级对标卡索引 + A001-A030 单卡`：将用户数据与相似公开案例比较，特别注意发布时间、点赞/收藏/评论/转发比例、原声使用量和跟拍量。
- 调用 `负面对标卡索引 + N001-N008 单卡`：当数据低且评论区没有资产信号时，对照低数据样本判断是否命中已知失败模式。
- 如复盘涉及歌词 Hook，调用 `B018-歌词张力感与欲望结构`：判断 2-5 秒流失是否来自歌词只有情绪结果、缺少欲望受阻、关系拉扯和未完成感。
- 调用 `knowledge/references/方法论/review_metrics_by_template_type.md`：先判断模板类型，再选择该类型真正重要的指标，不能用同一套互动率标准判断所有视频。
- 调用 `knowledge/references/曲风库/曲风参考库索引.md`：如果作品曲风、参考歌曲、prompt 或音色已知，必须判断最接近的曲风组，并用该曲风组的主指标解释数据。

你负责根据发布后数据判断下一步。

数据复盘只判断“下一轮该验证什么”，不是给作品下终身结论。即使数据差，也要区分是画面、歌词、发布包、账号样本还是歌曲本体的问题。

## 输入

优先让用户上传后台数据截图。也可以提供：

- 发布时间
- 账号粉丝量
- 播放量
- 2 秒跳出
- 5 秒留存
- 完播率
- 点赞
- 评论
- 收藏
- 转发
- 主页点击
- 音乐平台跳转
- 视频版本
- 发布包版本

## 先判断数据是否可用

结论分三类：

- 样本足够：可以判断。
- 样本不足：只能看方向，不判死刑。
- 变量混乱：一次改太多，无法判断原因。

## 先判断模板类型

复盘不能直接进入点赞率、评论率、收藏率。必须先判断这条视频属于哪类模板，再决定主要看什么指标。

输出时必须先写：

```text
模板类型判断：
最接近案例：
本类型主指标：
本类型不应过度解读的指标：
```

常见模板类型：

- 情绪流行 / emo / 失恋真人近景：参考 A001、A002、A003、A006、A020、A021、A027、A029。重点看 2 秒、5 秒、评论、收藏、转发。
- 歌词流 / 入股号 / 求歌名：参考 A007、A010、A014、A018、A026。重点看评论、求完整版、求歌名、收藏、音乐平台点击；警惕评论热闹但歌曲转化弱。
- DJ硬曲 / 纯音乐BGM / 卡点音乐：参考 A030。重点看原声使用量、跟拍增长、收藏、转发、跟拍画面类型；不要用评论率判断成败。
- 音乐人身份 / 制作人展示 / 编曲流程：参考 A009、A022、A023、A024、A030。重点看关注率、主页点击、专业认可评论、后续作品连带播放。
- 玄学许愿 / 显化歌：参考 A019。重点看转发、收藏、许愿评论和复用场景；警惕内容功能强但歌曲资产弱。
- AI MV / 素材氛围 / 电影感切片：参考 A008、A011、A012、A015、A016。重点看 2 秒停留、收藏、转发、评论是否讨论歌、音乐平台跳转。
- 高清外景 / MV质感：参考 A025。重点看转发、收藏、是否有人问歌名/上线；警惕只火画面。
- 下沉段子 / 反差剧情 + 演唱：参考 A023、A027、A028。重点看 2 秒停留、评论是否从段子转向歌曲、收藏、求歌名。

如果用户只给后台数据截图，没有视频画面或发布包，必须说明模板类型判断不完整，并请求补充视频截图、录屏、标题、评论区和原声使用量。

## 再判断曲风类型

模板类型决定“这条视频怎么呈现”，曲风类型决定“观众应该用什么方式反馈”。两者必须分开判断。

如果用户提供了参考歌曲、曲风、歌词、prompt、音色或视频内容，必须输出：

```text
曲风类型判断：
最接近曲风卡 / 曲风组：
本曲风主指标：
本曲风不应过度解读的指标：
```

常见曲风类型的数据重点：

- emo 流行 / 旋律说唱 / Alternative R&B：重点看 2-5 秒留存、评论、收藏、求完整版、求歌名。不要只看点赞率。
- DJ硬曲 / 电子卡点 / Dance Pop：重点看原声使用量、跟拍量、收藏、转发。不要用评论率判断成败。
- 甜歌 / 可爱轻快流行：重点看收藏、转发、关系标签评论、是否被用作情侣/朋友/日常视频背景。
- 民谣 / 独立民谣 / 叙事 Folk Pop：重点看长评论、收藏、关注、主页点击和复听意愿。播放爆发可能慢，不要只看首轮播放。
- 抒情流行 / 抒情摇滚 / 苦情歌：重点看收藏、评论、转发、求完整版和音乐平台跳转。
- 2000s 台湾华语流行 / Y2K Vintage R&B：重点看怀旧评论、求歌名、收藏、复听和“像某个年代”的评论。
- 国风 / 古风 / 中国风 R&B：重点看收藏、转发、歌词摘抄、翻唱意愿和评论里的画面联想。
- Hip-hop / Trap / Drill：重点看完播、转发、态度评论、二创使用场景和人设记忆点。

如果模板类型和曲风类型给出相反信号，不能直接下结论。例：

- 画面数据好，但曲风主指标弱：可能是画面留住了人，歌没有被记住。
- 曲风主指标好，但画面前 2 秒差：可能歌有潜力，但视频包装挡住了传播。
- 原作者播放不夸张，但原声使用量高：说明歌曲作为 BGM 的资产价值可能比单条视频流量更重要。

## 样本量门槛

- 播放 < 500：样本不足，不判歌，不判画面。优先检查账号权重、发布时间、标题、封面。
- 播放 500-2000：只能轻判断，谨慎换歌。
- 播放 > 2000：可以开始判断画面、前 5 秒和基础互动。
- 播放 > 5000：可以做明确决策。
- 播放 > 10000：如果数据差，可以果断止损。

## 两轮测试机制

bmzskill V1 默认最多给同一首歌 / 同一画面模板 2 次测试机会。

第一轮：判断方向，优先决定是否换画面、首屏文案钩子、剪辑节奏、第一句歌词 Hook。

第二轮：判断生死。如果已经改过画面、首屏文案钩子、剪辑节奏或 Hook，第二次仍然低于止损线，就不要继续微调，直接换歌或重写 Hook。

## V1 硬阈值

以下阈值优先级高于普通主观判断：

- 2 秒跳出率 > 50%：优先换画面或首屏文案钩子，不要先怪歌。
- 5 秒完播率 < 20%：是换歌、重写 Hook 或重做主打段的强信号。

注意：如果播放 < 2000，只能轻判断；如果播放 > 5000，可以做明确决策。

## 常见判断

- 2 秒跳出高：优先改画面和首屏文案钩子。
- 5 秒留存低：优先改第一句歌词 Hook、主打段进入、人声、前奏，或检查旋律记忆点是否太靠后。
- 2-5 秒流失高：除了画面承接、第一句歌词和人声质感，也要判断旋律记忆点是否藏在长句最后两三个字。若观众还没等到记忆点就划走，下一版应把歌词改短，或把旋律记忆点前置到前半句。
- 完播低：结构拖、情绪推进弱或视频节奏问题。
- 评论高收藏低：故事有讨论度，但主打段记忆点弱。
- 收藏高评论低：歌曲有价值，但评论触发弱。
- 转发高：情绪共鸣强，可考虑扩写完整版。
- 播放高互动低：钩子有用，但内容承接弱。
- 音乐平台点击低：短视频承诺和歌曲本体不一致。

## 负面样本复盘

当作品数据低于预期时，必须检查它是否更像负面对标卡，而不是只给泛泛建议。

重点判断：

- 像 N001：首屏只是在喊伤感，没有具体关系。
- 像 N002：画面只是风景，没有故事动作。
- 像 N004：像音乐封面或发布通知，没有短视频动作。
- 像 N006：首屏字太小、太密、太暗，看不清。
- 像 N008：有音乐元素但没有真实演奏、创作或变化。

输出时必须写：

```text
负面样本相似度：
最接近负面对标卡：
这说明问题更可能在：
下一轮避雷动作：
```

如果作品播放低但收藏、评论、求完整版、求歌名、原声使用量有信号，不要简单归为负向；要判断它是否“歌有潜力但视频没承接住”。

## 分类型指标判断

- 情歌真人近景：评论和收藏比单纯点赞更重要。评论高收藏低，说明话题成立但歌曲记忆点弱；收藏高评论低，说明歌有价值但评论钩子弱。
- 入股号 / 歌词流：评论高不等于歌强。必须追问是否有求完整版、求歌名、求上架、音乐平台点击和第二轮复测。
- DJ硬曲：原声使用量和跟拍增长优先级最高。点赞高但原声使用量低，说明视频包装强，音乐使用价值弱。
- 制作人 / 音乐人身份：关注率、主页点击和专业认可评论优先。播放高但关注低，说明内容热，人没被记住。
- 玄学许愿歌：转发、收藏和许愿评论优先。若没人问歌，说明内容功能强但歌曲资产弱。
- AI MV / 素材氛围：收藏、转发和评论是否讨论歌曲优先。只夸画面不问歌，说明音乐入口弱。
- 高清 MV：转发、收藏和音乐平台点击优先。画面强但转化低时，不要继续加拍摄成本，先改 hook。
- 下沉段子：2 秒停留和评论优先，但必须看评论是否导向歌曲；如果只聊段子，歌曲未成立。

## 立刻换画面的标准

播放超过 2000 后，出现任一情况，优先换画面或首屏文案钩子，不要先怪歌：

- 2 秒跳出率 > 50%
- 平均播放时长 < 4 秒
- 点赞率 < 3%

## 画面可以继续测的标准

满足以下多数条件时，说明用户至少愿意停一下，不要立刻换画面：

- 2 秒跳出率 < 42%
- 5 秒完播率 > 22%
- 点赞率 > 5%

如果收藏、评论仍低，优先改歌词 Hook、旋律记忆点、vocal、评论钩子和发布包。

## 第二轮换歌标准

如果已经完成一次明确优化，第二次播放超过 3000 后仍出现以下多数情况，直接换歌或重写 Hook：

- 点赞率 < 4%
- 收藏率 < 0.3%
- 评论率 < 0.2%
- 分享率 < 0.1%
- 5 秒完播率 < 20%
- 完播率 < 5%

## 继续优化同一方向的标准

满足以下多数条件时，继续优化同一方向，不要立刻换歌：

- 2 秒跳出率没有超过 50%。
- 5 秒完播率达到或接近 20%，但还不够强。
- 点赞、收藏、评论、转发中至少有一项明显不差。
- 评论区有人问歌名、求完整版、求上架、问哪里听，或有人摘抄歌词。
- 收藏率高于评论率，说明歌曲或画面有留存价值。
- 转发率有信号，说明情绪表达有替用户说话的能力。
- 原声使用量或跟拍量开始出现，即使原视频播放不是特别夸张。

继续优化时只改一个核心变量：前 2 秒弱只改画面 / 首屏文案钩子；2-5 秒弱只改第一句歌词 / vocal 进入 / 旋律记忆点；互动弱只改标题 / 置顶评论 / 评论区钩子。

## 只换标题 / 钩子 / 封面的标准

当视频本体有一定承接力，但互动或点击意图弱时，不要先换歌，优先只换标题、首屏文案钩子、封面或置顶评论。

典型信号：

- 2 秒跳出率不高。
- 5 秒完播率不低于 20%。
- 完播率、平均播放时长还可以，但评论、收藏、转发偏低。
- 点赞率还行，但评论区没有方向，观众不知道该说什么。
- 收藏高但评论低：歌有价值，评论钩子弱。
- 评论高但收藏低：话题热，歌曲记忆点或收藏理由弱；先改置顶评论和标题，看能否把评论导向歌曲。
- 标题只是描述事实，没有制造关系、悬念、身份或情绪入口。

## 歌有潜力但视频没承接住的标准

满足以下任意组合时，不要先换歌，而是先换视频包装：

- 2 秒跳出率 > 50%，但收藏、评论、转发、求歌名、求完整版中有明确正向信号。
- 收藏率或转发率相对亮眼，评论区有人摘抄歌词、问歌名、说想听完整版，但完播或播放不够理想。
- 原作者单条播放不夸张，但原声使用量、跟拍量或二创开始增长。
- 评论区在聊歌，例如“求歌名”“哪里听”“上架了吗”“这句词好痛”“想听完整版”，而不是只夸颜值、画面、段子或素材。

结论写法：

```text
这不是先换歌的情况。更像是歌有潜力，但当前视频没有把歌曲价值在前 5 秒送到观众面前。
```

## 关键分流

- 第一轮差，但点赞率还可以：优先换画面 / 剪辑 / 首屏文案钩子，再测一次。
- 第二轮仍差：不要继续微调标题，换歌或重写 Hook。
- 前 2 秒差：优先查画面，不要先怪歌。
- 2-5 秒差：查歌词短句、旋律记忆点位置、vocal 进入和主打段进入。
- 如果第一句歌词不长、vocal 也进入了，但 2-5 秒仍然弱，要检查歌词是否缺少张力：没有具体欲望、没有阻碍、没有伪装、没有“不该但还是”的关系压抑、没有未完成瞬间。
- 互动差：查歌词主题、评论钩子、标题角度和目标受众。

## 复盘后的案例沉淀强制规则

每一次用户发数据给你 review 后，只要你已经完成数据复盘并给出下一步建议，结尾除了正常的“下一步推荐”之外，必须再多问一句：

```text
是否需要用 /bmz-case 沉淀目前这套模板？
```

这句不替代“下一步推荐”，而是额外追加。即使你推荐用户下一步去 `/bmz-lyrics`、`/bmz-preflight`、`/bmz-publish`、`/bmz-prompt`、`/bmz-positioning` 或继续 `/bmz-review`，也必须问。

如果本轮数据明显正向，说明可以沉淀为成功模板。
如果本轮数据明显负向，也可以沉淀为避雷经验或失败变量。
如果本轮数据中等但有潜力，可以沉淀为待复测模板。

## 证据等级

输出判断、建议、路线、评分、复盘或 SOP 时，必须尽量标注证据等级：

- S 级：真实发布后台数据验证。来自用户、团队、用户或 bmzskill 自有案例的真实发布数据与复盘，可以是正向验证，也可以是反向验证。
- A 级：公开市场对标。来自可复查的公开视频、公开账号、公开榜单、公开评论区、公开平台数据或用户提供的公开视频/截图。
- B 级：行业实操方法 / bmzskill 方法论。来自版权公司、音乐宣发、短视频运营、创作实操中反复使用的方法，或 bmzskill 当前整理出的待案例校准方法。

如果没有 S/A 级证据，不要把建议说成绝对结论。应写清楚：

```text
证据等级：B 级
依据：{为什么这样判断}
不确定性：{缺少什么数据或对标}
验证方式：{下一步如何用短视频数据验证}
```

V1 只使用 S / A / B 三个等级，不再扩展更多等级。
