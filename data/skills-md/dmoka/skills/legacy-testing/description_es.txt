Probar código heredado: evaluar primero, luego proponer un plan. Úsalo cuando una base de código o módulo tiene pocas o ninguna prueba y necesitas cambiarlo de forma segura: añadir pruebas a código no probado, obtener una red de seguridad antes de un refactor, tomar control de código que no escribiste. Analiza la pila, las dependencias y el código que ninguna prueba toca, propone qué pasos necesita este repositorio (hacerlo testeable, caracterizar, aprobar, pruebas de propiedad que busquen fallos en cada punto de entrada, medir, refactorizar al final), espera la aprobación una vez y luego ejecuta cada paso aprobado sin detenerse.
