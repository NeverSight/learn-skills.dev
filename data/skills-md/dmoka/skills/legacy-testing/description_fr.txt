Tester du code hérité : évaluer d’abord, puis proposer un plan. À utiliser lorsqu’une base de code ou un module a peu ou aucun test et que vous devez le modifier en toute sécurité : ajouter des tests à du code non testé, obtenir un filet de sécurité avant un refactor, reprendre du code que vous n’avez pas écrit. Examine la pile, les dépendances et le code qu’aucun test ne touche, propose les étapes dont ce dépôt a besoin (le rendre testable, le caractériser, l’approuver, des tests de propriétés qui recherchent les plantages à chaque point d’entrée, mesurer, refactoriser en dernier), attend une fois l’approbation, puis exécute chaque étape approuvée sans s’arrêter.
