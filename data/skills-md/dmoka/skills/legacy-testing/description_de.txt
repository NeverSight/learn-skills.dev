Legacy-Code testen: zuerst bewerten, dann einen Plan vorschlagen. Verwenden, wenn ein Code‑Base oder Modul nur wenige oder keine Tests hat und Sie es sicher ändern müssen: Tests zu nicht getesteten Code hinzufügen, ein Sicherheitsnetz vor einem Refactoring schaffen, Code übernehmen, den Sie nicht geschrieben haben. Betrachtet den Stack, die Abhängigkeiten und den Code, den kein Test berührt, schlägt vor, welche Schritte dieses Repository benötigt (testfähig machen, charakterisieren, genehmigen, Property‑Tests, die bei jedem Einstiegspunkt nach Abstürzen suchen, messen, zuletzt refaktorieren), wartet einmal auf Genehmigung und führt dann jede genehmigte Phase ohne Unterbrechung aus.
