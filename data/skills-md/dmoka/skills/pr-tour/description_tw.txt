以導覽式的方式，按理性的閱讀順序審查單一 PR。將一個 pull request 轉換成導覽式閱讀之旅——作者的意圖、哪些檔案說明了該意圖、哪些則沒有，先列出可檢驗的主張，接著說明該看哪裡以及原因（腳本計算的事實加上逐行檢查的指標），然後依照審查者應該閱讀的順序列出檔案，將每個測試置於其程式碼旁，最後把噪音（鎖定檔、生成檔、重新命名、格式化）收納在最後——以單一自包含的 HTML 頁面加上 JSON 供代理程式讀取的形式呈現。不是 GitHub 的堆疊 PR。當使用者要求審查、走訪、說明或了解 PR 或 diff，詢問先讀什麼或在 PR 中該擔心什麼，或提到 PR 之旅或閱讀順序時，請使用此方式。
