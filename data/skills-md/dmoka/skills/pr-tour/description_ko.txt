하나의 PR을 가이드 투어처럼, 합리적인 읽기 순서로 검토합니다. 하나의 풀 리퀘스트를 가이드 읽기 투어로 변환합니다 — 작성자의 의도, 그 의도가 설명하는 파일과 설명하지 않는 파일, 그리고 확인 가능한 주장들을 먼저 제시하고, 그 다음 어디를 왜 봐야 하는지(스크립트가 계산한 사실과 라인 검증 포인터)를 제시하며, 리뷰어가 읽어야 할 파일들을 각 테스트가 코드 옆에 배치된 순서대로 보여주고, 잡음(잠금 파일, 생성된 파일, 이름 변경, 포맷팅)은 마지막에 축소합니다 — 이를 하나의 자체 포함 HTML 페이지와 에이전트가 읽을 수 있는 JSON 형태로 렌더링합니다. GitHub 스택형 PR은 제외합니다. 사용자는 리뷰 요청, 단계별 안내, 설명, PR 또는 diff 이해, 첫 번째로 읽을 부분이나 PR에서 주의할 점을 물어볼 때, 혹은 PR 투어나 읽기 순서를 언급할 때 이 기능을 사용합니다.
