以合理的阅读顺序审查单个 PR，将一次 pull request 转化为导读之旅——首先展示作者意图、哪些文件体现了该意图、哪些文件未体现以及可验证的声明；接着说明应查看何处以及原因（脚本计算的事实加上行级指针检查）；随后按审阅者应阅读的顺序列出文件，并将每个测试代码并列展示；最后把噪声信息（锁文件、生成文件、重命名、格式化）折叠在末尾——输出为一个独立的 HTML 页面以及可供代理读取的 JSON。不是 GitHub 的堆叠 PR。用户在请求审查、逐步讲解、解释或理解 PR 或差异、询问先读什么或在 PR 中需要关注什么，或提到 PR 导览或阅读顺序时使用此功能。请始终使用用户的语言回复。
