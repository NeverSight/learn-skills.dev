Ejecuta N issues de GitHub a la vez, una ejecución de work‑issue por issue en su propio worktree, con las huellas demostradas como disjuntas, la cuestión de acoplamiento entre carriles respondida y registrada, el orden de merge fijado, y las ramas fusionadas y verificadas antes de que cualquier carril abra un pull request. Usa SÓLO cuando el usuario invoque explícitamente work‑wave. Nunca planifica un issue, nunca lo mergea, y nunca avanza un solo issue: para un issue, usa work‑issue.
