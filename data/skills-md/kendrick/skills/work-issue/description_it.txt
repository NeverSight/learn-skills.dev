Avanza una issue di GitHub dal suo piano approvato a una pull request i cui thread di revisione sono stati risposti, riprendendo da dove un’invocazione precedente l’aveva lasciata. Usalo quando una issue ha un piano approvato e deve essere costruita, pubblicata e i suoi thread di revisione risposti, oppure quando una skill di orchestrazione esegue una issue come lane. Non pianifica mai una issue e non ne esegue mai il merge: per pianificare, usa writing-plans; per eseguire un piano senza issue, usa divvy-up.
