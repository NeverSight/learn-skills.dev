Einen GitHub‑Issue anlegen: ein Bug‑Report, Feature‑Request, Task oder Spike, erstellt mit `gh`. Verwenden, wenn der Nutzer einen Issue einreichen oder öffnen, einen Bug melden, ein Feature anfordern, eine Aufgabe oder einen Spike dokumentieren, eine halbformulierte Beschwerde in etwas Nachverfolgbares verwandeln oder einen Issue erstellen möchte, den ein Coding‑Agent sofort übernehmen kann. Legt exakt einen Issue an: Um ein Spec oder einen Plan in viele verknüpfte Tickets aufzuteilen, stattdessen „to‑tickets“ verwenden. Bearbeitet, schließt, triagiert oder sortiert niemals bestehende Issues. Außer der Erstellung verlinkt es den neuen Issue nur mit seinem Eltern‑Issue und Blockern und entfernt dann die verlinkten Einträge aus dem Body.
