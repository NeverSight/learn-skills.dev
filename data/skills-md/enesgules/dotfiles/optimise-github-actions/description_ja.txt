GitHub Actions をコストと速度の観点で最適化する。GitHub API から各ワークフローとジョブの課金済み分数と実時間を取得し、無駄を特定し、重要なチェックを削除せずにワークフローを変更する。典型的な無駄としては、プルリクエストですでに合格したテストスイートの再実行、すべての PR にマッチするパスフィルタ、規模の小さいマトリックスジョブ、キャッシュの未使用、ドラフトプッシュ、Docker ビルド、Windows および macOS の倍率、ハングしたジョブやボットなどがある。ユーザーが CI が遅い、または高コストである、と言ったとき、Actions のクォータを超えている、または超過料金を支払っている、"GitHub Actions の分数を減らしたい"、"CI を高速化したい"、"CI を安くしたい"、"なぜ CI が高額なのか" と質問したとき、あるいは CI の監査を求めたときにこの手法を使用してください。たとえユーザーが遅いジョブ一つやワークフローファイル一つだけ指摘した場合でも使用してください。
