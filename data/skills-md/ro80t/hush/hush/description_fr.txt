Impose une convention de nommage auto-documentant et des commentaires minimalistes, à fort signal. Renomme plutôt que de commenter chaque fois qu'un nom peut à lui seul porter le sens, limite les commentaires ordinaires à environ 3 lignes (plus est acceptable lorsqu'un saut de ligne au niveau d'une clause dépasse cette limite), rédige des commentaires de documentation complets avec des exemples d’usage uniquement pour les interfaces publiques/exportées, commente toujours les comportements non évidents quel que soit le niveau de visibilité, et ne commente une branche (if/for/while/switch) que lorsque sa condition ou son corps ne peuvent être déduits des noms impliqués. Utilise‑le pour TOUTE tâche de codage — écriture, ajout, refactorisation, correction ou révision de code — et chaque fois que l’utilisateur dit « hush », « comment style », « minimal comments », « self‑documenting code », ou se plaint de commentaires redondants, de bruit de commentaires ou de documentation manquante sur une API publique.
