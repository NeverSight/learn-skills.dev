自己記述的な命名と最小限で高信号なコメントを強制します。名前だけで意味が伝わる場合はコメントより名前をリネームし、普通のコメントは約3行までに抑えます（文節境界で改行が入る場合はそれ以上でも構いません）。公開／エクスポートされた API のみについて、使用例を含む完全なドキュメントコメントを書きます。可視性に関わらず、明らかでない動作は必ずコメントし、条件や本体が名前から推測できない場合に限り、分岐（if／for／while／switch）にコメントを付けます。あらゆるコーディング作業―作成、追加、リファクタリング、修正、コードレビュー―にこの方針を使用し、ユーザーが「hush」「comment style」「minimal comments」「self‑documenting code」と言ったり、冗長なコメントやコメントノイズ、公開 API のドキュメント不足を指摘したときにも適用してください。
