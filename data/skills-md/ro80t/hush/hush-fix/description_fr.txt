Audite les commentaires existants du code par rapport à l'échelle hush, de la même façon que hush‑review, puis applique directement les correctifs — renomme les identifiants pour supprimer les commentaires redondants, ajoute des commentaires de documentation aux API publiques non documentées, réduit les commentaires trop longs, met à jour ou supprime les commentaires obsolètes. Cible par défaut le diff actuel, ou un chemin/répertoire/branche/PR fourni en argument, en revenant à l’ensemble du dépôt s’il n’y a ni diff ni cible. À utiliser lorsque l’utilisateur dit « hush fix », « fix comments », « clean up comments », « improve existing comments », « /hush-fix », ou souhaite appliquer les constatations de qualité des commentaires plutôt que de simplement les lister.
