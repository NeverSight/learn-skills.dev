Verifica i commenti esistenti del codice rispetto alla scala hush, come hush‑review, quindi applica le correzioni direttamente — rinominando gli identificatori per rimuovere commenti ridondanti, aggiungendo commenti di documentazione alle API pubbliche non documentate, accorciando i commenti troppo lunghi, aggiornando o eliminando quelli obsoleti. Per impostazione predefinita si concentra sulla differenza corrente, o su un percorso/cartella/branch/PR specificato quando viene fornito come argomento, ricade sull’intero repository se non c’è differenza né obiettivo. Usalo quando l’utente dice “hush fix”, “fix comments”, “clean up comments”, “improve existing comments”, “/hush-fix”, o desidera che le segnalazioni sulla qualità dei commenti vengano applicate anziché semplicemente elencate.
