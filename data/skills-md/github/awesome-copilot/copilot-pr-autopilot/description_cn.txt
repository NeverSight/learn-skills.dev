Copilot 在你的 PR 上留下了 14 条审查评论——其中一半是鸡毛蒜皮的问题。几小时的修复 → 回复 → 解决 → 再请求，每一轮都会产生更多评论。这个技能实现了循环工程：通过 GraphQL 自动触发 Copilot 代码审查（无需 @copilot 提及），对每个未关闭的线程（Copilot、人类、advanced-security）进行分类处理，使用 修复/拒绝/升级 规则进行 triage，调度并行的修复子代理，遵循仓库的构建/测试/ lint 规范，每次迭代提交，回复并解决时引用已推送的 SHA，然后重新触发，直到 HEAD 被审查完毕且没有线程在等待代理回复（剩余未关闭的线程会明确交由人工处理——升级的拒绝、设计权衡）。你合并一个干净的 PR；机器人会执行它。触发短语：“address copilot comments”，“run a copilot review loop”，“fix this PR”，“iterate on copilot feedback”。与仓库无关，使用 gh CLI + PowerShell。完整的自动驾驶需要仓库的 Triage/Write 权限；外部 PR 作者则使用单次迭代模式并可手动重新触发（UI 🔄 或实质性提交推送）。
