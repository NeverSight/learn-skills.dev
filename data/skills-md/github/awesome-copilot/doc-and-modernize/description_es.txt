Dos flujos de trabajo relacionados para una base de código clonada localmente, en una sola habilidad. El modo Documentación produce un único documento de arquitectura integral y verificable, principalmente leyendo los archivos en disco (local‑first); úsalo siempre que el usuario quiera entender, mapear, documentar, investigar o incorporarse a una base de código (“investigar este repositorio”, “redactar la arquitectura”, “profundizar en la arquitectura”, “documentar cómo funciona esta base de código”, “mapear el diseño del sistema”, “crear un documento de incorporación”). El modo Modernización genera un plan por fases para modernizar, migrar, actualizar o reescribir un sistema legado (“modernizar esto”, “planificar la migración”, “¿cómo lo reescribiríamos? ”, “¿cómo abandonamos este stack legado?”); si aún no existe un documento de arquitectura, primero ejecuta el modo Documentación y luego continúa directamente con el plan. Asume que el stack legado puede estar muerto, realiza un spike de viabilidad con tiempo limitado y elige el peldaño más alto alcanzable en una escalera de seguridad en lugar de exigir una puerta de CI heredada totalmente verde desde el principio.
