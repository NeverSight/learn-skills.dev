Deux workflows liés pour une base de code clonée localement, en une seule compétence. Le mode Documentation produit un document d'architecture unique, complet et vérifiable, principalement en lisant les fichiers sur le disque (local‑first) — utilisez‑le chaque fois que l'utilisateur veut comprendre, cartographier, documenter, rechercher ou s'intégrer à une base de code (« rechercher ce dépôt », « rédiger l'architecture », « faire une plongée approfondie dans l'architecture », « documenter le fonctionnement de cette base de code », « cartographier la conception du système », « créer un document d'intégration »). Le mode Modernisation génère un plan progressif pour moderniser, migrer, mettre à jour ou réécrire un système hérité (« moderniser cela », « planifier la migration », « comment réécririons‑nous cela », « comment sortir de cette pile legacy ») ; si aucun document d'architecture n'existe encore, il exécute d'abord le mode Documentation, puis poursuit directement vers le plan. Il suppose que la pile legacy peut être obsolète, lance un spike de faisabilité à durée limitée, et choisit le niveau le plus élevé atteignable sur une échelle de sécurité plutôt que d'exiger une porte CI legacy entièrement verte dès le départ.
