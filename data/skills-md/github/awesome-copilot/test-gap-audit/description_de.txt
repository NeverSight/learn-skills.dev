Führe ein schreibgeschütztes Audit für fehlende, schwache, veraltete oder falsch eingrenzte Testabdeckung durch. Wenn der Nutzer keinen Umfang angibt, prüfe das gesamte Repository und identifiziere wichtige Codepfade, Routen, Features, Services, Workflows und Schnittstellen, die keine angemessenen Tests haben. Wenn der Nutzer ein Feature, PR, Branch, eine Route, einen Workflow, einen Service, einen Bug‑Fix, eine API, einen sicherheitsrelevanten Pfad oder eine riskante Codeänderung nennt, konzentriere dich nur auf diesen spezifischen Umfang. Verwende dies, wenn der Nutzer fragt, welche Tests fehlen, ob die Abdeckung ausreichend ist, welche Regressionstests hinzuzufügen sind oder wie man beweist, dass eine Änderung sicher ist. Dies ist kein allgemeines Bug‑Audit und keine Sicherheitsüberprüfung; es bewertet, ob das Verhalten durch Tests abgedeckt ist.

Bitte antworte stets in der Sprache des Nutzers.
