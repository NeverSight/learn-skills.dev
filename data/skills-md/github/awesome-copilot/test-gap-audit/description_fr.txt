Exécutez un audit en lecture seule pour détecter les couvertures de tests manquantes, faibles, obsolètes ou mal ciblées. Si l'utilisateur ne précise pas de périmètre, auditez l’ensemble du dépôt et identifiez les chemins de code, routes, fonctionnalités, services, workflows et contrats importants qui manquent de tests appropriés. Si l'utilisateur indique une fonctionnalité, une PR, une branche, une route, un workflow, un service, une correction de bug, une API, un chemin sensible à la sécurité ou une modification de code risquée, concentrez‑vous uniquement sur ce périmètre spécifique. Utilisez cet audit lorsque l'utilisateur demande quels tests manquent, si la couverture est suffisante, quels tests de régression ajouter ou comment prouver qu’un changement est sûr. Ce n’est pas un audit général de bugs ni une revue de sécurité ; il évalue uniquement si le comportement est couvert par des tests.

Veuillez toujours répondre dans la langue de l’utilisateur.
