Esegui un audit in sola lettura per la copertura dei test mancanti, deboli, obsoleti o con scoping errato. Se l'utente non specifica uno scope, esamina l'intero repository e individua percorsi di codice, route, funzionalità, servizi, workflow e contratti importanti che non hanno test adeguati. Se l'utente indica una funzionalità, PR, branch, route, workflow, servizio, correzione di bug, API, percorso sensibile alla sicurezza o modifica di codice rischiosa, concentrati solo su quello specifico scope. Utilizza questo audit quando l'utente chiede quali test mancano, se la copertura è sufficiente, quali test di regressione aggiungere o come dimostrare che una modifica è sicura. Non si tratta di un audit generico di bug né di una revisione di sicurezza; valuta se il comportamento è coperto dai test.

Rispondi sempre nella lingua dell'utente.
