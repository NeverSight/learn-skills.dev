Utilisez-le lors de la migration d’une application Meteor existante vers Rspack (Meteor 3.4+), ou de la mise à niveau de Rspack 1 vers 2 sur Meteor 3.6 bêta. Déclencheurs sur les imports imbriqués, les points d’entrée mainModule, les applications serveur‑only, le remplacement de fourseven:scss / meteor/less / coffeescript / jorgenvatle:vite / zodern:melte par des chargeurs, le prétraitement Svelte/TypeScript ou les échecs du plugin Lingui SWC après la mise à jour, l’interopérabilité des importations par défaut CommonJS, module.exports dans les graphes client, les bibliothèques natives Node dans le code du navigateur, _build / build‑assets / build‑chunks, .meteorignore masquant les fichiers de transfert, les chunks dynamiques sous ROOT_URL, meteor.modules pour CSS/HTML, la migration de resolve.symlinks ou resolve.alias, les mises à jour automatiques des dépendances et les builds CI/Docker immuables. Utilisez cette compétence lorsque l’utilisateur pose des questions sur la compatibilité de migration ou le remplacement d’un plugin de construction par Rspack. Pour la configuration d’une nouvelle application et les aides rspack.config.js, utilisez plutôt meteor-modern-build-stack.
