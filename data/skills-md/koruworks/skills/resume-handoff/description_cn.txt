在一个全新的会话中从 `docs/<feature>/HANDOFF.md` 中接手未完成的工作——你是手交接文档所针对的代理人，并在信任它之前先进行验证。当用户调用 `/resume-handoff <feature>`、指向 `HANDOFF.md`，或要求继续、恢复、或在上一次会话停下的计划或路线图（由 `execute-plan`、`execute-roadmap` 或 `build-feature` 构建）上继续时使用，例如“接手手交接并在我睡觉时继续”。读取项目的代理人定位和手交接内容，将其声明与 Git 和代码进行比对，检查待合并的内容并提出范围——随后停止并请用户确认合并以及工作计划，或在进行任何树形结构更改前给出新指令。确认后，会删除已使用的手交接文件，通过 `merge-branch` 门进行合并，继续执行 `execute-plan` 或 `execute-roadmap`，若仍有工作未完成则在末尾写入新的手交接。编写手交接时使用 `write-handoff`；结束已完成工作时使用 `close-plan` 或 `close-roadmap`。请始终使用用户的语言作答。
