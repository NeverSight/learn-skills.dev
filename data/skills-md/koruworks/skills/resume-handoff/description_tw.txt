在全新會話中從 `docs/<feature>/HANDOFF.md` 取得未完成的工作 — 你是該交接文件所針對的代理人，必須先驗證它再信任。當使用者呼叫 `/resume-handoff <feature>`、指向 `HANDOFF.md`，或要求繼續、恢復、或在先前由 `execute-plan`、`execute-roadmap` 或 `build-feature` 建立的計畫或路線圖中「從上次會話停止的地方」繼續時使用，例如「把交接接起來，我睡覺時繼續」。先讀取專案的代理人定位與交接內容，將其聲明與 Git 及程式碼對照，檢查待合併的變更並提出範圍建議 — 然後暫停，請使用者確認合併與工作計畫，或提供新指示，才會對程式樹進行任何變更。確認後，會刪除已使用的交接文件，透過 `merge-branch` 門檻執行合併，繼續執行 `execute-plan` 或 `execute-roadmap`，若仍有未完成工作，則在最後寫入全新的交接文件。若要撰寫交接文件，使用 `write-handoff`；若要結束已完成的工作，使用 `close-plan` 或 `close-roadmap`。
