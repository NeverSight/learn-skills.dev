Clore un <DOC>.final.md terminé — intégrer ce qui a atterri dans les documents déjà existants, transférer ce qui reste dû dans <DOC>-V2.rev1.md, puis supprimer les artefacts de planification dont l’arborescence n’a plus besoin. À utiliser quand l’utilisateur invoque /close-plan <feature>, ou demande de nettoyer ou de retirer les docs d’une petite fonctionnalité après l’exécution de execute‑plan ou build‑feature. Examiner ACCEPTANCE.md point par point avant de qualifier quoi que ce soit d’atterri, puis classer chaque phase comme atterri, en attente, différé ou abandonné. Le petit frère de close‑roadmap — fonctionne pour n’importe quel préfixe (PLAN, TECHNICAL, …) ; un plan ne mérite généralement pas son propre dossier de documentation permanente, donc le défaut est d’ajouter un paragraphe à une page existante plutôt que d’en créer une nouvelle.
