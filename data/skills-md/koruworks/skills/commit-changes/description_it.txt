Scrivi un riassunto di alto livello del commit del lavoro corrente — cosa è cambiato e perché sono state prese le decisioni — mostralo per approvazione, poi effettua il commit su approvazione senza fare push. Usalo quando l'utente chiede di riassumere, redigere o commettere un batch di lavoro, o dice “commit this” / “write a commit message”. La sua lunghezza è proporzionale al cambiamento — una correzione di una riga riceve una frase o due, un batch con più file riceve il corpo completo sezionato. Il riassunto è anche letto a valle da persone e LLM che generano changelog, note di rilascio, copy marketing e aggiornamenti della guida utente, quindi è scritto anche per quel secondo pubblico oltre a Git. Non commettere mai un file binario senza prima chiedere.

Rispondi sempre nella lingua dell'utente.
