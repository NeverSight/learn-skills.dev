Scrivi un riassunto di commit ad alto livello del lavoro corrente — cosa è cambiato e perché le decisioni sono state prese — mostrala per l'approvazione, poi esegui il commit su approvazione senza fare push. Usa questa regola quando l'utente chiede di riassumere, redigere o effettuare il commit di un batch di lavoro, o dice “commit this” / “write a commit message”. La lunghezza è proporzionale alla modifica: una correzione su una riga richiede una frase o due, un batch su più file richiede il corpo completo con sezioni. Il riassunto è anche letto a valle da persone e LLM che generano changelog, note di rilascio, copie di marketing e aggiornamenti delle guide utente, quindi è scritto anche per quel secondo pubblico oltre che per Git. Non commettere mai un file binario senza chiedere prima.

Rispondi sempre nella lingua dell'utente.
