Diseña cómo se construye una característica como una conversación de ingeniería con el usuario antes de que exista cualquier documento de planificación — descubran la arquitectura juntos, encuentren qué tiene ya la base de código para aprovechar, cuestionen la complejidad, registren cada decisión con su motivo y redacten docs/<feature>/TECHNICAL.rev1.md solo cuando el usuario indique que el diseño está listo. Úsalo cuando el usuario invoque /draft-technical <feature>, o pida diseñar, definir la arquitectura o reflexionar sobre cómo construir una característica, subsistema, integración, migración o cambio de infraestructura. Este es el primer paso técnico para una nueva característica o una hoja de ruta — no tendrá la imagen completa, y es el fuerte comienzo del que se derivan el plan de build‑feature y los hitos del draft‑roadmap.
