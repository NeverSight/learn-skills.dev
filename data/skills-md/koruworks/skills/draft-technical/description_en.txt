Design how a feature is built as an engineering conversation with the user before any plan document exists — discover the architecture together, find what the codebase already has to build on, challenge complexity, record every decision with its reason, and write docs/<feature>/TECHNICAL.rev1.md only when the user says the design is ready. Use when the user invokes /draft-technical <feature>, or asks to design, architect, or think through how to build a feature, subsystem, integration, migration or infrastructure change. This is the first technical step for a new feature or a roadmap — it will not have the whole picture, and it is the strong start that build-feature's plan and draft-roadmap's milestones are then derived from.
