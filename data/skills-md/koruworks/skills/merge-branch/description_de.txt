Änderungen von einem anderen Branch zusammenführen, während sie anhand der Projektprinzipien geprüft werden — ein Merge ist ein Review‑Tor, keine mechanische Operation. Verwenden, wenn der Benutzer bittet, einen Branch zu mergen, Änderungen aus einem anderen Branch zu übernehmen oder einen Merge zu lösen. Markiert unklare Absichten, unnötige Komplexität und wahrscheinliche Fehlerquellen vor dem Merge, fragt den Benutzer nach produktrelevanten Entscheidungen, die ein Konflikt klären würde, und empfiehlt, zuerst den Haupt‑Integrations‑Branch in den anderen Branch zu mergen, wenn das die einfachere Richtung ist.
