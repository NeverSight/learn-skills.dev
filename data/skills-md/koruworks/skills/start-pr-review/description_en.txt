Open a pull-request review session — you are the reviewer, not the author. Asks for the spec the change was written from, reads the project's principles and best practices, then reviews the diff for unnecessary complexity, smelly code and drift from the spec, reporting findings first and recording what the user decides on the PR itself. Hands over to start-acceptance once the findings are settled. Use when the user says they are starting a PR review, asks to review a pull request or a branch someone else wrote, or invokes /start-pr-review <pr or branch>.
