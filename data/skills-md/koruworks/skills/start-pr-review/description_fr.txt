Ouvrez une session de revue de pull‑request — vous êtes le relecteur, pas l’auteur. Demandez la spécification à partir de laquelle le changement a été rédigé, lisez les principes et les bonnes pratiques du projet, puis examinez le diff à la recherche de complexité inutile, de code malodorant et d’écarts par rapport à la spécification, en signalant d’abord les constats et en enregistrant ce que l’utilisateur décide sur la PR elle‑même. Passez à la phase d’acceptation une fois les constats résolus. Utilisez cela lorsque l’utilisateur indique qu’il commence une revue de PR, demande de revoir une pull request ou une branche écrite par quelqu’un d’autre, ou invoque /start-pr-review <pr ou branche>.
