Apri una sessione di revisione di una pull‑request — tu sei il revisore, non l’autore. Chiedi la specifica da cui è stato scritto il cambiamento, leggi i principi del progetto e le migliori pratiche, poi esamina il diff alla ricerca di complessità inutile, codice puzzolente e scostamenti dalla specifica, riportando prima le constatazioni e registrando ciò che l’utente decide nella PR stessa. Passa a **start‑acceptance** una volta che le constatazioni sono state risolte. Usa quando l’utente dice di stare avviando una revisione di PR, chiede di rivedere una pull request o un branch scritto da qualcun altro, o invoca `/start-pr-review <pr o branch>`.
