풀 리퀘스트 검토 세션을 시작합니다 — 당신은 리뷰어이며, 작성자는 아닙니다. 변경 사항이 작성된 사양을 물어보고, 프로젝트의 원칙과 모범 사례를 읽은 뒤, 차이점을 검토하여 불필요한 복잡성, 냄새 나는 코드, 사양에서 벗어난 부분을 찾아보고, 먼저 발견 사항을 보고하고 사용자가 PR 자체에 대해 결정한 내용을 기록합니다. 발견 사항이 정리되면 start‑acceptance 단계로 넘깁니다. 사용자가 PR 검토를 시작한다고 말하거나, 다른 사람이 만든 풀 리퀘스트나 브랜치를 검토해 달라고 요청하거나, `/start‑pr‑review <pr or branch>`를 호출할 때 사용합니다.
