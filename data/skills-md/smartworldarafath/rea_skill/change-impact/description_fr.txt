Réalisez une analyse d’impact fondée sur des preuves avant de modifier le code, les données, les interfaces ou les documents de gouvernance, puis comparez l’impact prévu avec le diff réel après implémentation. Cela couvre les chemins d’appel, les données et le schéma, les contrats d’API, les tests, la documentation, les ADR, le déploiement, la migration et le rollback. Utilisez‑le pour les changements inter‑modules ou à haut risque, les migrations de bases de données, l’authentification, les interfaces publiques, les questions de rayon d’impact, les vérifications pré‑changement et l’alignement post‑implémentation.
