# Vibe UI Polish：让 AI 做的前端更有质感

整理自 @bruc3van 推荐的 8 位设计师（枯白 @Kubai087、Zayn @ZaynHao、伊恩 @ianneo_ai、丁一 @dingyi、弦 @Xian0063、妍妍 @yanliudreamer、Rico @ricouii、Remix @remixdesigner）在 X 上的帖子。每条规则后面的【】标出出处，原帖链接见文末和 `sources.md`。

## 0. 总原则：先做判断，再做减法

1. **AI 默认会往上加东西，你要负责删。** 每个元素都问一句："它真的有必要存在吗？" AI 最爱加的是多余文案、分割线和图标。【伊恩·10 条老规矩；妍妍·如何用 AI 设计】
2. **从整体出发，不要局部打补丁。** 先列出所有约束（给谁用、用户来做什么、最重要的信息是什么），再出方案。【妍妍；伊恩·AI 越强，你的判断越值钱】
3. **先定美术方向，再写代码。** 至少确定这几项：
   - 一个关键词
   - 一个视觉母题
   - 配色：底色、文字色、1 个强调色，以及强调色用在哪
   - 字体
   - 页面焦点

   方向没定，AI 只会回到它见过最多的模板。【弦·文章 2】
4. **不要直接抄 AI 模板。** 参考已经上线的真实网站，弄清它为什么这样排版、它的动效在帮用户做什么。【伊恩】
5. **借用现成的组件库和设计系统，不要每处都重新造轮子。** 把好组件库的代码和样式规范直接喂给 AI，边界给清楚，它就能搭得规规矩矩。如果项目已有 Button、token 等，就在原有组件上改，不要另起一套。【伊恩；妍妍；枯白·001】
6. **风格要匹配产品类型。** 工具类产品要冷静、好读；活动页要有冲击力。极简布局如果靠大图撑场面，而你手上没有好图，就别照搬。【伊恩】
7. **多轮迭代。**
   - 先把整页搭出来，之后每轮只改一件事。
   - 让 AI 截图自查 2–4 轮，最后由人来看一眼。
   - AI 的自评不算数，要由真实用户来验证。【弦；伊恩；Zayn：10 条提示词只是基础，要做好需要很多轮】
8. **四种稀缺能力：克制、层次、一致性、判断力。** 学的是网格、字号比例和信息结构，不是模仿表面风格。【妍妍·Taste】

## 1. AI 味清单：先找出来、再删掉

在页面里搜下面这些特征，见到就删或改：

**视觉**
- 紫色或紫蓝渐变、渐变按钮、彩色图标、一张卡片一种颜色【丁一；弦；伊恩】
- 卡片左边缘的彩色竖线【Zayn；丁一】
- 卡片套卡片；每个标题上面放一个 emoji【弦】
- 装饰性发光球、弥散光晕；大卡片上的大阴影【伊恩】
- 细节多到过头：分割线、多层阴影、半透明叠色、到处带边框的容器【丁一】
- 彩色方块里放图标（colored square icons）【弦】
- 线条和边框粗细不统一，该用 0.5px 的地方用了 1px【丁一；Zayn】
- 嵌套的地方没有做同心圆角【丁一；Zayn；枯白】
- 字号多于 4 种，或者最小字号低于 12px；hero 标题大得离谱【丁一；Zayn】
- 不一致：比如一个页面里有 28 种字号、17 种圆角，还有半像素尺寸【弦】
- 下拉菜单按钮上的下拉小箭头。丁一认为这是"最恶心最严重的"一条，几乎所有人都没修。丁一没有给具体修法，建议检查下拉按钮是否真的需要这个箭头，箭头的大小和对齐是否精修过。

**字体**
- 三大 slop 字体：Instrument Serif、Space Grotesk、Bricolage Grotesque【丁一】
- 滥用等宽字体、滥用斜体和标签【丁一】
- 全大写的小标题、标题上方的小眉标（eyebrow）、英文眉标【丁一；弦·Hallmark sloplint】
- Inter / Roboto / Lato / Poppins 这类大众字体也会带来"AI 页面感"，可以考虑较新的字体【Rico】

**结构**
- 模板 hero："NEW" 胶囊 + 居中衬线大标题 + 一个高亮词【弦】
- 模板落地页：大标题 + 三张功能卡 + 按钮，以及一律居中的布局【伊恩；弦】
- 代码面包屑、章节编号【丁一】
- 页尾硬塞一个订阅框【弦·Hallmark sloplint】
- 滚动动效过多，过渡生硬、不收敛【丁一】
- 图表总是画得过分详细【丁一】
- 千篇一律的 ASCII、dither、莫奈油画风背景（这是当下的流行风格，不是默认答案）【丁一；Rico】

**文案**
- 用中圆点 "·" 当分隔符【Zayn；丁一】
- 冗余的解释性描述文字、正文里塞 emoji【Zayn；丁一】
- 过度口语化，或者自己造词【Zayn；丁一】
- 假数据、假评价、假 logo 墙，比如"10,000+ 满意客户"【伊恩；弦·Hallmark】
- 只把一个词染成强调色【弦·Hallmark】
- 借用别家品牌的素材【弦】

## 2. 间距与布局

- 间距、内边距、gap 全部落在 4px 网格上，以 8 为主；不要出现半像素【枯白·004；弦】
- 不要省间距、对齐、空状态和报错文案上的功夫【伊恩】
- 优先做光学对齐，不只是数值对齐。常见问题：按钮文字偏高 1px、卡片内容没对齐【Zayn；伊恩】
- 页面上最重要的东西必须最显眼，写之前先说清楚"这页给谁看、要他做什么"【伊恩】
- 每屏只放 1 个主按钮【弦】
- 尽量减少需要用户做判断的交互；必须做判断时，放在用户本来就要做选择的地方，并重新排一遍信息优先级【Zayn；妍妍：好设计是替用户消灭不值得思考的选择】
- 一组尺寸不同的图形放进同一个格子时，不要只做简单居中。细长的显得太小，扁平的显得太满，要按视觉面积微调缩放【伊恩·100 个微缩世界；伊恩·立体图标】
- 空白是给眼睛休息的地方，不需要拿装饰填满【伊恩】

## 3. 嵌套圆角（同心圆角）【枯白·004；Zayn；弦】

- 公式：**内圆角 = 外圆角 − 内边距**，内外圆角共用一个圆心。
- 从外往里算：弹窗/卡片 → 面板、输入框、按钮 → chip。
  - 例 1：弹窗圆角 32、内边距 16，内层圆角 = 16。
  - 例 2：圆角 16 的面板里放 chip，内边距 8，chip 圆角 = 8。
- 同一层级的盒子用同一个圆角。最小不低于 4。胶囊和圆形保持全圆。
- 全站只用 2–3 档圆角【弦】。项目有 radius token 就用 token。
- 图片放进圆角卡片时，如果图片圆角和外框一样（例如都是 16），角上会露缝，要按公式减【伊恩】。
- 不要到处撒圆角和阴影。必须用时，数值要符合它的功能场景【Zayn】。
- 枯白本人也说过，只在关键元素上严格执行就行，不必每处都死抠。
- 可选做法：连续曲率圆角（超椭圆）。目前只有 Chrome/Edge 139+ 支持，其他浏览器会回退为普通 border-radius：
  ```css
  @supports (corner-shape: superellipse(1.25)) {
    :where(*) { corner-shape: superellipse(1.25); }
    .pill, .avatar { corner-shape: round; }
  }
  ```
- 改完后列出每处改动，格式是"元素：旧值 -> 新值"。

## 4. 字体与排版

- **字号最多 4 种，最好 3 种；最小 12px。** 营销页可以另加 1–2 个展示字号。层级不够时，用字重、颜色和间距来拉开，不要再加字号【Zayn；弦；丁一】
- 层级靠扎实的排版、字重和留白，不靠 3D 和动效堆砌【伊恩·Deji 个站】
- 中文网站的 font-family 规则是"先西后中、兼顾主流系统、最后用 sans-serif 兜底"【Rico】：
  ```css
  :root {
    --font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
      "Helvetica Neue", Helvetica, Arial,
      "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei",
      "Noto Sans CJK SC", "Noto Sans SC", "Source Han Sans CN", sans-serif;
    --font-mono: "JetBrains Mono", "SF Mono", ui-monospace, Menlo, Consolas,
      "Liberation Mono", "Courier New", monospace;
  }
  body { font-family: var(--font-sans); }
  code, pre { font-family: var(--font-mono); }
  ```
  - 西文字体必须写在中文字体前面，否则中文字体自带的英文字母和数字会盖掉你设定的西文字体。
  - 中文字体写英文名，例如写 "Microsoft YaHei"，不写"微软雅黑"。
  - 名字里有空格的字体必须加双引号。
  - 不声明字体时，浏览器用的是"默认字体"，不一定是系统字体。
- 选字体时看字重、字宽、字间距，以及在不同字号下的表现。同一段文字试 3–5 种字体再比较【妍妍·Fontshare】
- 收尾时人工看一遍标题是否折行、末行是否只剩一个字【弦】

## 5. 颜色

- **界面只用黑白灰，颜色留给照片和内容。** 伊恩把这句话当作万能起手提示词。廉价感往往来自颜色太多：渐变按钮、彩色图标、每张卡片一种颜色，每个元素都在抢眼【伊恩】
- 只用 **1 个强调色**，并规定它只用在哪里，比如只用在结果或下一步操作上【弦；枯白·Bento/空状态】
- 想用色板，可以统一换成 **Radix UI Colors**，并按它 12 阶的用途规范来用（背景、交互态、边框、纯色、文字各有对应档位）。也可以挑 3–5 个有个性的颜色，例如米白底 `#f6f4f0`【Zayn】
- 暗色模式用中性灰，不要偏蓝，例如 surface `rgba(34,34,34,.96)`【枯白·002】
- 渐变背景想要高级感【伊恩·ElevenLabs 拆解】：
  - 色块：4–5 团大色块，边缘完全糊开。
  - 配色：只用色环上相邻的颜色，上浅偏冷、下深偏暖。
  - 噪点：最上面盖一层 1px 灰色噪点。它能打散色阶，带来纸张或胶片的质感，避免塑料感。
- 图标和插画里的颜色【枯白·AI 图标修正】：
  - 高光不能只是把颜色调亮，否则会发灰。
  - 阴影用相邻色相的深色，不用黑色。
- 用 Coolors 之类的工具时，要分析配色的冷暖、明度对比和饱和度，不要只是随机生成【妍妍】

## 6. 阴影与边框

- **阴影只给浮层**（菜单、弹窗、浮动卡片），平铺的卡片用 1px（或 0.5px）细边框，不要大阴影【弦；伊恩】
- 线条和边框用 0.5px，并且全站统一粗细【Zayn；丁一】
- 参考值【枯白·002 菜单；Bento】：
  - 浮层边框：`rgba(0,0,0,.14)`
  - 浮层阴影：`0 18px 34px rgba(15,23,42,.12), 0 2px 4px rgba(15,23,42,.05), inset 0 1px 0 rgba(255,255,255,.74)`
  - 卡片：`0 0 0 1px rgba(47,42,34,.06), 0 8px 20px -10px rgba(47,42,34,.25)`

## 7. 按钮（有触感的按钮）【枯白·001】

- 只用中性灰，不加玻璃高光，不加发光。
- 分 5 种变体：primary / secondary / tertiary / ghost / text。
- 由 5 层组成：
  1. 按钮面：渐变，顶部比底部亮 6–8%
  2. 边缘：1px 描边，颜色比按钮面深一档
  3. 顶部高光：`inset 0 1px 0` 白色
  4. 底部暗边：`inset 0 -1px 0`
  5. 投影：两层，`0 1px 2px` + `0 4px 10px -3px`
- Hover：投影加大到 `0 8px 16px -5px`。
- 按下：`translateY(1px)`，渐变上下翻转，改用内阴影。静止态和按下态的 inset 层数保持一致，阴影才能平滑过渡。
- 过渡时长：transform 120ms、阴影 140ms、颜色 160ms。
- md 尺寸：高 40px、`padding: 0 18px`、圆角 10px、字重 600。其他尺寸用 `u = 字号 / 14` 等比缩放。
- 改项目里已有的 Button，不要新造一个。

## 8. 图标

- 全站图标的线宽必须一致，不要 1.5px 和 2px 混用【伊恩；妍妍：精致感往往藏在图标的线宽、圆角、比例和视觉重量是否统一】
- 一整套界面只用一个图标体系（例如 Remix Icon 线性图标），不要东拼西凑【妍妍；枯白·空状态】
- 外框一样大的细长图形看起来偏小，要单独加宽，让整组的视觉大小接近【伊恩·立体图标】
- AI 生成的 App 图标【枯白】：
  - 减少不必要的体积感，主体上不要堆高光和阴影，用简单的线性或径向渐变。
  - 背景用简洁的线性渐变，不加弥散光和纹理。
  - 除非明确要求，不加内发光和内阴影。
- 细节参考 Apple 的做法：新 Preview 图标给 Clear 模式单独做了一层，因为直接把默认模式的图转过去会显得脏。不同主题或模式下的图形，不要只靠自动转换【Remix】

## 9. 动效

- **默认少放动效。** 一定要加时，`ease-out` + `250ms` 是不错的基础设定【Zayn】
- 全页的动效、渐变、弹窗各控制在 1–2 处【伊恩】
- 动效要帮用户理解状态变化。检查三件事：由什么触发、节奏如何、是否真的在帮用户【妍妍·React Bits】
- 进场用 ease-out。下拉菜单从触发点开始、由 0.96 缩放展开。按钮按下缩到 0.97。toast 堆叠显示。过长的名字截断【弦引用 Emil Kowalski skills】
- 实现规则【枯白·001/002/005/Bento】：
  - 用 transform 移动，不改 layout。
  - 每种动作用自己的曲线；所有时长写成具名常量。
  - 曲线参考：ease-out `cubic-bezier(.22,1,.36,1)`；弹簧 `cubic-bezier(.34,1.4,.64,1)`；菜单展开 `cubic-bezier(0.2,1.45,0.35,1)`（opacity 170ms，transform 360ms）。
  - 单个动作 250–600ms，整段场景控制在 3s 左右。
  - 元素进入视口约 70% 时再播放。静止态就是动画的最后一帧。
  - `prefers-reduced-motion` 下直接显示最终帧，或只保留最必要的提示。
  - 装饰性动画区域加 `aria-hidden`。
- **级联菜单**【枯白·002】：
  - 安全三角区；打开延迟 220ms；安全窗口每 80ms 复查一次，最长 1200ms；关闭延迟 360ms；拖拽悬停 420ms 后打开。
  - 每级菜单宽 210–260px、内边距 6px、圆角 12px、`backdrop-filter: blur(18px)`。
  - 行高 32px、行圆角 8px；文字 14px、字重 500；图标 18px。
  - 行高亮由组件状态驱动，不依赖 CSS `:hover`。
- **拖拽排序**【枯白·005】：
  - 光标：hover 时是 pointer，拖动时是 grabbing。
  - 被拖的项抬起；在竖向列表里缩到约 90%。
  - 插入线画在间隙里，颜色约为文字色的 15%，从中间向两端长出。
  - 周围元素依次让位：位移 = A×0.7ⁿ（图标 A≈10px，卡片 A≈8px），延迟 = 24ms×n，用弹簧在约 0.25s 内收住。
  - Esc 取消拖动，并支持键盘排序。reduced-motion 下只保留插入线。
- 酷炫效果（流光、ASCII、dither）只用来撑氛围，不能当主角【伊恩引 23rd 文档】。Dither/ASCII 参考值：ASCII 遮罩 90、尺寸 37；Dither 遮罩 88、尺寸 15。遮罩的作用是让效果读起来像质感，而不是噪点【枯白·003】。

## 10. 文案

- review 一遍全部文案：
  - 是否符合这个界面面对的人群；
  - 是否好懂但不过度口语化；
  - 长短是否适合功能场景；
  - 有没有冗余和自造词【Zayn】。
- 删掉解释性描述、"·" 分隔符、正文 emoji 和眉标【Zayn；丁一】。
- 不写假数据、假背书、假客户数【伊恩；弦】。
- CTA 文案想清楚是在描述操作还是强调收益；主次按钮层级要清楚，并降低用户的犹豫【妍妍·CTA Gallery】。
- 小白用户的"基础操作"可能是知识盲区，安装、权限这类流程要替用户多走一步【Remix·ChatGPT dmg 安装】。

## 11. 状态：空、错、加载

- 空状态和报错文案不能省【伊恩】。
- **空状态插图用"缩小版的真实产品 UI"，不用插画**【枯白·SVG 空状态】：
  - 面板底色 `#fafafa`，加 45° 斜纹。
  - 用占位条代替文字，图标用 Remix 线性图标。
  - 只在下一步操作上用 1 个强调色。
  - 不画文字和人物，不用半透明叠层。
  - 颜色全部写成 CSS 变量，并提供暗色值。
- 也可以用插画缓和空状态的挫败感。先想清楚：哪个场景需要插画、要传达什么情绪、它是否真的帮用户理解了当前状态【妍妍·Blush】。
- AI 产品要考虑：何时让 AI 主动行动、何时需要用户确认、如何让 AI 的行为透明可控（参考 shapeof.ai 的 AI UX Patterns）【妍妍】。

## 12. 响应式与移动端

## 14. 现成提示词（直接复制给 Codex / Claude Code）

**A. 一键去 AI 味（基础版，改写自 Zayn 的 10 条）**
```
请按以下规则优化当前页面 UI，改完列出每处"元素：旧值 -> 新值"：
1. 移除所有中点"·"分隔符。
2. 删除冗余的解释性描述文本。
3. review 全部文案，使其符合目标用户：易懂、不过度口语化、长短合适、不造词。
4. 颜色全部换成 Radix UI Colors，并按其 12 阶用途规范使用。
5. 做光学对齐；所有嵌套元素使用同心圆角（内圆角 = 外圆角 − 内边距）。
6. 线条和边框统一用 0.5px。
7. 尽量去掉动画；必须保留的用 ease-out 250ms。
8. 字号不超过 4 种（最好 3 种），最小 12px；层级用字重、颜色、间距拉开。
9. 减少需要用户判断的交互，必要时放到用户本来就要做选择的位置；重排信息优先级。
10. 不要随意加圆角和阴影，尤其不要给卡片左边缘加彩色竖线。
```

**B. 颜色收敛（伊恩）**
```
界面只用黑白灰，颜色留给照片和内容。去掉渐变按钮、彩色图标和每张卡片不同的底色；全页只保留 1 个强调色，只用在主操作上。
```

**C. 嵌套圆角（枯白 004，精简）**
```
审查所有嵌套容器的圆角：从最外层（弹窗/卡片）向内计算，内圆角 = 外圆角 − 内边距，内外同圆心；同一层级用同一个圆角；最小 4；胶囊和圆形保持全圆；padding、gap、圆角都落在 4px 网格。项目有 radius token 就用 token。可选：@supports (corner-shape: superellipse(1.25)) 下全局启用超椭圆，胶囊用 corner-shape: round。完成后列出"元素：旧值 -> 新值"。
```

**D. 先定方向再动手（弦·三步法）**
```
动手前先给我一份美术方向：关键词、视觉母题、配色（底色/文字/1 个强调色及其用途）、字体、页面焦点。
然后遵守规范：正文字号 ≤4 种（营销页另加 1–2 个展示字号），不用半像素；间距用 4 的倍数（以 8 为主）；圆角 2–3 档；阴影只给浮层，卡片用 1px 边框；每屏 1 个主按钮；不要"NEW 胶囊 + 居中衬线标题 + 高亮词"的 hero；不要彩色方块图标。
完成后在浏览器里截图自查并修改 2–4 轮，再交给我看。
```

**E. AI slop 自查（丁一清单）**
```
逐条检查并修掉以下 AI slop：到处的标签和斜体；Instrument Serif / Space Grotesk / Bricolage Grotesque；滥用等宽字体；过多的分割线、多层阴影、半透明叠色、带边框容器；过度详细的图表；口语化或自造词文案；代码面包屑、章节编号、标题上方眉标；紫色渐变；全大写小标题；中点分隔符；正文 emoji 和无用文字；过大的 hero 字号；解释性描述；未做同心圆角；边框粗细不统一；生硬过多的滚动动效；超过 4 种字号或小于 12px；卡片左侧彩色竖线；下拉按钮上没精修的下拉小箭头。
```

**F. 中文字体栈（Rico）**
```
把全站字体换成：--font-sans 先西文（-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Helvetica, Arial），后中文（"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans CJK SC", "Noto Sans SC", "Source Han Sans CN"），最后 sans-serif 兜底；代码用 --font-mono（"JetBrains Mono", "SF Mono", ui-monospace, Menlo, Consolas, "Liberation Mono", "Courier New", monospace）。中文字体写英文名，带空格的名字加双引号。
```

**G. 喂组件库（伊恩 / 妍妍）**
```
以下是 <组件库> 的组件代码和样式规范。只用这些组件和 token 搭页面，不要自创新样式；已有组件（如 Button）在原组件上改。
```

**H. 细节复查（伊恩）**
```
按 100% 尺寸和手机宽度检查：图标线宽是否统一；按钮文字是否偏高/偏低；卡片内容是否对齐；图片放进圆角卡片时角上是否露缝；平铺卡片是否有不该有的大阴影；是否有装饰性发光球。逐条修复。
```
