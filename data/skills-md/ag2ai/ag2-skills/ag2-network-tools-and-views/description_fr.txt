Déterminez ce qu’un agent réseau AG2 perçoit et quelles actions son LLM peut effectuer. Couvre les cinq outils auto‑injectés côté LLM fournis via `NetworkPlugin` (`delegate`, `peers`, `channels`, `tasks`, `context`) ainsi que le `say` appartenant à l’adaptateur ; remplace le gestionnaire par défaut par `agent_client.on_envelope(callback)` (passerelles, workers sans interface graphique) ; le protocole `ViewPolicy` avec les vues intégrées `FullTranscript`, `WindowedSummary(recent_n=N)` et `NamedWindowedSummary(recent_n=N)` ainsi que la façon d’écrire une vue personnalisée ; la découverte de pairs via le markdown des compétences (`skill_md=`, `parse_skill_frontmatter`, `hub.set_skill`) ; le format filaire `Envelope` avec la taxonomie d’événements `EV_*` (`EV_TEXT`, `EV_PACKET`, `EV_CHANNEL_*`, `EV_EXPECTATION_VIOLATED`, `EV_TASK_CANCEL_REQUEST`, `EV_TASK_CANCELLED`), les sémantiques `audience` et `visible_to`, `Priority`, `causation_id`, et la manière d’envoyer des enveloppes brutes avec des types d’événements personnalisés via `agent_client.send_envelope(...)`. À utiliser lorsque l’utilisateur souhaite personnaliser la surface réseau du LLM, écrire un gestionnaire d’enveloppes personnalisé, créer une passerelle / un worker sans interface graphique, ou câbler la découverte de pairs.
