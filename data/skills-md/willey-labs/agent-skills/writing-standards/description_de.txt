Standards für das Schreiben, Bearbeiten und Überprüfen von DOKUMENTEN — READMEs, Spezifikationen, Regeln, Fertigkeiten, Design‑Docs, Leitfäden und jede prosaartige Ausbringung, die aus einer Quelle (bestehendem Code oder einer vorherigen Diskussion) entsteht. Zwei Regelsets gelten für jede Dokumentenaufgabe: (1) source‑to‑deliverable — code→doc beschreibt, was das System TUT, ohne Code‑ oder Code‑Identifikatoren; discussion→rule formuliert das allgemeine Prinzip, nicht das gerade diskutierte konkrete Beispiel; (2) anti‑slop — Abschwächungen, Hype‑Wörter, Rülpsen, Anfeuerungen, reflexive Formatierung und Auffüllungen weglassen. Verwenden, wenn der Nutzer sagt „ein Dokument schreiben“, „dieser Code dokumentieren“, „beschreibe, was das macht“, „in eine Regel/Fertigkeit umwandeln“, „aus unserer Diskussion ein Doc machen“, „dieses Doc überprüfen“ oder „ist das Slop?“. Vor dem Verfassen oder Überprüfen JEDEs Dokuments konsultieren, selbst wenn der Nutzer nicht „Standards“ sagt — jede Dokument‑Schreib‑/Bearbeitungs‑/Review‑Aufgabe muss konform sein. Der Begleiter zu den Coding‑Standards: Diese regeln Code, diese regeln Dokumente.
