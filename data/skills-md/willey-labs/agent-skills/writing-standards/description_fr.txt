Normes pour la rédaction, l’édition et la révision de DOCUMENTS — README, spécifications, règles, compétences, documents de conception, guides, et tout livrable en prose produit à partir d’une source (code existant ou discussion préalable). Deux ensembles de règles s’appliquent à chaque tâche documentaire : (1) source‑vers‑livrable — code→doc décrit ce que le système FAIT sans inclure de code ni d’identifiants de code ; discussion→règle expose le principe général, pas l’exemple spécifique récemment abordé ; (2) anti‑slop — éliminer les hésitations, les mots à la mode, les justifications inutiles, les encouragements excessifs, le formatage réflexif et le remplissage. Utiliser lorsque l’utilisateur dit « write a document », « document this code », « write up what this does », « turn this into a rule/skill », « make a doc from our discussion », « review this doc » ou « is this slop? ». Consulter avant de rédiger ou de réviser UN DOCUMENT, même si l’utilisateur ne mentionne pas « standards » — chaque rédaction/édition/révision de document doit être conforme. Le compagnon des normes de codage : celles‑ci régissent le code, celle‑ci régit les documents.
