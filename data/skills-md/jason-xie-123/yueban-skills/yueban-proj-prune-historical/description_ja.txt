プロジェクト全体（ルートリポジトリ自体と、.gitmodules から動的に取得した、deprecated/ プレフィックスが付いているものは除外し、アクティブに保守されている各サブモジュールを含む）をスキャンし、クリーンアップします。ルートリポジトリと各サブモジュールは同等に扱い、フルリポジトリスキャンのために同じファイルタイプ規則セットを使用します。

対象はソースコードコメント（主流言語をカバーし、コメント構文でグループ化：Java/Kotlin/Swift/Go/C/C++/C#/Rust/Scala/Groovy/Dart/TS/JS などの //、/* */、/** */ スタイル；Python/Ruby/Shell/Perl/R/YAML などの # スタイル；SQL/Lua などの -- スタイル；PowerShell の # と <# #>；HTML/XML の <!-- -->；CSS/SCSS/LESS の /* */）と、Markdown 文書中で「歴史的変更プロセス」を記録している部分（AI 生成かどうかに関わらず、「当初はこうだった」「XX のために後に変わった」「マイグレーション/変更時に削除された」「古いモジュールから移行された」「design.md の決定 X」など、歴史的な叙述を含むもの）です。

このようなソースコードコメントのブロックはすべて削除し、Markdown 文書については歴史的叙述の文だけを削除し、依然として有用な指示は残します。このクリーンアップは、ユーザーが明示的に「これらのコメントは変更プロセスを記録しているだけで不要」と要求したとき、または「これらのコメントは削除して良い」と言及したときに実行します。

デフォルトの除外対象は、deprecated/ ディレクトリツリー全体、歴史的計画アーカイブとして明示的にマークされたディレクトリ、プロジェクトで openspec を使用している場合の openspec/ ツリー全体、エージェントツール設定ディレクトリ .claude/、.codex/、.gemini/、.agents/ の4つ、そして .gitignore に記載されたパス（例：node_modules、git ls‑files が自然に列挙しないもの）です。

常にユーザーの言語で応答してください。
