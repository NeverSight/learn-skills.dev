Analyse et nettoyage de l’ensemble du projet (à la fois le dépôt racine lui‑même et chaque sous‑module actuellement maintenu—obtenus dynamiquement depuis .gitmodules, en excluant ceux ayant le préfixe deprecated/ ; traiter le dépôt racine et chaque sous‑module de façon égale, en appliquant le même jeu de règles de type de fichiers pour une analyse du dépôt complet) des commentaires de code source (couvrant les langages courants, regroupés par syntaxe de commentaires : styles //, /* */, /** */ pour Java/Kotlin/Swift/Go/C/C++/C#/Rust/Scala/Groovy/Dart/TS/JS, style # pour Python/Ruby/Shell/Perl/R/YAML, style -- pour SQL/Lua, # et <# #> pour PowerShell, <!-- --> pour HTML/XML, /* */ pour CSS/SCSS/LESS) ainsi que du contenu des documents Markdown qui consignent les « processus de changement historiques »—indépendamment du fait qu’ils soient générés par IA, tant qu’il s’agit de récits tels que « comment c’était à l’origine, comment cela a changé plus tard à cause de XX », « supprimé lors d’une certaine migration/changement », « migré depuis un ancien module », « design.md décision X », etc. Le bloc complet des commentaires du code source doit être supprimé, et dans les documents Markdown seules les phrases narratives historiques doivent être retirées tout en conservant les guides opérationnels encore pertinents.
