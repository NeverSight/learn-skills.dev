Verificare se i file AGENTS.md/README.md/documenti aziendali sono obsoleti: riferimenti pendenti, stati contraddittori o autocontraddittori, collegamenti interrotti, incoerenze tra documenti, incongruenze nello stato delle modifiche di openspec (se il progetto utilizza openspec), conflitti di autorità non segnalati, lacune nella copertura dell’indice, infrastrutture recentemente aggiunte mancanti, comandi/percorso che non possono essere eseguiti, contenuti duplicati, narrazioni storiche residue. Quando si individua un problema, modificare direttamente il file. L’ambito è scoperto dinamicamente secondo regole, senza codificare una lista fissa di file: il file radice AGENTS.md/README.md, tutti i file .md nella cartella docs/, tutti i file .md nella cartella skills/ alla radice del repository (se esiste) e, per ciascun sottomodulo attualmente mantenuto (ottenuto dinamicamente da .gitmodules, escludendo quelli con prefisso deprecated/), il proprio AGENTS.md/README.md e la sottocartella docs/. Esclusioni predefinite: l’intero albero di directory deprecated/, le directory esplicitamente segnate dal progetto come archivi di pianificazione storica, l’intero albero di directory openspec/ (se il progetto utilizza openspec), le quattro directory di configurazione degli strumenti agente .claude/, .codex/, .gemini/, .agents nella loro interezza, e i percorsi elencati in .gitignore. Il materiale di prodotto/azienda sotto docs/ e i docs/ dei sottomoduli devono essere valutati con cautela aggiuntiva (se tale directory contiene l’AGENTS.md del progetto, leggerlo prima di procedere), vedere la sezione “Scope” per i dettagli. **Solo attivato manualmente**: viene eseguito solo quando l’utente inserisce esplicitamente `/yueban-docs-freshness-audit` o chiama esplicitamente questa abilità; affermazioni generiche come “controlla i documenti” o “vedi se i docs sono obsoleti” non devono mappare automaticamente qui—trattarle come richieste ordinarie o chiedere chiarimenti a meno che l’utente non lo nomini specificamente.
