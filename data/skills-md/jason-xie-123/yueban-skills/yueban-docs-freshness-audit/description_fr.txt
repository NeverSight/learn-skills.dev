Vérifier si les fichiers AGENTS.md, README.md et les documents métier sont obsolètes : références pendantes, états incohérents ou contradictoires, liens cassés, incohérences inter‑documents, divergences d’état de changement openspec (si le projet utilise openspec), conflits d’autorité non signalés, lacunes de couverture d’index, infrastructures récemment ajoutées manquantes, commandes/chemins non exécutables, contenu dupliqué, récits historiques résiduels ; modifier directement les fichiers dès la détection de problèmes.  

La portée est découverte dynamiquement selon des règles, sans coder en dur des listes de fichiers spécifiques : le AGENTS.md/README.md à la racine, tous les documents .md sous le répertoire docs/, tous les documents .md sous le dossier skills/ à la racine (si présent), et pour chaque sous‑module actuellement maintenu (obtenu dynamiquement à partir de .gitmodules, en excluant ceux avec le préfixe deprecated/), leurs respectifs AGENTS.md/README.md et sous‑répertoires docs/.  

Exclusions par défaut : l’arborescence complète du répertoire deprecated/, les répertoires explicitement marqués par le projet comme documentation d’archivage pour la planification historique, l’ensemble de l’arborescence openspec/ (si le projet utilise openspec), les quatre répertoires de configuration d’outils d’agent .claude, .codex, .gemini, .agents dans leur totalité, ainsi que les chemins répertoriés dans .gitignore. L’évaluation des matériaux produit/entreprise sous docs/ et les docs/ des sous‑modules doit être particulièrement prudente (s’il existe un AGENTS.md propre au projet dans ce répertoire, le lire en premier avant de continuer) ; voir la section « Portée » pour plus de détails.
