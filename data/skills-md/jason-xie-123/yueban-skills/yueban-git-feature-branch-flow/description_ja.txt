gitサブモジュールを使用しているリポジトリでは、spec/feature と同名のブランチを作成します――親リポジトリと、.gitmodules から動的に検出される（deprecated/ プレフィックスが付いた過去のモジュールは除外）現在保守中の各サブモジュールが、ユーザーが選択したベースブランチ（プロジェクトが実際に使用している任意のブランチで、ハードコーディングしない）から <change-id> ブランチへ均一に分岐します。開発中は sync を使ってこのブランチを複数マシン間で整合させます（ベースブランチ自体には影響を与えません）。コミット時には yueban‑git‑commit をオーケストレーションし、各パートを「サブモジュールが先、親リポジトリが最後」の順でコミットします。最後にマージ可能なレポートを提供しますが、自動マージは行わず（ユーザーが手動または PR でマージ）、マージ後にブランチを削除することも可能です。

yueban‑git‑safe‑sync との違い：このツールは現在のブランチそのもののプル／プッシュや「ベースを現在のブランチにマージ」および「現在のブランチの PR を作成」だけを管理しますが、こちらはベースブランチから切り離されたフィーチャーブランチのライフサイクル全体を管理します。

**明示的なトリガーのみ**：`/yueban-git-feature-branch-flow` と入力するか、スキル名を明示的に呼び出したときだけ起動します。「ブランチを作成」「ブランチをチェックアウト」「この仕様をどう開発するか」などの一般的な問い合わせは自動的に紐付けず、普通の git 操作として扱うか、明示的に言及がない限りは確認を求めます。
