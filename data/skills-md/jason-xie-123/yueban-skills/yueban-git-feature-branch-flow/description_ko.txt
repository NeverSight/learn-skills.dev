git 서브모듈을 포함하는 저장소에서는, 사양/기능 이름을 딴 브랜치를 생성합니다—부모 저장소와 현재 유지 관리 중인 각 서브모듈(.gitmodules에서 동적으로 발견하고, deprecated/ 접두사가 붙은 과거 모듈은 제외) 모두가 사용자가 선택한 베이스 브랜치(프로젝트에서 실제로 사용되는 어떤 브랜치든, 하드코딩된 것이 아님)에서부터 분기되어 <change-id> 브랜치를 만듭니다. 개발 중에는 sync를 사용해 이 브랜치를 여러 머신 간에 맞추되(베이스 브랜치 자체는 그대로 유지) 합니다. 커밋 시에는 yueban‑git‑commit을 조정해 각 저장소를 “서브모듈 먼저, 부모 저장소 마지막” 순서로 커밋합니다. 마지막에 병합 준비 보고서를 제공하지만 자동으로 병합하지는 않습니다(사용자가 직접 또는 PR을 통해 병합). 병합 후에는 선택적으로 브랜치를 정리합니다.

yueban‑git‑safe‑sync와의 차이점: 해당 도구는 현재 브랜치 자체의 pull/push를 관리하고, “베이스를 현재 브랜치에 병합”과 “현재 브랜치에 대한 PR 열기”라는 두 가지 단일 작업을 수행합니다. 이 흐름은 베이스 브랜치와 분리된 기능 브랜치의 전체 생명주기를 관리합니다.

**명시적 트리거만**: 사용자가 `/yueban-git-feature-branch-flow`를 명시적으로 입력하거나 이 스킬을 직접 호출할 때만 실행됩니다. “브랜치 생성”, “브랜치 전환”, “이 사양을 어떻게 개발할지”와 같은 일반적인 언급은 자동으로 호출되지 않으며, 일반 git 작업으로 처리하거나 사용자가 명시적으로 언급할 때까지 추가 질문을 합니다.

항상 사용자의 언어로 답변하십시오.
