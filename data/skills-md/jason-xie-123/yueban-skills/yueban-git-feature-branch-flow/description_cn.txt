在包含 Git 子模块的仓库中，打开一个与 spec/feature 同名的分支——父仓库以及每个当前维护的子模块（从 .gitmodules 动态发现，排除带有 deprecated/ 前缀的历史模块）都应从用户选择的基线分支（项目实际使用的任意分支，而非硬编码的分支）分出来，创建一个 <change-id> 分支。开发期间，使用 sync 在多台机器间保持该分支同步（不影响基线分支本身）。提交时，调度 yueban-git-commit 按 “先子模块，后父仓库” 的顺序提交每个项目。完成后提供可合并的报告，但不自动合并（用户手动或通过 PR 合并）。合并后，可选择清理分支。与 yueban-git-safe-sync 的区别在于：后者管理当前分支的 pull/push 以及 “将基线合并到当前分支” 与 “为当前分支打开 PR” 这类单点操作，而本工具管理脱离基线的特性分支的完整生命周期。**仅在明确触发时执行**：只有当用户显式输入 `/yueban-git-feature-branch-flow` 或明确点名本技能时才会调用；诸如 “创建分支”“切换分支”“如何开发此 spec” 等通用描述不应自动触发，而应作为普通 Git 操作处理或询问用户澄清，除非用户明确提到本工具。请始终使用用户的语言作答。
