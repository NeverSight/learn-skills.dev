在使用 git 子模組的倉庫中，根據 spec/feature 建立同名分支——父倉庫以及每個目前維護的子模組（從 .gitmodules 動態發現，排除以 deprecated/ 為前綴的歷史模組）皆統一從使用者選取的基礎分支（任何實際在專案中使用的分支皆可，非硬編碼）衍生出 `<change-id>` 分支。開發期間，使用 sync 在多台機器間對齊此分支（不影響基礎分支本身）。提交時，協調 `yueban-git-commit` 依序提交各組件，順序為「先子模組，後父倉庫」。最後提供可合併的報告，但不自動合併（使用者自行手動或透過 PR 合併）。合併完成後，是否清理分支為可選。

與 `yueban-git-safe-sync` 的差異在於：前者管理當前分支本身的 pull/push，以及「將基礎合併至當前分支」與「為當前分支開 PR」這兩個單一操作；而本工具管理的是脫離基礎分支的功能分支的完整生命週期。

**僅在明確啟動時才執行**：僅在使用者明確輸入 `/yueban-git-feature-branch-flow` 或明確呼叫此技能時才會觸發；類似「建立分支」、「切換分支」、「如何開發此規格」等一般敘述不應自動映射到此，應視為普通 git 操作或詢問使用者說明，除非使用者明確呼叫本功能。

請始終以使用者的語言回覆。
