在使用 git 子模块的仓库中，当执行 pull、push、把基准分支合并到当前分支，或为父仓库及所有子模块打开 GitHub PR 时，必须确保每个当前维护中的子模块（通过 .gitmodules 动态发现，排除以 deprecated‑ 前缀、历史或已冻结的模块）始终保持在其原始分支上（分支名严格遵循项目实际约定），且不会因为这些操作而进入 detached HEAD 状态或被强制检出父仓库记录的 SHA。Pull/push 适用于“同一项目在多台机器上运行，子模块分支状态必须在机器之间保持一致”的场景。Merge‑base/PR 适用于“你在基准分支上创建了特性分支，需要合并基准的新提交，或打开 PR 将此分支合并回基准”的场景。**唯一显式触发**：只能在用户明确输入 `/yueban-git-safe-sync` 或明确表示要使用此技能时才调用；如果用户仅说 “pull 一下”“push 一下”“同步代码”“合并 develop”“打开 PR” 等笼统表述，不要假设使用此技能——应按普通 git 操作处理或询问澄清，除非用户明确提到该技能。
