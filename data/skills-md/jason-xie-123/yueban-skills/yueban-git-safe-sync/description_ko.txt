git 서브모듈을 포함하는 리포지터리에서 pull, push, 기본 브랜치를 현재 브랜치에 병합하거나, 상위 리포지터리와 모든 서브모듈에 대해 GitHub PR을 생성할 때, 현재 관리되고 있는 모든 서브모듈( .gitmodules 에서 동적으로 발견하고, “deprecated/”로 시작하는 폐기/역사/고정 모듈은 제외)을 항상 원래 브랜치에 머물게 하고(브랜치 이름은 프로젝트 규칙을 따라 정확히 사용), 이러한 작업의 결과로 detached HEAD 상태가 되거나 상위 리포지터리에서 기록된 SHA로 강제로 체크아웃되지 않도록 해야 합니다.

Pull/push는 “동일한 프로젝트 세트를 여러 머신에서 실행하고 서브모듈 브랜치 상태가 머신 간에 일관되어야 하는” 경우에 적합합니다.  
Merge‑base/PR은 “베이스에서 분기한 기능 브랜치에서 베이스의 새로운 커밋을 병합하거나, 이 브랜치를 베이스에 다시 병합하기 위해 PR을 열어야 하는” 경우에 적합합니다.

**명시적 트리거만:** 사용자는 `/yueban-git-safe-sync`를 명시적으로 입력하거나 이 스킬을 사용하고 싶다고 명시적으로 말했을 때만 이 스킬을 호출하십시오. 사용자가 “pull 좀 해줘”, “push 좀 해줘”, “코드 동기화해”, “develop 병합”, “PR 열어”와 같은 일반적인 표현만을 사용한다면 이 스킬을 가정하지 말고 일반 git 작업으로 처리하거나 명확히 물어보세요. 사용자가 스킬 이름을 특정해서 언급한 경우에만 적용합니다.

항상 사용자의 언어로 응답하십시오.
