gitサブモジュールを使用しているリポジトリで、pull、push、ベースブランチを現在のブランチにマージ、または親リポジトリとすべてのサブモジュールのGitHub PR を開くときは、.gitmodules から動的に検出された（deprecated/ で始まる過去/凍結されたモジュールを除く）現在メンテナンス中のサブモジュールが、必ず元のブランチ（プロジェクトの実際の規約に従った正確な名前）にとどまり、これらの操作によりデタッチドHEADになったり、親リポジトリに記録された SHA を強制的にチェックアウトしたりしないようにしてください。pull/push は、同一プロジェクトが複数のマシンで実行され、サブモジュールのブランチ状態をマシン間で一貫させる必要があるシナリオに適しています。merge‑base/PR は、ベースから切り出したフィーチャーブランチ上でベースの新しいコミットを取り込む必要がある、またはこのブランチをベースにマージする PR を開くシナリオに適しています。**明示的なトリガーのみ**：このスキルは、ユーザーが明示的に `​/yueban-git-safe-sync​` と入力するか、明示的にこのスキルを使用したいと述べた場合にのみ呼び出してください。ユーザーが「ちょっとpullしたい」「ちょっとpushしたい」「コードを同期したい」「developをマージしたい」「PRを開く」などと一般的に言っただけでは、このスキルを前提にせず、通常のgit操作として処理するか、明確にスキル名を挙げていない限りは確認を求めてください。
