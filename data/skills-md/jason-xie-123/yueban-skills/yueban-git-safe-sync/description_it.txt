In un repository che contiene submodule git, quando si esegue pull, push, il merge del branch base nel branch corrente, o si apre una PR su GitHub per il repository principale più tutti i submodule, assicurarsi che ciascun submodule attualmente mantenuto (scoperto dinamicamente da .gitmodules, escludendo i moduli storici/congelati con prefisso “deprecated/”) rimanga sempre sul suo branch originale (il nome esatto definito dalle convenzioni del progetto). Non deve mai provocare che il submodule diventi un HEAD staccato o venga forzatamente checkout al SHA registrato nel repository padre. Pull/push è adatto per scenari in cui lo stesso progetto gira su più macchine e lo stato del branch del submodule deve rimanere coerente tra le macchine; merge‑base/PR è adatto per scenari in cui si è su un branch feature derivato dal base e si necessita di unire nuovi commit dal base, o aprire una PR per fondere questo branch nuovamente nel base. **Solo attivazione esplicita**: invocare questo solo quando l'utente inserisce esplicitamente `/yueban-git-safe-sync` o dichiara esplicitamente di voler usare questa funzionalità. Se l'utente dice semplicemente “pull a bit”, “push a bit”, “sync the code”, “merge develop”, “open a PR”, ecc., non associare automaticamente la skill—gestiscili come normali operazioni git o chiedi chiarimenti, a meno che l'utente non la nomini esplicitamente.

Rispondi sempre nella lingua dell'utente.
