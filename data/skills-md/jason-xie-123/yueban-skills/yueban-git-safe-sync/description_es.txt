En un repositorio que incluye submódulos git, al ejecutar pull, push, fusionar la rama base en la rama actual o abrir un PR de GitHub para el repositorio principal más todos los submódulos, asegúrese de que cada submódulo que se mantenga actualmente (descubierto dinámicamente a partir de .gitmodules, excluyendo los módulos históricos/congelados con el prefijo deprecated/) permanezca siempre en su rama original (el nombre exacto sigue las convenciones reales del proyecto) y nunca se convierta en un HEAD separado ni se fuerce a hacer checkout del SHA registrado en el repositorio principal por estas operaciones. Pull/push es adecuado para escenarios donde el mismo proyecto se ejecuta en varias máquinas y el estado de la rama del submódulo debe permanecer consistente entre máquinas; merge‑base/PR es adecuado para escenarios donde estás en una rama de característica creada a partir de la rama base y necesitas fusionar nuevos commits de la base, o abrir un PR para fusionar la rama de vuelta a la base. **Solo activación explícita**: esta habilidad debe invocarse únicamente cuando el usuario introduzca explícitamente `/yueban-git-safe-sync` o indique explícitamente que desea usar esta habilidad; si el usuario solo dice “pull un poco”, “push un poco”, “sincronizar el código”, “merge develop”, “abrir un PR”, etc., no asuma esta habilidad—maneje la operación como un git normal o pida aclaración, a menos que el usuario lo nombre específicamente.
