Utilisez-le avant de créer, modifier ou écrire du code contre les métadonnées Salesforce, afin de découvrir ce qui existe déjà dans l’organisation avec l’outil adéquat. Dirige chaque question vers le référencement des métadonnées, le SOQL ciblé avec sf data query, sf sobject list ou describe, sf org list metadata, la récupération de source ou les fichiers locaux, et couvre les organisations et configurations où le référencement n’est pas disponible. Utilisez-le pour vérifier si un objet, un champ, une liste de sélection, un ensemble d’autorisations, une page, une application ou un flux existe déjà avant d’en créer un, confirmer les noms de champs, les types et les valeurs de listes de sélection avant d’écrire du code Apex, LWC, SOQL ou de la logique Flow, lister chaque champ d’un objet ou chaque membre d’un type de métadonnée, trouver l’automatisation qui s’exécute sur un objet, ou expliquer comment quelque chose est configuré dans l’organisation et qui peut y accéder. NE PAS DÉCLENCHER pour des vues d’ensemble de l’ensemble de l’organisation, des comparaisons d’organisations ou des dérives (utilisez dx‑org‑analyze), la structure des fichiers de métadonnées ou la forme XML (platform‑metadata‑api‑context‑get), ou le schéma Data Cloud DLO et DMO (data360‑code‑extension‑generate).

Veuillez toujours répondre dans la langue de l’utilisateur.
