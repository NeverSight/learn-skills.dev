Diagnostiziere und behebe Probleme der Code‑Lesbarkeit, indem du Domänentypen anstelle von primitiven Typen und Booleans einführst, I/O an die Modulränder verschiebst, Zwischenschritte der Pipeline benennst, Module um Datentypen statt Verben reorganisierst und duplizierte Logik in einzelne autoritative Definitionen konsolidierst. Verwende dies beim Review eines PR, bei der Planung einer Refaktorisierung, beim Entwurf eines Moduls/Nahtpunkts oder wenn der Nutzer signalisiert, dass der Code schwer zu verstehen ist oder fragt, wo ein System gespalten oder zusammengeführt werden soll.
