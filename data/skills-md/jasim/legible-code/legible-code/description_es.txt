Diagnosticar y remediar problemas de legibilidad del código introduciendo tipos de dominio en lugar de primitivas y booleanos, desplazando I/O a los bordes del módulo, nombrando las etapas intermedias del pipeline, reorganizando los módulos alrededor de tipos de datos en lugar de verbos y consolidando la lógica duplicada en definiciones únicas y autoritativas. Utilizar al revisar un PR, planear una refactorización, diseñar un módulo/interfaz, o cuando el usuario indique que el código es difícil de razonar o pregunte dónde dividir o fusionar un sistema.
