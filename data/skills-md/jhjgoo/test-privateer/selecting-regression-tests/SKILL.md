# 选择回归测试

选择并验证能够保护变更的最小可信回归集。

按 `test-privateer` 的产物路由定位需求分析与用例。分析记录回归选择及排除理由，用例文件或其证据链接记录实际执行；独立任务在对话或指定位置交付。仅长期保护与跨需求薄弱面更新 TCO，风险状态在唯一归属处维护。

## 选择

1. 映射变更影响：行为、数据、状态、配置、依赖、接口、上下游和可能失败方式。
2. 加入直接保护：目标行为、已修缺陷的复现条件和关键 oracle。
3. 只有耦合、历史缺陷、业务后果或弱可观察性证明有价值时，才加入相邻检查。
4. 优先可靠、可区分失败原因的检查；隔离噪声，不拿数量换假信心。
5. 记录未覆盖区域、原因和残余风险。

## 执行并调整

把选中检查交给 `running-test-sessions`：无环境访问权时交付可执行任务并指导执行；有授权和访问权时直接运行。执行发现新耦合、反驳依赖假设或改变风险时，扩大、缩小或替换回归集。

## 输出

```markdown
## 变更面
变了什么 — 可能扰动什么

## 最小可信回归集
- 检查 — 保护的风险 — 选择理由 — 执行状态／证据

## 排除与延期
- 区域／检查 — 原因 — 残余风险

## 调整信号
- 哪类执行证据会扩大、缩小或替换集合
```

**完成条件：** 每个重要变更风险都有可信检查或明确残余风险；已执行项附实际证据，未执行项明确执行条件和负责人；局部回归集留在 Spec，TCO 只保留长期保护。

交回调用方时附 handoff：回归集路径、每项选择／排除理由、执行条件、未执行责任人和下一步 `running-test-sessions` 动作。
