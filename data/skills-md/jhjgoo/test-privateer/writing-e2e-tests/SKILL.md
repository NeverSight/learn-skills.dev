# 编写端到端测试

验证用户或系统能走完一条业务旅程。关键动作经过选定真实链路，结果由业务断言确认；点击完成、成功提示和模型总结都不能单独证明旅程成功。

## 1. 定位旅程

读取业务目标、成功／失败规则、已有测试和项目运行约定。确定起点、终点、身份、真实服务及被替换的依赖。已有合理范围直接使用，不先重做策略分析。

按请求交付设计、代码或获准运行结果。只设计不安装；只编写不启动测试。区分既有行为补保护与新行为／缺陷保护，不强制制造 RED，也不接管未授权的生产修复。

一例围绕一条有完整结果的旅程，可包含多个必要操作，不照搬单元测试的一个 Act。广泛输入组合留给适合的小范围测试。仅有局部组件交互时，转用[组件参考](../designing-test-automation/references/component-testing.md)，不强制全链路。

**完成条件：** 旅程起止、判定依据、真实范围和授权明确。

## 2. 准备独立的开始状态

沿用现有登录和数据夹具，核实账号及初始状态。接口可加速非目标准备；本次要验证的关键动作仍经过选定旅程。

隔离身份与后端可变数据，使用本轮可关联的资源标识。新的浏览器 context 只隔离浏览器，不能证明后端数据隔离。单独运行不依赖前例，支持并行时再检查共享资源。

先确定失败证据与恢复方式。已有清理机制直接复用；未知重置或删除入口先查证。只清理本轮拥有的数据，清理失败不覆盖业务失败。

**完成条件：** 开始状态可核实，失败后能定位证据和本轮遗留资源。

## 3. 编写操作与业务断言

沿用框架、配置、目录及目标命令。用实际可见名称、角色或稳定测试标识定位；缺少定位事实先观察页面或读代码，不猜内部选择器。

把准备、旅程操作和结果检查分开。等待具体可观察状态、相关请求或工具的可等待断言；同步预算注明依据，不用任意休眠。

- **保存后保留：** 合同要求重新打开仍可读时，再打开同一业务对象核对内容。
- **状态迁移：** 检查目标状态及受规则约束的后续动作，不只检查通知。
- **错误恢复：** 按规则核对输入保留、修正重试和最终结果；区分本次与旧提示。
- **跨层结果：** 用业务标识关联页面和服务结果，避免不同对象碰巧满足断言。

多个断言可以共同证明一条旅程。人工体验判断另列；自动化通过不表示整体易用性已验证。

**完成条件：** 能说明每个关键断言对应哪个业务承诺，目标动作没有被准备步骤绕过。

## 4. 复用工具，按需使用 AI

已有合适框架就直接编写。无合适框架时读取[框架与入口选型](../designing-test-automation/references/harness-readiness.md#框架与入口选型)，在明确委托范围内选择最小工具，未委托的实质选型先确认；选中 tester-army e2e 后才读取[官方接入参考](references/e2e-integration.md)，再读取匹配版本的官方 Skill。它负责工具操作，不决定产品预期。

确定性测试不需要模型凭证。选择 AI 操作时，每次给一个清楚目标，真实参数独立传递；操作后用明确断言核对业务结果。

首次验证 AI 路径禁用回放，核对实际模型调用。操作回放与模型冷运行分别报告；调用 agent.act 本身不证明模型实际参与。

**完成条件：** 框架与项目兼容，版本可核实；测试目标而非工具默认决定真实范围和权限。

## 5. 执行与定位失败

按授权先单独运行首条旅程，再选择相关回归。读取本轮报告和失败步骤，定位最后一个已确认状态：

| 失败位置 | 下一步 |
| --- | --- |
| 登录、数据或服务准备 | 核对前置，标明业务断言尚未到达 |
| 定位或同步 | 核对实际界面、对象与完成信号，不用加重试掩盖 |
| 模型或工具调用 | 保留调用诊断，区分工具失败与业务结果不符 |
| 业务断言 | 核对独立预期、关联对象和真实状态；不改 expected 迁就实现 |
| 清理 | 保留原始结果，单独报告本轮遗留及恢复动作 |

首次通过、重跑通过、失败、跳过和环境受阻分别记录。启动失败后磁盘上的旧报告不能作为本轮成功。

在安全可逆条件下，用已知缺陷版本或受控失败变体破坏目标业务结果，检查同一断言确实失败；恢复后复跑。改错 expected 只说明断言会失败，不足以证明业务探错能力。无法验证时交付限制，不改坏生产环境。

**完成条件：** 失败原因和实际到达位置有证据，判错能力有本轮验证或明确缺口。

## 6. 交付

沿用[共享表达](../test-privateer/references/artifact-routing.md#面向读者的测试表达)，先交代完成与限制，再给旅程、测试文件、运行命令、框架及应用版本、真实依赖、数据与清理、首次及重跑结果和必要诊断位置。

截图、trace 和视频按项目数据边界保存，不默认上传。交回调用方已有执行／报告流程，不重复运行。**完成条件：** 接手者能复跑并定位失败；只设计、只编写与实际运行保持区分。

## 方法依据

- [Playwright 最佳实践](https://playwright.dev/docs/best-practices)：用户行为、隔离、稳定定位和可等待断言。
- [Playwright 重试分类](https://playwright.dev/docs/test-retries)：首次通过与重试通过分别报告。
- [Google 单元测试](https://abseil.io/resources/swe-book/html/ch12.html)：小范围保护稳定规则，旅程保留其独有的协作证据。
