# 执行测试会话

Session（测试会话）服从任务和证据，不服从脚本惯性。

本 Skill 的前提是用户已经要求执行测试；显式调用本 Skill 视为授权在已声明边界内执行。安装依赖、启动服务、拉取镜像、创建或修改数据、访问外部环境都属于执行。这些动作超出已有授权时，先说明影响并取得确认。

## 从测试产物开始

沿用调用方已确定的独立／项目路径；编号与引用按 `test-privateer/references/artifact-routing.md` 维护，重跑沿用用例ID，以版本、环境和运行时间区分执行记录。独立任务使用当前用例、章程或用户指定材料；项目任务读取项目 TCO 与当前 Spec 测试文档。执行前读取当前测试轮次、charter ID 或测试 ID、访问与安全边界、需要获得和保留的证据。没有当前 Spec 不阻止明确且获准的单项测试；沿用已有测试目录或在对话中交付，不创建伪 Spec。未知项明确为未知，不补写成事实。

## 执行

执行前核实指定版本、账号、数据、操作入口和观察手段；未调查写待核实，实际缺失才写准备缺口。条件具备与用户授权分别判断。探索可边学习、边设计、边执行，超出当前任务或权限的分支先说明。

1. 核对本轮要执行与明确排除的 ID、起始风险、环境、执行人、时间、数据、oracle 和结束／转向信号。
2. 按访问权行动：
   - 无环境访问权：准备 probe、数据、操作、观察位置和 oracle，指导获授权的用户执行，只把其返回的原始观察记为结果；
   - 有明确授权和访问权：直接执行，保留命令或操作、环境版本、输入、时间、账号／权限、前置状态和原始结果。
3. 先运行最便宜、最能区分当前风险的 probe。计划、待执行或指导步骤保持未执行状态，不写成结果。
4. 分开记录原始观察与解释。每条结果和 finding 都引用实际执行的测试 ID 或 charter ID；重要 finding 保留复现所需的状态、数据、顺序、负载、环境和证据。
5. 意外若信息价值更高且仍在权限与安全边界内，跟进并记录分支；价值较低则停放，越界则停止。新 finding 可以新增候选测试点或产品风险并分配新 ID；保留既有执行证据，若后续证据改变解释，追加修正及原因。
6. 用本轮证据更新当前测试记录；项目路径写回对应 Spec，独立路径在对话或指定位置交付。未运行项目保留原因，长期或跨 Spec 认知改变时才更新 TCO。

结果写入对应 `-test-cases.md` 或证据文件；更新分析的行动和风险。风险按 analyzing-product-risks 的生命周期在唯一归属处更新，不以用例通过自动关闭。

## 写回测试记录

只更新与本轮执行有关的内容：

```markdown
## 当前测试轮次
- 实际执行范围、排除项、环境、执行人和访问方式

## 执行证据
- <测试 ID／charter ID>：已运行测试／Probe — 原始观察 — 证据链接
- <测试 ID／charter ID>：Finding — 影响 — 当前可信度
- <测试 ID／charter ID>：未执行内容 — 原因

## 产品风险
- <风险 ID>：被本轮证据提高、降低或新增的风险 — 关联测试／charter ID — 依据

## 下一步
- 下一项测试、待确认问题或停止理由 — 触发条件
```

观察只陈述实际看到或收到的原始结果；解释、影响和可信度另列。原始证据过长时放入独立文件，主测试记录保留摘要、稳定 ID 和链接。未执行计划不能升级成项目证据。

**完成条件：** 当前测试记录明确实际执行了哪些测试、由谁执行、观察到什么、证据在哪里、哪些未执行及原因；每条结果和 finding 可追溯到测试 ID 或 charter ID；局部证据留在 Spec，TCO 只接收符合升级判据的变化；产品风险和下一步由本轮证据更新，计划没有冒充结果。

交回调用方时附 handoff：执行记录路径、实际运行范围、未执行项及原因、原始证据、发现状态、风险变化和下一步 `investigating-findings`／`assessing-test-confidence`／回归选择。
