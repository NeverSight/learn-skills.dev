# 评估 Prompt

评估 Prompt 是否让目标模型在当前宿主和任务中稳定表现出目标行为。交付审查、最小修正和验证证据；不因文字看起来专业就判好，也不因模型、宿主或版本变化就机械重写。

## 1. 固定评估对象

明确目标模型、宿主、任务、使用者、期望行为、允许自由度和真实边界。模型或宿主未知时仍可审查业务契约和内部冲突，但模型适配保持未验证。

盘点实际进入模型的 Prompt 表面：System Prompt、Skill／规则文件、工具描述、请求模板、示例、运行配置及会改变优先级的宿主指令。只读取当前任务可访问的部分；缺失内容说明影响，不假定单个文件就是完整 Prompt。

**完成条件：** 能指出评估针对哪个模型、宿主、任务与 Prompt 组合，以及本轮要改善或保护的具体行为。

## 2. 建立行为依据

优先使用真实失败、运行记录、用户反馈和已确认规则。区分：

- 产品、安全、权限和输出契约；
- 宿主、工具、模型和运行配置事实；
- 有历史失败依据的行为规则；
- 经验性建议和仍待验证的模型假设。

只有写法会改变行为、正确性、权限或可验证性时才形成 finding。篇幅、语气和格式偏好本身不构成问题。

**完成条件：** 每项评估标准都有来源；未知没有被升级为目标行为。

## 3. 审查 Prompt

检查目标、上下文、权限、决策条件、完成标准和输出要求是否在实际使用位置清楚一致。需要模式卡时读取 `references/prompt-review-patterns.md`，按当前任务选择相关项，不逐项套用。

重点寻找：指令冲突、有效规则放错层级、同一含义重复加权、判断工作被写成固定步骤、示例过度限定、宿主事实失真，以及“做了动作”被写成“结果已成立”。

目标模型发生变化时，重新核对官方资料或该模型的行为证据；迁移只是目标配置变化，不另建一套评估流程。相邻模型或其他厂商的经验只能生成待验证假设。

**完成条件：** 每个 finding 指向具体位置、行为影响和直接证据，且没有把一般写作偏好包装成缺陷。

## 4. 提出最小修正

每项修正说明：要解决的失败、修改位置、预期改变、可能伤害的正常场景和验证方式。优先调整最接近行为决策的位置；能删除冲突或重复就不再叠加更强措辞。

用户只要求审查时给候选差异，不改文件。用户要求修改时，在授权范围内更新 Prompt 和相关引用；不能修改宿主或工具配置时说明边界。

**完成条件：** 候选差异只包含有证据支持的改动；允许结论为“保留当前 Prompt”或“证据不足”。

## 5. 验证行为

至少设计目标失败场景、邻近正常场景和必要边界场景。前后对照保持模型、宿主、材料、工具、权限和配置一致；实际执行已有授权与条件时才运行，否则交付可执行设计。

判断实际结果和产物，不按关键词、固定标题、模型自称遵守或单次偶然通过评分。生成式行为按风险决定是否重复；环境、工具和评分器问题与 Prompt 失败分开记录。

**完成条件：** 结论能说明目标问题是否改善、正常场景是否退化、证据适用于哪些配置；未实际对照时不声称优化有效。

## 交付

```markdown
## 目标行为与配置
模型 — 宿主 — 任务 — Prompt 表面 — 边界

## 发现
位置 — 行为问题 — 直接证据 — 影响

## 最小修正
候选差异 — 预期改善 — 副作用风险

## 验证
失败场景 — 邻近场景 — 前后结果／待执行条件

## 结论
保留／建议修改／证据不足 — 适用范围 — 下一步
```

若问题属于完整 Agent 的工具、环境、编排或产品结果，交给 `agent-eval`；仅把已经定位到 Prompt 表面的部分留在本 Skill。

**完成条件：** Prompt 结论有目标模型与行为证据，修正范围最小，验证包含目标与邻近场景，且没有把 Prompt 质量等同于完整 Agent 质量。
