# 评估测试信心

黑帆测试官在收帆前核对航海日志：主张有多强，证据就必须到哪里；证据不足的海域继续标为未知。

测试信心是“主张与证据是否匹配”，不是通过率，也不是发布批准。

按 `test-privateer` 定位项目 TCO 与当前 Spec 测试文档。当前 Spec 的证据边界、结论和残余风险写入其测试文档；只有跨 Spec 结论、项目风险状态或项目覆盖判断改变时才更新 TCO。

## 评估

1. 写清需要判断的事项、证据使用者和实际负责人。
2. 分开直接证据、间接证据、矛盾证据和未知。
3. 降低以下证据的权重：oracle 薄弱、执行条件污染、来源不清、不可重复或检查高度相关。
4. 对照主要风险：哪些被挑战、在哪种业务与系统条件下、使用什么 oracle。
5. 用业务和系统后果说明残余风险，不用“还有多少用例没跑”代替。
6. 比较下一项 probe 的证据价值、成本和延迟。

按 analyzing-product-risks 的生命周期更新风险唯一归属。证据只支持对应版本和场景，新反证可复开风险，不按通过率自动关闭。

## 信心说明

```markdown
## 待判断事项与负责人
事项 — 证据使用者 — 实际负责人

## 证据支持的主张
- 主张 — 直接证据 — 适用范围

## 证据不支持的主张
- 主张 — 缺失或不适用原因

## 薄弱或矛盾证据
- 证据 — 限制／冲突

## 残余风险与条件
- 风险 — 后果 — 不确定性 — 降低风险或补证条件

## 下一步选择
- 可选行动 — 证据依据 — 条件
```

提供证据支持的选择、条件和风险，不输出“允许上线”“批准发布”等发布决定。通过的检查只支持它实际挑战过的主张。

**完成条件：** 每项结论都能追溯到证据或明确缺口，结论强度不超过证据，最终决定仍由实际负责人承担；局部判断留在 Spec，TCO 只接收项目级变化。

交回调用方时附 handoff：信心评估路径、支持与不支持的主张、残余风险、下一项证据选择和是否建议继续／停止测试；不代替负责人作发布决定。
