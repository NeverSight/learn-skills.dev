# 导出测试用例脑图

把已经成稿的测试用例转换成 `.xmind`，用于评审、交接或团队熟悉的脑图阅读方式。用例文件仍是权威来源；脑图不新增、删除或改写 Case。用户尚未提供用例时，先回到 `designing-test-experiments` 完成设计，不先搭建空脑图。

读取用例文件和 `test-privateer/references/artifact-routing.md` 的编号规则。本包标准产物按 Case 表转换，保留 `C-xxx` 编号、关联依据、前置、操作、预期、当前安排和条件；已确认的执行记录和追溯矩阵不放进脑图。若来源采用 `tc-P0/P1/P2` 的 Markdown 标题层级，直接保留其原有层级和优先级，不强行改成本包编号。

脚本支持 Markdown 标题、Case 表、普通段落及平铺列表，保留标题下正文和表格额外字段；它不会自动将摘要表与分散详情按 ID 合并。代码围栏、缩进详情或非标准表格须先无损归一化，脚本报位置后停止，不静默丢弃。来源为摘要表＋按 ID 展开的详情时，先按原 ID 将共用准备及各条详情汇集成临时导出输入，使用字段 `ID、关联风险／依据、本轮安排、要检查什么、场景／前置条件、怎么操作、预期结果、需要保留什么、当前条件`。逐条回对源稿，保留步骤顺序、精确值及来源缺口，再转换；临时输入只是派生数据，不回写或另行维护为第二份用例。

在用例文件所在目录生成同名 `.xmind`，用户指定输出路径时除外。从本次实际加载的 Skill 目录定位 `scripts/md_to_xmind.py`，取得绝对路径后执行，不从使用方工作目录拼接仓库路径：

```bash
python3 "<实际 Skill 目录>/scripts/md_to_xmind.py" "<test-cases.md>"
```

使用临时输入时加 `-o <原用例同名.xmind>` 指定实际交付路径。核对源稿与导出结果的 Case 数量及每条关键字段；准备、操作或预期仍有遗漏时先补导出输入，不能将只有摘要的脑图交付为完整用例。

脚本保留路径、正则和字面反斜杠，只解开表格竖线的明确转义；跳过执行记录与附录整个章节，包括其中表格。异常 Case 行或不支持的详情必须先修正导出输入，源文档保持不变。脚本只使用 Python 标准库，生成 XMind 2020+ 的 ZIP/JSON 结构。导出后核对：源文件中的每条 Case 在脑图中有对应主题；前置、操作和预期没有互换；空白字段标「待确认」；文件是有效 ZIP 且包含 `content.json`。发现用例文件本身缺前置或 oracle，先报告来源缺口；为让脑图可直接交接，可将缺项主题命名为「待确认」，但不得编造规则或结果。

交付时列出源文件、`.xmind` 路径、导出的 Case 数量和按约定排除的执行记录和附录，说明脑图只是导出视图。复杂详情无法无损归一化时报告导出未完成，不把缺失详情的结果当作完整交付。
