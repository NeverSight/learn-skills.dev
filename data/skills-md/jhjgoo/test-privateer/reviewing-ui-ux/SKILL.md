# 评审界面与使用体验

**沿用户任务找断点，以适用依据作判断，用证据决定下一步。**

界面质量要落到用户能否发现入口、理解信息、实施动作、识别反馈、确认结果和失败后恢复。审美偏好、实现差异、违反约定和实际使用障碍分别判断。

## 接收当前问题

沿用已确认的用户任务、人群与知识、使用情境、材料和本轮阶段。只补会改变当前判断的未知；能依据已有材料回答的部分继续完成。直接调用本 Skill 就进行专项评审，不自动启动完整项目建图。

先确定材料支持什么：设计稿或截图支持材料评审，检查方案属于测试设计，已有操作记录可供结果分析。用户要求实际执行时，在已授权范围内交给 [running-test-sessions](../running-test-sessions/SKILL.md)，带上本专项的观察要求。沿用已有授权与编号，不重新索取相同确认。

**完成条件：** 当前要回答的体验问题与停止阶段明确；已有材料、可继续部分和取证缺口分开。

## 沿任务选择方法

将“样式不对、交互别扭、不好用”落到具体页面或组件、状态、用户动作与后果。按当前风险选择关注点，不逐页照抄全部质量分类。

| 当前问题 | 按需读取与使用 |
| --- | --- |
| 入口难找、含义不清、反馈不足、操作负担或恢复困难 | [交互与可用性](references/interaction-and-usability.md)：启发式评审、认知走查、用户任务观察、状态与恢复分析 |
| 元素与样式、布局、设计还原、长内容、语言、主题、缩放或环境适配 | [视觉与适配](references/visual-and-adaptation.md)：设计对照、元素交叉检查、代表性边界 |
| 感知、输入、导航、语义、辅助技术或标准符合性 | [无障碍](references/accessibility.md)：适用标准与完整任务中的互补证据 |
| 解释扫描/差异报告、比较版本、设计取证或解释体验指标 | [证据策略](references/evidence-strategies.md)：可比条件、基线、噪声、证据独立性及测量范围 |

每种方法要实际推导本次检查：它回答哪个问题，依据来自哪里，需要观察什么，什么结果会改变判断。第二种方法只有补足不同证据时才加入。方法可交叉使用，新证据也可使评审返回前一判断。

**完成条件：** 重要关注点有具体用户后果；所选方法能回答该问题，而非只列方法名称。

## 选择适用的判定依据

识别依据的来源及权威范围，再解释现象是否违背它：

- 有效需求与设计定义产品承诺；满足承诺与承诺是否利于使用分别判断。
- 标准须核对版本、等级、平台、适用条款和例外；组件与平台约定只约束相应情境。
- 批准基线用于识别变化，注明版本及批准范围；历史画面本身也可能有问题。
- 启发式和专家走查支持体验风险假设；用户观察支持所测人群、任务和条件下的行为结论。

依据冲突时，保留“符合哪项约定”和“仍有何用户后果”两条判断。只将会改变当前结论的冲突交回澄清，其余有依据的部分继续。

**完成条件：** 每个重要判断能追到适用依据；未知规则保留为缺口，偏好与有据问题分开。

## 形成发现与下一探查

提取实际可见或记录的内容，并引用对应材料。对未观察到的行为给出最小补证动作；环境不足时，仍交付材料支持的判断。截图、语义结构、操作轨迹和用户记录各有证明范围，不能互相冒充。

重要发现能追到：**用户任务 → 对象/状态 → 观察 → 依据 → 用户后果 → 证据范围 → 下一探查**。按用户当前请求呈现必要字段，不强制每次输出整张表。结论可为有依据的问题、待验证风险、预期变化或未发现可证明问题。

发现、缺陷和原因沿用 [artifact-routing](../test-privateer/references/artifact-routing.md) 的区分。沿用需求资产及稳定编号；独立评审可在对话或指定文档交付。依据任务影响确定优先顺序，频率、严重性或满意度缺证时不补造分数。

## 交回当前工作

需要风险排序时交给 [analyzing-product-risks](../analyzing-product-risks/SKILL.md)；复杂交互交给 [modeling-tests-with-ppdcs](../modeling-tests-with-ppdcs/SKILL.md)；具体用例或章程交给 [designing-test-experiments](../designing-test-experiments/SKILL.md)。

持续自动反馈由 [designing-test-automation](../designing-test-automation/SKILL.md) 选择层级与设计；异常原因由 [investigating-findings](../investigating-findings/SKILL.md) 调查；整体证据结论由 [assessing-test-confidence](../assessing-test-confidence/SKILL.md) 承接。本专项提供方法与判断，工具实现由宿主现有能力和任务条件决定。

**完成条件：** 当前问题有证据相称的回答；交回已完成、未覆盖、依据/产物、下一动作及执行状态。纯接口规则、界面实现或自动化接入请求保持原有入口；本次专项结束后，调用方沿原阶段继续。
