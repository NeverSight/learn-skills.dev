# 评估 Agent

评估模型、Prompt、工具、权限、记忆、编排和环境组成的 Agent 系统。帮助研发与测试定义质量、发现评估盲区、比较变化和纠偏结论；不负责搭建评测平台，不用模型榜单或单次 Judge 分数代替产品质量。

## 选择任务分支

- **设计测试：** 尚无可信的 Agent 测试方案；
- **审查现有评估：** 已有案例、指标、Judge、脚本或报告，需要判断是否测对；
- **比较版本：** Prompt、模型、工具、Skill、权限或编排发生变化；
- **分析失败：** 已有 trace、产物或环境状态，需要定位失败环节。

沿用用户请求的分支和停止边界。已有平台或日志就读取其证据；没有时输出工具无关的测试设计。实际运行仍需对应授权和可用环境。

## 1. 固定质量主张与系统版本

说明本轮要支持的判断及证据使用者，例如能否完成退款、候选 Prompt 是否改善、当前评估是否可信。记录用户任务、目标版本、模型与推理设置、Prompt／Skill、工具 schema、权限、记忆、编排、环境、数据和预算。

区分模型能力、当前 harness 和目标产品；benchmark 排名只能作为其任务与配置下的旁证。

**完成条件：** 能指出本轮评估代表哪个系统组合、哪类用户任务，以及结果将支持什么决定。

## 2. 选择质量维度与风险

从任务结果、业务规则、权限安全、证据可信、工具行为、对话协作、失败恢复、稳定性和资源效率中选择有业务后果的维度。需要完整质量模型时读取 `references/agent-quality-model.md`。

每个选中维度说明可能伤害、观察位置和为何值得投入；未选的重要维度说明排除或延期理由。不用统一总分替代关键风险。

**完成条件：** 每个主要风险都有测试方向或明确残余风险。

## 3. 设计或审查场景

场景优先来自生产失败、用户反馈、高频与高后果任务、历史缺陷和规则变化。每个失败场景配一个不应触发同一行为的邻近正常场景。

每个场景明确：用户目标、初始状态、业务与安全规则、允许动作、注入异常、期望环境状态、必要行为、允许变化、禁止行为和证据。场景必须能区分正确 Agent 与至少一种具体错误。

审查现有套件时，检查任务是否可解、环境能否重置、案例是否代表目标分布、是否泄漏答案或评分器，以及 Agent 是否能篡改测试。

**完成条件：** 场景既保护目标失败，也不会把合理替代路径或邻近正常任务判错。

## 4. 选择并质检 Oracle

按证据强度优先使用环境／业务状态、可执行测试与契约、文件／结构规则、必要轨迹、专家判断和校准后的 Judge。开放任务只固定承载业务、安全和权限约束的过程。

需要审查 Judge、重复统计或 reward hacking 时读取 `references/evaluator-checks.md`。先用已知正反例验证 Oracle：正确结果能通过、已知错误能失败、合理替代路径不会被拒绝。

结果状态分开记录：

- `pass`：有效案例中，证据支持目标主张；
- `agent_failure`：有效案例中，Agent 行为或结果不成立；
- `environment_error`：环境、依赖或工具无法支持有效判断；
- `invalid_case`：任务、规则或 Oracle 本身不成立。

**完成条件：** 每个通过条件都有观察位置；工具调用、最终文案和 Judge 自述没有冒充真实结果。

## 5. 分支交付

### 设计测试

给出最小场景集、Oracle、执行条件、需要记录的 trace／产物和停止边界。已有工具可满足时沿用，不默认选平台、写 harness 或生成评测代码。

### 审查现有评估

逐项判断案例、环境、Oracle、重复策略、指标和结论是否匹配。指出是“可观察”“可诊断”还是“足以作为门禁”；有 trace 平台不等于有可信发布门禁。

### 比较版本

在相同任务、初始状态、环境、权限与预算下配对比较。分别报告目标改善、邻近退化、高风险变化、环境异常、延迟和成本；样本不足时不宣称稳定提升。

### 分析失败

沿用户目标到环境结果追查：模型决策、Prompt、工具与参数、编排／handoff、记忆、环境、案例和 Oracle。优先选择能区分竞争解释的下一项证据。定位到 Prompt 表面时，向 `prompt-eval` 交回失败场景、目标行为、实际行为、直接证据、相关 Prompt 位置、邻近场景和验证方式。

## 交付

```markdown
## 评估对象与质量主张
系统版本 — 用户任务 — 证据使用者

## 风险与覆盖
质量维度 — 后果 — 场景／残余风险

## 评估质检
案例 — 环境 — Oracle — 重复／Judge — 可信边界

## 结果或执行设计
场景 — 状态 — 直接证据／观察位置

## 结论
证据支持什么 — 不支持什么 — 残余风险 — 下一验证
```

执行已有测试交给 `running-test-sessions`；异常原因需要深入调查时交给 `investigating-findings`；证据用于提测、灰度或停止判断时交给 `assessing-test-confidence`。本 Skill 不代替负责人批准发布。

**完成条件：** 被测系统与质量主张明确，重要风险有场景和可信 Oracle，Agent／环境／案例／评分器失败已区分，结论不超过实际证据，也没有把评测平台建设变成本轮默认工作。
