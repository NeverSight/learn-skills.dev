# 用 PPDCS 建模测试

PPDCS 用实际模型解释行为，再从模型派生测试条件。缩写不是产物。

## 输入

接收调用方选中的有界功能 M 或同等有界的行为机制、业务结果、相关风险和测试目标。包含多个独立业务结果时先拆分。用户直接调用但范围不清时，只澄清建模边界。

## 用 TEST 选模型

TEST 用于选型，不写进报告充数：

- Triggers：流程、规则、数据域、因素交互或状态变化的信号；
- Essentials：真正决定行为和结果的机制；
- Spanning Differences：不同模型会暴露哪些不同测试条件；
- Targets：有界功能和本次测试目标。

选择一个主模型。第二模型只有产生主模型没有的具体 TCON 时才保留。

| PPDCS | 必须交付的模型 | TCON 来源 |
| --- | --- | --- |
| Process | 参与者、步骤、分支、失败、恢复和结果 | 路径及变化 |
| Parameter | 条件、取值、动作、规则、缺口和冲突 | 决策规则 |
| Data | 数据域、分区、边界、约束和转换 | 分区及边界 |
| Combination | 因素、水平、约束、交互强度和可行组合 | 生成组合 |
| State | 主体、状态、事件、守卫、输出及合法／非法迁移 | 迁移及序列 |

优先用 Process、Parameter、Data 或 State 理解行为。只有因素、水平和约束已经明确，且需要压缩组合覆盖时才用 Combination。没有标签的箭头、没有取值的参数清单和模型名称都不算模型。

## 派生 TCON

1. 写明覆盖准则和排除项。
2. 从路径、规则、分区、有效组合或迁移派生 TCON。
3. 每个 TCON 用稳定 ID 追溯到具体模型元素。
4. 以下任一项不同就拆分：前置状态、角色或权限、数据分区或边界、动作或刺激、观察位置、oracle、关联风险、测试层级或环境。
5. 记录模型暴露的新问题、风险和未知，不把未知规则写成 oracle。

## 交付并停止

向调用方交付实际模型、覆盖准则、排除项、派生测试条件及来源、新问题和未知，供后续设计使用。每个测试点用角色、业务对象、动作和可观察结果命名。用户侧的展示深度按任务选择：点名建模或需要评审时展示完整模型；其他场景突出业务测试点，必要模型与追溯仍须可访问。调用方决定持久化、选择状态和是否具体化。用户只要求 PPDCS 或测试建模时，到此停止。

**完成条件：** 主模型是可检查的实际模型；每个 TCON 可追溯到路径、规则、分区、组合或迁移；粒度差异已拆开；第二模型如存在，新增覆盖明确；TCON 没有冒充可执行测试。
