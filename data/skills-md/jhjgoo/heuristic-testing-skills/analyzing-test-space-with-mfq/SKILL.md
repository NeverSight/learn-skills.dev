# 用 MFQ 分析测试空间

MFQ 的直接产物是 MFQ 覆盖大纲：组织候选测试点、风险、问题、重要数据和已知缺陷，不把每个节点当场展开为可执行测试。

## 1. 接收范围与上下文

接收调用方给出的有界范围，以及业务结果、角色、流程、系统边界、上下游、数据流、状态、规则和证据状态。

**完成条件：** MFQ 的分析边界明确，条目需要关联的业务或系统关系可见。

## 2. 建立 MFQ 覆盖

- **M — 单功能：** 当前分析粒度下可独立分析的一个功能，写清输入、输出或职责边界，以及它服务的业务结果或系统职责。页面、菜单和泛化功能名不能替代 M。
- **F — 交互：** 两个或以上功能、角色、系统、数据或时间之间会影响行为的关系，写清参与方、交互边界和业务／系统影响。
- **Q — 质量特性：** 挂在具体 M、F 或产品结果上的质量关注，写清关注的质量、可能后果及可观察方向。

M 始终是当前粒度下的单功能；粒度变化只调整该功能内部需要关注的规则、状态和边界，不把规则或状态另立为 M。拆开包含多个功能的大功能，合并不改变覆盖判断的碎片。F 和 Q 在覆盖阶段可以只是防遗漏提醒；当前风险值得深化时，将专题分析候选记入“下一步”。

每个条目保持轻量，至少记录：

- 稳定 ID 与 M／F／Q 类型；
- 具体功能、交互或质量关注；
- 边界及其业务／系统关系；
- 候选测试想法；
- 相关风险、问题、重要数据和已知缺陷（按当前已知情况记录）；
- 证据状态（已知／推断／未知／执行观察）及可能的下一步。

复用已有 ID；新增内容按 `M-01`、`F-01`、`Q-01` 递增编号，排序变化不改号。合并重复条目并保留来源和关联；新证据推翻旧内容时直接修正并简记原因。

**完成条件：** 重要的 M、F、Q 已形成可用覆盖大纲；条目能追溯到真实产品内容，风险、问题、数据、缺陷和证据缺口均显式可见。无需为每个节点生成可执行任务。

## 3. 交付并停止

返回使用 MFQ 的理由、M／F／Q 条目、候选测试点、重要数据、已知缺陷、证据缺口和排除项。调用方决定持久化、排序和下一阶段。用户直接要求 MFQ 时，交付覆盖大纲后停止。

**完成条件：** MFQ 覆盖大纲可继续使用；M 是有边界的功能，F 是具体交互，Q 挂在产品内容或结果上；条目能追溯到真实产品内容；未把候选测试点冒充测试结果或可执行用例。
