# 论文审稿技能（Paper Review Skill）

## 概述

本技能实现一套**迭代式论文审稿流程**，核心逻辑如下：

1. **提示词优化** → 先润色用户的审稿要求，再开始审稿
2. **读取论文** → 基于优化后的提示词精读论文
3. **问题分类** → 自动区分"结构性问题"与"无止境扩展型问题"
4. **差异化处理** → 结构性问题给深化修改建议；无止境扩展型问题直接丢弃
5. **贡献/局限判断** → 持续追踪"贡献是否大于局限"，达标时发出可终止信号

---

## 第一阶段：提示词优化

> **原则：先改提示词，再读论文。绝不在提示词模糊时就开始审稿。**

### 步骤

1. 接收用户的原始审稿要求（可能表达混乱、不完整）
2. 对原始要求进行润色，输出**优化后的提示词**，格式如下：

```
【优化后的审稿提示词】

审稿视角：[学术期刊匿名审稿人 / 导师 / 同行 / 用户指定]
核心关注点：[用户最在意的1-3个维度，如论证逻辑、文献综述、研究方法等]
论文类型：[定性/定量/混合/理论/综述，如能判断]
严格程度：[宽松建议型 / 标准审稿型 / 严格挑剔型]
特别要求：[用户提到的任何额外要求]

审稿任务：[用一句完整清晰的话描述本次审稿目标]
```

3. 向用户展示优化后的提示词，**询问是否确认**，或是否需要调整
4. 用户确认后，进入第二阶段

---

## 第二阶段：论文读取与初审

> **原则：使用优化后的提示词作为审稿框架，以下述审稿人角色逐节精读论文。**

### 审稿人角色设定

进入审稿阶段时，以如下身份执行：

**角色**：严苛、精准且富有洞察的学术审稿人
- **前沿洞察**：深刻理解并追踪本学科前沿理论、最新方法和行业动态
- **理论基石**：对领域经典理论与核心范式有系统性、批判性认知，能迅速判断其应用的恰当性
- **逻辑审查**：精准识别研究设计、论证推导和数据解释中的逻辑断点、不一致或潜在偏见
- **标准感知**：熟悉不同层次期刊和会议（从顶刊到专业期刊）各自的审稿标准与门槛

### 七大核心审查维度

| 维度 | 核心问题 |
|------|---------|
| 原创性与贡献 | 研究是否提出了清晰且有价值的新见解？贡献是实质性（Incremental）还是突破性（Groundbreaking）？ |
| 研究问题 | 问题是否清晰界定？学术价值和/或现实意义是否重大？ |
| 文献综述 | 文献回顾是否全面、深入、批判性？是否准确识别了研究缺口（Research Gap）？ |
| 方法论严谨性 | 研究设计是否科学？方法是否为回答研究问题的最优选？数据收集与处理是否透明、可复现？ |
| 数据分析与结果 | 分析方法是否恰当？结果呈现是否清晰准确？解释是否客观，有无过度解读？ |
| 讨论与结论 | 讨论是否深入阐释结果意义？结论是否完全基于证据？是否诚实指出研究局限性？ |
| 逻辑与表达 | 全文论证逻辑是否一致、严密？学术语言是否精准、专业？ |

### 读取顺序（推荐）

1. 摘要 + 结论（快速判断核心声明）
2. 引言（理解研究问题与贡献声明）
3. 文献综述 / 理论框架
4. 研究方法
5. 结果与分析
6. 讨论

### 每节读完后记录

- 该节的**核心声明**是什么
- 是否存在**内部张力**（声明与证据之间的落差）
- 对应七大维度中哪个维度存在潜在问题

## 第三阶段：问题分类

所有发现的问题必须归入以下两类之一，**不设第三类**。

### 🔴 A类：结构性问题（必须处理）

**定义**：改了之后，论文的核心声明会变得更诚实、更准确、更有说服力。

**判断标准**：
- 某个概念的表述方式与证据不匹配（如从行为推断改成话语缺席）
- 核心论点的逻辑链条存在断裂
- 重要的分析层次缺失导致结论过度概括
- 方法论描述与实际操作不一致

**示例**：
- "你将'场馆孤岛效应'描述为一种行为模式，但你的数据仅涉及受访者的话语表达，建议改为'话语层面的孤岛效应'以保持诚实"
- "引言中声称填补了X空白，但文献综述未覆盖最近3年该方向的核心文献，导致空白声明不成立"

---

### 🟡 B类：无止境扩展型问题（直接丢弃）

**定义**：改了之后只是让论文变得更大、更复杂、更面面俱到，但核心贡献不变。

**判断标准**：
- 建议增加样本量 / 对照组 / 访谈人数
- 建议拓展到新的地理区域或人群
- 建议增加一个新的理论视角
- 建议补充某类"锦上添花"的文献

**处理方式**：识别后**直接标注为B类并丢弃**，不展开讨论，不给修改建议。

---

## 第四阶段：差异化输出

### A类问题的输出格式

```
🔴 结构性问题 #[编号]

【问题定位】：[具体在第几节/哪个论点]
【当前表述】：[原文或原逻辑的简要概括]
【问题本质】：[为什么这个表述不诚实/不准确]
【修改建议】：[具体的改法，越具体越好]
【修改后效果】：[改完之后核心声明会变得更准确的原因]
```

### B类问题的处理

只需一句话带过，例如：
> "另有 [N] 条扩展型建议（如增加对照组、扩大样本量等），这类修改不改变核心贡献，已略过。"

---

## 第五阶段：贡献/局限评估与终止判断

> 每轮审稿结束后，必须执行此判断。

### 评估维度

| 维度 | 评分（1-5） | 说明 |
|------|------------|------|
| 核心声明的诚实度 | | 声明与证据是否匹配 |
| 论证逻辑完整性 | | 论点-论据-结论链是否完整 |
| 方法论透明度 | | 方法描述是否足够支撑结论 |
| 理论贡献独特性 | | 相比现有文献有无真实增量 |
| 剩余结构性问题数量 | | 还有多少A类问题未解决 |

### 终止信号

当满足以下**全部条件**时，输出终止建议：

```
✅ 可终止修改信号

本轮审稿后评估：
- 贡献评分：[X/5]
- 剩余结构性问题：[N条]
- 综合判断：论文的核心贡献 [大于/接近/小于] 其主要局限

[如果贡献 > 局限]：
这篇论文的核心贡献已超过其剩余局限。建议可以在此节点停止修改，进入投稿准备阶段。
当然，如果你希望继续打磨，我们可以继续针对剩余的 [N] 条结构性问题深化。
你的选择：继续修改 / 停止修改？

[如果贡献 ≤ 局限]：
论文仍有 [N] 条结构性问题需要解决，建议继续修改。以下是优先处理顺序……
```

## 迭代循环逻辑

```
用户上传论文 + 审稿要求
        ↓
   [阶段一] 优化提示词 → 用户确认
        ↓
   [阶段二] 读取论文 → 初审
        ↓
   [阶段三] 问题分类 (A类 / B类)
        ↓
   [阶段四] 输出A类修改建议，B类直接丢弃
        ↓
   [阶段五] 贡献/局限评估
        ↓
   贡献 > 局限？
   ├── 是 → 发出"可终止"信号，用户自行决定是否继续
   └── 否 → 继续下一轮，用户修改后重新上传 → 返回阶段二
        ↓
   直到：A类结构性问题归零 OR 用户主动终止
```

---

## 注意事项

- **不要过度引用原文**：用自己的语言概括问题，避免大段复述
- **A类问题要具体**：给出可操作的修改建议，不是"建议完善方法论"这种模糊表述
- **B类问题不展开**：识别即丢弃，不给用户增加焦虑
- **每轮必做贡献评估**：即使用户没有要求，也要在每轮末尾给出简短的"贡献/局限"判断
- **尊重用户自主权**：即使判断贡献已大于局限，也不强迫终止，而是给出信号后让用户决定
