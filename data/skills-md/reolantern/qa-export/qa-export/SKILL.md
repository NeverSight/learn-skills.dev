# qa-export

问答原文已经在本地会话记录里。**不要自己复述重写**——既费上下文又会走样。
一律调用本 SKILL.md 同目录下的 `scripts/qa_export.py`（下称 `$SCRIPT`）。

## 分工

脚本只做一件机械的事：**按序号取出原文**（只含主线问答，子 agent 的对话不导出）。
「用户指的是哪几轮」是理解问题，由你来判断——整段对话就在你的上下文里。
所以除了「最后 N 轮」，一律先看序号列表，自己对上，再用 `-t` 选。

## 路径一：用户明确说了「最后几轮」

不需要理解，直接走：

```bash
python3 "$SCRIPT" -n 2 --dry-run -o QA.md   # 空跑，只回每轮一行
python3 "$SCRIPT" -n 2 -o QA.md             # 对得上就去掉 --dry-run
```

`-n` 已自动排除用户刚发出的这条请求（当前这一轮还没结束），不要手动 +1 补偿。

## 路径二：其他所有情况

「从我们开始讨论 xxx 起的所有问答」「关于 yyy 的那几轮」「我提架构问题的那些」
「你给了方案的那两轮」——都走同一条路：

```bash
python3 "$SCRIPT" -l --tail 20              # 列出最近 20 轮：序号、时间、提问摘要
```

对照你上下文里的对话认出是哪几轮，然后：

```bash
python3 "$SCRIPT" -t 7-12 --dry-run -o QA.md
python3 "$SCRIPT" -t 7-12 -o QA.md
```

`-t` 接受 `7`、`7-12`、`3,5-7` 这些写法。要找的轮次比 20 更早就加大 `--tail`，
会话很长时先用 `-g "关键词"` 缩小范围拿到序号（关键词从用户原话或你记得的提问里取）。

**不要用 `--from` / `--to` 让脚本去字符串匹配用户的意思**——那是给人在命令行用的，
按你的理解选序号才准。

## 两条硬约束

- **导出时始终带 `-o`**（`-l` / `-g` 是列表命令，不需要它）。
  不带 `-o` 导出时正文会打到 stdout，也就是全部进你的上下文。
  只有用户明确要求「在对话里给我看」才可以省掉。
- **`-l` 一定带 `--tail`。** 直接 `--tail 0` 会把整个会话的提问列表读进上下文。

用户没说存哪里就用 `QA.md`（`-o` 是追加，文件不存在会自动建）。
认不准是哪几轮就把候选列给用户确认，不要猜着导。

## 其他选项

| 选项 | 作用 |
| --- | --- |
| `--sessions` | 列出当前目录下的会话（Claude Code 和 Codex 都扫） |
| `-s ID` | 指定会话：id 前缀，或 Claude Code 的会话名（会自动切到该会话的目录） |
| `-a claude\|codex` | 指定读哪个 agent 的记录，默认自动判断 |
| `-C DIR` | 指定项目目录，默认当前目录 |
| `--no-answer` | 只导出提问 |
| `--all-branches` | 保留被改写重发时废弃的旧提问 |
| `--include-pending` | 不排除当前进行中的那一轮 |

## 报告方式

导出完只说写了哪几轮、写进了哪个文件，**不要把问答内容复述一遍**。

可以顺带提一次：用户自己在输入框敲 `! python3 "$SCRIPT" -n 1 -o QA.md`
（或装好的 `qa` 命令）是零 token 的，完全不经过模型。

## 一个时序前提

某一轮的回答要等它生成完才落盘，所以「导出刚刚这一轮」只能在那一轮结束之后跑；
`-n` 的自动排除处理的正是这件事。
