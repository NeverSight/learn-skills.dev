Language-fit audit for any codebase in any language. Use when the user asks whether a project, service, or module should be rewritten or partly ported to another language (C, C++, Rust, Go, C#, Java, Zig, Swift, etc.), whether the current language is the right choice, or where a native addon, WebAssembly, a sidecar, or a language consolidation would pay off. Also use when hot paths, GC pauses, CPU-bound work in an interpreted runtime, memory blowups, slow startup, or bug-prone low-level code suggest a different language might fit better, including Electron, Node, Python, JVM, and .NET native-module decisions.
