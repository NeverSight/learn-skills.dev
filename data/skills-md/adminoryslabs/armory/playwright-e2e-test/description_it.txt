Scrive ed esegue un unico test end‑to‑end con Playwright per un singolo flusso utente critico (es. checkout, prenotazione, iscrizione), così l’agente può verificare il proprio lavoro in un browser reale invece di affermare “funziona”. Propone il piano di test in linguaggio semplice prima e attende l’approvazione, riutilizza una configurazione Playwright esistente o ne installa una minima, esegue solo quello spec e dimostra che il test può effettivamente fallire. Quando il test fallisce, riporta con evidenza e non modifica mai il test solo per farlo passare — l’umano decide se il bug è nell’app o nel test. Usa quando l’utente chiede di creare un test e2e, un test Playwright, un test browser o di coprire un flusso critico con QA automatizzata.
