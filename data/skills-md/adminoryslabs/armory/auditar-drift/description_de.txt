Erkennt Diskrepanzen zwischen dem Versprochenen (PRD.md und ADRs) und dem, was der Code tatsächlich implementiert — Geister‑Features, ausgelassene Geschäftsregeln, nicht eingehaltene Architekturentscheidungen, technische Schulden. Erstellt einen DRIFT.md‑Bericht mit nachgewiesenen Befunden und gibt für jeden an, ob der Code korrigiert oder die Dokumentation gerechtfertigt aktualisiert werden soll. Verwenden Sie dies, wenn der Benutzer um ein Drift‑Audit bittet, prüfen Sie, ob die Implementierung noch mit dem PRD/ADRs übereinstimmt, oder finden Sie Lücken zwischen Dokumentation und tatsächlichem Code.
