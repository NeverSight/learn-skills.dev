Développement correct de modules Magento 2 / Mage‑OS / Adobe Commerce : création de nouveaux modules, extension ou personnalisation du comportement du cœur (choix entre plugin, observer ou préférence), schéma déclaratif et tables personnalisées, attributs produit/EAV, injection de dépendances, logique de checkout/panier/totaux et frais de commande ou de livraison personnalisés, configuration admin (system.xml/ACL), grilles d’administration et ui_components, XML de mise en page et view models, mise à jour ou migration de modules personnalisés (y compris vers Mage‑OS) et leurs contraintes composer.json, ainsi que des guides de débogage pour les échecs de setup:di:compile, les mises en page qui ne s’appliquent pas et les observers/plugins qui ne se déclenchent pas. Utilisez cette compétence chaque fois que l’utilisateur écrit, modifie ou débogue du code Magento, Mage‑OS ou Adobe Commerce personnalisé — création ou extension d’un module/extension, interception du comportement du cœur, ajout de tables de base de données ou d’attributs, construction de paramètres admin ou de grilles, blocs ou modèles front‑end, ou correction d’erreurs provenant des commandes bin/magento — même s’ils ne mentionnent pas explicitement « module ». Déclencheurs forts : « comment remplacer X dans Magento », « mon layout/plugin/observer Magento ne fonctionne pas », « dois‑je utiliser un observer ou un plugin », ou tout ce qui touche app/code, di.xml, events.xml, db_schema.xml ou layout XML. NE PAS déclencher pour les audits de performance/mise en cache du storefront (utilisez la compétence magento‑audit), l’achat ou la recommandation d’extensions tierces, les tâches administratives opérationnelles (création de coupons, importation de CSV de produits, paramètres de session/connexion), les questions d’hébergement/dimensionnement Magento, le contenu/SEO, ou les plateformes non Magento comme Shopify ou WooCommerce.

Veuillez toujours répondre dans la langue de l’utilisateur.
