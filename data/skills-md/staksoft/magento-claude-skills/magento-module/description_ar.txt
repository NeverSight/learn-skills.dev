تطوير وحدات Magento 2 / Mage‑OS / Adobe Commerce بشكل صحيح: إنشاء هياكل جديدة للوحدات، توسيع أو تخصيص سلوك النواة (اتخاذ قرارات بين الـ plugin والـ observer والـ preference)، المخطط الإعلاني والجداول المخصصة، سمات المنتج / EAV، حقن الاعتمادات، منطق سلة/الدفع/الإجماليات والرسوم المخصصة للطلب أو الشحن، إعدادات الإدارة (system.xml/ACL)، الشبكات الإدارية ومكونات الواجهة (ui_components)، XML التخطيط والنماذج العرضية (view models)، ترقية أو ترحيل الوحدات المخصصة (بما في ذلك إلى Mage‑OS) وقيودها في composer.json، ودلائل تصحيح الأخطاء لأخطاء setup:di:compile، عدم تطبيق التخطيط، والـ observers/ـ plugins التي لا تُنفذ. استخدم هذه المهارة كلما كان المستخدم يكتب أو يعدل أو يصحح شفرة Magento أو Mage‑OS أو Adobe Commerce مخصصة — إنشاء أو توسيع وحدة/امتداد، اعتراض سلوك النواة، إضافة جداول قاعدة بيانات أو سمات، بناء إعدادات إدارية أو شبكات، كتل أو قوالب للواجهة الأمامية، أو إصلاح أخطاء من أوامر bin/magento — حتى وإن لم يذكر "وحدة" صراحة. المحفزات القوية: "كيف يمكنني تجاوز X في Magento"، "تخطيط/plugin/observer الخاص بي في Magento لا يعمل"، "هل أستخدم observer أم plugin"، أو أي شيء يتعلق بـ app/code أو di.xml أو events.xml أو db_schema.xml أو XML التخطيط. لا تُفعّل هذه المهارة لتدقيقات أداء/ذاكرة التخزين المؤقت للواجهة (استخدم مهارة magento-audit)، أو لشراء أو التوصية بامتدادات طرف ثالث، أو مهام إدارية تشغيلية (إنشاء قسائم، استيراد CSV منتجات، إعدادات الجلسة/تسجيل الدخول)، أو أسئلة استضافة/تحجيم Magento، أو محتوى/نسخ SEO، أو منصات غير Magento مثل Shopify أو WooCommerce.
