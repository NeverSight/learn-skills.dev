Conduce cambios de comportamiento testeables y correcciones de errores mediante ciclos disciplinados rojo‑verde‑refactor con pruebas de regresión observables. Úsalo al implementar nuevas funcionalidades con pruebas unitarias/de integración, al corregir errores reproducibles, al modificar la lógica de negocio o al escribir contratos de comportamiento test‑first — incluso si el usuario no dice explícitamente “fable‑tdd” (p. ej., “arreglar este error test‑first”, “escribe una prueba y hazla pasar”, “añade esta función con pruebas”, “TDD esta lógica”). NO lo uses para prototipado exploratorio amplio sin aserciones claras (usa fable‑discover o fable‑plan) o para revisiones post‑implementación (usa fable‑review).
