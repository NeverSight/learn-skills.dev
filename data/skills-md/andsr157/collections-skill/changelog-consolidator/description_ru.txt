Используйте, когда у пользователя есть документы журнала изменений из нескольких фронтенд‑модулей в этом сайте документации VitePress (каждый находится в docs/en/<module>-front/changelog.md, журналы в стиле git‑commit с хешом/автором/файлом/причиной/влиянием) и он хочет объединить их в ОДИН консолидированный, высокоуровневый журнал изменений, сгруппированный по дате с разбивкой по модулям. Консолидация производится только для фронтенд‑модулей — каталоги, заканчивающиеся суффиксом «-front» (например, fund-front, activity-front) — при этом пропускаются backend, mobile и другие не‑front модули, даже если их журналы присутствуют. Триггеры: «gabungkan changelog semua module front», «buat log version gabungan module -front», «summarize semua module frontend jadi satu changelog per tanggal» или любой запрос на объединение нескольких журналов изменений отдельных модулей в один сжатый документ. Ключевая особенность: конденсация, а не переоформление — убрать пути к файлам, хеши коммитов, авторов, развернутый текст Reason/Impact; оставлять только однострочное резюме каждого изменения, отмеченное тегом Added/Changed/Fixed/Removed/Other, сгруппированное по дате, затем по модулю.
