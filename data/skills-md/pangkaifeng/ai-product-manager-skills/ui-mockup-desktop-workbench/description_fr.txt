PRD vers alignement de livraison UI haute-fidélité / maquette UI du poste de travail de bureau : lorsqu’un utilisateur possède déjà un PRD, des spécifications UI, un chemin de projet front‑end réel, des captures d’écran ou une liste d’états de page, il doit d’abord extraire la structure UI, le modèle d’état et la mise en page ASCII du PRD, puis les utiliser lors du passage aux maquettes haute‑fidélité, à l’aperçu natif du projet ou à la remise pour le développement. Priorisez la sortie de la route/composant d’aperçu natif du projet ; ne générez du HTML autonome que lorsque seule une validation de concept précoce est disponible ou lorsque l’intégration avec le projet réel n’est pas possible. Le livrable doit inclure les artefacts de la phase structurale, le contrat d’écran, la carte des composants, les notes d’implémentation, les captures d’écran / résultats de validation, ainsi que la frontière de migration entre HTML et aperçu.
