Use when a user starts a new project or works across repository workspaces and needs to scan the product, users, business workflows, technical architecture, repository boundaries, domain language, reading entry points, and historical pitfalls, then generate or continuously maintain a global PROJECT_CONTEXT.md. Suitable for users who say “first take a complete look at the project and consolidate the context,” “create a context document for this project,” or “update this pitfall to the project context.” Not intended for drafting a single PRD, pure directory governance, or one‑off code implementation.
