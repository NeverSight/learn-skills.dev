Produit un plan de mise à jour personnalisé pour Sanity Studio en inspectant les versions installées du dépôt, la configuration et le code source, puis en ne signalant que les changements incompatibles qui s'appliquent réellement. Couvre Studio v3 et les versions ultérieures ; les projets v2 sont identifiés et redirigés, pas planifiés. Utilisez cette compétence chaque fois que quelqu'un souhaite mettre à jour, migrer ou moderniser un Sanity Studio à travers une ou plusieurs versions majeures à partir de v3, demande ce qui se cassera s'il augmente le package `sanity`, demande pourquoi son Studio s’est cassé après une mise à jour, ou demande à quel point son Studio est en retard. Se déclenche sur « upgrade sanity studio », « migrate our studio to v6 », « bump sanity », « what breaks if we upgrade », « our studio is on an old version », « sanity upgrade plan », « is our studio out of date », « we are several majors behind ». NE DOIT PAS être chargé pour la mise à jour de dépendances non‑Sanity, pour les questions sur `apiVersion` du Content Lake, pour les migrations de contenu ou de schéma qui modifient les documents, ou pour la création d’un nouveau projet Sanity.

Veuillez toujours répondre dans la langue de l'utilisateur.
