Erstellt einen maßgeschneiderten Sanity Studio-Upgrade-Plan, indem die installierten Versionen, die Konfiguration und die Quelle des Repositorys überprüft und dann nur die tatsächlich geltenden Breaking Changes gemeldet werden. Deckt Studio v3 und höher ab; v2-Projekte werden identifiziert und umgeleitet, nicht geplant. Verwenden Sie diese Fähigkeit immer dann, wenn jemand ein Sanity Studio über eine oder mehrere Hauptversionen ab Version 3 aktualisieren, migrieren oder modernisieren möchte, fragt, was kaputt geht, wenn er das „Sanity“-Paket anstößt, fragt, warum sein Studio nach einem Upgrade kaputt gegangen ist, oder fragt, wie weit sein Studio zurückliegt. Löst Folgendes aus: „Upgrade von Sanity Studio“, „Migrieren unseres Studios auf Version 6“, „Bump Sanity“, „Was geht kaputt, wenn wir ein Upgrade durchführen“, „Unser Studio ist auf einer alten Version“, „Sanity Upgrade-Plan“, „Ist unser Studio veraltet“, „Wir sind mehrere Majors im Rückstand“. NICHT zum Aktualisieren von Nicht-Sanity-Abhängigkeiten, für Content Lake „apiVersion“-Fragen, für Inhalts- oder Schemamigrationen, die Dokumente ändern, oder zum Einrichten eines neuen Sanity-Projekts laden.
