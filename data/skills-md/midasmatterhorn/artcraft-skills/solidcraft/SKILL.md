**Audit basis.** Refreshed **2026-11-15** against tag **v0.42.0**, commit **`1b1e940cc48e4d1d5d01971a4be20e2e55647066`** ("Merge main into release for 0.42.0", 2026-11-14; `git rev-parse HEAD` in the pinned checkout confirms it). The previous release this skill described was **v0.41.0** (`3c8efdb51952ed9a5f3ebc722c2bad1454fe6d80`).

**v0.41.0 → v0.42.0 delta.** This release is about trust and interchange, not new modelling depth. On top of it: `file.save` takes `sign`/`signing_key` and is refused for scripts and agents, `file.verify` reports the chain, `file.gpg_keys` lists GnuPG keys, and `doc.open` takes `verify` (`crates/engine/src/cmd/file.rs`; `crates/engine/src/gpg.rs`). Interchange gains a twentieth format row, `kicad` — KiCad `.kicad_pcb`/`.kicad_pro` boards read as a B-rep substrate with drilled holes, copper, silkscreen, text and footprint 3D models (`crates/io/src/kicad_in.rs`; `docs/kicad-import.md`). The registry grew 642 → **647** ids (+5, none removed: `file.verify`, `file.gpg_keys`, `sketch.insert_airfoil` for Selig/Lednicer `.dat` sections, `solid.cell_grid` for hex/square/triangle cell fields, `view.origin_axes_across_view`); `surface.fillet` is still the only planned id. Typed schemas cover **612 of 647** (was 572 of 642) and 35 commands describe neither (was 70). Design format 55 → **57**: folded changes for cell grids, frame standard sizes, frame member placement, expression-driven occurrence moves and pattern names by source, plus two pending changes (extrude-to-object placements, plane-at-angle following a named axis) — a probe save writes `"format": "solidcraft/57"` with those two named in `format_pending`. Measurements stop being tessellation guesses: B-rep volume, area, centre of mass and box come from SMLib mass properties (`crates/kernel/src/measure.rs`, replies `measured_by: "smlib"`), where 0.41 meshed the body at a tolerance. MCP keeps its 22 tools but rewrites their schemas from JSON-Schema `type` unions to `anyOf` so Moonshot and Gemini accept the list, and documents `view.pick` as an app-only control method, absent from the registry and from headless MCP. The CLI gains `--require-allow-path` and `--script-relative`; the workspace gains the `display-units` crate (32 → 33) and docs 139 → 140 pages.

**v0.40.1 → v0.41.0 delta.** The previous release added the plugin system, not new modelling: two crates (`craft-plugin`, `craft-plugin-wasm`) run sandboxed WebAssembly components against the same command registry (WIT `craft:plugin@0.1.0`, one call one undo step, no WASI or network), and the registry grew 634 → 642. ## Overview

SolidCraft is an open-source parametric 3D CAD application in pure Rust by Tangency Labs (MIT OR Apache-2.0). Sketch, constrain and build solids on an editable feature timeline; change a dimension and the model rebuilds. It is **independent and clean-room**: behaviour is designed from public documentation and general CAD conventions, reference tests use analytic values and FreeCAD as an external oracle, and it is not affiliated with any CAD vendor (`README.md` Disclaimer; `NOTICE`). **Status: early but usable for simple parts** — the generated oracle reports **90/90** reference parts passing, while `README.md` and `docs/capabilities.md` still say "75 of 76" (trust `docs/oracle.md` and `solidcraft-cli oracle`). The B-rep kernel is `solidcore`, a safe-Rust port of NVIDIA's SMLib (`solidcore/README.md`, `crates/smlib/src/lib.rs`); 0.42.0 still vendors the same tree, advanced it with the usual round of kernel fixes, and now measures through its exact mass properties instead of a tessellation. One command registry serves the desktop app (egui), the browser app, the CLI, the control channel, the MCP server and plugins.

### Signed provenance (new in v0.42.0)

- **A design can prove what was signed.** The container may hold `provenance/log.cbor`: a bounded chain of records, each signing a CBOR manifest of the SHA-256 of `document.json` and `container.json` plus the name, length and digest of every other authoritative entry, chained by the digest of the previous record and naming the file's oldest record (`crates/io/src/design/provenance.rs`; `docs/formats/cose-provenance.md`). Record kinds: COSE_Sign1 (RFC 9052, Ed25519, verified in-process) and OpenPGP (GnuPG, detached signature plus the signer's transferable public key, so a smartcard key never leaves the card). Derived data is not signed: `cache/`, previews, thumbnails, the provenance entry itself and the ZIP directory.
- **The entry is additive and bounded.** It changes nothing in `document.json`, a build that does not know it ignores it (and drops it on save), and the envelope is capped at 8 MiB, 64 records of 4 MiB each, 10,000 signed parts and 4 KiB text fields; when full, the oldest records are dropped and the new record signs that fact. A removed newest record leaves no trace — the report is then truncated, never "valid".
- **Commands and preferences.** `file.verify` (path defaults to the design's file) returns `status` (`unsigned`, `valid`, `not_covered`, `invalid`, `unsupported`), `truncated` and per-record `{method, key_id, user_id?, author?, created?, format, covered}`; a probe on an unsigned `.sc` returns `status: "unsigned"` with `records: []`. `file.gpg_keys` returns `{available, keys: [{fingerprint, key_id, user_id, on_card}]}` — desktop only. `file.save` takes `sign` and `signing_key` (container only) and returns `signature`; **scripts and agents are refused** — live reply: "signing is only available from the app's Save, with the key chosen in Preferences; a script or agent cannot sign". `doc.open` takes `verify: true` and reports `signature`. Preferences ▸ **Security** (`crates/ui-egui/src/prefs/security.rs`) carries the trust model: `sign_saved_designs` (default false) signs every app save, `signing_key` names the GnuPG key (empty: GnuPG's default), `trusted_signing_keys` lists the fingerprints whose signatures the app shows as verified (any other valid signature shows in grey with its fingerprint and no user id), and `verify_opened_designs` (default false) verifies on open instead of only on request.
- **A signature is tamper-evidence, not identity.** It proves a key holder signed a version of the design; deciding whether that key is the person it claims is the recipient's job. It also does not stop anyone editing and re-signing. A recipient that trusts a signature should evaluate the design from its timeline instead of adopting a stored model cache.

### Plugins (experimental, v0.41.0 surface, unchanged at v0.42.0)

- **Command plugins are sandboxed WebAssembly components** that reach the app only through the command registry. The interface is WIT package `craft:plugin@0.1.0`, capability `commands@0.1`; a manifest declares its entries (1–32), up to 128 command ids it may call, optional slot hints, limits and permissions (`docs/plugins.md`, `docs/plugin-runtime.md`, `crates/craft-plugin/wit/plugin.wit`). No WASI or network imports are linked; the server refuses `net`. Fuel, memory, deadline and a resource limiter bound each call; **one successful call is one undo step**, a failed call or trap rolls the whole transaction back.
- **Install** with `plugin.install` (`{"path": "gears.zip"}`; `dry_run: true` only checks; replacing an installed id needs `replace: true`) or Preferences › Plugins › Install plugin… (desktop). The zip holds one plugin (`plugin.json` + `.wasm`) at its top or in one top-level folder; the host refuses absolute paths, `..`, symlinks, device entries, entries over 16 MiB, more than 64 MiB unpacked, and refuses a newer/unknown capability in plain words. Installing runs no plugin code. On macOS the plugins folder is `~/Library/Application Support/SolidCraft/plugins`; the app also has a Plugins menu that builds a dialog from each entry's input schema.
- **Inspect, then run explicitly.** `plugin.inspect` reads a package **folder** and returns its manifest plus an `approval` SHA-256 over the manifest bytes *and* the component bytes, without instantiating anything. `plugin.run` requires `{"path", "approval": "<exact hash>", "entry", "params"}`; the hash is a content identity, not a signature, so re-inspect after any change. `plugin.list` lists inspected and installed packages. A design container reserves `plugins/<plugin-id>/` for plugin data (at most 1024 files, preserved byte for byte; the `storage` capability is future work) (`crates/doc/src/plugin_data.rs`).
- **Agent rules.** Never install or run a plugin unless the user asked for that plugin and reviewed what it requests; show them the inspected permissions/limits/commands first. Over the running desktop, `plugin.run` is refused inside `engine.batch`/`engine.script` (`ui.plugin_standalone`) — send it as its own `engine.execute`; headless CLI scripts may include it. MCP and the control channel keep their file scopes, so allow the package folder explicitly with `--allow-path`. The plugin runtime is desktop/headless only: no browser execution, no automatic download/update, no custom panels or plugin-defined feature types.

### Modelling (what it can actually build)

- **Sketches**: lines, rectangles, circles, arcs, polygons, slots, ellipses, fit/control splines, conics, text and **airfoil sections** on origin planes, offset planes or planar faces; construction geometry, projection, trim/extend, corner fillets/chamfers, spline tangent handles. `sketch.insert_airfoil` reads Selig or Lednicer `.dat` coordinates (told apart by content, `format` overrides), draws one fit-point spline scaled to `chord`, places it by `pivot`/`at`/`angle`, mirrors with `flip`, and replies with the point count, trailing-edge gap, largest merged-point deviation and largest spline bulge (`crates/engine/src/cmd/sketch_import.rs`; `docs/book/src/guide/files.md` "Airfoil coordinate files").
- **Constraints and dimensions**: coincident, point-on-curve, horizontal/vertical, parallel, perpendicular, tangent, curvature (G2), equal, concentric, collinear, midpoint, symmetry, fix; linear, aligned, horizontal, vertical, point-to-line, line-to-circle, point-to-circle, circle-to-circle, radius, diameter, angle, arc sweep, arc length and slot length, parameter-driven. Their own solver places fixed-relative points exactly and uses Levenberg–Marquardt for the rest, reporting remaining degrees of freedom; over-constraining edits are rejected (`docs/capabilities.md`).
- **Features**: extrude, revolve, sweep, loft, fillet/chamfer, shell, draft, holes (`docs/hole-presets.md`), threads (`docs/threads.md`, ISO sizes down to M3.5, M7, M33, M39, M45), patterns, mirror, split, combine, move, press/pull, offset face, replace face, rib, web, emboss, coil, pipe, boundary fill, bounding solid — on a parametric timeline with rollback and suppression. **0.42.0 adds `solid.cell_grid`**: a field of hexagon, square, triangle, circle or polygon cells cut into a sketch's closed profiles (a loop inside another is a keep-out), with `dot_grid`, `angle`, `anchor`, `clip` (whole/snap/free), `direction` and a 250-cell cap per operation; not for sheet metal, and the cut faces have no stable names yet (`crates/engine/src/cmd/cell_grid.rs`; `docs/features.md`).
- **Assemblies**: components, occurrences, joints, motion links, motion studies, contact sets, interference and BOM; a Constrain dialog (Mate/Flush/Distance over picked faces, edges, points, planes or axes) built on the joint commands. **Sheet metal**: flanges, contour flanges, hems, fold/unfold, flat pattern, DXF and bend-table export. **Plastic enclosure** features, **physical materials**, **notes**, **point clouds**, and a **Render workspace** with GPU rendering (`render.*`, `docs/render-workspace.md`).
- **Built-in agent skills**: the repo's `skills/` ships 19 Agent-Skills folders, unchanged at v0.42.0. Five are embedded in the binary and served by MCP `skill_reference`: `solidcraft-modeling`, `solidcraft-editing`, `solidcraft-checking`, `solidcraft-mechanisms` and `solidcraft-sheetmetal` (`crates/mcp/src/skill_reference.rs`; live reply lists these five). The `skill_reference` tool description names only four, and `docs/mcp.md` names five but substitutes `solidcraft-reporting` for `solidcraft-sheetmetal` — text drift; the table in code is authoritative. **Read `skill_reference` before a non-trivial model.**

### Files: open and save

- **Native design `.sc`** is a ZIP container: `container.json`, `document.json` (document format **57**) and content-addressed `blobs/<sha256>.<ext>`, optionally plus `cache/` and `provenance/log.cbor` (`crates/format/src/container.rs`; `docs/design-container.md`). A `.json` path saves the plain JSON design. `run --out part.sc` writes plain JSON — `--out` runs `file.export`; `--save` runs `file.save_as` and writes the container. `.solidcraft` and `.solvecraft` still open and keep their names (`crates/io/src/lib.rs` `DESIGN_EXT`/`DESIGN_EXTS`; `docs/compatibility.md`).
- **Format 57** = the five changes folded as format 56 (cell grid feature, frame standard sizes, frame member placement, expression-driven occurrence moves, pattern names by source) plus two pending changes: extrude-to-object keeps its picked placements, and a plane at an angle follows a named axis. A save writes `"format": "solidcraft/57"` with `format_pending` naming both (`crates/doc/src/format/v56/`, `crates/doc/src/format/pending/`).
- **Format registry, 20 rows** (`crates/io/src/formats.rs`): design (`.sc`/`.solidcraft`/`.solvecraft`/`.json`), STEP and IGES import+export, FreeCAD `.FCStd` and Rhino `.3dm` import, **KiCad `.kicad_pcb`/`.kicad_pro` import**, STL/3MF/OBJ import+export, glTF import only, GLB export only, PLY/XYZ/PTS point-cloud import, URDF export, DXF drawing import and current-view DXF export, SVG drawing import. Commercial codecs are not compiled in (`Cargo.toml`: cadmpeg without f3d/sldprt/inventor/catia/creo/nx/sat). IGES exports through `file.export` by extension even though the command's `format` enum does not list it.
- **KiCad import (new)**: the board substrate arrives as a B-rep solid by default with drilled holes cut, outline and cutouts read from `Edge.Cuts`, placement normalised to X = Y = 0, thickness from the board or the `thickness` option; footprint STEP/VRML models come in as nested components with their own colours, copper as a flat overlay (default) or 0.035 mm solids with `copper: "mesh"`, silkscreen and text as options, substrate colour with `color`. `doc.open` carries those options; the board is built once, so the design reopens without the board file (`docs/kicad-import.md`).
- **Commands**: `file.save` (`format: container|json`, `compression: fast|compact`, optional geometry `cache`, optional display `preview`, `sign`/`signing_key` from the app only), `file.export` (`stl|stla|obj|step|3mf|3mf-tagged|glb|urdf|json` plus extension-driven IGES; `lay_on_print_faces: true` lays each body on its print face for STL/3MF; `objects: component` groups a component's bodies as one 3MF object), `file.export_step`, `file.export_stl`, `file.export_3mf`, `file.export_obj`, `file.export_urdf`, `file.save_mesh`, `file.export_view_dxf`, `file.send_to_slicer`/`file.slicers`, `file.open_in_easyprint`, `file.verify`, `file.gpg_keys`, `file.import_cache_clear` (`crates/engine/src/cmd/file.rs`).
- **Forward compatibility**: format 57 reads every earlier format. A file whose format number is newer than the build opens with a warning, reads what it can and keeps the rest on save (`crates/format/src/newer.rs`); builds from before that mechanism refuse it. Designs saved by 0.30.x and earlier keep opening.
- **Drawings are groundwork only**: `.scdwg` has a document model and a container reader/writer (`crates/doc/src/drawing.rs`; `crates/io/src/design/drawing.rs`), but nothing in the app or engine opens one — there is no `drawing.*` command, and the drawings milestone is still listed as unmerged in `ROADMAP.md`. The Insert Drawing dialog places SVG and DXF files on a sketch, not `.scdwg`.

### Platform and packaging

- Desktop app (egui) with multiple designs as tabs; the same engine runs as a WebAssembly browser app (`apps/solidcraft-web`, `docs/browser-api.md`), a headless CLI, an MCP server and the plugin host (`docs/architecture.md`). The browser build does not run plugins.
- macOS is signed with a Developer ID and notarized (`spctl` on the installed bundle: "accepted, source=Notarized Developer ID"). Windows builds carry SignPath-provided code signing while the production certificate is not in place, so SmartScreen may still warn (choose **More info** → **Run anyway**) (`README.md` Download; the release notes still call the Windows files unsigned).
- Saves show progress and can be cancelled until the file is replaced. Agent commands compute beside the window on new installs (`agent_off_thread: true`), each waiting command is its own cancellable row in the operations panel, and the agent's pointer stays on what it picked when you turn the view.
- Headless screenshots use a GPU device and fall back to a CPU rasterizer, saying which (`docs/mcp.md` `screenshot`). The desktop app also hosts an agent **Assistant** panel for ACP/API agents; desktop only (`docs/agent-chat.md`).

## Known limitations and not-implemented

- **Early but usable for simple parts** — the project's own words. The oracle covers 90 simple reference parts; complex multi-body workflows are not proven to that standard (`docs/oracle.md`; `docs/capabilities.md`).
- **One planned command**: `surface.fillet` refuses with issue #769. Any other tool you cannot find in `solidcraft-cli commands` / `describe_command` should be treated as absent — including `view.pick`, which is a control-channel method the app answers, not a command.
- **Signing is app-only and one-directional**: an agent or script cannot sign a design (verified refusal), so a workflow that needs a signed design must ask the user to save it in the app. Verification is available everywhere (`file.verify`, `doc.open {verify: true}`), but a signature is not identity and the newest record can be removed without trace.
- **KiCad import is import-only and one-shot**: no export to KiCad, no re-read after import (the geometry is baked into the design), text boxes, dimensions and tables are not modelled (reported as warnings), and a board that fails to build falls back to a mesh.
- **Cell grids**: at most 250 cells per cut, `cut` is the only mode, not for sheet metal (use `sheet.perforate`), and the cut faces carry no stable names yet.
- **Plugins are experimental**: desktop/headless only; no browser execution, automatic download/update, custom panels or plugin-defined feature types; a 0.x capability may break between minors. Installing/running is always an explicit, user-reviewed action.
- **Drawings are milestone work**: `.scdwg` has a document model and reader/writer, but no UI or command opens it (`ROADMAP.md`; `crates/io/src/design/drawing.rs`).
- **No CAM**: Send to Slicer exports to a slicer; it does not generate toolpaths (`ROADMAP.md` "Manufacturing / CAM").
- **Kernel limits unchanged**: G2 fillets only on straight edges between planar faces with planar ends; some coincident curved booleans can still fail. Mass properties are exact for B-rep bodies (SMLib) and triangle-based for mesh bodies, so a mesh body's volume is still a tessellation number.
- **Format 57 is forward-only for old builds**: a 0.41 build opens it with a warning and keeps what it cannot read; 0.30.x and earlier refuse it (`crates/format/src/newer.rs`).
- **The control channel is off on a new install** and for preference files saved before the setting existed (`crates/ui-egui/src/prefs.rs`: `agent_control: bool = false`, test `agent_control_is_off_unless_saved_on`). Enable it in Preferences ▸ Assistant ▸ Agents through MCP ▸ "Let AI agents connect", or launch with `--control PORT`. A bridged `solidcraft-cli mcp` starts anyway but every call fails with `no SolidCraft app is listening at HOST:PORT` until the channel is enabled.
- **MCP file access is fenced**: save/open/export/screenshot only inside the design's folder, folders the agent opened or saved in, the recovery folder, the server scratch folder, and `--allow-path` entries; hidden folders and files are out of reach. A `save` elsewhere is an error — ask the user to add `--allow-path`, do not route around it through the control port (`docs/mcp.md` "Which files the agent can reach"). `--require-allow-path` makes the server refuse to start when none of its folders is usable. The same fences apply to `plugin.install`/`plugin.run` package paths.
- **Doc drift to discount**: `README.md`/`docs/capabilities.md` say "75 of 76" oracle parts (the generated `docs/oracle.md` says 90/90 and still notes case 95's centre-of-mass reference needs a replay); `docs/features.md` is one command behind (`sketch.insert_airfoil`); `docs/control-protocol.md` says "off by default" in one place and its launch table still says "on (the default)"; `docs/mcp.md` and the `skill_reference` description list `reporting`/four skills where the code embeds `sheetmetal`/five; `docs/rfcs/0002-plugins.md` still says "No plugin runs".

## How to operate

- GUI: `open -a SolidCraft`; `solidcraft --sample` opens a sample part. App flags: `--control PORT`, `--theme-file FILE`, `--max-file-size SIZE`, `--safe-mode`, `--crash-log`, `--version`, `--help` (`apps/solidcraft/src/main.rs`).
- First run of the control channel: Preferences ▸ Assistant ▸ Agents through MCP ▸ **Let AI agents connect** (default off). It takes effect immediately, closes/opens the port and rewrites the token file (`crates/ui-egui/src/control_switch.rs`). `--control PORT` and `SOLIDCRAFT_CONTROL_PORT` work regardless of the setting.
- Headless loop (verified flags):
  ```sh
  solidcraft-cli commands                                   # the registry as JSON (647 ids)
  solidcraft-cli exec solid.box '{"length":40,"width":30,"height":20}'
  solidcraft-cli run examples/bracket.json --out bracket.step
  solidcraft-cli run build.json --save part.sc               # .sc container (--save = file.save_as)
  solidcraft-cli eval part.sc                               # measurements as JSON (measured_by: smlib)
  solidcraft-cli script part.sc --out rebuild.json          # history as a script
  solidcraft-cli snapshot part.sc --out shot.png --view iso
  solidcraft-cli render part.sc --out render.png --samples 64
  solidcraft-cli oracle tests/oracle/01-box                 # needs case directories
  solidcraft-cli kernel-cases tests/kernel-cases/continuity/g0-box-edge-crease
  solidcraft-cli mcp --headless --in part.sc
  solidcraft-cli mcp setup                                  # register with your client
  # plugins, explicitly: plugin.inspect (folder) -> review -> plugin.run (same hash), in a script
  ```
  `--out` runs `file.export` (STEP/STL/3MF/OBJ/JSON by extension; `--out x.sc` writes plain JSON), `--save` runs `file.save_as` and writes the `.sc` container. `snapshot` takes `--out` (there is no `-o`). `oracle` and `kernel-cases` refuse with no case directory. `run` accepts a design, STEP or 3MF mesh as `--in` and writes `--out`/`--save`; a failed feature fails the run unless `--allow-errors`. `--json-out FILE` writes the JSON those commands print, as plain UTF-8; `--script-relative` makes a script's own file paths relative to the script.
- **Signing** (`file.verify`, `file.gpg_keys`) runs headless; **saving with `sign` does not** — the app's Save signs, GnuPG may ask for a smartcard PIN, and Preferences ▸ Security carries `sign_saved_designs`, `signing_key`, `trusted_signing_keys` and `verify_opened_designs`. Verify a received design with `file.verify` or `doc.open {verify: true}` before trusting its contents, and read a `truncated` chain as "history was cut", never as valid.
- Bridged MCP (watch the agent model): turn the control channel on (or `solidcraft --control 7878`), then `solidcraft-cli mcp` finds the app from `control/current.port`; or `solidcraft-cli mcp --connect 127.0.0.1:7878`. A bridged server starts before the app and retries on the first call.
- Token/discovery live in the platform data folder's `control/` directory, per the table in `docs/control-protocol.md` (macOS uses the Application Support family). `SOLIDCRAFT_CONTROL_DIR` moves it; `SOLIDCRAFT_CONTROL_TOKEN` supplies a known token.
- Web: `solidcraft.io/app` runs the same engine in the browser; pages drive it through the API in `docs/browser-api.md`.

### Getting the CLI (the launcher installs the app, not the CLI)

The ArtCraft Launcher installs `SolidCraft.app`; it does not put `solidcraft-cli` on your `PATH`.
It **does** ship a copy inside the bundle at
`/Applications/SolidCraft.app/Contents/MacOS/solidcraft-cli`, the same build as the app, so a
launcher install can use that binary directly. The CLI is published on the app's GitHub release,
`solidcraft-cli-0.42.0-macos-universal.zip` (150.9 MB), so `solidcraft-cli` answering *command not
found* means "not installed yet", not "not supported".

Find it, in this order:

1. **On `PATH`** — `command -v solidcraft-cli`. If it answers, `solidcraft-cli --version` must
   report the version this skill was written against (0.42.0). A different version means the CLI and
   the app have drifted: re-read *Verify against your installed version* before trusting ids.
2. **Bundle copy** — `"/Applications/SolidCraft.app/Contents/MacOS/solidcraft-cli" --version`; to
   make it callable as `solidcraft-cli`, link it: `mkdir -p ~/.local/bin && ln -sf
   "/Applications/SolidCraft.app/Contents/MacOS/solidcraft-cli" ~/.local/bin/solidcraft-cli`.
3. **Install it from the release** — user-local, no `sudo`:

```sh
APP_VER=0.42.0
REL="https://github.com/tangency-labs/solidcraft/releases/download/v$APP_VER"
ASSET="solidcraft-cli-$APP_VER-macos-universal.zip"
mkdir -p "$HOME/.local/bin" "$HOME/Downloads/solidcraft-cli" && cd "$HOME/Downloads/solidcraft-cli"
curl -fLO "$REL/$ASSET" && curl -fLO "$REL/SHA256SUMS.txt"
expected=$(grep -F "$ASSET" SHA256SUMS.txt | awk '{print $1}')
actual=$(shasum -a 256 "$ASSET" | awk '{print $1}')
[ "$expected" = "$actual" ] && echo "checksum OK" || { echo "checksum MISMATCH — stop"; exit 1; }
unzip -oq "$ASSET"
install -m 0755 "solidcraft-cli-$APP_VER-macos-universal/solidcraft-cli" "$HOME/.local/bin/solidcraft-cli"
"$HOME/.local/bin/solidcraft-cli" --version
```

`~/.local/bin` must be on `PATH` for the shell that runs the skill:
`export PATH="$HOME/.local/bin:$PATH"` (put it in your shell profile to keep it).

Rules: never `sudo` into `/usr/local`, never unzip into `/Applications`, and never replace an
existing `solidcraft-cli` of a different version without telling the user. Prefer the bundle copy
(step 2) — it is the same commit as the app; a downloaded CLI is only needed on a machine without
the app.

## Working with an AI agent

- **Model like a person**: `list_commands` → `describe_command` for the typed contract → `execute` per step, or `batch` for a stage. Sketch ids from `created:` are stable, so `sketch.*` → `sketch.dimension` → `solid.extrude` → `solid.fillet` can chain without re-picking. `describe_command` takes `id`.
- **Read `skill_reference` first** for enclosures, brackets, plates, flanges, wings and mechanisms. Its discipline (paraphrased): work the part out as numbers first; place it on the origin; use one `batch` per stage; verify every stage with `measure` against values you computed; keep risky steps in their own batch; pass `verbose: false` in large designs; edge picks snap to the nearest edge (compute exact midpoints); a cut that misses can still report success.
- **Measure with `eval`/`measure`, and trust the numbers more than you did at 0.41.0**: B-rep volume, area, centre of mass and box now come from exact SMLib mass properties (`measured_by: "smlib"`), so a mismatch against your hand calculation is a modelling error, not tessellation slack. Mesh bodies (`measured_by` differs) are still triangle-derived.
- **Use `check_parameters`** to try parameter values without keeping them (one checkpoint, one rebuild, restore); use `inspect.parameter_variants` to compare named value sets. `model.mesh` reads a body's evaluated mesh (chord tolerance default 0.05 mm, capped at 8192 vertices / 16384 triangles) without changing the design.
- **Prepare and verify files**: scripts are plain JSON — generate them, diff them, keep them in git. `script` extracts an existing design's history; `eval` and `inspect_design`/`measure` verify geometry; `compare_picture` checks a model outline against a reference image; `screenshot`/`ui.render` give visual evidence. To inspect or repair a `.sc`, use `file.save {format: "json"}` for the plain document or `script` for the history rather than editing the container's ZIP members by hand — and never hand-edit `provenance/log.cbor`, which would only make the design report `invalid`.
- **Airfoils and cell fields are file/dimension problems, not GUI problems**: `sketch.insert_airfoil` takes a `.dat` path (keep coordinate files beside the script and read the reply's trailing-edge gap and bulge before lofting), and `solid.cell_grid` is a single cut with a 250-cell ceiling — split large fields into several operations.
- **Undo is a tool**: `undo`/`redo` over MCP; `batch` rolls back completed steps on failure by default, and a failed command leaves the design unchanged — a failed `execute` needs no cleanup.
- **Respect the fences**: the MCP server's folder rules are a security boundary; ask the user to add `--allow-path DIR` rather than saving through another surface. Read the token file or use `SOLIDCRAFT_CONTROL_TOKEN`; never hard-code a token. The plugin package folder is fenced the same way.
- **Plugins are never implicit**: use `plugin.list`/`plugin.inspect` to answer questions about what is installed or what a package asks for; only `plugin.run` (with the exact approval hash the user reviewed) executes code, and only when the user asked for that plugin. Do not install a plugin to "try it".
- **Prefer commands to pixels**: `ui.*` input injection exists for dialogs and picks that no command covers, and `ui.agent_cursor` makes it watchable, but pixel-driving is slower and more brittle than an id from `commands`. `view.pick` only exists over the app's control channel; headless, read geometry through `inspect_design`, `body_topology` and `measure`.
- **What not to attempt**: assuming commercial-CAD parity (clean-room, independent); expecting proprietary formats (SolidWorks, CATIA, Creo, NX, Inventor, ACIS SAT are not compiled in) or KiCad export; promising `surface.fillet`, a drawing workspace, CAM or a general plugin platform; signing a design from a script (refused by design); driving the GUI before checking whether a command exists; installing or running plugins without explicit user review.

## Verification protocol

1. **Round-trip in a scratch design first**: new design → build → `save part.sc` → `open` it back → `export` STEP → re-import or `inspect_design`; compare volume, area and bbox with `measure` before trusting the chain. The volume is now exact for B-rep bodies, so a disagreement is real geometry, not mesh noise — but a mesh body still measures by triangles, and a stale STEP written by 0.40.x may read inside out (0.41.0 fixed that export).
2. **Use the oracle and kernel rig as harnesses**: `solidcraft-cli oracle tests/oracle/<case>` replays recipes with expected values; `kernel-cases` runs the kernel regression rig. Model your own checks the same way (recipe/script plus expected values in git).
3. **Never trust a silent export, a silent cut or a "status 1001"**: `export` says what it wrote — re-open and re-measure. A cut or hole that leaves the volume unchanged has missed even when it reports success (`skills/solidcraft-modeling/SKILL.md`). A fillet/chamfer failure names its reason.
4. **Verify provenance before trusting a received design**: `file.verify` (or `doc.open {verify: true}`) reports `unsigned`, `valid`, `not_covered` (signed earlier, saved since without a key), `invalid` or `unsupported`, plus `truncated`. Treat `not_covered` and `truncated` as "what I measured is not what was signed", and check the key against the user's `trusted_signing_keys` before calling a signature verified: a valid signature from an unknown key is grey, not proof. Never sign on the user's behalf, and never claim a design is authentic because it carries a record: the signature proves a key, not a person.
5. **One design per session, save between phases**: `new_design`/`open`/`save`; keep scripts in git so any phase is replayable. `script` recovers a history you did not keep.
6. **Re-verify after updates**: compare `solidcraft --version` with this skill's pin (v0.42.0) and run `solidcraft-cli commands`; the registry is the contract. Design format 57 opens in 0.41.x with a warning and keeps what it cannot read; 0.30.x and earlier refuse it.
