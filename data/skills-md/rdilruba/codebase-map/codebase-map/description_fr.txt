Construisez une carte persistante, fondée sur des preuves, d’un dépôt logiciel dans docs/codebase-map/ – TL;DR, diagrammes d’architecture et de dépendances en Mermaid, flux de données réels tracés avec une stratégie spécifique à l’archétype, les fichiers les plus importants (« la colonne vertébrale »), un ordre de lecture, éventuellement du code assisté par IA, concepts clés et questions ouvertes. Cinq modes : « codebase-map init » construit la carte complète, « codebase-map update » la rafraîchit après des changements, « codebase-map explain [sujet] » couvre une fonctionnalité ou un domaine, « codebase-map trace [flux] » suit un chemin de requête, « codebase-map check » signale les écarts sans écrire. Utilisez-le chaque fois que l’utilisateur souhaite comprendre, documenter ou s’intégrer à un dépôt inconnu ou généré par IA – « map this repo », « explain the architecture », « how does this app work », « trace this feature », « which files matter », « update the codebase map ».
