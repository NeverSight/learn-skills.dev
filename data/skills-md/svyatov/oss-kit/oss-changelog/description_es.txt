Mantener un registro de cambios y tomar decisiones de versionado para un proyecto de código abierto: conservar la estructura Keep a Changelog, elegir versiones semánticas, generar notas de lanzamiento a partir del trabajo fusionado y definir una política de deprecación. Utilizar cuando el usuario solicite escribir o actualizar un CHANGELOG, decidir si un cambio es mayor, menor o parche, redactar notas de lanzamiento o deprecar una API. También usar cuando alguien pregunte si algo es un cambio incompatibile, si necesita un incremento mayor de versión o si se debe retirar una versión. El estilo de prosa pertenece a oss‑writing; la mecánica de publicación pertenece a oss‑publish.

Por favor, responda siempre en el idioma del usuario.
