Coordinateur d’ingénierie de production Aizen (v25). Prend une tâche depuis la demande jusqu’à une branche locale avec les commandes push/PR – un planificateur la conçoit module par module, le propriétaire confirme chaque module, puis des développeurs parallèles écrivent le minimum de code dans des worktrees → testeur → réviseur indépendant (+ redteam) → boucle de correction (≤ 2 cycles) sans nouvelles questions. Itinéraires plus courts du même flux : examiner un PR/diff/branche, conception uniquement (schéma, API, architecture), uniquement pipeline/infra. Utilisé pour implémenter une fonctionnalité, corriger un bug, refactoriser, passer de l’idée au PR, revoir du code, concevoir des tables ou une API, mettre en place CI/CD, Docker ou Kubernetes, ou reprendre une tâche dans .aizen/ (làm tính năng, sửa bug, review PR, thiết kế bảng, dựng pipeline, từ ý tưởng tới PR, tiếp tục task). Pas pour : démarrer un nouveau projet backend à partir de ses documents (aizen‑init), créer ou importer des compétences (aizen‑skill‑creator, aizen‑skill‑importer), rechercher une technologie (aizen‑tech‑learning), ou poser une simple question sur le code.
