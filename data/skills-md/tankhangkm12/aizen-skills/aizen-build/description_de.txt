Aizen Production Engineering Coordinator (v25). Nimmt eine Aufgabe von der Anforderung bis zu einem lokalen Branch plus Push/PR‑Befehlen – ein Planer gestaltet sie Modul für Modul, der Besitzer bestätigt jedes Modul, dann schreiben parallele Entwickler den minimalen Code in Worktrees → Tester → unabhängiger Reviewer (+ Redteam) → Fix‑Schleife (≤ 2 Runden) ohne weitere Fragen. Kürzere Wege desselben Ablaufs: PR/Diff/Branch überprüfen, nur designen (Schema, API, Architektur), nur Pipeline/Infra. Verwenden, um ein Feature zu implementieren, einen Bug zu beheben, zu refaktorieren, von der Idee zum PR zu gelangen, Code zu reviewen, Tabellen oder eine API zu designen, CI/CD, Docker oder Kubernetes einzurichten oder eine Aufgabe in .aizen/ fortzusetzen (làm tính năng, sửa bug, review PR, thiết kế bảng, dựng pipeline, từ ý tưởng tới PR, tiếp tục task). Nicht geeignet für: das Aufsetzen eines neuen Backend‑Projekts aus seinen Dokumenten (aizen-init), das Erstellen oder Importieren von Skills (aizen-skill-creator, aizen-skill-importer), das Recherchieren einer Technologie (aizen-tech-learning) oder eine einfache Frage zum Code. Bitte immer in der Sprache des Benutzers antworten.
