Aizen Produktions‑Engineering‑Koordinator (v25). Nimmt eine Aufgabe von der Anfrage bis zu einem lokalen Branch plus Push/PR‑Befehlen entgegen – ein Planner entwirft sie Modul für Modul, der Owner bestätigt jedes Modul, dann schreiben parallele Entwickler den minimalen Code in Worktrees → Tester → unabhängiger Reviewer (+ Redteam) → Fix‑Schleife (≤ 2 Runden) ohne weitere Fragen. Kürzere Wege des gleichen Ablaufs: PR/Diff/Branch prüfen, nur Design (Schema, API, Architektur), nur Pipeline/Infra. Einsatz zum Implementieren eines Features, Beheben eines Bugs, Refaktorieren, vom Konzept zur PR, Code prüfen, Tabellen oder eine API entwerfen, CI/CD, Docker oder Kubernetes einrichten oder eine Aufgabe in .aizen/ fortsetzen (làm tính năng, sửa bug, review PR, thiết kế bảng, dựng pipeline, từ ý tưởng tới PR, tiếp tục task). Nicht geeignet für: das Aufsetzen eines neuen Backend‑Projekts aus seinen Dokumenten (aizen-init), das Erstellen oder Importieren von Skills (aizen-skill-creator, aizen-skill-importer), das Recherchieren einer Technologie (aizen-tech-learning) oder eine reine Frage zum Code.
