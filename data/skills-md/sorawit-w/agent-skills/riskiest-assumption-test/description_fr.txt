Guide le fondateur à travers le dépôt d’hypothèses, le classement risque × impact, la réécriture d’hypothèses falsifiables et la sélection de méthodes de test — produit un plan de test d’hypothèses d’une page avec les trois meilleures hypothèses classées, les critères de succès/arrêt et une matrice interactive HTML risque × impact. À utiliser après `validation-canvas` et AVANT `pitch-deck` — présenter des hypothèses non testées est du théâtre de vente. Se déclenche sur « testez mes hypothèses », « hypothèse la plus risquée », « RAT », « que devrais‑je valider en premier », « cartographie des hypothèses », « conception d’expérience », « comment dé‑risquer cela », « test du magicien d’Oz », « test de porte factice », « MVP conciergerie », « test de fumée », « règle des 5 entretiens », ou lorsque `validation-canvas.md` a rempli les tests de stress et que l’utilisateur demande la suite. Objectif — « qu’avons‑nous prouvé ? ». Première moitié en amont de la clôture de validation ; la seconde moitié renvoie les résultats dans le canvas. CE N’EST PAS une discussion générale sur les tests (utilisez `team-composer`) ; CE N’EST PAS une plateforme d’expérimentation générique. Produit un plan, pas les expériences.
