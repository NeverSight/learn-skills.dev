**Web 与移动 H5 术语层** – 将用户模糊的 UI 描述转换为可直接发送给 Agent 的精确需求，并方便地指出他们刚描述却说不出名称的术语。

**适用于每一次对话轮次，不局限于任何特定阶段**：在任何对话轮次，只要用户以口语描述网页或 H5 的效果、交互、状态、动画、体验或 bug（例如 “鼠标悬停颜色变化”、 “点击无响应”、 “底部黑条遮挡按钮”、 “弹窗下方仍可滚动”、 “键盘遮住输入框”、 “内容太长‑需要截断”、 “感觉有点俗气”、 “太拥挤，缺乏呼吸感”、 “根本没有数据”、 “图片加载后页面下跳”、 “在微信中打开显示异常”、 “这款 H5 在电脑上表现怪异”），都应使用本技能：

**照常完成用户的工作**，随后自然地在进度或结果中加入对应的术语、通俗的解释，以及最常见的“坑”。

- 内置 128 条本地词汇表（五卷，覆盖 web·h5·motion·mp·base；主题包括布局、交互、状态、组件、表单、动画、体验、可访问性、性能、容器平台、小游戏、前端基础）。  
- 零网络依赖；使用 `scripts/term.mjs find` 逆向查找**用户的原话**——搜索键是“用户会如何描述它”，而不是“它叫什么”，因为不会命名正是要解决的问题。

**三项硬性约束**：  

1. **提供的每个术语必须可追溯到用户本轮对话的确切表述**——如果找不到触发词，就不要提及该术语；宁可不说也不强行加入。  
2. **H5 陷阱成对出现**——“pairs” 条目中列出的搭配必须同时提及（例如 “sticky bottom ↔ safe area”、 “modal ↔ scroll lock”、 “input field ↔ keyboard push‑up”、 “image ↔ aspect‑ratio placeholder”）。只说一半是隐藏陷阱。  
3. **始终先交付任务结果，再附加术语**——每次回复最多 1–3 个术语；如果用户的表达已经准确，则不进行教学。

该技能也支持逆向使用：当用户遇到 Agent 或同事说的自己不懂的内容（例如 “他想要乐观更新和错误回滚”、 “他说这里有 CLS 问题”），挑选对下一步决策影响最大的概念，精准解释其在当前任务中的含义，并指出一个常被混淆的边界。

**可选输出**：`.finesse/lexicon.md` – 项目术语对齐表，避免同一组件在需求、代码和沟通中出现三个不同的名称。

支持的操作指令：`say · name · explain · check · align · list`。

触发短语：“更专业地说”、 “如何精准表述”、 “重新表述为 Agent 的需求”、 “这叫什么”、 “专业术语”、 “术语”、 “我不懂他说什么”、 “H5”、 “移动端”、 “在手机上”、 “响应式”、 “安全区”、 “粘性底部”、 “弹窗”、 “骨架屏”、 “空状态”、 “可访问性”、 “术语对齐”、 “/term”。

请始终使用用户的语言作答。
