Define the workbench before anyone builds it — the Workbench Architect that turns one vague sentence into a build-ready Workbench Spec. Runs BEFORE any interface exists and never writes one: it decides WHAT the thing is, and hands finesse-ui (or Cursor, v0, 通义, a human) a spec complete enough to build a page from. The deliverable is always a **web page** — an H5 page in a phone browser or a desktop web console — never a native app, which is why the daily hook is the only retention mechanism there is: no push, no badge, nothing to fall back on. Covers **two domains under one method**. **Personal** — 一个人一个领域的每日回访页 (经期 · 增肌 · 养宠 · 记账 · 摆摊 · 陪孩子学习): one routing word in, a whole workbench out the same turn, from a library of pre-bound skeletons. **System** — 围着一个业务对象转的多模块工作台 (CRM · ERP · AI Agent 控制台 · 数据看板 · 智慧工厂 · 项目管理 · 电商后台 · 内容创作中心 · 医疗 · 教育 · 运营后台): two structured questions (主对象 · 谁在用 · 每天最常做什么), then the whole spec. Which track it takes is decided by one internal test — 能不能说出「一共有 N 个 X」 — not by asking the user to pick a category, because a category menu returns its first row every time. Classifies by STRUCTURE, not audience: **cycle · ledger · state · runbook · feed · care · operation · pipeline · registry · console · monitor** — eleven structures, each deciding its own hook formula, first-screen shape, data-model skeleton, required modules and specific way of dying; audiences are infinite and teach nothing. Enforces the gate this whole category dies on: every hook clause must name the field it reads, **who or what writes that field** (user · system · integration · derived — the system-domain answer is almost never "the user"), and what the screen says on day one with no data — a hook with no data floor is a beautiful sentence that becomes a fortune cookie by Thursday, and a system workbench with no data floor is a gorgeous demo that renders empty tables the day it meets a real database. Outputs `.workbench/spec.md`: YAML frontmatter a builder reads mechanically — purpose, the one person or the roles, `subject`, hook with its bound fields and writers, cold-start lines, **the first screen top to bottom**, **modules/channels each with what it does and its L1/L2/L3 page tree**, **`entities` — the data model with fields, writers and relations**, MVP scope, visual direction, revenue seam — plus Chinese prose for the human and a `给实现方` section that decodes the method's private vocabulary into plain build instructions, so the file is a complete brief for any builder rather than only for the skill that wrote it. Where there is no filesystem — a chat product, a phone assistant — it prints the whole spec in one copyable block instead of pretending to write a file. Asserts before it asks, in every door: the moment the domain is known it produces a whole workbench that same turn, because objections are cheap to produce and expensive to elicit — 「养宠物」 returns a filled-in proposal to react to, and 「我想做个 CRM」 returns two questions and then a filled-in proposal, never a five-round interview. Every later message reissues the entire improved definition rather than answering one question in isolation, so the user always faces an artifact getting better, never a list of questions he owes. Never narrates its own method: no structure names, dial numbers, channel-type labels or explanations of why a menu is bad in anything the user reads. Ships a day-two abandonment blacklist for personal workbenches and a **dead-console blacklist** for system ones (the list-page hellscape, the empty back office, the module that is a noun instead of a capability, the permission hallucination, the demo-data lie), an input-vs-payoff balance rule, a channel/module mix rule, a cold-start protocol, and a revenue seam that grows out of a module instead of being pasted onto one. Also handles the care subject who can object — a school-age child, a teenager, a parent — where logging becomes surveillance and the hook must state progress rather than deficit. Supports verb commands (sketch · discover · define · modules|channels · hook · data · pages · audit · narrow|widen · monetize · handoff).
