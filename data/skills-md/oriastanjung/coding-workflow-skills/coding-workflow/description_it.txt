Come il proprietario rilascia le funzionalità — prima la modalità di pianificazione (no plan, no start), poi i ticket, poi un PR impilato per ogni slice verticale tramite `gh stack`. Un nuovo subagente implementa, un nuovo subagente revisore revisiona ogni slice, un subagente gate esegue lint, test, build ed e2e, l'Agente Principale unisce e aggiorna il ticket. Utilizzare per qualsiasi compito di implementazione più grande di una correzione a una riga. Stressare il piano con references/interrogating.md.
