Cómo el propietario entrega funcionalidades — primero modo de planificación (sin plan, sin inicio), luego tickets, luego un PR apilado por cada segmento vertical vía `gh stack`. Un subagente nuevo implementa, un subagente revisor nuevo revisa cada segmento, un subagente de puerta ejecuta lint, pruebas, compilación y e2e, el Agente Principal fusiona y actualiza el ticket. Úsalo para cualquier tarea de implementación mayor que una corrección de una sola línea. Prueba la resistencia del plan con references/interrogating.md.
