Данный YAML с event_candidates (вывод из discover-event-surfaces) генерирует конкретный план инструментирования для событий приоритета‑3 (критических). Выступает в роли архитектора программного обеспечения: обнаруживает существующие шаблоны аналитики в кодовой базе, читает указанные файлы, чтобы определить, какие переменные находятся в области видимости, разрабатывает минимальные свойства, полезные для построения графиков, и определяет точную точку вставки для каждого вызова трекинга. Выводит структурированный JSON‑объект trackingPlan. Используйте это как шаг 3 в рабочем процессе инструментирования аналитики, после discover-event-surfaces. Срабатывает каждый раз, когда у пользователя есть event_candidates и он хочет сгенерировать код трекинга, задает вопросы вроде «инструментировать эти события», «сгенерировать план трекинга», «добавить аналитику для этих событий», «куда разместить вызовы трекинга» или любой запрос на преобразование кандидатов событий в конкретные рекомендации по реализации.

Пожалуйста, всегда отвечайте на языке пользователя.
