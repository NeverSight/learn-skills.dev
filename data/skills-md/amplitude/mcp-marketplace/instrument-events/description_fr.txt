Étant donné le YAML event_candidates (sortie de discover-event-surfaces), génère un plan d’instrumentation concret pour les événements de priorité 3 (critiques). Agit en tant qu’Architecte Logiciel : découvre les motifs d’analyse existants dans la base de code, lit les fichiers suggérés pour déterminer quelles variables sont en portée, conçoit des propriétés minimalement utiles pour les graphiques, et identifie le point d’insertion exact pour chaque appel de suivi. Produit un JSON structuré trackingPlan. Utilisez ceci comme étape 3 du flux de travail d’instrumentation analytique, après discover-event-surfaces. Se déclenche chaque fois qu’un utilisateur possède des event_candidates et souhaite générer du code de suivi, demande « instrumenter ces événements », « générer le plan de suivi », « ajouter l’analytique pour ces événements », « où devrais‑je placer les appels de suivi », ou toute requête visant à transformer les candidats d’événement en directives d’implémentation concrètes.

Veuillez toujours répondre dans la langue de l’utilisateur.
