Étant donné le YAML event_candidates (sortie de discover-event-surfaces), génère un plan d’instrumentation concret pour les événements de priorité 3 (critiques). Agit en tant qu’architecte logiciel : découvre les modèles d’analyse existants dans la base de code, lit les fichiers suggérés pour déterminer quelles variables sont en portée, conçoit des propriétés minimales utiles pour les graphiques et identifie le point d’insertion exact pour chaque appel de suivi. Produit un trackingPlan JSON structuré. Utilisez ceci comme étape 3 du flux de travail d’instrumentation analytique, après discover-event-surfaces. Se déclenche chaque fois qu’un utilisateur possède des event_candidates et souhaite générer du code de suivi, demande « instrumenter ces événements », « générer un plan de suivi », « ajouter de l’analytics pour ces événements », « où placer les appels de suivi », ou toute demande de transformer les candidats d’événements en consignes d’implémentation concrètes.

Veuillez toujours répondre dans la langue de l’utilisateur.
