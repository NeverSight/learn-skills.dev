Gegeben ein change_brief YAML (Ausgabe von diff-intake) erzeugt eine umfassende Liste von potenziellen Analyse‑Events, die instrumentiert werden können. Es nimmt die Perspektive eines Ingenieurs mit einer PM‑Mentalität ein — stellt alles, was es zu bedenken gilt, zur Verfügung, damit ein PM entscheiden kann, was tatsächlich wichtig ist. Verwende dies als Schritt 2 im Workflow zur Analyse‑Instrumentation, unmittelbar nachdem diff-intake ein change_brief produziert hat. Auslösen, wann immer ein Nutzer ein change_brief YAML hat und wissen möchte, welche Analyse‑Events hinzuzufügen sind, oder fragt „was sollte ich für diesen PR tracken“, „welche Events sollte ich instrumentieren“, „Event‑Kandidaten generieren“ oder irgendeine Anfrage, um Lücken in der Analyse‑Abdeckung für eine Code‑Änderung aufzudecken.

Bitte immer in der Sprache des Benutzers antworten.
