Поиск ошибок конфигурации CORS — отражение origin с учётными данными, доверие к null‑origin, обход проверки поддомена с помощью regex (незакреплённый vs незаключённый‑точкой vs только префикс), обход гейта предварительного запроса (OPTIONS), проверка origin в postMessage. Уровень риска высокий только тогда, когда контролируемый злоумышленником origin может выполнить аутентифицированный кросс‑доменный запрос чтения конфиденциальных данных, и вы доказали это в браузере. Применяется при тестировании API‑конечных точек, SPA или любого приложения, отправляющего заголовки Access‑Control‑*.
