Chaîne d'attaque red‑team Cloud IAM sur AWS, Azure, GCP — axée sur les chemins d'exploitation EXTERNES et l'analyse des privilèges après découverte de crédentiels. Couvre l'énumération IAM (aws iam, az role, gcloud iam), le chaînage STS/AssumeRole, l'abus d'Azure Managed Identity (via SSRF/fuite), l'abus de JSON de compte de service GCP, les attaques IMDSv1/v2 via SSRF, l'analyse des privilèges du token ServiceAccount K8s une fois détenu (la découverte du token / l'exposition du cluster est gérée par hunt‑k8s), la politique de confiance de rôle « confused‑deputy », l'énumération cross‑account assume‑role, les modèles d'escalade de privilèges IAM (24 + AWS, 8 + Azure, 6 + GCP), et la chaîne d'attaque AWS Cognito Identity Pool rôle non authentifié (GetId → GetCredentialsForIdentity → abus de rôle IAM). Conçue pour le cas où la reconnaissance aboutit à un crédentiel (clé, JSON, token) et où vous devez savoir ce qu'il accorde et comment l'escalader. À utiliser lorsqu'une clé AWS / secret Azure / JSON de compte de service GCP / token SA K8s apparaît dans un dépôt de code, un bundle JS, un APK, un corpus de fuite ou une chaîne SSRF.
