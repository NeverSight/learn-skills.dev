Cloud-IAM-Red-Team-Angriffsfolge über AWS, Azure, GCP – fokussiert auf EXTERNE Ausnutzungswege und die Analyse von Privilegien nach Credential‑Entdeckung. Beinhaltet IAM‑Aufzählung (aws iam, az role, gcloud iam), STS/AssumeRole‑Kettung, Missbrauch von Azure Managed Identity (via SSRF/Leak), Missbrauch von GCP‑Service‑Account‑JSON, IMDSv1/v2‑Angriffe via SSRF, Analyse von K8s ServiceAccount‑Token‑Privilegien nach Erwerb (Token‑Entdeckung / Cluster‑Exposition wird von hunt‑k8s verwaltet), verwirrte Stellvertreter‑Rollen‑Vertrauenspolitik, cross‑account Assume‑Role‑Aufzählung, IAM‑Privileg‑Escalation‑Muster (24+ AWS, 8+ Azure, 6+ GCP) und AWS Cognito Identity Pool unauthentifizierte‑Rollen‑Angriffsfolge (GetId → GetCredentialsForIdentity → IAM‑Rollen‑Missbrauch). Entwickelt für den Fall, dass Recon ein Credential (Schlüssel, JSON, Token) liefert und man wissen muss, welche Berechtigungen es gewährt und wie man eskaliert. Einsatz, wenn ein AWS‑Schlüssel / Azure‑Geheimnis / GCP‑Service‑Account‑JSON / K8s‑SA‑Token aus einem Code‑Repository, JS‑Bundle, APK, Breach‑Korpus oder SSRF‑Kette auftaucht.
