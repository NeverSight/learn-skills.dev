Bousculer la recherche de détournement de requêtes HTTP (CL.TE, TE.CL, H2.CL, H2.TE). Cause : le proxy front‑end et le serveur back‑end ne sont pas d’accord sur la fin d’une requête et le début de la suivante (incohérence d’interprétation des en‑têtes Content‑Length vs Transfer‑Encoding). CL.TE : le front‑end utilise CL, le back‑end utilise TE → détourner en envoyant TE : chunked avec un corps qui correspond au nombre indiqué par CL. TE.CL : l’inverse. H2.CL : rétrogradation HTTP/2, injection de CL dans un back‑end HTTP/1.1. Outils de détection : extension Burp HTTP Request Smuggler, smuggler.py, h2csmuggler. Confirmation : technique du délai temporel (GET détourné avec un timeout de 30 s) — si le front‑end répond lentement à la requête suivante de la victime, le détournement fonctionne. Validation : chaîne d’empoisonnement de cache (détourner une requête qui sera mise en cache pour la victime), vol d’identifiants (détourner un en‑tête X‑Forwarded‑For qui capture les cookies du prochain utilisateur), contournement d’authentification (requête interne détournée). Exemples réels payants provenant de gros déploiements CDN. À utiliser lors de la chasse aux programmes H1 payants fonctionnant sur des piles CDN+origin, ou lorsqu’on cible le contournement de load balancer / WAF.
