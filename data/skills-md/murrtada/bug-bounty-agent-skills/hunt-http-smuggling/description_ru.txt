Hunt HTTP‑request smuggling (CL.TE, TE.CL, H2.CL, H2.TE). Причина: фронтенд‑прокси и бэкенд‑сервер расходятся в определении границы запросов (непоследовательный разбор заголовков Content‑Length и Transfer‑Encoding). CL.TE: фронт использует CL, бек — TE → смуглить, отправив TE: chunked, но тело, соответствующее Count из CL. TE.CL: наоборот. H2.CL: понижение до HTTP/2, смуглить CL в бэкенд HTTP/1.1. Инструменты обнаружения: расширение Burp HTTP Request Smuggler, smuggler.py, h2csmuggler. Подтверждение: техника задержки (смоугленный GET с таймаутом 30 с) — если фронт возвращает медленный отклик на следующий запрос жертвы, смуглинг работает. Проверка: цепочка отравления кэша (смоуглить запрос, который кэшируется для жертвы), кража учётных данных (смоуглить переопределение X‑Forwarded‑For, которое захватывает cookie следующего пользователя), обход аутентификации (смоугленный запрос к внутреннему пути). Реальные платные примеры из крупных CDN‑развёртываний. Используйте при охоте на программы H1 с стеками CDN + origin, при атаке на балансировщик нагрузки / обход WAF.
