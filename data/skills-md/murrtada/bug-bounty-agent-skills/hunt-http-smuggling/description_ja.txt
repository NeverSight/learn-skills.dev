Hunt HTTPリクエストスモッグ（CL.TE、TE.CL、H2.CL、H2.TE）。原因：フロントエンドプロキシとバックエンドサーバが、リクエストの終端位置（Content‑Length と Transfer‑Encoding ヘッダーの解析不一致）について合意していない。CL.TE：フロントエンドが CL、バックエンドが TE を使用 → TE: chunked を送信しつつ、ボディを CL のカウントに合わせて送ることでスモッグ。TE.CL：逆。H2.CL：HTTP/2 ダウングレードで、CL を HTTP/1.1 バックエンドにスモッグ。検出ツール：Burp HTTP Request Smuggler 拡張、smuggler.py、h2csmuggler。確認方法：タイムディレイ手法（30秒タイムアウトの GET をスモッグ）—フロントエンドが次の被害者リクエストで遅延応答すればスモッグ成功。検証例：キャッシュポイズニングチェーン（被害者のためにキャッシュされるリクエストをスモッグ）、認証情報窃取（X-Forwarded-For の上書きで次のユーザーのクッキーを取得）、認証バイパス（内部パスへのリクエストをスモッグ）。主要 CDN の実運用例あり。CDN+オリジン構成の H1 有料プログラムを狙う際、ロードバランサ／WAF バイパスを狙う際に使用。
