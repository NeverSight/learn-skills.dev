Hunt HTTP 요청 스머글링 (CL.TE, TE.CL, H2.CL, H2.TE). 원인: 프런트엔드 프록시와 백엔드 서버가 요청이 끝나는 시점과 다음 요청이 시작되는 시점을 합의하지 못함(Content‑Length와 Transfer‑Encoding 헤더 파싱 불일치). CL.TE: 프런트엔드가 CL을 사용하고 백엔드가 TE를 사용 → TE: chunked를 보내면서 바디가 CL 카운트에 맞도록 스머글. TE.CL: 그 반대. H2.CL: HTTP/2 다운그레이드, CL을 HTTP/1.1 백엔드에 스머글. 탐지 도구: Burp HTTP Request Smuggler 확장, smuggler.py, h2csmuggler. 확인 방법: 타임 딜레이 기법(30초 타임아웃을 가진 스머글된 GET) — 프런트엔드가 다음 피해자 요청에 대해 느리게 응답하면 스머글링 성공. 검증 방법: 캐시 오염 체인(피해자를 위해 캐시되는 스머글 요청), 자격 증명 탈취(X‑Forwarded‑For 오버라이드로 다음 사용자의 쿠키를 가로채는 스머글), 인증 우회(내부 경로 요청을 스머글). 주요 CDN 배포에서 실제 유료 사례 존재. CDN+오리진 스택이 동작하는 H1 유료 프로그램을 사냥하거나 로드밸런서/WAF 우회를 목표로 할 때 사용.
