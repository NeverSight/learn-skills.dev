狩猎 HTTP 请求走私（CL.TE、TE.CL、H2.CL、H2.TE）。原因：前端代理与后端服务器在请求结束位置上出现分歧（Content‑Length 与 Transfer‑Encoding 头部解析不一致）。CL.TE：前端使用 Content‑Length，后端使用 Transfer‑Encoding → 通过发送 TE: chunked 但正文长度符合 Content‑Length 来走私。TE.CL：相反。H2.CL：HTTP/2 降级，将 Content‑Length 走私到 HTTP/1.1 后端。检测工具：Burp HTTP Request Smuggler 插件、smuggler.py、h2csmuggler。确认方法：时间延迟技术（走私的 GET 带 30 秒超时）——如果前端在受害者的下一次请求上返回缓慢，说明走私成功。验证方式：缓存投毒链（走私请求并被缓存供受害者使用）、凭证窃取（走私 X‑Forwarded‑For 覆盖以捕获下一个用户的 Cookie）、绕过认证（走私内部路径请求）。真实付费案例来源于大型 CDN 部署。适用于在针对 CDN+源站堆栈的 H1 付费项目进行狩猎，或针对负载均衡器 / WAF 绕过时使用。
