偵測 HTTP 請求走私（CL.TE、TE.CL、H2.CL、H2.TE）。原因：前端代理與後端伺服器對於請求何時結束、何時開始（Content‑Length 與 Transfer‑Encoding 標頭的解析不一致）意見不合。CL.TE：前端依賴 Content‑Length，後端依賴 Transfer‑Encoding → 透過傳送 TE: chunked 但主體長度符合 CL 計算來走私。TE.CL：相反。H2.CL：將 HTTP/2 降級，將 Content‑Length 走私至 HTTP/1.1 後端。偵測工具：Burp HTTP Request Smuggler 擴充功能、smuggler.py、h2csmuggler。驗證方式：時間延遲技術（走私的 GET 設置 30 秒超時）——若前端在受害者的下一個請求上回應緩慢，即表示走私成功。驗證案例：快取投毒鏈（走私請求讓受害者的請求被快取）、憑證竊取（走私 X‑Forwarded‑For 以攔截下一位使用者的 Cookie）、繞過認證（走私內部路徑請求）。實際付費案例來自主要 CDN 部署。適用於偵測使用 CDN + 原始伺服器堆疊的 HTTP/1 程式、或針對負載平衡器 / WAF 進行繞過時使用。
