Détecter les échecs cryptographiques JWT — suppression de signature alg:none et confusion de clé RS256→HS256 permettant à un attaquant de falsifier un jeton pour n’importe quelle identité (p. ex. un administrateur) sans connaître de secret. À utiliser lorsque l’application s’authentifie avec un JSON Web Token (un jeton Bearer `eyJ…` dans l’en‑tête Authorization, un cookie ou une réponse de connexion). Cette compétence MAÎTRISE la falsification de signature/cryptographie JWT (alg:none, confusion de clé, injection d’en‑tête kid/jku) ; hunt-ato couvre JWT comme une voie d’ATO, hunt-auth-bypass couvre la confiance des jetons SSO/SAML, hunt-api-misconfig couvre la gestion non cryptographique des JWT. Critique lorsqu’un jeton falsifié donne accès aux données d’un autre utilisateur ou à un point d’accès réservé aux administrateurs.
