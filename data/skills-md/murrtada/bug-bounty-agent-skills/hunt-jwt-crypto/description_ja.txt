JWT の暗号的失敗をハント — alg:none の署名除去や RS256→HS256 のキー混乱により、シークレットを知らなくても攻撃者が任意の ID（例: 管理者）用のトークンを偽造できる。アプリが JSON Web Token（Authorization ヘッダーの `eyJ...` ベアラートークン、クッキー、またはログイン応答）で認証する場合に使用。このスキルは JWT の署名/暗号偽造（alg:none、キー混乱、kid/jku ヘッダーインジェクション）を網羅し、hunt-ato は JWT を ATO の一経路として扱い、hunt-auth-bypass は SSO/SAML トークンの信頼を、hunt-api-misconfig は暗号を使用しない JWT の取扱いをカバーする。偽造トークンが別ユーザーのデータや管理者専用エンドポイントへのアクセスを許す場合は重大である。
