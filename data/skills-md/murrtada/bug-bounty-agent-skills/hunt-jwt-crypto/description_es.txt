Hunt JWT fallas criptográficas — alg:none eliminación de firma y confusión de claves RS256→HS256 que permiten a un atacante forjar un token para cualquier identidad (p. ej., un administrador) sin conocer un secreto. Úsalo cuando la aplicación se autentica con un JSON Web Token (un token Bearer `eyJ...` en el encabezado Authorization, una cookie o una respuesta de inicio de sesión). Esta habilidad DOMINA la falsificación de firma/criptografía de JWT (alg:none, confusión de claves, inyección de encabezados kid/jku); hunt-ato cubre JWT como una vía de ATO, hunt-auth-bypass cubre la confianza en tokens SSO/SAML, hunt-api-misconfig cubre el manejo de JWT sin criptografía. Crítico cuando un token falsificado otorga acceso a los datos de otro usuario o a un endpoint solo para administradores.
