Охота за криптографическими уязвимостями JWT — alg:none снятие подписи и путаница ключей RS256→HS256, позволяющие злоумышленнику подделать токен для любой личности (например, администратора) без знания секрета. Применять, когда приложение аутентифицируется с помощью JSON Web Token (Bearer‑токен `eyJ…` в заголовке Authorization, в куке или в ответе на вход). Этот навык ОВЛАДЕВАЕТ подделкой подписи/криптографии JWT (alg:none, путаница ключей, инъекция заголовков kid/jku); hunt-ato покрывает JWT как один из путей ATO, hunt-auth-bypass охватывает доверие к токенам SSO/SAML, hunt-api-misconfig покрывает обработку JWT без криптографии. Критично, когда поддельный токен предоставляет доступ к данным другого пользователя или к эндпоинту, доступному только администратору.
