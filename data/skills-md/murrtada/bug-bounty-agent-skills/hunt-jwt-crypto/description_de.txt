Jäger JWT‑Kryptografie‑Fehler – alg:none‑Signaturentfernung und RS256→HS256‑Schlüsselverwechslung, die es einem Angreifer ermöglichen, ein Token für jede Identität (z. B. einen Administrator) zu fälschen, ohne ein Geheimnis zu kennen. Verwenden, wenn die Anwendung sich mit einem JSON Web Token authentifiziert (ein `eyJ…` Bearer‑Token im Authorization‑Header, einem Cookie oder einer Login‑Antwort). Diese Fähigkeit BEHERRSCHT JWT‑Signatur‑/Krypto‑Fälschung (alg:none, Schlüsselverwechslung, kid/jku‑Header‑Injection); hunt‑ato deckt JWT als einen ATO‑Pfad ab, hunt‑auth‑bypass deckt das Vertrauen in SSO/SAML‑Token ab, hunt‑api‑misconfig deckt nicht‑kryptografische JWT‑Verarbeitung ab. Kritisch, wenn ein gefälschtes Token Zugriff auf die Daten eines anderen Benutzers oder auf einen nur für Administratoren vorgesehenen Endpunkt gewährt.
