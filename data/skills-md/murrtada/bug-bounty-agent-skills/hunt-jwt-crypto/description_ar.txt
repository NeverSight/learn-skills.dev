صَيد فَشَل التَشفير في JWT — إِزاحة التَّوقيع عبر alg:none والخلط بين RS256→HS256 الذي يَسمح للمُهَاجِم بإنشاء توكن لأي هوية (مثلاً المسؤول) دون معرفة السِّر. استَخدمها عندما يُصَدّق التطبيق باستخدام JSON Web Token (توكن Bearer `eyJ...` في رأس Authorization أو كُكي أو استجابة تسجيل الدخول). هذه المَهارة تَمتلك تزوير تَوقيع/تَشفير JWT (alg:none، خَلط المفاتيح، حقن رأس kid/jku)؛ hunt-ato تُغطي JWT كمسار ATO واحد، hunt-auth-bypass تُغطي ثقة توكنات SSO/SAML، hunt-api-misconfig تُغطي التعامل غير التشفيري مع JWT. أمرٌ حرج عندما يُمنح توكن مَزور الوصول إلى بيانات مستخدم آخر أو نقطة نهاية مخصَّصة للمسؤول.
