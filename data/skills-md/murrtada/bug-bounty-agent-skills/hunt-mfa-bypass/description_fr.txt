Bypass MFA/2FA – 7 schémas distincts. (1) MFA non imposée sur les points d’entrée sensibles (changement de mot de passe, changement d’e‑mail acceptés sans défi MFA), (2) contournement de l’étape MFA via navigation directe vers l’URL post‑connexion, (3) relecture du token MFA (le même code accepté deux fois), (4) force brute du OTP à 6 chiffres sans limitation de taux (10⁶ tentatives à vitesse serveur), (5) condition de concurrence sur la validation du OTP, (6) fuite du code de récupération via /api/me, (7) dégradation du facteur de secours (facteur SMS sans limitation de taux). Plus la chaîne : vol de cookie + oracle de mot de passe + aucune élévation = ATO sans défi MFA. Détection : tracer le flux d’authentification dans Burp, identifier chaque transition d’état, vérifier si le MFA est appliqué comme middleware ou par point d’entrée, contrôler l’entropie du OTP et la limitation de taux sur la validation du OTP. Validation : session de l’attaquant atteignant l’état post‑MFA. Utiliser lors de la recherche de contournement d’authentification, de flux MFA, de primitives en chaîne vers l’ATO.
