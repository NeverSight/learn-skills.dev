hunt 忘記密碼 / 帳戶恢復驗證缺陷 — 5 種不同模式：(1) 透過對有效與無效電子郵件回應不同來列舉使用者名稱，(2) 重設令牌直接暴露於 API 回應主體中，(3) 重設令牌使用後未被失效（重放），(4) 密碼重設連結可在不同 IP／瀏覽器上使用（未綁定），(5) 重設請求端點缺乏速率限制。這些是獨立的恢復流程破損驗證原語——不同於重設郵件主機標頭投毒 (hunt‑host‑header) 與完整的帳戶接管鏈 (hunt‑ato 將密碼重設作為 ATO 路徑；在此證明原語，於那裡串接)。偵測方式：追蹤完整的忘記密碼流程，從請求到令牌再到使用；比較有效與無效電子郵件的回應差異；測試令牌在消費後的重放。風險等級為中至高（列舉＝中，令牌重用＝高，當與已知電子郵件串接時帳戶接管＝關鍵）。
