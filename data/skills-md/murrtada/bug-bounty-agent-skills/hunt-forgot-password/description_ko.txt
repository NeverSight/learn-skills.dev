Hunt Forgot Password / Account Recovery 인증 결함 — 5가지 구별되는 패턴: (1) 유효 이메일과 무효 이메일에 대해 다른 응답을 반환함으로써 사용자 이름 열거, (2) 리셋 토큰이 API 응답 본문에 직접 노출, (3) 사용 후 토큰이 무효화되지 않음(재사용 가능), (4) 비밀번호 재설정 링크가 다른 IP/브라우저에서도 작동(바인딩 없음), (5) 리셋 요청 엔드포인트에 속도 제한이 없음. 이는 독립적인 복구 흐름의 깨진 인증 원시(primitives)이며, reset-email host-header poisoning (hunt-host-header) 및 전체 ATO 체인 (hunt-ato가 비밀번호 재설정을 ATO 경로로 보유; 여기서 원시를 증명하고 저기에 체인)과 구분된다. 탐지: 요청부터 토큰까지, 사용까지 전체 비밀번호 찾기 흐름을 추적; 유효/무효 이메일에 대한 응답 차이를 확인; 토큰 사용 후 재사용 테스트. 중간~높음 (열거=중간, 토큰 재사용=높음, 계정 탈취=알려진 이메일과 연계될 경우 중요).
