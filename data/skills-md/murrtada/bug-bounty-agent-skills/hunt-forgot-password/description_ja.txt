Hunt Forgot Password / アカウントリカバリー認証の欠陥 — 5つの異なるパターン: (1) 有効なメールと無効なメールで応答が異なることによるユーザー名列挙、(2) リセットトークンが API のレスポンスボディに直接露出、(3) 使用後にリセットトークンが無効化されない（リプレイ可能）、(4) パスワードリセットリンクが別の IP／ブラウザからでも機能する（バインディングなし）、(5) リセットリクエストエンドポイントにレートリミットが設定されていない。これらはスタンドアロンのリカバリフローにおける認証破壊のプリミティブであり、reset-email のホストヘッダーポイズニング (hunt‑host‑header) や、完全な ATO チェーン (hunt‑ato がパスワードリセットを ATO パスとして所有; ここでプリミティブを証明し、そこにチェーンする) とは別物です。検知方法: リクエストからトークン取得、トークン使用までの Forgot Password フロー全体を追跡する；有効メールと無効メールでのレスポンス差分を確認する；トークンを消費した後のリプレイをテストする。重要度は中程度から高程度 (列挙=中、トークン再利用=高、既知メールと連携した場合のアカウント乗っ取り=クリティカル)。常にユーザーの言語で回答してください。
