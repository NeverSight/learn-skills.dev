Hunt vector-store / embedding-layer weaknesses in RAG pipelines (OWASP LLM08 Vector and Embedding Weaknesses) — empoisonnement persistant du corpus qui survit à travers les sessions et les utilisateurs (distinct de l’injection indirecte de prompt en une seule fois, qui appartient à hunt-llm-ai), IDOR de base de données vectorielle inter‑locataires (requêtes non authentifiées ou non limitées contre Pinecone/Weaviate/Chroma/Milvus/Qdrant/pgvector), fuite de texte source/métadonnées dans les résultats de recherche par similarité, et détournement de récupération via proximité d’embedding adversaire (« SEO poisoning » pour RAG). Cibles : toute application avec une base de connaissances partagée, téléchargement de documents alimentant un chatbot, ou un port vector‑DB directement accessible. Validation : une deuxième session/comptes propre doit hériter d’un résultat empoisonné, ou un artefact inter‑locataire doit être vérifiable de façon indépendante — la confabulation n’est pas une découverte, même exigence que hunt-llm-ai. Utiliser quand la cible est basée sur RAG, expose un port vector‑DB, ou permet aux utilisateurs de télécharger des documents que les requêtes d’autres utilisateurs récupèrent plus tard.
