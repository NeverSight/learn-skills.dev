Таксономия захвата аккаунтов при охоте — 9 различных путей к ATO, плюс цепочки. Пути: (1) уязвимости сброса пароля (инъекция host‑header перенаправляет токен, предсказуемый/числовой токен, утечка Referer, отсутствие истечения срока/повторное использование), (2) изменение e‑mail без повторной аутентификации, (3) CSRF при привязке аккаунта в OAuth, (4) обход MFA (см. hunt‑mfa‑bypass), (5) фиксация сессии, (6) манипуляция JWT (подделка токена для другой личности; детали криптографии → hunt‑jwt‑crypto), (7) изменение пароля без повышения уровня проверки (цепочка с оракулом времени/длины входа), (8) brute‑force восстановления через социальные вопросы/контрольные вопросы, (9) захват субдомена SSO на redirect_uri OAuth. Цепочки: кража cookie + оракул пароля + отсутствие повышения уровня = постоянный ATO; расслабленный redirect_uri = кража кода авторизации; захват dangling‑CNAME на redirect_uri = ATO. Валидация: продемонстрировать реальный захват тестового аккаунта B из сессии атакующего A; OOB/Collaborator подтверждают слепые шаги утечки токена. Использовать при поиске цепочек ATO, тестировании сброса пароля/изменения e‑mail/MFA/OAuth/сессий/JWT или объединении примитивов к критическим.
