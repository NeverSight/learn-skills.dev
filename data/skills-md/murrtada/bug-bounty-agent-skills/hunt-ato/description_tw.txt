Hunt 帳戶接管分類——9 種不同的 ATO 路徑，加上鏈接。路徑：(1) 密碼重設缺陷（host‑header 注入導向 token、可預測／數字 token、Referer 泄漏、無失效／可重用）、(2) 未重新驗證的電子郵件變更、(3) OAuth 帳號連結 CSRF、(4) MFA 繞過（參見 hunt‑mfa‑bypass）、(5) 會話固定、(6) JWT 操作（偽造 token 為其他身份；加密細節 → hunt‑jwt‑crypto）、(7) 未提升驗證的密碼變更（與登入時間／長度 oracle 鏈接）、(8) 社交恢復／安全問題暴力破解、(9) OAuth redirect_uri 的 SSO 子域接管。鏈接：Cookie 盜取 + 密碼 oracle + 無提升驗證 = 持續性 ATO；寬鬆的 redirect_uri = 授權碼盜取；在 redirect_uri 的 dangling‑CNAME 接管 = ATO。驗證：展示從攻擊者 A 的會話實際接管測試帳號 B；OOB/Collaborator 確認盲目 token 泄漏步驟。使用於搜尋 ATO 鏈、測試密碼重設／電子郵件變更／MFA／OAuth／會話／JWT，或將原語鏈接至 Critical。
