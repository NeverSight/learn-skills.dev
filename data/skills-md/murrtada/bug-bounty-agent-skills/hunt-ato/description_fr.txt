Taxonomie de la prise de contrôle de compte — 9 voies distinctes vers ATO, plus les chaînes. Voies : (1) failles de réinitialisation de mot de passe (injection d’en‑tête Host redirige le jeton, jeton prévisible/numérique, fuite du Referer, pas d’expiration/réutilisation), (2) modification d’e‑mail sans réauthentification, (3) CSRF de liaison de compte OAuth, (4) contournement MFA (voir hunt-mfa-bypass), (5) fixation de session, (6) manipulation JWT (forge le jeton vers une autre identité ; détails cryptographiques → hunt-jwt-crypto), (7) changement de mot de passe sans élévation (chaîne avec oracle de timing/longueur de connexion), (8) récupération sociale / force brute de question de sécurité, (9) prise de contrôle de sous‑domaine SSO sur redirect_uri OAuth. Chaînes : vol de cookie + oracle de mot de passe + pas d’élévation = ATO persistant ; redirect_uri laxiste = vol de code d’authentification ; prise de contrôle de CNAME en suspension sur redirect_uri = ATO. Validation : démontrer une vraie prise de contrôle du compte de test B depuis la session de l’attaquant A ; OOB/Collaborator confirmer les étapes de fuite de jeton à l’aveugle. À utiliser lors de la chasse aux chaînes ATO, du test de réinitialisation de mot de passe / changement d’e‑mail / MFA / OAuth / session / JWT, ou du chaînage de primitives vers Critical.
