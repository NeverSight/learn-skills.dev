Hunt 账户接管（ATO）分类——9 条不同路径以及链路。路径：(1) 密码重置缺陷（host-header 注入导致令牌重定向、可预测/数字化令牌、Referer 泄漏、令牌永不过期/可重用），(2) 未重新认证的邮箱变更，(3) OAuth 账户绑定 CSRF，(4) 多因素认证绕过（参见 hunt-mfa-bypass），(5) 会话固定，(6) JWT 操作（伪造令牌以冒充其他身份；加密细节→hunt-jwt-crypto），(7) 未进行二次验证的密码修改（与登录时间/长度 Oracle 链接），(8) 社交恢复/安全问题暴力破解，(9) 在 OAuth redirect_uri 处的 SSO 子域名接管。链路：Cookie 窃取 + 密码 Oracle + 未进行二次验证 = 持久化账户接管；宽松的 redirect_uri = 授权码盗取；在 redirect_uri 处的悬挂 CNAME 接管 = 账户接管。验证：演示在攻击者 A 的会话中真实接管测试账户 B；使用 OOB/Collaborator 确认盲目令牌泄漏步骤。在狩猎 ATO 链路、测试密码重置、邮箱变更、多因素认证、OAuth、会话、JWT，或将原语链向 Critical 时使用。
