Taxonomia di hunt per il takeover di account — 9 percorsi distinti verso ATO, più catene.  
Percorsi: (1) vulnerabilità nella reimpostazione della password (iniezione di host‑header che reindirizza il token, token prevedibile/numerico, perdita di Referer, token senza scadenza/riutilizzabile), (2) cambio email senza ri‑autenticazione, (3) CSRF nell’associazione di account OAuth, (4) bypass MFA (vedi hunt‑mfa‑bypass), (5) fissazione della sessione, (6) manipolazione JWT (forgiare token per un’altra identità; dettagli crittografici → hunt‑jwt‑crypto), (7) cambio password senza step‑up (catena con oracolo di timing/lunghezza di login), (8) brute‑force di social‑recovery / domande di sicurezza, (9) takeover del sottodominio SSO al redirect_uri OAuth.  
Catene: furto di cookie + oracolo password + nessun step‑up = ATO persistente; redirect_uri permissivo = furto di auth‑code; takeover di CNAME sospeso al redirect_uri = ATO.  
Validazione: dimostrare un vero takeover dell’account di test B dalla sessione dell’attaccante A; OOB/Collaborator confermano i passaggi di perdita di token in cieco.  
Usare quando si cercano catene ATO, si testano reimpostazioni password / cambi email / MFA / OAuth / sessione / JWT, o si concatenano primitive verso Critical.
