Découvrez l'API backend cachée d’une application monopage (SPA) à partir de son bundle JavaScript public, puis testez cette API pour des problèmes de contrôle d’accès ou d’absence d’authentification. C’est l’une des tactiques web les plus rentables en reconnaissance moderne — les SPA livrent toute la carte de leurs routes backend au navigateur, et l’API qui les supporte manque souvent le middleware d’authentification que la page de connexion implique. Cette méthode a été mise au point lors d’un engagement autorisé où elle a permis de déceler une API financière non authentifiée qu’un scan ASM signalant des centaines de « Criticals » avait totalement manqué. Utilisez‑la chaque fois qu’une cible propose une SPA lourde en JS (React/Vue/Angular/Next), un sous‑domaine « app »/« console »/« dashboard »/« portal », ou tout hôte contenant `*api*` apparaît lors de la recon. Les artefacts de build fuités (source maps / .env / .git / asset‑manifest) sont gérés par hunt‑source‑leak ; l’inventaire des versions d’API et le diff comportemental par hunt‑shadow‑api ; cette compétence consiste à cartographier les routes backend d’une SPA en direct à partir de son bundle JS et à les tester pour des contrôles d’accès défaillants ou une authentification manquante.
