Lors qu’une réponse est complexe, la rendre sous forme d’un explicateur HTML visuel d’une seule page : le modèle rédige uniquement un bref brouillon en Markdown étendu ; le CLI intégré gère les modèles, les composants, la mise en page automatique des SVG et une vérification d’écriture contrôlée par STE, produisant une page monofichier en un appel. Utilisez‑le également lorsque l’utilisateur demande une vidéo explicative (« vidéo style 3b1b », « make a video », « 做个视频 », « 讲成视频 ») : le même format de brouillon avec des lignes de narration génère une page lecteur animée et narrée, avec éventuellement un MP4. Utilisez‑le aussi quand l’utilisateur saisit « /answer-me-with-html config » ou souhaite modifier les paramètres (ouverture automatique du navigateur, mode toujours‑actif, thème par défaut). Employez‑le de façon proactive, sans demande explicite, lorsque la réponse implique l’un des cas suivants : plus de 3 concepts interconnectés ; un flux / protocole / architecture avec des branches ou plusieurs acteurs ; une comparaison ou un compromis sur plus de 3 dimensions ; une hiérarchie (répertoires, modules, taxonomies) ; une évolution ou des phases ; ou que l’utilisateur dise « explain how it works », « I don’t get it », « draw a diagram », « explain this codebase », « explain visually », « 讲讲原理 », « 没看懂 », « 画个图 », « 用 HTML 讲 ». Ne pas l’utiliser pour : des questions‑réponses courtes (claires en moins d’environ 150 mots), des commandes à copier‑coller immédiatement, des modifications de code pures, ou lorsqu’on demande du texte brut.

Veuillez toujours répondre dans la langue de l’utilisateur.
