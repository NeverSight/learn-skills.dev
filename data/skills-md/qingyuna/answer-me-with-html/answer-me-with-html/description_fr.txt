Lorsqu’une réponse est complexe, la rendre sous forme d’explicatif visuel HTML d’une page : le modèle écrit seulement un court brouillon en Markdown étendu ; le CLI intégré gère les modèles, les composants, la mise en page automatique SVG et une vérification d’écriture contrôlée par STE, produisant une page monofichier en un seul appel. Utilisez‑le également lorsque l’utilisateur demande une vidéo explicative (« vidéo style 3b1b », « make a video », « 做个视频 », « 讲成视频 » ): le même format de brouillon plus des lignes de narration produit une page lecteur animée et narrée, avec éventuellement un MP4. Utilisez‑le aussi lorsque l’utilisateur saisit « /answer-me-with-html config » ou veut changer les paramètres (ouverture automatique du navigateur, mode toujours‑on, thème par défaut). Employez‑le de façon proactive, sans qu’on le demande, lorsque la réponse implique l’un des cas suivants : plus de 3 concepts interconnectés ; un flux/protocole/architecture avec des branches ou plusieurs acteurs ; une comparaison ou un compromis sur plus de 3 dimensions ; une hiérarchie (répertoires, modules, taxonomies) ; une évolution ou des phases ; ou que l’utilisateur dise « explain how it works », « I don’t get it », « draw a diagram », « explain this codebase », « explain visually », « 讲讲原理 », « 没看懂 », « 画个图 », « 用 HTML 讲 ». Ne l’utilisez pas pour : des questions‑réponses courtes (claires en moins d’environ 150 mots), des commandes à copier‑coller et exécuter immédiatement, des changements de code purs, ou lorsque l’utilisateur demande du texte brut.

Veuillez toujours répondre dans la langue de l’utilisateur.
