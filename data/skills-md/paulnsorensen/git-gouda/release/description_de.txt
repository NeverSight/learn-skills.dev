End-to-End-Release-Erstellung für ein GitHub-Repository: die nächste semantische Version aus den Conventional Commits seit dem letzten Tag bestimmen, korrekte Release‑Notes entwerfen (automatisch von GitHub über `.github/release.yml` generiert oder handgefertigt, nach Änderungstyp gruppiert mit Highlights und Upgrade‑Hinweisen für Breaking Changes), ein annotiertes Tag erstellen und pushen, das GitHub‑Release veröffentlichen und optional `CHANGELOG.md` aktualisieren. Verwenden, wenn der Nutzer sagt „cut a release“, „tag a release“, „publish a release“, „ship vX.Y.Z“, „bump the version“, „what version should this be“, „write the release notes“, „draft the changelog“ oder /release aufruft. Unterscheidet sich von /gh-bootstrap (das einmalig das `.github/release.yml` + Release‑Workflow‑Gerüst bereitstellt): Diese Fähigkeit führt die eigentliche Release‑Zeremonie aus – Versionsentscheidung, Notizen, Tag, Veröffentlichung. Ausführen, nachdem die Arbeit in den Standard‑Branch gemerged wurde.
