Coupure de release de bout en bout pour un dépôt GitHub : décider de la prochaine version sémantique à partir des Conventional Commits depuis le dernier tag, rédiger des notes de version appropriées (générées automatiquement par GitHub via `.github/release.yml`, ou sélectionnées manuellement, regroupées par type de changement avec des points forts et des notes de mise à jour pour les changements incompatibles), créer et pousser un tag annoté, publier la release GitHub, et mettre éventuellement à jour `CHANGELOG.md`. À utiliser lorsque l'utilisateur dit « cut a release », « tag a release », « publish a release », « ship vX.Y.Z », « bump the version », « what version should this be », « write the release notes », « draft the changelog », ou invoque /release. Distinct de /gh-bootstrap (qui crée le squelette du fichier `.github/release.yml` + le pipeline de release une fois) : cette compétence exécute la cérémonie réelle de release — décision de version, notes, tag, publication. À exécuter après que le travail a été fusionné dans la branche par défaut.
