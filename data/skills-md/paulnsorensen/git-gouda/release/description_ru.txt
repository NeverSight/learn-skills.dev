Полный процесс выпуска для репозитория GitHub: определить следующую семантическую версию на основе Conventional Commits с момента последнего тега, набросать корректные примечания к выпуску (автоматически генерируемые GitHub через `.github/release.yml` или вручную сгруппированные по типу изменений с выделением ключевых моментов и инструкциями по обновлению для несовместимых изменений), создать и отправить аннотированный тег, опубликовать выпуск в GitHub и при необходимости обновить `CHANGELOG.md`. Использовать, когда пользователь говорит «cut a release», «tag a release», «publish a release», «ship vX.Y.Z», «bump the version», «what version should this be», «write the release notes», «draft the changelog» или вызывает /release. Отличается от /gh-bootstrap (который один раз создаёт шаблон `.github/release.yml` и инфраструктуру workflow выпуска): эта команда выполняет реальную церемонию выпуска — выбор версии, примечания, тег, публикацию. Запускать после того, как работа слита в ветку по умолчанию.
