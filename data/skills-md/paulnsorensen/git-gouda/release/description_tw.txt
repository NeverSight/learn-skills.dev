端到端的 GitHub 儲存庫發布流程：根據自上一次標籤以來的 Conventional Commits 決定下一個語意化版本，草擬適當的發布說明（透過 `.github/release.yml` 由 GitHub 自動生成，或依變更類型手動整理，並加入重點與破壞性變更的升級說明），建立並推送帶註解的標籤，發佈 GitHub 發布，並可選擇性更新 `CHANGELOG.md`。當使用者說「cut a release」、「tag a release」、「publish a release」、「ship vX.Y.Z」、「bump the version」、「what version should this be」、「write the release notes」、「draft the changelog」或呼叫 /release 時使用。與 /gh-bootstrap（只在一次性建立 `.github/release.yml` + 發布工作流程設定）不同，此功能執行實際的發布儀式——版本決策、說明撰寫、標籤建立與發布。於工作合併至預設分支後執行。請始終以使用者的語言回覆。
