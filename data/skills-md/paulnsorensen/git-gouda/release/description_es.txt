Corte de lanzamiento de extremo a extremo para un repositorio de GitHub: decidir la siguiente versión semántica a partir de los Conventional Commits desde la última etiqueta, redactar notas de lanzamiento adecuadas (generadas automáticamente por GitHub mediante `.github/release.yml`, o curadas manualmente agrupadas por tipo de cambio con aspectos destacados y notas de actualización para cambios breaking), crear y enviar una etiqueta anotada, publicar el lanzamiento en GitHub y, opcionalmente, actualizar `CHANGELOG.md`. Utilízalo cuando el usuario diga "cut a release", "tag a release", "publish a release", "ship vX.Y.Z", "bump the version", "what version should this be", "write the release notes", "draft the changelog", o invoque /release. Distinto de /gh-bootstrap (que genera la estructura de `.github/release.yml` + la canalización del flujo de trabajo de lanzamiento una vez): esta habilidad ejecuta la ceremonia real de lanzamiento — decisión de versión, notas, etiqueta, publicación. Ejecuta después de que el trabajo se haya fusionado a la rama predeterminada.
