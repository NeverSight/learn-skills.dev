GitHub 저장소에 대한 엔드‑투‑엔드 릴리스 절차: 마지막 태그 이후의 Conventional Commits를 기반으로 다음 시맨틱 버전을 결정하고, 적절한 릴리스 노트를 초안 작성합니다( `.github/release.yml`을 통한 GitHub 자동 생성 또는 변경 유형별로 구분하고 하이라이트와 파괴적 변경에 대한 업그레이드 노트를 포함한 수동 작성). 주석이 달린 태그를 만들고 푸시한 뒤 GitHub 릴리스를 공개하고, 옵션으로 `CHANGELOG.md`를 업데이트합니다. 사용자는 “cut a release”, “tag a release”, “publish a release”, “ship vX.Y.Z”, “bump the version”, “what version should this be”, “write the release notes”, “draft the changelog”와 같은 표현을 하거나 /release 명령을 호출할 때 이용합니다. `/gh‑bootstrap`(한 번 `.github/release.yml`과 릴리스 워크플로우를 스캐폴딩하는 도구)과는 구별되며, 이 스킬은 실제 릴리스 의식을 수행합니다—버전 결정, 노트 작성, 태그 생성, 공개. 기본 브랜치에 작업이 병합된 후 실행합니다.
