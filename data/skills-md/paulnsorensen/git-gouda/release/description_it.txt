Taglio di release end‑to‑end per un repository GitHub: decide la prossima versione semantica dai Conventional Commits dal ultimo tag, redigi note di rilascio appropriate (generate automaticamente da GitHub tramite `.github/release.yml`, o curate manualmente raggruppate per tipo di cambiamento con evidenziazioni e note di aggiornamento per le breaking changes), crea e spingi un tag annotato, pubblica il rilascio su GitHub e, opzionalmente, aggiorna `CHANGELOG.md`. Usa quando l’utente dice “cut a release”, “tag a release”, “publish a release”, “ship vX.Y.Z”, “bump the version”, “what version should this be”, “write the release notes”, “draft the changelog”, o invoca /release. Distinto da /gh-bootstrap (che scaffolda il `.github/release.yml` + la pipeline del workflow di rilascio una volta): questa skill esegue la vera cerimonia di rilascio — decisione della versione, note, tag, pubblicazione. Esegui dopo che il lavoro è stato mergiato nel branch predefinito.
