Configurez `safe-settings` de GitHub (une application GitHub basée sur Probot provenant de l’organisation github) pour une politique de dépôt déclarative, à l’échelle de l’organisation, en tant que code. Utilisez‑le lorsque l’utilisateur dit « settings as code », « safe-settings », « manage repos declaratively », « centralize repo settings », « org-level branch protection », « scaffold an admin repo », « github settings app », ou invoque /safe-settings sur une organisation qui souhaite gérer les paramètres des dépôts, la protection des branches, les jeux de règles, les labels, les équipes, les environnements et les collaborateurs depuis un seul dépôt d’administration. Il crée la structure du dépôt d’administration (`settings.yml` + `suborgs/` + `repos/`), les étapes d’installation de l’application GitHub, et un workflow GitHub Actions programmé `full-sync`. Distinct de /gh-bootstrap (configuration ponctuelle d’un seul dépôt via `gh api`) — cette compétence est destinée aux **settings as code à l’échelle de l’organisation** qui se réconcilient en continu. Elle n’est pas destinée aux opérations GitHub ponctuelles (PR, issues, statut CI) ou au travail local git — ces cas sont hors du champ de ce catalogue.
