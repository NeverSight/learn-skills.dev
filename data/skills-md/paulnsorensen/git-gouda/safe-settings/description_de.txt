Richte GitHubs `safe-settings` (eine Probot‑basierte GitHub‑App der github‑Organisation) ein, um deklarative, organisationsweite Repository‑Richtlinien als Code zu verwalten. Verwende sie, wenn der Nutzer sagt „settings as code“, „safe-settings“, „manage repos declaratively“, „centralize repo settings“, „org-level branch protection“, „scaffold an admin repo“, „github settings app“ oder /safe‑settings für eine Organisation aufruft, die Repository‑Einstellungen, Branch‑Protection, Rulesets, Labels, Teams, Environments und Collaborators aus einem einzigen Admin‑Repo verwalten möchte. Legt das Admin‑Repo‑Layout an (`settings.yml` + `suborgs/` + `repos/`), die GitHub‑App‑Installationsschritte und einen geplanten `full-sync`‑GitHub‑Actions‑Workflow. Unterscheidet sich von /gh‑bootstrap (einmalige `gh api`‑Konfiguration eines einzelnen Repos) – diese Fähigkeit dient **org‑weiten Settings as Code**, die kontinuierlich abgeglichen werden. Nicht für einmalige GitHub‑Operationen (PRs, Issues, CI‑Status) oder lokale Git‑Arbeit – das liegt außerhalb des Umfangs dieses Katalogs.
