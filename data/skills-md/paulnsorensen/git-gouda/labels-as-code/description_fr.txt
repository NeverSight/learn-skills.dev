Gérez les labels d’un dépôt GitHub comme un fichier sous contrôle de version et auto‑étiquetez les pull requests en fonction du chemin modifié. Exportez les labels actuels, comparez‑les à un fichier `.github/labels.yml` proposé, synchronisez la différence (en une fois ou via un workflow planifié utilisant une action vérifiée, épinglée à un SHA), et branchez l’étiquetage des PR basé sur les chemins avec `actions/labeler` et `.github/labeler.yml`. Utilisez ceci lorsque l’utilisateur dit « standardiser les labels », « synchroniser les labels », « auto‑étiqueter les PR par chemin », « labels en tant que code », ou invoque `/labels-as-code`. NE l’utilisez PAS pour une politique de labels à l’échelle de l’organisation sur de nombreux dépôts — redirigez cela vers `/safe-settings`, qui réconcilie les labels (renommage, exclusion) depuis un dépôt admin central. NE l’utilisez PAS pour les formulaires ou modèles d’issues — cela relève de `/oss-hygiene`. Les suppressions de labels ne sont jamais automatiques ; la compétence demande d’abord une autorisation explicite.
