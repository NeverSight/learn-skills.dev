决定是否跟随喊单人的喊单。对一次喊单钱包在两个维度上评分——**选币**（他喊的币实际是否上涨）和**喊单后行为**（他是否在自己制造的关注中抛售）——随后返回“跟随”或“不跟随”的判定。行为维度依据喊单人自身的每笔交易账本，而非任何自报字段：对每个抽样的币比较首次买入、喊单时间戳以及其后的每一次卖出，因此“他在跟随者上抛售”是一个可度量的序列，而不是推断。当用户询问某个喊单是否值得跟随时使用本技能，例如：

- 这个喊单的能不能跟
- 这个喊单号靠不靠谱
- 喊单信誉分
- 喊单评分
- 他喊完会不会砸盘
- 他是不是喊完就卖
- 跟他的单能不能吃到
- caller 评分
- is this caller trustworthy
- can I follow this caller's calls
- does he dump after calling
- call‑out credibility score
- score this caller

本技能接受 **GMGN 个人资料句柄**（twitter_username，例如 `gmgn.ai/profile/<handle>` 链接的最后路径段）或 **钱包地址**；句柄将在第 0 步解析为（链，钱包）对，并始终回显该解析结果。其他语言的同义提问亦会匹配本技能——匹配意义而非字面。

**请勿使用本技能**处理原始喊单数据，如“这个钱包喊过什么单”“最新喊单”“谁在喊这个币”“KOL 在喊什么”等，这属于 **gmgn‑callout**，仅返回原始数据；亦不要用于将钱包视为交易者而非喊单人进行评价，如“这个钱包能不能跟单”“跟单评分”等，这属于 **gmgn‑wallet‑analysis / gmgn‑wallet‑score**；亦不要用于查询喊单人提及的代币安全性，如“他喊的那个币安全吗”“尽调”“rug check”，这些属于 **gmgn‑contract‑dd**；也不要用于代币创作者的下一次发行评估，如“这个 dev 的新盘能不能买”，这属于 **gmgn‑dev‑score**。仅有喊单意图的裸钱包地址仍交由 **gmgn‑wallet‑analysis** 处理；裸代币地址仍交由 **gmgn‑contract‑dd** 处理。

本技能仅在提问中出现 **喊单 / caller / call‑out** 等关键词时激活。**冲突解决**：因为三个相邻技能共用词汇，若出现“喊单 + 能不能跟 / 信誉 / 砸盘 / 评分”则归属于本技能（判断类），而出现“喊单 + 喊过什么 / 最新 / 谁在喊 / 列表”则归属于 **gmgn‑callout**（返回行列表）。不带“喊单”的“能不能跟”属于钱包交易者分析，交由 **gmgn‑wallet‑analysis / gmgn‑wallet‑review**；不带“喊单”的“信誉”属于项目发行者评分，交由 **gmgn‑dev‑score**。

**预设可回答的短语**（均含喊单意图词）：

- 「帮我看看 [喊单人ID或地址] 这个喊单的能不能跟」
- 「[喊单人ID] 喊的币能跟吗」
- 「查一下 [钱包地址] 的喊单信誉」
- 「这个喊单号喊完会不会砸盘:[地址]」

**本技能不能回答**的情形会转交其他模块，例如：判断任何被喊币是否安全购买（gmgn‑contract‑dd）；他当前喊的是什么币（gmgn‑callout 全局）；他是否是值得复制的好交易者（gmgn‑wallet‑score）；谁也喊过同一币或谁先喊（CLI 不提供此类代币‑喊单人列表，无法计算）；他在一次喊单上投入了多少（仅在不可过滤的全局 feed 中可读）；以及超过 30 天的历史记录（喊单记录仅覆盖最近 30 天）。
