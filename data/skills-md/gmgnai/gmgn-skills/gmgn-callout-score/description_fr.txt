Décidez s’il faut ou non suivre les appels d’un (喊单人). Évaluez chaque portefeuille d’appel sur deux axes — SÉLECTION (les pièces annoncées par l’appelant sont‑elles réellement en hausse) et CONDUITE APRÈS L’APPEL (vend‑il en profitant de l’attention créée par son propre appel) — puis renvoyez un verdict « suivre / ne pas suivre ». L’axe de conduite est prouvé à partir du registre de transactions de l’appelant, pas à partir d’un champ auto‑déclaré : pour chaque pièce échantillonnée, il compare le premier achat, le timestamp de l’appel, puis chaque vente qui suit, de sorte que « il a vidé ses suiveurs » est une séquence mesurée plutôt qu’une inférence. UTILISEZ CETTE COMPÉTENCE lorsque l’utilisateur demande si un appelant vaut la peine d’être suivi : 这个喊单的能不能跟, 这个喊单号靠不靠谱, 喊单信誉分, 喊单评分, 他喊完会不会砸盘, 他是不是喊完就卖, 跟他的单能不能吃到, caller 评分, is this caller trustworthy, can I follow this caller's calls, does he dump after calling, call‑out credibility score, score this caller. Accepte soit un identifiant de profil GMGN (nom d’utilisateur Twitter, par ex. le dernier segment du chemin d’un lien gmgn.ai/profile/<handle>) soit une adresse de portefeuille ; un identifiant est résolu en une paire (chaîne, portefeuille) à l’étape 0 et la résolution est toujours renvoyée. Les mêmes questions dans toute autre langue sont redirigées ici — correspondance sur le sens, pas sur le libellé. N’UTILISEZ PAS CETTE COMPÉTENCE pour des données brutes d’appel — « 这个钱包 喊过什么单 », « 最新喊单 », « 谁在喊这个币 », « KOL 在喊什么 », le flux, le champ de vidage, la carte récapitulative 30 j — cela relève de gmgn‑callout, qui lit chaque appel sans le modifier ; cette compétence l’appelle et ajoute un verdict. Ni pour un appelant jugé comme trader plutôt que comme appelant (« 这个钱包能不能跟单 », « 跟单评分 », back‑test de copie‑trade) — cela relève de gmgn‑wallet‑analysis / gmgn‑wallet‑score, qui lit ses transactions et ne connaît rien de ses appels. Ni pour un token mentionné par l’appelant (« 他喊的那个币安全吗 », 尽调, vérification rug) — cela relève de gmgn‑contract‑dd. Ni pour le prochain lancement d’un créateur de token (« 这个 dev 的新盘能不能买 ») — cela relève de gmgn‑dev‑score. Une adresse de portefeuille seule sans intention d’appel reste sous gmgn‑wallet‑analysis ; une adresse de token seule reste sous gmgn‑contract‑dd. Cette compétence nécessite le mot 喊单 / caller / call‑out dans la demande pour s’en charger. PRIORITÉS, car trois mots sont partagés avec les compétences voisines : 喊单 associé à 能不能跟 / 信誉 / 砸盘 / 评分 conduit ici, tandis que 喊单 associé à 喊过什么 / 最新 / 谁在喊 / 列表 renvoie à gmgn‑callout — le premier groupe demande un jugement, le second des lignes. 能不能跟 sans 喊单 porte sur un portefeuille en tant que trader et reste avec gmgn‑wallet‑analysis / gmgn‑wallet‑review. 信誉 sans 喊单 est une question de lanceur et reste avec gmgn‑dev‑score. PHRASES PRÉDÉFINIES auxquelles cette compétence répond, chacune contenant le mot d’intention d’appel : 「帮我看看 [喊单人ID或地址] 这个喊单的能 不能跟」「[喊单人ID] 喊的币能跟吗」「查一下 [钱包地址] 的喊单信誉」「这个喊单号喊完会不会 砸盘:[地址]」. CE QU’ELLE NE PEUT PAS RÉPONDRE, la demande est redirigée ailleurs : si une pièce annoncée est sûre à acheter (gmgn‑contract‑dd) ; ce qu’il appelle en ce moment (gmgn‑callout global) ; s’il est un bon trader à copier (gmgn‑wallet‑score) ; qui d’autre a appelé la même pièce ou s’il l’a appelée en premier (aucune liste d’appelants par token n’existe dans l’interface CLI, donc non calculable) ; combien il a misé sur un appel (lisible seulement dans le flux global non filtrable) ; tout ce qui date de plus de 30 jours (les enregistrements d’appel couvrent seulement 30 jours).
