Décidez si le prochain lancement d'un créateur de token est sûr à acheter. Attribuez à une adresse de développeur un score de 0 à 100 sur deux axes séparés — CONDUCT (va‑t‑il vous vendre à l'ouverture) et POWER (a‑t‑il déjà réellement construit quelque chose de grand) — en vous basant sur son historique complet de lancements et chaque transaction qu'il a faite avec ses propres tokens, puis renvoyez une recommandation d'achat / non‑achat avec une fenêtre de timing. UTILISEZ CETTE COMPÉTENCE QUAND l'utilisateur pose une question de décision d'achat concernant un lanceur : « puis‑je acheter le nouveau lancement de ce dev », « devrais‑je acheter son prochain lancement », « ce dev va‑t‑il rug », « va‑t‑il vendre à l'ouverture », « son lancement est‑il sûr à sniper », « est‑il sûr d'acheter à son ouverture », « score dev », « score créateur », « score lancement », « ce lanceur est‑il suffisamment fiable pour acheter » ; OU quand l'utilisateur fournit une adresse TOKEN plus une question de confiance d'équipe (« l'équipe de ce token est‑elle fiable », « le développeur de ce projet a‑t‑il un antécédent », « ce créateur a‑t‑il déjà rugé ») — résolvez d'abord le créateur avec `gmgn-cli token info` -> `dev.creator_address`, puis notez cette adresse ; OU quand l'utilisateur donne une adresse WALLET plus une question explicite sur l'historique de lancements (« quels tokens cette adresse a‑t‑elle lancés », « comment se sont déroulés ses précédents lancements », « tous ses tokens sont‑ils tombés à zéro »). Les mêmes questions posées dans toute autre langue doivent également être traitées ici — correspondre au sens, pas à la formulation. N'UTILISEZ PAS CETTE COMPÉTENCE pour une adresse de portefeuille brute sans question jointe : une adresse brute est par défaut une question de copy‑trade et appartient à gmgn-wallet-analysis, qui se déclare le défaut pour cela. N'utilisez pas non plus pour les questions de copy‑trade (« ce portefeuille vaut‑il la peine d'être copié », « devrais‑je copier ce portefeuille », « score copy‑trade »), rentabilité du portefeuille (« ce portefeuille est‑il rentable », « quel est le bilan de ce portefeuille »), ou formulations de profil de portefeuille (« est‑ce un portefeuille de créateur de token », « quelle est la réputation de ce dev ») — celles‑ci relèvent de gmgn-wallet-score. La séparation se fait par type de question, pas par type d'adresse : ces compétences répondent à « qui est ce portefeuille » (un profil), cette compétence répond à « devrais‑je acheter son lancement » (une décision, avec une fenêtre de timing). Notez à quel point « quelle est la réputation de ce dev » (profil → gmgn‑wallet‑score) est proche de « score dev » (décision → ici) : le facteur décisif est de savoir si un achat est à l'ordre du jour. Si c'est réellement ambigu, posez une courte question au lieu de deviner — les deux produisent des rapports différents et il n'y a pas de couverture bon marché.

Veuillez toujours répondre dans la langue de l'utilisateur.
