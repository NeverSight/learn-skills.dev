Решите, безопасно ли покупать запуск NEXT создателя токена. Оценивает адрес разработчика от 0 до 100 по двум отдельным осям — ПРОВЕДЕНИЕ (свалит ли он вас при открытии) и МОЩНОСТЬ (он когда-нибудь действительно строил что-нибудь большое) — на основе своей полной истории запусков и каждой сделки, которую он совершил с собственными монетами, а затем возвращает вызов «купить/не покупать» с временным окном. ИСПОЛЬЗУЙТЕ ЭТОТ НАВЫК, КОГДА пользователь задает вопрос о покупке лаунчера: «могу ли я купить новый запуск этого разработчика», «стоит ли мне купить его следующий запуск», «будет ли этот разработчик ковриком», «свалит ли он при открытии», «безопасно ли его запускать для снайперов», «безопасно ли покупать при его открытии», «оценка разработчика», «оценка создателя», «оценка запуска», «достаточно ли надежен этот лаунчер, чтобы его покупать»; ИЛИ когда пользователь дает адрес ТОКЕНА плюс вопрос о доверии команды («заслуживает ли доверия команда этого токена», «есть ли у разработчика этого проекта запись», «был ли этот создатель надежен раньше») — сначала разрешите создателя с помощью `gmgn-cli token info` -> `dev.creator_address`, затем оцените этот адрес; ИЛИ когда пользователь дает адрес КОШЕЛЬКА плюс явный вопрос об истории запуска («какие токены были запущены по этому адресу», «как прошли его предыдущие запуски», «все ли его монеты обнулились»). Здесь тоже задаются те же вопросы, которые задаются на любом другом языковом маршруте — совпадение по смыслу, а не по формулировке. НЕ ИСПОЛЬЗУЙТЕ ЭТОТ НАВЫК для пустого адреса кошелька без прикрепленного вопроса: пустой адрес по умолчанию является вопросом для копирования и принадлежит gmgn-wallet-analysis, который объявляет себя для него значением по умолчанию. Также не используйте его для вопросов о копировании («стоит ли копировать этот кошелек», «должен ли я скопировать этот кошелек», «оценка копирования-торговли»), прибыльности кошелька («прибыльный ли этот кошелек», «каков послужной список этого кошелька») или фраз в профиле кошелька («это кошелек для создателей токенов», «какова репутация этого разработчика») — они принадлежат gmgn-wallet-score. Разделение происходит по типу вопроса, а не по типу адреса: эти навыки отвечают на вопрос «кто этот кошелек» (профиль), этот навык отвечает на вопрос «должен ли я купить его запуск» (решение с временным окном). Обратите внимание, насколько близко «какова репутация этого разработчика» (профиль → gmgn-wallet-score) к «оценке разработчика» (решение → здесь): решающим фактором является возможность покупки. Если ситуация действительно двусмысленная, задайте один короткий вопрос вместо того, чтобы гадать: эти два отчета дают разные результаты, и дешевого хеджирования не существует.
