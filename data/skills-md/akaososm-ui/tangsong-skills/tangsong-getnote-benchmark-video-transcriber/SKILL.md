# Get 对标视频整理

## Overview

将 Get 笔记知识库中的视频整理为可检索的本地 Markdown 资料。每次运行都先读取知识库和本地目标目录，按内容 ID 做增量判断，不覆盖已有稿件；视频原文是内容真源，Get 摘要只能放在原文之后。

## 首次使用与配置

本技能可以被没有既有整理记录的人使用，但它不是 Get 笔记的开户或订阅工具。首次运行必须先完成以下检查：

1. 确认 `mcp__getnote__*` 工具可调用。若未连接或未授权，停止写入，并提示用户先在当前 AI 客户端完成 GetNote OAuth 授权；不要索要或暴露 API Key。
2. 读取目标知识库。用户明确提供知识库名称时使用该名称；未提供时默认使用 `对标博主`。找不到时停止写入，提示用户在 Get 笔记中创建知识库。
3. 读取订阅博主。知识库没有博主时停止写入，提示用户先在 Get 笔记中订阅至少一位博主；本技能不擅自创建订阅、不访问其他知识库。
4. 读取内容列表。博主存在但没有可用视频时，报告“暂无可整理内容”或“内容可能仍在处理中”，不生成空白文档。
5. 确定本地保存目录：
   - 用户明确说“保存到/落盘到”某路径时，该路径就是最终的 `对标视频` 目录，不再自动追加子目录。
   - 用户只说使用本技能、没有给路径时，优先使用当前工作目录下的 `外部对标/对标视频/`。
   - 当前工作目录明显不适合作为知识库落点，或用户要求使用 Obsidian 但没有提供 Vault 路径时，只询问一次保存路径，再开始写入。
6. 首次运行且用户没有明确要求“全部/批量”时，默认只处理一条视频并停止，等待用户确认；用户明确要求批量时才批量处理。

Get 笔记里的知识库创建、博主订阅和内容处理需要用户在 Get 笔记侧完成。本技能负责连接检查、读取、转写整理和本地 Markdown 落盘。

## 落点与范围

- Get 目标知识库名称：默认 `对标博主`，以用户本次指定为准。
- 本地目标目录：以本次用户指定为准；没有指定时使用当前工作目录下的 `外部对标/对标视频/`。不得把某个用户的绝对路径当成所有用户的固定配置。
- 每位博主使用一个直接子文件夹；每条视频使用一个独立 .md 文件。
- 账号名出现 唐宋AI商业教练 前缀时，统一落到 唐宋AI商业教练/，不要把活动宣传后缀带进文件夹名。
- 保留目标目录已有文件，尤其是目录根部的旧资料；只新增明确缺失的稿件。

## 使用的 GetNote 工具

按以下顺序使用已配置的 mcp__getnote__* 工具：

1. list_topics：找到名称为 对标博主 的知识库，取得 topic_id。
2. list_topic_bloggers：读取当前订阅博主及其 follow_id_str、账号名、平台和数量。
3. list_topic_blogger_contents：按页读取每位博主的全部内容列表；服务端每页固定 20 条，不要只读第一页。
4. get_blogger_content_detail：按 post_id_alias 获取单条视频详情。原文取 post_media_text，总结取 post_summary，来源取 post_url 和发布时间。

不要用 post_summary 代替 post_media_text。如果详情接口没有返回原文，也要建立文档，但必须明确标注“Get 未返回视频原文转写”，不能根据摘要伪造逐字稿。

## 执行流程

### 0. 运行前自检

在任何本地写入前完成自检，并把结果分为“已通过/需用户操作/本次停止”：

- GetNote MCP 未连接或授权失效：停止，不创建本地文档。
- 知识库不存在：停止，告诉用户默认查找的知识库名称，并给出需要在 Get 笔记侧完成的创建动作。
- 知识库存在但没有订阅博主：停止，告诉用户需要先订阅博主，并要求再次调用本技能。
- 博主存在但列表为空：停止或跳过该博主，说明没有可读取的视频，不用摘要臆造内容。
- 目标目录不存在：只创建本次需要的目标目录和博主子目录，不删除、不移动、不覆盖其他文件。

自检通过后，先向用户简报：知识库名称、博主数量、待整理视频数量、目标目录和本次运行模式；再开始获取详情。

### 1. 先判断运行模式

- 用户说“先测试一条”“先跑一个”“确认后继续”时，只处理一条，写完后停止并等待确认。
- 用户要求“其他未整理的”“继续整理”“全部整理”时，处理当前知识库中所有本地缺失的视频。
- 用户说“初始化”“第一次使用”“帮我检查能不能用”时，只做连接、知识库、博主、内容和目标目录自检；除非用户同时要求测试，不写视频文档。
- 用户未说明模式且本地目标目录没有任何本技能产物时，按“单条测试”处理，不能直接批量落盘。
- 每次运行都重新读取 Get 当前列表，不依赖上一次的数量；用内容 ID 和本地文件来源信息做增量判断。

### 2. 盘点本地已有内容

- 先 find 目标目录下的 .md 文件，确认真实目录和现有文件数量。
- 已存在文件默认不动、不覆盖、不移动。
- 优先用文档末尾的 Get 笔记内容 ID 判断是否已整理；若旧文件没有 ID，再用博主文件夹和标题辅助判断，并避免擅自覆盖。

### 3. 获取详情并保留原文

- 将 post_media_text 作为原文真源，保留口语、重复、语气词和疑似识别错误。
- 不把摘要改写成逐字稿，不为了通顺替换原文。
- Get 原文中的连续星号、脱敏占位、[UNK]、空白或明显不可识别片段都要保留其可见形式，并放入“转写待核对”部分。
- 对原文中的 Markdown 控制字符做显示层转义：至少转义连续星号，必要时转义反引号、方括号、行首标题符号、列表符号，避免原文被渲染成粗体、斜体、链接或标题。转义只改变 Markdown 表示，不改变页面上看到的原始字词。

### 4. 生成待核对标记

每篇文档都保留 ## 转写待核对：

- 有连续星号或占位符：写出原始片段，并说明“Get 未识别或可能脱敏，需回看视频核对”。
- 没有返回原文：明确写出“Get 未返回视频原文转写”。
- 发现语义明显不通的片段：保留原词，只在待核对区写“疑似为……”，不能直接改写原文。
- 没有发现明确异常时，写“暂未发现 Get 明确标出的未识别占位符；普通同音字或专有名词识别偏差仍需以视频为准”。
- Get 接口未提供时间戳时，不虚构时间码；用原文片段定位。若后续接口返回时间戳，再补充时间点。

### 5. 生成 Markdown

文件名优先取视频标题，去掉连续话题标签和非法文件名字符；标题过长时适度截短；同一博主标题重复时在文件名后追加内容 ID，确保不覆盖。

固定结构如下，原文必须在总结之前：

~~~markdown
# 视频标题

## 视频转文字原文稿

视频原文……

## 转写待核对

- 待核对片段与原因

## 总结

Get 返回的摘要……

## 来源信息

- 博主：
- 平台：
- 发布时间：
- 原视频：<原始链接>
- Get 笔记内容 ID：
~~~

总结可以保留 Get 返回的 Markdown 项目符号和粗体格式，但不能挪到原文前面。

### 6. 写入与校验

- 使用 apply_patch 批量新增文件；批量写入前先确认路径不存在。
- 分批写入，避免一次操作过大；每批完成后更新已写入清单，发生中断时从缺失内容继续。
- 写入完成后检查：博主子文件夹数量、每位博主文件数、文档是否包含“视频转文字原文稿 / 转写待核对 / 总结 / 来源信息”四个段落、空原文标记数量、内容 ID 是否重复。
- 最终报告新增数量、各博主数量、未返回原文数量和待回看标记数量；明确说明保留了哪些旧文件。

```text
知识库名称：对标博主

先不要整理视频，只告诉我缺什么。
```

### 首次测试

```text
使用 $tangsong-getnote-benchmark-video-transcriber，
从“对标博主”中先整理唐宋AI商业教练的一条视频，
账号链接：https://www.douyin.com/user/self?from_tab_name=main

完成后停止，等我确认。
```

### 后续增量批量整理

```text

把“对标博主”知识库中所有还没有整理的视频，
增量保存到：/你的本地路径/外部对标/对标视频/
不要覆盖已有文档。
```

### 连接或准备失败时的处理

- 不要假装已经读取 Get 数据。
- 不要用用户没有提供的知识库、博主或视频链接替代目标数据。
- 一次性列出缺失的准备动作，优先让用户完成最少的一个动作后再重试。
- 如果只是目标路径不明确，不要反复检查 Get；只询问保存路径。

## 边界与安全规则

- 只处理用户指定的 Get 知识库和本地目标目录，不自行扩展到其他知识库、公众号或外部网站。
- 不下载、发布、同步或改写视频内容；本技能只做读取、转写整理和本地 Markdown 落盘，除非用户另行授权。
- 不因为摘要看起来完整就跳过原文详情获取。
- 不把一次运行的博主数量、视频数量当成永久配置；下次运行重新盘点。
- 对 Get 接口的空结果、权限错误、分页异常或内容为空，记录一次并继续处理其他条目；最终报告限制，不反复空转。
