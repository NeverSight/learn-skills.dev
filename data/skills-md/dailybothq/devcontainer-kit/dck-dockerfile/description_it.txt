Creare o rigenerare il contenitore di sviluppo proprio del repository con devcontainer‑kit — .devcontainer/devcontainer.json, docker/local/<service>/Dockerfile (immagine runtime ufficiale fissata per digest, DeepWorkPlan Vim, Herdr, agenti di codifica tramite agentkit), docker/local/docker-compose.yaml e dev.sh — quindi dimostrarlo con una build reale. Usare solo quando l’utente richiede un dev container, un devcontainer, un docker/local/<service>/Dockerfile o un contenitore `dev.sh up` per un repository, o per rigenerare o aggiornare uno creato da devcontainer‑kit. Non usarlo per immagini di produzione, distribuzione, Kubernetes, runner CI, o semplicemente perché un repository contiene un Dockerfile.
