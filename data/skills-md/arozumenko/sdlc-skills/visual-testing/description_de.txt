Verwenden, wenn die gerenderte UI eine visuelle Regressionsprüfung benötigt – „hat sich die UI geändert“, „visueller Test“, „Screenshot‑Diff“, „gegen den Baseline vergleichen“, „Layout‑Regressionen erkennen“ oder eine visuelle Assertion im Testlauf. Funktioniert mit jedem HTML, das Sie rendern können – einer erzeugten statischen Seite (Design‑Mockup, Bericht, Flow‑Map‑Poster), die von der Festplatte geöffnet wird, oder einer laufenden Anwendung, die durch Ihre bestehende Browser‑/Geräte‑Automatisierung gesteuert wird. Macht Screenshots jeder Ansicht, vergleicht sie mit einem festgeschriebenen Baseline mittels reg‑cli (MIT, keine Cloud) und meldet die Änderungen in einem HTML‑Report plus einer Erfolgs‑/Fehlschlag‑Zusammenfassung. Capture nutzt das Browser‑ bzw. Gerätetool, das Sie bereits haben – es wird keine separate Headless‑Engine installiert. KEINE funktionale oder Korrektheitsprüfung (ein Diff beweist, dass Pixel sich bewegt haben, nicht dass etwas korrekt ist), und ein roter Diff ist ein Hinweis zum Nachsehen, kein automatisches Urteil.
