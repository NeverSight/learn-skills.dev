ウェブアニメーションをフレーム予算内に収める — 合成のみのプロパティをアニメートし、ページが混雑しているときはモーションをメインスレッドから切り離し、アニメーションがフレーム落ちしたときは原因を特定する。レイアウト／ペイント／合成パイプライン、低コストなプロパティの切り替え、CSS と WAAPI と requestAnimationFrame の比較、Framer Motion のハードウェアアクセラレートパス、React のフレームごとの再レンダリング、継承される CSS 変数の再計算、ブラーのコスト、そして `will-change` が実際に効果を発揮する場面を取り上げる。アニメーションがぎくしゃく、カクつく、スタッタリングする、またはフレーム落ちする場合、どのプロパティをアニメートすべきか選ぶとき、パフォーマンス観点で CSS と JS アニメーションのどちらを選択すべきか決めるとき、あるいは `will-change` や GPU レイヤーを使用しようとする時に利用する。イージングや継続時間、アニメーション自体を行うかどうかを決める際は `animate` を、モーション全体をレビューする際は `review-animations` を使用する。
