Prova a rompere un elemento UI fornendogli dati peggiori possibili — nomi lunghi, email non interrotte, nomi di una sola lettera, campi mancanti, conteggi enormi, zero elementi, etichette lunghe, testo non latino, emoji, numeri estremi — poi visualizzalo dietro un interruttore “Dati demo / Caso peggiore” e segnala tutto ciò che si è rotto, indicando la correzione per ciascun caso. Usa questa procedura quando l'utente chiede di fare test di stress, rompere o trovare casi limite in un componente o schermata, o di “provare il caso peggiore”. Per la critica del design visivo usa emil-design-eng; per il motion usa review-animations.  

Per favore rispondi sempre nella lingua dell'utente.
