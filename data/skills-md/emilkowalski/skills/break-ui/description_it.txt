Prova a rompere un elemento UI fornendogli dati peggiori possibili — nomi lunghi, email non spezzabili, nomi di una sola lettera, campi mancanti, conteggi enormi, zero elementi, etichette lunghe, testo non latino, emoji, numeri estremi — poi visualizzalo dietro un toggle “Dati demo / Caso peggiore” e segnala tutto ciò che si è rotto, con la correzione per ciascuno. Usa quando l’utente chiede di stressare, rompere o trovare casi limite in un componente o schermo, o di “provare il caso peggiore”. Per la critica di design visivo usa emil-design-eng; per l’animazione usa review-animations.

Rispondi sempre nella lingua dell’utente.
