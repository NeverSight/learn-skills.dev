Génère un ticket (titre + description, uniquement en markdown) à partir d’un tripack d’ingénierie, d’un rapport brut/document de constatation, ou directement à partir des changements de code réels (diff/comparaison de branches) lorsqu’aucune documentation n’existe. Utilisez ceci à la FIN du travail d’implémentation, juste avant de pousser vers une branche, ou de façon rétroactive lorsque le travail a déjà été commité/poussé mais aucun ticket n’a jamais été rédigé. Utilisez toujours cela lorsque l’utilisateur demande « buat tiket », « generate ticket », « write a ticket for this change », ou souhaite une description de ticket/tâche dérivée d’un tripack, d’une constatation (par ex. mise à jour de dépendance, constat SonarQube), ou d’une comparaison diff/branche. NE L’UTILISEZ PAS pour les tickets de planification pré‑travail (c’est la tâche du générateur de plan‑tripack) — cette compétence documente ce qui a réellement été fait ou est réellement en cours de modification.
