Genère ou révise les trois documents techniques standard (« tripack ») pour le travail sur les fonctionnalités d’un projet logiciel : technical-design.md, tactical-strategy.md et task-plan.md — ainsi qu’un decision‑log.md optionnel consignant les décisions techniques guidées par le business (lisibles par le PM/PO/lead technique) chaque fois que l’entrée les contient. Indépendant de la pile technologique — il découvre la stack du projet, son architecture et ses conventions à partir de CLAUDE.md à la racine du projet et du code lui‑même. Utilisez cette compétence chaque fois que l’utilisateur souhaite un plan d’implémentation — pour une NOUVELLE fonctionnalité, un AJUSTEMENT d’une fonctionnalité existante, ou une RÉVISION d’un tripack déjà généré (améliorer, ajuster ou supprimer des parties après un changement de besoin en cours de développement). L’entrée peut être un PRD, un FSD, un document d’analyse ou une description directe de la fonctionnalité — aucun document en amont spécifique n’est requis. Les phrases déclencheuses incluent : « generate tripack », « buat technical design », « buatkan task plan », « generate implementation plan », « buat rencana implementasi », « update tripack », « revisi technical design », « ada perubahan requirement », « re-sync doc », « adjust tripack », « tripack dari PRD/FSD ini ». NE PAS utiliser pour : de petites corrections de bugs, des revues de docs sans génération, ou des questions générales d’architecture.

Veuillez toujours répondre dans la langue de l’utilisateur.
