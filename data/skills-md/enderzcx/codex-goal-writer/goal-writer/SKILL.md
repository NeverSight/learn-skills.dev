# goal-writer

为原生 Codex Goal Mode 编写可直接复制的目标。默认使用中文，并保留可执行前缀 `/goal`。

## 输出

先在 `text` 代码块中给出推荐目标：

```text
/goal <最终结果>。<真正重要的约束>。<可验证的完成标准>。
```

优先使用自然语言，不强制分节或套用固定表格。只保留真正有帮助的内容：

- **结果：** 写清最终状态，而不是只描述要做的动作。
- **约束：** 只写能避免实际问题的边界、兼容要求或审批点。
- **验证：** 写清证明完成所需的测试、指标、产物或验收标准。

## 流程

1. 起草前先查看用户提供的仓库上下文、计划、命令和约束。
2. 把请求改写成一个有边界的最终结果，并补上重要约束和完成验证。
3. 只有缺失信息会改变产品方向、范围、成本、风险或外部状态时才提问。可发现的信息自行查明；低风险歧义使用一句明确假设。
4. 长期或多阶段工作应引用权威计划、规格或路线图，不把整套编排协议塞进 goal；整体保持简洁。
5. 审查现有 goal 时，只指出结果、约束或验证中的缺失与歧义，然后给出修正版。

## 边界

- 除非用户同时要求实施，否则不要执行 goal 描述的任务。
- 不重复当前仓库或运行环境已经提供的规则。
- 不虚构凭据、生产审批、业务决定、写入权限或验证命令。
- 只有外部写入、破坏性、高成本、不可逆或扩大范围的操作才显式要求审批。
- 除非用户要求，否则不附带英文镜像版本。

示例：

```text
/goal 把这个代码库迁移到 TypeScript，保留现有行为，开启 strict mode 且不使用显式 any，并让完整测试套件通过。
```
