Diagnostiziert, warum ROCm, das HIP‑SDK, PyTorch oder llama.cpp auf einer AMD‑GPU unter Linux, Windows oder WSL2 nicht funktioniert, und wendet dann mit Zustimmung eine risikoarme Lösung an oder gibt den genauen nächsten Schritt zurück. Leitet außerdem Probleme mit Lemonade, LM Studio und Ollama an den richtigen Upstream‑Kanal weiter. Verwenden, wenn der Nutzer meldet, dass ROCm oder HIP „nicht funktioniert“, torch.cuda.is_available() False ist, rocminfo / hipInfo die GPU nicht erkennen kann, oder Fehlermeldungen wie hipErrorNoBinaryForGpu, HSA_STATUS_ERROR_INVALID_ISA, „invalid device function“, „no kernel image is available“, /dev/kfd nicht öffnen kann, Berechtigung verweigert für /dev/kfd, „ROCk module is NOT loaded“, eine fehlende libamdhip64.so / amdhip64_6.dll / hipblas.dll / vcruntime140_1.dll, ein HSA_OVERRIDE_GFX_VERSION‑Page‑Fault, ein iGPU+dGPU‑Absturz, ein Container, der die GPU nicht sieht, oder ein amdgpu-install / DKMS‑Fehler auftreten. Unterstützt vom `rocm`‑CLI (`rocm examine` / `rocm diagnose` / `rocm fix`); diese Fähigkeit ist ein dünner Wrapper um diese Befehle, keine Neuimplementierung.

Bitte immer in der Sprache des Benutzers antworten.
