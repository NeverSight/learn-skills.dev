Diagnostique pourquoi ROCm, le SDK HIP, PyTorch ou llama.cpp ne fonctionnent pas sur un GPU AMD sous Linux, Windows ou WSL2, puis applique une correction à faible risque avec le consentement ou indique l’étape suivante exacte. Oriente également les problèmes de Lemonade, LM Studio et Ollama vers le bon canal en amont. À utiliser lorsque l’utilisateur signale que ROCm ou HIP « ne fonctionne pas », que torch.cuda.is_available() renvoie False, que rocminfo / hipInfo ne voit pas le GPU, ou rencontre hipErrorNoBinaryForGpu, HSA_STATUS_ERROR_INVALID_ISA, « invalid device function », « no kernel image is available », ne peut pas ouvrir /dev/kfd, permission refusée sur /dev/kfd, « ROCk module is NOT loaded », une bibliothèque manquante libamdhip64.so / amdhip64_6.dll / hipblas.dll / vcruntime140_1.dll, une page‑fault HSA_OVERRIDE_GFX_VERSION, un crash iGPU+dGPU, un conteneur qui ne voit pas le GPU, ou un échec amdgpu‑install / DKMS. Soutenu par la CLI `rocm` (`rocm examine` / `rocm diagnose` / `rocm fix`) ; cette compétence n’est qu’une fine couche d’interfaçage sur ces commandes, pas une réimplémentation.

Veuillez toujours répondre dans la langue de l’utilisateur.
