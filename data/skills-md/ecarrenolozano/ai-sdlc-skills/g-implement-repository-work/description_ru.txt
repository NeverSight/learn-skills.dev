Планировать и выполнять работу с репозиторием после утверждения требований, утверждённой архитектуры, синхронизации задач репозитория и завершения технической основы. Использовать, когда Codex должен либо (1) создать или обновить руководство по приоритету бэклога sdlc_docs/03_implementation на основе нерешённых проблем без реализации кода, либо (2) реализовать одну явно выбранную пользовательскую историю, баг, рефакторинг или небольшую техническую задачу через гибридный дизайн архитектуры на уровне кода, принадлежащий разработчику, соответствующие ссылки на лучшие практики, Ping‑Pong TDD, где «Тестирующий драйвер» определяет/создаёт RED‑тесты, а «Навигатор‑разработчик» реализует только достаточный код для их прохождения, обновления статуса, видимые пользователю RED‑GREEN‑REFACTOR, защищённые локальные обновления документации отслеживания статуса, такие как sdlc_docs/trace_workflow.md и sdlc_docs/03_implementation/backlog_priority.md, доказательства на основе pytest, утверждённая структура тестов, локальное одобрение записи и отсутствие удалённых действий в GitHub или системе контроля версий без отдельного явного одобрения.
