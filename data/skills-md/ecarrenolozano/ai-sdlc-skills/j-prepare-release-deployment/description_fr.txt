Préparer le travail de release et de déploiement après une implémentation validée, en utilisant un workflow discovery‑first pour le versioning, les lockfiles, l’empaquetage, les conteneurs Docker ou Podman, les workflows CI et la documentation de déploiement. Utiliser lorsqu’il faut que Codex inspecte la readiness d’une release, propose ou applique des changements de préparation de release approuvés, mette à jour le statut de release dans sdlc_docs/trace_workflow.md, ou renvoie les décisions non résolues d’hébergement, de sécurité, d’exécution ou d’opérations vers les exigences ou l’architecture. Ne pas utiliser pour implémenter les récits produit, valider les scénarios BDD, créer des pull requests, publier des artefacts, pousser des tags ou déployer sans approbation séparée. Veuillez toujours répondre dans la langue de l’utilisateur.
