# natural-slides

AIが作るスライドにありがちな「細い線・余白だらけ・均等3カラム・箇条書きの羅列・ですます調の説明文」を避け、図とイラストで一目で伝わる日本語の資料を作るためのルール。どの会社・どの業種でも使えるように、ブランドに関わる値は「ブランド設定」で差し替える。

出力形式の指定がなければ、その環境で使えるスライド作成の仕組み（スライド型のアーティファクト、.pptx、HTMLなど）で作る。比率は16:9、寸法は1920×1080基準で書く。文章の自然さを上げたいときは、日本語の文章スキル（natural-japaneseなど）を併用する。

## ブランド設定（最初に確かめる）

作り始める前に、ブランド設定がもう決まっているかを確かめる。見る順番は、今回の依頼の中の指定、このスキルのフォルダにある`brand.md`、プロジェクトの指示やメモリにある設定。どこかで決まっていれば、それに従ってすぐ作り始める。一部の項目しか決まっていなければ、足りない項目だけを尋ねる。

どこにも設定がないときは、作り始める前に一度だけ尋ねる。今の既定値を先に見せて、変えたいところだけ答えてもらう。選択肢で答えてもらう仕組みがある環境ではそれを使い、なければ1通のメッセージにまとめる。尋ねるのは次の5項目まで。

| 項目 | 既定値 | 尋ねること |
|---|---|---|
| メインカラー | #2F3237（黒っぽいグレー） | ブランドカラーのカラーコード。わからなければ色の名前かロゴ画像から決める |
| 書体 | 欧文・数字はMontserrat、和文はNoto Sans JP | 決まった書体があるか |
| ロゴ | なし（右上を空ける） | ロゴ画像があるか |
| 会社名・サービス名 | なし | 表紙や締めに入れる名前 |
| 主な出力先 | PDF | PowerPoint・Googleスライド・Canvaのどれで開くか |

- 「全部このままでいい」と一言で答えられる聞き方にする
- 依頼の中で決まっている項目は「受け取った」と一行で添えるだけにし、表に並べて尋ねるのは足りない項目だけにする
- 「始める前に」の約束の一文を決めるのに相手や目的を尋ねる必要があれば、ブランドの質問と同じ1通にまとめる。5項目の上限はブランド設定だけに数える
- 答えは保存して次から尋ねないことを、質問の最後に一言添える
- 「おまかせ」「すぐ作って」と言われたら既定値で作り、仕上げの報告で変えられる項目を添える。このときは保存せず、次に使うときにまた尋ねる
- 書体を変えるときは、主な出力先で使えるかを添えて答える。Googleスライド・Canvaにない書体や、PowerPointに埋め込めない書体は、開いたときに置き換わって文字幅が変わる
- メインカラーが明るすぎて白い文字が読めないときは、そう伝えて箱の文字を#3C3C3Cにする
- 紫から青のような「AIらしい色」は、ブランドが本当にその色でない限り勧めない

**答えを残す**：決まった設定は、次から尋ねずに済むよう残す。ユーザーが答えなかった項目は既定値で埋める。ファイルを書ける環境（Claude Codeなど）では、このスキルのフォルダに`brand.md`を保存し、保存したことを伝える。形は`brand.example.md`と同じにする。見本がなければ、「項目｜値」の2列の表に、上の5項目（書体は欧文・数字と和文の2行に分ける）を並べる。ファイルを書けない環境（claude.aiにアップロードしたスキルなど）では、`brand.md`の中身をメッセージで渡し、プロジェクトの指示に貼るよう案内する。複数のブランドを使い分ける人には、`brand.md`ではなくプロジェクトごとの指示に置くよう勧める。

「ブランド設定を変えて」と言われたら、今の設定を見せて同じ形で尋ね、保存し直す。

## 始める前に

1. **ブランド設定を確かめる**：上の「ブランド設定」の節に従う。ロゴがなければ位置を空けておく
2. **約束を一文で書く**：「誰に、何を約束する資料か」。決まらないうちは作り始めない
3. **対比を一つ決める**：資料全体の筋になる対比（今と導入後、自分でやる場合と任せた場合、など）を決め、各ページがそこに戻るようにする
4. **各スライドの主役を1つ決める**：図解、大きな数字、イラストのどれか。イラストを使えないときは、図解、大きな数字、大きなアイコン、大きく置いた一文から選ぶ（「イラストを使えないとき」の節）

## 色

メインカラーをAとして、次の役割で使う。以下の「アクセント」はメインカラーのこと。指定がないときの既定値はA=#2F3237（黒っぽいグレー）で、段階色は#DDDEDD → #A0A1A2 → #5F6268 → #2F3237、淡いアクセントは#BCBDBD、アクセントの地は#EFEFEE。メインカラーが無彩色のとき、色で目を引くのは黄色のマーカーとハイライト（#E5B521）だけにする。

ユーザーへの質問や報告でカラーコードを書くときは、カラーコードだけを並べず、どんな色かがわかる名前を添える（例：#F5F5F3（ごく薄いグレー）、#E5B521（濃い黄色））。色の見本を表示できる環境では見本も添える。

| 役割 | 値 |
|---|---|
| 背景 | #FFFFFF（真っ白） |
| カード・図の箱 | #FFFFFF（背景と同じ白。箱は枠線で区切る） |
| 箱の枠線 | #DDDBD5（強調する箱はA）、太さ6〜9px |
| 主テキスト | #3C3C3C（真っ黒にしない） |
| 副テキスト | #6B6B6B（数字の時点・比較対象、表の注だけ。「小さく薄い文字を増やさない」の節） |
| 弱テキスト・ページ番号 | #9A9A9A（ページ番号と出典だけ） |
| アクセント | A（ピル、見出しバー、強調の箱、大きな数字） |
| 淡いアクセント | Aを背景に対して約35%の濃さにした色（図の矢印、補助の枠） |
| アクセントの地 | Aを約8%の濃さにした色（比較表の自社列など） |
| 段階色 | Aの15% → Aの45% → A → Aを少し暗くした色（左から右へ濃くなる工程フロー用。文字は前の2色で#3C3C3C、後の2色で#FFFFFF） |
| マーカー | #F9DC72（黄。区別が要る2つ目だけ#9ADB6E） |
| ハイライト | #E5B521（マトリクスの星など、注目する1点だけ） |
| 図の矢印・引き出し線 | #A3A5A8 |
| 図の淡い面 | #EEEEEC（マトリクスの象限など） |
| 比較の他社列 | #8A94A6 |

- グラデーション背景、影、グロー、絵文字は使わない（マーカーと下の「グラデーションを指示されたとき」は例外）
- 本文をアクセント色にするのは、短い語か大きな数字だけ
- 文字と背景のコントラストは本文4.5:1以上、44px以上は3:1以上。アクセントが明るすぎて白文字が読めないときは、箱の文字を#3C3C3Cにする

### グラデーションを指示されたとき

「グラデーションを使って」と言われたときだけ、次の2種類に限って使う。

- **文字のグラデ（工程名）**：淡いグレーの矢羽（#F7F8FAから#ECEEF0へ）を並べ、各矢羽の工程名を太字48〜56pxのグラデ文字にする。色は矢羽ごとに少しずつずらし、左から右へ一続きに流れるようにする。説明文は単色
- **棒のグラデ（比較・割合）**：強調したい棒だけを横方向に淡いアクセントからAへのグラデにし、比較対象は#D9D9D9の単色。棒の角は丸めず、値は棒の右に太字で
- どちらも1スライドに1か所。グラデを使うスライドではマーカーを使わない

## 書体

- 指定がなければ、欧文と数字はMontserrat、和文はNoto Sans JP。指定は`font-family: 'Montserrat', 'Noto Sans JP', Arial, sans-serif`の順にする（Montserratに和文の字形がないため）。読み込むウェイトは500・600・700・900
- ウェイト：見出し・強調700、本文500。400以下の細字は使わない
- 締めの一文（そのページの結論を言い切る一文）は900、44px前後で、アクセント色で置いてよい
- サイズ：ページタイトル44、リード文36〜40、箱の見出し32、本文28〜32、出典24、大きな数字240〜300。24px未満の文字は使わない
- 数字は太字で一回り大きくし、「万円」「%」などの単位は小さく添える
- 大文字英字の飾りラベル（OUR SERVICE、PROBLEMなど）を見出しの上に置かない。小文字の「point 1」「Case 01」程度はよい

### 小さく薄い文字を増やさない

見出しの下に灰色の小さな説明を添え、それをカード・図の段・工程ごとに繰り返すと、情報を足しただけの資料に見え、AIが作った感じが強く出る。小さく薄い文字は、ないと困るところにだけ使う。

- 1つの箱・段・工程に置く文字は、見出しか言い切る一文のどちらか1つにする。説明が要るときは、見出しそのものを一文にするか、説明を本文の色（#3C3C3C）、28px以上、1行で書く。「太字の見出し＋灰色の2行の説明」の組を並べない
- 見出しの上に小さなラベルを乗せない（「01認知」「STEP 1」、見出しの英訳など）。順番が要るときは円で囲んだ番号かピルにする
- 「経路は顧客ごとに異なる」「あくまで一例」のような断り書きや補足は、スライドに書かずスピーカーノートに回す
- 小さく薄い文字（24〜26px、#6B6B6Bか#9A9A9A）を使ってよいのは、出典、数字の時点と比較対象、表の注、ページ番号だけ。出典は1スライド1行までにし、数字の時点はできるだけリード文や数字の横に本文の色で入れる
- 仕上げに、灰色の小さな文字を1つずつ消してみる。消しても意味が通じるものは消す。消すと意味が通じないものは、リード文か見出しに入れ直す

## ページの骨組み（全スライド共通）

1. 左上：アクセント色の縦バー（幅8px、高さ48px）＋ページタイトル44px/700。タイトルの下に全幅のヘアライン（#E6E4DE、1px）
2. 右上：ロゴを小さく（高さ32px程度）。ロゴがなければ空ける
3. タイトルの下：リード文を1〜2行、中央揃え36〜40px/700。言いたいことはここで言う
4. その下：図・イラスト・数字のどれか1つを主役に置く
5. 右下：ページ番号24px、弱テキスト色。右下の隅に小さく置くだけで、左右240pxの内側に置く中身とは横に重ならない。ページ番号のために中身の下端を上げない

## ページタイトル

- 句読点（「、」「。」）を使わずに済む一言にする。主張はリード文に回す
- 良い：「サービスの特徴」「料金のご案内」「導入までの流れ」「導入後の体制」「導入事例」
- 悪い：「顧客の手元から、煩雑な作業をなくす」のような句読点入りの主張文
- 全角14字まで。疑問形は「こんなお悩みありませんか？」のような1枚だけ

## 余白

**左詰めにしない**
- 主要な中身は幅1440px以内で中央に置き、左右240px以上の余白を残す
- 箱・表・カードの中の文字は、枠から最低32px離す。色の帯や縦線の横に置く文字は64px以上離す
- リード文と見出しは中央揃え。左揃えは2カラムの説明文や表の中身だけ
- 上下の間隔は24 / 40 / 64pxの3段階

**余白を余らせすぎない**
- リード文の下から画面の下端の60px手前まで（y約360〜1020、幅1440px）を主役の領域とし、その縦横8割以上を中身で埋める。ページ番号は右下の隅にあって中身と重ならないので、ページ番号の高さで主役を止めない。出典の1行も含めて、いちばん下の要素の下端がy1000前後に来るようにする。要素の間が120pxを超えたら配置かサイズを見直す
- 図の高さは、出典の行があれば600px前後、なければ650px前後を目安にする。図を描いてから下が空いたら、図の高さ・箱の高さ・行の高さを広げて埋める。図を上に寄せたまま下に空白を残さない
- 主役は大きく。大きな数字は240〜300px、主役のイラストは高さ480px以上、図は幅1440pxいっぱいを目安に
- 2カラムは左右の幅を使い切り、間に空白の帯を作らない
- 補足の図や注記は主役のすぐ下か横に置き、画面の下端に孤立させない
- 仕上げに全スライドを縮小して見て、余白が中身より目立つページを作り直す

## 強調の手法

**太線マーカー**：キーワードの下半分に太い黄色の線を敷く。1スライドに1〜2か所。CSSなら`background: linear-gradient(180deg, transparent 52%, #F9DC72 52%)`。マーカーを引く語は、リード文の2行目として独立した段落にし、中央に置く。同じ行の中で普通の文と横に並べない（書き出すと境目がずれる）

**アクセントのラウンド箱（ピル）**：短い語を白抜き文字で、角丸の強いアクセントの箱に入れる。角丸は高さの半分、全角10字まで。組み方は「書き出しやすい構成」のピルの項に従う。カード上端の「point 1」、図のノード、強調したい短い条件、段階名に使う

マーカーとピルは合わせて1スライド3つまで（ポイントカードや図のノードとして使うピルは除く）。

## 線の太さ

図形を囲む線が細いと弱く、AIが作ったように見える。箱・カード・列の枠、番号の円、ハブ図の円は6〜9px（5〜7pt）。矢印は5〜6pxで矢じりを大きく。1〜3pxの細い線は、表の罫線とタイトル下のヘアラインだけに使う。

## 要点を複数並べるとき

「・」の箇条書きは使わず、番号を円で囲んだリストにする。目次、課題、選ばれる理由など、2〜5個並ぶときはすべてこの形。

- 番号：直径120pxの円、線6pxのアクセント、塗りなし。中に「01」「02」を太字36px、アクセント色。必ず2桁
- 本文：円の右に80px空け、44px/700。各項目1行、全角28字まで
- 項目の間は48〜64px。リスト全体をひとかたまりとして中央に置き、文字の頭は左揃え
- 項目は問いかけや「」を使った具体的な一文にする。単語だけを並べない

## 図解（言葉より図で伝える）

箇条書きにする前に、図にできないかを考える。資料の半分以上のスライドに図解を入れる。図は1枚に1つまで。2つ目の図が要るときはページを分ける。図の横に小さな補助の図を添えたり、図の中に別の図を入れ子にしたりしない（アイコンは図に数えない）。

1. **アイコン付きの工程フロー**（手順・工程の第一候補）：工程を3〜5個横に並べ、「段階色」で左から右へ濃くする。各工程に工程名（全角6字まで）、アイコン（140〜180px）、説明は30px以上で1行まで（なくてよい）
2. **業務フロー図**：白い角丸箱（角丸24px、太枠）を順に並べ、太い矢印でつなぐ。箱の中に作業名と、使うツールのロゴ
3. **ハブ図**：中央にイラスト、周りにピルで領域を円形に置き、淡いアクセントの矢印を中央へ。主役の領域の縦8割以上を使う
4. **ピラミッド（段階）**：段階的に何かを表すときはこの図を使う。三角形を水平に3〜5段に切り、段の間に白い細い隙間を空ける。色は上ほど濃く下ほど淡い段階色。各段の右端から丸い点付きの水平な引き出し線（#A3A5A8、太さ4px）を右へ伸ばし、その先に段階名（36px/700）を1行で置く。段階名の下に灰色の説明を足さず、名前だけで伝わらないときは「AIが売上の柱」のように段階名を一文にする。文字を三角形の上に重ねない
5. **比較図**：「今のやり方」と「導入後」を左右に並べ、導入後の見出しだけアクセント
6. **比較表**：列はサービス、行は比較項目。左端に分類の列を置き、同じ分類の行をまとめる。セルは「○」「△」「×」と短い理由。見出し行は他社列をグレー地、自社列をアクセント地に白文字。セルは自社列だけアクセントの地、ほかは淡い面（#F5F5F3）。罫線は引かず白い細い隙間で区切る（背景が白なので、セルを白にすると区切りが見えなくなる）。他社名は頭文字で伏せるのを基本にする
7. **ポイントカード**：白い角丸カード3〜4枚。カードの上端から40px前後の余白を取って「point 1」のピルを置き、ピルを枠線に貼りつけない。中にイラスト、見出し（全角8字まで）、説明は本文の色で1行まで
8. **タイムライン**：段階名を横に並べ、下にイラストと一文
9. **大きな数字**：数字だけを大きく、単位を小さく、数字の下半分に太い黄色マーカー（数字の高さの3分の1ほど）を重ねる。組み方は「書き出しやすい構成」の図ごとの組み方に従う。何の数字かと時点を、数字の下に本文の色で1行添える
10. **マトリクス**：2軸で位置づけを見せるときはこの図を使う。淡いグレー（#EEEEEC）の角丸の象限を4つ並べ、その間を両端矢印の十字（#A3A5A8、太さ5px）で区切る。軸名は矢印の4つの端の外側に置く。注目させたい位置にハイライト色の星を1つだけ置き、象限の中には象限名を入れる（説明は要るときだけ本文の色で1行）
11. **ベン図**：集合の重なりは、半透明の円を2〜3個重ねて、重なったところが濃く見えるようにする。全体と部分の関係は、大きな淡い円の中に濃い小さな円を置く。円の色は段階色から選び、枠線は付けない。集合名は色の丸を添えた凡例にして図の下に置き、円の上に文字を重ねない

12. **ロジックツリー**：課題や目標を分解するときに使う。左端に問いをアクセントの箱で置き、右へ2〜4本ずつ枝分かれさせる。階層は3段まで。同じ段の箱は幅と高さをそろえ、白地に6pxの枠、文字は箱の中に流し込む。枝は直角の線（#A3A5A8、太さ5px）を1枚のSVGにまとめて描く。線は10本を超えやすく、x-connectorで引くと1つの土台に置ける24個を超える。同じ段の項目は、重なりも漏れもない分け方にする
13. **マインドマップ**：1つのテーマから考えを広げるときに使う。中央にテーマをアクセントのピルで置き、周りに4〜6本の枝を出し、枝の先に短い語のピル（白地に枠）を置く。階層は2段まで。枝は直線のx-connector
14. **サイクル図**：繰り返す流れ（改善の回し方、月次の業務など）を見せるときに使う。3〜5個の円（直径140px前後、線6px）を円周上に等間隔で置き、時計回りの矢印でつなぐ。円の中は番号、工程名は円の外のpに置き、輪の中央に流れ全体の名前を置く。円は中に番号を入れるので、x-shapeではなく角丸を半径にしたdivで作る
15. **フィッシュボーン図**：結果に効いている原因を洗い出すときに使う。右端に結果をアクセントの箱で置き、左へ太い背骨（6px）を引き、上下に斜めの骨を4〜6本出す。骨の先に原因の分類名（ヒト・モノ・方法・環境など）を置き、分類の下に具体的な原因を短い語で2〜3個並べる。線はすべてx-connector
16. **スイムレーン図**：担当ごとの役割と受け渡しを見せるときに使う。担当ごとに横長のレーンを積み、すべて淡い面（#EEEEEC）にして、レーンの間を白い隙間（6px）で区切る（白と交互にすると、白い背景に溶けて境目が消える）。左端の列にレーン名を置く。作業は白い角丸箱でレーンの中に置き、太い矢印でつなぐ。自社や読み手のレーンは、レーン名の欄だけをアクセントの地に白文字にする（面の色を変えても淡い色どうしで見分けがつかない）
17. **ファネル図**：段階を進むほど数が減る流れ（問い合わせから契約まで、など）を見せるときに使う。下ほど幅の狭い帯を4〜5段、中央そろえで積み、段階色で下ほど濃くする。帯はdivで作り、段階名と数字は帯の中に流し込む。段と段のあいだの移行率は右側に添える。数字は渡されたものだけを使う
18. **カスタマージャーニーマップ**：顧客の体験を段階ごとに見せるときに使う。列に段階（認知・比較・検討・契約・利用など）、行に「行動」「接点」「気持ち」「打ち手」を置き、比較表と同じ組み方でセルを淡い面にし、白い隙間で区切る。セルの文は全角7字まで。気持ちの行は高低を点と線で見せ、点の上に「期待」「迷い」「不安」のような気持ちを短い語で添える（点だけでは上が良いのか読み取れない）。段階名の上に小さな番号やラベルを乗せない
19. **ガントチャート**：期間の重なる作業の予定を見せるときに使う。左端の列に作業名、上に期間の目盛り（月か週）を置き、作業ごとに角丸の横棒（divで、段階色かアクセント）を引く。月や週の名前は列の左端にそろえ、境目に淡い縦線（#E6E4DE、2px）を引く（名前を列の中央に置くと、棒や今日の線がどの月にあるか読み違える）。今日や締め切りの位置には縦の線（x-connector、ハイライト色）を1本だけ引き、線の下に日付を添える。棒の色の意味（終わった・進めている・これから）は凡例で示す
20. **同心円図**：中心から外へ広がる範囲（TAM・SAM・SOMの市場規模など）を見せるときに使う。大きい円から順に小さい円を、下端をそろえて重ねる（x-shape、外側ほど淡い段階色、枠なし）。中心をそろえると円どうしの帯が細くなり、引き出し線の始点を離して置けない。各円の名前と数字は、ピラミッドと同じく各円の上のほうから右へ引き出し線を伸ばした先に、名前と数字の2行に分けて置く（横に並べると折り返して崩れる）。引き出し線の間は120px以上空ける。円の上に文字を重ねない
21. **ツリーマップ**：全体の中の内訳を面積で見せるときに使う。長方形を値の大きさに比例した面積で区切り、大きい順に左上から並べる。区画はgridかflexのdivで作り、色は段階色。区画の中に名前と割合を流し込み、小さすぎて入らない区画は外に凡例で添える

### 図の選び方

何を見せたいかで型を選ぶ。迷ったら、読み手が最初に知りたいことを一文で書き、それに答えられる型にする。

| 見せたいこと | 図 |

### アイコン

- 2トーンの太線アイコンをSVGで描く。viewBox 0 0 160 160、線幅6px、角と端は丸める。外形は#3C3C3C、内側は白塗り、細部だけアクセント色。白塗りがあるので、濃い色の上でも沈まない
- モチーフはその資料の題材にある実際の物（書類、PC、カレンダー、吹き出し、箱、道具など）。一つのアイコンに描く物は1つ。資料内の全アイコンで線幅と色を統一する
- 絵文字、影、グラデは使わない。アイコンは「物」、イラストは「人と場面」と使い分ける

## イラストと写真

- イラストを使えるかは、作り始める前に決める。画像を生成する手段（Canvaのコネクタなど）があるか、ユーザーから絵を渡されたときは使える。どちらもなければ、下の「イラストを使えないとき」の組み方で最初から作る
- イラストを使えるときは多用する。表紙・目次・章扉には必ず入れ、本文でも図解のないスライドには大きなイラストを主役として置く
- テイストは、斜め上から見たアイソメトリックのフラットなビジネスイラスト。スーツ姿の人物、オフィスの机、PC、グラフ、書類、ビルなどを、紺・グレー・淡い青・黄色を中心にした配色で描いたもの。資料の中でこのテイストを統一し、写真や別の画風を混ぜない
- 画像生成を使うときは、プロンプトの型をそろえて主題だけ入れ替える（「Isometric flat business illustration on a plain white background:［主題。人物はnavy suit］. Clean flat vector style with soft shading, palette of navy, gray, light blue and yellow accents, no text, no logo.」）。一枚に描く場面は1つ。生成した絵は、白い背景を透過して資料の背景になじませる
- 画像の解像度：資料に置く画像は、スライド上の表示サイズの1.5倍以上の画素数がある原寸を使う（480px角で置くなら720px以上）。生成ツールのプレビューや縮小版（200px角など）を拡大して使わない。拡大した画像は、人の目にはすぐぼやけて見える
- Canvaの生成画像の原寸：get-generate-image-jobやget-assetsが返すのは200px角のプレビューとメディアIDだけで、原寸は正方形なら2048px角ある。原寸は、画像をCanvaのデザインに置いてPNGで書き出して受け取る。ユーザーに画像を保存してもらったり、ブラウザでダウンロードしたりはしない
  1. 作業用のデザインを1つ用意する。最初の画像のメディアIDをseparate-image-layersに渡すと、2048px角のデザインができる。題は「natural-slides画像書き出し用」にする。1ページ目はレイヤーに分解されて継ぎ目が出るので使わない。資料1本のあいだは同じデザインを使い回す
  2. read-designをopen_transactionで開き、画像1枚につき1ページをedit-designのadd_pageで足す（幅・高さ2048、白地）。足したページにinsert_fillで元の画像を置く（top 0、left 0、幅・高さ2048）。縦長・横長の画像は、ページの寸法を画像の比率に合わせる
  3. 全部の画像を置いてから、1回だけcommitで保存する。作業用のデザインは画像を取り出すためだけに自分で作るものなので、作るときも保存するときもユーザーに断らず、確認も求めない。仕上げの報告で、Canvaに「natural-slides画像書き出し用」が残っていて、要らなければ消してよいと一行添える
  4. export-designで、足したページだけをPNG（width 2048）で書き出す。透過の指定は効かないので付けない。返ってきたexport-download.canva.comのURLは数時間で切れるので、すぐ作業環境に取り込む
  5. 取り込んだ画像は、画素数を確かめてから表示サイズの1.5倍以上（1200px角程度）に縮小し、端からつながる白を透過して資料に入れる
  6. 作業環境からexport-download.canva.comにつながらないときは、claude.aiの設定で、コード実行がつながってよいドメインにexport-download.canva.comを足してもらう。一度足せば次からは聞かない。足せない環境では、イラストを使えないときの組み方に切り替える
- 拡大したプレビューを仕上がりとして出さない。仕上げに使う画像はすべて、画素数を確かめてから資料に入れる。最後まで原寸が手に入らなかった画像は使わず、そのスライドは「イラストを使えないとき」の組み方に替える
- 引用する素材は、商用可でクレジット条件を満たせるものだけ。出典と利用条件を報告する
- SVGで人物を描いて代用しない。イラストを用意できないときに、空の枠や「ここに絵」の置き場を残さない
- 光る球、ロボット、回路、握手のストック写真、抽象的な3Dは使わない
- 大きいイラストは1スライド1点、小さいイラストは同じ大きさで揃える。枠や影を付けない
- 人物写真は、本人から渡されたものだけを使う。正方形か円に切り抜き、顔が切れないようにして、近くに役職と氏名を添える。複数人は同じサイズに揃える

### イラストを使えないとき

イラストが欠けた資料ではなく、はじめから絵のいらない資料として組む。主役は図解と大きな数字にし、絵の代わりの空きを作らない。報告でも、イラストがないことを足りないものとして扱わず、要る絵の一覧も出さない。

- 本文は、イラストを主役にする予定だったスライドから先に、図にできないかを考える。工程ならアイコン付きの工程フロー、比べるなら比較図、段階ならピラミッド
- 表紙：タイトルを64〜80px/900で置き、メインカラーの面を画面の左3分の1か下3分の1に敷く。面の上には約束の一文かサービス名を白抜きで置く。ロゴは右上のまま
- 目次：円で囲んだ番号のリストで組む。イラストを添えず、リストを主役の領域いっぱいに広げる
- 章扉：章番号を240〜300px/900のアクセント色で大きく置き、横に章タイトル（44px/700）と、その章で言い切る一文を並べる
- 図解のない本文：題材の物を描いた大きなアイコン（「アイコン」の節の描き方で240〜320px）を1つ主役に置くか、言い切る一文を56〜64px/900で大きく置き、要の語に黄色のマーカーを引く
- 図の中のイラストはアイコンに替える。ハブ図の中央は直径320px前後のアクセントの円に大きなアイコン、ポイントカードとタイムラインはイラストの位置に同じ大きさのアイコンを置く
- 絵がない分、余白が余りやすい。主役の領域の8割を埋める決まりはそのまま守り、図・数字・アイコンを大きくして埋める

## 数字とグラフ

- 数字や実績を新たに作らない。渡されていない数字は[00]のような空欄にし、報告で一覧にする
- 人の言葉を引用するときは原文どおりにし、言い換えには「」を付けない
- 数字には「何の数字か」「いつ時点か」「何との比較か」を添える
- グラフは渡された画像かデータをそのまま使う。画像から値を読み取って描き直したり、推測したりしない
- 見出しの数字とグラフの値が食い違っていたら、直さずに報告する

### データのグラフ

グラフは、データを渡されたときだけ描く。値を推測したり、見た目のために作ったりしない。どのグラフも、軸の名前と単位、時点を本文の色で添える。強調する系列や項目だけをアクセントにし、ほかは淡いグレー（#D9D9D9）にする。線は太め（折れ線は4〜6px）にし、目盛り線は引かないか最小限にする。

| 見せたいこと | グラフ | 組み方 |
|---|---|---|
| 2つの量の関係 | 散布図 | 点は直径16〜24pxのx-shapeの円。ほかの点は淡いアクセント（#BCBDBD。#D9D9D9では白い背景に消える）、注目する点だけアクセントにして名前を添える。点と軸と目盛りの数字で土台の24個に近づくので、点が15個を超えるときは点をSVG1枚で描く |
| 3つの量の関係 | バブルチャート | 散布図の円の面積を3つ目の量に比例させる。円は半透明にして重なりを見せる |
| 項目×項目の強弱 | ヒートマップ | 格子のセルをgridのdivで作り、値の大きさを5段で塗る（図の淡い面#EEEEECと段階色の4色）。値の数字はセルの中に24px以上で入れ、凡例を添える |
| 複数の観点での比較 | レーダーチャート | 軸は5〜8本。多角形はSVGで描き、比べる系列は2つまで。強調する系列はアクセントの線（5px）に淡い塗り、比べる系列は#A0A1A2の破線にする（#D9D9D9だと目盛りの線と見分けがつかない）。目盛りの線は外周と中間の2本だけ、#EEEEEC、2px。軸名はSVGの外のpで周りに置く |
| 目標に対する達成度 | ゲージチャート | 半円の弧をSVGで描き、達成した分だけアクセントで塗る。達成率は弧の下に大きな数字で置き、目標値を添える |
| 量と率を一緒に | 複合グラフ（棒＋折れ線） | 棒はdiv、折れ線はSVGのpolyline。左右の軸それぞれに単位を書く。折れ線は、いちばん高い棒の値より上の帯に収まるよう右の軸の範囲を決める（棒と重なると、棒の値と折れ線の値がぶつかる） |
| 「何人に1人」 | 絵グラフ（ピクトグラム） | 人型のアイコンを10個並べ、該当する数だけアクセント、残りを淡いグレーにする。横に大きな数字を置く |
| 割合の比較 | 帯グラフ（100%積み上げ） | 横棒をdivで割合ごとに区切り、各区画の中に割合、区画の上に名前を入れる。強調する区画だけアクセント。1本だけだと主役の領域の下半分が空くので、前年と今年、部署別など2〜4本を縦に並べて比べる。データが1本分しかないときは、帯の高さを240px以上にし、帯の下に強調する区画の意味を一文で添える |
| 推移 | 棒グラフ、折れ線グラフ | 棒は角を丸めず、値は棒の上か右に太字で置く |

## 書き出しやすい構成（PowerPoint・Canva・Googleスライド）

スライド型のアーティファクトで作り、PowerPoint（.pptx）やPDFで書き出す。Googleスライドへは共有メニューの「送信先」から送る。Canvaは送信先に出てこないので、.pptxを「現在のフォント」で書き出し、Canvaのホームの「アップロード」から取り込む。書き出すたびに新しいファイルができるので、直したあとは書き出し直し、古いものは消すよう伝える。どこへ持っていっても文字と図形を直せるよう、HTML/CSSを次の構成で書く。

**ファイルの分け方**
- 見た目はdeck.cssにクラスで書き、スライドのファイルは1枚に`<section>` 1つ。インラインstyleは位置と大きさの微調整にだけ使う
- 色はクラスに持たせる（.bar .pill .st1〜.st4 .quadなど）。メインカラーを変えるときはdeck.cssの値だけを置き換える
- deck.cssの先頭に、この構成の約束をコメントで書いておく

**何で描くか**
- 文字：h1〜h3とpだけ。SVGの`<text>`と、::before / ::afterに書いた文字は使わない（書き出すと消えるか、直せなくなる）。ページ番号のカウンターだけは例外
- 四角・角丸の箱、象限、色の帯：塗りと枠を付けたdiv。書き出すとそのまま図形になる
- 円：中に文字を入れない円は`<x-shape kind="ellipse">`。重なりはopacityで出す。番号の円やサイクル図の円のように中に文字を入れる円は、角丸を半径にしたdiv（x-shapeは中に文字を持てない）
- 軸・矢印・引き出し線：`<x-connector>`（両端矢印はhead="both"）。並びの中の矢印は`<x-shape kind="arrow-right">`か小さな山形のSVG
- 汎用のアイコン：`<x-icon>`で足りるものはx-icon（ハイライトの星はStarを#E5B521で）。題材専用のアイコンだけSVGで描く
- SVG：ピラミッドの段、矢羽、専用アイコンなど、図形で描けない形だけに使う。SVGは画像として書き出され、後から色を変えられない。文字は必ずSVGの外のpに置く
- イラスト・写真：透過PNGのimg。url()の背景画像にしない

**組み方**
- flexとgridで組む。float、z-index、inline-blockの横並び、clip-pathは書き出しで消えるので使わない
- 座標（position:absolute）で置くのは、骨組み（バー、タイトル、ロゴ、ヘアライン、ページ番号）と、図の中の円・線だけ。図の中で座標を使うときはposition:relativeの土台を置き、1つの土台に置く要素は24個まで
- 1枚の要素は200個まで、divの入れ子は15段まで
- 線が多い図（ロジックツリーの枝など）は、線だけを1枚のSVGにまとめて土台の先頭に置き、箱をその上に並べる。x-connectorを1本ずつ置くと土台の24個をすぐ超える
- 図形の上に文字を座標で重ねない。箱の中の文字はその箱の中に流し込む
- 文字の入る箱は1割ほど余裕を持たせる

**強調**
- マーカー：リード文を2行に分け、1行目は普通のp、マーカーを引く語は2行目の独立したpにして（.lead-2と.mk-line）、`linear-gradient(180deg, transparent 52%, #F9DC72 52%)`を当てる。文の途中のspanに背景を付けない（書き出すと消える）
- ピル（角丸の強い箱に文字を入れたもの）：pに背景とpaddingを付けて作らない。書き出すと箱と文字が別々になり、文字が箱の左上に寄る。塗りと角丸を付けたdivを箱にして幅と高さを決め、display:flex・align-items:center・justify-content:centerで中のpを上下左右の中央に置く。pはline-height:1、text-align:center、折り返さない（.pillと.pill-t。白地に枠だけのピルは.pill-oを足す）
- ピルの寸法：幅は「文字数（全角＝1、半角＝0.6）×文字サイズ×1.15＋左右44pxずつ」、高さは「文字サイズ＋36px」（枠付きは＋40px）を目安に、1つずつ文字に合わせて決める。並べるピルは高さをそろえる

**ズレやすいところ**

書き出すと、文字の塊が1つずつ別のテキストボックスになる。書体が置き換わると幅が変わるので、次の組み方は避ける。
- 1行の文を、色や強調の違う複数のpに分けて横に並べる。境目で重なるか、すき間が空く
- 見出しの途中にピルを挟む。ピルはタイトルの上に1行で置く
- 背景とpaddingを付けたpをピルや箱にする。文字が左上に寄るので、幅と高さを決めたdivの中央にpを置く
- white-space:nowrapで長い文を1行に固定する。長い文は幅を1割多めに決めた箱に入れ、改行はbrで自分で決める。nowrapを使うのはピル、価格、短い語だけ
- 大きな数字と単位を詰めて並べる。別のpにしてよいが、間を16px以上空ける
- ラベルと値を1つの箱に横に並べ、justify-content:space-betweenで両端に寄せる。中身が箱の内側より広いと、はみ出した分が片側の余白だけを食い、左右の余白がそろわない。箱の幅は、中の文字の幅（全角＝文字サイズ、半角＝文字サイズの0.6倍）と間の幅を足し、そこに左右の余白と1割の余裕を足して決める。中身はjustify-content:centerで箱の中央に置く。両端に寄せてよいのは、ラベルと値の行が縦に複数並び、値の右端をそろえたい表のときだけ
- 大きな数字に、文字の背景のグラデーションでマーカーを引く。Googleスライドでは下からにじむ帯になる。黄色の長方形を数字の後ろに重ねる（「図ごとの組み方」）
- ピラミッドの段階名を図の高さに合わせて座標で置く。行の高さを段の高さに固定した列に入れ、文字量が変わっても位置が動かないようにする
- 図の上に文字を座標で置く。円や線は土台の中で座標で置いてよいが、文字は土台の外に流す

**図ごとの組み方**
- ピラミッド：段と引き出し線を1枚のSVGに描き、段階名と説明は右の列にpで並べる。列の1行の高さを段の高さにそろえる
- マトリクス：position:relativeの土台に、4つの象限をgridのdivで置く。十字の軸はx-connector 2本（両端矢印、#A3A5A8、太さ5px）。軸名は土台の外のp、星はx-icon
- ベン図：position:relativeの土台にx-shapeの円を2〜3個、opacity 0.55〜0.75で重ねる。凡例は小さな丸のdivとp
- 工程フロー：工程の箱をflexで並べ、間に矢印を置く
- 大きな数字のマーカー：数字の文字に背景のグラデーションで引かない。Googleスライドに書き出すと、下からにじむ薄い帯に変わる。黄色（#F9DC72）の長方形のdivを数字の後ろに重ねる。縦に並べる列（display:flex、flex-direction:column）の中で、長方形を数字の行より先に書き、数字の行に負のmargin-topを付けて長方形の上に重ねる。後から書いた要素が上に描かれるので、数字は長方形の上に出る。position:absoluteで重ねると、スライドの表示では長方形が数字の上に描かれて数字が隠れるので使わない
  - 寸法：長方形の高さは数字の文字サイズの3分の1ほど（280pxの数字なら90px）、幅は数字と単位を合わせた幅より左右に20〜30pxずつ広く。数字の行の高さをH、長方形の高さをh、列のgapをg、長方形の下端を数字の行の下端からdだけ上げるとき、数字の行のmargin-topは −(g＋H−d)、列のpadding-topはH−h−dにする（H=280、h=90、g=16、d=30ならmargin-top −266px、padding-top 160px）
  - 例：`<div class="big"><div class="big-mk"></div><div class="big-row"><p class="big-num">0</p><p class="big-unit">円</p></div><p class="big-cap">…</p></div>`に、`.big{display:flex;flex-direction:column;align-items:center;gap:16px;padding-top:160px}` `.big-mk{width:340px;height:90px;flex:none;background:#F9DC72}` `.big-row{display:flex;align-items:flex-end;gap:20px;margin-top:-266px}`

**書き出し先ごとの注意**
- PDF：見た目がそのまま残る。見せるだけならPDFを案内する
- PowerPoint：MontserratとNoto Sans JPが入っていない環境では書体が置き換わり、文字幅が変わる。配る相手にはPDFも添える
- Canva・Googleスライド：書き出した後に開き、マーカーのグラデーションが崩れていたら単色の黄地に替える。大きな数字のマーカーは、はじめから「図ごとの組み方」の長方形で作る
- どの書き出し先でも、1枚ずつ開いて文字のはみ出しと改行位置を確かめる

## 改行

- 文や語の途中で行が変わる状態を残さない（悪い例：「ほとん／どない」「スタートアッ／プ向け」）
- 2行になる文は、句読点か意味の切れ目に改行を入れて、改行位置を自分で決める
- 箱に入れる文は、1行に入る文字数（内側の幅÷文字サイズ。英数字は0.6文字）を先に数え、入らなければ改行・箱を広げる・文を短くする
- 社名・サービス名・カタカナ語・数字と単位は2行に割らない
- 1行に収まる長さのもの（「¥4,536（税込）」のような価格、数字と単位、短い見出し、商品名、ピルの中の語）を2行に折らない。並べたときの幅を先に数え、箱に入らなければ文字を小さくするか箱を広げる。それでも入らないときだけ、意味の切れ目で改行する
- 行の途中で文字の大きさを変えない（書き出すと大きさが消え、1行に入らなくなる）。「（税込）」「〜」のように小さく添える語は同じ行の中に入れず、別のpにして横に並べ、折り返さないようにする

## コピー

- スライドに載せる文は、です・ます調にしない。言い切り（〜する／〜できる／〜している）か体言止めで終え、体言止めばかり続かないように混ぜる。引用は原文のまま、スピーカーノートは話し言葉でよい
- 日本語の文の中で、英字・数字の単語の前後に半角スペースを入れない（「Claude␣のスキル」ではなく「Claudeのスキル」、「月額␣25␣万円」ではなく「月額25万円」。␣は半角スペース）。英単語どうしの間（Claude Code）、URLの直後、コードの中は除く。スライドの文、スピーカーノート、報告のすべてに当てはめる
  - 悪い例：「設計から運用まで引き受けるサービスです」「2.4ヶ月で回収できています」
  - 良い例：「設計から運用まで引き受けるサービス」「2.4ヶ月で回収できている」
- 「シームレス」「加速」「革新的」「DX推進で業務効率化」のような中身のない言い回しを避け、何を・誰の代わりに・どこまでやるかを書く
- 感嘆符は表紙のキャッチに限る。見出しと本文には使わない

## テンプレートを作るとき

- テキストは「ページタイトル」「ここにリード文が入ります」のような、何が入るかわかるダミー文にする。実在の社名・人名・数字は入れない
- 数字は「00」「00.0%」、連絡先はsample@example.comとhttps://example.com/
- 画像は淡いグレー（#EDEBE6）の地に画像マークを描いたダミー、人物の枠は人型のダミー、アイコンは汎用のダミーにする。イラストを多用する前提で、表紙・目次・章扉・本文にダミー画像の枠を大きく取っておく
- 各スライドのノート欄に、その型の使い方とダミーを何に差し替えるかを書く

## やらないこと

- タイトルに「、」「。」を入れた長い主張文
- 文字を画面の左端や枠線に寄せること
- アイコン付きの均等3カラムに説明文を並べるだけのスライド
- 「・」の箇条書きで要点を並べること
- 文字だけの図、細い枠線
- 見出しの下に灰色の小さな説明を並べること、見出しの上に小さなラベルを乗せること、スライドに断り書きを書くこと
- グラデ背景、影、グロー、絵文字、自作のSVG人物
- 小さな要素が中央に固まり、まわりががらんとしたページ
- 会社名を入れ替えても成り立つ言い回し。仕上げに「これはこの会社にしか言えないか」を確かめる
