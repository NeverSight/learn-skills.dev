# Phaser 4 记录与中间产物清理

## 全局控制接入

以 [`phaser4-game-workflow-control`](../phaser4-game-workflow-control/SKILL.md) 为唯一任务范围、风险门和状态权威。本 Skill 在当前 Work Item 范围内提出清理提议、审查引用与风险，提交清理清单、执行结果和验证证据，再回到控制面审计与状态迁移；不建立第二套状态机，不直接修改审批账本或手写状态以解除引用。

用户要求清理时，可在指定范围内盘点并处理已确认可再生成的本地产物，不重复请求普通本地操作批准。阶段收尾只处理本任务产生的临时文件；历史记录、其他任务和共享目录不因收尾而自动纳入。发现范围外候选时仅报告。不可恢复的数据删除、外部删除等带副作用的 A4-A6 操作按控制面逐对象批准，授权只覆盖批准清单和对应内容身份。

## 判定边界

“过期”需要项目保留策略、用户指定期限或已被新版本替代的事实；修改时间早不等于过期。“未使用”需要完整引用检查和明确归属；文本搜索零匹配不等于无引用。任务完成、证据已失效、文件被 Git 忽略、文件未跟踪或内容重复，都不能单独作为删除依据。

| 文件类别 | 默认处理 |
| --- | --- |
| `.workflow-control/work-items/`、审批账本、状态迁移/返工记录 | 保留；终态也不自动删除，历史记录支撑追踪和审计 |
| 实施包、`evidence/<workItemId>/execution-state.json`、Result、验证清单、路径与 SHA 绑定文件 | 保留有效引用和审计链；失效不等于可删 |
| V2 拆解与布局确认、V3 正式资源/生产记录、V4 草图/确认、V5 运行证据 | 保留完整依赖闭包，包括原图、JSON、审阅页、截图及宿主上下文 |
| 明确属于本任务的临时日志、临时导出、失败候选、重复预览、可再生成构建或缓存 | 证明无引用、无运行占用且可再生成后，纳入清理清单 |
| 源码、正式资源、源素材/视频、用户交付物、锁文件、测试夹具、发布产物 | 默认保留；不是一般中间产物 |

原视频可能用于重新抽帧，去背景原图可能支撑生产记录与质量复核，`review.html` 可能参与 SHA 硬门。不要按扩展名、目录名含 `output`/`temp`，或体积大小批量判断。已有产物目录规范见[游戏项目目录规范](../phaser4-game-architecture/references/project-structure.md)，证据语义见[控制模型](../phaser4-game-workflow-control/references/control-model.md)。

## 清理流程

1. **限定范围**：读取当前任务、Work Item、允许路径和现有保留策略。确认仓库绝对根路径，记录 Git 已有修改及暂存内容；识别并行任务和正在写入产物的进程。没有既定保留期限时，不自行发明“超过 N 天删除”的策略，先处理能证明无用且可再生成的文件。
2. **建立保留集合**：从所有仍保留的 Work Item、实施包、审批/返工记录、证据清单、资源清单、加载入口、构建/测试配置和交付清单追踪路径与 SHA；递归保留其依赖，不只检查当前 Work Item。引用解析覆盖相对路径基准、动态加载、目录扫描、HTML/CSS/JSON 内嵌引用和软链接。无法确认的动态引用或引用记录无法读取时保留对应候选，不猜测安全性。
3. **列出候选**：逐文件记录项目相对路径、解析后的绝对路径、类别、所属任务、大小、SHA-256、过期/未使用依据、引用检查范围、再生成命令与输入、建议动作和保留原因。缺少可用输入、工具或可执行再生成途径时，不标记“可再生成”。内容相同只用于识别重复候选，不自动合并路径或更新引用。
4. **执行前复核**：核对清单与任务允许路径，运行控制面 `check`，并按实际动作执行 `preflight`。将需批准的对象和影响先提交精确 pending；普通本地可再生成候选在已授权范围内直接执行。删除前重新检查 SHA、引用和写入占用；清单生成后内容或依赖发生变化时跳过该对象并重新判定，不沿用旧批准。
5. **逐对象清理**：只操作已复核清单中的具体文件，不递归删除整个记录目录，不执行 `git clean`、`git reset` 或批量历史清理。未知所有权、他人改动、仍活跃工作项、写入中的文件和再生成所需输入一律保留。遇到失败记录实际结果，停止依赖该失败的后续动作，继续无依赖对象；不扩大通配符范围或自动提权重试。
6. **验证与收尾**：先推荐 T0-T3 等级、理由、覆盖与命令，再自动执行适用检查。复查所有保留记录及引用文件存在、SHA 不变，运行控制面 `check`；涉及资源或构建产物时运行受影响资源检查/构建，启动服务前复用同项目健康实例。文件删除成功不代表证据门通过，验证失败先修复并复验，报告无法恢复项，不手写状态绕过门。

## 路径与恢复

- 删除前解析最终绝对路径，确认位于项目根与允许清理目录内；拒绝根目录本身、`..` 越界、指向范围外的软链接/junction/reparse point，以及经此类目录转向范围外的子文件。Windows 下按实际文件系统大小写规则判断路径边界，不能只用字符串前缀判断。
- Windows 文件操作全程使用 PowerShell 7 与 `-LiteralPath`；不要把 PowerShell 枚举结果拼接到 `cmd /c` 或另一 shell 删除。优先逐文件 `Remove-Item -LiteralPath <已复核绝对路径>`，不把示例占位路径当作可执行清单。
- 可恢复操作优先使用项目已有的回收/隔离方式；只有在明确允许的项目内目录中才移动，且核对移动目标不会覆盖文件。报告隔离占用空间，不把移动伪称为释放空间；隔离目录继续受到保留规则约束，不能无限增长。
- 删除 Git 跟踪文件前确认其可从当前提交恢复且没有未提交内容；恢复只针对本任务精确路径，不覆盖他人修改。未跟踪且不可再生成的记录若没有恢复副本，按不可恢复删除处理，不以“未跟踪”为授权。

## 结果报告

优先复用当前 Work Item 的结果/证据位置或直接在最终回复报告，不为每次清理创建长期独立日志、备份与报告副本。报告本身若属于验收证据则加入保留集合。

- 清理范围、保留策略及引用检查覆盖；
- 实际删除、隔离、保留、失败和跳过的精确文件与理由；
- 实际删除字节数、隔离字节数及恢复/再生成方法；
- 执行的测试等级、命令、结果与未验证项；
- 控制面复核结果、剩余不确定性和需用户决定的范围外项。

只盘点时明确说明未执行删除；没有可靠字节统计时不宣称释放空间。清理不改变原任务的阶段或证据有效性，最终交回控制面并按既有收尾规则提交本任务差异。
