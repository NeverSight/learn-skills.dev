# Roblox 游戏界面

让界面在目标设备上可读、可操作，并与服务器权威状态一致。开始前读取玩家流程、DataModel 结构、资源登记，以及[Studio 插件路由](../roblox-development-workflow/references/studio-plugin-routing.md)和[控制模型](../roblox-game-workflow-control/references/control-model.md)。

所有可见 UI 工作项均按[响应式 UI 合同](../roblox-development-workflow/references/responsive-ui-contract.md)维护 `visualContractRef`；需要视觉基线和人工画面验收时同时遵守[视觉工作流](../roblox-development-workflow/references/visual-workflow.md)。合同记录实际安全区、视口、语言、输入和语义节点关系，不能以截图或一处尺寸推断全平台适配。

## 职责与输入

- 先检查 StarterGui、ScreenGui、已有 UI 模块、输入动作、文本本地化和设计规格；复用现有组件。
- 把纯表现和输入采集放在客户端；涉及物品、购买、奖励、设置服务器状态的动作必须通过 Remote 请求并由服务器验证。
- 单独定义 HUD 与模态层的打开、关闭、焦点、暂停/继续和恢复行为。
- 关键布局路线或玩家可见文案有实质取舍时交由策划；不可访问或缺少授权的资产标记为阻断。
- 布局、输入范围或验收目标确需用户作关键取舍时，由[拷问技能](../roblox-game-grilling/SKILL.md)统一记录，避免把可查询的 Studio 属性转成用户问题。
- 界面触发的权威玩法请求遵守 [玩法开发](../roblox-gameplay-development/SKILL.md) 契约；动画与反馈按 [juice](../roblox-game-juice/SKILL.md) 的生命周期规则收尾。

## 实施步骤

1. 将画面拆为稳定组件，记录层级、锚点、尺寸约束、状态、按钮语义和关闭路径。
2. 针对安全区和系统 UI 避让配置 ScreenGui 布局；关键交互内容放在安全显示区域，背景装饰才可延伸至边缘。
3. 为触控、键盘/鼠标、手柄导航分别定义可达路径、焦点反馈、取消操作和误触容错；只覆盖已批准的平台。
4. 文字通过本地化表和真实运行数据呈现；覆盖长短文本、缺失翻译、字体回退、换行、数字/计时变化和无文本图标的无障碍名称。
5. 客户端展示服务器状态的等待、成功、拒绝、加载和超时状态；不要只依赖颜色传达结果。
6. 打开与关闭界面时保存并恢复焦点、输入模式和被临时遮挡层的状态；Player/Character 变化时重置无效绑定。
7. 用多次打开关闭、快速重复点击、断线/重连和小屏布局路径检查状态泄漏与重复监听。
8. 交接给 QA 的输入和布局场景应按 [QA 与性能](../roblox-game-qa-performance/SKILL.md) 的证据要求记录。

## 交付与验证

- 交付 ScreenGui 路径、组件/状态图、布局约束、本地化键、输入映射、Remote 请求和服务器响应。
- 使用 Studio 插件检查实际实例树和脚本；通过已授权的 Studio 运行流程采集交互证据。
- 性能与兼容结论按实测设备/模拟器记录；单一截图不能证明输入和动态布局通过。
- 若需要视觉确认，提供截图和检查要点，由用户人工检查显示效果；不自动分析截图或替用户判定视觉通过。

不要让本地按钮直接改变权威进度或购买结果。不要把只在一个屏幕尺寸验证的布局描述为全设备适配。

## 交互状态检查

- 主按钮需呈现可用、按下、等待、禁用、成功和失败等必要状态。
- 操作结果要能被屏幕阅读器和非颜色线索理解；图标按钮应有有意义的文本名称。
- 文本输入要定义长度、提交、取消、焦点丢失、软键盘遮挡与不可信内容显示策略。
- 菜单切换和模态层关闭后恢复玩家输入或焦点，不把快捷键误传到游戏世界。
- 手柄操作应能进入每个关键控件并清晰显示当前焦点。
- 玩家离开、重生或界面被销毁时，断开按钮监听与状态订阅，避免重复绑定。
- 动态数字和价格来自服务器状态；购买流程的按钮提示不能替代服务端收据确认。
- 本地化校验使用真实翻译和代表性长文，记录文本截断、换行和布局偏移。
- 新界面需标记其语言键、屏幕方向、输入方式和覆盖层层级，方便 QA 复验。
