# Roblox 玩法开发

玩法实现应让玩家操作产生清楚结果，同时让服务器决定关键规则。开始前读取[Studio 插件路由](../roblox-development-workflow/references/studio-plugin-routing.md)、[控制模型](../roblox-game-workflow-control/references/control-model.md)和架构交付。

## 职责与输入

- 使用 search_game_tree、inspect_instance、script_search、script_grep、script_read 定位现有逻辑，再用 execute_luau 或 multi_edit 按当前工具路由实施。
- 先读玩家流程、验收条件、状态所有者、Remote 契约、数值配置、资源登记和目标 place。
- 服务器拥有伤害、奖励、货币、道具授予、冷却与胜负等关键规则；客户端输入仅是请求或表现提示。
- 重大规则、公开接口、数据格式或资源需求变化先报告架构/策划，不在实施中扩大任务范围。
- 规则或多人关系存在证据无法消除的实质取舍时，交[拷问技能](../roblox-game-grilling/SKILL.md)记录用户决定；闭合后回到本工作项，普通实现细节不重复提问。

## 实施步骤

1. 列出状态、触发事件、前置条件、成功/失败结果和退出路径，再确定服务器与客户端各自承担的部分。
2. 对每个客户端请求，在服务器重新检查玩家身份、类型与大小、权限、当前状态、距离、冷却和速率；非法或过量请求安全拒绝。
3. 将关键结果由服务器计算并广播所需状态；客户端显示结果，不能用客户端传来的奖励金额或命中结论作为事实。
4. 对 Player 和 Character 事件做重复调用安全处理；玩家退出、角色更换、实例销毁时清理连接、计时器和临时状态。
5. 按 Streaming 行为处理临时不可见对象，避免依赖客户端永远持有完整世界副本。
6. 消费已登记的资源和动画接口；反馈事件与资源生命周期交给 [反馈与动效](../roblox-game-juice/SKILL.md)，持久化流程交给 [LiveOps](../roblox-game-live-ops/SKILL.md)。
7. 修改脚本时先读取完整相关代码；使用 multi_edit 的 Edit 操作，首次创建脚本时提供正确 className。

## 交付与验证

- 交付改动的树路径、脚本职责、Remote 输入与服务端校验、状态变化及失败处理。
- 通过脚本读取和代码搜索确认调用链与所有权；需要运行行为时仅用用户授权的 Studio Play 流程。
- 记录控制台错误、未覆盖的多玩家场景、Streaming 假设和数据依赖；证据不足标记 NOT_RUN。
- 给 QA 提供正常流程、无效请求、边界值、退出/重生、重复触发和多人竞争的复现步骤。

不得把 NetworkOwnership、客户端碰撞或本地 UI 当作关键规则的安全保证。不得在超出授权范围时执行 Luau、启动或停止 Play。

## 状态与边界检查

- 为玩家状态、角色临时状态、全局回合状态和持久状态分别确定生命周期与清理责任。
- 对 RemoteEvent/RemoteFunction 分别标明请求与响应；服务端重算关键结果，不接受客户端声明的最终结果。
- 单次调用检查类型、数值范围、字符串长度、实例归属、距离、冷却和当前游戏阶段。
- 对高频请求设置服务器侧节流；拒绝无效消息时避免过量日志造成额外负担。
- 对异步等待、角色重生和玩家离场建立取消或失效检查，防止旧任务修改新角色状态。
- 对不在客户端 Streaming 区域内的目标提供可恢复行为，不依赖客户端永远缓存实例。
- 用纯规则或配置测试覆盖边界值；运行游戏流程时记录实际服务器/客户端视角。
- 多人竞争、掉线重进和并发奖励需要多人环境证据；单客户端结果只能证明单客户端路径。
- 若需要创建新脚本，先确认正确的服务容器、类名、运行上下文和现有模块依赖。
- 发现关键逻辑位于 LocalScript 时，先确认是否只是表现；若是奖励或规则则移回服务器所有权。
