Construit et maintient le harnais de vérification propre d’un produit dans son dépôt, un CLI verify, une commande doctor, une isolation par worktree, une carte des fonctionnalités rédigée du point de vue de l’utilisateur, des données d’amorçage et un transfert de bug « reproduce‑first ». À utiliser lorsqu’on demande de « construire un harnais de vérification », « ajouter une commande doctor », « donner aux agents un moyen de vérifier cette application », « prouver que chaque fonctionnalité fonctionne toujours » ou « reproduire ce rapport de bug ». Pour des sondages ponctuels de navigateur contre un catalogue de règles UI fixe, utilisez ui‑verification ; pour les frontières de modules à l’échelle du dépôt et les garde‑fous de lint, utilisez codebase‑architecture.

Veuillez toujours répondre dans la langue de l’utilisateur.
