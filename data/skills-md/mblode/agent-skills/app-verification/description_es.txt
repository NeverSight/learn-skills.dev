Construye y mantiene el arnés de verificación propio del producto dentro de su repositorio, una CLI de verificación, un comando doctor, aislamiento por worktree, un mapa de funcionalidades escrito desde el punto de vista del usuario, datos semilla y una entrega de errores centrada en reproducir primero. Úselo cuando se le solicite “construir un arnés de verificación”, “añadir un comando doctor”, “dar a los agentes una forma de verificar esta aplicación”, “demostrar que cada funcionalidad sigue funcionando” o “reproducir este informe de error”. Para sondeos puntuales de navegador contra un catálogo de reglas UI fijo, use ui-verification; para límites de módulos y guardias de lint en todo el repositorio, use codebase-architecture.
