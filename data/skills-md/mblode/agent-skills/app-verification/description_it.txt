Costruisce e mantiene un harness di verifica proprio del prodotto all’interno del suo repository, un CLI verify, un comando doctor, isolamento per worktree, una mappa delle funzionalità scritta dal punto di vista dell’utente, dati seed e un passaggio di bug incentrato sulla riproduzione. Usalo quando ti viene chiesto di “costruire un harness di verifica”, “aggiungere un comando doctor”, “dare agli agenti un modo per verificare questa app”, “provare che ogni funzionalità funzioni ancora” o “riprodurre questo report di bug”. Per indagini occasionali del browser contro un catalogo fisso di regole UI usa ui‑verification; per confini di moduli a livello di repository e guardrail di lint usa codebase‑architecture.
