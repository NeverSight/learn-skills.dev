확인된 버그에서 시작해 그와 유사한 버그들을 찾아라: 근본 원인(소스, 싱크, 누락된 가드)을 일반화하고 이를 양·음성 테스트 케이스를 포함한 정적 분석 쿼리로 인코딩하거나, HTTP를 통해서만 보이는 변형을 위한 비파괴 Nuclei 템플릿으로 인코딩한다. 코드를 전체 또는 조직 전체에 적용해 실행하고, 원본과 연결된 판정으로 모든 결과를 종료하며, CI에 체크를 유지해 해당 버그 클래스가 고정되도록 한다. 사용자는 ‘variant analysis’, ‘find variants’, ‘where else does this bug exist’, ‘are there more bugs like this’, ‘same bug in other routes’, ‘custom semgrep rule’, ‘semgrep --test’, ‘ruleid annotation’, ‘CodeQL query for this bug’, ‘CodeQL query test’, ‘nuclei template for this bug’, ‘turn this bug into a check’, ‘stop this bug class coming back’와 같은 문구를 언급하거나, 알려진 버그가 있고 그 모든 다른 인스턴스를 원할 때 이 방법을 활용한다.
