Commencez à partir d’un bug confirmé et traquez ses semblables : généralisez la cause racine (source, puits, garde manquante), encodez‑la sous forme de requête d’analyse statique avec des cas de test positifs et négatifs, ou d’un modèle Nuclei non destructif pour les variantes visibles uniquement via HTTP, exécutez‑la sur l’ensemble du code ou sur toute l’organisation, clôturez chaque occurrence avec un verdict lié à l’original, et conservez la vérification dans le CI afin que la classe de bugs reste corrigée. Utilisez‑le lorsque l’utilisateur mentionne « analyse de variantes », « trouver des variantes », « où d’autre ce bug existe », « y a‑t‑il plus de bugs comme celui‑ci », « même bug dans d’autres routes », « règle Semgrep personnalisée », « semgrep --test », « annotation ruleid », « requête CodeQL pour ce bug », « test de requête CodeQL », « modèle Nuclei pour ce bug », « transformer ce bug en contrôle », « empêcher le retour de cette classe de bug », ou possède un bug connu et veut chaque autre instance de celui‑ci.
