Testez une application Web autorisée pour détecter les défauts de logique métier et les conditions de concurrence — les classes que les scanners ne trouvent pas. Modélisez les invariants (conservation de la valeur, unicité, monotonie, exclusivité), construisez une matrice Acteur × Action × Ressource, exploitez les machines d’état (saut/reordonnancement/rejeu d’étapes, découpage de limites), trouvez les bugs numériques (arrondi flottant vs décimal, arbitrage de remboursement interdevise, montants négatifs), les portes de fonctionnalités obsolètes et les lacunes de saga ; prouvez les bugs de concurrence (double dépense, mise à jour perdue, réutilisation de clé d’idempotence) avec des requêtes parallèles contrôlées. Utilisez lorsque l’utilisateur mentionne « test de logique métier », « condition de concurrence », « double dépense », « TOCTOU », « bug de concurrence », « idempotence », « réutilisation de coupon », « contournement de workflow », « contournement de limite », « montant négatif », « arbitrage de remboursement », « attaque de requête parallèle » ou « défaut de logique ».
