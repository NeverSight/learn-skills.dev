تدقيق خطوط أنابيب CI/CD، بدءًا من GitHub Actions ثم نظرة سريعة على GitLab CI وCircleCI، للبحث عن المسارات التي تمنح طرفًا خارجيًا إمكانية تنفيذ الشيفرة أو الوصول إلى الأسرار أو توكن كتابة: pull_request_target وworkflow_run التي تشغّل شفرة غير موثوقة، حقن التعبيرات في خطوات التشغيل، أذونات workflow مفقودة أو واسعة، إجراءات طرف ثالث غير مثبتة على SHA للالتزام، سياسات الثقة OIDC مع موضوعات wildcard، عدّائين مستضيفين ذاتيًا على مستودعات عامة، وصول الأسرار إلى الفروع المتفرعة، الثقة في التخزين المؤقت والقطع بين workflows، ووكلاء الذكاء الاصطناعي في CI الذين يقرؤون نص المشكلة أو طلب السحب أثناء امتلاكهم لتوكن كتابة. تشغيل zizmor وactionlint بصلاحية قراءة فقط وكتابة findings.json. استخدم ذلك عندما يذكر المستخدم “pull_request_target” أو “pwn request” أو “workflow injection” أو “zizmor” أو “actionlint” أو “pin actions to SHA” أو “GITHUB_TOKEN permissions” أو “self‑hosted runner” أو “claude‑code‑action” أو “AI agent in CI” أو “GitLab CI security” أو “CircleCI security” أو “is this workflow safe” أو عندما يحتاج إلى تأمين مسار بناء.
