Auditer les pipelines CI/CD, en commençant par GitHub Actions puis brièvement GitLab CI et CircleCI, afin d’identifier les vecteurs qui permettent à un tiers d’exécuter du code, d’accéder aux secrets ou à un token d’écriture : pull_request_target et workflow_run exécutant du code non fiable, injection d’expression dans les étapes run, permissions de workflow manquantes ou trop larges, actions tierces non épinglées à un SHA de commit, politiques de confiance OIDC avec des sujets génériques, runners auto‑hébergés sur des dépôts publics, secrets atteignant les forks, confiance du cache et des artefacts entre les workflows, et agents IA dans le CI qui lisent le texte d’une issue ou d’une PR tout en détenant un token d’écriture. Exécuter zizmor et actionlint en mode lecture seule et générer findings.json. Utiliser lorsque l’utilisateur mentionne « pull_request_target », « pwn request », « workflow injection », « zizmor », « actionlint », « pin actions to SHA », « permissions GITHUB_TOKEN », « self‑hosted runner », « claude-code-action », « AI agent in CI », « GitLab CI security », « CircleCI security », « is this workflow safe », ou lorsqu’il doit sécuriser une chaîne de construction.
