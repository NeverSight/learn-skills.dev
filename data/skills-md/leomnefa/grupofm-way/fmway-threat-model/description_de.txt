Verwenden, um ein kleines und abgegrenztes Bedrohungsmodell für die aktuelle Arbeit oder für neuen Code zu erstellen – ein Feature, ein Service, eine API oder die Änderungen im aktuellen Branch. Zerlegt das System in Vermögenswerte, Einstiegspunkte und Vertrauensgrenzen, listet Bedrohungen mit STRIDE auf und dokumentiert Gegenmaßnahmen und Restrisiko in einem nachvollziehbaren Bericht mit einem Datenflussdiagramm. Wird separat aufgerufen, um eine Komponente zu modellieren, oder aus einem anderen Flow (fmway-dev nach dem PRD oder dem Plan, fmway-bugs für einen sicherheitsrelevanten Fix), um Bedrohungen aufzudecken, bevor Code geschrieben oder ausgeliefert wird. Besonders wichtig für neue externe Angriffsflächen, Authentifizierungsabläufe, Zahlungen oder personenbezogene Daten sowie Änderungen an den Vertrauensgrenzen.
