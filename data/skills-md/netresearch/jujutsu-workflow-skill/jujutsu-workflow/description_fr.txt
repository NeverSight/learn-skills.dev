Utilisez‑le lorsqu’un agent de codage travaille dans un dépôt où Jujutsu (jj) est disponible (un répertoire `.jj/`) — exécution de commandes jj, modifications spéculatives, division des changements, récupération avec le journal d’opérations (jj undo / jj op restore), remise d’une PR à Git/GitHub/GitLab, mise à jour d’une PR après révision, ou coordination d’agents parallèles. Utilise jj comme couche locale de gestion des changements tout en conservant Git comme interface distante canonique, PR, CI et audit. À utiliser également pour éviter les pièges de l’agent jj (blocages du pager/éditeur, absorption de commit, désynchronisation git/jj co‑localisée) ou pour remplacer la récupération fragile avec git reset/checkout/stash/rebase par des opérations jj réversibles.
