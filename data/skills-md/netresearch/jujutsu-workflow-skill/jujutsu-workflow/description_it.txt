Usalo quando un agente di codifica lavora in un repository dove Jujutsu (jj) è disponibile (una directory `.jj/`) — eseguendo comandi jj, effettuando modifiche speculative, suddividendo i cambiamenti, recuperando con il registro delle operazioni (jj undo / jj op restore), passando una PR a Git/GitHub/GitLab, aggiornando una PR dopo la revisione o coordinando agenti paralleli. Usa jj come livello locale di gestione delle modifiche mantenendo Git come remoto canonico, interfaccia per PR, CI e audit. Usalo anche per evitare le insidie degli agenti di jj (blocchi del pager/editor, assorbimento dei commit, disallineamento git/jj collocati insieme) o per sostituire il fragile recupero con git reset/checkout/stash/rebase con operazioni jj reversibili.
