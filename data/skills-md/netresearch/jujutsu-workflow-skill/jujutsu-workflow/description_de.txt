Verwenden, wenn ein Coding‑Agent in einem Repository arbeitet, in dem Jujutsu (jj) verfügbar ist (ein `.jj/`‑Verzeichnis) — jj‑Befehle ausführen, spekulative Änderungen vornehmen, Änderungen aufteilen, mit dem Operations‑Log wiederherstellen (jj undo / jj op restore), einen PR an Git/GitHub/GitLab übergeben, einen PR nach Review aktualisieren oder parallele Agenten koordinieren. Verwendet jj als lokale Änderungs‑Management‑Schicht, während Git als kanonisches Remote, PR‑, CI‑ und Audit‑Interface erhalten bleibt. Auch verwenden, um die Fallstricke von jj (Pager/Editor‑Hänger, Commit‑Absorption, ko‑lokalisierte Git/Jj‑Desynchronisation) zu vermeiden oder um fragile git reset/checkout/stash/rebase‑Wiederherstellungen durch reversible jj‑Operationen zu ersetzen.
