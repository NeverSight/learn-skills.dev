Úsese cuando un agente de codificación trabaja en un repositorio donde Jujutsu (jj) está disponible (un directorio `.jj/`) — ejecutando comandos jj, realizando ediciones especulativas, dividendo cambios, recuperándose con el registro de operaciones (jj undo / jj op restore), entregando un PR a Git/GitHub/GitLab, actualizando un PR después de la revisión o coordinando agentes paralelos. Usa jj como la capa local de gestión de cambios mientras mantiene Git como el remoto canónico, PR, CI e interfaz de auditoría. También sirve para evitar los problemas de los agentes de jj (colgues del paginador/editor, absorción de commits, desincronización coubicada git/jj) o para sustituir la frágil recuperación de git reset/checkout/stash/rebase por operaciones reversibles de jj.
