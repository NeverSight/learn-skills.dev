Verwenden Sie diese Fähigkeit, wenn Sie ein Taiga‑UI‑Projekt auf eine neue Hauptversion migrieren. Bestätigen Sie vor dem Start mit dem Benutzer, welche Hauptversionen beteiligt sind (z. B. v4 → v5). Ersetzen Sie im gesamten Ablauf die Quellversion durch **CURRENT_MAJOR** und die Zielversion durch **NEXT_MAJOR**. Rufen Sie die Fähigkeit ebenfalls auf, wenn Sie Migrations‑Schemata ausführen, verbleibende Migrations‑TODOs nach `ng update` oder `nx migrate` bearbeiten, aufgefordert werden, TODOs zu beheben, Migrations‑Hinweise zu bereinigen, Deprecation‑Warnungen zu lösen oder mit dem Paket @taiga-ui/legacy zu arbeiten. Folgen Sie dem vollständigen Migrations‑Workflow: Kontext erfassen, Umgebung vorbereiten, Schematics ausführen, Änderungen überprüfen, TODOs bearbeiten und häufige Probleme beheben. Lösen Sie jedes umsetzbare TODO nur, wenn der umgebende Code zeigt, dass die Korrektur sicher ist; andernfalls prüfen Sie weiteren Kontext oder fragen Sie den Benutzer, bevor Sie Verhalten, Templates, Styles oder Skripte ändern. Bitte stets in der Sprache des Benutzers antworten.
