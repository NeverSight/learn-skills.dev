Возьмите запись экрана UI (мобильное/настольное/веб/маркетинговое видео) и выполните одну из четырёх задач — на ваш выбор: (1) просто извлечь кадры в формате PNG, (2) проанализировать систему дизайна, показанную в видео, и перечислить отдельные экраны, (3) сравнить видео с файлами в вашем кодовом базе и составить конкретный список правок, чтобы эти файлы соответствовали видео, или (4) создать реальное фронтенд‑приложение (Vite + React + TypeScript + Tailwind), которое воссоздаёт поведение UI — а не только его внешний вид — с работающими взаимодействиями и анимациями. Вариант 3 всегда сначала показывает предложенные изменения и ждёт вашего одобрения перед редактированием. Требуется ffmpeg; режим 4 дополнительно нуждается в Node.js для запуска сгенерированного приложения. Режим 4 читает навык `frontend-design` (если установлен) перед генерацией, чтобы унаследовать его качество компонентов и эстетические рекомендации.

Активировать каждый раз, когда пользователь упоминает запись экрана, видеопройзход, демо мобильного приложения, захват рабочего стола, маркетинговое/продуктовое видео или хочет извлечь дизайн‑инсайты из клипа — даже если он явно не говорит «использовать навык видео». Фразы вроде «У меня есть это видео UI», «извлечь кадры из этой записи», «какая система дизайна в этом видео», «сделать мои компоненты похожими на этот клип», «создать фронтенд‑приложение из этого видео» или «У меня есть демо UI, вот файлы, которые я хочу обновить» — всё это должно триггерить его. Сам навык спросит, какой из четырёх режимов запустить.
