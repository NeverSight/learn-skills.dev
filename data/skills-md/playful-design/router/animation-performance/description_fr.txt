Gardez les animations Web dans le budget de trame — animez uniquement les propriétés composites, maintenez le mouvement hors du thread principal lorsque la page est occupée, et identifiez la cause lorsqu’une animation perd des images. Le guide couvre le pipeline mise en page/peinture/composite, les permutations de propriétés moins coûteuses, CSS vs WAAPI vs requestAnimationFrame, le chemin matériel accéléré de Motion, le re‑rendering de React à chaque image, le recalcul des variables CSS héritées, le coût du flou, et les cas où `will-change` est réellement utile. Utilisez‑le lorsque une animation est saccadée, hachurée, hésite ou perd des images ; lors du choix de la propriété à animer ; lors de la décision entre animation CSS et JavaScript pour des raisons de performance ; ou lorsque vous avez recours à `will-change` ou aux calques GPU. Pour choisir l’easing, la durée, ou décider d’animer ou non, utilisez **animate** ; pour revoir l’ensemble du motion, utilisez **review-animations**.
