Halten Sie Webanimationen innerhalb des Frame‑Budgets – animieren Sie nur Composite‑Eigenschaften, halten Sie die Bewegung vom Haupt‑Thread fern, wenn die Seite ausgelastet ist, und finden Sie die Ursache, wenn eine Animation Frames fallen lässt. Behandelt die Layout‑/Paint‑/Composite‑Pipeline, günstigere Eigenschafts‑Swaps, CSS vs. WAAPI vs. requestAnimationFrame, den hardwarebeschleunigten Pfad von Motion, React‑Re‑Renderings pro Frame, die Neuberechnung geerbter CSS‑Variablen, die Kosten von Blur und wann `will-change` tatsächlich hilft. Verwenden Sie es, wenn eine Animation ruckelig, stotternd oder splitterig ist bzw. Frames fallen lässt; wenn Sie entscheiden, welche Eigenschaft animiert werden soll; wenn Sie aus Leistungsgründen zwischen CSS‑ und JS‑Animation wählen; oder wenn Sie `will-change` bzw. GPU‑Layer einsetzen möchten. Zum Auswählen von Easing, Dauer oder ob überhaupt animiert werden soll, verwenden Sie „animate“; zum Gesamtüberblick über Motion nutzen Sie „review-animations“.
