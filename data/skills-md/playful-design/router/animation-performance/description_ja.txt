Webアニメーションをフレーム予算内に収める―合成のみで処理できるプロパティをアニメーションし、ページが忙しいときはメインスレッドからモーションを外し、アニメーションがフレーム落ちしたときは原因を特定する。レイアウト／ペイント／合成パイプライン、コストの低いプロパティの入れ替え、CSS と WAAPI と requestAnimationFrame の比較、Motion のハードウェアアクセラレートパス、フレームごとの React 再レンダー、継承された CSS カスタムプロパティの再計算、ぼかしのコスト、そして `will-change` が実際に効果を発揮するタイミングについて解説する。アニメーションがぎこちない、カクカクする、スタッタリングする、またはフレーム落ちする場合や、どのプロパティをアニメーションすべきか選ぶとき、パフォーマンス観点で CSS アニメーションと JS アニメーションのどちらを選択すべきか判断するとき、あるいは `will-change` や GPU レイヤーを利用しようとする際に活用する。イージングや継続時間、あるいはアニメーション自体を行うかどうかを決めるときは「animate」を、モーション全体をレビューするときは「review-animations」を使用する。
