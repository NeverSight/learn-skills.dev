Connectez, exposez ou auditez les agents Python Google ADK à travers les frontières de processus avec MCP et A2A : sélection de la source d’outil (FunctionTool, OpenAPIToolset, McpToolset, Toolbox, Application Integration), consommation des serveurs MCP (connexion, cycle de vie, tool_filter, préfixes, en‑têtes, drapeau de confirmation, épinglage du SDK), exposition d’un agent en tant que serveur MCP, décision entre sous‑agents et topologie A2A distante, consommation d’un agent distant avec RemoteA2aAgent (cartes d’agent, états des tâches, streaming, délais d’attente), exposition avec to_a2a et enregistrement sur Agent Runtime ou Gemini Enterprise. Utilisez‑le lorsque un agent doit appeler ou être appelé par un autre service ou framework, ou pour examiner le câblage MCP et A2A. Ne l’activez pas pour le modèle de menace MCP, les listes d’autorisation ou la politique d’épinglage (adk-agent-security), l’orchestration en‑processus (adk-workflow-design), le plumbing OAuth (adk-tool-auth-and-secrets), la politique de nouvelle tentative d’un appel API unique (safe-api-tool-calls) ou le déploiement (deploy-adk-on-google-cloud).
