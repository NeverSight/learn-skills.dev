Sélectionnez, implémentez ou révisez le contrôle de flux du workflow Google ADK, la consommation d’événements, les transferts d’état de session, les rappels et les points de contrôle. Utilisez‑le lors du choix entre du code ordinaire, séquentiel, parallèle, boucle bornée, graphe ou orchestration dynamique, ou pour réparer ces contrats d’exécution dans un agent existant : transferts output_key où le {key} d’un agent ultérieur reste littéral ou soulève une KeyError, réutilisation des étapes sauvegardées après une modification d’entrée, un point de contrôle trop volumineux pour son stockage, une exécution en attente plusieurs jours pour approbation à travers des redémarrages (reprise ADK ou moteur persistant), vérifications de cohérence d’ébauche dans le code et corrections en mode avertissement uniquement. Ne pas activer pour des modifications d’interface non liées, des explications générales de LLM, un déploiement cloud autonome, la mise en œuvre de RAG, des services de mémoire ou SQL, le libellé des instructions ou les descriptions de sous‑agents (adk-agent-instructions), les agents A2A distants ou les serveurs MCP (adk-agent-interoperability), ou un modèle de menace d’injection (adk-agent-security).
