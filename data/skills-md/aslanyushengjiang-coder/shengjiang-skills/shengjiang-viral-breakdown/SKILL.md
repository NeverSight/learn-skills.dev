# 生姜爆款拆解

让每次拆解回答三个问题：这条视频说中了哪类人的什么问题；它怎样让观众一步步看下去；哪些方法适合自己的账号。

本 Skill 按输入视频、视频解析、分镜、全文稿四步执行。来源、逐页字段和未展示的部分见 [原件核对](references/source-map.md)；首次执行时读取它，避免把本地补充当作原框架。

## 触发与分工

| 请求 | 执行范围 |
| --- | --- |
| 拆指定的同行视频、爆款内容、按流程拆解 | 运行下面四步，并给可迁移方法 |
| 复盘自己的视频 | 同样执行四步，将结论用于定位具体段落的问题 |
| 只有文稿、截图、PDF 或部分素材 | 用现有证据完成可判断部分；说明缺少视频、评论或时间信息造成的具体缺口 |
| 搜账号、搜关键词、批量抓作品 | `shengjiang-research` 负责采集；本 Skill 负责对选定作品深入拆解，不自动扩大账号或平台范围 |
| 只优化开头、只分析传播心理、只改稿 | 按宿主注册表使用 `dbs-hook` / `dbs-resonate` / `dbs-spread` 或对应写作 Skill；未安装这些可选 Skill 时按用户限定范围直接分析，不强行跑完整流程 |

## 1. 输入视频：先建立证据

从用户消息和当前项目取得链接、原片、字幕、数据、评论与用途。已有信息直接复用；只有作品对象或关键目标无法确定时才追问。用户未说明自身定位时先完成原片拆解，迁移部分只写适用条件。

- 回读实际材料，登记平台、作品标题、作者、原链接、发布时间、时长、采集时间和本地原件位置。未知字段保留“未提供”，不要根据文件名推测。
- 先确认是同行学习还是自身复盘。自身复盘需区分“用户原本想触达的人”与“从现有内容推断的人”。
- 公开数据使用平台原字段：点赞、推荐、收藏、评论、分享/转发、播放量分别记录；“推荐”不得改写为播放量。
- “爆款”是待核实的表现描述。只有单条数据时呈现实际表现；需要判断相对表现时使用已有的同账号、同平台可比数据，不擅自补采。没有播放量、留存或后台证据，就不计算播放率、完播率，也不把逐段推测写成实测流失。
- 只有作品链接时，从宿主已安装的 Skill 中找到并完整读取 `shengjiang-research`（有注册表时按注册表定位）及它转指的真源，复用其中的视频下载、字幕/第三方 ASR、详情和评论流程。未安装时先按 [安装说明](README.md) 安装；已有材料可继续分析。先显示具体请求与费用，按已有授权执行；本 Skill 的编写或测试不自动授权付费采集。
- 默认只处理指定作品，评论沿用采集 Skill 的范围。平台 API 受阻时记录具体缺口，继续分析已有材料；不切换网页抓取补齐。
- 已有可靠官方字幕直接复用；否则走现有第三方 ASR。禁止本地语音模型。标题与简介不当逐字稿。
- 准备完整视频、带时间字幕和必要画面证据后分析。技术执行可先拿到字幕；交付仍按原文四步组织。

PDF 或长截图含素材时，正文与图片都要读取。整页渲染核对上下文，放大内嵌图阅读字段、字幕和数字；跨页截图合并理解。看不清或原图裁掉的部分明确记录，不补写成原文。

## 2. 视频解析

### 作品表现与综合诊断

先用一段话说明这条视频怎样建立观看价值，具体说清有效机制和证据不足处。随后填写原图可见的六个字段：

| 字段 | 需要回答 |
| --- | --- |
| 内容类型 | 内容形式及它承担的任务 |
| 核心命题 | 创作者希望观众相信的主要判断，区别于话题名称 |
| 目标处境 | 哪类人处于什么情境、有什么问题或情绪 |
| 观看承诺 | 看完能够获得什么答案、理解或行动价值 |
| 核心机制 | 开头、疑问、观点、证据与结尾怎样共同发挥作用 |
| 证据边界 | 哪些是原片事实、作者主张、评论反馈或分析推断；具体缺少什么 |

每个关键结论回指时间、原句、画面或评论记录。作者引用的数据只证明他使用了该证据；未核实的数据不能自动当作事实。

### 开头如何建立观看理由

确定真实开头区间，结合第一段口播、封面/画面标题、可见字幕分析：

1. 原片时间与原句。
2. 钩子类型及具体作用，避免仅贴“反差、悬念、痛点”标签。
3. 制造的信息缺口：观众此刻具体想知道什么。
4. 承诺的观看收益。
5. 兑现情况：由后文哪个时间点回应；完整兑现、部分兑现或没有兑现的依据。

### 内容如何一步步成立

按语义推进划分段落，不机械按固定秒数等分。逐段记录：时间范围、核心内容/原句、表达方式、观众状态变化（分析推断）、本段内容任务、如何承接前后文。

在段落证据上回答原文提出的问题：面向谁、为何停留、产生了什么信息差、观点怎样成立、用什么建立信任、观众认同与质疑什么。原截图未展示完整的分结构栏目名称，不虚构未展示的七项算法。

具体检查：问题是否逐步得到回答；有没有只抛结论却缺中间解释；例子和数据是否支持结论；哪句话增加新信息；哪个段落重复、偏离或承接中断。没有真实留存数据时只说“可能影响继续观看的原因”。

### 高赞评论反映了什么

先交代评论数量、采集时间、排序方式及范围。有点赞数才按样本内点赞排序；无法确认时称“已提供评论”。保留有代表性的评论原文、点赞数（如有）和来源 ID/位置，避免只剩二次总结。

沿用图片中的四个字段：**印证了什么、质疑与阻力、用户需求、情绪共鸣点**。允许同一条评论支持多个观察，不为填栏目虚构评论。再从有证据的未解问题提炼下一条选题，说明来源评论与需要补充的事实。

评论赞同只证明有人表达认同；评论样本不代表所有观众。用户的质疑保留原意，不能改成赞美。没有评论则标记缺失，不能用自己的想象充当用户反馈。PDF 中只有评论分析摘要时，明确引用为“资料中的二次分析”。

## 3. 分镜：回到真实画面

按实际镜头切换、字幕或演示变化、内容任务变化划段。内容段落与镜头段可以不同，不把语义分段当成真实剪辑点。

每段包含 **起止时间、同期口播、画面设计、可见字幕、内容任务**，附关键帧或可回看的原片定位。画面描述写清景别、人物/物体位置、演示动作、文字出现方式，以及画面怎样帮助理解。

原片可用时先观察完整时间线，结合关键帧和转折附近的连续片段核对；稀疏抽帧只支持已观察时刻。帧提取可复用当前可用 FFmpeg/视频工具，临时帧存系统临时目录，需要长期引用的少量证据图留在项目资料目录。

只看到静态图时不推断运镜、手势变化、剪辑频率或全段持续画面；只有文稿时不生成虚构分镜。可以另外给创作建议，但必须明确是建议。

自身复盘检查：开头何时进入问题；画面是否帮助理解；拖沓出现在哪里、为什么；字幕是否突出重点；口播、画面、字幕是否承担同一任务。

## 4. 全文稿：完整保留与可回看

从官方字幕或第三方 ASR 结果输出带时间戳的完整逐字稿，保留口语、重复、强判断和疑问，不擅自改写为精简稿。注明来源，疑似人名/品牌/术语错误单独标注，核对后保留修改记录。

检查实际字幕覆盖范围与媒体时长，查缺失的开头、中段、结尾。静默或片尾画面不等于漏字，依据原片判断。有起止时间就保留；只有起始时间不捏造结束时间。纯文字不均匀分配时间伪造字幕。

PDF 截图中只展示一部分逐字稿时，交付名称必须是“逐字稿节选”；其他章节不能把它描述成全片。无法拿到可靠转写时交付已有分析与具体缺口。

## 迁移到自身内容

这是本地执行补充，服务于原文“判断哪些方法适合自己”的要求。

- 同行学习：列出值得借用的具体机制、原片证据、适用条件、在目标账号中如何使用和需要的真实材料。保留打法细节与情绪功能；不照搬对方身份、经历、收入、客户或产品结果。
- 自身复盘：逐项核对目标人群、继续观看的理由、明确问题、观点证据、画面字幕口播；输出“具体段落 → 影响 → 下一条可执行调整”。没有问题的部分明确保留，不为凑数硬找问题。
- 当前 IP 的定位与栏目按项目事实源读取，不在本 Skill 固化业务状态。用户只要拆解时不擅自重写原稿、标记采用、修改拍摄排期或发布内容。
- 不设原文不存在的权重、总分、爆款概率、固定公式或保爆承诺。需要迁移示例时只使用已经核实的自身材料；资料不足就给结构与材料要求。

## 交付与验收

使用 [报告模板](templates/report.md) 组织四步结果。默认一份完整 Markdown 报告，已有原片、字幕和数据用链接引用；用户指定 HTML、表格等再按对应 Skill 制作。篇幅随素材变化，字段有证据才填写，缺口集中说明。

写入前按宿主归位规则确定唯一目标。当前 IP 拆解沿用对应对标素材目录；其他项目跟随项目；本 Skill 目录只放执行规则、参考和测试，不积累日常业务报告。

完成前核验：

1. 对象、数据字段、来源与时间正确；事实和推断可区分。
2. 正文、图片/原片、评论、字幕按实际可用范围检查，关键结论有定位。
3. 开头承诺与兑现、逐段推进、评论四项、分镜五项都处理到；缺材料如实标明。
4. 分镜与字幕时间相容；报告未把截图分析当完整看完原片。
5. 原文方法与本地执行补充可追溯；迁移未盗用他人事实。
6. 报告、引用原件、必要证据能打开；按宿主要求更新最近索引与日志。

完成状态分为“完整拆解”和“基于现有材料的部分拆解”。完成了 Skill 编写或离线测试，不代表新视频采集与全流程已经通过。测试案例与真实记录见 [评测用例](evals/evals.json) 和 [验收记录](evals/validation.md)。
