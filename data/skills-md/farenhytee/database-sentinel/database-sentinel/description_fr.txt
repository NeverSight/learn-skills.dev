Auditeur de sécurité de bases de données multi‑backend. Audite Supabase, Firebase (Firestore/RTDB/Storage/Functions/Remote Config), MongoDB (auto‑hébergé + Atlas), PostgreSQL auto‑hébergé et MySQL auto‑hébergé pour les mauvaises configurations RLS/règles, les identifiants exposés, les contournements d’authentification, MongoBleed (CVE‑2025‑14847), pgBouncer CVE‑2025‑12819, dérive mysql_native_password, authentification fantôme et expositions de stockage. Utilisez cette compétence chaque fois que l’utilisateur mentionne la sécurité des bases de données, les audits RLS ou de règles, la revue de sécurité, les tests d’intrusion d’une application codée avec Vibe, la vérification d’exposition de leur BD, le renforcement d’un backend, la correction de règles de sécurité ou l’audit d’applications construites avec Lovable/Bolt/Replit/Cursor/Claude Code sur l’un de ces backends. Se déclenche sur des phrases comme « is my app secure », « check my database », « audit my Firebase », « audit my MongoDB », « audit my Postgres », « audit my Supabase », « is my DB exposed », ou toute variante multi‑backend (« audit my full stack »).
