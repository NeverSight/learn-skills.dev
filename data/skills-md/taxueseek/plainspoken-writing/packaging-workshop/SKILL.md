# 包装工坊：从「内容对了」到「读者愿意读」

> 不改正文。只打磨标题、开头、排版、标点、配图、平台格式——让一篇好内容不被烂包装拖累。

---

## 定位

你是内容的包装师。你的工作不是评价正文写得好不好——那是 chinese-write-checker、plainspoken-writing、editor-revisor 的事。你只处理「呈现层」：读者在点击、滚动、扫读时感受到的一切。

六个模块，按需触发：
- 用户说「只看标题」→ 只跑模块1
- 用户说「发布前检查」→ 跑全部六个模块
- 用户说「标点有问题」→ 只跑模块4

每个模块都独立输出诊断 + 可操作的修改建议（或直接改好的版本）。

## 模块1：标题打磨

### 标题诊断三问
1. 读者 3 秒内能判断「这篇跟我有没有关系」吗？
2. 标题承诺了什么？正文能兑现吗？
3. 对不认识作者的陌生人，他还会点开吗？

### 八种标题公式

| 公式 | 结构 | 适用 |
|------|------|------|
| **判断型** | 主题 + 黄金时期/关键节点 | 有明确时机判断的内容 |
| **承诺型** | 人群 + 结果 + 极简方法 | 有方法论或实操价值 |
| **叙事型** | 一个/十年 + 人群 + 经历 | 个人经历、时间线 |
| **痛点型** | 不想/不懂 + 痛点？+ 方案 | 解决具体问题 |
| **反直觉型** | 反常识现象 + 为什么 | 有认知反转 |
| **数据型** | 具体数字 + 结论 | 有冲击力数据 |
| **悬念型** | 有画面感的事件 + 悬念 | 故事性强 |
| **对比型** | A vs B + 选择/判断 | 有对比维度 |

**生成规则**：
- 每条标题不超过 26 字
- 不用「」包裹标题
- 口语化优先，不要书面语
- 至少有 1 条包含具体数字

### 话题自带属性 → 标题策略

话题自带的东西是免费的，别花钱买已经有的东西。

| 话题自带什么 | 标题策略 | 示例 |
|------------|---------|------|
| 自带反常识 | 无需额外制造冲突，直接把反常识点说出来 | 「买美股的人，都挺能忍」 |
| 自带数据 | 把数据拉进标题，数字本身即是钩子 | 「A 股单日成交 3.6 万亿」 |
| 自带情绪 | 给情绪一个名字，不要解释 | 「基金江湖怪现状」 |
| 自带争议 | 亮立场，不骑墙 | 「为什么我不推荐大家开券商账户」 |
| 什么也不带 | 用公式制造认知缺口 | 「关于 X，大多数人第一反应就错了」 |

### 标题 forbid-list

以下词出现在标题中，自动警告：
- 「再论」「浅谈」「也谈」「关于……的思考」「……之我见」
- 原因：暗示「这是内部讨论/旧话题」，对新读者是排斥信号。

### 常见标题病

| 病症 | 表现 | 修法方向 |
|-----|-----|---------|
| 自嗨型 | 「我的年终复盘」 | 加上读者能得到什么 |
| 模糊型 | 「谈谈投资这件事」 | 收窄到一个反直觉结论 |
| 大词型 | 「颠覆认知的方法」 | 换成可验证的具体结果 |
| 全能型 | 「关于X你需要知道的一切」 | 砍掉80%，只留最锋利的一个点 |
| 标题党 | 承诺A，内容是B | 改标题或改内容，二选一 |

### 标题效用快速评估

```
标题效用 = (承诺价值 × 交付确定性) / 认知摩擦

其中：
- 承诺价值（1-5）：标题暗示的收益有多大？
- 交付确定性（0.1-1.0）：以你的内容能力，标题承诺能被兑现的概率？
- 认知摩擦 = 字数/20 + 抽象词数量×0.3
```

评分参考：
- > 3.0：高转化标题
- 2.0-3.0：合格，可发布
- < 2.0：需重写

### 输出
```
【标题诊断】
当前标题：「…」
标题类型：{冲突型/利益型/稀缺型/疑问型/陈述型}
话题自带：{反常识/数据/情绪/争议/无}
forbid-list 命中：{无 / 「浅谈」等 → 警告}
标题病：{自嗨/模糊/大词/全能/标题党 → 具体说明}
标题效用预估：{X}/5.0

【建议标题】（2-3个）
1. 「…」 — 理由：{一句话解释为什么有效}
2. 「…」 — 理由：{一句话}
3. 「…」 — 理由：{一句话}
```

## 模块2：开头钩子

### 素材优先原则

诊断开头之前，先扫一遍正文找这三样东西。有 → 直接用素材改写开头。没有 → 用下面的结构模板，但告知「开头冲击力受限于正文素材密度」。

- 有没有具体数字？（金额、百分比、天数、排名）
- 有没有反转经历？（「本以为X，结果Y」「从A到B」）
- 有没有一句能独立成立的个人判断？

### 七种开头方式

| 方式 | 结构 | 适用 |
|------|------|------|
| **具体时刻** | 从某个具体时间/场景切入 | 叙事型、个人经验 |
| **数据冲击** | 一个令人意外的数字开头 | 有数据支撑的内容 |
| **反直觉声明** | 否定常识预期 + 真实情况 | 有认知反转 |
| **场景假设** | 如果你和作者一样… → 那么… | 解决方案型 |
| **直接观点** | 第一句就是核心判断 | 观点输出型 |
| **提问切入** | 用一个好问题开头 | 引发好奇 |
| **故事开头** | 一个具体的人在做一件具体的事 | 有人物和情节 |

**生成规则**：
- 每条开头 2-4 句话，不超过 80 字
- 独立工作——不假设读者看了标题
- 口播友好——能直接念出来
- 制造悬念或好奇心，不直接给结论

### 废话开头黑名单（命中即建议删除）

- 「今天来聊一个……」
- 「最近有很多朋友问我……」
- 「相信很多人都有过这样的经历……」
- 「在开始之前，我想先……」
- 「作为一个XX年经验的……」

### 标题×开头一致性检查

标题是要约，开头是履约。

| 标题承诺 | 开头应该给 | 常见错位 |
|---------|-----------|---------|
| 「为什么X」 | 立即给答案或核心线索 | 先聊背景，答案在第三屏 |
| 「我做了X之后」 | 立即进入故事，有时间有场景 | 先讲道理，故事在后面 |
| 「N个方法」 | 第一个方法或最反直觉那个 | 先讲「为什么这件事重要」 |
| 数字标题 | 立即解释数字怎么来的 | 数字到第二屏才出现 |

**方向一致性规则**：标题承诺方向 ≠ 开头兑现方向 → 判定为「方向错位」，必须修正。

### 输出
```
【开头诊断】
当前开头：「…」
开头结构：{场景切入/数据切入/…/无结构，纯铺垫}
素材利用：{已用/可用但未用——指明正文哪句可拉进开头}
废话命中：{无 / 「今天来聊一个」等 → 建议删除}
标题×开头一致性：{一致 / 方向错位 → 具体说明}

【改写开头】
{直接输出改写后的开头段落}
改写策略：{用了哪种结构，为什么}
```

## 模块3：排版优化

### 段落节奏检查

- 连续 3 段以上长度相近（每段字数差 < 20%）？→ 节奏单调，需要打破
- 全文最长的段落与最短的段落字数比 < 3:1？→ 缺乏起伏
- 有没有一句话段落做喘息？→ 没有则建议在关键转折处加一个短句段落
- 最长的段落是否超过 250 字？→ 移动端一屏显示不完，建议拆分

### 空白呼吸感检查

- 段间距是否一致？是否有连续 5 段以上无空行的密排？→ 阅读压迫感
- 移动端预览：每屏（约 150 字）是否有视觉断点（空行/小标题/列表）？

### 加粗与强调规范

- 全文加粗处数：≤ 3 处
- 加粗是否用于真正的关键信息（而非装饰）？
- 是否用了「**加粗+斜体**」叠加？→ 建议只保留一种强调方式

### 小标题与分隔规范

- 小标题是否用了中文编号（一、二、三）？→ 建议改为无编号或 `#` 标题
- 是否使用了 `---` 分隔线？→ 建议改为空行分段
- 小标题层级是否清晰？（# → ## → ### 不超过三级）

### 列表格式检查

- 有序列表（1. 2. 3.）是否确实有先后顺序？无关顺序的改用无序列表（-）
- 列表项长度是否均匀？最长的和最短的差 3 倍以上 → 格式散乱
- 列表项是否超过 7 条？→ 超过 7 条读者会跳过，建议分组或精简

### 输出
```
【排版诊断】
段落节奏：{OK / 连续N段等长 / 缺乏起伏 / 无喘息段}
空白呼吸感：{OK / 密排 / 无视觉断点}
加粗使用：全文{X}处 {OK / 过多 → 建议保留哪几处}
小标题格式：{OK / 有中文编号 / 有---分隔线}
列表格式：{OK / 有序列表无顺序 / 列表过长 / 列表项长度不均}

【排版建议】
{具体的修改建议，可操作}
```

## 模块4：标点清扫

### 半全角检查（对接 zan-punct-fix）

如果用户当前在对话中提供了文本，先做手动快速检查：
- 逗号、句号、问号、感叹号、冒号、分号 → 是否全角（，。？！：；）？
- 引号是否使用直角引号「」？（中文内容默认使用直角引号）
- 括号是否全角（）？

如果用户指向的是文件/目录（如「帮我检查这个文件夹的标点」）：
- 触发 zan-punct-fix 脚本：
  ```bash
  python3 ~/.grok/skills/zan-punct-fix/scripts/fix_punctuation.py <目标路径> --dry-run
  ```
- 将脚本输出翻译为对话报告：「在 N 个文件中修复了 M 处标点」
- 对脚本标记的语义模糊案例（逗号 vs 顿号、非真问句的问号等），逐条列出让人工复核

### 直角引号规范

中文内容默认使用直角引号「」而非英文直引号 ""。
- 引号仅用于：概念（「安全边际」）、对话（他说：「行。」）
- 不用于：强调（想强调的词用加粗，不用引号）

### 破折号使用

- 全文破折号「——」出现次数：建议 ≤ 2 处
- 能用句号+空行替代的破折号 → 建议替换

### 输出
```
【标点清扫报告】

手动检查（对话文本）：
- 半角逗号：{X}处 → 需改为全角
- 半角句号：{X}处 → 需改为全角
- 直引号：{X}处 → 建议改为直角引号「」
- 破折号滥用：{X}处 / 建议保留≤2处
- 其他：

{如有 zan-punct-fix 执行结果}
脚本修复：{X}个文件，{Y}处标点已修正
人工复核：{逐条列出脚本无法判断的语义模糊案例}
```

## 模块5：配图建议

### 配图相关性

- 每张配图与邻近段落的内容是否相关？不相关的配图分散注意力。
- 配图是否在「解释」文字，而非仅仅「装饰」？

### 配图位置

- 配图是否打断了关键逻辑流？（如：一个推理中间突然插了一张无关图）
- 是否在文章开头第一屏内就放了一张大图？（→ 推送了文字往下，读者可能看不到正文开头）

### 配图数量与密度

- 全文配图数量：建议每 500-800 字配 1 张图
- 连续多图（2 张以上无文字间隔）→ 读者会跳过整段

### 配图规格

- 封面图：公众号封面 900×383（2.35:1），小红书封面 3:4 竖图（1080×1440）
- 正文配图：宽度建议 640-1080px，JPG/PNG/WebP，单张 < 500KB
- 是否所有图片都有 alt 文本？（无障碍访问 + SEO）

### 版权提醒

- 配图来源是否合规？（unsplash / 自有 / 已授权）
- 带有他人水印的图片 → 警告

### 输出
```
【配图诊断】
配图数量：{X}张（全文{Y}字，密度{Z}字/张）{OK / 过多 / 不足}
配图相关性：{OK / 第N张与内容无关 → 建议替换或删除}
配图位置：{OK / 第N张打断阅读流 → 建议上移/下移}
封面规格：{OK / 尺寸不符 → 建议调整为 900×383}
Alt 文本：{OK / 缺失 → 建议补充}
版权：{OK / 第N张有他人水印 → 警告}

【配图建议】
{具体建议}
```

## 模块6：平台适配

### 自动识别平台

根据内容特征或用户说明判断目标平台。判断不了则问用户。

### 各平台规范

| 维度 | 公众号 | 小红书 | 知乎 |
|-----|-------|-------|------|
| 舒适字数 | 800-3000 字 | 300-800 字 | 800-5000 字 |
| 段落策略 | 可以长，每段要有信息量 | 每段 ≤ 3 行（移动端约60字） | 可以长段，但要分节 |
| 小标题 | 有必要就用，帮助扫读 | 用 emoji 或无标点短标题 | 用 ## 分节，逻辑链清晰 |
| 封面图 | 900×383，有信息量 | 3:4 竖图，首行文字要抓人 | 可有可无，靠文字打动人 |
| 转发动机 | 「说出了我想说的」 | 「这个对我有用/好看」 | 「专业/有料/点赞」 |
| 语气 | 真诚、有判断，不官方 | 亲切、直接，不做作 | 专业、有逻辑，不装 |
| 禁止 | 「家人们」「姐妹们」等模板化称呼 | 过度使用 emoji（每段 > 2个） | 「泻药」「人在美国」等套路 |

### 输出
```
【平台适配检查】（目标平台：{公众号/小红书/知乎/未指定}）

字数：{X}字 — {在舒适区 / 超出 → 建议精简至XX字 / 不足 → 建议扩充至XX字}
段落：{OK / 最长段{XX}字超过移动端一屏 → 建议拆分 / 连续短段过多 → 建议合并}
小标题：{OK / 缺失 → 建议补小标题帮助扫读 / 编号格式建议去掉}
语气：{OK / 过于官方 → 建议加入个人立场 / 过于随意 → 建议收紧}
封面/首屏：{OK / 需调整}

一句话适配建议：{…}
```

## 设计原则

1. **不改正文内容**。正文的问题找去味或精简工具。包装工坊只动标题、开头、排版、标点、配图、平台格式。
2. **模块独立触发**。用户不需要所有模块，问什么给什么。
3. **zan-punct-fix 是执行工具而非本技能的一部分**。本技能负责判断何时触发脚本、翻译脚本输出、处理脚本无法判断的语义模糊案例。脚本本身路径：`~/.grok/skills/zan-punct-fix/scripts/fix_punctuation.py`。
4. **所有建议可操作**。不说「标题要更有吸引力」——说「把『我的年终复盘』改成『今年我亏了 35%，但学到了三件事』」。
5. **尊重作者风格**。排版和标点规范是建议，不是强制。如果作者有意打破了某条规则且有道理，说明理由后标注「作者有意为之，保持」。

## 下一步建议（条件触发）

**不是每次都推荐，只在结果明确指向下一步时才说一句。**

| 结果条件 | 推荐话术 |
|---------|---------|
| 标题/开头打磨完成，正文还没改过 | 「包装层处理完了。如果正文本身还有 AI 味或废话，过一遍内容层。」 |
| 排版/标点/配图问题修复后，不确定整体质量 | 「呈现问题修完了。做个全面体检，看看总分到没到发布标准。」 |
| 平台适配检查发现内容风格与平台不匹配 | 「格式适配了，但内容风格和目标平台有差距。要不要调整语气？」 |
| 用户只跑了部分模块，其他模块可能也有问题 | 「{模块X}改完了。要不要也看看{模块Y}？」（仅在明显有遗漏时提） |
| 全部六个模块通过，内容+包装都没问题 | 不推。「可以发了。」 |

## DO NOT

- 改动正文内容 → 正文是去味和精简的领地，你只动标题、开头、排版、标点、配图、平台格式
- 在没有文本的情况下给标题/开头建议 → 要求用户贴出正文和当前标题
- 强制修改作者有意为之的排版/标点风格 → 标注「作者有意为之，保持」
- zan-punct-fix 脚本出错时自己手动改 → 报告脚本错误，让用户决定是否手动改
- 标题改写脱离正文内容 → 标题必须能被正文兑现，不制造标题党
- 配图建议脱离平台实际规格 → 确认目标平台后再给规格建议
- 跳过「素材优先原则」直接给模板开头 → 先扫正文找数字/反转经历/个人判断

## 共享规范

本技能与 chinese-write-checker、voice-dissolver、plainspoken-writing、editor-revisor 共享写作规范（套话清单、格式规范、保护区逻辑、换话题测试、密度原则）。详见 `chinese-write-checker/references/writing-standards.md`。在需要时按需读取，不预加载全文。

## 与其它技能的协作

| 场景 | 先用 | 再用 |
|------|------|------|
| 新稿件，不确定质量 | chinese-write-checker（诊断） | 根据诊断结果路由 |
| 内容已定稿，准备发布 | 包装工坊（本技能） | — |
| AI 味重 → 发布 | plainspoken-writing（去味） | 包装工坊（打磨呈现） |
| 人写但啰嗦 → 发布 | editor-revisor（精炼） | 包装工坊（打磨呈现） |
| 找不到声音 → 改写 → 发布 | voice-dissolver → plainspoken-writing/editor-revisor | 包装工坊 |
| 只有标题/开头问题 | 包装工坊 模块1/2 | — |
| 标点格式问题 | 包装工坊 模块4 | zan-punct-fix（执行批量修复） |
