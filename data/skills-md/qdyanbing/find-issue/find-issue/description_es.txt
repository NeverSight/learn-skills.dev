Inspecciona un repositorio de código local para encontrar errores reales y observables por el usuario. Rastrea el comportamiento público a través del código en tiempo de ejecución, excluye el comportamiento intencional y los problemas o pull requests ya presentados en GitHub, construye y verifica de forma independiente una reproducción pública mínima, y redacta un borrador en Markdown listo para crear un issue que permanece sin verificar hasta que un humano lo confirme. Utilízalo cuando se solicite escanear código en busca de errores, encontrar candidatos de alto valor para issues, validar un defecto sospechoso, producir Markdown listo para issue con un enlace de reproducción, o registrar un no‑issue marcado por el usuario en not‑issues.md.
