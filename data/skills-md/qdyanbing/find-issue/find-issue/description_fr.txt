Inspectez un dépôt source local pour trouver des bugs réels et observables par l'utilisateur. Suivez le comportement public à travers le code d'exécution, excluez les comportements attendus ainsi que les tickets ou pull requests déjà déposés sur GitHub, créez et vérifiez de manière indépendante une reproduction publique minimale, puis rédigez un brouillon Markdown prêt à être publié comme issue, qui reste non vérifié jusqu'à ce qu'un humain le confirme. Utilisez-le lorsqu'on vous demande de scanner le code à la recherche de bugs, de trouver des candidats d'issues à forte valeur ajoutée, de valider un défaut suspect, de produire un Markdown prêt à être publié avec un lien de reproduction, ou d'enregistrer un élément marqué par l'utilisateur comme non‑issue dans **not‑issues.md**. Veuillez toujours répondre dans la langue de l'utilisateur.
