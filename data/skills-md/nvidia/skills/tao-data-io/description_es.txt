El data‑mover para trabajos TAO — decide el nivel de almacenamiento (A montaje preposicionado sin fetch / B volumen desde S3 / C fetch efímero dentro del cómputo), prepara las entradas (bulk + selección por anotación + extracción de archivo + HF/NGC PTM), asigna credenciales al entorno, enruta las salidas en tres vías con exclusiones de carga y ejecuta la puerta de verificación del marco de cómputo. Una habilidad de soporte y otras habilidades de plataforma (docker, kubernetes, slurm, brev, virtualenv) se invocan para obtener datos hacia y desde el contenedor de cómputo sin el SDK de TAO. Las frases disparadoras incluyen “stage inputs”, “mount the dataset”, “upload TAO results”, “download only referenced files”, “resolve results_dir”, “verify the container can read the data”.
