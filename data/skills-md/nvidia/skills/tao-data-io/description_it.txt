Il data-mover per i job TAO — decide il livello di archiviazione (A mount pre‑posizionato con zero fetch / B volume‑da‑S3 / C fetch effimero in‑compute), prepara gli input (bulk + selettivo per annotazione + estrazione da archivio + HF/NGC PTM), mappa le credenziali all’ambiente, instrada gli output in tre vie con esclusioni di upload e avvia il gate di verifica del compute‑frame. Un’abilità di supporto altre abilità di piattaforma (docker, kubernetes, slurm, brev, virtualenv) chiamano per ottenere dati da e verso il contenitore di calcolo senza il SDK TAO. Le frasi di attivazione includono “stage inputs”, “mount the dataset”, “upload TAO results”, “download only referenced files”, “resolve results_dir”, “verify the container can read the data”.
