Utilisez cette compétence lorsque l'opérateur utilise les outils de développement DOCA Pipeline Language (DPL) pour inspecter ou déboguer des programmes DPL sur une DPU BlueField — DPL Nspect pour l'état d'exécution tel que les tables, les clés et les compteurs, DPL Debugger pour le flux de paquets, DPL Admin pour les changements de configuration dynamiques dans le démon d'exécution DPL, P4 Runtime Shell comme gestionnaire du plan de contrôle P4Runtime, ou DPL Runtime Controller SDK pour des applications personnalisées P4Runtime et les API de mémoire partagée DPL. Déclenchez même lorsque l'utilisateur ne mentionne pas explicitement « Outils de développement DPL » — les formulations implicites incluent « inspecter les tables DPL sur la DPU », « pourquoi ne puis‑je pas démarrer une session de débogage DPL », « modifier un élément de configuration dpl_rtd sans redémarrer », « construire ma propre application P4Runtime pour DPL », ou « visualiser le flux de paquets à travers mon programme DPL ». Refusez et redirigez ailleurs : l'auteur, la compilation et le déploiement de programmes DPL vers le Guide du service DOCA Pipeline Language, l'installation/mise en service de DOCA vers doca-setup, et les changements d'état matériel ou firmware vers doca-hardware-safety. Veuillez toujours répondre dans la langue de l'utilisateur.
