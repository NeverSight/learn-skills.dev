# claat 手順書ワークフロー統括

工程を進行させるのがこの skill の仕事で、**本文は書かないし、lint の直し方も決めない**。書くのは `claat-writer`、直して HTML にするのは `claat-build` が担当する。ここが持つのは、その 2 つの間で落ちるもの——順序、差し戻し、完了条件——だけになる。

## 1. 今どこにいるかを決める

工程を頭から始めるとは限らない。手元にあるものを見て入口を選ぶ。

| 手元にあるもの | 入口 |
| --- | --- |
| 素材だけ（ソース、README、メモ、URL） | `claat-writer` から始める |
| `.md` がある（書きかけを含む） | まず `claat-build` の lint で現状を把握する。診断を見てから、直しで済むか書き直しかを決める |
| `.md` があり lint が通る | `claat-build` で HTML を生成する |
| HTML まであるが内容を直したい | 直すのは `.md`。生成物は触らない（→ §3） |

分からなければ `.md` の有無を確認し、あれば lint を 1 回回す。診断は現状把握として最も安く、最も情報が多い。

## 2. 工程の順序を守る

```text
素材 → 執筆(claat-writer) → 日本語チェック → claat lint → build(claat-build) → 報告
                  ↑                                    │
                  └──────── 本文を書き足す必要が出たら ──┘
```

順序を入れ替えない理由がそれぞれにある。

- **日本語チェックは claat lint より先。** 日本語を直すと行がずれ、画像の相対パスや `Duration` の位置が壊れることがある。逆順にすると通ったはずの lint をもう一度落とす
- **lint は build より先に単独で回す。** `build` は lint に落ちた時点で止まるので、診断を先に全部見てまとめて直したほうが往復が減る
- **本文を書き足す必要が出たら `claat-build` の中で書かない。** 執筆は `claat-writer` に戻す。日本語チェックを通さない文が 1 段落だけ混ざるのが、この工程で最も起きやすい品質の穴になる

## 3. 生成物を編集しない

`output/<id>/index.html` は毎回作り直される。ここを直しても次のビルドで消えるうえ、`.md` と HTML の内容が食い違ったまま気づけなくなる。**直す対象は常に `.md`** で、HTML は確認のために開くだけにする。

`id` を変えると出力ディレクトリの名前も変わり、古いディレクトリはそのまま残る。作り直しで `id` を変えたときは、古い出力を消すかどうかをユーザーに確認する。

## 4. 画像で止まらない

このワークフローで唯一、こちらの都合で進められない待ちが画像になる。`claat-writer` は撮影依頼リストを出し、ユーザーが `images/` に置き、`claat-build` の lint が実在を検証する。この 3 つは非同期に起きる。

**待たない。** 画像が揃うまで工程全体を止めるのではなく、画像を必要としない範囲を全部先に通す。`.md` を書き上げ、日本語チェックを通し、画像以外の lint エラーを潰しきったところで、撮影依頼リストを添えてユーザーに渡す。画像が届いたら lint と build を回すだけで済む状態にしておく。

未撮影の画像パスを `.md` に先に書かない。lint が実在を確認するので、書いた時点でビルドが止まり、それ以降どの工程も進められなくなる。

## 5. 差し戻しの上限を決める

build が失敗したら直して再ビルドする。ただし**同じ文書で 2 往復まで**にする。

3 往復目に入るなら、原因はたいてい文書ではなく別のところにある。素材が足りていない、`claat` の環境が壊れている、そもそも書こうとしている手順が確定していない、のいずれかが多い。回数を重ねるより、何が分かっていないかをユーザーに返したほうが早い。

同じ診断コードが 2 回続けて出た場合も同じ扱いにする。直し方が効いていないので、直し方を変えるか、前提を疑う。

## 6. 完了の条件

次の 3 つが揃って完了になる。ひとつでも欠けているなら「できました」と言わない。

1. `go run github.com/nogikun/claat/cmd/claat-tools@v0.1.0 lint <file>` が終了コード 0
2. `output/<id>/index.html` が実在する
3. 残っている宿題が一覧でユーザーに伝わっている

3 は特に落としやすい。次を漏らさず伝える。

- 未撮影の画像（どの画面を、どのパスに置いてほしいか）
- 素材から確認できず「未確認」のまま残した記述
- ユーザーにしか決められなかったメタデータ（`summary` の文言、`feedback link`、`analytics account`）

頼まれていなければ、生成物のコミットも公開もしない。
