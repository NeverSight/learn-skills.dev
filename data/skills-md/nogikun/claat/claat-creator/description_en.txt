claat is the entry point that oversees the entire process of creating a step‑by‑step guide. From the materials (project source, README, notes, existing documents) we write manual.md, run Japanese checks and lint, generate HTML, and report—these steps are assigned to the claat‑writer skill and the claat‑build skill to proceed. When a user makes a request that spans both writing and conversion, such as “create a guide and turn it into HTML,” “produce a complete codelab,” “make a manual for this project and publish it,” or “run the claat workflow,” or when the current stage is unclear (the .md is partially written, lint is failing, images are not yet taken, HTML is outdated), this is always used. If the request is just to write, use claat‑writer; if the request is only to convert/validate an existing .md, use claat‑build directly. Determining the order of steps, deciding on rejections, and confirming completion criteria are the responsibilities of this skill; it does not perform the actual writing of the text or lint corrections.
