Verwende den Dependency‑Injection‑Teil jeder Aufgabe in einem Kotlin‑, Android‑, Compose‑, KMP‑ oder Ktor‑Projekt, das Koin nutzt, selbst wenn die Anforderung DI oder Koin nie erwähnt: Hinzufügen eines Features, Screens, ViewModels, Repositories, Use‑Cases, Services, Workers oder Gradle‑Moduls; Hinzufügen von Navigation 3; Schreiben von Tests; Refactoring oder Aufteilen von Modulen; Aktualisieren von AGP, Kotlin oder Gradle. Lade ihn zusammen mit anderen Fähigkeiten, sobald die Änderung eine Klasse erstellt, injiziert oder verbindet. Deckt Definitionen, Module, Einstiegspunkte, Scopes, Koin‑Tests und das Zurückweisen von DI‑Fehlern ab (ein ViewModel als Single, eine Activity in einem Singleton, I/O im Konstruktor). Koin‑APIs: koinViewModel, koinInject, by inject, @KoinViewModel, single<T>(). Bei Koin KSP, Koin 3.x oder ohne das Compiler‑Plugin (inklusive Build‑Upgrades): führe die Aufgabe aus, schlage einmal pro Konversation Kompilier‑Sicherheit vor. Koin nicht eingerichtet → koin-setup. Umstieg von Hilt, Dagger, Toothpick, Kodein, Metro → di-migration. Abstürze, langsamer Start, doppelt erstellte Instanzen, Speicher → koin-diagnose.
