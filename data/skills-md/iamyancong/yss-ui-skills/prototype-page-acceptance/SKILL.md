# 原型页面还原验收 Skill

## 触发条件

- 用户提供原型图、截图、设计稿、旧项目 view/logic/service 路径。
- 用户要求“参考老项目、照原型、复刻页面、保持和旧系统一致”。
- 开发结果需要人工视觉对照，而不只是接口和类型正确。

## 不适用场景

- 纯逻辑修复、纯 API 对接、无 UI 改动。
- 用户明确要求自由设计，不需要贴近旧页面。
- 组件库内部能力开发，不涉及业务页面还原。

## 硬约束（禁止/必须）

- 开发前必须打开用户给出的旧项目 view 文件、相关 logic/service 文件和当前项目相近页面，不得只看接口。
- 必须把截图/旧页面拆成验收清单：查询区布局、按钮位置、表格工具栏、表格高度/分页、操作列、弹窗/抽屉尺寸、表单 label 宽度和对齐、FormGrid 响应式、字段控件类型。
- Vue3 + YSS UI 列表查询区默认验收“字段在上、查询/重置按钮独占下一行并右对齐”；缩放或窄屏导致字段换行时，按钮必须仍在搜索卡片右下角，不得贴在第一行字段旁。
- 若截图里出现但需求文字没写的通用交互（查询/重置、表格列设置、新增按钮位置、分页器、抽屉底部按钮），默认按截图实现。
- 不允许用“用户没说”跳过截图里明显存在的 UI；只有业务含义不明时才询问。
- 开发后必须运行页面或至少完成类型/构建检查；可运行时必须截图对照首屏和关键弹窗/抽屉。
- 交付说明必须列出“已对照原型的验收项”和“未能验证的项”。

## 标准代码骨架

```text
原型验收清单：
- 查询区：字段数量、FormGrid 响应式列数、label 固定宽度和右对齐、查询/重置按钮右下角位置，缩窄后按钮不贴第一行字段。
- 表格区：YTable、toolbar-config.custom、#toolbar-right 新增按钮、分页、无底部大空白。
- 操作列：按钮可见条件、更多菜单、删除气泡确认文案。
- 抽屉/弹窗：响应式宽度、底部按钮、查看态只读、label 右对齐且宽度统一、缩窄时 2 列变 1 列、备注/长文本占满行。
- 编辑表格：使用 YEditTable，列控件类型、可输入/多选、添加行/删除行、校验。
```

```text
验收输出：
- 通过：查询区三列栅格，查询/重置按钮独占下一行并右对齐；缩窄到字段两行或三行时按钮仍在搜索卡片右下角。
- 通过：表格工具栏右侧为新增和列设置按钮，分页贴底显示，无大空白。
- 通过：抽屉宽度使用 min(90vw, 1200px)，labelWidth 固定且右对齐，FormGrid 从 2 列响应式收缩为 1 列，查看态不显示保存。
- 未验证：后端真实数据返回为空，仅用 mock/空态验证布局。
```

## 交付检查清单

- [ ] 已读取旧项目 view/logic/service 或当前相近页面。
- [ ] 已把截图中可见 UI 转成验收清单。
- [ ] 查询/重置按钮右下角布局、表格工具栏、新增按钮、分页和空白高度已对照。
- [ ] 抽屉/弹窗响应式、label 宽度和右对齐、FormGrid 换列、底部按钮已对照。
- [ ] 编辑表格控件类型、可输入/多选、添加/删除已对照。
- [ ] 已运行类型检查、构建或浏览器截图验证，并说明未验证项。

## 失败兜底策略

- 旧项目代码太复杂时，先提取最终 UI 结构和字段映射，再复用当前项目组件实现。
- 截图与文字需求冲突时，优先按文字业务规则，UI 布局仍尽量按截图；冲突点写入交付说明。
- 无法运行项目时，至少执行静态类型检查并逐项说明哪些视觉项未验证。
