Write code comments the way a senior engineer would — almost none, and the few that survive are short human fragments, not sentences. The code documents itself; a comment is a last resort for what the code genuinely cannot say. Use this WHENEVER writing or editing code in any language, and especially when the user complains that comments are too verbose, too long, noisy, "AI-sounding", essay-like, or that they add lines to a diff or PR. Triggers on "fewer comments", "shorter comments", "stop over-commenting", "these read like AI wrote them", "make comments concise", "the code should self-document", or any time you are about to add a comment to code.
