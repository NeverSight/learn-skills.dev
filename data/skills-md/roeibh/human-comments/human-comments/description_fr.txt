Rédigez les commentaires de code comme le ferait un ingénieur senior — presque aucun, et les rares qui subsistent sont de courts fragments humains, pas des phrases complètes. Le code se documente lui‑même ; un commentaire n’est qu’un dernier recours pour ce que le code ne peut pas réellement exprimer. Utilisez cette règle chaque fois que vous écrivez ou modifiez du code, quel que soit le langage, et surtout lorsque l’utilisateur se plaint que les commentaires sont trop verbeux, trop longs, bruyants, « à la façon d’une IA », essayistes, ou qu’ils ajoutent des lignes à un diff ou à une PR. Cela s’applique aux déclencheurs tels que « moins de commentaires », « commentaires plus courts », « arrêter de trop commenter », « ça ressemble à du texte généré par IA », « rendre les commentaires concis », « le code doit être auto‑documenté », ou chaque fois que vous êtes sur le point d’ajouter un commentaire au code. Veuillez toujours répondre dans la langue de l’utilisateur.
