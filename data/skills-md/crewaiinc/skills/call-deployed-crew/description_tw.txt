透過 HTTP 呼叫在 CrewAI AMP 部署的 crew 或 flow：bearer token 與部署 URL、GET /inputs、POST /kickoff 並帶上 {"inputs": {...}} 的請求主體，哪些 input keys 為必填（{placeholder} 代換字元），使用帶有截止時間與退避機制的 GET /status/{kickoff_id} 進行輪詢，終止狀態與結果所在位置、webhook、POST /resume、首次呼叫較慢，以及撰寫能在重複或同時 kickoff 時仍保持正確的 crew。於撰寫呼叫已部署 crew 的 client、script、backend 或 frontend 時使用；當 kickoff 回傳 422 “Missing inputs: …”、狀態輪詢永不結束、回傳 “NOT FOUND” 或結果欄位為空、/resume 因 executionId 回傳 422、run 的 prompt 顯示其他 run 的資料，或使用者貼上 kickoff_id、/kickoff 的 curl 指令，或出現 “Template variable … not found in inputs dictionary” 時，皆適用此說明。
