Obtenir un crew ou un flow CrewAI sur CrewAI AMP : la forme du projet que la construction attend (uv.lock, type [tool.crewai], points d’entrée src/<pkg>/, une vraie sous‑classe Flow, imports absolus, une racine autonome), `crewai deploy validate`, les trois voies de déploiement (CLI create/push, GitHub, téléchargement ZIP) et ce que chacune téléverse réellement, les variables d’environnement par déploiement et ce que le CLI renvoie depuis .env, les clés de fournisseur et les extras, ainsi que la sélection d’organisation à l’échelle de la machine. À utiliser lors de l’exécution de `crewai deploy create` / `crewai deploy push` / `crewai deploy validate`, lorsqu’un déploiement indique Online mais exécute du code ancien, des valeurs d’environnement obsolètes ou qu’une clé a disparu, ou lors du collage d’erreurs telles que `missing_lockfile`, `Crew class annotated with @CrewBase not found`, `No Flow subclass found`, `Expected to find at least one of these files: uv.lock or poetry.lock`, `OPENAI_API_KEY is required`, `Anthropic native provider not available`, `deployment_not_found`, `git_clone_failure`, `Automation error, fix the code and deploy again`, ou `pyproject.toml not found`.
