# 海龟汤 skill

## 任务路由

先判断当前任务：

- 玩汤：只展示汤面，按玩家提问回答，不主动泄露汤底。
- 出汤：设计事实链、汤面、汤底、主持手册和提示阶梯。
- 审汤：检查唯一性、公平性、因果、物理可行性和玩法执行。
- 研究本地题库：用户明确提供本地数据库或语料时，读取相关记录并提炼抽象规律。

没有本地题库时，直接使用本 skill 的设计规则，不声称做过额外语料训练。

## 出汤流程

1. 写出核心异常：玩家看到的现象为什么值得追问。
2. 写出完整汤底：谁、何时、何地、做了什么、为什么导致异常。
3. 选择一个主机制，最多两个辅助机制，并说明组合的必要性。
4. 建立事实表：人物与身份、时间线、空间边界、物件、认知误差、行动、结果和动机。
5. 为每句汤面标记表层解释、汤底解释和提问入口。
6. 设计最短可行提问路径，让每次答复都缩小关键分支。
7. 设计由弱到强的提示阶梯。
8. 主动寻找另一套同样简洁、同样能解释全部线索的第二解；若存在，继续改写。

汤面和汤底使用连贯文字。只有规则表、档案、对话、阶段信息等真实结构切换时才分段。

## 诡计边界

- 时间：写清事件顺序、时间锚点和玩家可验证的记录。
- 空间：写清边界、视线、出入口、物件位置和行动限制。
- 身份：说明称谓或观察视角如何持续影响事实。
- 感知：说明谁缺失了什么信息，以及缺失为何稳定。
- 语言与叙事：双关、错字、叙述顺序或元叙事必须能从原文回扣。
- 规则与系统：写明触发、作用对象、允许行为、答复边界和结束条件。
- 媒介与第四面墙：依赖外部媒介或现场行为时，提供玩家能够获得的文字或行动替代路径。

本格与变格不是质量等级。变格可以严谨，本格也可能松散；评价始终以公平、闭合和唯一为准。

## 主持模式

标准模式：

- 只在玩家提问后回答，优先短答。
- “是”表示问题与汤底事实一致；“否”表示不一致；“是也不是”只用于问题同时包含真和假两层；“不重要”表示该信息不影响核心还原。
- 记录已确认事实，保持前后一致。
- 玩家越界时，给出最小必要澄清，不替玩家完成推理。

机制汤模式：

- 分开 surface、solution、host_manual 和 mechanism 四层。
- mechanism 至少包含触发、状态、玩家可见信息、主持回应、推进条件、失败或结束条件。
- 若机制是故事真相的一部分，区分故事事实与游戏规则。
- 主持人改变答复依据时，必须有玩家可感知的阶段变化和故事内理由。

需要机制字段、状态机或多阶段玩法时，读取 references/host-mechanism-schema.md。

## 质量审查

硬门槛：

- 汤面和汤底是连贯文字，关键事实没有在揭晓时才首次出现。
- 汤底能逐句解释汤面；人物、时间、空间、物件和行动互不冲突。
- 动机足以推动关键行为。
- 特殊设定有稳定边界，不靠临时宣布规则。
- 至少一条关键线索能排除主要错误模型。
- 主持答复可执行，玩家换种问法时判定不变。

软指标：

- 异常具体，而不是只有气氛。
- 线索同时服务表层误导和底层回收。
- 存在清晰的模型转换点。
- 情感和主题进入行动因果，而不是汤底附录。
- 红鲱鱼有误导价值且不会制造第二解。
- 长度服务推理，形式服务信息结构。

需要分类、组合机制或主题标签时，读取 references/reasoning-element-taxonomy.md；需要逐项评分时，读取 references/fairness-rubric.md。

## 可选本地题库

只有在用户提供本地数据库并要求研究、检索、复盘或二次训练时，才读取 references/local-database-extension.md。推荐把“二次训练”理解为本地检索增强和规则提炼；模型参数微调属于独立工程，不是本 skill 的必要步骤。

本地题库的作用是提供事实样本和风格对照，不是替代质量审查。每次提炼都要区分可迁移优点、原题事实和待复核风险。

## 输出契约

出汤默认输出：标题、难度、玩法模式、主/辅机制、汤面、汤底、事实链、关键线索表、主持答复、提示阶梯、第二解审计和设计点评。

游玩时只输出当前阶段允许看到的内容；公布时按“事实链 → 初始误导 → 线索回收 → 第二解排除 → 设计评价”还原。
