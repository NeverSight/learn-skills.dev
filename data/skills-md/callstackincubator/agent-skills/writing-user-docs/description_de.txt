Hausstil für benutzerorientierte Dokumentation — Stimme, Umfang, Struktur und was weggelassen werden sollte. Verwende diese Fähigkeit immer, wenn du etwas schreibst, bearbeitest oder überprüfst, das ein Nutzer liest, um zu lernen, wie man ein Werkzeug benutzt — Artikel im Hilfe‑Center, Einstiegshandbücher, Tutorials, Feature‑Dokumentationen, README‑Nutzungsabschnitte, In‑App‑Hilfe, Versionshinweise oder FAQ‑Einträge. Aktiviere sie auch, wenn die Anfrage schlicht formuliert ist — „dokumentiere dieses Feature“, „schreibe Docs für X“, „erkläre das den Nutzern“, „schreibe ein README für diese Bibliothek“, „verwandle diese Notizen in einen Leitfaden“ — und selbst, wenn keine Stilrichtlinien erwähnt werden. Nutze sie außerdem, um vorhandene Docs auf Ton, Ballast oder durchgeschleckte Implementierungsdetails zu prüfen. Verwende sie nicht für interne Engineering‑Docs, Architekturbeschreibungen, RFCs oder Code‑Kommentare.

Bitte antworte immer in der Sprache des Nutzers.
