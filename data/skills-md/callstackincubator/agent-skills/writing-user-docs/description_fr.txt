Style de rédaction pour la documentation destinée aux utilisateurs — ton, portée, structure et ce qu'il faut exclure. Utilisez cette compétence chaque fois que vous écrivez, éditez ou relisez tout ce qu'un utilisateur lit pour apprendre à utiliser un outil — articles du centre d'aide, guides de démarrage, tutoriels, documentation des fonctionnalités, sections d'utilisation du README, aide intégrée, notes de version ou FAQ. Activez‑la même lorsque la demande est formulée simplement — « documenter cette fonctionnalité », « rédiger la doc pour X », « expliquer cela aux utilisateurs », « écrire un README pour cette bibliothèque », « transformer ces notes en guide » — et même lorsqu'aucune consigne de style n'est mentionnée. Utilisez‑la également pour revoir la documentation existante afin de vérifier le ton, le superflu ou les détails d'implémentation fuités. Ne l'utilisez pas pour les documents d'ingénierie internes, les descriptions d'architecture, les RFC ou les commentaires de code.

Veuillez toujours répondre dans la langue de l'utilisateur.
