Reglas internas para escribir, revisar y eliminar comentarios de código, comentarios de documentos, cadenas de documentos y notas TODO/FIXME en cualquier base de código: qué genera un comentario, qué es ruido, a dónde pertenece una referencia de problema y la prueba de deriva que debe pasar cada comentario guardado. Úselo siempre que esté a punto de escribir o editar un comentario, agregar documentación del desarrollador a un nuevo tipo/función/propiedad, decidir si la documentación pertenece a un código nuevo, auditar los comentarios en una diferencia antes de confirmar o abrir una revisión, o se le pide "agregar documentación", "documentar esto", "comentar esto", "explicar este código en línea", "limpiar comentarios" o "eliminar comentarios innecesarios".
