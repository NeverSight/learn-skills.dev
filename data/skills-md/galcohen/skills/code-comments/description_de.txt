Hausregeln für das Schreiben, Überprüfen und Bereinigen von Codekommentaren, Dokumentkommentaren, Dokumentzeichenfolgen und TODO/FIXME-Notizen in jeder Codebasis – was einen Kommentar verdient, was Rauschen ist, wo ein Issue-Verweis hingehört und der Drifttest, den jeder aufbewahrte Kommentar bestehen muss. Verwenden Sie diese Option immer dann, wenn Sie im Begriff sind, einen Kommentar zu schreiben oder zu bearbeiten, Entwicklerdokumentation zu einem neuen Typ/einer neuen Funktion/Eigenschaft hinzuzufügen, zu entscheiden, ob die Dokumentation zu neuem Code gehört, die Kommentare in einem Diff zu prüfen, bevor Sie eine Überprüfung durchführen oder öffnen, oder wenn Sie aufgefordert werden, „Dokumentation hinzuzufügen“, „dies zu dokumentieren“, „dies zu kommentieren“, „diesen Code inline zu erklären“, „Kommentare zu bereinigen“ oder „unnötige Kommentare zu entfernen“.
