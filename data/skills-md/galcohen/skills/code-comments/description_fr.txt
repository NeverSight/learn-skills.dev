Règles internes pour l'écriture, la révision et l'élagage des commentaires de code, des commentaires de document, des docstrings et des notes TODO/FIXME dans n'importe quelle base de code : qu'est-ce qui mérite un commentaire, qu'est-ce que le bruit, à quelle place appartient une référence de problème et le test de dérive que chaque commentaire conservé doit réussir. À utiliser chaque fois que vous êtes sur le point d'écrire ou de modifier un commentaire, d'ajouter la documentation du développeur à un nouveau type/fonction/propriété, de décider si la documentation appartient au nouveau code, d'auditer les commentaires dans une comparaison avant de valider ou d'ouvrir une révision, ou si vous êtes invité à "ajouter de la documentation", "documenter ceci", "commenter ceci", "expliquer ce code en ligne", "nettoyer les commentaires" ou "supprimer les commentaires inutiles".
