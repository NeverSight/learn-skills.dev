Detects which frontend architecture convention a repo (React/Next.js/ monorepo) uses, and tells you where an app-wide shared component/hook/ utility should live — the `ui/` vs. feature-specific boundary, and 9 other repo shapes beyond it (monorepo, Feature-Sliced Design, shadcn-vendored, …). Use it when the user asks "where do I put this component", "should this be a shared component", "where does shared stuff go", is creating a new cross-cutting component, or is evaluating/migrating the frontend folder organization. Complements `architecture`, which covers feature- module folder structure but not this app-wide-shared-component boundary. Do NOT trigger for a component that's clearly feature-specific already — see `architecture`.
