Schreibe, prüfe oder verbessere Pull‑Request‑Titel und -Beschreibungen nach Best Practices — klares Titel‑Format, strukturierte Beschreibung (Was/Warum/Wie/Testen), verknüpfte Issues und eine prüferfreundliche Checkliste. Verwende dies immer, wenn der Nutzer bittet, einen PR zu schreiben, einen PR zu öffnen, eine PR‑Beschreibung zu entwerfen, die PR‑Qualität zu prüfen oder einen Branch zum Merge vorzubereiten. Außerdem auslösen bei Ausdrücken wie „เขียน PR“, „PR description“, „commit message for PR“ oder „ready to merge?“.

Bitte immer in der Sprache des Nutzers antworten.
