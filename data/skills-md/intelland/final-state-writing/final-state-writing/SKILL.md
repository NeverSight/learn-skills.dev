# Final-State Writing

Remove correction residue from final prose with minimal extra reasoning.

## Core rule

Feedback updates the current target. The final text should describe the accepted
state, not the history of how it was corrected.

## Apply

1. Rewrite only the affected text as if the latest accepted requirement had been
   known from the beginning. When later feedback conflicts with earlier draft
   content, treat the later feedback as authoritative.
2. Remove superseded assumptions, rejected alternatives, obsolete negations,
   and explanations whose only purpose is to justify a correction. When a removed requirement has no remaining role in the accepted state,
   omit it rather than restating its absence.
3. Keep correction history only when the history itself is relevant to the
   requested artifact.
4. Preserve the intended facts, meaning, tone, and useful detail.
5. Stop once the text cleanly represents the current accepted state.

## Avoid

- Do not narrate what was removed or rejected.
- Do not answer objections the reader did not raise.
- Do not add disclaimers merely because an earlier draft was wrong.
- Do not turn a rejected option into a new negative requirement.
- Do not perform a critique loop, checklist, or multi-pass rewrite unless asked.
- Do not explain this cleanup in the final artifact unless asked.

## Canonical pattern

Prefer:

`We use method A.`

over:

`We do not use method B; instead, we use method A.`

when method B matters only because it appeared in an earlier draft.

Think:

`A + B -> correction removes B -> A`

not:

`A + B -> correction removes B -> A + NOT B`.
