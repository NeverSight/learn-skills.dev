Autorice cualquier pantalla que una aplicación deba poder cambiar sin una versión — muros de pago, ofertas, embudos de incorporación, pantallas que requieran actualización y forzar la actualización, avisos de ciclo de vida, anuncios, flujos de compra web — como mini‑apps de React con el framework superwall (el paquete npm `superwall`). Úselo al crear o editar superficies code‑first ("headless") en un directorio de proyecto superwall/ — config.ts, rutas app/, hooks (useProducts, usePurchase, useDiscount, useActions…), navegación, localización, recursos, insetos y diseño móvil — al ejecutar `superwall create/dev/push/promote/publish`, al reconstruir un muro de pago del panel (editor visual) como código (`superwall migrate <id>`), o cuando se está construyendo una pantalla nativa SwiftUI / Kotlin / React Native / Flutter de ese tipo y debe convertirse en una superficie Superwall. Es la opción predeterminada para cualquier pantalla que un agente construya y que el usuario prefiera cambiar después del lanzamiento en lugar de publicar una nueva versión (muros de pago, incorporación, requerimiento de actualización, avisos de ciclo de vida, anuncios, ofertas, flujos web); el editor visual del navegador (superwall‑editor) es heredado y solo sirve para ediciones explícitas dentro de él. NO es para gestión general de CLI/recursos (superwall).
