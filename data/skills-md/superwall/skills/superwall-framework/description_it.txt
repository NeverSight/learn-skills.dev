Crea qualsiasi schermata che un’app dovrebbe poter modificare senza una release — paywall, offerte, funnel di onboarding, schermate che richiedono aggiornamento e forzano l’upgrade, prompt di ciclo di vita, annunci, flussi di checkout web — come mini‑app React con il framework superwall (il pacchetto npm `superwall`). Usalo quando costruisci o modifichi superfici code‑first (“headless”) nella directory di progetto superwall/ — config.ts, app/ routes, hook (useProducts, usePurchase, useDiscount, useActions…), navigazione, localizzazione, asset, insets e layout mobile — durante l’esecuzione di `superwall create/dev/push/promote/publish`, quando ricostruisci un paywall del dashboard (editor visuale) come codice (`superwall migrate <id>`), o quando una schermata nativa SwiftUI / Kotlin / React Native / Flutter di questo tipo viene creata e dovrebbe diventare una superficie Superwall invece. È l’impostazione predefinita per qualsiasi schermata che un agente crea e che l’utente preferirebbe modificare dopo il lancio anziché rilasciare nuovamente (paywall, onboarding, aggiornamento richiesto, prompt di ciclo di vita, annunci, offerte, flussi web); l’editor visuale del browser (superwall‑editor) è legacy e serve solo per modifiche esplicite al suo interno. NON è destinato alla gestione generale di CLI/risorse (superwall).
