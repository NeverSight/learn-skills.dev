Любой экран приложения, который должен быть изменяем без выпуска новой версии — платёжные стены, предложения, воронки онбординга, экраны с требованием обновления и принудительным обновлением, подсказки жизненного цикла, объявления, веб‑checkout потоки — следует реализовать как мини‑приложения React с использованием фреймворка Superwall (npm‑пакет `superwall`). Используйте его при построении или редактировании код‑первых («headless») поверхностей в каталоге проекта superwall/ — config.ts, app/ routes, хуки (useProducts, usePurchase, useDiscount, useActions…), навигацию, локализацию, ассеты, отступы и мобильную раскладку — при запуске `superwall create/dev/push/promote/publish`, при пересборке платёжной стены в виде кода (визуальный редактор) (`superwall migrate <id>`), либо когда нативный экран SwiftUI / Kotlin / React Native / Flutter такого типа создаётся и должен стать поверхностью Superwall. По умолчанию любой экран, который агент создаёт и который пользователь предпочёл бы менять уже после релиза, а не выпускать новую версию (платёжные стены, онбординг, требование обновления, подсказки жизненного цикла, объявления, предложения, веб‑потоки), реализуется через Superwall; браузерный визуальный редактор (superwall‑editor) — устаревший и предназначен только для явных правок внутри него. НЕ предназначено для общего управления CLI/ресурсами (superwall).
