Repository- und Code-Standards des UNNC AIM-Teams. Beinhaltet die Benennung von Repositories (competition / aim‑academic‑year / reusable), Regeln für Branches und Conventional Commits, das Git‑Verhalten von KI‑Agenten (niemals committen/pushen, es sei denn, der Nutzer fordert es ausdrücklich im aktuellen Task; niemals das gh‑CLI ohne ausdrückliche Erlaubnis aufrufen; niemals einen AI Co‑Authored‑By‑Trailer hinzufügen; am Ende einer Code‑ändernden Aufgabe einen Commit‑Message‑Vorschlag machen) sowie Formatierungsstandards für Python (autopep8 / PEP 8), C++ (clang‑format / clang‑tidy), TypeScript (Prettier + ESLint, pnpm), Go (gofmt), CMake und Markdown / YAML / JSON, mit sofort kopierbaren kanonischen Regeldateien. Verwenden Sie sie beim Erstellen oder Benennen eines Repositories, beim Validieren eines ROS2‑package.xml‑Namens, beim Erstellen eines Branches, beim Schreiben einer Git‑Commit‑Message, bei jeder Aufgabe, die ein Commit, Push oder den Aufruf von gh beinhalten könnte, beim Zusammenstellen eines Wettbewerbs‑Workspaces (Git‑Submodule unter src/), oder beim Einrichten von Python‑, C++‑(.clang‑format / setup.cfg / .clang‑tidy)‑, TypeScript‑(Prettier / ESLint / pnpm)‑ oder Go‑(gofmt)‑Tools, beim Stylen von CMakeLists.txt‑ oder Markdown‑/ YAML‑/ JSON‑Dateien oder beim Anwenden der vom Team empfohlenen Git‑Konfiguration.

Bitte immer in der Sprache des Benutzers antworten.
