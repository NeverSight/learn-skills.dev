Usa questa competenza ogni volta che una pull request è aperta, riaperta o sincronizzata in microsoft/apm per valutare se e come il corpus della documentazione deve cambiare per rimanere coerente con la modifica di codice proposta. Attivalo anche quando il titolo o il corpo della PR non menzionano la documentazione — la competenza deve essere eseguita su ogni PR per rilevare eventuali scostamenti silenziosi tra codice e documentazione. Classifica l’impatto come nessuna modifica, modifica in loco (uno o pochi paragrafi) o cambiamento strutturale (nuova pagina o riorganizzazione del TOC), quindi orchestra un loop CDO + scrittore di documentazione + architetto Python + responsabile editoriale + growth‑hacker per produrre un avviso pronto per il patch. NON revisiona la qualità del codice, la sicurezza o la copertura dei test. NON esegue merge automatico o push automatico delle modifiche alla documentazione.
