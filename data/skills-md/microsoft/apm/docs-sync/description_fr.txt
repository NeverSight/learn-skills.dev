Utilisez cette compétence chaque fois qu’une pull request est ouverte, rouverte ou synchronisée dans microsoft/apm afin d’évaluer si le corpus de documentation doit changer et comment, afin de rester fidèle au changement de code proposé. Activez‑la même lorsque le titre ou le corps de la PR ne mentionne rien concernant la documentation — la compétence doit s’exécuter sur chaque PR pour détecter une dérive silencieuse entre le code et la documentation. Classe l’impact comme aucune modification, modification sur place (un à quelques paragraphes), ou modification structurelle (nouvelle page ou refonte de la table des matières), puis orchestre une boucle CDO + doc‑writer + python‑architect + editorial‑owner + growth‑hacker pour produire un avis prêt à être intégré. Ne REVOIT PAS la qualité du code, la sécurité ou la couverture des tests. Ne FAIT PAS d’auto‑fusion ni d’auto‑push des modifications de documentation.

Veuillez toujours répondre dans la langue de l’utilisateur.
