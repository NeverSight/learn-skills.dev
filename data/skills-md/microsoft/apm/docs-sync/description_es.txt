Utilice esta habilidad cada vez que se abra, reabra o sincronice una pull request en microsoft/apm para evaluar si y cómo debe cambiar el corpus de documentación para mantenerse fiel al cambio de código propuesto. Actívela incluso cuando el título o el cuerpo de la PR no mencione la documentación; la habilidad debe ejecutarse en cada PR para detectar desviaciones silenciosas entre el código y la documentación. Clasifica el impacto como sin cambios, edición in situ (uno a unos pocos párrafos) o cambio estructural (nueva página o reorganización del TOC), y luego orquesta un bucle CDO + escritor de docs + arquitecto Python + propietario editorial + growth‑hacker para producir un asesoramiento listo para parche. NO revisa la calidad del código, la seguridad o la cobertura de pruebas. NO hace auto‑merge ni auto‑push de ediciones de documentación.
