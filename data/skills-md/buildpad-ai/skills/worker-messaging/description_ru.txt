Переносите длительные задачи из приложения Next.js/Amplify в рабочий процесс Buildpad через RabbitMQ и связывайте задачу → рабочий процесс → рабочий процесс. Охватывается стандартный convention topic‑exchange (один exchange `jobs`, routing key = тип задачи, конверт сообщения, dead‑lettering), сторона продюсера (публикация задачи, fire‑and‑forget) и сторона потребителя (рабочий процесс, который потребляет и может передать задачу другому рабочему процессу), а также как получить живое соединение RabbitMQ из Buildpad Platform MCP (`get_project_detail` → `messaging`). Используйте, когда запрос слишком медленный для request/response, требуется фоновая обработка или когда один рабочий процесс должен передать работу другому. Поскольку продюсер (репозиторий Next.js) и потребитель (репозиторий Node.js worker) находятся в ОТДЕЛЬНЫХ репозиториях, над которыми работают разные агенты, этот навык также генерирует документ передачи между репозиториями, содержащий тему/ключ маршрутизации, схему полезной нагрузки и способ её чтения, намерения пользователя и всё, что необходимо агенту другого репозитория для реализации соответствующей стороны.
