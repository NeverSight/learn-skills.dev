# 分かるように言い直す

ユーザーが分からなかったものを、ユーザーが分かる言葉で言い直す。中身は変えず、伝え方を変える。

## 何が分からなかったかを見極める

言い直す前に、ユーザーが引っかかったものを決める。

- **語**（「〜とは？」）: 作業の中で使い続けた呼び名や、ツールの出力から拾った語であることが多い。
- **つながり**（「どういうこと？」）: 1つずつの文は読めても、何が何の理由なのか、何と何を比べているのかが追えていない。
- **結論**（「つまり？」）: 説明は読めたが、自分にとって何を意味するのか、何を決めればよいのかが分からない。
- **違い**（「〜と〜の違いは？」）: 並んだものの、どこが違い、選ぶと何が変わるのかが分からない。
- **全体**（「分かりやすく」）: 上のどれか1つに絞れない。直前の返答を、経緯を知らない人の目で頭から読み、引っかかる箇所をすべて拾う。

どれか分からないときは、直前の返答で、ユーザーがこのセッションで使っていない語と、指す先が行の中に無い語から当たる。

## 長さの向きを選ぶ

| 言われた言葉 | 向き |
|---|---|
| 「つまり？」「簡潔に」「一言で」 | 短くする。結論を1〜3文で言い、必要な条件だけを残す |
| 「どういうこと？」「小学生でも分かるように」「平易に」 | 前提を足す。結論の前に、知らないと読めない前提を短く置く |
| 「言い換えると？」「分かりやすく」 | 長さは大きく変えない。語と文の組み立てを替える |
| 「〜とは？」 | その語の意味を1〜2文で言い、今の話の中で何を指しているかを添える |
| 「〜と〜の違いは？」 | 違う点だけを並べる。選ぶと何が起きるかまで書く |

表に無い言葉（「噛み砕いて」「簡単に」）は、意味の近い行に当てる。

## 言い直し方

- 結論を先に書く。「つまり」と聞かれたら、最初の文が答えになるようにする。
- 作業の中で付けた呼び名・略称・ファイルの中の語は、ユーザーが使った言葉か、一般に通じる言葉に置き換える。正確さが必要な固有名（ファイル名・コマンド名）は残し、何のためのものかを添える。
- 元の説明に無い因果やつながりを足さない。別々に決めた2つのことを「〜なので〜」でつながない。つながりが分からなければ、別々の文で書く。
- 例えを使うなら1つだけにし、例えのどこが本題のどこに当たるかを書く。
- 前の説明で書いた条件・例外・確かさ（「推定」「まだ確かめていない」など）を、短くするために落とさない。落とすなら、落としたことを書く。
- 言い直しそのものから始める。前の説明のどこが分かりにくかったかの説明や、謝りの前置きは要らない。

書き方は規則 `writing-to-user`（ユーザーへの返答は、経緯を追っていない人が読んで分かるように書く）に従う。この規則がセッションに読み込まれていなければ、同じ本文の `references/writing-to-user.md` を読んでから書く。

## 送る前に

- 言い直した文を、直前の返答を読んでいない人の目で、頭から順に読む。前に戻って読み直した箇所があれば直す。
- 規則 `polishing`（書いた文章は、渡す前に整える）に沿って整える。規則が読み込まれていなければ `references/polishing.md` を、表記で迷ったら `references/styles.md` を読む。
