# セッションの状況を答える

ユーザーが何を目指していて、どこまで進み、自分が何を決めればよいかを、読めば分かるようにする。状況は確かめられる範囲で今の事実に合わせる。

## 伝え方

書き方は規則 `writing-to-user`（ユーザーへの返答は、経緯を追っていない人が読んで分かるように書く）に従う。この規則がセッションに読み込まれていなければ、同じ本文の `references/writing-to-user.md` を読んでから書く。

## 答えの形

次の順に書く。書くことが無いセクションは、見出しごと省く。

```markdown
## 現在のゴール

<このセッション全体で、何を、何のためにしているか>

## 直近の指示

<最後の依頼で取り組んでいること：何を、何のために>

## タスク

| # | タスク | 状態 | 背景・補足 |
|---|---|---|---|
| 1 | … | … | … |

## 直近のステータス

<今どこにいるか。直前に何が終わり、何が動いていて、次に何をするか>

## 判断を求めていること

<ユーザーに決めてもらうことを、「判断の問いかけの書き方」（`references/asking.md`）の形で書く>
```

決めてもらうことが1つだけで、タスクの進み具合など、ほかに伝えることが無ければ、返答を「判断を求めていること」の節だけにしてよい。

見出し・表の列名・状態の語は、返答と同じ言語で書く。

## タスクの状態欄

状態欄は「絵文字＋状態の語」で書く。次の 7 つは固定で、当てはまる場面ではこの組をそのまま使う。

| 状態欄の表記 | 使う場面 |
|---|---|
| ✅ 完了 | 終わっていて、結果を確かめた |
| 🚧 作業中 | 今このセッションで手を動かしている |
| ⏳ 処理待ち | 自分の手を離れて動いているもの（裏で動かした処理、サブエージェント、CI など）の終わりを待っている |
| 🙋 判断待ち | ユーザーが決めないと進められない。判断を求めていることの番号を添える（例：🙋 判断待ち（1）） |
| 📝 未着手 | やることは決まっているが、まだ始めていない |
| ❗ 問題あり | 失敗した、または結果が想定と違って止まっている。何が起きたかを背景・補足に書く |
| ⛔ 中止 | やらないことに決まった。誰の判断かを背景・補足に書く |

絵文字を使わないようにユーザーに言われていれば、状態の語だけを書く。

7 つのどれにも当たらない状態は、その状態を表す絵文字と語の組を作って使ってよい。上の 7 つの絵文字はほかの意味に使わない。

状態欄の絵文字は意味を担うので、整えるときも残す。

## 送る前に

書いた報告を、規則 `polishing`（書いた文章は、渡す前に整える）に沿って整える。yomiyasu は呼ばない。規則が読み込まれていなければ `references/polishing.md` を読む。表の構造も残す。
