StarSling の `sling` CLI を使用して GitHub Actions の失敗を診断し、CI の時間とコストを帰属させます。ユーザーがジョブや実行の失敗理由、実行の遅延要因、ランナーミニットや CI コストについて尋ねたり、再実行やキャンセルを要求したり、GitHub Actions の URL を貼り付けたときは、`gh` を使用したりログを取得する前に必ずこれを呼び出してください。`sling` はログの grep だけでは見逃すサーバー分類の失敗原因とコスト帰属情報を返します；状態変更は `gh` にルーティングされます。リポジトリ全体のワークフローファイルの監査（ci-score、ci-speedup、ci-secure）やワークフロー YAML の作成、GitHub Actions 以外の CI には使用しないでください。
