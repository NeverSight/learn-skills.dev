使用 StarSling 的 `sling` CLI 诊断 GitHub Actions 失败并归因 CI 时间和成本。每当用户询问作业或运行为何失败、运行为何慢、关于 runner 分钟或 CI 成本、请求重新运行或取消运行，或粘贴 GitHub Actions URL 时，需在使用 `gh` 或获取任何日志之前先调用它——`sling` 会返回服务器分类的失败原因和成本归因，日志搜索难以捕获；状态变化则交由 `gh` 处理。此工具不用于仓库范围的工作流文件审计（ci-score、ci-speedup、ci-secure）、编写工作流 YAML，亦不适用于非 GitHub Actions 的 CI。

请始终使用用户的语言作答。
