リポジトリの GitHub Actions ワークフローを、10 の重要な CI/CD 攻撃ベクトル（テンプレートインジェクション、特権で実行されるフォークコード（pwn リクエスト）、キャッシュ汚染、偽装アクション SHA、シークレット漏洩、GITHUB_ENV ハイジャック、write‑token の信用できないトリガー、キャッシュ／アーティファクト内の認証情報、検証されていないリモートコード実行（curl|bash および可変 fetch‑and‑run）、シークレットを保持するジョブ内で実行される依存関係インストールスクリプト）をスキャンし、各検出結果を平易な英語の攻撃シナリオとともに報告、設定の衛生チェック（合格／不合格）を実施し、選択された検出項目はサブエージェントで自動修正します。意図的に網羅的ではなく、重要なエクスプロイトチェーンチェックのみを対象とします（references/why‑these‑ten.md）。  
使用例：ユーザーが CI/CD または GitHub Actions のセキュリティ姿勢の監査・レビューを依頼したとき（「CI は安全ですか」「CI のセキュリティを監査して」）や、ci-secure／/ci-secure と呼び出す場合。  
トリガーしないケース：CI の速度・コスト・実行時間の監査（「なぜ CI が遅いのか」）は ci‑speedup を、CI 設定のベストプラクティス評価（「CI を評価して」「CI スコア」）は ci‑score を使用してください。  

常にユーザーの言語で回答してください。
