Scansiona i workflow di GitHub Actions di un repository per i dieci vettori di attacco critici nel CI/CD — iniezione di template, codice fork eseguito con privilegi (richieste pwn), avvelenamento della cache, SHA di azioni impostori, dump di segreti, hijack di GITHUB_ENV, trigger non attendibili con token di scrittura, credenziali in cache/artifatti, esecuzione di codice remoto non verificata (curl|bash e fetch‑and‑run mutabile) e script di installazione di dipendenze che girano in un job che contiene segreti — riporta ogni scoperta con uno scenario di attaccante in linguaggio semplice, più controlli igienici di configurazione pass/fail, e corregge le scoperte selezionate tramite sub‑agent per singola scoperta. Deliberatamente NON completo — solo controlli critici della catena di exploit (references/why‑these‑ten.md). Da usare quando: l'utente chiede di auditare o revisionare la postura di sicurezza CI/CD o GitHub Actions, “il mio CI è sicuro”, “audit della sicurezza del mio CI”, o usa i nomi ci-secure / /ci-secure. NON attivare per: velocità del CI, costi o audit temporali (“perché il CI è lento”) — usare ci‑speedup; valutazione delle migliori pratiche di configurazione CI (“valuta il mio CI”, “punteggio CI”) — usare ci‑score.
