레포의 GitHub Actions 워크플로를 10가지 주요 CI/CD 공격 벡터 — 템플릿 인젝션, 특권으로 실행되는 포크 코드(pwn 요청), 캐시 오염, 가장된 액션 SHA, 시크릿 유출, GITHUB_ENV 탈취, write‑token 신뢰되지 않은 트리거, 캐시·아티팩트에 저장된 자격 증명, 검증되지 않은 원격 코드 실행(curl|bash 및 가변 fetch‑and‑run), 비밀을 보유한 작업 내에서 실행되는 종속성 설치 스크립트 — 에 대해 스캔합니다. 발견된 각 항목을 평이한 영어 공격자 시나리오와 함께 보고하고, 구성 위생에 대한 통과/실패 검사를 제공하며, 선택된 항목은 항목별 서브에이전트를 통해 자동으로 수정합니다. 의도적으로 전체 검사는 아니며 핵심 익스플로잇 체인 검사만 포함합니다( references/why‑these‑ten.md ). 사용 시점: 사용자가 CI/CD 또는 GitHub Actions 보안 상태를 감사·검토 요청할 때, “내 CI가 안전한가?”, “CI 보안을 감사해줘” 등 또는 ci‑secure / /ci‑secure 라는 이름을 사용할 때. 트리거하지 말아야 할 경우: CI 속도, 비용, 실시간 감시와 관련된 질문(“왜 CI가 느리죠?”) — ci‑speedup 사용; CI 구성 베스트 프랙티스 평점(“내 CI 평가해줘”, “CI 점수”) — ci‑score 사용.
