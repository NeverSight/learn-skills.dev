Analyse les workflows GitHub Actions d'un dépôt à la recherche des dix vecteurs d'attaque critiques du CI/CD — injection de modèles, code de fourche exécuté avec des privilèges (requêtes pwn), empoisonnement du cache, SHA d'actions imposteurs, fuites de secrets, détournement de GITHUB_ENV, déclencheurs non fiables avec jeton d’écriture, identifiants dans les caches/artéfacts, exécution de code à distance non vérifiée (curl|bash et fetch‑and‑run mutable), et scripts d’installation de dépendances s’exécutant dans un job contenant des secrets — rapporte chaque découverte avec un scénario d'attaquant en langage clair, ajoute des contrôles d’hygiène de configuration pass/fail, et corrige les découvertes sélectionnées via des sous‑agents par découverte. Délibérément NON exhaustif — seuls les contrôles critiques de chaîne d'exploitation (références/why‑these‑ten.md). À utiliser lorsque : l'utilisateur demande à auditer ou réviser la posture de sécurité du CI/CD ou de GitHub Actions, « is my CI secure », « audit my CI security », ou mentionne ci-secure / /ci-secure. Ne PAS déclencher pour : la vitesse du CI, le coût ou les audits en temps réel (« why is CI slow ») — utilisez ci‑speedup ; l’évaluation des meilleures pratiques de configuration du CI (« grade my CI », « CI score ») — utilisez ci‑score. Veuillez toujours répondre dans la langue de l'utilisateur.
