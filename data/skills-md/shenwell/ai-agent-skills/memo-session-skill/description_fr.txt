Mémoire persistante d’agent IA pour les sessions de codage — connaissance inter‑session qui survit aux réinitialisations de la fenêtre de contexte. Consolidation du bruit de session en faits durables et acheminement via le routage de mémoire vers MEMORY.md, les couches memory/ HOT/WARM/COLD, le wiki du projet, AGENTS.md, les compétences, et la mémoire de portefeuille optionnelle — suivie par Git, avec porte de conflit et limites de température. Transmission d’état lorsque le contexte de chat volatile est perdu ; complète les systèmes vectoriels RAG ou les plateformes de mémoire gérée, sans les remplacer. À utiliser lorsque l’utilisateur dit « wrap up the session », « save what we learned », « handoff », « open loops », « update memory », « agent memory », « persistent memory », « cross‑session persistence », « how to give my agent memory », ou lorsqu’une autre compétence demande un point de contrôle de la mémoire. Aussi pour la mémoire portefeuille/globale, le bootstrap de la mémoire du projet, le journal de session, `/inbox`, le traitement de la boîte de réception, ou l’ingestion de fichiers depuis memory/inbox. Lorsque memo‑session‑mcp est connecté, utiliser `search_all` pour la recherche portefeuille/projet et `reindex_changed` après les écritures. Privilégier après un débogage non trivial ou des corrections de l’utilisateur. Ne pas utiliser pour des anecdotes d’une ligne, des secrets, la configuration de mémoire vectorielle gérée, ou le remplacement de l’historique Git.
