Use when writing, editing, or reviewing code in any language. The rule is one thing: never write a comment on a line you add or change. Covers what to write instead - intent-revealing names, extracted functions, structure that makes the trap impossible, a test that fails when the claim stops being true, and rationale recorded in the PR, the commit message, an ADR or the wiki. Also use when deciding how to make code clear enough to need no comment: naming, extraction, types that make an illegal state unrepresentable, guard clauses, and tests that carry the claim. Also use when a diff adds comments, docstrings, JSDoc, test narration such as Arrange/Act/Assert, section banners, TODO or FIXME markers, or commented-out code. Also use to decide whether something is a comment or a machine-read directive such as eslint-disable, @ts-expect-error, noqa, a shebang, or a license header.
