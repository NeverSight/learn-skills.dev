Verwenden Sie es beim Schreiben, Bearbeiten oder Überprüfen von Code in jeder Sprache. Die Regel ist einfach: Schreiben Sie niemals einen Kommentar in der Zeile, die Sie hinzufügen oder ändern. Es deckt ab, was stattdessen geschrieben werden soll – absichtsoffenbare Namen, extrahierte Funktionen, Strukturen, die die Falle unmöglich machen, ein Test, der fehlschlägt, wenn die Behauptung nicht mehr wahr ist, und die Begründung, die im PR, in der Commit‑Nachricht, in einem ADR oder im Wiki festgehalten wird. Verwenden Sie es auch, wenn Sie entscheiden, wie Sie Code so klar machen, dass kein Kommentar nötig ist: Benennung, Extraktion, Typen, die einen illegalen Zustand nicht darstellbar machen, Guard‑Clauses und Tests, die die Behauptung tragen. Verwenden Sie es auch, wenn ein Diff Kommentare, Docstrings, JSDoc, Test‑Narration wie Arrange/Act/Assert, Abschnittsbanner, TODO‑ oder FIXME‑Marker oder auskommentierten Code hinzufügt. Verwenden Sie es außerdem, um zu entscheiden, ob etwas ein Kommentar oder eine maschinenlesbare Direktive ist, wie eslint‑disable, @ts‑expect‑error, noqa, ein Shebang oder ein Lizenz‑Header.
