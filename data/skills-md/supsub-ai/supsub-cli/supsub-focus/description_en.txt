SupSub focus management — list my focuses, view the aggregated content/articles within a specific focus (filter by read/unread, support pagination), mark an entire focus as read, and delete a focus. It matches phrases such as “my focuses,” “focus list,” “what I’m following,” “the content I follow,” “what content/articles are in focus X,” “what unread items are in focus X,” “how many unread items remain in the focus,” “I’m done with this focus / mark focus as read,” and “delete focus X.” ⚠️ Read status applies only to the whole focus (`mark-read --all`, irreversible): articles do not have a “detail/read” step, so single‑article read marking is not supported. ⚠️ It also matches browsing expressions that use a topic name to refer to a focus, e.g., “show me the recent content of X,” “what’s new in X.” When such a request appears, first run `supsub focus list` to compare X with existing focus titles (including partial matches, case‑insensitive). If it matches, use `focus contents` to pull that focus’s content; if X also matches a subscription source name, present both options for the user to choose; if it matches neither, fall back to `supsub-search` to perform a site‑wide search (do **not** ask the user whether to search, and do **not** treat it as a default keyword search). A focus is a theme‑based content stream aggregated across multiple sources (public account MP / website / Twitter X). ⚠️ Verb discrimination: “focus / focused / what I focus on / focus point” all belong to this skill (focus); only “subscribe / subscribed” go to `supsub-sub` (subscription sources). This skill is not for adding/removing/querying subscription sources (that uses `supsub-sub`), nor for full‑text keyword search (that uses `supsub-search`). The CLI has no command to add a new focus; deletion is irreversible.
