مراجعة عدائية لتصميم واجهة برمجة تطبيقات (API) أو حزمة Go المقترحة قبل تنفيذها، مستندة إلى أسلوب Go في API وتصميم يركز على المجال. يهاجم حدود الحزمة، ملكية الثوابت والحالة المستمرة، دورة الحياة وحالات الفشل، وشكل الأنواع المصدرة والتواقيع، ثم ينتهي بسطر حكم قابل للقراءة آليًا. يُستعمل عند طلب مراجعة تصميم، خطة، اقتراح API، خطة إعادة هيكلة، أو تخطيط نوع أو حزمة جديدة لكود Go، أو عندما يتطلب سير العمل مراجعة شكل API قبل كتابة الكود، حتى وإن كان الطلب يقتصر على "مراجعة هذه الخطة" أو "هل هذا الـ API منطقي".
