実装前の提案された Go API やパッケージ設計に対する対立的レビュー。Go の API イディオムとドメイン駆動設計に基づく。パッケージ境界、イナーシャの所有権と永続化状態、ライフサイクルと失敗状態、公開型とシグネチャの形状を批判的に検証し、最後に機械可読な VERDICT 行で締めくくる。設計、計画、API 提案、リファクタリング計画、または新しい型やパッケージ構成の Go コードをレビューするよう求められたとき、あるいはワークフローでコードを書く前に API の形状をレビューするよう指示されたときに使用する。依頼が「この計画をレビューして」や「この API は妥当ですか」だけであっても適用する。
