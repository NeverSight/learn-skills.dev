JSVMP/VMP Méthodologie de rétro‑ingénierie de protection par machine virtuelle — Lors du traitement de cas difficiles tels que l’interpréteur à grand tableau + boucle de dispatch qui compile la logique originale en bytecode et ne peut pas être récupéré directement avec un AST (par ex., Douyin a_bogus, Geetest 4 w, Ruisu, Ctrip, etc.), adoptez un processus discipliné « d’abord localiser l’interpréteur → instrumenter pour enregistrer les opcodes → désassembler → reconstruire le chemin cible » pour la rétro‑ingénierie, plutôt que d’enlever le code à l’aveugle ou de patcher durement l’environnement. Mots‑clés déclencheurs : « JSVMP », « virtual machine protection », « vmp », « bytecode », « opcode », « large‑array interpreter », « a_bogus », « w parameter », « dispatch loop », « switch interpreter », « cannot strip this code ». Appliquez ceci lorsque la logique de chiffrement cible est du bytecode VM et que la dé‑obfuscation par AST a été confirmée comme inefficace. Portée : ne traite que la méthodologie de restauration du bytecode VM ; une fois l’algorithme récupéré, le remettre à param‑encryptor ; si vous choisissez d’abandonner le calcul pur et de patcher l’environnement, le remettre à env‑patcher.
