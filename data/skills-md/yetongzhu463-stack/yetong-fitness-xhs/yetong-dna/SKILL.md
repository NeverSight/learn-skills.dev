# 叶童健身教练人物底色访谈

把教练的业务、场馆、客群、交付过程、经历和表达习惯整理成唯一的人物 DNA。首次建档默认一次展示六组问题，教练可以一段语音一起回答，再由 Agent 归类、补关键缺口和汇总确认。六组就是默认建档问题全集，后续按当篇内容需要补事实。选题、文案、标题、体检和封面共同读取这份档案，不在各自目录复制人物信息。

## 核心产出

交付一个 `person-dna.md` 文件。它既是本人可以检查的档案，也是下游 Skill 的人物信息真源。

档案必须区分：

- 已由本人确认的事实；
- 尚待确认的推断或缺口；
- 可以公开、仅可内部使用和禁止使用的信息；
- 真实经历、表达偏好与内容创作建议。
- 所在城市、实际服务半径、本地客群底色及经过事实支持的痛点地图。

档案结构见 [人物 DNA 结构](references/person-dna-schema.md)。

## 不变量

1. 不编造人生经历、会员案例、证书、成绩、数字、地点或人物关系。
2. 首次建档必须按 [访谈指南](references/interview-guide.md) 一次展示六组问题和规定开场，不把它拆成每次一组的长链访谈，也不只显示前三组。用户明确想分组回答时可以按其节奏推进。
2a. 收到回答后不再重发六组问卷。先归类已有信息，只把会阻碍当前建档的缺口或矛盾合并追问；没证书、暂时想不到三件高光或没有会员案例就如实标缺口，不强迫补造或继续问完整人生。
3. 用户说得口语化、跳跃或不完整时，先整理再复述确认，不要求用户重新组织。
4. 原话与 Agent 的归纳分开保存。没有获得本人确认的归纳不得写成确定事实。
5. 隐私权限与事实真实性同等重要。禁止公开的信息可以服务内部判断，但不能进入公开内容。
6. 只有状态为 `active` 的档案才算人物 DNA 已激活。`draft` 和 `pending_confirmation` 只能用于继续访谈或请求确认。
7. 更新档案时修改同一真源并提高版本号，不复制出互相冲突的人物档案。
8. 本 Skill 的对象是以本地线下客户为主要业务的普通健身教练。纯线上、全国招生或教同行获客不进入这套内容流程；教练若另有业务，可以作为背景记录，但下游目标始终是其本地潜在会员。
9. 不根据城市标签猜测客群。痛点必须来自教练的真实咨询、成交、会员案例、访谈或明确标注的待验证观察。
10. 不强迫真实经历出现戏剧性转折。长期重复的基础服务、稳定履约和普通训练日常也可以成为有辨识度的故事资产。
11. 追问服务、价格或售后承诺前，先核对用户此前给出的权益和书面规则；已经明确的内容不重复问。口述与既有规则不一致时，保留两种来源并标记待核实，不把临场措辞直接升级为公开承诺。
12. 每次提问前先检查地点来源。只有当前受访教练对本人**当前线下服务城市**的明确陈述，或身份匹配的本人已确认档案，才能用作提问前提。出生地、学习地、第三方故事、示例、测试档案、其他教练档案，以及平台默认地点、IP 定位或无法核实来源的宿主记忆，都不能填入当前服务城市；未知就先问城市，有歧义就核对。
13. 六组中的举例用于帮助回忆，不是这位教练或其会员的事实。表面诉求、深层阻碍与信任顾虑按本人提供的来源整理；不能因“宝妈／女性”等标签推断婚育、焦虑、收入或健康问题。场馆优势、本人优势和客户选择理由分别记录，不把本人自我定位写成会员证言。

## 进入方式

### 首次建档

用户明确首次建档或没有人物档案时（只是缺已有档案路径时先问位置）：

1. 完整读取 [访谈指南](references/interview-guide.md) 的六组提问模板。开头按规定展示“请回答下面几组问题……”原文，再一次输出六组；说明可以用一段或几段语音、口语化和不按顺序回答。城市未知时第一组用中性城市问法，不能填入默认地点；已可靠提供的城市和其他信息可标注已知、无需重复回答。
2. 当前 Agent 能处理语音／转写时，从实际收到的口述提取信息；只有音频而当前没有读取能力时，明确需要可读转写，不能假装已听过。保留自然原话及来源；转写不清的名字、证书、日期、金额和测量值标为待核对，不猜数值。
3. 把散乱或一次性长回答映射到六组及 [人物 DNA 结构](references/person-dna-schema.md)，合并重复内容，记录全部新增字段。没回答的部分标“尚未提供”，不要把问题里的例子补入档案。已有原话足以先记录表达习惯，语气证据不足则标“待校准”。
4. 输出一份六组摘要，把当前事实、来源、关键缺口和拟公开范围集中给本人核对；只补会阻碍当前建档的少数缺口。保存位置未指定时合并询问一次。没有三件高光、证书或效果图不阻止已有基础事实的确认。
5. 本人明确确认前保持 `draft` 或 `pending_confirmation`；确认并通过基础校验后可激活。未提供、待核实或未授权的材料继续留为缺口，下游不得补造。

如果用户的业务主要面向全国线上客群，说明本 Skill 的本地业务假设不成立并停止，不把全国用户强行改写成本地客群。

### 继续访谈

已经存在 `draft` 时：

1. 读取已有内容；
2. 找出会阻碍后续内容工作的关键缺口；
3. 从上次停止位置继续，不重复已经确认的问题。

### 确认与激活

核心信息已经足够时：

1. 将六组回答整理成便于检查的摘要，达到基础条件就请求确认；无需凑满三件高光或补完未提供的细节；
2. 单列矛盾项、推断项、敏感项和拟公开边界；
3. 请求本人确认或更正；
4. 只有收到明确确认后，才把状态改为 `active` 并写入确认日期。`active` 表示已记录的信息获确认，不表示人生故事、会员案例和语气都已完整；下游只使用已知事实，缺什么就针对当篇内容补问什么。

### 更新档案

用户补充新经历、换城市、换场馆、调整业务或纠正旧信息时：

1. 保留新旧信息的时间范围；
2. 标明哪些旧事实已经失效；
3. 更新同一档案的 `profile_version` 和 `updated_at`；
4. 重大变化重新进入 `pending_confirmation`。

用户否定一个城市时，立即停止沿用它。若它只是 Agent 的未确认假设，从当前字段、待确认摘要和后续问题中删除，将服务城市恢复为「未知」，中性询问当前城市；不把被否定的城市留成候选，也不猜另一个城市。若否定的是本人已激活档案中的城市，先标记原信息不再适用并将档案置为 `needs_review`，核对现状后再确认激活。

## 六组建档范围

默认一次展示：①业务定位与一句话场馆优势；②到店会员、服务最多的人群及表面／深层痛点；③客户问题原话与真实处理；④你是谁、资历优势、课程标准及课外服务；⑤最骄傲的三件事与一个匿名成功案例；⑥一句话客户为什么选择你。完整可直接发送的问法见 [访谈指南](references/interview-guide.md)。

六组提供的是采集范围，不是全部字段必须有答案的激活门槛。成长经历、生活关系和旧稿若用户主动讲出就归档；默认不额外启动原来的八／九模块人生访谈。已有已激活的旧档案继续可用，新字段按任务需要补充，不因本次模板更新而失效。

## 最少提问原则

满足以下任一条件时才追问，且优先判断它是否阻碍**当前要做的选题或文案**；不影响当前产出的缺口留到以后：

- 答案会改变人物定位、目标客户或内容方向；
- 不清楚用户实际覆盖的城市区域、通勤范围或到店方式；
- 客群痛点只是行业常识，尚无本地咨询、案例或原话支持；
- 当前选题必须使用某段经历而档案缺少事实；否则先选有来源的服务场景，不为建档而强迫讲人生故事；
- 同一信息出现冲突，需要确定时间范围；
- 不清楚信息能否公开；
- 无法判断一句话是用户原话、他人评价还是 Agent 推断。

低风险的格式、标题和排序由 Agent 直接处理。

## 人物 DNA 就绪度

使用以下状态：

- `draft`：正在访谈，信息可以继续补充；
- `pending_confirmation`：核心档案已经形成，等待本人核对；
- `active`：本人明确确认基础档案，可以被下游 Skill 使用已知事实；缺少的故事、案例或文风仍不可推断；
- `needs_review`：业务、身份或公开边界发生重大变化，暂停个性化生成。

当下游请求发生在档案未激活时，原样使用下面的提示：

> 人物 DNA 尚未激活。当前只能调用通用方法，无法启用个性化选题、真实经历映射与个人表达校准。完成「人物底色访谈」并确认档案后，才能解锁完整的叶童内容方法引擎。

用户可以明确要求跳过访谈并获取通用结果，但下游输出必须标注“通用版本”，不得声称符合本人经历或个人表达。

## 保存规则

1. 优先使用用户明确指定的保存位置。
2. 未指定位置时，在第一次写入前只询问一次保存位置，不静默写入私人目录。
3. 文件名使用 `person-dna.md`；多人建档时，每人使用独立目录。
4. 不把人物档案、访谈原文或私密案例写入本 Skill 目录。
5. 写入后运行：

   从本 Skill 所在目录运行以下命令，或使用脚本的真实绝对路径；不把用户项目当前目录当作 Skill 目录。

   ```bash
   python3 scripts/validate_profile.py /path/to/person-dna.md
   ```

6. 校验失败时保持原状态，修正结构后再请求本人确认。

## 下游交接

主入口、选题、文案、标题、体检和封面接入人物档案时，读取 [下游读取契约](references/downstream-contract.md)。更新模块不读取人物 DNA。根据本次任务挑选相关场馆优势、主力客群、诉求／阻碍、交付标准、服务、高光案例和选择理由；不要求每篇把全部资料写进去。

下游结果必须能指出：

- 使用了哪些已确认的人物信息；
- 哪些创作判断来自人物 DNA；
- 哪些事实仍然缺失；
- 是否触碰公开边界。

## 隐私与证据边界

- 会员案例默认去标识化；公开姓名、照片、聊天记录和健康信息前，要求用户确认已有授权。
- 小城市、固定场馆和窄客群容易被反向识别；即使隐去姓名，也要检查组合信息是否暴露具体会员。
- 医疗、康复和训练效果不得从单个故事上升为普遍保证。
- 他人对用户的评价要标明来源，不把自我评价伪装成第三方背书。
- 身份、证书、业绩和效果数字没有证据时标为待确认。
- 不读取用户没有主动提供或授权的私人文件、聊天记录和联系人信息。

## 完成条件

默认「基础可用」访谈在以下条件满足时完成：

- `person-dna.md` 符合结构要求；
- 本地线下业务、真实服务区域或到店情境、主要客群已明确；
- 至少一个有来源的真实客户问题和一个本人确实在做的服务动作已记录，可支撑首轮选题；
- 目前能观察到的本人原话已保存；样本太少时明确标「语气待校准」；
- 拟公开的当前事实、其余材料的未知权限、矛盾与缺口已单列；
- 本人已经明确确认档案；
- 状态为 `active`；
- 校验脚本返回成功。

没有成长故事、授权会员案例或完整生活资料，不阻止基础档案激活，但相应类型的个性化内容仍不得编造。若基础事实或公开边界尚未确认，保存为 `draft` 或 `pending_confirmation`，不能为缩短流程而擅自激活。用户愿意时可继续深访；不把深访作为获得第一个可用选题的前置收费时间。
