# 叶童本地内容五关体检

本 Skill 只诊断教练**本人**面向其真实服务区域线下潜在会员的具体选题或已有稿件。它从当前教练的已激活人物 DNA 出发，给出有位置、有依据、可立即执行的最小修改；不沿用任何外部 Skill 的诊断文本、模板或例句。五关标准和输出格式见 [体检规则](references/review-rubric.md)。

## 进入条件

- 用户明确交接该教练自己的 `person-dna.md` 路径，并提供一个已选定的具体选题，或一份现成标题、开头、正文、配图方案中的至少一项。只说“我想发减脂内容”时先交给选题 Skill；要求直接写成或整篇改写时交给文案 Skill。
- 先从本 Skill 所在目录运行 `python3 scripts/check_profile.py <person-dna.md>`，或使用脚本的真实绝对路径；不把用户项目当前目录当作 Skill 目录。只有结构有效且 `status: active`，才可进行基于此人的城市、客群、经历、服务和语气的诊断。预检通过不等于单条事实或公开权限已获证实，仍须逐条核对。
- 档案路径未交接时只问路径，不搜索私人目录；身份不一致、多人资料混杂时先确认对象。档案未激活时停止个性化体检，原样提示：

> 人物 DNA 尚未激活。当前只能调用通用方法，无法启用个性化选题、真实经历映射与个人表达校准。完成「人物底色访谈」并确认档案后，才能解锁完整的叶童内容方法引擎。

用户明确要跳过访谈时，仅可提供不引用城市、经历、会员故事或本人语气的通用检查清单，不把它称为个性化诊断，也不替用户激活档案。

旧版 `schema_version: 2` 有效且已激活的档案继续可用；六组新增项是补充依据，不构成重新激活或完整重访的条件。仅当前诊断缺关键证据时补问，缺少与本篇无关的高光、资质或场馆信息不算稿件问题。

## 诊断顺序

1. 确认本轮材料：已选题还是已有稿；人设型、营销型、利他型、流量互动型的主类型是什么；目标本地会员、服务区域、内容形式、可用真实素材和用户实际想获得的反馈。缺少标题或配图时标记“未提供”，不得假装已看过。
2. 从六组 DNA 中仅提取本轮需要的业务定位、主要本地客群及真实目标／阻碍、会员原话与处理、身份／优势、实际课程与课外服务、高光／授权案例和表达样本。用这些依据核对稿件是否命中该人群的问题、标准与信任证据是否匹配、是否像本人；不因未使用全部资料扣分。访谈举例不算事实，本人概括的选择理由不算客户评价；证书名称／范围、饮食跟踪方式／频率和个案公开权限分别核对，不默认每天监督或匿名就可公开。当前对话的新说法若与档案冲突，标为待核对，不擅自覆盖档案。
3. 按 [体检规则](references/review-rubric.md) 逐关检查：本地受众命中、事实与公开边界、第一眼识别、阅读收获与本人表达、制作与验证。对只有选题的材料，只检查选题层面可观察的内容；不臆测成稿表现。
4. 每个发现必须指向用户给出的具体词句、缺失字段或已确认的档案依据。区分“确定问题”“待补证据”“个人偏好”，不把主观审美说成平台规则。训练、营养、身材改变和服务承诺的数值要核对适用对象、时间、条件与证据；会员素材还要核对公开授权和本地反向识别风险。
5. 先交付最影响本地会员理解或信任的 1–3 个最小修改动作；对明显失实、越权公开或医疗效果保证，标为发布前必须解决。用户明确要求改稿时可把诊断交接给文案 Skill，但本 Skill 不自动整篇重写或发布。

## 交付

用简短结论开头。随后按五关列出状态（通过／需修改／缺材料）、证据位置和改法；没有问题的关可以合并为一行。最后给“先改哪 1–3 处”和“发布前需确认什么”。若没有标题、封面、数据或授权材料，明确指出无法判断的范围。不得打出没有可重复标准的总分，不承诺流量、咨询或成交。

诊断是内容制作反馈，不是小红书实时规则核查、法律或医疗意见；若用户主要问敏感词、平台审核或法规，说明该专项不在本 Skill 范围内。
