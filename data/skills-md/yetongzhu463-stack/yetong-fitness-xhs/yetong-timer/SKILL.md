# 叶童每日热点选题

固定的是检索、筛选和输出规则；城市、角色、目标会员、业务、可讲视角与表达来自本次教练自己的 DNA。交付每日 3 个可拍的具体问题，或真实原生任务的创建结果。抖音是热点来源，不是把受众改成健身同行的理由；选题可用于小红书或真人短视频，但不保证跨平台热度。

## 先确定动作

- **创建**：“根据我的 DNA 帮我进行定时任务选题”“每天定时给我热点选题”进入创建准备。只补问尚缺的执行时间、重复频率、时区和资料位置；用户已明确的信息不再问。没有时间不擅自设置早上 9 点，没有时区不根据 IP 或城市推定。
- **试跑**：“今天找 3 个热点选题”“先试跑，不创建”只执行一次内容任务，不调用调度写入。
- **运行**：从已登记的原生任务启动且已有绑定信息时，只执行本次选题。运行不再次创建自身，也不擅自改频率。
- 制作／修改本 Skill 的请求不是创建后台任务的请求；安装本 Skill 也不会自动建立任务。普通“出 5 个选题”属于 `yetong-topic`；“朋友圈每天发什么推广这门课”属于 `yetong-promo`，不是定时授权。任意提醒、课程营销定时写稿或业绩管理不由本模块临时承接。

## 本人档案门槛

1. 只读取用户明确提供或当前任务已绑定的本人 `person-dna.md` 路径／私有文档引用。缺位置只问位置，不扫描私人目录、不拿示例、宿主记忆中的他人资料或叶童本人档案替代。多人档案或身份冲突时先确认对象。
2. 有可执行文件环境时，从本 Skill 目录运行 `python3 scripts/check_profile.py <档案路径>`。退出码为 `0` 且输出以 `active:` 开头后仍须核对逐条事实和权限。有可读的云端文档、但无 Python 时，可逐项核对同一 schema、状态、确认日期和六个必要章节；明确是人工结构核验，不声称运行了脚本。不接受只有“我已激活”的口头声明。
3. 无法读取、未激活、结构无效时显示下列提示，停止个性化选题与新任务创建；只缺引用位置时先追问位置。不得自行激活，也不提供借用私人资料的“通用版定时任务”。

> 人物 DNA 尚未激活。当前只能调用通用方法，无法启用个性化选题、真实经历映射与个人表达校准。完成「人物底色访谈」并确认档案后，才能解锁完整的叶童内容方法引擎。

4. 本人角色、服务区域、本地受众、真实顾虑、相关业务和可公开的经历／服务动作是依据。档案已激活但缺当前关键受众／城市资料时只补问该缺口；旧版有效 `schema_version: 2` 不要求全量重访。不得由女性、宝妈等标签推断痛点。逐条权限规则优先读取包内 `yetong-topic/references/profile-contract.md`；取不到时遵循本节及热点规则中的权限边界。

## 选题规则与依赖

每次运行重新读取当前绑定档案与 [热点检索、筛选和输出规则](references/hotspot-method.md)，不沿用过期的检索结果。

- 优先读取已安装的 `yetong-topic/SKILL.md` 和 `yetong-topic/references/topic-method.md`，复用其中八大元素与四类内容方法。本模块固定数量、热点依据与输出格式优先于常规选题默认的 8 题、全部候选表或咨询导向。
- 如果当前任务绑定了可核验的八大元素 Skill／项目规则，先检查是否为这套方法及当前版本，再读取；不能把名称相似当作已读取。
- 取不到真实方法资源时，使用热点规则中的内嵌八大元素和四类内容规则，写“规则状态：按内嵌规则执行”，说明方法资源未取得。不能声称调用过缺失的 Skill，也不能自动安装依赖。
- 固定目标是对本人本地潜在会员建立专业信任、增加相关曝光。允许从跨行业热点切入及获得非本地观看，但每题必须能回答“我的哪类目标会员，在什么处境下，可以理解或解决什么具体问题？”并说明“为什么适合我这位教练讲”。不把它写成给教练同行上营销课；不要求每题卖课、附购买口令或成交转化。

## 执行

试跑／运行：档案通过 → 当次联网检索并核验时间与数据 → 在实际取得的范围内形成 6—9 个候选 → 按受众业务相关性优先筛出 3 个不同问题 → 只交付最终卡片。无法核验或候选不足时按 reference 明确降级，不编造候选、热榜或指标。

创建：先读取 [原生调度与私有资料绑定](references/scheduling.md)。只有本次创建授权、完整时间配置、可用原生调度能力，以及未来执行环境确实可读取的本人档案和方法全部满足时，才注册任务。优先先试跑检查内容和引用是否可用；试跑不能替代调度成功。宿主无原生能力时交付可复制的任务指令和尚缺条件，明确“未创建”，不写系统 cron、不设置后台常驻进程或借用别的平台工具。

## 输出与停止

- 单次内容仅按热点规则输出最终 3 题及必要依据，不展示完整候选池，不扩写正文、开头、脚本、分镜、封面，不发布或联系客户。
- 只有原生调度成功且取得可核对的任务标识、启用状态、时间／频率及时区后，才确认创建成功，并返回任务名称、标识、启用状态、执行时区、重复频率、下一次运行时间与核验依据。上述创建证据缺失时写“创建结果未确认”，不重复创建。未取得下一次时间须写“未取得”，不能把估算当作平台返回值；不能声称到点执行已验收。
- 不成功时说明原因、哪些准备已完成、缺哪项配置；任务卡和提示词不等于已创建。结果未知时先查原生列表，不重复创建。
- 每次运行复核 active 与分项公开权限；资料失效时停止该次个性化输出并提示修复，不自行改档案或暂停／删除原生任务。私人 DNA、任务配置、历史选题、会员资料及测试记录不进入公开 Skill 目录或 GitHub。
