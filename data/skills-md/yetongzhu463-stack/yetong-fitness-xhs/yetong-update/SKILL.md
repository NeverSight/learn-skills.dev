# YETONG 更新

本模块负责当前安装实例的版本维护。更新源固定为 `yetongzhu463-stack/yetong-fitness-xhs` 的 `main`，具体版本、成员和文件从随包发布清单读取，不使用硬编码的技能数量。[更新方法](references/update-method.md) 说明校验、备份和恢复边界。

默认中文报告，保留原始状态码与错误。网络失败不等于用户账号或技能损坏；只有明确限流依据才称为限流，不把所有 HTTP 403 都归为同一原因，也不保证某个时间必然自动恢复。

## 识别请求

- “检查更新”“有新版本吗”只检查；“更新”“更新叶童技能”“升级 YETONG”已经授权执行本次更新，无须另问一次是否更新。
- “更新我的人物资料／城市／客户信息”交回人物 DNA 模块；“改一下这篇文案”不属于软件更新。
- 此模块不读取人物档案，不要求 DNA 激活。不要把更新请求转成访谈。

## 执行

重新安装／导入的前置保护：无论因缺更新模块还是旧更新器获取失败，都先核对同名目录归属、备份目录中原有文件，并确认人物档案在包外、平台实例相同。安装器可能清空同名目录，不能保证重装保留未知文件；归属不清时停止覆盖。下述接入新版的建议均受此规则约束。

1. 先确认当前 Agent 有文件读取、Python 3、联网和当前 Skill 安装目录的写入能力。从本 Skill 所在目录运行 `python3 scripts/update_bundle.py check`；脚本通过自身真实路径定位当前技能根目录，不扫描用户的其他环境。
2. 用户明确要求更新时运行 `python3 scripts/update_bundle.py apply`。也可使用脚本绝对路径。只有安装位置已经由 Agent 的真实文件状态确定时才使用 `--target <Skills 根目录>`，不得猜目录或把维护者源码工作区当作学员安装目录。
3. 脚本先固定远端提交，再检查发布清单、文件哈希和登记关系；API 无法返回有效提交时，使用官方归档元数据取得提交号，再重新下载该不可变提交的快照，不直接安装浮动分支内容。变更前保存旧文件，失败自动恢复。它只接管旧清单或旧登记表能够证明归属本包的文件；同名未知内容发生冲突时停止，不能替用户覆盖。未知文件、人物档案、其他技能和旧版已移除模块目录保留。
4. 只有脚本报告 `updated` 或 `up_to_date` 且完成运行文件验证时，才说当前安装实例已更新／已是最新完整文件版本。`repair_needed` 表示同版本文件损坏或缺失，需要执行 `apply` 修复。官方获取渠道均失败时停止、不反复刷请求；明确本次是否未写入，或是否已恢复及备份位置，不把未完成说成成功，不擅自创建重试提醒／定时更新。老更新模块无法取得快照时，可说明用原官方安装方式接入新更新器；重装前核对人物档案在包外，平台实例相同。不能把下载完成或文件验证当成宿主加载与持久验证。
5. 更新后展示真实版本、新增可用技能及主入口菜单。当前对话可能仍缓存旧指令；按照宿主的能力重新读取 `yetong/SKILL.md` 和登记表，必要时提示刷新技能列表或开启新对话。

## 手机与云端

手机只是访问入口。若其云端任务环境确实提供 Python、联网和持久可写的目录，可在该实际环境更新；脚本检查的是这一个实例。若宿主只支持上传技能、没有执行工具或安装目录不可写，应明确说明需要在宿主的技能管理页面重新导入最新包，并交付固定仓库链接和待验收清单。一次临时任务中的写入不等于账号级持久安装；不能宣称跨平台自动升级、后台自动更新或更新了所有 Agent。

旧版若尚未安装本模块，需要先用原安装方式重新安装整组技能一次，之后才能通过“更新叶童技能”调用本模块。
