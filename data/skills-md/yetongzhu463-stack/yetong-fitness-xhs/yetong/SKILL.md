# YETONG 主入口

这套方法面向健身教练所在地的线下潜在会员，分为“小红书内容创作、朋友圈营销、业绩管理”三条服务线。每日热点选题归内容线，不是第四类或通用任意任务服务。各线的上线状态须实时读取 [能力登记表](references/capability-registry.json)；登记为 `planned` 的方向不可作为已安装能力承诺。主入口只判断、核验、交接，不自行冒充下游方法。[路由与交接契约](references/routing-contract.md) 解释输入成熟度、档案门槛与冲突处理。只有审核、登记、验证并随运行包交付的模块才可用。仅多放一个目录不算接入。

默认使用中文介绍、解释进度与报告检查结果，除非用户另行指定语言；命令、路径、产品名称和原始错误保留原文。本入口尚未加载时不能控制宿主的安装开场语言，安装请求也需明确要求中文。

## 安装后展示与首次使用

- 用户说“安装好了”“展示全部技能”“打开菜单”“第一次怎么用”时，**先于人物档案门槛**从本 Skill 所在目录运行 `python3 scripts/show_menu.py`，或使用脚本的绝对路径。只有脚本返回运行文件校验通过，才按实际登记内容说明共同入口、人物基础、三条服务线、每个已交付模块的用途和触发语。脚本核对的是该目录的完整资源和哈希，不证明宿主已发现、实际调用或跨会话持久保存。若校验失败，报告具体文件或登记错误，不能把静态介绍当成已安装能力。
- 当前轮如果刚由 Agent 完成安装并继续执行同一请求，立即进行上述展示。单独执行 `npx skills add` 或手机云端安装可能不会自动发起新对话；本 Skill 无法在所有 Agent 上监听安装完成事件。此时请用户说“使用 $yetong，打开技能菜单并检查安装”，不要声称会跨平台自动弹窗。
- 用户没有指定任务、首次调用 `yetong` 时，先给简短的三类菜单与第一步；用户已经提出明确任务时，直接路由，不每次重复长菜单。用户要求朋友圈或业绩管理时，查看登记表服务线状态和模块边界；`active` 不代表整条服务线所有场景都已上线。目前朋友圈只覆盖具体本地课程产品的营销策划与计划内文案，不覆盖泛人设／日常生活发圈；业绩管理仍 `planned`。两者是产品范围／规划，不是安装缺失，不进入缺文件警告或要求补装；不得从服务线 id 拼造未登记的 Skill 调用名。未覆盖时说明边界，不借小红书模块假装已提供。主入口与人物 DNA 是共用基础，不算第四条服务线。

## 安装证据与宿主加载

- 安装检查分别报告“运行文件”“当前宿主发现／调用”“跨会话持久保存”三层状态，未知就写未核实。安装工具的退出码与实际落盘／注册位置属于执行证据；“我将帮你安装／开始执行”只是意图，没有日志时只能说未见执行结果，不能推断成功，也不能凭一句英文判定平台安装失败。当前任务已有安装授权且确有执行工具时继续执行和验收，没有能力时明确说明缺口，不用准备话术结束并假报已完成。
- `--all` 仅选择安装器已支持的全部 Agent 与全部 Skill，不等于自动适配任何云端产品或完成账号级持久安装。优先使用当前宿主已核实的技能管理／启用入口；下载到通用目录后仍需核对宿主是否读取该目录。不能把 CodeBuddy 当作 WorkBuddy。直接按文件路径读取完整 Skill 后处理本次任务，可以报告“本次文件读取方式执行”，但不冒充宿主原生注册。
- 宿主列表未发现而运行文件完整时，分别说清这两个事实；只有真实界面、工具返回或已核实宿主规则支持，才建议对应的手动启用、刷新或新会话加载。未知时不给虚构重扫命令，也不声称“所有平台必须重开”或“新会话一定有效”。缺文件／哈希异常才按具体原因修复或重新导入，规划方向无需重装。
- 未在新任务实际读取同一安装实例，或取得宿主可核对的持久存储与加载证据前，持久状态写“未验证”；不能因本轮补装就保证不会丢失。安装检查不读取或上传私人 DNA，也不自动创建定时任务。

## 固定范围与依赖

旧版缺更新模块、更新器无法取得快照，或确需重新安装／导入时，先核对同名目录归属、备份目录中原有文件，并确认人物档案在包外、更新的是同一实例。安装器可能清空同名目录，不能把重装冒充保留未知文件的安全更新；归属不清时停止覆盖。下述原安装方式接入建议均受此保护规则约束。

- 明确更新本套 Skill，或在 YETONG 工作流内单独说“更新／升级”时，先交给 `yetong-update`，无需人物档案，也不受内容材料门槛影响。“更新我的城市／档案”交给人物模块；“更新这门课程的权益／宣传计划／朋友圈文案”交给课程营销模块维护产品资料卡，涉及本人当前业务或档案中公开承诺的矛盾再回人物模块；“更新小红书文案／标题／封面”按内容请求处理。其他上下文中无法确定要更新哪个对象时只问对象。询问版本或有没有更新只检查，不执行写入。若旧安装没有更新模块，提供本仓库原安装命令以首次接入更新能力。更新可修复缺失模块，因此不先以登记校验失败阻止更新；只核对更新模块自身能读取。
- 固定受众是该教练真实服务城市、商圈或社区的本地线下潜在会员；允许通过泛曝光建立专业信任，不要求每题强卖课。城市、人群、场馆和表达方式只从这位教练自己的档案取得。抖音等平台可作为热点来源，不因此把输出改成教同行获客。`yetong` 是方法品牌，不是所有教练共用叶童档案或口吻的许可。
- 即使某份人物档案还记录其他业务，这套主入口也不将其变成“教同行”的内容目标；明确要求教授教练同行获客时，说明超出范围并停止，不把它列为常规选项让用户选择。
- 本次需要路由时，读取登记表并从本 Skill 所在目录运行 `python3 scripts/validate_registry.py`，或使用脚本的绝对路径；只考虑 `enabled: true` 且实际可读取的能力。登记校验失败时报告具体缺失并停止受影响阶段，不回退到硬编码的旧模块列表。缺少目标 Skill 时说明依赖缺失，不自行安装、复制或临时冒充它。
- 只使用用户明确提供、或本次会话已经明确交接的 `person-dna.md` 路径。不得扫描私人目录猜测档案。用户说“我已有档案”但没有交接路径时，只追问位置；明确没有档案时进入访谈。若用户指定的教练与档案身份不符，或同时出现多人档案，先确认本次用哪位教练的档案，不混用城市与经历。
- 首次建档时交接“已确认的本人服务城市＋来源”，没有可靠来源就交接“城市未知”。示例教练、测试素材、叶童的城市、IP／设备定位和宿主记忆里的他人地点都不作为学员城市。人物模块默认一次展示六组问题，使用指定开场，支持一段语音或文字一起回答；第一组先中性询问真实服务城市，再让用户补充区县／商圈，不预设城市，也不为等城市回答而拆散六组。已知信息直接沿用，不重复问。用户否定某城市时清除该假设，不继续以该城市组织问题。

## 路由顺序

按 [路由与交接契约](references/routing-contract.md) 先看范围和用户想要的结果，再比较登记表里各模块的用途、适用／排除情境、输入和产品适配；示例不是简单关键词触发器。

1. 明确要求教同行获客或全国线上招生时停止本入口。若请求属于登记表里尚为 `planned` 的服务线，或可用线中未交付的场景，说明尚未覆盖，不进入小红书内容模块。新课程可由用户自己构造，产品资料与人物 DNA 分开：同一已确认本地业务中的新课程名称、价格或权益不因档案未收录就强制重建 DNA；课程营销模块记录草案／已确认状态。只有本人身份、服务城市、业务能力或公开承诺实质矛盾才回人物模块核对。草案可内部策划，不能虚写成已在售；公开成稿依赖用户确认真实可交付的产品事实，不擅自补造价格、名额、效能与权益。
2. 要首次建档、继续访谈，或更正本人经历、城市、主要客群、业务能力、服务与公开权限时，交给产出 `active_profile` 的模块。`draft`、`pending_confirmation`、`needs_review` 也回到此处。只补充一门新课程的资料，不等于要重做整份人物档案。
3. 候选模块要求 `profile_requirement: active` 时，先核验**该教练本人**的档案，再执行该登记项声明的 `profile_check <档案路径>`。`optional` 模块可在没有档案时处理不含个人事实的通用任务；一旦要引用该教练的城市、经历、产品或表达，也必须用自己的 `profile_check` 确认 active。退出码 `0` 只说明结构与激活状态可用；下游仍须核对单条事实、授权和适用时间。档案不存在、未激活、结构无效或路径未交接时不得进入个性化输出；只缺路径时只追问路径，其余交回建档模块。
   要“根据我的DNA帮我进行定时任务选题”“每天定时给我3个热点选题”、单次试跑本人热点选题或实际运行已注册热点任务时，进入 `yetong-timer`。该模块每次固定 3 题，绑定本人 active DNA、热点方法与已核实的宿主原生调度能力。单次试跑只执行选题，不自动注册后台任务。创建任务缺时间或时区时只补问缺项，不擅自定为 9 点或一律使用中国时区；创建前核对已有同类任务，避免重复。普通“出5题”仍进 `yetong-topic`；“朋友圈每天4条计划”仍进 `yetong-promo`，每日计划不等于注册调度。任务取消或其他调度管理引导宿主原生任务列表，不把本模块扩成通用管理服务。
4. 检查 `required_any_of`：该列表非空时，至少一种声明的材料须真实存在；空列表不要求另交草稿或已选题。要推新课、问“新课程朋友圈怎么推广”“今天发什么推广这门课”、按课程营销计划写朋友圈或修改课程朋友圈文案，优先进入 `yetong-promo`；产品简介、已有营销计划或课程朋友圈草稿可作为材料。只有推广意愿而没有课程资料时只索取这门产品信息，不回小红书选题。处于同一产品策划流程时，续写、改天数或调整当天内容均保留产品卡与已确认计划，不把“今天发什么”误判为新的小红书选题。纯小红书请求仍走原路线：已有草稿且要整篇改写、或已有具体本地会员问题要成稿时进入小红书写稿／改稿；只要拟标题／改标题时进入标题；只要整篇诊断时进入体检；已有**具体且选定**的本地会员选题或草稿而要封面构图、生图提示词或文字排版时进入封面。封面模块执行叶童原版逐步单题流程；用户回复当前选择题的编号、上传参考图或选择封面文字时，沿用当前封面阶段，不重新路由为选题或笔记标题优化。若上一轮封面模块已交付可执行提示词，本轮只回复“直接生成”或“继续优化提示词”，沿用同一封面任务并回到封面模块；不把这两个短回复当作新选题或写稿请求。“直接生成”仍须由封面模块核对工具、素材与授权。单独一个原标题若无法明确本篇问题或正文承诺，不等于封面的选题材料；未处于课程营销接续的“想写减脂”“帮我写点内容”“做一张健身封面”仍是宽泛小红书方向，先交给能产出选题候选的模块。刚交付具体小红书题或稿件后，用户说“再出 5 个选题”，把上一主题作为同主题延展交接。
5. 同时要求出题和成稿时按前置关系顺序执行。用户选定其中一题，或**明确授权系统代选**并给出依据后，才能把题和证据链交给写稿模块。多个模块都适配时，选能直接完成当前结果、条件更具体的一个；`priority` 只作同等适配时的辅助排序。实质歧义只问一个能改变选择的问题；无已登记能力时如实说明尚未覆盖。

固定提示原样使用：

> 人物 DNA 尚未激活。当前只能调用通用方法，无法启用个性化选题、真实经历映射与个人表达校准。完成「人物底色访谈」并确认档案后，才能解锁完整的叶童内容方法引擎。

对要求 `active` 档案的模块，只有用户明确要求跳过访谈，才可按目标模块规则提供标为“通用版本”的方法或内容；`optional` 模块可直接处理不依赖人物事实的通用任务。两种情况都不能带入未经 active 核验的个人城市、经历、会员故事或口吻。目标模块不支持通用版本时，只说明边界。`yetong-timer` 不以通用题替代本人热点任务，缺本人 active DNA 时不得出个性题或创建声称已绑定 DNA 的任务。

## 执行交接

选定模块后，读取其完整 `SKILL.md`，按其必要引用和脚本执行该阶段，不只报一个 Skill 名字。已确认的信息直接交接。模块之间使用同一张简短的“内容任务卡”：该教练的档案身份、其真实城市与本地客群、具体顾虑及来源、相关本地产品、可公开的经历或服务动作、所用内容类型、已选题、原标题或已有稿件与证据链、待核对风险。六组建档资料都可作为依据，按本篇相关性取用场馆优势、主力客群与表层目标／深层阻碍、真实问题与处理、本人身份／资质／标准／课外服务、高光与匿名案例、选择理由；不要求每篇用全六组。教练自述的选择理由不冒充会员评价，例子不变成客群事实，未知资质与服务频率不补造。旧版已激活 `schema_version: 2` 档案按已记录资料继续使用，不因新问题缺字段要求全量重访。封面阶段还须交接图1人物参考、图2起辅助素材、肖像／场馆／会员素材授权、当前单题问答阶段与已选编号、给定封面文字、已给出的提示词与用户后续选择，以及希望得到方案还是成图。封面模块先做档案、业务与权限预检，再完整读取 `original-cover-workflow.md` 执行原版流程，并读取原版视觉与构图参考；已有具体主题时跳过内容问题，从尚未确认的构图选择开始，已给全部信息就不重复问。缺图1时停在上传参考图，不以无人物海报替代。未明确请求生成图片时不主动调用生图工具。任务卡只在本次交接中引用人物档案，不复制私人档案全文。

课程朋友圈任务另交接“产品资料卡”：产品名称及草案／已确认／失效状态、真实目标与适合／不适合人群、已确认课程内容／价格／权益／标准、素材及分项公开授权、当前推广目标、计划版本与日序、本轮要策划还是写／改文案、可执行频率。产品未知项标待确认，不把 DNA 中其他课程的权益或历史会员效果自动移植给新课程；已有计划接续时不丢失这张卡。内部草案提纲明确不可直接发布，对外文案仅用已确认真实可交付事实。课程营销结构与现有营销型四子类的匹配由 `yetong-promo` 执行，不转给小红书文案模块套笔记格式。

每日热点任务另交接本人档案路径与身份、热点方法入口、已确认每日时间与时区、本轮是创建／单次试跑／已注册任务运行、当前环境可核实的原生调度工具、已有任务标识及状态；未知项如实标记。后台任务需要在执行时能读取同一教练的 active DNA 和热点方法；宿主不能提供这种访问时说明限制，不把私人档案全文复制进公开 Skill。豆包、WorkBuddy 等平台的原生调度能力须在当前环境核实，不编造创建 API 或声称手机云端已实测。Skill 文件交付或一次试跑成功都不等于后台任务已创建；只有原生调度返回可核对的任务标识、启用状态、时间及时区后，才按其实际结果报告任务状态。只交付每次 3 个选题，不擅自扩写脚本、发布标题、封面或代发内容。

只在本次任务需要时读取私人档案；不把档案、访谈原文、会员资料、原图片或课程 PDF 复制进任何 Skill 目录。若缺一个会改变路由的关键输入，只问最少一个问题，例如档案位置、课程资料或本篇具体想回答的问题；已可从档案或当前对话取得的城市、人群不重复问。

同一轮可顺序完成用户明确要求的多个阶段，但每阶段仍须满足自己的前置条件和确认规则。人物档案未获本人明确确认时，不能为了完成选题或文案而替用户激活。选题尚未由用户选定、或按其明确授权代选并说明依据时，不能把候选偷偷当作最终题来写成稿。
