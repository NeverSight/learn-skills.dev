Draft and file well-structured GitHub issues AND pull requests via the `gh` CLI. Use whenever the user wants to create, file, open, draft, raise, or log a GitHub issue/ticket/bug/feature-request/task, OR to open/draft/create a pull request (PR) — phrasings like "create an issue", "file a gh issue", "open a github ticket", "log this bug", "raise an issue", "open a PR", "draft a pull request", "create the PR", or when they hand you a chat/diff/piece of work and ask to capture it as a GitHub issue or PR. Also use it to write an issue or PR body to a file for review before filing. It distinguishes bug reports (reproduction + root cause + file:line) from feature/task issues (outcome + acceptance criteria, NOT implementation), and issues (describe behaviour, NO code internals) from PRs (the Changes section DOES carry code internals). This is for GitHub via `gh` — for Jira/Linear/Asana use the dedicated ticket skill instead.
