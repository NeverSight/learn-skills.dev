Rédiger et déposer des tickets GitHub bien structurés ainsi que des pull requests via l’outil en ligne de commande `gh`. Utilisez‑le chaque fois que l’utilisateur veut créer, déposer, ouvrir, rédiger, soumettre ou consigner un ticket/issue/bug/demande de fonctionnalité/tâche GitHub, OU ouvrir/rédiger/créer une pull request (PR) — expressions telles que « créer un ticket », « déposer un ticket gh », « ouvrir un ticket github », « consigner ce bug », « soumettre un ticket », « ouvrir une PR », « rédiger une pull request », « créer la PR », ou lorsqu’ils vous fournissent un chat/diff/piece de travail et demandent de le capturer comme un ticket ou PR GitHub. Utilisez‑le également pour écrire le corps d’un ticket ou d’une PR dans un fichier afin de le réviser avant le dépôt. Il distingue les rapports de bugs (reproduction + cause racine + fichier:ligne) des tickets de fonctionnalité/tâche (résultat + critères d’acceptation, PAS d’implémentation), et les tickets (décrivent le comportement, PAS les détails du code) des PR (la section « Changes » CONTIENT les détails du code). Ceci concerne GitHub via `gh` — pour Jira/Linear/Asana, utilisez la compétence de tickets dédiée.
