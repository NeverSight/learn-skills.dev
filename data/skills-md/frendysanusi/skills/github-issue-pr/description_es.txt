Boceta y archiva problemas y pull requests bien estructurados de GitHub mediante la CLI `gh`. Úsalo siempre que el usuario quiera crear, archivar, abrir, redactar, levantar o registrar un issue/ticket/bug/solicitud de función/tarea de GitHub, o para abrir/redactar/crear un pull request (PR) — expresiones como “crear un issue”, “archivar un issue en gh”, “abrir un ticket de GitHub”, “registrar este bug”, “levantar un issue”, “abrir un PR”, “redactar un pull request”, “crear el PR”, o cuando te entregan un chat/diff/pieza de trabajo y piden capturarlo como un issue o PR de GitHub. También úsalo para escribir el cuerpo de un issue o PR en un archivo para revisarlo antes de archivarlo. Distingue los reportes de errores (reproducción + causa raíz + archivo:línea) de los issues de funcionalidad/tarea (resultado + criterios de aceptación, NO implementación), y los issues (describen el comportamiento, SIN internals de código) de los PR (la sección Cambios SÍ incluye internals de código). Esto es para GitHub vía `gh` — para Jira/Linear/Asana usa la habilidad de tickets dedicada.

Por favor, siempre responde en el idioma del usuario.
