Redigi e archivia issue GitHub ben strutturati E pull request tramite la CLI `gh`. Usalo ogni volta che l’utente vuole creare, archiviare, aprire, redigere, sollevare o registrare un issue/ticket/bug/richiesta di funzionalità/compito su GitHub, O aprire/redigere/creare una pull request (PR) — frasi come “crea un issue”, “archivia un issue gh”, “apri un ticket GitHub”, “registra questo bug”, “solleva un issue”, “apri una PR”, “redigi una pull request”, “crea la PR”, o quando ti consegnano una chat/diff/pezzo di lavoro e chiedono di catturarlo come issue o PR su GitHub. Usalo anche per scrivere il corpo di un issue o di una PR in un file per la revisione prima dell’invio. Distingue i report di bug (riproduzione + causa radice + file:linea) dalle issue di funzionalità/compito (esito + criteri di accettazione, NON implementazione), e le issue (descrivono il comportamento, NESSUN interno del codice) dalle PR (la sezione Changes CONTIENE interni del codice). Questo è per GitHub via `gh` — per Jira/Linear/Asana usa la skill dedicata ai ticket.
