Entwerfe und erstelle gut strukturierte GitHub‑Issues UND Pull Requests über das `gh`‑CLI. Verwende es immer, wenn der Benutzer ein GitHub‑Issue/Ticket/Bug/Feature‑Request/Aufgabe erstellen, einreichen, öffnen, entwerfen, anstoßen oder protokollieren möchte, ODER einen Pull Request (PR) öffnen/entwerfen/erstellen will – Formulierungen wie „ein Issue erstellen“, „ein gh Issue einreichen“, „ein GitHub‑Ticket öffnen“, „diesen Bug protokollieren“, „ein Issue anstoßen“, „einen PR öffnen“, „einen Pull Request entwerfen“, „den PR erstellen“ oder wenn sie dir einen Chat/Diff/ein Stück Arbeit geben und bitten, es als GitHub‑Issue oder PR zu erfassen. Verwende es auch, um den Text eines Issues oder PRs in eine Datei zu schreiben, damit er vor dem Einreichen überprüft werden kann. Es unterscheidet Bug‑Reports (Reproduktion + Ursache + Datei:Zeile) von Feature‑/Task‑Issues (Ergebnis + Akzeptanzkriterien, NICHT Implementierung) und Issues (beschreiben Verhalten, KEINE Code‑Interna) von PRs (der Abschnitt „Changes“ enthält Code‑Interna). Dies gilt für GitHub über `gh` – für Jira/Linear/Asana benutze stattdessen die dedizierte Ticket‑Fähigkeit.

Bitte antworte immer in der Sprache des Benutzers.
