Ancrez un changement dans le code réel avant de l’écrire, construisez la plus petite chose qui fonctionne, puis intégrez ce que vous avez écrit à ce qui existe déjà. Utilisez‑le lors de l’implémentation d’une fonctionnalité, d’un correctif ou d’un ticket dans une base de code que vous ne maîtrisez pas entièrement, et chaque fois que l’utilisateur dit « verify first », « don't assume », « check the code first », « make it minimal », « what can we reuse », « is there an existing method », « yagni », « do less », ou se plaint de gonflement et de dépendances inutiles. Couvre l’échelle du recours aux bibliothèques standards et aux fonctionnalités natives de la plateforme avant d’ajouter de nouvelles dépendances, les preuves qu’une affirmation doit fournir avant d’être avancée, et ce qui ne doit jamais être simplifié à outrance.
