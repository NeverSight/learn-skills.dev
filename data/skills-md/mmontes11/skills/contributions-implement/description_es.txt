Implementa una contribución elegida en un fork de un proyecto de código abierto: verifica que el fork del usuario ya exista (detente y pide al usuario que lo haga si no existe), sigue estrictamente las convenciones del repositorio upstream (CONTRIBUTING.md, AGENTS.md, CLAUDE.md, plantilla de PR, formato de commit y sign‑off), trabaja en una rama del fork sin abrir ningún PR de fork, escribe pruebas de equivalencia‑first, ejecuta localmente las verificaciones CI/CD del upstream antes de empujar (el fork no las ejecutará), firma los commits según la convención DCO/CLA del upstream, y publica el cuerpo del PR — construido a partir de la plantilla de PR del upstream — en formato markdown pegable en el issue de Multica. En iteraciones de revisión (el PR ya está abierto y un mantenedor dejó comentarios de revisión), atiende solo las peticiones explícitas en la misma rama del fork y publica un comentario de PR pegable por PR en el mismo formato de markdown con delimitadores; las discusiones del PR — respuestas, resoluciones, solicitudes ambiguas — se dejan para los humanos. Utiliza esto siempre que un issue de Multica pida “trabajar en la contribución”, “implementar <candidato> en <owner/repo>”, “preparar la rama para <repo>”, “convertir la contribución detectada en un diff listo para PR”, o “abordar los comentarios de revisión en <PR>”, incluso si el issue solo menciona el repositorio objetivo y el cambio a realizar.
