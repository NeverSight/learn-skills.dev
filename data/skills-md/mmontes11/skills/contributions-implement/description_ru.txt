Реализовать выбранный вклад в форке открытого проекта: проверить, что форк пользователя уже существует (при отсутствии — остановиться и попросить пользователя создать форк), строго следовать конвенциям оригинального репозитория (CONTRIBUTING.md, AGENTS.md, CLAUDE.md, шаблон PR, формат коммитов и подписи), работать в ветке форка без создания PR из форка, писать тесты, ориентированные на эквивалентность, запускать проверки CI/CD оригинального проекта локально перед отправкой (форк их не выполняет), подписывать коммиты согласно конвенции DCO/CLA оригинального проекта и размещать тело PR — построенное по шаблону PR оригинального проекта — в виде вставляемого markdown‑текста в issue Multica. При итерациях ревью (PR уже открыт и мейнтейнер оставил комментарии) отвечать только на явные запросы в той же ветке форка и размещать вставляемый комментарий к PR в том же оформленном markdown‑блоке; обсуждения PR — ответы, решения, неоднозначные запросы — оставляются людям. Использовать данный подход каждый раз, когда issue Multica просят «работать над вкладом», «реализовать <candidate> в <owner/repo>», «подготовить ветку для <repo>», «превратить найденный вклад в готовый к PR дифф» или «ответить на комментарии ревью в <PR>» — даже если в issue указано лишь целевой репозиторий и требуемое изменение.
