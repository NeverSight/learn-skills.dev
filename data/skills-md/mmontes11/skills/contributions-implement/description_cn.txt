在开源项目的分叉中实现所选贡献：先确认用户的分叉已经存在（如果不存在则停止并要求用户先进行分叉），严格遵循上游仓库的约定（CONTRIBUTING.md、AGENTS.md、CLAUDE.md、PR 模板、提交和签名格式），在分叉的分支上工作且不打开任何分叉 PR，编写等价优先的测试，在推送之前本地运行上游的 CI/CD 检查（分叉不会运行它们），按照上游的 DCO/CLA 规范签署提交，并在 Multica 议题上以可粘贴的 Markdown 格式发布 PR 内容——该内容依据上游 PR 模板构建。审阅迭代时（PR 已打开且维护者留下审查评论），仅在同一分叉分支上处理明确的请求，并以相同的代码块 Markdown 格式发布可粘贴的 PR 评论；PR 讨论——回复、解决、含糊的请求——留给人工处理。每当 Multica 议题要求“处理贡献”、“在 <owner/repo> 中实现 <candidate>”、“为 <repo> 准备分支”、“将已发现的贡献转化为可提交的差异”或“处理 <PR> 的审查评论”时，都使用此流程——即使议题仅列出目标仓库和要进行的更改。
