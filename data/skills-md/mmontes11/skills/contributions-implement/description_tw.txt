在開源專案的分支（fork）中實作選定的貢獻：先確認使用者的 fork 是否已存在（若不存在則停止並請使用者自行 fork），嚴格遵循上游儲存庫的規範（CONTRIBUTING.md、AGENTS.md、CLAUDE.md、PR 模板、提交與簽署格式），在 fork 的分支上作業且不開任何 fork PR，撰寫等價優先的測試，在推送前於本地執行上游的 CI/CD 檢查（fork 本身不會執行），依上游的 DCO/CLA 規定簽署提交，並將 PR 內文——依上游 PR 模板構建——以可貼上的 Markdown 格式發布於 Multica 議題上。於審查迭代（PR 已開啟且維護者留下審閱意見）時，只回應同一 fork 分支上的明確請求，並以相同的 fenced‑markdown 格式貼上可貼的 PR 評論；PR 討論——回覆、解決、模糊要求——交由人類處理。當 Multica 議題要求「處理貢獻」、「在 <owner/repo> 中實作 <candidate>」、「為 <repo> 準備分支」、「將偵測到的貢獻轉為 PR‑ready diff」或「回覆 <PR> 的審閱意見」時，即使用此流程——即使議題僅列出目標儲存庫與要進行的變更。
