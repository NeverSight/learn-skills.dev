選択した貢献をオープンソースプロジェクトのフォークで実装する：ユーザーのフォークがすでに存在しているか確認し（存在しなければフォークするように指示して停止する）、上流リポジトリの慣習（CONTRIBUTING.md、AGENTS.md、CLAUDE.md、PRテンプレート、コミットとサインオフの形式）を厳密に遵守し、フォークのブランチ上で作業しフォークからの PR は開かない、等価性第一のテストを書き、プッシュ前に上流の CI/CD チェックをローカルで実行する（フォークでは実行されない）、上流の DCO/CLA の規定に従ってコミットにサインし、PR 本文を上流 PR テンプレートから作成し、Multica イシューに貼り付け可能な Markdown 形式で投稿する。レビューのイテレーションでは（PR はすでにオープンしており、メンテナがレビューコメントを残している）、同じフォークブランチ上で明示的な要求のみを対応し、PR ごとに貼り付け可能な PR コメントを同じフェンス付き Markdown 形式で投稿する；PR の議論（返信、解決、曖昧な要求）は人間に任せる。Multica のイシューが「contribution に取り組む」「<owner/repo> に <candidate> を実装する」「<repo> 用のブランチを用意する」「スカウトされた貢献を PR 準備済みの diff に変える」または「<PR> のレビューコメントに対応する」と求めたときは常に使用する――たとえイシューが対象リポジトリと変更内容だけを記載していても。
