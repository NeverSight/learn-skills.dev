# dbs-theory-grounding：理论溯源与案例重释

任务目标：把未经检验的经验判断处理成有来源层级、有边界、能解释案例的理论表达。先审命题，再选理论；先判断核实是否必要，再决定使用已有知识、本地资料或外部来源。

## 硬性原则

1. **先审命题。** 提取原判断、案例和使用场景，检查绝对化、因果跳跃、定义偷换、以偏概全和反向推断。
2. **匹配度优先。** 理论必须解释案例里的核心机制。名气不能弥补理论错配。
3. **保留有效部分。** 案例成立而结论过度时，缩小结论边界；不要为了换理论整段推翻。
4. **人物约束服从任务需要。** 用户要求「已故名人」时，只把「确为已故」和相关专业身份作为入选条件，不主动补充出生年、去世年与国籍变化。已有知识足以高置信判断时可以离线完成并标注核实层级；存在争议且会影响入选资格时，再把外部核实视为必要步骤。
5. **默认离线。** 先依据用户提供的材料、当前对话、本地资料和模型已有知识完成命题审查与理论匹配。联网不是默认研究步骤，不能因为想补充人物、理论、原话、页码或候选数量就自动联网。
6. **按结论需要核实。** 只有外部事实会实质改变结论，或用户明确要求核实、来源、原话、页码、首创归属或最新信息时，才进入外部核实。用户要求不联网时，禁止联网；无法离线确认的细节标为「尚未核实」，不得以核实为由违背用户限制。
7. **区分经典表述与逐字引文。** 用户要求「经典理论」「经典表述」「找理论依据」，默认允许交付基于已有知识的通行概念和明确标注的中文意译，不等于要求联网查找逐字原话。只有用户明确要求「原话」「准确出处」「页码」或逐字引用时，才把引文核实视为任务必要部分。
8. **后台分层，前台只给中文。** 研究时区分外文原话、忠实翻译和中文意译；未外部核验原文时，优先给明确标注的中文意译，不得把模型记忆中的近似措辞包装成逐字引文。给课程老师、客户或其他当事人的文档不展示外文原话。
9. **给出边界。** 至少写出一个适用场景、一个不适用场景和一个可能推翻当前解释的反例。
10. **拒绝硬套。** 找不到高匹配理论时，直接说明「暂未找到足够匹配的理论」，保留经验判断或改找学派、研究结论。
11. **禁止编造。** 无法核实页码、原话或首创关系时，写明核实状态，不补写推测信息。
12. **区分研究过程与交付文档。** 候选评分、文件检查和检索过程用于内部判断。给课程老师、客户或其他当事人看的版本默认从「总体判断」开始，只保留简短的理论选择说明，把篇幅留给入选理论、案例解释和修改建议。
13. **控制理论数量。** 同一组案例默认只保留解释力最强的 1 个主理论。辅助理论必须解释主理论无法覆盖的新机制；如果只能得到「表达要清楚」「内容要有价值」一类常识性结论，直接删除。

## 执行流程

### Step 1：固定原问题

输出：

```markdown
原命题：
原案例：
使用场景：
用户希望理论完成的任务：
```

「完成的任务」只选主要一项：解释机制、提高可信度、修正标准、组织案例或生成 PPT 表达。

### Step 2：审查原命题

逐项检查：

| 风险 | 检查问题 |
|---|---|
| 绝对化 | 是否使用「都、一定、只要、凡是、就」？反例能否轻易成立？ |
| 因果跳跃 | 案例只展示相关、结果或感受，却被写成原因了吗？ |
| 定义偷换 | 前后使用的核心词是否改变了含义？ |
| 经验普遍化 | 单个案例是否被扩展成所有场景的规律？ |
| 反向推断 | 看到结果后，是否倒推出唯一原因？ |

作出一个状态判断：

- `保留`：原命题与案例匹配，边界清楚；
- `收窄`：核心洞察可用，措辞或适用范围过宽；
- `重构`：案例可用，原命题无法准确解释；
- `放弃`：命题与案例均缺少支撑。

先写修正后的标准，再进入理论搜索。

### Step 3：定义理论需要解释的机制

把「找名人」改写为 1—3 个理论检索问题，例如：

- 为什么具体细节更容易形成理解或记忆？
- 为什么抽象结论在某些场景有效，在另一些场景空泛？
- 什么机制能同时解释正例与反例？

理论必须回答检索问题。只和案例共享关键词，不算匹配。

### Step 4：建立候选池

提出 2—4 个候选理论，按下表评分：

| 维度 | 分值 | 判断标准 |
|---|---:|---|
| 机制匹配 | 0—3 | 能否解释案例的主要矛盾 |
| 来源可靠 | 0—2 | 是否有原著、论文或权威档案 |
| 人物辨识度 | 0—2 | 目标受众是否容易理解其身份 |
| 可用于表达 | 0—2 | 是否有清楚概念、通行表述或可准确标注的中文意译 |
| 边界清楚 | 0—1 | 是否能解释何时成立、何时失效 |

总分低于 7 分不得入选。`机制匹配 < 2` 或 `来源可靠 < 1` 时直接淘汰。用户要求已故人物时，「死亡状态能够高置信确认，并如实标注当前核实层级」是额外硬门槛。

完成评分后再做一次去重：

- 两个理论解释同一机制时，只保留机制匹配分更高的一个；
- 辅助理论必须明确写出「主理论解释不了、它能够解释的部分」；
- 新理论只能生成宽泛、正确但没有信息增量的结论时，删除该理论；
- 删除理论后仍能完整解释案例时，不为增加名人数量而保留。

候选比较用于内部筛选。用户明确要求研究过程时，再输出完整表格：

```markdown
| 候选人物 | 候选理论 | 能解释什么 | 解释不了什么 | 得分 | 结论 |
|---|---|---|---|---:|---|
```

### Step 5：确定人物、理论与核实层级

先判断当前任务是否真的需要外部核实：

- 只需解释机制、修正命题或寻找经典理论时，默认使用用户材料、本地资料和模型已有知识，核实状态写「基于已有知识，未在本轮外部核实」；
- 用户要求「经典表述」但没有要求逐字原话时，优先输出中文意译，并明确标注「意译」；
- 用户明确要求准确原话、页码、版本、首创归属或争议事实时，再按末尾「知识、核实与联网标准」决定是否外部核实；
- 用户明确要求不联网时，删除非必要的精确细节，保留可离线完成的理论原义、案例解释和适用边界。

#### 人物定位

给当事人的正文只保留国家或主要学术归属、相关身份、中文名和外文通行名。生卒年、履历、奖项、国籍变化和相关贡献用于后台核实，不进入人物定位或 PPT。

推荐句式：

```markdown
[国家或主要学术归属][相关身份][中文名]（[外文通行名]）
```

例如：

```markdown
美国语义学家塞缪尔·早川（S. I. Hayakawa）
```

中文姓名遵守以下规则：

1. 优先采用本人中文署名、中文正式出版物、国家图书馆／大学／出版社等权威来源使用的译名；
2. 没有唯一权威译名时，采用中文出版物中的通行译名，并写「中文常译……」；
3. 存在两个常见译名时，正文采用最通行的一种，注释中写「亦译……」；
4. 无法核实中文译名时，保留外文名并明确写「暂未找到可靠的统一中文译名」，禁止自行音译；
5. 出生地、族裔、国籍变化和任职国家容易混淆时，不依赖未经核实的精确细节完成人物定位；必要时标为「尚未核实」，不进入给当事人的正文。
6. 用户要求「已故人物」时，优先选择已有知识中身份明确、争议较小的人物，不主动补充生卒年。只有死亡状态本身存在不确定性并会影响入选资格时，才把外部核实视为可能改变结论的必要事实。

#### 理论卡

```markdown
理论名称：
理论要解决的问题：
核心机制：
原始出处：作者，《作品》，年份；只有确知时才补版本 / 章节 / 页码
核实状态：用户材料 / 本地资料 / 基于已有知识，未在本轮外部核实 / 原始来源已核实 / 权威二手来源已核实 / 尚未核实
```

研究时把引用文字分三层：

```markdown
外文原话：只有实际查阅并核实时才记录，不进入给当事人的文档
中文译文：只有实际核对原文时使用，尽量保留原意，不添加案例结论
中文意译：可依据可靠的理论原义和已有知识压缩表达，必须明确标注「意译」
```

给当事人的理论卡只输出中文译文或中文意译。未实际核对原文时不得标「中文译文」，只能标「中文意译」。页码随版本变化时，同时写版本；只能确认章节时引用章节，不猜页码；不影响核心结论的页码可以直接省略。

### Step 6：用理论重释案例

逐句映射，不能只在案例前面贴理论名。

```markdown
| 案例原句 / 事实 | 理论中的对应概念 | 理论解释 | 修正后的判断 |
|---|---|---|---|
```

检查映射：

- 理论是否解释了案例为什么有效；
- 理论是否解释了原说法为什么说过头；
- 案例是否真的提供理论所需证据；
- 新解释有没有加入案例中不存在的事实。

### Step 7：写适用边界与反例

```markdown
适用场景：
- ...

不适用场景：
- ...

反例：
- 如果出现……，当前解释需要被收窄或放弃。

仍需核实：
- ...
```

任何理论都不能推出「文案永远应该更具体」「所有成功都由单一原因造成」一类无限结论。

### Step 8：生成标准输出

先判断读者：

- 给研究者或 skill 调试者：可以附候选评分和核实过程；
- 给课程老师、客户或其他当事人：默认使用精简交付版，不展示文件检查、解密过程和完整淘汰记录。

给当事人的文档按以下模板交付：

```markdown
# 1. 总体判断

用一小段或一张简表说明哪些命题保留、收窄、重构或暂不补理论。

# 2. 理论选择说明

用 1 段说明入选标准与主要淘汰原因，不展开评分过程。

# 3. 理论锚点

原命题：
审查状态：保留 / 收窄 / 重构 / 放弃
修正后的标准：

## 人物定位

用一行写「国家或学术归属＋相关身份＋中文名＋外文名」。

## 相关理论

理论名称：
理论原义：
中文译文：
原始出处：
核实状态：

## 理论如何解释案例

| 案例 | 理论解释 | 得出的判断 |
|---|---|---|

## 适用边界

适合：
不适合：
反例与待核实事实：

## PPT 可用版

【标题】10 字以内
【人物署名】国家或学术归属＋相关身份＋中文名（外文通行名）
【理论表述】已核实的中文译文，或基于已有知识且明确标注的「意译」
【一句解释】20 字以内
【案例对比】两侧各不超过 30 字
【演讲者注】说明边界、出处和不能上屏的核实信息
```

同一份文档有多个理论锚点时，「总体判断」和「理论选择说明」只出现一次，随后直接展开各个理论锚点。核心理论放在最前面，辅助理论排在后面。

## 知识、核实与联网标准

默认不联网。先依据用户提供的材料、当前对话、本地资料和模型已有知识回答。理论匹配、命题审查、案例重释和边界判断通常可以离线完成；不能为了让答案显得更学术、补齐理论卡字段或增加候选数量而联网。

只有满足以下任一条件时，才允许联网：

1. 用户明确要求联网搜索、事实核验、准确来源、逐字原话、页码、版本、首创归属或最新研究；
2. 某项外部事实会实质改变主理论是否入选、人物是否符合硬约束，或核心结论是否成立；
3. 用户要求可正式发表的精确引文，而现有材料和本地资料不足以完成核验。

以下情况不能单独触发联网：

- 用户只说「找经典理论」「找经典表述」「给观点找依据」；
- 已有知识足以完成机制匹配，只缺页码、逐字措辞或非关键履历；
- 想确认更多候选、补充更多案例或提高答案的表面完整度；
- 已经能够用中文意译准确表达理论原义。

用户明确要求不联网时，禁止调用网页搜索、浏览器、网络 API、`curl` 或任何其他外部检索能力。此时应：

- 正常完成命题审查、理论匹配、案例解释和边界分析；
- 把来源状态写成「基于已有知识，未在本轮外部核实」；
- 删除无法确认且不影响结论的精确页码、版本、生卒年和逐字引文；
- 对会影响结论但无法离线确认的事实标注「尚未核实」，不得用猜测补齐。

需要联网时，先用一句话说明「什么关键事实需要核实，以及它为什么会改变结论」，再按最小充分原则检索。证据足以支持结论后立即停止；同一事实连续 2 次无法核实，标注「尚未核实」并停止。

进行外部核实时，来源优先级为：

1. 原著、原始论文、作者档案；
2. 大学、学会、政府、博物馆、权威出版社；
3. 同行评议论文或可靠学术工具书；
4. 高质量二手解释；
5. 百科仅用于发现线索，名言站与聚合文章不能作为唯一来源。

只有任务确实进入外部核实时，才按需要为以下两类关键事实分别寻找来源；未进入外部核实时，不为补齐格式主动搜索：

- 人物身份与生卒；
- 理论原义、原话或作品出处。

如果引用经由二手文献找到，要写「该二手文献引自……」，不能伪装成已直接查阅原著。

## 校准样例

输入：

```text
「需要解释的词就不是好文案。」
「我努力创业，才有了今天的成就。」
对比案例是「我开了 30㎡ 的重庆小面馆，2 个月做到 35 万」。
请找一个已故名人的理论解释。
```

最低合格结果：

- 默认不联网；先用已有知识完成理论匹配，并把核实状态写清楚；
- 原命题判为 `收窄`，因为抽象表达可以承担标题、总结和价值判断；
- 检索问题聚焦「抽象与具体如何分工」；
- Hayakawa 的「抽象阶梯」优先于只解释记忆效果的理论；
- 人物定位写成「美国语义学家塞缪尔·早川（S. I. Hayakawa）」，不输出字段式人物简卡、生卒年或详细履历；
- 输出人物中文译名、领域定位、理论中文意译、已知出处与核实状态；只有实际核对原文后才使用「中文译文」；
- 说明具体案例提升可感知性，但「35 万」仍需核实口径；
- 中文意译必须明确标注，不能冒充 Hayakawa 原话的忠实翻译。

## 自检

- 是否先审命题，再找人物？
- 入选理论是否通过评分硬门槛？
- 同一问题是否只保留解释力最强的主理论？
- 辅助理论是否提供了主理论没有覆盖的新机制？
- 是否默认先用用户材料、本地资料和已有知识完成回答，没有把联网当成理论研究的起点？
- 用户只要求「经典表述」时，是否避免把它自动解释为逐字引文核验？
- 用户要求不联网时，是否完全停止网页、浏览器、网络 API 和命令行网络访问？
- 人物生卒、国家和身份如果没有外部核实，是否省略非关键细节或如实标注核实状态？
- 中文译名是否标明当前核实层级，并在没有统一译名时如实标注？
- 人物定位是否只保留国家或学术归属、领域、中文名和外文名？
- 是否在后台区分原话、翻译和意译，并在给当事人的文档中隐藏外文原话？
- 是否避免把二手引文标成原著直引？
- 是否逐句映射案例，没有只贴理论标签？
- 是否写出适用边界、反例与待核实事实？
- 给当事人的文档是否省略文件检查、解密过程和完整候选打分？
- PPT 文案是否短，并保留演讲者注中的来源信息？

完成当前任务后直接结束。只有用户明确询问下一步，且当前环境已经安装 `/dbs` 时，简短提示输入 `/dbs`。
