Debugge das `#[copper_runtime]` Proc‑Macro in copper-rs (`cu29_derive`): Lies seine Kompilierfehler, entscheide, wann `cargo expand` / `just expand-runtime` auszuführen ist, verstehe, was das Makro um die `App`‑Struktur des Benutzers herum erzeugt, und erkenne die wiederkehrenden Fallgruben (fehlendes `Reflect`/`Freezable`, RON‑Parse‑als‑Macro‑Fehler, `sim_mode`‑Abweichung, feature‑gesteuerte Lifecycle‑Hooks). Verwende es immer dann, wenn der Compiler‑Fehler `#[copper_runtime]` erwähnt, auf die Zeile der `App`‑Struktur zeigt oder ein Symbol nennt, das nur im expandierten Code existiert. Das Ausführungsmodell findest du in `copper-arch`; zum Ändern der Makro‑Implementierung siehe `copper-core-dev`; die `just`‑Befehle stehen in `copper-workflow`.
