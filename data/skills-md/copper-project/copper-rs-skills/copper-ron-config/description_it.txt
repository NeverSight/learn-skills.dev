Riferimento approfondito allo schema per `copperconfig.ron`. Usalo quando leggi, scrivi o fai debug di un file di configurazione copper-rs: ogni chiave di livello superiore, ogni campo per‑task/per‑cnx/per‑bridge, le regole tipizzate di accesso `ComponentConfig` (`get` vs `get_value`) e gli errori di validazione esatti generati dal parser. Tutte le affermazioni citano `core/cu29_runtime/src/config.rs`. Per l'architettura di runtime e il modello mentale del grafo di task vedi `copper-arch`; per la formattazione `fmtron` e il ciclo `just fmt` vedi `copper-workflow`; per le regole di gusto “come dovrebbe sentirsi un nuovo campo di configurazione” (enum tramite `Deserialize`, nessun parsing basato su stringhe) vedi `copper-api-flavor`.
