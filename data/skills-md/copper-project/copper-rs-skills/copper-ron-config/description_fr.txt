Référence de schéma approfondie pour `copperconfig.ron`. Utilisez‑la lors de la lecture, de l’écriture ou du débogage d’un fichier de configuration copper‑rs : chaque clé de niveau supérieur, chaque champ par‑tâche/par‑cnx/par‑bridge, les règles d’accès typées `ComponentConfig` (`get` vs `get_value`), et les erreurs de validation exactes émises par l’analyseur. Toutes les affirmations citent `core/cu29_runtime/src/config.rs`. Pour l’architecture d’exécution et le modèle mental du graphe de tâches, voir `copper-arch` ; pour le formatage `fmtron` et le cycle `just fmt`, voir `copper‑workflow` ; pour les règles de « comment un nouveau champ de configuration doit se sentir » (énumérations via `Deserialize`, pas de parsing de chaînes), voir `copper-api-flavor`.

Veuillez toujours répondre dans la langue de l’utilisateur.
