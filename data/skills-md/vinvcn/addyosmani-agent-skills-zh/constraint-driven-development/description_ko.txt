프로젝트의 품질 기준을 서면 계약으로 설정하고 에이전트가 조용히 이를 낮추는 것을 방지하십시오. 인터뷰를 통해 사용자가 중요하게 생각하는 차원을 파악하고, 사용자가 구체적인 수치를 제시하지 않을 경우 합리적인 기본 임계값을 제공하며, 모든 내용을 CONSTRAINTS.md에 기록하고, diff에서 품질 기준이 약화되는 징후—새로운 @ts-ignore 또는 eslint‑disable 억제 주석, 건너뛰거나 삭제된 테스트, 제거된 assertion, 구현되지 않은 스텁, 낮아진 임계값—를 주시하십시오. 다음과 같은 경우에 사용하십시오: 품질 기준이 문서화되지 않았을 때; 사용자가 “제약 조건을 설정해 주세요” 또는 “우리 표준을 정의해 주세요”라고 말할 때; 사용자가 접근성, 웹 성능, 커버리지와 같이 중요하게 여기는 차원을 제약 조건으로 강제하려 할 때; 에이전트가 지속적으로 조용히 검사를 수행하거나 테스트를 건너뛰어 단순히 녹색 상태만 만들 때; 커버리지 또는 성능 임계값이 필요하지만 어떤 수치를 선택해야 할지 모를 때; 혹은 에이전트가 작성한 코드가 실제로 누군가가 읽을 수 있는 양을 초과할 때.
