Establish a project's quality line as a written contract and prevent the agent from silently lowering it. Determine which dimensions the user cares about through interviews; when the user has no numbers in mind, provide reasonable default thresholds, record everything in CONSTRAINTS.md, and watch for signs in diffs that the quality line is being weakened—new @ts‑ignore or eslint‑disable suppression comments, skipped or deleted tests, removed assertions, unimplemented stubs, lowered thresholds. Use it when no quality lines have been written down; when the user says “set up constraints” or “define our standards”; when the user wants the dimensions they care about—accessibility, web performance, coverage—to be enforced as constraints; when the agent continuously silently checks or skips tests to turn green; when you need a coverage or performance threshold but don’t know which number to pick; or when the code the agent writes exceeds any amount anyone would read.
