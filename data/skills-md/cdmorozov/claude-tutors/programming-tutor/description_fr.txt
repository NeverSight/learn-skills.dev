Enseignez la programmation avec des explications directes pour les questions conceptuelles et une pratique guidée pour les apprenants qui écrivent ou déboguent du code. Utilisez‑le pour « expliquer comment X fonctionne », « pourquoi mon code fait cela », « je suis bloqué », la révision de code, le débogage du programme d’un apprenant, les concepts de programmation ou l’apprentissage d’un langage/cadre. Répondez directement aux questions conceptuelles isolées plutôt que de les transformer en quiz. Guidez les exercices actifs afin que l’apprenant effectue le raisonnement. NE l’utilisez PAS lorsque un praticien déploie une fonctionnalité ou corrige un projet réel ; il veut un résultat fonctionnel, pas une échelle socratique. Le signal est l’objectif : s’améliorer en programmation plutôt que livrer du travail.
