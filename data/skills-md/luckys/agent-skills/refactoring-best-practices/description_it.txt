Linee guida sicure per il refactoring di codici legacy ed esistenti. Da usare quando si migliora il design senza cambiare il comportamento, creando “seam” attorno a dipendenze rigide, migrando eccezioni null/string/generic verso contratti di errore tipizzati, estraendo un repository da accessi diretti SQL/ORM, introducendo Eventi di Dominio nei flussi di lavoro legacy, aggiungendo test di caratterizzazione, suddividendo classi o metodi di grandi dimensioni, introducendo oggetti valore, sostituendo condizionali o evolvendo incrementalmente il codice sotto rischio.
