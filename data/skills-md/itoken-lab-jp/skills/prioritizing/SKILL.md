# やる順と、やらないことを決める

AI は、一つひとつの作業は上手にこなす。外すのは、全部は入らないときの絞り方で、次の形が多い。

- 入らないと気づいても、目玉の項目を自分で「必須」に入れる。削るか日をずらすかは頼んだ人が決めることなのに、決めたことにしてしまう。
- 使える時間を目いっぱい埋め、余白を残さない。1つ遅れると全部ずれる。
- 変更履歴やコードを見れば分かる「もう済んでいるか」を、自分で見ずに質問に回す。決めてほしいことが3つも5つも並ぶ。
- 「同じ話です」と書いて、両方を残す。
- 「ほかに何かある？」と聞かれると、気づいたことを5〜7個並べ、「続けてやりましょうか」と作業を申し出る。

人も AI も、良くしようとすると足す案ばかり考え、引く案を見落とす（足す方への偏りは研究で確かめられている）。足した項目は、どれも誰かが読み、決め、いつか片付ける。頼んだ人の時間と注意がいちばん足りない資源なので、この Skill は「やらない」を先に決めて、急ぐものに力を集めることを受け持つ。

## 1. 先に量を比べる

- 頼まれた時間・人・期限から、使える量を出す。今日の日付は、頼みの言葉にあればそれを正とする。
- やることの見積もりを足し、使える量と比べる。入らなければ、返事の最初の1文でそう言う。
- 使える量の2〜3割は、試験・手戻り・割り込みの余白に残す。余白を削らないと入らないなら、それも「入らない」に数える。

## 2. 引けるものを先に外す

並べる前に、やらなくてよいものを外す。どれも手元で確かめ、人には聞かない。見る所は、変更履歴のファイル（CHANGELOG・リリースノート・運用の記録など。一覧と同じフォルダーや README から探す）、git の履歴、コード、票の履歴。git の履歴が浅くても、ファイルの記録を読む。

- **もう済んでいる**：変更履歴やコードで確かめる。確かめたら、根拠を書いて閉じる（または外す）。
- **同じ話**：1つにまとめる。任されていれば片方を閉じ、任されていなければ「#8 を残して #14 を閉じる」と案にする。「同じです」と書いて両方残さない。
- **前提が崩れた**：頼んだ人がもういない、長く動きがない、目的がはっきりしない。自分では閉じず、「閉じる案」として理由を1行付けて出す（残すかは持ち主が決める）。自分で閉じてよいのは、済んだものと同じ話のものだけ。

## 3. 遅れたときの損で並べる

- 先にやるのは、遅れると損が出る・広がるもの：外の期限（止まる日、規約や法令の日、締め、診断の指摘）、遅れるほど直す件数が増えるもの、ほかの作業の前提になるもの。
- 同じくらいの損なら、手間の短いものを先にする。番号順・メモの順・易しい順では並べない（急ぐものが無いときだけ、易しい順でよい）。
- 並べた理由は、各項目に短く書く（「12/15 に v1 が止まる」）。

## 4. 削り方は、決める人に1つにして出す

- 範囲・期限・目玉の機能を落とすか、日をずらすかは、頼んだ人が決める。お金や契約が絡むもの（買う、増やす、外に頼む）は、頼んだ人かその上が決める。返事待ちのものは、待っていることと誰が決めるかを書き、自分で「後に回す」と決めない。自分で「必須」に入れて決めたことにしない。逆に、入らない分を「余裕があれば」に全部残して、決めないままにもしない。
- 選択肢を2〜3つにして推しを1つ付け、決めてほしいことを1つに絞って出す。計画は推しの案で組んで見せ、相手が選ぶだけで済む形にする。
- 手元で確かめられることは聞かない。聞くのは、答えで計画が変わり、手元に無いことだけ。

## 5. 足さない

- 作業中に気づいたこと（TODO、気になるコード、別の改善）を、1件ずつ Issue や作業にしない。報告の最後に、急ぐ順で1〜3点だけ書く。残りは書かないか、1件の票にまとめる。
- 新しい Issue を作るのは、頼まれた範囲で直せず、放っておくと損が出るものだけ。作る前に既存の票を探し、あれば重ねる。
- 「ほかに何かある？」と聞かれたときも同じ。急ぐ順に1〜3点にする。見た範囲で急ぐものが無ければ、見た範囲を添えて「一覧とコードを見た範囲では、急ぐものはありません」でよい。見ていない所について、無いと言い切らない。頼まれていない作業を「続けてやりましょうか」と申し出ない。

## 6. 止める

- 時間の箱があれば、大きなもの（書き換え、道具の置き換え、新しい機能）には手をつけない。終わらないまま時間が切れるより、小さく終えて残りを渡すほうが、頼んだ人は次を決めやすい。
- 残りは「次にやる順（理由つき）」と「やらない・閉じる案（理由1行）」に分けて返す。

## 7. 手間は頼みに合わせる

- 1件を直す頼み、やることがはっきりした頼みでは、この手順を回さない。そのまま直して短く報告する。ほかに急ぐものに気づいたら1行だけ添える。気づかなかったときは、何も書かない（見ていないのに「ほかに急ぐものは無い」とは書かない）。
- 使うのは、一覧・バックログ・計画を頼まれたとき、時間や期限より仕事が多いとき、作業を足したくなったとき。

## 出し方

1. 結論：入るか、入らないか（数字つき）。
2. 決めてほしいこと1つと、推し。
3. やる順（表。人と日、理由を各1行）と、残した余白。
4. やらない・閉じるもの（理由1行）。
5. 気づいたことは、急ぐ順に1〜3点。

## 例

頼まれた言葉：「月曜の顧客デモまでに直すものがこの12件。使えるのは私と2日だけ」

外す形：12件を全部「必須」「できれば」に振り分け、2日を目いっぱい埋めた日程を出す。「この画面は直っていますか？」など、コミットの履歴を見れば分かることを3つ聞く。最後に「ほかにログの整備もした方がいいです」と足す。

渡す形：

> 2日では入りません（見積もり 4.5 日、使えるのは余白を除いて 1.5 日）。
> 決めてほしいこと：デモで見せる画面を「注文」と「請求」の2つに絞るか、デモを木曜にずらすか。推しは2つに絞る案で、下の計画もその前提です。
> 1日目：デモの筋で落ちる不具合2件（デモが止まる）→ 請求の金額の表示（顧客の目に入る）。2日目の午前：注文の画面の表示の崩れ2件。午後は通しの確認と余白。
> やらない：直った2件（履歴で確認、閉じました）、同じ話の2件（1件にまとめました）、文言の好み3件（デモ後に回す案）。
