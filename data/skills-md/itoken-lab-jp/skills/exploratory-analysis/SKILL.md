# 答えの見えない探索を迷走させない

答えがあるか分からない探索では、AI は一つひとつの計算は正しく、偶然の当たりを「見つかった」と言わないくらいの慎重さもある。外すのは進め方で、次の形が多い。

- 探す前に「何を満たせば効くと言うか」を決めず、結果を見てから線を引く。
- 最後に1回だけ使うはずの確かめのデータを、表に並べて覗く、「もう少し」と言われて2回目に使う。使った自覚が無いか、使ってから認める。
- データの作り（時刻のずれ、欠け、記録のしかたの癖）を確かめないまま探し、作りの見かけを効果と読むか、時刻ごとの偏りのような所を一度も見ない。
- 試したスクリプトと結果を作業場所に残さず、次の人も自分も、何を何通り試したかを追えない。
- 外れたあと、次の手を「条件をさらに変える」で出す。なぜ効くはずかの見立てから出さない。

この Skill はそこを受け持つ。探すこと自体は楽観的に、数え方と結論は厳しくする。

## 1. 探す前に書く（1つの試しごとに）

作業場所のファイル（例：`hypotheses/001-<名前>.md`）に、流す前に書いて残す。版の管理があればコミットする。書いた時刻が「先に決めた」証拠になる。

- **見立て**：なぜ効くはずか。誰が・何が、なぜそう動くのか（例：「月末は経理の締めで支払いが集中するので、月末の数日は問い合わせが増える」）。見立てを言えない形を試すときは「探索」と書き、合否を付けない（下の 2 と 7）。
- **線**：何を満たせば「効く」と言うか。数字で書く（効果の大きさ、t の値、期間の前半と後半の両方でプラス、など）。費用（手数料・手間・値引きの原資）を引いた後で見る。
- **比べる相手**：何と比べて良いと言うか。何もしない版、でたらめに選んだ版、時期をずらした版のどれか。決まりを当てはめる所だけをでたらめにして、ほかの条件（回数・長さ）はそろえる。
- **データの範囲**：探す範囲・確かめる範囲・最後に1回だけ使う範囲に分ける。時間の流れがあるデータは時間で分ける（古い方で探し、新しい方で確かめる）。
- **動かす値**：調整する値は5つ以内にし、試す範囲も書く。書いていない値は試さない。

## 2. 試した数を数える

- 試した決まり・条件・値の組み合わせを、捨てたものも含めて全部数え、一覧（例：`trials.csv`、1行1試し）に残す。同じデータを見てから直した版も1つと数える。
- 線は試した数に合わせて厳しくする。試した数 N の中の一番を選ぶなら、たとえば片側 2.5% を N で割った水準の t を線にする（N = 1 なら 1.96、N = 20 なら 3.02、N = 100 なら 3.48）。または、でたらめの版で同じ N 通りを探し、その一番の分布の 95% 点を越えるかで見る。
- 結果を書くときは「何通り試した中の一番か」を必ず添える。
- 「探索」として流したもの（見立ての無い形、安い確かめ）も、一覧に「探索」と印を付けて残す。N には入れないが、その代わり探索で見つけた形は結果として出さず、事後の芽として、まだ使っていないデータで確かめる新しい試しにしてから数える。条件をいじる試しを「探索」と呼んで N を増やさずに回すことはしない。

## 3. 確かめのデータを汚さない

- 最後に1回だけ使う範囲は、決まりを固めてから1回だけ流す。表に並べる、平均を覗く、グラフで見るのも「使った」に入る。探す段階の表や集計に、その範囲を入れない。
- 使ったあとに直したら、その範囲はもう確かめに使えない。新しい範囲（これから来るデータ、まだ取っていない期間、本番で小さく試す）で確かめる計画を、流す前に書く。
- 使ってしまったら隠さず書き、その範囲での結果は「確かめ」と呼ばない。

## 4. 良すぎる結果と外れの両方で、まずデータを疑う

探す前に一度、データの作りを確かめる。結果が出たあとも、良すぎる結果（t が 5 を超える、特定の時刻・曜日・1件に効果が集中する）と外れの両方で、決まりより先にデータを疑う。

- **時刻**：時刻帯（UTC か現地時間か）と、日の区切り。分かっている出来事（発表・締め・祝日）が、データのどの時刻に出ているかで時計を確かめる。時期によってずれていないかも見る。
- **欠けと重なり**：1日の件数、週や月の初めと終わり、長い穴、同じ行の重なり。
- **記録のしかたの癖**：何の値か（買い値か売り値か、税込か税抜か、集計の締めの時刻）、特定の時刻だけ値が飛ぶ・戻る所、値幅0の行。時刻ごと・曜日ごとに値の分布を一度並べると、作りの癖が見つかりやすい。
- 作りの見かけを疑ったら、別の記録（反対側の値、別の出どころ、記録した人への質問）で確かめる。確かめられないうちは、その形を効果と呼ばない。
- **費用**：手数料・手間・値引きの原資を、上の 1 で書いた置き方どおりに引いたか。引く前と後の両方を見る。
- 直して測り直した結果は参考にとどめ、試した数は戻さない。直し方は、結果を見ずに決まるものだけにする。

## 5. 外れたとき・2回続けて外したとき

1. **データと費用を疑う**（上の 4）。
2. **何が残ったかを書く**：費用を引く前の形、効いた期間・場所・向き、まだ試していないやり方。悪い数字もそのまま書く。
3. **楽観の読み直しを1回だけする**：同じ結果を「どこなら効くか」の目で読み直す。見つけた形は「事後の芽」と書き、その場で合否を付けない。進めるなら、新しい番号で、まだ使っていないデータで確かめる計画を書いてから。
4. **棚に置く**：戻る条件と次の一手を1つ添えて、一覧（例：`shelf.md`）に置く。

2回続けて外したら、次を流す前に止まって、分かったこと・試した数・まだ疑っていない前提（データの作り、費用の置き方、比べる相手）を書き出す。次の一手は、条件をさらに変える案ではなく、別の見立て（なぜ効くはずか）から出す。

次の一手は、1つにつき1行で書く：見立て（誰が・何が、なぜそう動くのか）・一番安い試し方・期待する大きさ・やめる線。例：「使わなくなった会員は価値を感じていないので、ログインが3か月続けて減った会員は解約しやすいはず。今あるデータの翌月の解約率で見る。差が5ポイント未満ならやめる」。列や条件の組み合わせを並べるだけの案にしない。

「無い」「閉じる」は、同じ見立ての仲間（言い換え・範囲の絞り込みは同じ仲間）を3回外したときか、依頼者が決めたときだけ言う。それまでは「このやり方では残らなかった」と、やり方に向けて書く。

## 6. 押されたとき

- 「もう少し粘って」「何か1つくらいあるでしょ」には、線を下げない。粘るなら、新しい見立てで試しを足し、試した数に足して同じ線で見る。条件をいじり続けて、通ったものを出すことはしない。
- 依頼者が、確かめの済んでいないものでお金や本番を動かそうとしたら、何で確かめて何をまだ確かめていないかを数字で言い、小さく試す・期限と損の上限を決めるなどの案を出す。動かすか、いくら張るかは依頼者が決める。

## 7. 書き方

- 最初の文は「何が残ったか」と「次の一手」。
- 数字はそのまま書く（効果、t、何通りの中の一番か、年ごとや前半・後半）。「有望」「確実」「有意な傾向」のような言葉で盛らない。
- 試したスクリプト、試しの一覧、結果は作業場所に残す（一時フォルダーに置かない）。依頼者が次の回に追えるように、どこに何があるかを報告に書く。
- 結果を書くたびに「なぜ？」を3つ書く（変な数字、外れた期間、予想と逆の向き）。安く確かめられるものは「探索」として流してよい。合否は付けず、一覧には「探索」の印で残す（扱いは上の 2）。見つけた形は事後の芽として棚に置く。
