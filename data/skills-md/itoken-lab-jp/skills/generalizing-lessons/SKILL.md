# 具体と抽象を行き来する

抽象化は、具体の例から本質を抜き出すこと。本質とは、例がそうなっている理由や目的で、見た目の共通点とは違う。具体化は、抜き出した本質を別の場面の形に落とすこと。落としながら横に広げ、本質と食い違う例が出たら、本質の言葉を直す。この往復を回す。

AI は、上がる一歩はできる。指摘を「同じ種類」にまとめたり、事例から原則を立てたりする。外すのは次の形が多い。

- 決まりや指摘を、言葉のとおりに当てる。「22時以降は洗濯機を回さない」（理由は、階下の人が眠れない）を、21時だが階下の人が夜勤明けで寝ている日には当てず、22時過ぎだが階下が空き部屋の日には当てる。決まりができた経緯を読まない。
- 作った原則を、作るときに使った例にしか当てない。原則が手元の例の言葉に縛られて狭くなる（「`retry(3)` の 3 が回数か秒か分からない」という指摘から、ほかの `retry` は直すが、`wait(500)` や `limit` の同じ抜けは見落とす）。
- 当ててみて言葉と理由のずれに気づいても、元の原則や決まりの言葉を直す所まで戻らない。
- 直した箇所や差分を並べて終わる。逆に、原則だけを書いて例を捨てる。どちらも、次に使う人が新しい例に当てられない。

人は、似た例を思い出すときは見た目に引かれ、役に立つのは関係の形が同じ例だと分かっている。LLM も、見た目の似た例に引かれ、自分で作った規則を個々の例に当てるのが苦手である。だから、抜き出した本質は当ててみるまで仮のものとして扱う。直しや事例が3つ以上並んだら、並べて終える前に一度上がる。

## 1. 上がる：本質を抜き出す

- 例（直された箇所、事例、差分、決まり）ごとに、何を変えたかでなく、なぜそうなっているかを1文で書く。誰が何で困るか、何を防ぐためかで書く（「`retry(3)` を `retry({ times: 3 })` に」でなく「読み手が 3 を回数か秒か決められない」）。
- 決まり・仕様・前例は、できた経緯（振り返り、変更の履歴、決めたときの記録）を探して読む。経緯が無ければ、理由は推測と明記する。
- 2つ以上の例を並べ、理由の共通点を本質の文にする。例が1つしかないときは、ありそうな別の場面を自分で2つ作って比べる。
- 本質の文を、例に出てくる物の名前を使わずに言い直す。文に残るのが物や見た目の言葉（22時、`retry`）だけで、関係の言葉（〜すると〜になる、〜のために）が無ければ、まだ見た目の共通点にとどまっている。
- 高さを合わせる。新しい場面を見て、当たるか当たらないかを決められる高さにする。低すぎると言葉の禁止になる（「`retry` の引数に名前を付ける」）。高すぎると何も決められない（「読みやすく書く」）。ちょうどよい例：「数には、何の数か（単位・対象）が読み手に分かる形を付ける（文脈で一つに決まるときは省いてよい）」。

## 2. 下りる：別の場面の形に落とす

- 落とす先は、作るときに使っていない例にする。文書やコードの残り、同じフォルダーのほかのファイル、相談されている場面、次に使う予定の文章、違う分野の場面を自分で2つ。
- 探すとき・判断するときは、例や決まりの言葉でなく本質で見る（「何の数か」の抜けなら、`retry` に限らず、名前の無い数・単位の無い設定値・`n` や `limit` のような名前も拾う）。
- 落とした先に線を引く所（時間・金額・件数）があれば、線の両側の値を1つずつ挙げる（「30分以内」なら、29分は可、31分は不可）。
- 当たった所は、手元で分かる範囲で直す。直すのに要る事実（数字・連絡先・名前など）が手元に無ければ、作らずに印（【要確認】など）を付けて残し、報告で聞く。当たったのに黙って元のまま残さない。

## 3. 横に広げる：食い違う例を探す

当たる例を足すだけでは、本質に届いたかは分からない。食い違いを探す。

- 見た目は似ているが当てはまらない例を1つ探す（決まりの言葉には当たるが、防ぎたいことが起きない場面）。そこは変えない・止めない。なぜ当てはまらないかを、本質の文から説明する。
- 見た目は違うが当てはまる例を1つ探す（決まりの言葉には当たらないが、防ぎたいことが起きる場面）。
- この2つを本質の文だけで仕分けられなければ、文がまだ見た目をなぞっている。1に戻る。

## 4. 直す：食い違ったら、本質の言葉を直す

- 拾うべき所を拾えなかったら、本質の文を広げる。拾ってはいけない所を拾ったら、当てはまらない場合を理由つきで書き足す。直したら、前に当たっていた例が外れていないかを見る。
- 元の決まりや指摘の言葉が理由とずれていたら（「22時以降」でなく「階下の人が寝ている時間」）、言葉の直しを1〜2行で提案する。自分の持ち物でない決まりは、書き換えずに提案にとどめる。
- 止めどころ：当てて直す一巡で本質の文が変わらなければ止める。変わり続けても3巡で止め、残った迷いを報告に書く。

## 5. 残す：本質に例を1つ付けて戻す

- 手引き・学び・チェックリストに残すときは、原則ごとに、理由、典型の直す前と後の例を1つ（多くて2つ）、当てはまらない場合を付ける。
- 骨組みは原則で組み、事例は原則の下に置く。事例ごとの節（「A 社の場合」「B 社の場合」）にしない。細かい決まりの一覧を組み直すときは、元の決まりを捨てずにどれかの原則の下に置く。
- 作るときに使った例しか知らない読み手でも、新しい例に当てられるかを最後に見る。

## 6. 手間は頼みに合わせる

- 1か所だけの決まった直し（名前の変更、誤字、指示どおりの書き換え）では、この手順を回さない。そのまま進めて短く報告する。
- 決まりを当てる場面で、経緯を読んで理由を1文にした結果、言葉と理由が食い違わなければ、3以降は省いてそのまま答える。食い違うかどうかは、理由を読む前には決めない。
- 報告は結論から書く。取り出した本質、どこに当てて何を直したか（判断したか）、迷って残した所、決まりの言葉の直しの提案を短く添える。講釈は長くしない。
