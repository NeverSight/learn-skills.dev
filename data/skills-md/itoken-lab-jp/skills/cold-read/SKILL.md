# 文脈を持たない読み手に読ませる

書いた本人とレビューするエージェントは、会話・コード・経緯を知っているので、自分の言葉が通じるように見える。ルールや検査に照らすだけでは、照合できるもの（内部の名前、表記のゆれ）しか見つからない。「それ何？」「だから何？」は、文脈を持たない読み手にしか見つからない。

読ませるのは、新しく書いた文と大きく書き直した文。誤字や数行の直しは、読ませずにそのまま進める（新しい読み手を立てる手間に見合うつまずきが出ない）。

## 手順

1. 読ませる写しを、リポジトリの外（一時フォルダー）に作る。書き手のメモ（front matter、コメント、TODO）を外す。画像も伝わるかを見たいなら、同じフォルダーに置く。
2. 新しいエージェントを1つ立て、写しのパスだけを渡す。リポジトリ・会話・Skill は渡さない。依頼文に「ほかは見ない」と書くだけでは文脈は切れない。Claude Code の子は既定で CLAUDE.md の階層（全体とプロジェクト）と git の状態（ブランチと最近のコミット）を受け取るので、このリポジトリの `agents/claude/cold-reader.md`（`omitClaudeMd: true`、道具は `Read` だけ。v2.1.271 以降）に読ませる。それでも、環境の情報と git の状態は残る（公式 sub-agents の What loads at startup は、環境の情報の例に作業フォルダーを挙げ、git の状態は Explore と Plan のほかは外せないと書く。2026-11-01 にクラウドで `cold-reader` に尋ねると、作業フォルダーのパス・OS・日付・userEmail・モデルの名前があると答えた（自己申告）。子は頼む側の作業フォルダーで始まるので、写しをリポジトリの外に置いても、フォルダーの名前と git の状態から何の文章かを推し量られる余地は残る。減らす手立ては確かめていない）。Kiro では、このリポジトリの `agents/kiro/cold-reader.md`（道具は `read_file` だけ）に読ませる。全体の steering は入り、定義では外せない。起動したフォルダーのワークスペースの `AGENTS.md` と `always` の steering も入る（2026-10-26 の観測）ので、写しのフォルダーで `kiro-cli chat --agent cold-reader` を起動して読ませる。委譲で呼んだ子は親のワークスペースのものを受け取る（委譲で呼んだ子に何が入るかは確かめていない）。Antigravity では、このリポジトリの `agents/antigravity/cold-reader.md`（道具は `view_file` だけ）に読ませる（全体のルールとワークスペースのルールが子に入るかは確かめていない）。写しをリポジトリの外に置くのは、Claude Code では、中に置くとそのフォルダーの CLAUDE.md と path-scoped のルールも読み込まれるため（公式 sub-agents の What loads at startup）。子が親の会話を引き継ぐ道具では、引き継がない指定で起動する（Codex の組み込みの子は、`fork_turns` を受ける版では既定の `all` で会話を引き継ぐので `"none"` を明示する。`fork_context` を受ける版では、付けなければ引き継がない。どちらの版かは設定とモデルで変わる。openai/codex のソース rust-v0.163.0）。モデルは、その道具で選べるものから役割に合うものを選ぶ（下の「読み手」の中くらい・軽いは目安）。
3. 下の頼み方で読ませる。
4. 挙がった所を直す。書き手が「知っていて当然」と思っても、読み手が止まったなら直す。直さないと決めた所は、理由を PR に書く。
5. 大きく直したときは、直した写しを、別の新しいエージェントに読ませる（同じ相手は前の版を覚えている）。読ませるのは、最初の1回を入れて3回まで。読み手は回ごとに新しい小さなつまずきを挙げるので、つまずきが0になるのを待つと終わらない。3回目でも大きなつまずきが残れば、直すか残すかを書き手が決めて PR に書く。言い回しを数か所直しただけなら、読ませ直さない。
6. PR に、読ませた回数、挙がった所、直した所、直さなかった所とその理由を書く。

## 読み手

- 読み手の立場（知っていること・知らないこと）を2〜3行で与える。リポジトリに読み手の定義（例：`readers.md`）があれば、それを使う。
- 強いモデルは分野を知りすぎていて、読み手が止まる言葉で止まらないことがある。中くらいのモデルを基本にし、最後の版を軽いモデルにも読ませると、別の所に引っかかる（Claude Code の `cold-reader` は `sonnet`。軽いモデルに読ませるときは、呼ぶときに `haiku` を渡す）。
- 軽いモデルは、設定した読み手なら知っているはずの言葉（その道具の画面の言葉など）でも止まることがある。読み手の立場に照らして取捨し、捨てた理由を PR に書く。

## 頼み方（ひな形）

```
あなたは、はじめてこの文章を読む読み手です。日本語で答えてください。

読むのは次の1ファイルだけです。ほかのファイル・リポジトリ・ウェブは見ないでください（書いた人の事情を知らない状態で読むのが目的です）。
<写しのパス>

あなたの立場：<知っていること・知らないことを2〜3行>

上から順に読み、次の2種類の「つまずき」を挙げてください。
- 「それ何？」：意味が分からない、または何を指すか迷った言葉・言い回し
- 「だから何？」：書いてあるが、自分に何の関係があるのか、何をすればいいのか分からない文や見出し

形式：つまずきごとに1行で「場所｜種類｜引っかかった言葉｜なぜ引っかかったか（読み手の心の声で）」。出てきた順。
最後に、読み終わって何ができるようになったかを、読み手として2〜3行で。直し方の提案は要りません。
```

画像も見せるときは、画像のパスも「読むのは」の下に並べ、「画像が出てきたら、その場でファイルを開いて見る。『図で止まった』所も挙げる」を足す（並べずに頼んだ 2026-11-01 の1回では、`cold-reader` は画像を開いたが、「1ファイルだけ」とぶつかって迷ったと答えた）。読み手は図を見間違えることもあるので、挙がった所は自分で図を開いて確かめてから直す。

## 読ませても見つからないもの

別に確かめる。事実の正しさ（コード、公式の説明、実機）、リンク先が実在して公開されているか、図や画像の中の文字、同じシリーズのほかの文書とのずれ、値段や版のようにあとで変わる値。
