# iskronify — приведение репозитория к стандарту

Приведи **текущий репозиторий** к стандарту iskron: плотный `AGENTS.md` (читается каждую сессию каждым харнесом), `REALITY.md` рядом (носители реальности, читается по поводу), `CLAUDE.md`-указатель, ритуалы сессии и гейт качества. Конфиг **генерируешь** из скелетов `references/agents-template.md` (обложка и тело) и `references/reality-template.md`: слоты `<…>` заполни, неприменимые опциональные строки выброси, заметок `<!-- … -->` и угловых скобок в выходе не оставляй. Оба файла — *производные виды*: проекция источников (код, манифесты, CI, файловая система, граф) плюс тонкий слой авторского суждения, которое больше нигде не живёт. Два требования: **плотность** (каждая строка меняет поведение) и **точность** (каждая производная строка сверена с источником *в этом прогоне*).

**Контракт: `41`.** Минимально поддерживаемый — `39`. Шаг 7 пишет целевой контракт после проверки, не вместо неё; то же число стоит в `description` после «КОНТРАКТ AGENTS.md:». Поднимай на единицу, только когда перемена здесь или в скелетах делает уже сгенерированный файл *неверным* (секция, файл, ритуал, имя тула, обязательство), никогда ради формулировок. Для 38 и ниже — полный прогон по текущим источникам, не цепочка прежних переходов; для 39 и 40 — сверка и переход к 41 по справке. Отсутствующий, неверный и неоднозначный контракт назови именно так, не угадывай число. Обложка ниже 41, прежней формы, со штампом-датой или без штампа — полная дуга (правило запуска — «Выравнивание» двери `iskron`): назови исходное состояние и **до перемен открой и прочти целиком `references/migrations.md`**. Прежнее содержимое ищи и при контракте 41: число не заменяет сверки. Полный прогон сохраняет авторское суждение и чужие хуки, не стирает конфиг. **Файл впереди поставки не понижай**: `contract` выше 41 — прогон не зови и число не переписывай, обнови затеняющую копию `iskronify` и перечитай описание. **Расхождение строки `AGENTS.md` со скиллом называй вслух, молча не выбирай** (чья правда при каком `contract` — там же в двери); равен — дефект шаблона, **feedback** стюарду поставки скиллов.

**Сверка редакции поставки** — первым ходом всякого прогона и всякого вывода «инструкция скилла неверна»:

```
cat ~/.claude/plugins/cache/*/*/*/.claude-plugin/plugin.json     # что бежит (Claude Code)
gh release view --repo <репозиторий плагина> --json tagName      # что выпущено
node ~/.iskron-bridge/iskron-bridge.mjs --version                # что бежит у прочих харнесов — сборка моста
```

Отстал больше чем на патч — обнови поставку, перезапусти сессии харнеса, затем дуга; контракт движется с формой конфига, версия — с каждой отгрузкой.

Скелет *инлайнит* дисциплину («Правила персистентности», «Жизненный цикл сессии», «Рабочие принципы») исполнимой строкой на правило — действие, условие, ответственный, детали указателем: файл обязан стоять и без хука старта.

## Аудит → классификация → действие
«Файл есть» не значит «факты верны»: каждую заботу — против её источника, затем:
- **absent** — выведи из источника; авторский слот без проверяемого источника — в дело выравнивания, не выдумывай.
- **stale** — ре-спроецируй, перезаписав; записанное не тащи вперёд.
- **correct** — оставь.

### Источник истины по заботам
| Забота | Источник истины | Как проверить |
|---|---|---|
| Версии, зависимости | `package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` + lockfile | прочитать |
| Команды build/test/lint/dev | scripts, `Makefile`/`Justfile`, CI-workflow | прочитать; `--help`/dry-run, где дёшево |
| Гейт качества | конфиг линтера, `tsconfig`, CI-yaml | прочитать |
| Раскладка: карта кода, ловушки среды | слот «Раскладка» раздела «Проект» | слота нет — умолчание скелета: README компонента, до него карта в «Структуре проекта»; README уезжает потребителю — файл карты вне поставки; раздел — где README у выходов запрещён. Найден `GOTCHAS.md` — разреши по Шагу 1, до того слот «открыто», файлы нетронуты |
| Структура проекта, path-алиасы | файловая система + конфиг бандлера; при «README компонента» — сами README | glob / list; «компонент → README» — существованием файлов |
| Nature, production statement, послабления | граф, код репо, слово агентов; принятые владельцем ограничения сохраняются | порядок Шага 1; смена мандата или цены поломки без основания — принципиальный вопрос |
| Носители реальности (`REALITY.md`) | граф, наблюдаемый кодом путь поставки, слово агентов | достижимость канонического носителя; неизвестное — Ceiling, не выдуманный носитель |
| Проектные решения, why-клаузы, открытые вопросы | граф | `iskron_orient` / `iskron_search` |
| Состояние веток | git + форжа | `git status` / `log`; CLI форжи |
| Ловушки | авторское; дом — по слоту «Раскладка» | sanity-check — не автовыводить, не переносить между домами |

**Производные факты** (верхние строки, блоки канонов) ре-проецируются каждый прогон; **авторское суждение** (ловушки, why-клаузы, nature, носители) сохраняется, лишь сверяясь на здравость с кодом.

## Контракт выхода — плотность и точность
1. **Императив агенту**: «ориентируйся до кода», не «агенту следует».
2. **Каждая строка меняет то, что агент делает**; иначе удали. Чек-лист, не эссе.
3. **Без обоснований и пересказа графа** — линкуй; обоснование — в граф. `(why: …)` — только у инварианта, который агент иначе нарушит.
4. **Таблицы и буллеты**, одна директива на буллет.

**Вне объёма — механика оркестрации** (цепочки гейтов, проверка пушей субагентами, выбор моделей): её дом — скилл оркестрации или граф; делегирование проецируется ролевыми файлами (Шаг 6), не прозой.

## Процедура — два такта
Идемпотентна: в зрелом репо прогоняй каждую самопроверку, действуй по провалам, докладывай остаток.

**Кто исполняет прогон.** Граф прогона (контур, роль, атрибуты, дело выравнивания) и само дело ведёт позвавший (ведущий) — ремесло графа («Сквозные нормы» двери `iskron`); человека он будит только принципиальным вопросом, не разрешённым графом, кодом и коллегами (Шаг 1). Объёмную проекцию файлов (`AGENTS.md`, ролевые файлы, хуки) можно отдать роли `designer` на своём мосту-спутнике (такт 1, п. 5); нет субагентов, файла `designer` или спутника — проецируй сам. Файлы прогон обновляет сам, человека не ждёт.

**Ветвь «Первый граф» — `references/first-graph.md`: предложи человеку, принял — открой и исполни целиком до такта 1.** Срабатывает при нуле признаков выравнивания в git-репозитории (обложка, хук старта, штамп — Замер двери `iskron`) или нуле своих рабочих графов у учётки (личный mind и приглашение в общий не в счёт); при своих графах — один вопрос до первого действия, подключить к одному из них или завести новый, без ответа граф не заводится; свой граф есть и репозиторий хоть чем-то выровнен — не срабатывает. Разговор ведёт **onboarding**; рабочий запрос человека ветви не ждёт.

**Такт 1 «встать» — без вопросов, до минуты, в любом репозитории**: первый контакт, слово «iskronify» или отставание конфига. Быстро разрешаемое — в файл, остальное — «открыто» и вопросом в дело; затем такт 2 без ожидания человека.
1. **Адреса.** Граф и роль — из слова человека, адреса места в строке окна или `AGENTS.md`. Граф не назван — `iskron_realm(action="list")`: нуль рабочих — ветвь «Первый граф»; иначе сверь с записанным о репо и спроси коллег; не разрешилось — принципиальный вопрос о границе проекта (Шаг 1), имя не угадывай; создание — `iskron_realm(action="create")` по принятому выбору. Человек сессии и маршрут принципиального вопроса — «Старт» двери **iskron**; привязка — «Сойдись или эскалируй» скилла **standing**. Роль агента не привязывай к человеку; найденную прежнюю привязку назови в деле, не переизбирай роль молча. Для роли человека прежде создания ищи `iskron_search(q="", node_type="karta", manifested_as="svatantra")`; непривязанную связывай `user="me"` только по подтверждению человека; не выбирается — один вопрос человеку сессии, нет его — в дело выравнивания.
2. **Контур репозитория.** `origin` → `хост/организация/репо` → `iskron_search(q="", node_type="holon", attrs_filter="repository:<значение>")`. Нет — `iskron_add_holon` с `attrs.repository` и `open_room` дела выравнивания: под подходящим контуром области либо на верхнем уровне, не под единым корнем графа. Верх графа — 5–7 самостоятельных границ, а не холон «всё»; неясна область — спроси по лестнице старта. Один репозиторий — один контур; на повторном прогоне сверь снова.
3. **Роль на репо.** `iskron_search(q="", node_type="karta", steward_of=<контур>)`; нет — `iskron_add_karta` (`manifested_as=adhikarin`, мотивация — дистиллят того, что репо поставляет, `attrs.skills` — CSV ключевых скиллов роли до 64 знаков: по нему карту агента отличают от человеческой) и `steward` к контуру. Одна роль на репозиторий; у найденной без `attrs.skills` — допиши.
4. **Обложка и файлы — шагом моста**, первым ходом такта и снова по мере адресов п. 1–3, 5: `node ~/.iskron-bridge/iskron-bridge.mjs prepare --json --lang <ru|en> [--graph rN --holon N --agent-role N --case N] </dev/null` без модели пишет блок `iskron:` в `AGENTS.md`, заготовки `REALITY.md` и указателя `CLAUDE.md`, memory-guard рядом с чужими; стоящее не перезаписывает; контур и роль без флага выводит по `origin` из графа, когда у моста есть ключ (`derived`). Твоё — `left` (код 3); код 1 — отказ, ничего не записано; ответ не JSON (мост старше) — обложка по скелету и Шагу 7, guard по Шагу 4. Тело — на языке репозитория (скелет русский, английский переводишь сам). Слоты «Проекта» — значением по порядку Шага 1; неразрешённое — «открыто», вопрос — в деле. `REALITY.md` — таблица разрешённых носителей; пока их нет — заготовка моста (без него — заголовок и строка-заготовка из заметки `references/reality-template.md`); до носителей поведенческих закрытий нет.
5. **Дело выравнивания** на контуре п. 2: открытое есть (`iskron_case(action="at", node=<контур>)`) — веди его; нет — `open_room` у записи контура или `iskron_update`, зачин до 64 знаков: «Выравнивание <репо> под контракт N». Прежде первой записи — место под ролью на репо: держит мост — `iskron_channel(action="register", realm, karta=<роль на репо>, name=<его имя>)`, нет — `iskron_stand(realm, karta=<роль на репо>)`; затем `join`. Проекцию отдаёшь `designer` по «Поручению» справки `cases.md` двери **iskron** — дочернее дело, его №N в строку запуска; он встаёт спутником твоего места (`iskron_stand` с `satellite_of`, `register` не зовёт; форма записи — `references/delegation-1.md`, `delegation-2.md`, обе по порядку), дела выравнивания не ведёт, в граф не пишет, вопросы слотов — словом в дочернем деле, принципиальное — итогом; остаток переносишь в дело выравнивания. Первое слово: «есть вопросы по проекту, за который я отвечаю, — ответьте или скажите, кто может ответить». **Анкету, план и ход выравнивания в граф не пиши**: такт пишет туда только структуру (контур с `repository`, роль) и ловушки правилами (Шаг 7).
6. **Сторож памяти** — хук ставит п. 4; стаб `MEMORY.md` не создаётся и не обещается — guard его не пропустил бы; найденный — `references/migrations.md`. Непустая директория памяти — эвакуация по Шагу 5 в такте 2; до неё строка скелета о заморозке ссылается на строку дела выравнивания, не утверждает завершения.
Отчёт — слово в деле выравнивания: что разрешено, что открыто (такт по поручению из другого дела — отчёт там, с номером дела выравнивания и наблюдённым исходом); затем эстафета Шага 7.

**Такт 2 «доделать» — сам, не блокируя**, сразу после такта 1; каждый следующий старт читает сводку дела («Выравнивание» двери `iskron`) и пишет своим местом, войдя (п. 5). Слоты — по Шагу 1, разрешённый — значением в «Проект» без переспроса, вопрос — карточкой `ask`; строка «слот: <имя>» (`partial` — на ком, чего ждёт) — по желанию, только у неразрешённого, снимается тем же ходом (`ok`); ответ агента подписан его именем, не владельца, и подтверждения человеком не требует. Полная дуга (Шаги 1, 3, 4, 6) идёт без человека; неразрешённый слот держит только зависимую часть. Все слоты разрешены — `propose_close` (свидетельство — слоты «Проекта» и кто ответил), если ведущий ты; иначе слово ведущему.

### Шаг 1 — Разреши слоты (такт 2)
Дефолты молча не выбирай: граф, код репо и старый конфиг, затем агенты соседних контуров в деле выравнивания (порядок — ниже). В «Проект»: **Nature** (не `production` — что ослаблено и почему), «Стек», **гейт** (Шаг 3); политику ревью пачки — в слот раздела «Холодное ревью пачки» скелета, где нет применимого блока канона (не выведена — вопрос такта 2); граф — в обложку; принятые авторские ограничения сохраняй. Прежняя анкета узлом `#N` — полный прогон по `references/migrations.md`.

Также согласуй:
- **Кто отвечает на принципиальные вопросы** — по лестнице «Старта» двери **iskron**, не вершиной `group`; вопросы слотов — через ведущего в деле выравнивания, не анкетой в графе. Акт человека ответом координирующего агента не заменяется.
- **Общее изменяемое состояние build/test** (база, фиксированный порт, dev-сервер, глобальный кэш, облачная песочница): есть — зафиксируй ловушкой изоляцию по полосам: агенты гоняют ветки конкурентно в отдельных worktree.
- **Реальность** → `REALITY.md` по `references/reality-template.md` из графа, кода и ответов коллег — до *канонического носителя* каждого класса (собранный артефакт, не исходники; живой эндпоинт, не хендлер; чистая установка, не тёплый кэш); подтверждено правомочным держателем или предложено — помечай; недостижимое — *Ceiling* с причиной; вывод о носителе — не наблюдение поведения; датированные замеры — узлами в граф; в `AGENTS.md` — «Reality» указателем; закрытия по таблице — **reality-audit**.
- **Личной памяти в AGENTS.md нет** — ни слота, ни правила: где живёт личное и когда читается, решают дверь `iskron` и **minding**; вход в неё единый — **minding**, без хэндла и сохранённого адреса, недоступность не отсутствие; отказ memory-guard ведёт личную ветку туда же. Проектные инструкции — коммитящиеся файлы дерева и граф проекта, никогда глобальный файл инструкций, память харнеса, пользовательские хуки (о глобальном файле не спрашивай и не заводи). Личное предпочтение, мнение или переносимый способ → личный mind, даже на тему разработки; правило самого проекта → AGENTS.md или граф проекта по полномочию; применение найденного — по **minding**, не копированием в проект.
- **Фидбэк-рефлексия** (опыт *о методе* — в граф работы случаем, адресом стюарду инструмента): умолчание — **да** (`выведено: умолчание шаблона`, без вопроса человеку), регион feedback-reflection скелета остаётся, такт несёт хук мержа; **нет** — только по записанному слову (`согласовано: кто`): регион удали целиком.
- **Interop с workflow-набором** — только при найденном коэрсивном наборе (его скиллы в списке или директория в кэше плагинов; сегодня superpowers); найденный — не согласие: (1) **полный** (рекомендуется) — подсекция из `references/superpowers-interop.md` + spec-write-хук; (2) **только проза**; (3) **пропустить** — назови риск: дизайн-сессии набора не осядут в граф.

**Человек обычно не в треде** (его присутствие — не условие прогона). «Согласуй», «спроси», «подтверди» для слота везде означают этот порядок:
1. **Сделай всё, что от ответа не зависит**: аудит, выводимое, гейт, хуки.
2. **Сперва граф и код, затем братья — агенты соседних контуров.** Неразрешённое — в одном деле выравнивания: вопрос и передача работы — `ask`, знающих коллег — `invite`, уточнение уже взятого — `say` с `to` на место, их `answer` прими `ack` («Ожидание от делателя» справки `cases.md` двери **iskron**); строка «слот» — на отдельном от карточки ключе, не узел и не дело на слот; ответ — в слот с именем ответившего. Факт из графа или кода — «выведено», без строки дела; неочевидное основание — словом в деле.
3. **Принципиальный остаток — по лестнице старта через ведущего дела.** Принципиальное — смена мандата, принятого ограничения, цены поломки, выбор или создание графа (такт 1, п. 1), неразрешимый конфликт источников; отсутствие ответа или сведений само по себе — нет. Спросить, кроме человека, некого (новый граф, соседей нет) — невыводимое спрашивай у него, не угадывай. Прежде эскалации назови проверенное в графе и коде, кого спросил и почему вопрос вне твоего мандата. Рабочий ответ агента не заменяет акт человека. Дошло до своего человека — ведущий спрашивает по «Вопросу человеку» справки `cases.md`: карточка `ask` его месту, нет места — его роли; показ карточки и резервное слово — по той же справке, без дополнительного слова вслед карточке. В дело человека не зовёт (`invite`); места нет вовсе — карточка ждёт в деле, работа продолжается.
4. **Дырка, не догадка** (такт 1, п. 4), вопрос — в деле; непринципиальное неизвестное ждёт знающего агента или ведущего — старт двери впишет ответ без переспроса.
Отвеченное пишется сразу; один слот не держит остальные.

### Шаг 2 — Первое заведение графа
- Фокус-контур (граница проекта, не корень всего графа) — спроектируй `design`, создай `iskron_add_holon` (размещение — такт 1, п. 2; графа нет — ветвь «Первый граф»); seq — в `holon` обложки. **Атрибут `repository`** — `хост/организация/репо` из `git remote get-url origin`, без протокола и `.git`; его сверяет с origin старт двери и каждый прогон. Стоит другой — не перезаписывай: та же `организация/репо` на другом хосте — алиас (каноническое имя в атрибуте, предложи человеку перевести origin; ищи `attrs_filter="repository:*организация/репо*"`), иная организация или репо — форк или зеркало, решает человек (Шаг 1). «Not found» форжи по каноническому имени — не отсутствие: так приватный репозиторий отвечает без учётных данных; одна ли это форжа — проверяй без них или по публичному репо на ней.
- **Делатель — стюард.** Роль агента (такт 1, п. 3; мотивация — дистиллят Production statement) — `steward` к фокус-контуру, именно она, не старшая, иначе ориентация на контур не найдёт делателя; seq — в `agent_role` обложки. `group` — только к старшей агентской роли, не к роли человека. Найденные прежние связи к людям не воспроизводи: назови их в деле выравнивания для отдельного разбора, не снимай вслепую. Человек сессии и маршрут принципиального вопроса — по «Старту» двери **iskron**.
- **Холон + стюард — корень поля интеграции**; обход держит `integrity`. Об «общих поверхностях» не спрашивай и списка в AGENTS.md не пиши; не найденная зависимость — дефект модели (`design`, `weaving`).

### Шаг 4 — Хуки
**Ритуалы несёт поставка, не рабочее дерево**: старт, пуш и мерж говорят хуки плагина Claude Code и плагин OpenCode по `graph` обложки (полное слово старта — когда блок называет и `holon`, `agent_role`, иначе ранний вход онбординга; пуш и мерж — по исходу; в OpenCode он же — guard памяти). Прогон их в репо не пишет; Codex и pi хуков не получают — ритуалы держит проза «Жизненного цикла сессии». Поле `rituals:` блока (`start push merge guard turn`; нет поля — все) — выбор человека, прогон его не пишет.

**Memory-guard Claude Code — хук репо** в `.claude/settings.json`, пока `guard` включён (поля хук не читает — выключили, сними его): ставит шаг моста (такт 1, п. 4), коммитится; **мержи, никогда не перезаписывай** — чужие записи остаются рядом; моста нет — образец `references/hooks.md` байт-в-байт (путь в директории проектной памяти → **блок**, exit 2, с маршрутом факта в сообщении). Харнес спросил разрешение на запись — назови в отчёте и проверь чтением, что запись легла.

**Переход — своё старое только после проверенной замены, не по числу контракта** (кандидатов называет `left` шага моста). Свой хук старта, пуша или мержа в `.claude/settings.json` / `settings.local.json` глушит её слово; прежде снятия проверь на служебной сессии того же харнесса, что поставка несёт заменяемые роды по этой обложке. Только после наблюдённой замены снимай эти роды; иные ветки (гейт мержа…) и чужие записи остаются. Свой плагин ритуалов OpenCode — по `references/step4-hooks.md`. Нет проверенной замены или поставка на машине старше контракта — живые старые хуки не снимай, назови остаток в отчёте. Предупреждение о старом контракте не отключает хуки и не снимает memory-guard Claude Code.

**spec-write** (`PostToolUse` `Write|Edit`; только полный interop по штампу AGENTS.md) — путь похож на design/spec-док → напоминание: запись дизайна — граф; **свежесть ветки** — предложи pre-push-хук (оба — `references/hooks.md`).

**`references/step4-hooks.md` — открой и исполни целиком после хуков Claude Code, до Шага 5:** «OpenCode» — когда у репо есть OpenCode; «Самопроверка» — всегда, итогом шага.
