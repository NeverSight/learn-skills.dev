# 出件与门禁

模型写 Markdown，冻结的转换器以官方模板为版式载体转成 DOCX，版式门禁检查后一次性落进工作区（ADR-0006、ADR-0017）。本 skill 持两个 CLI，互不 import：

- `scripts/md2docx.py`：转换器，只依赖 python-docx，离线。
- `scripts/gate.py`：门禁，**本体零第三方依赖、且不新增任何依赖**（静态检查加版面推算，只用标准库）；PyMuPDF 降为可选，只在有渲染结果时才 import。只读、可单独对任意 DOCX 跑。

`--help` 是参数的权威。

## 跑得动转换器的环境

**约束的是转换器的后端版本，不是哪个解释器**（ADR-0018）。怎么弄到一个能跑转换器的解释器（系统的、uv 管的、现装的）归你，正文不指定；**没配过 python 不得阻断出件**（律师 2026-09-08 裁定，同 ADR-0017 对渲染器那条）。要守的只有四条：

1. **能 `import docx`，且是钉住的那个版本**：[requirements.txt](requirements.txt) 精确钉 `python-docx==1.2.0`，随本 skill 分发到这台机器，`pip install -r` 与 `uv pip install -r` 都直接吃得下。
2. **装出来的东西只落在临时位置**：不进案件工作区（工作区里只有过了门禁的东西），不进本 skill 目录与本仓库，也别装进用户全局环境。
3. **不静默**：转换器回显第二行给出这次用的解释器与实测到的 `python-docx` 版本，原样抄进审查报告的「生成依据」段。**版本对不上照常出件**（退出码不因此变成非零），那一行里会明写它不是钉住的那个版本，照抄即可。
4. **门禁本体零第三方依赖**（ADR-0017）：它不读这份清单，任何解释器上都跑得动；哪怕转换器怎么都起不来，已有的 DOCX 照样检得动。PyMuPDF 只是可选的渲染加信。

一条**走通过**的路（2026-09-08，Codex Full access，沙箱里系统 `python` 敲不动）：

```
uv python find                                                    # 拿到 uv 管的解释器，记作 <它>
uv pip install --python <它> --target <临时目录> -r <本目录>/requirements.txt
PYTHONPATH=<临时目录> <它> <本目录>/scripts/md2docx.py ...        # Windows 上是 set PYTHONPATH=...
```

**这只是走通过的一条路，不是唯一路**：手边的解释器已经装着钉住的那版 python-docx 就直接用它，uv 不在就另想办法。**受限沙箱（Codex `workspace-write`）下这条路 2026-09-08 实测走得通**（#78），两个条件：uv 与至少一个 uv 管的解释器已经在那个模式读得到的地方（沙箱里装不了新解释器）；uv 的缓存要指到能写的地方，默认缓存写不动时上面三条命令都要加 `--cache-dir <临时目录>`，或先设 `UV_CACHE_DIR`，否则第一条就退 2。**律师那台 mac 上能不能，仍未验证**（#79），别把它当成已验。

## 出一版的三步

1. **写稿**：按 [references/最小集.md](references/最小集.md) 写 `.md`，先整读该节点的官方模板（`模板/官方/<文件名>`）照它的段落与表格结构写；模板里的 `XX`、`【…】`、「（注：…）」是占位与说明，一个都不能留在稿里。一切标注、疑问、待确认写进审查报告，文书本体只有可提交的正文。
2. **转换到临时位置**：

   ```
   python <本目录>/scripts/md2docx.py <稿.md> --template 模板/官方/<文件名>.docx
   ```

   **不给 `--out`**，它写到 `%TEMP%/loo0ng-to-docx/` 并打印路径；回显第一行是产物路径，**第二行是出件环境**（解释器与 python-docx 版本），后者原样抄进审查报告的「生成依据」段。稿子 `.md` 也先写在那个临时目录里。**工作区里不建任何暂存目录**（`_staging/`、`tmp/`、`草稿/` 之类都不要）：工作区里只有过了门禁的东西。退出码 1 是稿子不在最小集里或表形与模板不合，按 stderr 改稿重转。
3. **门禁并落盘**：

   ```
   python <本目录>/scripts/gate.py <临时 docx> --template 模板/官方/<文件名>.docx --deliver 文书/<节点标题>/<标题>-v<n>.docx
   ```

   **通过与需人眼**两档都拷到 `--deliver` 的路径（位置相同、文件名不加任何装饰，已存在则拒绝、不覆盖），不通过什么都不落。

   | 退出码 | 结论 | 落盘 |
   | --- | --- | --- |
   | 0 | 通过 | 有 `--deliver` 则已落盘 |
   | 3 | 需人眼 | 有 `--deliver` 则已落盘 |
   | 1 | 不通过 | 否 |
   | 2 | 门禁跑不动：文书或模板打不开、推算层自身抛异常、用法错误、落盘被拒 | 否 |

   **零只有一个，任何非零都不许当成通过用**（ADR-0017）：`if gate.py; then` 这种写法必须让需人眼落进 else 分支。

   **`--deliver` 到 `文书/` 是出一版的最后一步，由 skill "loo0ng-doit" 驱动**：落进 `文书/<节点标题>/` 的就是一次生成，三件与图上那条生成条目缺一不可。律师只说「这稿子转成 word」「把这份 docx 检一下」时那不是一次生成，产物落在律师指的位置或留在临时位置，不进 `文书/`、不写审查报告、不动图（#28、#32）。

不通过就按不通过项改稿，重转重检**至多 2 次**；仍不通过就是**生成失败**：把门禁输出原文交给律师，不交出不合格件，律师可兜底自写（ADR-0006）。永远不要为了过门禁改成品 DOCX、跳过门禁、或把临时件手动拷进 `文书/`。

**重试只数不通过。** 需人眼不触发重试、直接落盘交人：带内时真值可能离阈值很远，为了让尺子好读去砍律师要的表述是净损失（ADR-0017）。一件同时有两档时结论取不通过、重试针对不通过项；重试后不通过项清了、需人眼还在，就按需人眼落盘。唯一的杠杆在预防：写 Markdown 那一步就把过长的标记写短。

门禁的输出（结论、不通过项、需人眼项、披露项）原样贴进审查报告的「版式门禁」段；结论为需人眼时，门禁另出一段**须目验清单**，原样放在审查报告的开头（第一段，在「生成依据」之前），它由门禁生成，**不由模型撰写、不改一个字**；报告的五段与引用律师陈述的格式见 [references/审查报告.md](references/审查报告.md)。落盘后再把稿子拷成同名的 `.md`、写 `-审查报告.md`，三件同目录。**生成条目由 skill "loo0ng-doit" 经 skill "loo0ng-graph" 追加，本 skill 自己不追加**：条目只有那一条来路（ADR-0008，#32）。

## 门禁查什么

不通过项（客观几何与结构，任一命中即不通过）：行高超阈值、页数超阈值（长标记撑列）；空白页（只有页码的页也算）；表宽超页面；页脚 PAGE 域写死，给了 `--template` 还查丢失；表格直接接 sectPr；元数据残留作者 / 最后修改者 / 上次打印时间；模板占位残留（`XX`、`×××`、`【…】`、下划线串），给了 `--template` 还查模板里括号说明段整段残留。

披露项（写进审查报告，不判不通过）：空单元格坐标（印模、签字等纸质要件本来就空，由律师判断）；页数；没有渲染结果时那一条（三项几何判据按推算给区间）；有渲染结果时另有请求字体不在嵌入字体里（本机没有方正小标宋简体，Word 用微软雅黑渲出，官方模板自身亦然）、有字没渲出来（多半是模板的固定行高把长文字裁掉了，改短或列进待裁定）。**没有渲染结果时这两条整条消失，不报「无」。**

需人眼（三档之一）：页数、空白页、最大行高这三项的推算区间横跨了阈值，门禁**测不准**，不是测出事故。判定式是推算给出 `[lo, hi]`、阈值 `T`：`T < lo` 该项不通过，`T >= hi` 该项通过，`lo <= T < hi` 该项需人眼；整件取最重的一档。其余七项静态判据读 XML 得点值、没有区间，**恒为二值**：需人眼永远指向一个几何量，不指向结构问题。有渲染结果时点值取代区间，这一档当场坍缩。

阈值 `--max-pages`（默认 30）、`--max-row-height`（默认 200 磅）**由律师定，模型不调**：默认值就是门禁，为了过门禁调高阈值与跳过门禁是同一件事；律师说本案文书就是长，落成一条陈述再带参数。阈值是单一常量，不按渲染后端分组（ADR-0017）。无渲染跑一件不到一秒；接上 Word 约 7 秒（冷启动），在 Codex 的 30 秒 shell 上限内。不做姓名词表。

## 没有渲染后端

**这是正常路径，不是故障**：律师办案那台机器（mac + WPS）恒定没有可无人值守的渲染通道，而缺 Word / WPS / 其他软件**不得阻断文书生成**（律师 2026-09-07 裁定，ADR-0017）。门禁照常给结论，只是三项几何判据从点值变成区间，披露项里多一条「无渲染结果」。已知的三种情形都照此处理，都**不是**退出码 2：

- 这台机器没有 Word / WPS：正常出结论。要显式走这条跑道就加 `--no-render`。
- 在 Codex 的沙箱里：沙箱里起不来 Word COM（0x80070520 登录会话不存在）。门禁照常给结论，不必请求在沙箱外重跑。
- Word 瞬时故障：门禁自己整个重试一次，仍不成就跳过渲染层、按推算给结论。不要同时跑两件门禁。

结论是需人眼时**不重试、直接落盘交人**，把门禁那段须目验清单原样放进审查报告开头，请律师在 WPS 或 Word 里打开看那几处。**「已生成」不再唯一等于「过了门禁」**（ADR-0017 后果段），判断依据只在审查报告里。

退出码 2 现在只剩：文书或模板打不开、推算层自身抛异常、用法错误、落盘被拒（目标已存在）。这几种照旧原话转告律师。

## 律师兜底自写的文书

律师说「X 我自己写好了」时，对那份 DOCX 跑一次门禁（不带 `--deliver`），结论与两类项照样写进审查报告，**只披露不阻断**：文件在律师放的位置（多半是归档后的 `材料/`），不搬、不改、不重转（ADR-0002）。这一步的整个流程（归档、写报告、经 `generate --lawyer-written` 登记为已生成来源律师）由 skill "loo0ng-doit" 驱动，本 skill 只出门禁结论。

## 与邻居的边界

- 本 skill 不决定写什么：材料、指南、模板、过往文书、现行陈述的整读与稿子的内容由 skill "loo0ng-doit" 负责；缺的事实照出并列进审查报告的待律师裁定，不停下来问。
- 官方模板原件住领域目录，起手时拷进 `模板/官方/`（skill "loo0ng-domain"、skill "loo0ng-setup-case"）；本 skill 只读它。
- 确定性规则只从真实事故进入：一次事故 → 通用裁定台账 → 一条规则加一对 fixture（仓库 `tests/loo0ng-to-docx/`），不预写。
