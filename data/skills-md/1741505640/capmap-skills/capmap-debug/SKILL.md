# capmap-debug — Debug 回合契约

原则：[capmap-system](../capmap-system/SKILL.md) · 方案：套件仓 `docs/方案/文档体系/Debug回合契约.md`  
**正交于** scheme→dev→archive：**不**读写方案/切片/测试的 `状态/*`。

## 何时进入

满足任一即进入本回合：

1. 用户消息含明显运行时失败信号：`Error` / `Exception` / `Traceback` / `FAILED`，或「报错」「修一下」且附日志  
2. 用户说「继续修 / 接着查这个错 / debug」  
3. **本会话已在 debug 回合**，用户只说「继续」→ 仍按本契约；**不要**重读全套 capmap 主流程 / 倒 Inbox

**不进入**：纯需求设计、纯文档、无失败信号的功能开干（走领域编码或 [capmap-scheme](../capmap-scheme/SKILL.md)）。

## 每轮强制清单（须写在回复里）

量级一行一项，缺一不可：

```text
复现：<命令或操作；没有则先要复现，本轮不改代码>
假设：≤2 条；各附「若否如何证伪」
改动：<为本假设服务的最小面；禁止顺手重构/扩 scope>
验证：<已跑复现的结果 / 无法在本环境跑→要用户下一份日志>
计数：尝试 n/3
```

## 硬规则

1. **无复现不改代码**（除非用户显式只要读代码定位，仍须给出将如何复现）。  
2. 本轮根因假设 **≤2**；改动只服务当前假设。  
3. 改完必须验证，或明确阻塞原因。  
4. **计数**：每次「为修同一失败而改动代码」+1。用户贴了**不同**失败信号可重置为 1；同一失败无新证据则累加。  
5. **停损**：无新复现证据下 `n ≥ 3` 仍未解决 → **停止盲改**，不得继续第 4 次碰运气修改。  
6. **停损后升级（默认）**：先**建议** Inbox 一行（须含开干指令：已证伪假设摘要 + 下一步实验）；**点头再写入**首页 Inbox。用户要成文再走 [capmap-scheme](../capmap-scheme/SKILL.md) 短方案。  
7. **覆盖**：用户明确「别管契约继续改」可覆盖停损；回复注明已覆盖。  
8. **与 gate/方案并存**：不改切片 Tag、不改方案主状态；结束后一句话回到原语境（如「可继续 01 / 交票」）。  
9. 判明是需求/设计错误 → 退出 debug → scheme 或 Inbox，不要用盲改代码「圆」需求。

## Checklist

```
- [ ] 1. 判定已进入 debug 回合（或「继续」续跑）
- [ ] 2. 回复写出 5 行清单；无复现则停在要复现
- [ ] 3. 最小改动 + 验证；更新 n/3
- [ ] 4. n≥3 无进展 → 停改 → 建议 Inbox 行（点头再写）
- [ ] 5. 不碰方案/切片/测试状态 Tag
```

## 不做

- 不引入 debug 专用 `状态/*`  
- 不强制每次写 `测试/` 文档  
- 不替代自动化测试框架配置  
- 不把「继续」解释成开下一张切片或推进方案主状态
