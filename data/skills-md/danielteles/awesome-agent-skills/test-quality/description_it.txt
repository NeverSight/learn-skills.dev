Standard indipendenti dal framework per la qualità di un singolo test automatizzato in TypeScript: asserire sul comportamento, non sull'implementazione; asserzioni significative; un solo scenario denominato per risultato per test; builder anziché fixture condivise; test double che meritano il loro utilizzo; test deterministici indipendenti dall'ordine; copertura letta come una mappa del non verificato. Usalo quando scrivi test per codice nuovo o modificato, rivedi i test in una pull request, o correggi un test debole, fragile o instabile — o quando l'utente dice "test quality", "unit test review", "these tests are brittle", "flaky test", "over-mocking", "testing implementation details", "AAA", "arrange act assert", o "assert on behavior".
