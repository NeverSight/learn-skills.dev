Normes neutres vis-à-vis du framework pour la qualité d’un test automatisé individuel en TypeScript : affirmer le comportement et non l’implémentation, assertions significatives, un scénario nommé par le résultat par test, constructeurs plutôt que fixtures partagées, doublures de test qui méritent leur place, tests déterministes indépendants de l’ordre, couverture lue comme une carte du non‑vérifié. Utilisez‑les lors de l’écriture de tests pour du code nouveau ou modifié, lors de la revue des tests dans une pull request, ou pour corriger un test faible, fragile ou instable — ou lorsque l’utilisateur dit « test quality », « unit test review », « these tests are brittle », « flaky test », « over‑mocking », « testing implementation details », « AAA », « arrange act assert » ou « assert on behavior ».
