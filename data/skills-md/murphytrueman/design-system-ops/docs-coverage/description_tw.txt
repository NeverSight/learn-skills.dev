審核設計系統的文件界面是否與其元件庫保持同步——涵蓋缺口（沒有文件的元件）、陳舊性（文件早於元件最後一次程式碼變更）、以及孤兒文件。此功能不需與程式碼庫整合，只需 Storybook 建置即可運作；Zeroheight、Supernova 以及自訂文件網站為可選層級。當有人提及以下關鍵字時觸發：docs coverage、documentation audit、are our docs up to date、which components are undocumented、is our documentation keeping pace、stale docs check、documentation health、Storybook coverage，或任何關於文件界面是否與元件相符的描述。不要因「撰寫文件」而觸發——此情況請使用 usage‑guidelines、pattern‑documentation、token‑documentation 或 ai‑component‑description。不要因一般系統健康（請使用 system‑health）或文件使用率/分析（請使用 adoption‑report）而觸發。請始終以使用者的語言回應。
