デザインシステムのドキュメントがコンポーネントライブラリの進捗に追いついているかを監査します — カバレッジのギャップ（ドキュメントがないコンポーネント）、陳腐化（コンポーネントの最終コード変更よりも古いドキュメント）、および孤立したドキュメント。コードベースやStorybookビルドとの統合は不要で動作します；Zeroheight、Supernova、カスタムドキュメントサイトはオプションのレイヤーです。次のような表現があったときにトリガーします：docs coverage、documentation audit、are our docs up to date、which components are undocumented、is our documentation keeping pace、stale docs check、documentation health、Storybook coverage、またはドキュメントの表面がコンポーネントと一致しているかどうかに関する質問。ドキュメントの作成（WRITING documentation）に対してはトリガーしません — その場合は usage‑guidelines、pattern‑documentation、token‑documentation、または ai‑component‑description を使用してください。システム全体の健全性（system‑health を使用）やドキュメントの利用状況/分析（adoption‑report を使用）に対してはトリガーしません。常にユーザーの言語で応答してください。
