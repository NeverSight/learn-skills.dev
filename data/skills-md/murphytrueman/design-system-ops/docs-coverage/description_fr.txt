Auditer si la surface de documentation d’un système de conception suit le rythme de sa bibliothèque de composants — lacunes de couverture (composants sans docs), obsolescence (docs antérieurs à la dernière modification du code du composant) et docs orphelins. Fonctionne sans aucune intégration du code source et d’un build Storybook ; Zeroheight, Supernova et les sites de docs personnalisés sont des couches optionnelles. Déclencher quand quelqu’un dit : couverture docs, audit documentation, nos docs sont‑ils à jour, quels composants sont non documentés, notre documentation suit‑elle le rythme, vérif docs obsolètes, santé documentation, couverture Storybook, ou tout ce qui concerne la correspondance entre la surface de documentation et les composants. NE PAS déclencher pour la RÉDACTION de documentation — utilisez usage‑guidelines, pattern‑documentation, token‑documentation ou ai‑component‑description pour cela. NE PAS déclencher pour la santé générale du système (utilisez system‑health) ou pour l’usage/analytique de la documentation (utilisez adoption‑report).

Veuillez toujours répondre dans la langue de l’utilisateur.
