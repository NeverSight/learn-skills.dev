رسم خريطة القماش الهوية على مستوى المنظمة: بصمة المستأجر/الاتحاد وتطبيق منهجية أوراكل لتعداد المستخدم قبل المصادقة — التعداد والبصمة فقط، ولا يُجرى تقديم الاعتماد أبداً. يغطي حل المجال إلى المستأجر (التحقق من مساحة الاسم Managed/Federated عبر Microsoft getuserrealm.srf، استخراج GUID الخاص بالمستأجر من بيانات التعريف OIDC لـ Entra، Autodiscover v2)، خريطة المستأجر‑الاتحاد من Microsoft بدون مفتاح (GetFederationInformation SOAP → اكتشاف النطاق الشقيق، اكتشاف فقط ROE، حافة المصدر FEDERATED_WITH محجوزة خارج مسار الهجوم)، اشتقاق slug المؤسسة في Okta + بصمة OIDC + تعداد النطاق المخصص المُحكم، بصمة ADFS سلبية/إيجابية + استنتاج الإصدار، كشف مرتبط بـ MX لـ Google Workspace، اكتشاف OIDC عام (Auth0/Keycloak/Ping Identity/OneLogin/Duo)، بيانات تعريف SAML (5 مسارات)، كشف تحدي Negotiate لـ Azure AD Seamless‑SSO، فحص وجود مستشعر API لـ Microsoft Defender for Identity (MDI)، منهجية أوراكل لتعداد المستخدم لـ Microsoft GetCredentialType (دلالة IfExistsResult: موجود / غير موجود / موجود في مستأجر مُتحالف / مخنوق) و Okta /api/v1/authn (اختلاف errorCode)، انضباط قابلية اكتشاف متوسطة مع حد ثابت قدره 20 مرشح لكل مستأجر وترتيب يعتمد على اهتمام المشرف/الدور، وتوليد مرشح تسجيل دخول من الاسم ونمط البريد الإلكتروني المؤكد يَفْشَل إغلاقاً (FAILS CLOSED) مع عدم إرجاع أي نتيجة عندما لا يُؤكَّد أي نمط للمؤسسة. يستند مباشرة إلى وحدات sso_idp.py و tenant_recon.py و core/email_patterns.py في تنفيذ ASM الإنتاجي. يعمّق — دون تكرار — مرجع نقطة نهاية القماش الهوية في مهارة OSINT الهجومية مع خريطة المستأجر‑الاتحاد، سير عمل الأوراكل، ومنهجية توليد المرشحات التي يفتقر إليها المرجع. يُستخدم عند بصمة مزود هوية المنظمة، أو رسم خريطة حدود المستأجر/الاتحاد، أو تشغيل تمريرة تعداد مستخدم قبل المصادقة المصرح بها، أو توليد مرشحات تسجيل الدخول من الأسماء المحصودة لتغذية ذلك الأوراكل — ليس أبداً للرشّ بكلمات المرور، أو تقديم الاعتماد، أو تجاوز المصادقة.
