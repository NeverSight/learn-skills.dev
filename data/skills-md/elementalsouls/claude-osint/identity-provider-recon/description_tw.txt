組織級別的身份結構映射：租戶/聯邦指紋辨識以及預驗證使用者列舉（ENUMERATION）之 Oracle 方法論——僅進行列舉與指紋辨識，絕不提交憑證。涵蓋網域到租戶的解析（Microsoft getuserrealm.srf 受管/聯邦命名空間檢查、Entra OIDC 中繼資料的租戶 GUID 抽取、Autodiscover v2）、無金鑰的 Microsoft 租戶與聯邦映射（GetFederationInformation SOAP → 同屬網域偵測、僅偵測的 ROE、將 FEDERATED_WITH 起源邊緣排除於攻擊路徑樞紐外）、Okta 組織 slug 推導 + OIDC 指紋 + 受管的自訂網域列舉、ADFS 被動/主動指紋 + 版本推斷、Google Workspace MX 相關偵測、通用 OIDC（Auth0、Keycloak、Ping Identity、OneLogin、Duo）偵測、SAML 中繼資料（5 種路徑）、Azure AD Seamless‑SSO 協商挑戰偵測、Microsoft Defender for Identity（MDI）感測器 API 存在檢查、Microsoft GetCredentialType（IfExistsResult 語意：存在／不存在／在聯邦租戶中存在／限流）以及 Okta /api/v1/authn（錯誤碼差異）的使用者列舉 Oracle 方法論、中等可偵測性規範，設有每租戶最多 20 個候選人的上限，並根據管理員／角色關注度進行排序；以及名稱 × 確認的電子郵件模式之登入候選人合成，若未確認任何組織模式則以封閉失敗（FAILS CLOSED）方式返回零輸出。直接根植於生產環境 ASM 實作的 sso_idp.py、tenant_recon.py 以及 core/email_patterns.py 模組中。深化——而非重複——進攻性 OSINT 技能中身份結構端點的參照，加入租戶‑聯邦映射、Oracle 工作流程以及參考中缺乏的候選人合成方法。於對組織的身份提供者進行指紋辨識、繪製其租戶／聯邦邊界、執行授權的預驗證使用者列舉階段，或從收集的名稱合成登入候選人以供該 Oracle 使用時使用——絕不可用於密碼噴射、憑證提交或驗證繞過。
