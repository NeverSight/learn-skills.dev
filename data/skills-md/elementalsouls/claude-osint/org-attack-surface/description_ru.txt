Составление карты поверхности атаки на уровне организации: учитывая юридическую идентичность компании, выясните ВЕСЬ ее интернет-след — корпоративную семью -> принадлежащие домены -> принадлежащие сетевые блоки/ASN -> действующие активы — с дисциплиной атрибуции, а не только с шириной DNS. Пирамида атрибуции на уровне организации (юридическое лицо -> LEI/регистрация -> корпоративная группа -> принадлежащие домены -> принадлежащие сетевые блоки/ASN -> действующие активы). Разрешение корпоративной идентичности через GLEIF LEI API (юридическое название -> LEI, прямое расширение дочерних элементов с точным кодом LEI, BFS с ограничением глубины только вниз, НИКОГДА повторное разрешение имени), полнотекстовый поиск SEC-EDGAR + названия дочерних компаний в Приложении 21, подтверждение объектов OpenCorporates, корпоративный график Wikidata SPARQL (P856/P355/P749/P1830). Атрибуция домена через обратный WHOIS (защита квот WhoisXML с предварительным просмотром и покупкой, связанные домены SecurityTrails — оба платные), crt.sh O = ось организации прозрачности сертификатов (без ключа), корреляция инфраструктуры (общий NS/MX/SaaS-TXT, членство в сетевых блоках, PTR обратного DNS) и объединитель независимых доказательств (1-prod(1-w_i), правило трех, OwnerTier НЕТ/СЛАБЫЕ/УМЕРЕННЫЕ/СИЛЬНЫЕ/ПОДТВЕРЖДЕННЫЕ) — «связанные» кандидаты, предназначенные только для обнаружения: НИКОГДА не сканируются автоматически. Атрибуция Netblock/ASN с помощью запросов RIR на уровне организации (поиск по дескриптору организации ARIN Whois-RWS, организация RIPE DB + поиск по обратной организации), которые восстанавливают «темные сетевые блоки» без ссылки DNS на начальное число, обнаружение ASN (RIPEstat + объединение BGPView), HYPERSCALER-SCOPE GUARD (никогда не присваивайте арендатору весь объявленный диапазон AWS/GCP/Azure/Cloudflare — оставляйте только блок, содержащий начальное значение, тегshared_hosting_cdn) и запросы Internet-Scan-Index с org-identity-seeded (Shodan/Censys/ZoomEye/FOFA/BinaryEdge org: фильтры + всегда включенный запасной вариант crt.sh без ключа). Сортировка при повышении к сканированию ранжирует забытые сетевые блоки, предназначенные только для обнаружения, путем обнаружения удаленного доступа (оценка портов поставщика шлюза/KEV/плоскости управления/хранилища данных) в очередь оператора. Рубрика достоверности атрибуции + антишаблоны (прививка тезки посредством повторного разрешения имени GLEIF, владение одним сигналом, чрезмерная атрибуция гипермасштабатора, подмена сводной информации о конфиденциальности и WHOIS, коллизии названий организаций RIR). Только пассивный/бесключевой OSINT — каждая зависимость платного ключа является дополнением к бесключевому ядру и никогда не является жестким требованием. Используйте при сопоставлении всего корпоративно-семейного Интернет-следа организации, привязке юридического лица к его кодам LEI/дочерних компаний, обнаружении доменов/сетевых блоков/ASN, которыми владеет организация за пределами ее одного исходного домена, аудите слияний и поглощений/разрастания теневых ИТ или определении масштаба взаимодействия, которое начинается с НАЗВАНИЯ компании, а не с домена.
