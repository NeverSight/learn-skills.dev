组织级云和供应链攻击面发现：通过观察名称挖掘 (CNAME/cert-SAN/Wayback) 和有界两类排列（受信任令牌上的 6 个前缀 x 15 个后缀、子域词干上有界目标绑定扩展）进行 S3/GCS/Azure Blob 存储桶发现、存在 (HEAD/GET) 与公开列表确认、将对象密钥分类为 9 个值层（数据库转储、凭证、 IaC 状态、kubeconfig、VCS 目录、配置、存档、PII、日志）、悬空 CNAME 存储桶接管检测以及所有权门控严重性模型，该模型可阻止不可归属的公共存储桶成为错误的 CRITICAL；从泄露的 AKIA/ASIA/AROA 访问密钥中完全离线恢复 AWS 账户 ID（base32 解码、可运行的 stdlib Python、规范测试向量、AWS 文档示例 ID 筛选）； npm/PyPI 的依赖混淆确认（内部信号分类器——私有注册表绑定与组织命名空间匹配——与只读公共注册表 404 检查和公共搜索 API 错过的 npm 范围声明性细微差别配对）；以及被动云原生/容器/Kubernetes/CI 控制平面指纹识别（Lambda URL、API 网关、Cloud Run、应用服务、kubelet/etcd/K8s API/仪表板、Jenkins/GitLab/Argo CD）作为组织归因和暴露表面。仅被动/发现——无利用、无凭证提交、无主动控制平面确认（描述了第 6 阶段 validate_cloud 主动层，但超出了范围）。在枚举目标的云存储足迹、从泄露的密钥中恢复 AWS 账户 ID、确认供应链依赖性混淆向量或对云原生/K8s/CI 基础设施进行指纹识别以进行授权的外部侦察时使用。
