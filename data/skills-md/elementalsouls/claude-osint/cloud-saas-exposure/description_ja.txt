組織レベルのクラウドおよびサプライ チェーンの攻撃対象領域の検出: 観察された名前マイニング (CNAME/cert-SAN/Wayback) および制限された 2 クラスの順列 (信頼できるトークンの 6 つのプレフィックス x 15 のサフィックス、サブドメイン ステム上の制限されたターゲット制限拡張) による S3/GCS/Azure Blob バケットの検出、存在 (HEAD/GET) と公開リストの確認、9 つの値層へのオブジェクト キーのトリアージ(データベース ダンプ、認証情報、IaC 状態、kubeconfig、VCS dirs、config、アーカイブ、PII、ログ)、ダングリング CNAME バケット乗っ取り検出、および原因不明のパブリック バケットが誤って CRITICAL になるのを防ぐ所有権ゲート型重大度モデル。漏洩したAKIA/ASIA/AROAアクセスキーからの完全オフラインのAWS-account-IDリカバリ（base32デコード、実行可能なstdlib Python、正規テストベクトル、AWS-documentation-example-IDスクリーニング）。 npm/PyPI の依存関係の混乱の確認 (内部シグナル分類子 -- プライベート レジストリ バインディングと組織名前空間の一致 -- 読み取り専用のパブリック レジストリ 404 チェックと、パブリック検索 API が見逃している npm スコープの要求可能性のニュアンスと組み合わせたもの)。組織属性および公開サーフェスとしてのパッシブなクラウドネイティブ/コンテナ/Kubernetes/CI コントロール プレーン フィンガープリンティング (Lambda URL、API Gateway、Cloud Run、App Service、kubelet/etcd/K8s API/ダッシュボード、Jenkins/GitLab/Argo CD)。パッシブ/ディスカバリーのみ -- 悪用なし、認証情報の送信なし、アクティブなコントロールプレーンの確認なし (ステージ 6 validate_cloud アクティブ層については説明されていますが、範囲外です)。ターゲットのクラウドストレージのフットプリントを列挙する場合、漏洩したキーから AWS アカウント ID を回復する場合、サプライチェーンの依存関係の混乱ベクトルを確認する場合、または認可された外部偵察活動のためにクラウドネイティブ/K8s/CI インフラストラクチャのフィンガープリンティングを行う場合に使用します。
