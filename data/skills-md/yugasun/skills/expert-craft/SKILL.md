# 专家式做事：做深，而不是做大

用顶尖专业人士的方法完成用户要的工作：**明确边界 → 四问定方法 → 实际执行 → 独立验收 → 交付成果**。

列出了方法不算完成；按方法做了工作，并用证据检验结果，才算完成。深度来自问题判断、原始材料、领域方法和验收，不来自更多篇幅、功能、章节或研究主题。本技能提供通用工作方法，按需结合领域技能，不以专家口吻或虚构资质代替专业动作。

## 一、明确交付与授权边界

从上下文明确：为谁解决什么问题、结果用于什么决定、交付什么，以及范围、时间、预算等约束。

按用户要求选择交付路径：
- **完成任务（默认）**：用四问确定方法，然后实际执行并验收，交付用户要的成果，不停在诊断、计划或重写提示词。
- **只优化任务或提示词**：显式回答四问，再交付可独立执行的新指令，到此停止。具体要求见末节。

“执行”指完成被要求的工作。用户要方案，就产出并评审方案；要分析，就完成分析；不因此获得实施方案、部署、发消息或修改生产环境的授权。外部副作用和高风险操作遵守现有授权与确认要求。

保持原目标、对象、资源和交付形式。新增动作必须直接提高原结果的可靠性，优先替换浅层做法，而非叠加工作量。资源有限时优先验证最可能改变结论的问题，缩减低价值步骤，不擅自增加资源要求或删减原定交付。确需改变边界时说明冲突，让用户决定。

先用上下文和可用工具补齐信息。只有缺口会改变目标、方法或可行性，且无法自行查明时才提问；非关键缺口标注假设后继续。

## 二、四问定方法

开始实质工作前，为当前任务回答四问，形成可执行的工作依据。复杂任务可用几句话说明关键动作、材料和验收；简单任务直接融入执行，无需强制输出四个章节，也不等待用户重新发送提示词。

### 1. 顶尖专业人士会做什么，而原任务没有要求？

找出最影响结果的 1–3 个遗漏动作，说明它们解决什么关键不确定性。例如核对分母、检查样本偏差、比较替代解释、复核关键计算、寻找反例。

只补服务原目标的动作。已有要求则明确需要加深的环节，不把复述包装成洞见；用具体动作替代“全面分析”“最佳实践”。

### 2. 应从什么最原始的材料开始，而不是已被消化的结论？

点名材料及需要的部分，并识别摘要可能隐藏的信息：
- 业务分析：交易明细、事件记录、访谈原话，而非汇总观点。
- 研究：官方原文、原始数据、实验记录，而非二手报告结论。
- 文稿：原稿、事实出处、目标读者的原始反馈，而非修改意见摘要。

核对来源、时间、定义、单位、口径和代表性；一手材料也可能失真，多个转述同一出处的来源不算独立佐证。

### 3. 具体采用什么方法和工具？

落实为：**具体输入 → 分析或处理方法 → 工具 → 产生的证据**。

点名适合问题的方法和工具，并说明它们减少哪个不确定性。例如“用 SQL 按渠道与注册周重算留存，检查总体下降是否来自用户构成变化”，而非“使用数据工具深入分析”。

优先采用现有环境和工具，必要时使用领域技能。环境未知则先检查，不虚构工具可用性或为显得专业堆砌工具。方法按风险和不确定性选取，不机械套用全部技术。

### 4. 除了你或我，什么能证明结果正确？

在形成结论前明确：
- **主张**：具体要验证什么。
- **依据**：对应的独立数据、原文、可复现测试、领域标准或真实使用表现。
- **通过条件**：观察到什么才支持主张。
- **推翻条件**：什么反例、替代解释或失败现象会使结论不成立。

验收应约束结论，不能只是 AI 自评、用户觉得满意、工具调用成功，或用同一套假设重复生成答案。阈值来自用户约束、适用标准或有依据的业务要求；未确定的阈值标为待校准，不凭空设定。

没有唯一答案的任务，分别检验事实、约束和预期效果，保留审美与偏好判断的边界。

## 三、按方法实际完成工作

把四问落实为行动，而不是只描述未来会做什么：
1. **取得材料**：已有材料直接使用；授权范围内能用工具取得的就实际取得。区分已取得、缺失和不可得，不把摘要冒充原文。
2. **处理与产出**：实际分析、计算、修改、运行或创作，优先处理最可能推翻初步判断的问题，产出用户要的成果。
3. **保留依据**：关键判断能追溯到材料位置、计算或运行结果，形成“主张 → 证据 → 推理 → 限制”。区分事实、推断与假设。

材料冲突时追查口径或时间差，无法消解则保留分歧。材料不可得时使用有说明的替代来源，完成仍有依据的部分，明确哪些结论不能成立；不虚构访问、调用、结果，也不无限扩张收集范围。

## 四、独立验收并修正

实际执行第二节确定的验收：复算关键数字、核对原文、运行真实使用路径、比较独立数据或检查适用标准。工程修改要观察改变后的行为；分析与方案要检查依据和约束，不能把“未实施”写成“已证明有效”。

检查最强替代解释、边界和失败情形。发现反例或不符时，回到材料或方法修正，再验证受影响的结论。相关关系不自动证明因果，小样本点估计不自动证明优势。

分别标明计划做、实际做、验证通过的内容。无法执行某项验收时说明原因及影响，降低结论强度；可以交付有明确边界的结果，不把未验证包装成通过。

## 五、交付成果与停止

遵循用户指定的形式和篇幅，先给成果或结论，再按需要附关键证据、实际验证结果和影响使用的限制。无需固定输出诊断长文或新提示词，也不为展示工作额外交付报告。

完成前检查：
- 用户要的成果是否实际产出，而非只有方法或计划？
- 专家关键动作是否落实，关键判断是否有可追溯证据？
- 验收是否实际发生，未验证部分是否明确？
- 是否保留原范围、资源与授权边界？

达到验收条件即停止。资源用尽或关键前提不可得时，如实交付已完成内容、证据缺口及尚不能支持的结论，不用无依据的确定性填补空白。

## 分支：用户只要求优化提示词

按顺序交付 **四项诊断 → 重写后的提示词**，不执行原任务。

四项诊断分别具体回答专家遗漏动作、最原始材料、方法工具、独立验收。将答案转为一段可复制、可独立执行的指令，包含原目标与约束、关键动作、材料、方法工具、验收与反例、材料不足处理、最终交付形式及停止条件。

所有新增要求应能追溯到四问，删除装饰性流程和附加交付物。使用当前任务的具体内容，不留泛化占位符或“按上面的方法”等指代。明确这是任务设计，拟用方法不代表已经执行或验证。

## 示例：同一方法，两种交付

用户：“分析本月留存下降的原因，给我一页建议。”

默认先确认留存定义和完整观察窗口，实际取得用户级注册、活跃事件及渠道数据，用现有 SQL 工具重算总体和分群留存，并按基期渠道权重重算本月指标。用独立计数路径复核关键分子分母、抽查原始事件，检查同渠道同成熟度用户是否也下降。最终在一页内交付证据支持的解释、限制和建议，不只输出查询计划，也不将观察性结果写成因果证明。若数据无法取得，明确不能完成原因判断，不编造分析结果。

若用户说“只优化这段提示词”，则显式回答四问，将上述动作及验收写入新指令后停止，不查询数据、不宣称已分析。
