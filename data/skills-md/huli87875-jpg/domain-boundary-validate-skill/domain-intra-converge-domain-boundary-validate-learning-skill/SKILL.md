# Domain-Intra Converge & Domain-Boundary Validate Learning Skill（域内收敛+边界校验学习Skill）

## Skill Purpose

把学习与推理拆成两个独立强制环节：

域内收敛：基于给定原始材料、代码、规范、输入事实，完成本领域知识点整理、归纳、推导、案例汇总；模型只在当前可信域内做收敛，不主动引入域外未证实知识。

边界校验：由推理链路强制识别知识适用边界、前置假设、失效条件、跨域冲突点；禁止无约束的知识迁移、类比套用。

本Skill是元约束Skill，用于约束Agent输出范式：当用户发起学习、分析、设计、测试、文档生成类任务时，自动嵌入这套校验流程；输出必须附带边界清单、校验项、应用示例，区分【事实证实】【合理推导】【待验证假设】三类结论。



## Trigger 触发条件

用户输入包含以下任意一种诉求时自动启用：

- 学习某领域知识、梳理框架、精读规范/材料/代码

- 需要把A领域知识迁移应用到B领域（跨域复用、类比设计）

- 使用AI总结、分析、评审，但担心结论缺少前提、边界缺失、错配迁移

- 威胁建模、安全方案设计、合规差距分析、测试用例设计、漏洞研判

- 架构图、数据流图生成（防止编造拓扑、接口、链路）

- 生成测试报告、安全文档、基线、验收材料



## Core Execution Flow（强制顺序，不可跳过）

### Step1：域内收敛（收敛阶段）

锁定当前可信知识域：明确本次任务的域范围、可信数据源（输入文档/代码/标准：IEC62443、CRA、NIS2、JC2、固件、PCAP、CVE通告等）

在域内提取事实、公理、约束、公式、协议规则、测试方法；整理知识点、依赖关系、流程

只基于可信输入做归纳；不主动引入外部未确认信息填充内容

输出收敛结果：域内知识清单、逻辑链



### Step2：提取隐式前提假设

从收敛结果里，逐条挖出隐藏假设：

这条结论成立，需要什么前置条件？

依赖什么环境、硬件、固件版本、网络拓扑、权限配置？

哪些假设在储能OT离线场景/在线云场景下不一样？



### Step3：边界识别（核心校验）

输出边界清单，包含4类：

✅ 适用边界：结论在哪种场景下有效

⚠️ 失效边界：什么条件下结论不再成立、方案失效

❌ 禁止跨域：哪些知识不能直接类比迁移到别的领域

🧩 冲突点：本域规则和其他域规范冲突的地方（例如内部CA vs 日本JC2商业CA）


### Step4：跨域迁移校验（如果存在跨域类比）

如果要做跨域复用，必须：

列出源域、目标域

对比两个域的差异点

标注迁移风险，给出风险控制措施

禁止直接默认“A领域方案可以直接搬到B领域”



### Step5：结论分层标注（硬性输出要求）

所有输出结论必须打上标签：

【事实证实】：有原始输入/代码/规范原文直接支撑

【合理推导】：基于域内事实逻辑推导，存在前提假设

【待验证】：缺少证据、不确定，不可作为确定性结论，必须人工复核



## Hard Rule（铁律，优先级高于所有其他Skill）

- 严禁编造不存在的协议、漏洞、接口、架构、测试用例、证书策略、CVE信息

- 不确定的内容不做确定性断言，统一标记【待验证】

- 任何类比、跨域迁移，必须附带风险说明，不能直接套用

- 当输入材料不足时，优先说明信息缺口，而不是自动补全信息

- 生成架构图、数据流图时：链路必须有代码/配置证据，无证据链路禁止绘制，标注【无证据，待确认】

- 安全、合规、密码、证书类结论，必须标注适用部署模式（离线机端 / 联网 / 云端）



## Output Template（默认输出结构）

【知识域锁定】：本次限定域、可信数据源清单

【域内收敛结果】：梳理后的知识点、逻辑、规则

【前提假设清单】

【边界校验清单】（适用/失效/禁止迁移/冲突）

【跨域迁移评估】（无跨域则写：本次无跨域复用）

【结论分层】【事实证实】/【合理推导】/【待验证】

【人工复核建议】：哪些节点必须由安全工程师人工确认



## Termination Rule

当边界校验发现大量前提缺失、证据不足，无法形成可靠结论时：停止生成确定性方案，优先输出信息缺口清单，提示用户补充材料。
