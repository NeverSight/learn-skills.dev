# PPO 设计原则

用 PPO 训练强 agent，关键只有两件事：**可扩展（scale）** 和 **训练稳定**。设计目标是"模型变大、经验变多就会变强"，然后在不崩的前提下把这两个量做大。本 skill 的六条原则来自 Kaggle 模拟赛（对战类游戏 agent）的实战总结，底层思想是 Sutton 的 The Bitter Lesson：塞入人类知识短期见效但很快封顶，最终胜出的是靠搜索与学习去消耗算力的方法。

## 核心权衡：scale vs 先验知识

预算（算力、时间）有限，PPO 设计就是在两侧之间取平衡：

| 靠 scale 学 | 靠先验提效 |
|---|---|
| 表达全部行动 | 约束行动 |
| 原始信息 + 大量经验 | 人工特征 |
| 有实绩的结构（Transformer） | 自研结构 |
| 只用胜负奖励 | 辅助奖励 |
| 自博弈 | 和别的策略对打 |

**默认站 scale 一侧**。只有在算力约束下、为了学习效率、且清楚自己放弃了什么时，才引入先验。每引入一条先验，都要能回答："这会不会让模型变大后无法继续变强？"

## 适用范围：完全信息与不完全信息博弈都适用

六条原则不区分信息是否完整。典型的不完全信息任务如卡牌对战：对手手牌、牌库不可见，牌库只能看到张数。它的处理方式没有任何特殊机制：

- 观测 = 规则允许看到的部分；信息损失只发生在这一步，之后（特征、模型）不再丢（原则③）
- 策略和价值都只用这个观测，不给价值网络偷看全局状态，也没有加历史或 belief 建模——靠经验量让模型自己学会在隐藏信息下决策
- 抽牌随机、胜负信号有噪声，仍然只用胜负奖励（原则⑤），用 γ=1、λ=0.99 和大经验量来消化噪声

所以遇到不完全信息任务，不要默认先去找"隐藏信息专用方法"。asymmetric critic、历史 token、对手建模这类手段都属于先验知识一侧，按原则③的判据（学习效率提升 > 探索成本 + 训练成本）决定加不加，而且要能回答"模型变大后它会不会成为瓶颈"。

"变大就变强"需要三个条件同时成立，评审任何设计时用它们做检查：

1. **变大不崩** —— 训练不发散、持续上升（见 [references/stability-tips.md](references/stability-tips.md)）
2. **变大不变慢** —— 采集经验和推理的速度不被拖垮
3. **变大有价值** —— 必要的信息和行动都能被表达，否则再大也封顶

## PPO 全貌

rollout（采集经验）与 update（更新权重）交替：N 个向量化环境并行，agent（策略 π_θ + 价值 V_θ）从观测输出行动，对手也是同一个 π_θ；经验数据 = 观测、行动、log π_old、价值、奖励（胜负），规模为 env 数 × step 数；update 用 clipped loss + value loss + entropy，同一批经验更新数个 epoch，再把新 θ 送回 rollout。六条原则分别对应这张图上的六个部件。

## 六条原则

### ① 用 Rust/C++ 写向量化环境

**经验量的上限由环境速度决定**。先把环境做快、做并行，GPU 才不会空等。

- 反模式：拿着慢的逐步环境直接训练 —— GPU 在等，经验量上不去
- 反模式：用 JAX/CUDA 写环境 —— 环境挤占本该给训练的 GPU；环境多是稀疏运算，很少比 Rust 快；特征不好灵活改，维护成本吞掉本该花在 scale 上的时间
- 经验量 ∝ 环境数 × 单环境速度。目标是 N 个环境的观测合成一次 forward
- 重写环境交给 coding agent（Codex 等）一次完成即可；正确性用"与官方实现输出一致"来验证
- 常见瓶颈不在规则引擎本身，而在 Python 侧每步的序列化/反序列化（如 JSON decode 组装观测）。直接传观测，去掉这层

### ② 不约束行动空间

**把最小单位的行动全部表达出来**；mask 只用于规则上无意义的行动。

- 反模式：人设计宏动作让模型选（攻击/防御/攒资源）。漏掉的行动永远表达不了，模型再大也封顶
- 原则：最小操作直接作为行动（选一张卡、走一格），组合方式交给模型学
- mask 规则上不可执行、或执行了什么也不发生的行动。若引擎能枚举合法手，直接用引擎的枚举，规则上不能做的手根本不出现
- **不要 mask 人"觉得没意义"的行动**（比如"直接结束回合"）。人一删就退化成人工行动空间；判断交给学习
- 例外：受算力约束、为学习效率而加人工约束（固定数量等）是可以的，但要先弄清楚会失去哪些策略再决定

### ③ 不丢信息，不在特征上花哨

**丢掉的信息学不回来**；人工特征只加那些收益大于成本的。

- 反模式一：丢信息 —— 模型变大也不变强
- 反模式二：过度设计特征 —— 时间花在探索特征和反复重训上；重特征让每步计算变慢，同预算下经验量减少（长历史也同理）
- 链路是 环境状态（全部信息）→ 观测（可见部分）→ 特征（喂给模型的形式）→ 模型。信息损失要发生在"观测"这一步（规则决定的可见性），不要发生在"特征"这一步
- 加人工特征的判据：**学习效率的提升（更少经验学会） > 探索成本（找特征、重训）+ 训练成本（每步更重、经验变少）**。只有净收益为正的才加
- 结构化定义（如卡牌/技能效果的 DSL）可以逐操作 token 化，用一个小 encoder 编成 embedding 喂给主模型，不必手工总结成数值。这类 embedding 若只依赖静态定义、与局面无关，推理时可预先算好缓存，encoder 不参与推理

### ④ 模型用 Transformer

灵活、有 scaling law、有成熟的加速手段。格子状棋盘也可以考虑 CNN。

- 反模式：用先验去精雕模型结构，把预算花在结构探索上 —— 不保证命中，加速和稳定化都得自己重来
- 选 Transformer 的三个理由：能变成 token 序列的东西都能塞（卡牌、盘面、历史）；scaling law 已知，"变大就变强"押得住；FlashAttention、fused kernel、量化、分布式训练的知识都现成
- 变长的合法行动集合：把每个合法行动作为 option token 一起送入，对 option token 的输出做 softmax 得到策略；盘面 token 输出价值。局面之间合法手数量不同也能用同一个模型：

  ```
  观测 token:  Card 1, Card 2, …, Card N, 盘面
  合法手 token: Option 1, Option 2, …, Option M
            ↓ 同一个 Transformer，全 token 互相 attend
  Option 1: 0.10   Option 2: 0.75   …   Option M: 0.05   ← 对 option token 输出做 softmax
  ```

  推理选概率最高的，训练时采样。
- 若数据里有 Transformer 只能从排列顺序猜测的显式关系（附属物贴在哪个单位上、进化/升级链），可以加一个轻量 relation module（message passing）把边显式传进去，与 self-attention 相加 —— 这是"补 Transformer 表达不便之处"，不是"自研结构"

### ⑤ 奖励只用胜负

**只把真正要解的量作为奖励**。辅助奖励只限于开局提效，最后必须拿掉。

- 反模式：依赖辅助奖励，把时间花在设计和调它上；结果辅助目标达成了，真正的目标（赢）没达成
- 原则：终局 +1 / −1，中途全部 0。像"资源拿了多少""推进了几步"这种中间奖励不加
- 对局长不是理由 —— 只要经验量够，单靠胜负就能学会；还省下调奖励的时间
- 若非要加，只在早期用来加速，之后撤掉，目标函数始终保持是胜负

### ⑥ 用自博弈

**两个席位都是当前 π_θ，两个视角的经验都直接用于更新**。

- 反模式：对手用旧 checkpoint —— 对手视角的经验不能直接用于更新当前策略，可用经验减半、变慢；对手不变强，策略会过拟合到这个对手上
- 只有两种情况可以换对手策略：
  1. 博弈有强"剪刀石头布"性质，同时学多个不同的强策略太耗时
  2. 只需要赢过特定对手
- 警惕"按类型拆成多个 expert 组成 league"的做法：对手多样性受限，遇到分布外的对手会输；最终选哪个 expert 上场也变成一次赌博。用一个权重覆盖全部类型往往更好

## 工作流

### 设计新方案

按 ①→⑥ 逐项给出选择与理由，每项都对照"变大不崩 / 不变慢 / 有价值"三条检查。先做环境（①），因为它决定了后面一切的经验量上限。给出初始 PPO 配置时用下面的起点配置，再按任务调。

### 起点配置

来自回合制对战赛的实战配置，作为默认值起步：

- γ = 1（不折扣），λ = 0.99
- 回合制博弈：对手回合作为一个宏转移跳过，agent 只在自己决策点看到 step
- 每 GPU 256 env × 128 step，4 epoch，clip 0.2
- ref KL：β = 0.005，π_ref 为 last-best，评估中 macro 胜率提升 ≥ 3pp 才替换
- 有公开对局/回放时先做 BC 初始化；模型用 Net2Net 逐步扩大（见 stability-tips）

### 评审既有方案

输出一张表：

```markdown
| 原则 | 当前做法 | 判断 | 建议 |
|---|---|---|---|
| ① 环境 | ... | 符合 / 偏离（原因） | ... |
| ② 行动空间 | ... | ... | ... |
| ③ 观测·特征 | ... | ... | ... |
| ④ 模型 | ... | ... | ... |
| ⑤ 奖励 | ... | ... | ... |
| ⑥ 对手 | ... | ... | ... |
```

"偏离"要区分两种：一种是无意识的反模式（直接改），一种是为了学习效率有意引入的先验（问清楚放弃了什么、是否打算最后撤掉）。

### 排查训练问题

先定位是 scale 问题还是稳定性问题：

- GPU 利用率低、经验量涨不上去 → ①
- 模型变大也不变强 → ②③（表达不了）或 ⑤（目标偏了）
- 策略突然变弱回不来 → ref KL（稳定化）
- 策略很早就只选同一手、不再探索 → 熵项（稳定化）
- 对特定对手胜率高、换对手就崩 → ⑥

稳定化手段的具体做法与参数在 [references/stability-tips.md](references/stability-tips.md)。
