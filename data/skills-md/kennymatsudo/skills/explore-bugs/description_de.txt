Führen Sie eine Runde explorativer Tests in der laufenden App durch, um Fehler zu finden, die niemand aufgeschrieben hat: Versuchen Sie eine Art von Änderung in mehreren Fällen an echten Benutzerflüssen, beurteilen Sie sie anhand von Invarianten, die als Code geschrieben wurden, bestätigen Sie jeden Bruch (ein Codezitat, wenn es deterministisch ist, wird erneut ausgeführt, und die Widerlegung eines neuen Agenten, wenn dies nicht der Fall ist), verwandeln Sie ihn in eine fehlgeschlagene Überprüfung und zeichnen Sie die Runde in einem Hauptbuch auf. Läuft alleine oder unter einer Schleife. Verwenden Sie die Build-Verifizierung, um eine bekannte Änderung nachzuweisen.
