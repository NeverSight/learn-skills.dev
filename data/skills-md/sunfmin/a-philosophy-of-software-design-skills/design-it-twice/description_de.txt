Bevor du ein neues Modul, Paket, eine Klasse, API oder CLI implementierst, skizziere zwei oder drei radikal unterschiedliche Schnittstellendesigns, vergleiche sie und wähle das beste aus oder synthetisiere es (Ousterhouts „design it twice“). Verwende das, wenn der Nutzer gerade dabei ist, ein neues Modul oder Paket von Grund auf zu schreiben und zuerst Hilfe beim Entwerfen der Schnittstelle möchte, fragt, wie eine API aussehen sollte, Alternativen vor dem Codieren wünscht oder „design it twice“ sagt. Nicht für das Review oder Refactoring bestehenden Codes oder die Auswahl einer Bibliothek.
