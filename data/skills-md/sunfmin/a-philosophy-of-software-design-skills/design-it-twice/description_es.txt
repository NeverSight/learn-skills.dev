Antes de implementar un nuevo módulo, paquete, clase, API o CLI, esboza dos o tres diseños de interfaz radicalmente diferentes, compáralos y elige o sintetiza el mejor (el “diseñalo dos veces” de Ousterhout). Utilízalo cuando el usuario esté a punto de crear un módulo o paquete desde cero y quiera ayuda para diseñar su interfaz primero, pregunte cómo debería ser una API, quiera alternativas antes de codificar o diga “diseñalo dos veces”. No es para revisar o refactorizar código existente ni para elegir una biblioteca.
