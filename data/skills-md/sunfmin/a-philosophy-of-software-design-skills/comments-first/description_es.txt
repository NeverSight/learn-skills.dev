Escribe comentarios de interfaz antes de la implementación y úsalos como una sonda de diseño, audita los comentarios de código existentes y los doc comments, o elige nombres precisos para variables, métodos y tipos (la “Filosofía de diseño de software” de Ousterhout). Utilízalo cuando el usuario pida escribir o mejorar comentarios o docstrings, diga “comentarios primero”, sospeche que los comentarios solo repiten el código o tenga dificultades para escoger un buen nombre para una variable, función o tipo. No es para README, changelog o documentación dirigida al usuario.

Por favor, responde siempre en el idioma del usuario.
