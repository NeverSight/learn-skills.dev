La **Passerelle d’Invocation** de la plateforme Doubaoya (compétence d’infrastructure, **ne gère pas les intentions métier**) : comment gérer l’authentification, comment choisir entre deux itinéraires qui ne sont pas des solutions de repli, comment interpréter l’enveloppe unifiée et les codes d’erreur, et une règle — **récupérer la spécification d’entrée avant l’invocation**. Elle n’est pas responsable de la rédaction d’articles / de la sélection de sujets / de la création de couvertures / de la vérification des mots interdits ; ces tâches passent par `dby`. Mots déclencheurs : protocole d’invocation doubaoya / passerelle d’invocation / DOUBAOYA_API_KEY / operationKey / execution.target / inputContract / spécification d’entrée / enveloppe unifiée / SKILL_NOT_FOUND / ENDPOINT_NOT_FOUND / DEDICATED_ROUTE / NO_RESULT / CAPABILITY_UNAVAILABLE / quel itinéraire sélectionner ; ainsi que lors de l’appel aux API Doubaoya rencontrant les erreurs « 401 / 404 / 429 », « impossible d’atteindre », « comment s’authentifier », « requestId ».
