Richtet das TencentDB Agent Memory (MemoryCore + MemoryHub + MemoryProxy + MemoryPanel, aus AnEntrypoint/agent-memory) ein und steuert es – ein persistentes, sitzungsübergreifendes Speicher‑ und Wissenssystem für KI‑Agenten. Chat Memory (L0 Gespräch → L1 Atom → L2 Szenario → L3 Persona), eine versionierte Skill‑Bibliothek, extrahiert aus früheren Arbeiten, eine Wiki + CodeGraph‑Wissenskarte über Dokumente und Code sowie ein von Menschen gesteuertes Review‑Panel. Verwenden, wenn der Nutzer möchte, dass ein Agententeam Speicher/Skills/Wissen über Sitzungen hinweg und über mehrere Agenten‑Frameworks hinweg (nicht nur diese Claude‑Code‑Sitzung) teilt und anhäuft, wenn Begriffe wie „memory hub“, „team memory“, „chat memory“, „skill library“, „wiki“, „codegraph“ genannt werden oder nach Installation/Konfiguration/Fehlerbehebung des memory‑tencentdb‑Plugins gefragt wird, oder wenn ein neuer Agent in die bereits gesammelte Erfahrung eines bestehenden Teams eingearbeitet wird. Seit der Ergänzung von gms tencentdb_backend kann das Format dieses Systems AUCH das eigene gm‑Backend für memorize/recall/memorize‑fire/memorize‑prune in einem opt‑in‑Namespace sein (siehe gm.config.json → memory.tencentdb_backend) – wenn das aktiviert ist, bleibt die bereits bekannte Verb‑Oberfläche des Agenten unverändert; nur das Speicherziel ändert sich. Nutze diese Fähigkeit für die eigenständige Bereitstellung (Docker‑Compose, Panel‑UI, Team‑Review) oder wenn das eigene gm‑Backend nicht Gegenstand der Anfrage ist.
