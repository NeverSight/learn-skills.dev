Richtet den TencentDB Agent Memory (MemoryCore + MemoryHub + MemoryProxy + MemoryPanel, aus AnEntrypoint/agent-memory) ein und steuert ihn – ein persistentes, sitzungsübergreifendes Speicher‑ und Wissenssystem für KI‑Agenten. Chat‑Memory (L0 Gespräch → L1 Atom → L2 Szenario → L3 Persona), eine versionierte Skill‑Bibliothek, die aus früheren Arbeiten extrahiert wurde, ein Wiki + CodeGraph‑Wissensgraph über Dokumente und Code sowie ein vom Menschen kontrolliertes Review‑Panel. Verwenden, wenn der Nutzer möchte, dass ein Agententeam Speicher, Skills und Wissen über Sitzungen und über mehrere Agenten‑Frameworks hinweg (nicht nur diese Claude‑Code‑Sitzung) teilt und anhäuft, wenn er Begriffe wie „memory hub“, „team memory“, „chat memory“, „skill library“, „wiki“, „codegraph“ erwähnt oder nach Installation/Konfiguration/Fehlerbehebung des memory‑tencentdb‑Plugins fragt oder wenn ein neuer Agent in die bereits gesammelte Erfahrung eines bestehenden Teams eingearbeitet wird. Seit der Ergänzung von gm's tencentdb_backend kann das Format dieses Systems AUCH gm's eigenes memorize/recall/memorize‑fire/memorize‑prune‑Backend für einen optionalen Namespace sein (siehe gm.config.json → memory.tencentdb_backend) – wenn dies aktiviert ist, bleibt die bereits dem Agenten bekannte Verb‑Oberfläche unverändert; nur das Speicherziel ändert sich. Nutze diese Fähigkeit für die eigenständige Bereitstellung (Docker Compose, Panel‑UI, Team‑Review) oder wenn gm's eigenes Backend nicht das Gesuchte ist.
