Configura e gestisce TencentDB Agent Memory (MemoryCore + MemoryHub + MemoryProxy + MemoryPanel, da AnEntrypoint/agent-memory) – un sistema di memoria e conoscenza persistente, cross‑session, per agenti IA. Chat Memory (L0 conversazione → L1 atomo → L2 scenario → L3 persona), una libreria di Skill versionata estratta dal lavoro precedente, una mappa di conoscenza Wiki + CodeGraph su documenti e codice, e un pannello di revisione controllato dall’uomo. Da utilizzare quando l’utente desidera che un team di agenti condivida e accumuli memoria/skill/conoscenza tra sessioni e tra più framework di agenti (non solo questa sessione Claude Code), quando menziona “memory hub”, “team memory”, “chat memory”, “skill library”, “wiki”, “codegraph”, o richiede l’installazione/configurazione/risoluzione dei problemi del plugin memory‑tencentdb, o durante l’onboarding di un nuovo agente nell’esperienza accumulata di un team esistente. A partire dall’aggiunta del tencentdb_backend di gm, il formato di questo sistema può ANCHE essere il backend di gm per memorise/recall/memorize‑fire/memorize‑prune per un namespace opt‑in (vedi memory.tencentdb_backend in gm.config.json) – quando è abilitato, la superficie verbale che l’agente già conosce rimane invariata; solo l’obiettivo di archiviazione cambia. Usa questa abilità per il deployment standalone (Docker Compose, UI del pannello, revisione di team) o quando il backend di gm non è quello richiesto.
