# 代码注释规范

用于新增、修改或审查源码中的注释。先根据文件类型读取对应参考资料，再只添加能帮助读者理解意图、约束、生命周期或风险的注释；不要为显而易见的代码逐行添加说明。

## 语言路由

根据源文件类型选择对应参考文档，每个文件只读取一份语言规则，不混用其他语言规则：

- C/C++（`.c`、`.h`、`.cc`、`.cpp`、`.cxx`、`.hh`、`.hpp`）：读取 [references/c-cpp.md](references/c-cpp.md)。
- Kotlin（`.kt`、`.kts`）：读取 [references/kotlin.md](references/kotlin.md)。
- Java（`.java`）：读取 [references/java.md](references/java.md)。

## 通用要求

- 新增的注释必须使用中文；修改注释时也应使用中文表达。
- 注释解释“为什么”、业务背景、限制条件和易错点，不重复代码、函数名或类型名已经表达的信息。
- 公共 API 在行为、状态变化、线程安全、生命周期、异常、空值语义或平台约束不明显时，使用文档注释补充这些信息。
- 注释应贴近被说明的声明或逻辑，避免失效、空泛或与实现不一致的描述。
- 只在代码意图、业务原因、边界条件、生命周期、并发、资源管理、平台兼容或性能取舍不明显时添加注释。
- 不要为显而易见的代码、简单属性、直观转换或普通布局逐行添加注释。
- 修改已有注释时，保持项目已有语言和表达风格；如果注释与代码不符，应一并修正。
