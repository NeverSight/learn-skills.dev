Úselo cuando el usuario quiera simplificar, limpiar, refactorizar, ordenar o refinar el código: sus cambios de git preparados/no preparados o un archivo/ruta de destino. Reduce la complejidad, aplana el anidamiento, elimina la redundancia y el código inactivo, califica cada cambio por valor (manteniendo la tasa de abandono de valores bajos) y luego ejecuta pruebas para demostrar que no hay nada roto. Invocar en: "simplificar", "simplificar esto", "simplificar mi código/cambios", "limpiar", "limpiar esto", "limpiar mis cambios", "refactorizar esto", "hacer esto más limpio", "ordenar esto", "reducir la complejidad", "aplanar esto", "eliminar código inactivo", "hacerlo más legible", "pulir antes de confirmar" o "simplificar absolutamente". Actúa sobre su diferencia de trabajo; para código inactivo en todo el repositorio, utilice poda absoluta; para pelusa/tipo de deuda utilice deuda absoluta.
