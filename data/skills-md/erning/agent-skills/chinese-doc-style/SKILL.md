# 中文正式文档写作规范

统一正式中文文档的书写格式，并为新建、改写正文提供基本表达约束。是否修改文件取决于用户请求；专项格式审阅也可以只交付问题和建议。

## 调用边界

自动调用以任务正在撰写、修改或专项审阅正式文档为前提，例如供发布、交付或评审的报告、指南、教材和仓库文档；在聊天中起草正式文档也适用。

- 日常聊天、概念解释、代码讨论、临时翻译和非正式笔记不自动调用，出现中文、技术名词、Markdown、表格或文件路径本身不构成理由。用户说明只是随手记录、不必严格规范时，按普通交流处理，不追问也不做全套检查。仅阅读、总结、比较内容或审查事实与逻辑时也不调用。
- 规范只用于当前交付的文档正文，不扩展到过程说明或后续闲聊。用户明确要求使用本 skill 时，按其指定范围处理；仅提及 skill 名称不等于要求应用规范。

## 按任务处理

- 新建或改写：写作时一并遵循下文原则和核心检查，一次写出，不先写后改。
- 排版修订：只修正请求涉及的格式问题，保留原有表达和含义。
- 格式审阅：按同一套规范检查，只报告位置、问题和建议，不修改文件或擅自交付整篇改稿。

## 新建与改写原则

以下原则仅用于新建和改写正文，排版修订及格式审阅不据此润色原文。

- 减少空泛评价、重复铺垫和没有信息的结尾，优先用已有事实说明具体变化或作用。
- 不为了使文字具体而编造功能、数字、来源、经历或反馈；资料不足时保留缺口。
- 保留事实、作者立场、必要的不确定性和适用范围，不把计划写成已完成的结果，不把有条件的结论写成确定事实。

## 核心检查

- 默认使用简体中文和中国大陆常用词，现有文档另有约定时保持原风格。
- 品牌、产品、项目和技术名称使用官方大小写；无法确认时保留原文。
- 中文与英文、中文与数字、数字与拉丁字母单位之间通常保留一个半角空格。
- 中文或以中文为主的句子使用全角中文标点，完整英文句子使用英文标点。
- 中文正文的每个段落、列表项内的每个段落各写在一个源码行内，不按固定列宽硬换行；阅读时使用编辑器的自动折行。段落之间留空行，保留列表、表格、代码块等结构需要的换行。
- 不要机械拆分日期、时间、版本号、小数、百分比、比例、端口号或文件名。
- 仅修正排版时，保留原有标题层级、列表和表格结构。重写或重组文档时，可以在用户授权范围内调整结构，无需为必要的结构调整再次确认。

## 保护技术内容

默认不修改以下内容内部的字符：

- 围栏代码块和行内代码
- Shell 命令、参数和环境变量
- URL、电子邮件地址和 Markdown 链接目标
- 文件路径、文件名、Git 分支名和版本号
- API 名称以及函数、类、变量等代码标识符
- 用户要求保留的引用或原文

可以调整这些内容与中文正文之间的空格。Markdown 链接的可见文字属于正文，链接目标必须保持不变。

## 输出方式

- 新建、改写或排版修订：直接交付完整文本；要求编辑文件时写回目标文件，不额外生成副本。
- 只读格式审阅：只报告问题和建议，必要时给出局部示例；没有问题时如实说明。
- 只说明有实际价值的内容变化，不逐条解释重复的机械格式修正。遇到不确定的术语、品牌写法或标识符时，保留原文并简要指出疑点。

## 详细规范

默认使用上述核心检查。仅在用户要求严格、逐项的格式检查（直接修订或只读审阅），或遇到无法依据核心检查判断的规则冲突时，读取 `references/style-guide.md`。

若任务还要求改变写作风格、语气或去除 AI 写作痕迹，在同一次写出中先处理内容层面，再套用本规范的格式，不为格式另外改写一遍文件。
