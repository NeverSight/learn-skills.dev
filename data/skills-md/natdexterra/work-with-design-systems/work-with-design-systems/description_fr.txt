Inspectez, créez ou étendez les systèmes de design Figma — et synchronisez‑les éventuellement avec le code. Deux modes dans une même compétence : mode d’inspection (audits en lecture seule avec contrôles WCAG, notation des composants, détection d’instances détachées, documentation de remise) et mode de construction (création de composants avec liaisons de variables, composition basée sur des slots, descriptions structurées, validation, et exportation optionnelle de tokens.css + règles IA vers le code de l'utilisateur). Utilisez‑le lorsque l'utilisateur dit « auditer mon système de design », « vérifier la qualité des composants », « créer un système de design », « construire le DS dans Figma », « générer une bibliothèque de composants », « ajouter des slots à mes composants », « synchroniser les design tokens depuis le code », « trouver des instances détachées », « vérifier la conformité WCAG », « exporter les tokens vers le code », « générer CLAUDE.md pour le système de design », ou souhaite pousser un système de design du code vers Figma ou inversement. La compétence détecte automatiquement le mode à partir de la requête, ou demande clarification si ce n’est pas clair. Après l’inspection, elle PAUSE TOUJOURS et attend une décision explicite de l'utilisateur avant toute action de construction. La phase 6 (synchronisation vers le code) est DÉSACTIVÉE par défaut — elle ne se déclenche que sur demande explicite de l'utilisateur. NE PAS implémenter les designs Figma en code — utilisez figma-implement-design pour cela. NE PAS créer d’écrans individuels — utilisez figma-generate-design pour cela.

Veuillez toujours répondre dans la langue de l'utilisateur.
