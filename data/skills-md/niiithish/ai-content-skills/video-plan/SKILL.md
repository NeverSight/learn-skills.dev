---
name: video-plan
description: Turn a client's video brief into an approved production plan before anything is generated. Writes PLAN.md and a matching PLAN.pdf in one fixed layout — a title and summary line, short paragraphs (concept, look, camera, cast, sheets, on camera, end card) and a Shot | Time | Voiceover | What we show table timed from a real voiceover read (a Cartesia read in a voice the user picked, the client's recording or the song). Fills in the visuals the brief leaves out. Works for any style (3D animation, claymation, photoreal, UGC) and then hands over to that style's skill. Use when a client sends a brief, script or message for a new AI video, when starting a video in an empty client folder, or when the user asks for a plan, treatment, shot list or storyboard. Not for a single prompt with no brief.
---

# Video Plan

The first step of every client video, whatever the style. Its output is `video-N/PLAN.md`, the file the style skill works from, and `video-N/PLAN.pdf`, printed from it for the user to read. The two never drift apart because the PDF is only ever printed from the Markdown: edit `PLAN.md`, then reprint.

Most wasted time happens when the story changes after generation has started, or a clip turns out shorter than its voiceover line. This plan settles both before anything is generated.

Run every command yourself: they take seconds. `<skill-dir>` is the folder holding this file.

## Steps

1. **Folders.** `python3 <skill-dir>/scripts/plan.py init <client-folder> video-1` creates `brief/`, `video-1/PLAN.md` and `video-1/voiceover/`, and never overwrites anything. **The user often drops the brief and the reference video loose in the video folder:** init moves them into place itself (videos, and files named after them such as `REF.words.json`, to `video-N/reference-video/`; PDFs, docs, images, audio and zips to `video-N/brief/`) and prints what it moved. Never copy them there yourself: a copy leaves two of everything. A file whose name is already taken is left where it is, with a note. **Standalone videos:** some clients send unrelated projects (a photoreal b-roll library one month, an animated ad the next). Then each video folder is its own project with its own `AGENTS.md`, `brief/` and sheets, and you set it up in place with `.` as the video: `plan.py init <client>/video-2 .` puts `PLAN.md`, `brief/` and `voiceover/` straight into `video-2/`, never a `video-2/video-1/`. Use this whenever the video folder already has its own brief or `AGENTS.md`, or the client folder has no `AGENTS.md` at its top. If the brief came as a chat message, save it verbatim to `brief/message-YYYY-MM-DD.md`. Read every file in `brief/` in full, including the editing and caption sections.
   - **PDFs:** convert each one once, next to it: `pdf2md --raw "brief/<name>.pdf" > "brief/<name>.md"`. From then on read the `.md` (skip the conversion if it already exists), in full. Never plan from a partial read, and never ask the user what the brief says: reread it.
   - **Reference or inspiration videos:** run the `video-breakdown` skill on each one before planning (you can't watch video; Gemini can). A breakdown JSON someone saved earlier is only a hint until it passes that skill's check. Write the reference's pattern into the plan: its hook, how each segment opens and builds, each character's own world, how often something new happens. The client sent it because they want that.
2. **The layout.** Every plan has the layout of `templates/PLAN.md` and nothing else (`upwork-alaria/video-2/PLAN.pdf` is the example the user picked): the title (`<Product> "<Concept>" <ad type>: plan`), the summary line, then short bold-labelled paragraphs, **Concept**, **Look**, **Camera**, **Cast**, **Sheets**, **Blocking** (when two or more characters share a place), **Light** (each place with a sheet or hero still), **On camera**, **End card** (with the captions), and **Open questions** while there are any, then the shot table. No other sections, headings, lists or tables. Take particular care with voiceover, music, captions, deliverables and clip rules: these are what get delivered wrong, so put each in its paragraph. Write the open questions short enough to paste into a message to the client.
3. **Style.** Choose it from the brief: its words, its reference videos, or the client's earlier videos in this folder. If the brief doesn't make it clear, ask the user before going on, because the style changes the sheets and the shots.
4. **Time the voiceover.**
   - **Ask the speed up front** for a talking head or voiceover (the user's ads run at 1.1x): the timing, the clip lengths and the edit are built at that speed from the start. Video-23 sped up after the edit was built and every time on the timeline had to be redone.
   - Copy the script to `video-N/voiceover/script.md`, one spoken line per row, in story order, word for word from the brief's `.md` (or the client's message). Every sentence of the script is in it; leave nothing out because it looks like a note.
   - **The voice comes before the plan, and the user picks it first.** If the client sent a recording, it goes at `voiceover/recording.wav` (or `.mp3`/`.m4a`); skip to the next point. Otherwise, before making anything, ask the user in one message (the `cartesia-tts` skill):
     - the tool: Cartesia by default, or one they name
     - 3–5 voices that fit the brief, with their samples saved to `voiceover/voices/`
     - the speed
     - the emotion

     Wait for the answer. If they want to compare, audition the first two lines in each voice. Then read the whole script with `cartesia say --script voiceover/script.md --voice <id> --speed <s> --out voiceover/recording.wav`. It also writes `recording.words.json` with Cartesia's exact word times.
   - Run `plan.py voiceover <video-folder>`. It times every line of `voiceover/recording.*` from `recording.words.json` when there is one; otherwise it transcribes the recording with Parakeet (the `transcribe` skill's helper, local). Its old fallback, a Cartesia scratch read in a default voice, is for a quick estimate only, never for the plan you send.
   - The result is `voiceover/timing.md`: each line's in and out time and its slot (until the next line starts). The shot table's Time column comes from it.
   - **Characters who speak their lines on camera** (Flow generates the voice inside each clip): run `plan.py voiceover <video-folder> --on-camera` instead. No Cartesia read, since its pacing isn't Flow's: it times each line from its word count at the rate Flow was measured speaking (3.2 words a second) and gives the clip length, or how many 10 s clips a long line needs.
   - **A sung ad** (the song replaces the voiceover): write the song and get the chosen take first (the uninstalled song-ad method, stages 1–2, is still at `~/Work/ai-content-skills/skills/song-ad/SKILL.md`). `song.py lyrics --video` writes `script.md` from the lyric sheet, and the take is `voiceover/recording.wav`; then run `plan.py voiceover` as usual.
   - A brief with no spoken words at all skips this step: time each shot by its action instead.
5. **Concept and shots.** Write the Concept paragraph, then the shot table: **Shot | Time | Voiceover | What we show**.
   - **Time** is the shot's place on the voiceover, `12.6 – 14.4 s`, one decimal. Shots run back to back from 0.0 s to the end of the audio: a line's shots share its slot, and each shot starts where the one before ends. A shot is at most 10 s (the longest clip); its clip is the shortest Flow length (4, 6, 8 or 10 s) that holds its time, trimmed in the edit. Each shot is one visible beat.
   - **Voiceover** is the words heard during that shot, word for word. A shot that carries on the line before says `(cont.)`; music with no words says so in brackets: `(intro: soft piano)`, `(instrumental)`.
   - **Lines spoken on camera** stay whole: one sentence is never split across two clips (the model cuts it off). A line up to about 9.5 s gets one clip that ends 0.5–2 s after the last word. A longer line gets the **fewest** clips that hold it, each up to 10 s, split at a sentence or clause break: a 16–18 s line is two clips, not three. Those clips chain (each starts from the last frame of the one before) so the line plays as one continuous shot.
   - Shot ids: a scene with one shot is just its number (`3`); a scene with several shots gets a letter each (`1a`, `1b`). Number scenes from 1 in story order. A letter means a different beat of the same line with its own camera ("the cat steals the bread and the police give chase": `5a` the grab, `5b` the chase), never another try of the same picture.
   - The shot table is only what gets generated. Captions, end card text and music go in the **End card** paragraph (captions in the client's exact wording), because the user adds them in the edit and they must never reach a prompt.
6. **Fill the gaps.** Where the brief only gives voiceover, decide what we show, and tell the user in your message which shots you invented.
   - **Reuse before you generate.** Before planning any insert still or clip, look through `<client>/assets/clips/` and the other videos' approved finals (`video-*/clips/clip-*/final/`, their PICKS.md) for a clip that already shows it, and write the reuse into What we show ("reuse video-10 clip-103, from 1 s"). On video-23 we made 17 insert stills and then swapped 16 of them for asset clips the user pointed us to. Show the user a contact sheet of the candidates.
   - **Paired shots are one chain.** When two shots show the same moment (she pours, then she sips), the second is planned as an edit of the first still, so nothing appears or vanishes between them (video-23: a glass of water came from nowhere).
   - Show the line; don't just repeat it. "The cat stole the food from the police officer" becomes a scene someone can film: The officer sits on the station bench, lunch box open beside him, turned away to wave at a colleague. The cat hops up and slides the sandwich out.
   - Say who is where, which way they face and what they look at ("backs to us, staring up at the pie on the sill"), what they're doing and what changes by the end of the shot, so every shot can start from a still: characters already in place, nothing growing on screen, nobody walking in through a wall.
   - Make it move. Open each "What we show" with the place and the camera, in plain text ("Kitchen, low angle, slow push-in:", "Close-up, locked:", "Her POV:"), and change the camera from the shot before. These are framings, not moves: clips are generated with a locked camera, so the motion comes from the characters. (Clips where a character talks to camera are the exception: they get one slow, smooth move, a push-in, drift or arc, never a crash zoom or whip.) A POV shows what that character sees, so they aren't in it (at most a paw or a nose at the frame edge). Two shots of the same characters in the same spot need clearly different cameras (wide from behind them, then a close-up of one face), or the stills come out alike. Every shot has something happen: someone grabs, falls, turns, reacts. Characters just sitting and looking is a deliberate pause, never two shots in a row. Aim for something new on screen every 2–5 s. Write each shot's visual idea into the plan, not just its framing: what appears, grows or changes, and on which words. The first drafts should already be engaging; "a character stands and talks" is a boring clip.
   - Keep the cast and sets manageable, not tiny: reuse locations and characters before adding new ones (each is another sheet to make), but use enough of them for the story to travel. A story in one room with one character can't move.
   - Where the brief does say what to show, follow it exactly, including its order.
7. **Cast and Sheets.** The Cast paragraph describes every character who gets a sheet, with the details that must never drift (face, hair, eyes, jewelry) and their relative scale where it matters ("the cat's back is at the officer's shin"). The Sheets paragraph lists the sheets in the order to make them: characters with their outfits, then environments that return many times (with what is in them), then props, and says which places get one hero still instead. The style skill writes the sheet prompts from these two paragraphs.
   - **Who gets a character sheet.** Go through the shot table and count each person's shots. A character gets a sheet when they are part of the story and their face must match from shot to shot: they appear in **two or more shots**, or they **speak or sing a line on camera**. In video-1 of `upwork-alaria` that was six: the wife, the husband, his girlfriend at the shop, the wife's sister, the woman at the diner door who asks about the pillow (lip-sync), and the closing "maybe you're her" woman (lip-sync).
   - **Cast for the buyer, not the reference.** Every character the viewer is meant to be is the audience's age (Mysa: women 45–65, so about 50–58), even when the reference's cast is younger. Cloning a reference keeps its room, framing and wardrobe type, but change at least one visible thing per person (video-23: the host's grey blazer became camel-brown, the user's pick) so it is not a copy. Name who is the host and who is the guest, and which lines each speaks, in the Cast paragraph: video-23 lost time on host vs guest.
   - **Extras never get a sheet**, however many shots they are in: waiters and waitresses, couples at other tables, shop customers, passers-by, a crowd, a doctor seen once. Describe them in the shot's What we show (age, look, clothes) and keep them secondary: at the edge of the frame, out of focus, or turned away. List them at the end of the Sheets paragraph as "Extras, no sheet: the waitress (35, 38), diner couples (36–40)" so the choice is visible.
   - **Outfits.** For each character with a sheet, work out from the story every outfit they wear, by when and where they are: night clothes, everyday clothes, work clothes, going out (a café, a date, church). Write each outfit in the Cast paragraph with the shots it is worn in: "nightgown (1–3, 24–27), everyday: berry henley and jeans (4–23), café: emerald dress, hair up (33–44)". Every outfit gets its own sheet, so the clothes stay the same across shots: the outfit worn most is the base sheet (`hero`), and each other one is an outfit sheet (`hero-sleep`, `hero-cafe`) made later as an edit of the approved base, so the face stays the same. Don't invent outfits the story doesn't need: one character, one setting, one day is one sheet.
   - In the Sheets paragraph, give the count: "Characters, 9 sheets: wife ×4 (everyday, sleep, café, church), husband ×2 (work, sleep), girlfriend, sister, door woman." Every shot of a sheet character names which outfit they're in (in What we show, or by the outfit's shot range in Cast).
   - **Environment sheets (animated and claymation only).** In a photoreal video (live-action DTC ads, many short clips) make **no environment sheets**: each location's first approved still is its look reference, and the room's items are described in the shots. In 3D animation and claymation, a real place where characters appear in **two or more shots** gets an environment sheet (the bedroom, the kitchen, the diner, the clinic), so its layout (doors, windows, furniture) and everything in it hold from shot to shot. Without one, the stills redraw the room, and the objects in it, every time. The sheet includes the room's story items at their places: the bed with the old flat pillow, the nightstand clock, the coffee maker. A place seen in one shot gets no sheet: describe it in the shot, and that still is its look. Never a sheet for CGI, macro, cutaway, diagram or abstract visuals, a void or blurred backdrop, or a product or tabletop close-up.
   - **Blocking.** For each place where two or more sheet characters share shots, fix who is where by the room's landmarks, never by frame left and right: "Bedroom: husband on the window side of the bed, wife on the lamp side." Add the side the camera stays on for the scene, and keep it (the 180° rule) unless a shot needs the reverse; then say so in that shot. Without this, the couple swaps sides from still to still.
   - **Light.** For each place with a sheet or a hero still: the main light as an object you can see in the room (the brass floor lamp beside the sofa, the string lights over the fire pit, the sink window), the time of day, a second source that rims hair and shoulders, and what stays dark: "Living room, evening: the brass floor lamp beside the sofa is the key, the side-table lamp rims them, the corners and photo wall stay in warm shadow." The environment sheet shows that lamp, and every still and clip there names it. Without it the image model lights every corner the same and faces come out flat.
   - **Acting.** For each sheet character, a base acting direction in the Cast paragraph: their energy, how big their gestures are, how they stand and move, and how they talk ("Darnell: sly and slow, big eyebrow work, leans back, talks low and smooth"). Every clip prompt starts from it, so movement and delivery don't come out stiff or generic.
   - **Prop sheets are for the product.** The client's product always gets one, made from the client's real product photos (`--ref`), never from a description, and every shot it is in passes it. Anything that sits in a room comes from that room's environment sheet, not a prop sheet. A prop sheet for anything else only when it appears in two or more shots in different places, its look must match, and no environment sheet holds it (a branded bottle she carries from the kitchen to the car). When unsure, put it in the environment sheet.
8. **Check and print.** Run the coverage check below, then `plan.py pdf <video-folder>`. It rewrites the summary line under the title (shot count, length, what it's timed to, average and longest shot), prints any gap, overlap, shot over 10 s or shots ending before the voiceover, and prints `PLAN.pdf` (A4, plain black table) with your installed Chromium. Fix what it flags and reprint.
   - [ ] Every sentence of the script is in the Voiceover column, word for word: tick them off against the brief's `.md`. Rerun this after any shots are merged, split or dropped.
   - [ ] A line spoken on camera is never split mid-sentence, and a long one uses the fewest clips (up to 10 s each).
   - [ ] If the client sent a reference video, the plan follows its pattern (hook, how each segment builds, each character's world).
   - [ ] Each shot is one visible beat that can start from a still: characters already in place, nothing growing on screen, nobody walking in through a wall.
   - [ ] No two shots in a row share the same camera, and something happens in every shot. Every character's facing and eyeline is stated, and no POV shot shows the character whose eyes it is.
   - [ ] Every character in two or more shots or speaking on camera has a sheet, no extra (waiter, other diners, passers-by) has one, and every outfit a sheet character wears has its own sheet with its shots listed.
   - [ ] Animated or clay: every place with characters in two or more shots has an environment sheet that lists the story items in it (photoreal: none); and the only prop sheets are the product (and any item carried between places in two or more shots).
   - [ ] No caption or on-screen text in the shot table.
9. **Gate.** Give the user `PLAN.pdf` and a few lines on what you invented and what you're asking the client. Revise `PLAN.md` and reprint until they approve, then set the Status comment at its top to approved with the date. In an unattended run (the user is away), run the coverage check yourself, answer the open questions with the most conservative choice, mark them "(agent)", and approve the plan yourself.

After approval, add or cut shots only when the user asks, and reprint the PDF after each change. After any merge, split or cut, rerun the script check: a dropped sentence is a dropped line in the video. When the client's real voiceover arrives, save it as `voiceover/recording.*`, rerun `plan.py voiceover`, and lengthen any shot that no longer covers its line before its clip is made. Retime the Time column from the new `timing.md` and reprint.

## Hand-over

Once the plan is approved, load the skill for its style. It starts from `PLAN.md` and doesn't repeat the intake. Every Flow scene video (animated or photoreal) goes through `video-production`: its layout, `make.py` and gates. Never hand-write batch files instead.

| Style | Skill |
|---|---|
| 3D feature animation (DreamWorks, Pixar) | `animated-video-production` (it loads `video-production`) |
| A sung ad (the song replaces the voiceover) | `animated-video-production` for the B-roll; the song comes first (method and `song.py` in `~/Work/ai-content-skills/skills/song-ad/`, not installed as a skill) |
| Claymation or stop-motion | `clay-video-production` |
| Photoreal scenes under a voiceover (ads, b-roll) | `photoreal-video-production` (it loads `video-production`) |
| One speaker carries the script to camera, with picture inserts over her (the Aleo video-3 method, the video-5 infomercial host) | `talking-head-video-production` (it loads `video-production` and `photoreal-video-production`) |

Sheets use the shared layouts in `video-production/references/sheets/` plus the style skill's `characters.md`, `places.md` and `product.md`.
