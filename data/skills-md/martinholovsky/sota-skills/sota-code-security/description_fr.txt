Règles de codage sécurisé et d’audit de sécurité. Utilisez‑les chaque fois que vous CONSTRUISEZ ou modifiez du code qui franchit une frontière de confiance — points de terminaison, gestionnaires, auth/login/signup, sessions, JWT/OAuth, téléversements de fichiers, paiements, fonctionnalités multi‑locataires, gestion de crypto/secrets, analyseurs, wrappers CLI/exec, agents LLM ou appel d’outils — ET chaque fois que vous AUDITEZ du code pour la sécurité (revue de sécurité, chasse aux vulnérabilités, durcissement, OWASP, CWE, fuite de secrets, « ce code est‑il sûr » ) — ET chaque fois qu’un contrôle est déjà PRÉSENT et que la question est de savoir s’il impose quelque chose (une porte qui ne rate jamais, un comparateur vide), même lorsque ce contrôle réside dans un script shell, une étape CI ou un fichier de configuration. Mots‑clés déclencheurs : secure, security, vulnerability, audit, authn, authz, authentication, authorization, crypto, TLS, sanitize, validate, injection, SQLi, XSS, CSRF, SSRF, IDOR, JWT, OAuth, upload, rate limit, prompt injection, feed, parser, decompression bomb, webhook, deserialization, silent failure, fail‑open, no‑op control, business logic.
