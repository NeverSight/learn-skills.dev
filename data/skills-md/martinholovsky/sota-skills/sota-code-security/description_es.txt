Reglas de codificación segura y auditoría de seguridad. Úselo siempre que SE ESTÉ CONSTRUIENDO o modificando código que cruza una frontera de confianza — puntos finales, manejadores, autenticación/registro/inscripción, sesiones, JWT/OAuth, carga de archivos, pagos, funciones multicliente, manejo de criptografía/secretos, analizadores, envoltorios CLI/exec, agentes LLM o llamadas a herramientas — Y siempre que SE AUDITE código por seguridad (revisión de seguridad, búsqueda de vulnerabilidades, endurecimiento, OWASP, CWE, fuga de secretos, “¿es este código seguro?”) — Y siempre que ya exista un control y la pregunta sea si impone algo (una puerta que nunca falla, un comparando vacío), incluso cuando ese control vive en un script de shell, un paso de CI o un archivo de configuración. Palabras clave desencadenantes: secure, security, vulnerability, audit, authn, authz, authentication, authorization, crypto, TLS, sanitize, validate, injection, SQLi, XSS, CSRF, SSRF, IDOR, JWT, OAuth, upload, rate limit, prompt injection, feed, parser, decompression bomb, webhook, deserialization, silent failure, fail-open, no‑op control, business logic.
