Regole di codifica sicura e di audit della sicurezza. Utilizzare ogni volta che si COSTRUISCE o si modifica codice che attraversa un confine di fiducia — endpoint, handler, auth/login/signup, sessioni, JWT/OAuth, caricamenti di file, pagamenti, funzionalità multi‑tenant, gestione di crittografia/segreti, parser, wrapper CLI/exec, agenti LLM o chiamate a tool — E ogni volta che si AUDITA il codice per la sicurezza (revisione di sicurezza, ricerca di vulnerabilità, hardening, OWASP, CWE, perdita di segreti, “questo codice è sicuro”) — E ogni volta che un controllo è già PRESENTE e la domanda è se impone qualcosa (un gate che non fallisce mai, un comparatore vuoto), anche quando quel controllo vive in uno script shell, in un passaggio CI o in un file di configurazione. Parole chiave di attivazione: secure, security, vulnerability, audit, authn, authz, authentication, authorization, crypto, TLS, sanitize, validate, injection, SQLi, XSS, CSRF, SSRF, IDOR, JWT, OAuth, upload, rate limit, prompt injection, feed, parser, decompression bomb, webhook, deserialization, silent failure, fail-open, no‑op control, business logic.
