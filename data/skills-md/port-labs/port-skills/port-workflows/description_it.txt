Costruisci workflow Port: automazioni basate su nodi composte da trigger (moduli self‑service, eventi del context lake), nodi di azione (webhook, upsert entity, integrazioni con agenti gestiti da GitHub/GitLab/Azure DevOps/Claude, Kafka, Cursor Agent, AI), nodi condizione e input, templating JQ tra i nodi e permessi di trigger self‑service, redatti come JSON del workflow contro l’API di Port. Usa quando ti viene chiesto di creare un workflow Port, aggiungere un trigger a un workflow, aggiungere un nodo di azione, collegare un workflow self‑service, aggiungere un ramo con un nodo condizione, inserire un passaggio di approvazione in un workflow, costruire un’automazione event‑driven in Port, o scrivere JSON di workflow. I workflow Port sono il grafo di automazione a nodi‑e‑archi di Port, non un file di pipeline CI/CD come GitHub Actions.
