Bereiten Sie die GitHub-Pull-Anfrage standardmäßig in einem lokalen Zweig vor. Verwenden Sie einen isolierten Arbeitsbaum, wenn dies ausdrücklich erforderlich ist, und führen Sie optional den neuesten Basiszweig zusammen. Verwenden Sie den Überprüfungskern wieder, um Remote-Code genau zu prüfen und den Thread-Status anhand von Beweisen aufrechtzuerhalten. Deaktivieren Sie Remote-Schreibvorgänge, wenn der Benutzer schreibgeschützten Zugriff anfordert. Geeignet für GitHub PR-Rezension.
