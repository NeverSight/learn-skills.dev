You MUST use this in the Design phase whenever a spec has a UI, AFTER the spec is agreed and BEFORE planning and any implementation. The goal is to turn the spec into the screens, flows, states, and a visual direction, mocked as static HTML in Lavish for the user to annotate. You are not allowed to write product code. Skip it for a spec with no user-facing surface and say so. Trigger phrases: ui design, ux, screen design, mockup, wireframe, user flow, design system.
