Tiefe Analyse der Nutzeranforderungen, als würde ein Koch einen Ochsen zerlegen. Durch eine zweistufige (Requirements Analyst → Systemarchitekt) Gesprächsführung werden verschiedene Eingaben wie gesprochene Nutzeranforderungen, PRD‑/Anforderungsdokumente, Geschäfts­beschreibungen usw. analysiert und zerlegt, um schrittweise ein vollständiges Set an Entwicklungsdokumenten zu erzeugen. Anwendungsfälle: wenn ein Nutzer vage Anforderungen präsentiert, die strukturiert werden müssen; wenn PRD‑/Anforderungsdokumente in Entwicklungspläne umgewandelt werden sollen; wenn Geschäfts­beschreibungen in funktionale Module und Aufgaben zerlegt werden müssen.
