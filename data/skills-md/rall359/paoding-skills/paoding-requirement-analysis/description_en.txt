Analyzing user requirements with the precision of a master chef dissecting a bull. Through a two‑stage (Requirement Analyst → System Architect) dialogue‑driven approach, the system examines and breaks down various inputs—spoken requirements, PRDs/requirement documents, business descriptions, etc.—and gradually generates a complete set of development documentation.  

Use cases: when a user’s vague requirement needs to be clarified; when a PRD/requirement document must be turned into a development plan; when a business description needs to be broken down into functional modules and tasks.
