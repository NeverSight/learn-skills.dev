Recupero runtime attivo per agenti di codifica: quando qualcosa si rompe a metà compito, diagnostica la causa radice, scrivi una correzione, VERIFICA rieseguendo la cosa rotta, poi registra una voce `HEAL-` in `.learnings/HEALS.md` con prova. Usalo ogni volta che un comando, test, build o lint fallisce o esce con codice non zero; in caso di strumenti mancanti, incompatibilità di dipendenze/file di lock, versione runtime errata, venv o errori di permessi, conflitti di porta, stato sporco di git o un `.env` mancante; quando l’agente ha bisogno di un helper o di uno script monouso che non esiste ancora; quando un’API esterna, uno strumento o errori MCP o limiti di rate‑limiting; o quando un test è flaky. Cerca `HEALS.md` per `Pattern-Key` prima — la maggior parte dei heal è ricorrenza, quindi incrementa `Recurrence-Count` invece di duplicare. La verifica è obbligatoria: segna `pending-verify` onestamente se sandboxato, `abandoned` se la correzione non può funzionare. Si abbina a `self-improvement` (che promuove i heal ricorrenti a memoria durevole) ma possiede la disciplina “verifica‑prima‑di‑persistire” che il self‑improvement non ha.
