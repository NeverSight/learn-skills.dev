استعادة وقت التشغيل النشط للوكلاء البرمجيين: عندما يتعطل شيء ما أثناء المهمة، تشخيص السبب الجذري، كتابة إصلاح، التحقق منه بإعادة تشغيل العنصر المتعطل، ثم إنشاء إدخال `HEAL-` في `.learnings/HEALS.md` مع الدليل. استخدم ذلك كلما فشل أمر أو اختبار أو بناء أو فحص أو خرج برقم غير صفر؛ عند نقص الأدوات، أو عدم توافق ملف القفل/التبعيات، أو نسخة زمن التشغيل الخاطئة، أو أخطاء البيئة الافتراضية أو الأذونات، أو تعارضات المنافذ، أو حالة git غير نظيفة، أو فقدان ملف `.env`؛ عندما يحتاج الوكيل إلى مساعد أو سكريبت أحادي لا وجود له بعد؛ عند حدوث أخطاء أو تحديد معدلات للـ API الخارجي أو الأداة أو MCP؛ أو عندما يتقلب اختبار. ابحث أولاً في `HEALS.md` باستخدام `Pattern-Key` — معظم العلاجات متكررة، لذا زد `Recurrence-Count` بدلاً من تكرار الإدخال. التحقق إلزامي: ضع علامة `pending-verify` بصدق إذا كان في بيئة معزولة، و`abandoned` إذا لم يمكن جعل الإصلاح يعمل. يتزاوج مع `self-improvement` (الذي يرفع العلاجات المتكررة إلى ذاكرة دائمة) لكنه يتحكم في انضباط التحقق قبل الحفظ الذي لا يغطيه التحسين الذاتي. يرجى دائمًا الرد بلغة المستخدم.
