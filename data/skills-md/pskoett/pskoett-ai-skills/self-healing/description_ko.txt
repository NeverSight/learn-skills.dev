코딩 에이전트를 위한 능동적인 런타임 복구: 작업 중에 무언가가 깨지면, 근본 원인을 진단하고, 수정을 작성한 뒤, 깨진 작업을 다시 실행하여 **VERIFY**하고, 증거와 함께 `.learnings/HEALS.md`에 `HEAL-` 항목을 기록한다. 명령, 테스트, 빌드, 린트가 실패하거나 비정상 종료될 때, 도구가 없거나 종속성/락파일 불일치, 잘못된 런타임 버전, 가상 환경 또는 권한 오류, 포트 충돌, 더러운 git 상태, `.env` 누락 등 상황에서 사용한다; 에이전트가 아직 존재하지 않는 도우미나 일회성 스크립트가 필요할 때; 외부 API, 도구, MCP 오류 또는 레이트‑리밋이 발생할 때; 혹은 테스트가 간헐적으로 실패할 때도 사용한다. 먼저 `Pattern‑Key`로 `HEALS.md`를 검색한다 — 대부분의 치유는 재발 사례이므로 중복 대신 `Recurrence‑Count`를 증가시킨다. 검증은 필수이며, 샌드박스 환경이라면 정직하게 `pending‑verify`로 표시하고, 수정을 작동하도록 만들 수 없으면 `abandoned`로 표시한다. 이는 `self‑improvement`와 쌍을 이루는데 (`self‑improvement`는 반복적인 치유를 지속적인 메모리로 승격시킴), 검증‑후‑저장 규율을 담당한다.
