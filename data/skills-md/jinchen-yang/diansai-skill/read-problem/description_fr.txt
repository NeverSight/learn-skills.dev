Analysez le problème de compétition de cette année (lisez / examinez le problème). Utilisez ceci lorsque l'utilisateur place le PDF officiel du problème ou le texte dans inputs/problem/ et souhaite « lire le problème », « examiner le problème », « analyser le problème » ou « extraire les exigences / contraintes du problème ». Produisez un fichier structuré design/problem.yaml (incluant les contraintes, les fonctions requises, le barème, le lieu, le calendrier) comme source unique d'exigences pour les solutions ultérieures ou la sélection de matériel.

Veuillez toujours répondre dans la langue de l'utilisateur.
