목표와 평가자를 기준으로 실제 아티팩트(코드, 학습 레시피, 에이전트 하니스, 데이터 파이프라인, 프롬프트)를 자율적으로 개선하기 위해 Arbor 논문의 가설 트리 정제(HTR)를 사용합니다. 이것은 과적합 없이 여러 실험을 반복적으로 최적화하려는 경우에 사용합니다—예를 들어 “내 모델의 평가 점수를 높여줘”, “이 에이전트/하니스를 개선해”, “이 파이프라인을 튜닝해”, “이 벤치마크에서 베이스라인을 능가해”, “접근 방식을 탐색하고 최선의 결과를 유지해”, “MLE‑bench/Kaggle 스타일 최적화를 수행해” 혹은 “이 아티팩트를 장기적으로 개선하고 개발 세트를 단순히 암기하지 않게 해”와 같은 작업입니다. 사용자가 “Arbor”나 “가설 트리”라는 용어를 명시하지 않더라도, 반복적인 실험‑평가 루프, 경쟁 아이디어의 분기 탐색, 혹은 개발/테스트 격차에 대한 우려를 설명하면 이를 트리거합니다. Claude 자체를 코디네이터로 실행하고, 서브 에이전트 실행자는 격리된 git 워크트리에서 동작합니다; 독립 실행형 `arbor` CLI 도구에 대한 자세한 내용은 references/arbor-upstream.md를 참고하세요.
