自動地根據目標與評估者，使用 Arbor 論文中的假設樹精煉（HTR）來改進實際的工件（程式碼、訓練配方、代理框架、資料管線、提示）。在以下情況下使用此方法：當有人想在許多實驗中反覆優化某事而不致過度擬合——例如「提升我的模型評分」、「改進這個代理/框架」、「調整這條管線」、「在此基準上超越基線」、「對各種方法進行搜尋並保留最佳」、 「執行 MLE‑bench / Kaggle 風格的優化」，或任何長期的「讓此工件變得更好且不要僅僅記憶開發集」任務。即使用戶未提及「Arbor」或「假設樹」但描述重複的實驗與評估迴圈、競爭想法的分支探索，或擔憂開發/測試差距，也要觸發此流程。Claude 本身作為協調者，配合在隔離的 git 工作樹中的子代理執行者；獨立的 `arbor` CLI 工具請參見 references/arbor-upstream.md。
