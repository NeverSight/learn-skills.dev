# 店铺篇

## 范围

本篇只用于商家经营（直接处理当前店铺任务）：按 [总入口](../cap-skill/SKILL.md) 与 [共用交接约定](../cap-skill/references/shared-contracts.md) 处理，不套用课程的一次一步、单格跳过和固定话术；本篇阶段表仅用于判断当前所处阶段。本篇没有课程陪跑模式；来自课前准备上下文的请求按 [课前准备流程控制契约](../cap-tiktok-prep/SKILL.md#流程控制契约全局硬规则) 固定拒答。

本篇是市场、主体、注册、资质、经营阶段、履约和财务的唯一真源。专业任务交给对应大师，完成后回到本篇当前阶段：选品 → [选品大师](../cap-tiktok-selection/SKILL.md)；文案与钩子 → [拆解大师](../cap-tiktok-breakdown/SKILL.md)；独立站 → [建站大师](../cap-tiktok-site/SKILL.md)；商品采集与推送 → [上架大师](../cap-tiktok-listing/SKILL.md)；广告执行 → [投流大师](../cap-tiktok-ads/SKILL.md)；买家消息与客服系统 → [客服大师](../cap-tiktok-service/SKILL.md)。成本与利润统一用 [贡献利润口径](../cap-skill/references/profit.md)。

只处理本模块范围内的问题；范围外的问题不顺手作答，告诉用户这不属于本模块，交回总入口分派。

按固定顺序处理店铺篇。默认讨论中国大陆经营者申请 TikTok Shop 东南亚跨境自运营店。其他注册地、市场、本土店或全托管另查对应规则，不套用默认流程。

## 店铺篇顺序

| 阶段 | 完成标准 | 下一阶段 |
|---|---|---|
| 0 市场与模式 | 国家、店铺模式、主营大类和履约方式已确定 | 营业执照 |
| 1 营业执照与经营范围 | 主体类型已选、经营范围已确认、营业执照状态正常 | 注册店铺 |
| 2 注册店铺 | 资料已提交并出现申请状态 | 等待审核 |
| 3 等待审核 | 审核通过；或根据明确原文完成补件 | 店铺启用 |
| 4 店铺启用 | 保证金、结算、履约仓库、退货和基础形象可执行 | 定位与资金 |
| 5 店铺定位与启动资金 | 人群、类目、价格带、差异点、预算和亏损线已确定 | 选品 |
| 6 专业选品 | 候选通过需求、利润、竞争、内容和供应链筛选 | 商品合规 |
| 7 商品合规与供应商资料 | 禁限售、资质、标签、知识产权、物流和来源已核对 | 商品上线 |
| 8 商品上线 | 样品、日常价与三价复核、SKU、库存、商品卡、物流和前台通过验收 | 内容账号 |
| 9 内容账号基建 | 官方号/渠道号、资料、权限、橱窗和素材库可用 | 定价与营销 |
| 10 定价与营销 | 日常价复核、活动底价、保本价、优惠叠加、平台活动和营销日历已确认 | 首月启动 |
| 11 新店 7/14/30 天启动计划 | 启动前验收完成，首月动作、记录和停止线已安排 | 内容与达人冷启动 |
| 12 内容与达人冷启动 | 找到可复现的有效素材、达人或转化信号 | 付费与直播放大 |
| 13 GMV Max 与直播 | 广告或直播在贡献利润停止线内稳定运行 | 日常运营 |
| 14 订单、客服与售后 | 发货、客服、退换货和店铺健康形成稳定日常 | 财务与 SOP |
| 15 财务对账与现金流 | 订单贡献利润、平台结算、到账、库存和可用现金能核对 | 扩张决策 |
| 16 扩品、扩达人、扩预算或扩市场 | 原市场贡献利润、履约和现金流稳定，扩张条件已核对 | 扩品/扩达人/扩预算回到第 6 阶段（含第 7、10 阶段）；扩市场回到第 0 阶段 |

本表用于判断当前阶段，不是逐步打卡清单。识别用户已有结果，从当前卡点开始；不要求从头重做，也不一次发送所有阶段。用户说跳过某阶段时照做，但说明该阶段完成标准未核对、可能影响后续哪一步。

主体、注册审核、保证金、结算、权限、合规和上线验收严格照资料；选品、内容、营销和复盘的建议不能成为提前启动投放、采购或扩张的理由。

## 表达

- 先给结论，再给动作。多用选、办、准备、提交、核对、缴纳等动词。
- 默认 3–4 条短句加一个下一步；单点问题用 1–3 句答完。
- 只保留影响当前选择的条件；用户追问才展开原理、例外和完整材料清单。
- 已有信息不重问。只问会改变下一步的一个关键问题。
- 说明白就停。不追加“还想了解什么”，不反复征询是否展开。
- 规则说明不强套课前准备入口的六字段故障诊断格式。
- 数据分析先给结论和关键证据；用户追问时再展开完整评分。

## 营业执照流程

1. 先选主体：个体户或公司。
2. 再选范围：先读取用户已经说明的类目。类目明确就直接给建议；类目未说明就只问一次。
3. 交给注册地办理人员：让对方按当地登记系统确认规范名称。
4. 拿到执照后验收：核对主体名称、统一社会信用代码、法定代表人或经营者、经营范围和执照状态。截图必须遮住完整证件号码和个人信息。

当前一步没有完成就不主动展开下一步。用户确认主体类型后，直接进入经营范围。用户已经明确类目时不再问；用户明确表示暂时没选类目时，直接给通用经营范围。营业执照完成后进入注册店铺，不再停止整个店铺篇。

## 首次说明模板

以下模板基于 2026-09-17 检索到的官方条文。实际使用时核对更新；未确认的活动期限不补成确定数字。

用户还没有确定市场和店铺模式时：

> 店铺篇第一步：先定市场和模式。
>
> 1. 选国家：新手先确定一个首发国家，不同时开多个市场。
> 2. 选模式：准备自己选品、定价、做内容和投流，走跨境自运营流程；本土店或全托管另查对应条件。
> 3. 选履约：没有目标国现货就先评估中国直发；已经备货再核对海外仓。
> 4. 定大类：先确定准备经营的一级类目，再检查准入和营业执照。
>
> 现在只告诉我：准备做哪个国家、什么类目？

市场和模式已经确定后进入营业执照：

> 下一步：准备营业执照。
>
> 1. 选执照：个体户执照目前可申请东南亚跨境自运营店；准备长期做、申请多个市场，建议优先办公司执照。
> 2. 查市场：公司执照按目标站点审核，不能保证全球通开。
> 3. 留出保证金：东南亚跨境店按每店 90 美元准备。领到豁免权益后，按后台期限补缴，不默认所有新店都免 90 天。
> 4. 预留收款资料：TikTok Shop 回款使用后台支持的结算工具；PayPal 等独立站收款另按对应产品申请。
>
> 现在只告诉我：你还没办执照，还是已经有个体户或公司执照？

已有事实就复用并记录依据，免重复询问。附直接支持当前结论的官方来源，不展示完整研究过程。遇到不同注册地或店铺模式时重新查证，不套用默认模板。

## 阶段路由

| 状态 | 当前动作 |
|---|---|
| 尚未确定国家或店铺模式 | 先进入市场与模式，只确认主体、国家、经营方式和履约方式 |
| 想同时开多个国家 | 先选一个首发市场，跑通上架、履约和退款后再扩展 |
| 没执照，计划长期经营或多市场 | 建议优先考虑公司执照；用户问怎么办时，再查注册地官方办理流程 |
| 已有个体户 | 只核对目标市场与店铺模式，确认能否使用现有执照，不强迫升级 |
| 已有公司执照 | 核对目标市场的资质清单，不承诺全球通开 |
| 问经营范围且类目明确 | 给“通用核心项目＋该类目专项项目”，删除重复项 |
| 问经营范围但没说类目 | 只问一次“准备做什么类目”；给服装、3C配件、家居、美妆或暂未确定等例子 |
| 用户回复暂未确定或想做多个普通类目 | 给通用经营范围参考版，不继续追问 |
| 用户给出多个类目 | 合并各类目项目，删除重复项，单独标出许可或定邀类目 |
| 做手机壳 | 按 3C 与手机配件类目给建议；手机壳只作为示例，不作为默认类目 |
| 做定邀类目 | 确认主营类目已经写入营业执照经营范围；没有就先变更范围 |
| 做食品、药品、医疗器械等许可商品 | 先查许可或备案要求，不把一般经营项目当作经营许可 |
| 问免保证金 90 天、到期 90 美元 | 查该店的豁免资格、起算日、到期日、计费单位及应缴金额；缺证据就明确未确认 |
| 问 PayPal 或独立站 | 区分账户注册地、企业/个人账户、搭站/开通收款；按对应产品查官方清单 |
| 反馈执照已办好 | 核对执照关键信息后进入店铺注册 |
| 问怎么注册店铺或提交什么资料 | 进入注册流程，一项一项核对，不代替用户上传证件 |
| 问多久下店、审核中或被拒 | 根据提交日期和页面原文处理；不承诺统一审核天数 |
| 反馈店铺已审核通过或已下来 | 进入店铺启用，从保证金状态开始 |
| 问先装修、先收款还是先绑定仓库 | 按保证金 → 结算 → 履约仓库 → 基础装修的顺序处理 |
| 问海外仓 | 先确认是否真的在目标国备货；没有海外库存就不要求绑定海外仓 |
| 基础启用完成 | 先确定店铺定位、价格带、首批预算和最大亏损线，再进入选品 |
| 问准备多少钱、怎么分预算或现金不够 | 进入定位与资金，先算保证金、样品、库存、物流、达人、广告和退款准备金 |
| 基础启用完成并问卖什么 | 定位和资金已明确后进入选品，确认国家、类目、预算和履约模式 |
| 问 FastMoss 或其他工具 | 进入 `cap-tiktok-selection`；先用官方数据和免费/试用功能，第三方数据只作交叉验证 |
| 问去哪里买工具会员 | 不无条件推荐闲鱼；只接受可核验授权的独立许可，不购买共享、租用或破解账号 |
| 给出具体商品 | 进入 `cap-tiktok-selection` 评分（硬性淘汰优先），合规仍在本篇商品合规核对 |
| 问商品能不能卖、需要什么认证或供应商资料 | 进入商品合规，先查禁限售、类目资质、标签、知识产权和物流 |
| 选品已完成或问下一步 | 先完成商品合规与供应商资料，再拿样验品和复核利润 |
| 商品上线完成 | 绑定内容账号、核对橱窗和权限，建立首批素材库 |
| 问定价、优惠券、折扣、包邮或平台活动 | 先计算日常价、活动底价和保本价，再检查优惠叠加 |
| 问新店前一个月怎么做 | 使用 7/14/30 天计划，不承诺固定出单日期 |
| 问先投流还是先找达人 | 先完成商品卡和素材；无内容团队先建联达人，能稳定拍摄就自营内容与达人同步测试 |
| 问商品怎么上架、标题、主图、详情或 SKU | 进入商品上线资料，先核对样品、利润和类目 |
| 问达人联盟、佣金、寄样或建联话术 | 进入内容与达人冷启动，按公开合作、定向合作、寄样和漏斗复盘处理 |
| 问 GMV Max、投流、ROI 或预算 | 先按 [付费与直播增长](references/paid-growth.md#投流前置条件) 检查冷启动信号和保本线；通过后再进入 Product GMV Max。只读分析不受此限 |

| 问直播或 LIVE GMV Max | 先验收主播、货盘、脚本、库存和自然转化，再小规模放大 |
| 问订单、发货、客服、退货、退款或差评 | 先处理截止时间最近、影响店铺健康最大的异常；客服系统、渠道接入、知识库或自动回复进入 `cap-tiktok-service` |
| 问独立站、Shopify 或承接页 | 进入 `cap-tiktok-site`；独立站不是 TikTok Shop 的必修前置 |
| 要把商品导入或推送到 Shopify/Wix，或批量整理商品资料 | 进入 `cap-tiktok-listing`；TikTok Shop 原生上架仍按本篇商品上线 |
