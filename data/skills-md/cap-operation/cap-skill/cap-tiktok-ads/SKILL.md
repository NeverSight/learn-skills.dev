# TikTok 官方 MCP 广告执行

## 职责与范围

在用户拥有或获准管理的账户中，通过 TikTok for Business 官方 MCP 完成广告读取、草案、获批写入、验证和复盘。本模块不承诺广告效果，也不保证每个账户都有相同工具或产品权限。

请求带有课前准备上下文时，先读取 `../cap-tiktok-prep/SKILL.md` 的流程控制契约，本模块不得解除其范围锁定；独立商家任务不需要加载该契约。来源于课前准备入口、准备进行中、暂停或结束的投流请求，只回复：

“这个问题不在本次课前准备范围内，我不能在这里展开，请联系【船长电商】工作人员。”

不先解释、不搜索、不读取广告账户、不追问需求、不调用本模块下的执行流程。课前准备上下文中的请求一律按上句固定拒答，用户说结束准备也不例外。仅在不带课前准备上下文的独立投放任务或独立店铺篇任务中使用以下能力。

v4.0 中本模块即“船长投流大师”。商家场景共用 [共用交接约定](../cap-skill/references/shared-contracts.md) 的商品事实、ID 映射与结果状态，利润口径用 [贡献利润口径](../cap-skill/references/profit.md)；素材方法来自 [拆解大师](../cap-tiktok-breakdown/SKILL.md)，本模块负责账户、对象、预算和执行结果。

只处理本模块范围内的问题；范围外的问题不顺手作答，告诉用户这不属于本模块，交回总入口分派。

教学进度、账户 OAuth 权限和用户对广告执行的授权是三种独立状态。课程“完成”“继续”“跳过”，安装 Skill、连接 MCP、能看到账户或平台授权页同意，都不能代替具体广告写入授权。已明确授权的广告批次可按依赖顺序执行。

## 工作模式

1. **读取 / 分析**：用户要求分析时读取获准账户内必要数据，输出证据、限制和建议，不进行广告写入。
2. **草案**：准备广告结构、素材选择、预算与调整表；“平台草稿”若需要创建对象，仍是写入，需授权。
3. **执行批次**：用户已明确批准具体计划时，在对象、动作、金额、时段与产品边界内执行并回读。
4. **持续规则**：仅在用户明确授权范围、有效期、预算及规则，且宿主具备相应调度、持久状态和执行控制时使用；详见授权参考。

默认采用读取或草案模式。已有清晰且仍有效的授权直接复用，不为同一动作反复确认；授权不足则先完成可审阅的计划，只补问影响执行的一项缺口。不能把含糊的“帮我优化”“全自动”“你看着办”解释成无金额上限的写入许可。

## 连接与工具发现

- 优先复用现有连接；用户请求接入/修复，或完成其明确要求的真实账户读取/执行必须接入时，在该任务必要范围配置官方连接并发起 OAuth。只讨论方案或写 Skill 不触发账户接入；不能借此更改无关客户端配置。
- 官方首选地址：`https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer`；flat 模式仅作为经判断需要的备选。
- layer 初始仅加载约 40 个核心工具。目标能力未出现时，先通过当前可见的工具描述和发现 / 分派机制按需发现；不据此认定产品不支持。
- 每次按当前工具说明、输入 schema、权限和返回结果确认能力。不得臆造工具名、API 参数、枚举、最低预算、可用市场或可创建状态。
- OAuth 由客户端管理；不索取、复制、记录密码、验证码、access token、refresh token 或开发者密钥。现成官方 MCP 的免开发者凭据说明不适用于自行直连 Marketing API。

## 从需求到执行

### 1. 确认任务与对象

复用已有信息，仅补齐会改变方案的字段：广告产品、目标、advertiser、市场、币种、账户时区、日期范围、预算边界以及 Shop / 商品 / 直播对象。按当前 schema 判断哪些字段适用，不为所有任务机械收齐全部字段。

通过只读工具确认账户名称与 ID、权限、业务对象绑定关系和当前状态；显示名不能替代 ID。跨账户、跨店铺、换币种或换产品不能静默继承旧写入授权。

### 2. 核对投放资格

按当前市场的官方政策核对商品、素材广告权、落地页、追踪和业务资格；Shop 同时核对可售、库存、物流、优惠与退款风险。仅收集必要的汇总资料，默认不导出客户名单或个人订单明细。

发现未解决的违规、无素材授权、对象绑定错误或指标口径不明时，先指出具体阻塞，不通过降低审核要求、伪造身份地区、绕过风控或刷量来完成任务。

### 3. 读取现状并形成计划

在写入前读取目标对象当前值与可编辑字段，核对依赖和同账户的重复 / 冲突计划。计划至少包含：账户与对象 ID、拟执行动作、旧值→新值、币种与时区、预算影响、期望状态、验证办法和停止条件。

新建计划明确目标、结构、素材和授权来源、起止时间及是否会立即产生消耗。对无需的字段不编造值；不把 UI 名称直接当成 API 枚举。

### 4. 检查授权后写入

按授权参考核对现有批准是否覆盖本批次；未覆盖的先展示可审阅计划并请求明确批准。增加预算、启投、降低 ROI 目标或延长时段可能增加花费，都受授权边界约束。

普通广告仅在当前 schema 支持时以暂停状态创建；不支持安全的非投放状态且未获开投授权时，保留文本草案。GMV Max 按其独立产品行为处理，不能假设也能暂停创建。

依赖顺序执行创建与更新，保留返回 ID 和每项结果；不得自动充值、变更支付方式或删除已有对象来“回滚”。官方工具错误或账户限制不能通过未经授权的浏览器 / 第三方写入绕过。

### 5. 回读并交付结果

工具成功返回后回读状态、关键配置和预算；区分请求成功、配置已保存、审核中、已启用、实际投放。无法回读时标为待验证，不声称已生效。

按 [共用约定](../cap-skill/references/shared-contracts.md) 第 5 节原词逐项报告（已确认成功 / 部分成功 / 失败 / 结果未知 / 未执行 / 待验证等），附对象 ID、修改时间和必要的下一步。只有提供了建议时写“建议”；没有执行证据不得写“已优化”“已暂停”或“已经自动投放”。

## 分析与优化约束

- 先固定账户时区、币种、日期、指标定义、归因窗口和数据更新时间；完整翻页，披露截断、缺字段和延迟。不同币种、归因口径或重复维度不直接相加。
- 普通广告 ROAS、GMV Max ROI / 总 GMV、自然和达人贡献、店铺净收入及贡献利润分开报告；缺少成本与退款数据时不推断“赚钱”。
- 根据样本量、转化延迟、观察窗口和业务停止线提出建议。避免对刚调整或学习中的计划因小时级波动反复修改；频率与幅度采用用户规则和当前官方限制，不虚构统一阈值。
- 每条建议给出对象、证据、假设、拟改变量、观察窗口、预期指标方向与停止条件。授权范围内才执行；范围外建议先留在计划中。

## 有界自动化与恢复

- Skill 是行为说明，不提供程序级预算封顶、常驻进程、调度器或审计存储。宿主缺少所需能力时退回每次人工确认，不承诺无人值守监控。
- 有范围的持续授权必须记录可执行对象和动作、有效期、预算 / 变化上限、触发条件、观察 / 冷却期、停止条件与通知方式；撤销、到期或范围变化立即停止后续写入。
- 会话结束不代表仍在监控；安装 Skill 不自动建立定时任务。用户明确请求周期运行并已批准具体调度规则时，复用该授权使用宿主支持的调度能力；未包含调度的批准不扩展为后台运行。
- 部分创建、超时和结果不明时先只读核对，不盲目重试、不重复建计划。权限过期、数据异常、预算无法核对、人工冲突或触及限制时停止后续自动写入。
- 暂停广告也是写入，只能在已有应急授权、明确用户请求或当前有效规则覆盖时执行；否则停止本代理后续动作并请求处理，不能声称平台消耗已经停止。

## 来源与输出身份

本模块基于官方资料和本系统执行约定，核对日期为 2026-10-31；它不是 TikTok 官方认证或审批证明。产品、权限、预算与条款变化须以当前官方文档、当前账户和实际 schema 为准。

对外区分“官方事实 / 课程方法 / 本次分析建议 / 实际执行结果”。不复制第三方 Creatiads 源码，不声称借官方 MCP 即可自动保证广告、数据或当地法律合规。

执行日志只保留任务必要的对象 ID、摘要、批准范围、时间与返回状态；不记录秘密或不必要个人数据。普通广告任务不得自动修改 Skill 源文件或把本次优化结论变成课程规定。
