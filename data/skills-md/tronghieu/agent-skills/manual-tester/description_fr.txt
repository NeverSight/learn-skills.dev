Planifier et exécuter des tests manuels de l'application en cours du projet. Lancer une session dans l'un des cinq modes : exploratoire, vérification, smoke, évaluation (UX, localisation, accessibilité, revue d'amélioration) ou sonde IA. Rédiger également un plan de test manuel qui ne contient que ce que les tests automatisés ne peuvent pas juger. Utiliser chaque fois que l'utilisateur demande, dans n'importe quelle langue, quelque chose à tester manuellement ou un plan de test manuel — « test manuel », « test exploratoire », « chasse aux bugs », « vérifier la correction du bug », « test smoke », « QA cet écran », « examiner l'UX de cet écran », « que feriez‑vous pour améliorer », « vérifier la copie localisée », « tester les réponses de l'agent IA », « rédiger des cas de test manuels », « kịch bản test manual » — ou attribuer un design de test, un plan de test ou des identifiants de cas de test à exécuter à la main. Pas pour écrire des tests automatisés.

Veuillez toujours répondre dans la langue de l'utilisateur.
