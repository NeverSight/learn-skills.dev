Рабочий процесс завершения PUSH/RELEASE/PR/MR — вызывается, когда пользователь упоминает «release», «push», «ship», «выпустить релиз», «открыть PR» или «создать MR». Выполняется CHECKLIST условий ПРЕД ПУШЕМ: (1) medic --ci (порт здоровья: правила bite/drift/docs/code/eval); (2) UAT /fdk-uat через реальный remote, если diff содержит новые возможности (только для release/PR/MR, medic --ci не доказывает путь curl); (3) чистый git (scratchpad/ephemeral не отслеживается); (4) selftest; (5) версия x.x.x+1 от ближайшего тега (только уровень release); (6) честные примечания к патчу/тело PR (Added/Fixed/Removed/Known‑limitations, НЕ преувеличивать). Поддерживается 5 уровней: «ship push» = только push без тега; «ship release» = push + тег vX.Y.Z + release notes; «ship pr» = push ветки + gh pr create (GitHub); «ship mr» = push ветки + glab mr create (GitLab); «ship merge» = перечислить входящие PR/MR репозитория по remote, вытянуть ветку, запустить gate + test, сливать только если ЗЁЛЁНЫЕ. STOP — ждать одобрения перед шагом с побочными эффектами. Триггер: /ship, «release», «push», «ship», «открыть PR», «создать MR», «ship pr», «ship mr», «ship merge», «гом PR в merge», «merge PR если тест зелёный», «подготовить push», «выпустить релиз», «checklist перед push», «условия для push выполнены?».
