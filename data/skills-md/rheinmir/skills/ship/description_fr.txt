Flux de travail pour finaliser PUSH/RELEASE/PR/MR — appelé lorsque l’utilisateur mentionne « release », « push », « ship », « lên release », « mở PR » ou « tạo MR ». Exécuter la CHECKLIST des conditions AVANT le push : (1) medic --ci (port de santé : loi du mordant / drift / docs / code / eval), (2) UAT /fdk-uat via le vrai remote si le diff possède de nouvelles capacités (seulement release / pr / mr, medic --ci ne peut pas prouver le chemin curl), (3) git propre (scratchpad / ephemeral non suivi), (4) self‑test, (5) version x.x.x+1 à partir du tag le plus proche (seulement pour le niveau release), (6) notes de patch / corps du PR honnêtes (Added / Fixed / Removed / Known‑limitations, NE PAS exagérer). Support de 5 niveaux : « ship push » = push uniquement, sans tag ; « ship release » = push + tag vX.Y.Z + notes de release ; « ship pr » = push de branche + création de PR avec gh (GitHub) ; « ship mr » = push de branche + création de MR avec glab (GitLab) ; « ship merge » = lister les PR/MR ENTRANTS du dépôt selon le remote, récupérer la branche, lancer gate + test, ne merger que si VERDE. STOP en attente d’approbation avant l’étape à effet secondaire. Déclencheurs : /ship, « release », « push », « ship », « mở PR », « tạo MR », « ship pr », « ship mr », « ship merge », « gom PR về merge », « merge PR nếu test xanh », « chuẩn bị push », « lên release », « checklist avant push », « đủ điều kiện push chưa ».
