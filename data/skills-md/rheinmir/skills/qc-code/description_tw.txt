以資深 10 年風格檢視程式碼 — 四項目：安全性·效能·命名·邏輯，每項目給予 分數/10 + 最嚴重錯誤 + 修正方式，最後給出 PASS‑可進入下一步 或 需要修正 的結論。邏輯項目尋找 bug（null / 空 / 負 / overflow、off‑by‑one、race）並產生對應的測試案例以重現每個 bug（命名為 qc‑*），這些測試會透過固定的 hook 自動執行（0‑token，不使用 LLM）。當使用者說「qc code」「review code」「soi code」「chấm điểm code」「kiểm tra chất lượng code」「/qc-code」時觸發。不同於 /orca‑sec‑scans（Trivy 掃描狀態 — 漏洞 / 錯誤設定 / 機密）以及內建的 /code‑review（總體檢閱）：qc‑code 採用資深四項目打分 + 判定 + 產生重現測試的格式。預設檢閱目前的 DIFF；必要時可指定檔案。
