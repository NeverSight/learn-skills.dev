当任务因缺失或未验证的信息（未记录的协议、未知的 API 形状、只有真实硬件/生产环境才能确认的数值）而受阻时，先构建所有当前不依赖于这些未知因素的部分，并将未知因素隔离在单一适配器边界后——采用最佳猜测的默认值、一个已验证标记以及一个符合/适配套件——这样以后适配时只需编辑一个文件，而不是重写整个项目。当用户说“làm những gì có thể trước”“build what we can now”“wrap the unknowns”“isolate/quarantine the unknown parts”“don't block on missing info”“adapter so we can swap later”“ready to adapt”，或调用 /build-now-adapt-later 时触发。该规则也适用于规范中出现⚠️“待验证”项目，但大部分工作并不实际依赖这些项目的情况。
