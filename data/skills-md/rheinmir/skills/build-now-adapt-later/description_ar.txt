عندما يتعطَّل مهمة بسبب نقص أو معلومات غير مُتحقَّق منها (بروتوكول غير موثَّق، شكل API غير معروف، قيمة لا يمكن تأكيدها إلا من خلال العتاد الفعلي/الإنتاج)، قم ببناء كل ما لا يعتمد على المجهول الآن، وعزل المجهول خلف حدّ مُكيِّف واحد — قيم افتراضية مبنية على أفضل تخمين + علم تحقق + مجموعة توافق/تكيف — بحيث يعني التكيّف لاحقًا تعديل ملف واحد فقط، لا إعادة كتابة المشروع. يتم التفعيل عندما يقول المستخدم «làm những gì có thể trước», «build what we can now», «wrap the unknowns», «isolate/quarantine the unknown parts», «don't block on missing info», «adapter so we can swap later», «ready to adapt» أو يستدعي ‎/build-now-adapt-later. ينطبق ذلك أيضًا كلما كان في المواصفات عناصر ⚠️ «to be verified» ولكن معظم العمل لا يعتمد عليها فعليًا.
