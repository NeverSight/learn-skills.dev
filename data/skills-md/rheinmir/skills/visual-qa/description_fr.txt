Flux de travail d'auto‑vérification visuelle en boucle fermée pour les SPA locaux (applications générées par /br, ou toute application web) : capture headless de chaque route → référence de pixel‑diff (détecte les changements non désirés) → invariance du test machine (conformité du design) → agent LIT toutes les images selon le rubric → FINDINGS.md → correction → nouvelle capture → ne passe que si la machine ET l'œil sont tous deux satisfaits. Utilisé lors du changement de thème/UI/rebranding, lorsque l'extension MCP ne peut pas capturer le localhost, ou lorsqu'il faut verrouiller l'UI pour un cadre. Déclencheurs : « qa visuel », « visual qa », « route‑shots », « screenshot de chaque route », « vérification d'interface », « baseline diff », « l'UI a-t-elle une régression », « test d'interface headless », « /visual-qa ».
