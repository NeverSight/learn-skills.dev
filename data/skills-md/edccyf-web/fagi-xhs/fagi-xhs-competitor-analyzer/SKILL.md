# Fagi xhs competitor analyzer｜小红书对标账号分析 Skill

## 0. 定位与底线

本 Skill 是**通用的账号研究与策略分析工具**，不预设用户从事旅行、旅拍、越野或任何其他行业。输入是1–3个对标账号的**主页链接或截图**，以及用户自身业务和本次学习目标。最终交付五维分析与具体可操作建议。

**事实先于结论：**仅使用可访问的公开内容、用户提供的图片/文件、或用户依法授权的数据；不可绕过验证码、登录保护、风控或抓取限制。没有获取的数据必须写“未获取/无法核实”，不得臆测粉丝量、爆文数、曝光播放、销量、转化率或历史涨粉。

## 1. 启动与交互：先索取三项信息

当用户只说“分析对标账号/研究小红书博主/启动 Skill”等而**尚未提供账号**时，第一条回复必须直接输出以下启动引导；只问这一轮，不使用长表单：

> 请把你想分析的 **小红书账号主页链接或截图** 发来，先看 **1–3 个**就够。
>
> 再补充两点：
> 1. **你现在做什么内容、卖什么产品或服务？** 还没开始的话，说想做的方向。
> 2. **这次主要想学什么？** 内容涨粉、获客成交，还是判断这个账号值不值得模仿？
>
> 收到后，我会从 **行业赛道、粉丝数据、爆文数据、爆款逻辑、值得借鉴的内容点** 五个维度分析，并给出适合你的可执行建议。

若用户已提供账号链接或截图：**直接开始身份和数据核验**，不要重复索要已提供的信息。若业务方向或目标尚未提供，可简短请求补充（若阻碍策略定制）；用户不补充时照样出通用报告，明确注明“用户业务/研究目标未提供，建议按通用情况给出”，不能卡住流程。账号超过3个，请建议先选1–3个，避免浅层分析。

输入可以混合使用（例如账号 A 给链接，账号 B 给主页截图）；可以有多个截图分别对应同一账号。仅需主页截图就能产出**基于可见信息的初步五维报告**；若看不到具体笔记数据，不能把它包装成完整历史爆文排名。

## 2. 任务路由（最短可执行路径）

1. **解析输入**：提取账号名称、主页 URL/用户 ID（若有）、截图文件、用户业务/产品、目标（涨粉/获客成交/是否值得模仿/其他）。不要将账号名称作为唯一身份标识。
2. **核对身份**：优先主页链接或截图中可见昵称、头像、简介、ID。链接与截图冲突须明确提示；不要把同名账号数据混入。
3. **采集与证据登记**：
   - 链接：在可用的网页/浏览器能力范围读取公开主页及笔记，不可访问则转向搜索索引；索引结果必须能与目标 ID/链接对应才可纳入。
   - 截图：直接视觉识别截图中**能看清**的计数、简介、标题、封面信息，记录截图序号；模糊无法辨认则写“无法辨认”。
   - 链接访问失败但已有截图：以截图继续分析，不要求用户更换数据渠道才能得到结果。
   - 记录每条信息的来源、采集/截图日期（若无法确认为截图当日，写“截图拍摄时间未知”）、可核实级别。
4. **建立样本**：如果可访问，默认收集最近最多30篇有可核实信息的笔记（不强求一定30篇），同时关注公开可访问的历史高互动内容；实际有效数 N 必须注明。截图仅能显示几篇就分析几篇。
5. **TOP榜逐篇核验**：先固定样本排序口径，再打开榜内每一篇笔记详情（最多10篇/账号），补录观看量、点赞、收藏、评论、转发及证据。详情不可访问时保留该行已有数值并注明缺失，不跳过、不补零；不得只停留在首页点赞榜。数值补齐后沿用原排序口径；如需改口径，重算全组可比样本并说明，不把补齐的少数笔记与未补齐的笔记混排。
6. **分析五维**：用相同维度与统计口径研究所有账号，并按照用户业务/目标进行策略匹配。
7. **交付报告**：即使只有主页截图，也生成五维报告；不支持的维度保留“可见线索 + 无法验证内容 + 可作出的谨慎结论”，不编造量化结论。多账号时增加横向比较与优先学习对象建议。
8. **必要时一次性补充材料**：仅当用户确实希望更深入、且关键页面缺失时，在报告末尾提出最少数量的可选补图建议（例如各账号笔记列表1张、TOP3作品详情若干），不让材料补充成为完成现有报告的前提。

## 3. 五维分析标准（必须全部覆盖）

### 维度一：行业赛道与账号定位

从简介、内容样本和身份信息判断：一级/细分赛道、核心内容支柱、目标人群需求、价值承诺、人设/差异化定位、可能的商业路径。

- **事实**：主页简介、认证、账号标签、可见笔记内容。
- **推断**：目标受众痛点、商业模式、差异化动机；必须标记为“推断”，不得把推断写成事实。

### 维度二：粉丝数据与运营表现

- 有则列：粉丝数、关注数、主页显示的获赞/收藏总量、更新频率、最近 N 篇互动中位数及可见发布时间。
- 只有一次主页截图，记录为**当前截图所示数值**；没有历史快照，**禁止声称粉丝增长趋势或涨粉速度**。
- 不能将“主页累计获赞与收藏”视为单篇互动，也不能将互动/粉丝比当成真实阅读互动率。

### 维度三：爆文数据

- 明确样本 N、窗口、来源、哪些字段可见。
- 条件允许时输出 **样本 TOP10**（不足10则输出“样本TOP N”），每篇包括：排名、标题、笔记链接/截图编号、发布日期、内容类型，以及观看量、点赞、收藏、评论、转发五项数值；每项记录原页面字段、原显示值、来源与采集时间。未取得的字段用“未获取”并写原因，不省略该列。
- 观看量保留平台原字段：视频播放量、图文阅读/浏览量分别标记，曝光量不能替代观看量；转发/分享数不能从分享按钮或评论数推算。页面为“1.2万”时保留原显示，可另记约12000，不能伪装成精确计数。观看量、转发数只有可见页面或用户授权的后台/导出中确有数值时才填写，不推测对方后台数据。
- 同一组有可比计数时可按点赞+收藏+评论之和排序。任一关键字段缺失时不得将缺失视作0；采用同口径的可见指标，报告说明。
- 相对爆文指数：R=单篇可比互动值÷同窗口*其他*可比笔记的互动中位数，仅在至少10篇有效可比笔记、分母>0时计算，并注明仅为内部研究指标，非平台官方标准；R≥3可标记“相对高表现候选”。
- 若只看到主页九宫格封面，没有互动数据，可做**选题/封面模式**观察，不能生成所谓TOP爆文数据。

### 维度四：爆款逻辑与内容结构

对 TOP榜中的每篇笔记分别按“选题→标题→封面→内容结构→情绪/利益价值→互动设计”拆解，不以账号概述代替逐篇分析。每篇绑定同一笔记ID的五项数值、详情核验状态、正文/视频可见程度和证据；正文/视频不可访问时只拆可见部分，并写明未分析项。再选3–5篇代表作做更深入对照，至少配一篇样本内普通表现笔记；没有可比普通样本则注明，不能编造。

- 只见封面时只能分析可见的**封面信息与标题**；未观看视频/未取得正文时，不能声称“前3秒如何设计”“第几秒出现转折”“视频完播率”。
- 输出区分：**观察到的事实 → 可能解释 → 需要验证的假设**。不要将热门原因描述为已证实因果。

### 维度五：值得借鉴的内容点

必须结合“用户自己做什么内容、卖什么产品/服务”和“本次目标”，不是泛泛模仿。

对每个借鉴点输出：**参考案例或截图编号｜为什么对用户有用｜如何改造成自己的内容｜成本/难度｜风险/不建议照搬之处**。

根据目标调整优先级：
- **内容涨粉**：优先研究选题覆盖、标题/封面、内容辨识度、可连续生产性、相对互动表现；不以涨粉量推断作为依据。
- **获客成交**：优先研究信任建立、问题解决、案例证据、适当的商业表达与行动引导；没有后台数据不得宣称其成交效果。
- **判断是否值得模仿**：优先看目标人群契合、资源要求、内容可迁移性、可持续供给、竞争差异和平台合规风险。给出“值得学习/部分借鉴/不宜作为主要对标”结论和依据。
- 用户有其他目标时，按目标重排而不是套用固定答案。

## 4. 证据与缺失控制

每个有意义的数字标注来源：`[主页链接，读取日期]`、`[截图A-1]`、`[笔记URL]`；重要判断使用 `[已验证]` / `[基于样本推断]` / `[数据不足]`。

分清四类情况：
1. **已验证**：页面/截图直接可见；
2. **推断**：来源充分但仍非直接观测；
3. **缺失**：没看到/字段不可访问；
4. **不适用**：例如用户只给截图而无法获得历史粉丝曲线。

不要制造虚假的完整性：没有取到笔记不写“0篇笔记”（只能写“成功采集0篇”）；样本TOP10不等于该账号历史全量TOP10。对可访问性问题简短解释，不重复搜索直到耗尽预算。

## 5. 输出规格

必须依次输出：

1. **摘要**：账号列表、输入类型、研究目标、数据覆盖情况、优先建议（一段）。
2. **维度一：行业赛道**：每个账号定位/人群/核心内容矩阵。
3. **维度二：粉丝数据**：公开可核实指标、发布频率及缺失说明。
4. **维度三：爆文数据**：样本TOP N、固定排序口径及逐篇观看/赞/藏/评/转五项明细、来源与缺失原因；无排名条件时不伪造TOP榜。
5. **维度四：爆款逻辑**：TOP榜每篇单独拆解，绑定数值与证据；另对3–5篇代表作深化对照，不能仅列标题和数字后跳到泛泛建议。
6. **维度五：值得借鉴的内容点**：针对用户业务/目标提出3–5项优先行动（证据不足时缩减）。
7. **1–3账号横向结论**：对标适配度、可学习点、不要照搬点及推荐优先级（单账号则做适配性结论）。
8. **数据质量说明**：来源、样本、缺失、哪些结论仅为推断、如需深入应补哪些材料（可选）。

报告应**先结论再证据**，少套话，尽量避免超过用户实际想看的信息量。若缺失较多，采用“阶段性五维报告”命名。

更加详细的操作规则请参考 `references/analysis-method.md`，输出结构参考 `references/report-template.md`，测试场景见 `tests/acceptance-cases.md`。不要为了遵循模板而填补不存在的数据。

## 6. 资源、效率与运行边界

- 只在现有工具能够正常访问时读取 URL；Skill 文本本身**不代表自动获得小红书 API、登录会话或网页浏览权限**。
- 有截图时优先充分使用截图，避免无意义的网络重复请求。
- 一次只处理1–3账号；每个账号上限30篇默认样本；TOP榜内每篇做数值核验和基础拆解（最多10篇/账号），其中最有代表性的3–5篇做深度对照。不可访问项一次说明后继续，不反复请求到耗尽预算。
- 绝不让用户提供密码、cookie 或私密令牌；允许用户自行在受信任的浏览器中正常登录。
- 合规、版权、隐私优先；不建议复制他人原文或直接盗用素材。
