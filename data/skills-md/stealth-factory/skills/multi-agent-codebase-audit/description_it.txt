Audita un intero codebase con più agenti in parallelo — mappa il repository, suddividilo in sezioni di revisione, assegna uno (o più, multi‑lente) sub‑agente revisore per sezione, riduci con un critico trasversale/di architettura più un controllo di completezza, quindi gestisci la triage, correggi e riporta con un registro di copertura onesto. Usalo quando ti viene chiesto di “auditare l’intero codebase”, “revisione completa di sicurezza/qualità del repository”, “revisionare l’intero progetto”, “fare un audit di codice profondo/comprensivo”, “scansionare tutto per bug o vulnerabilità”, durante l’onboarding/ereditarietà di un repository poco familiare, o per una pulizia periodica approfondita. Scoping su tutto il repository e scala il numero di agenti alla dimensione del repository — NON è una revisione di diff (per linee modificate utilizza la revisione a doppio agente).
