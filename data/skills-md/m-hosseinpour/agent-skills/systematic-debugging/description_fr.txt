Utilisez-le lorsqu’il s’agit d’enquêter ou de corriger un bug, une régression, un test qui échoue ou est instable, un échec de compilation ou de déploiement, un problème de performance ou une sortie incorrecte ; également lorsque l’on vous demande pourquoi une défaillance s’est produite. Pas pour la conception de fonctionnalités, l’explication d’un code sans erreur, ou l’application d’une correction déjà vérifiée sans nouvelle incertitude.

Veuillez toujours répondre dans la langue de l’utilisateur.
