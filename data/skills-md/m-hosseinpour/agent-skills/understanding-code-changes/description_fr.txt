Utilisez cette approche lorsque vous avez besoin de comprendre ou d'expliquer une pull request, une merge request, une branche ou un diff plutôt que de le juger, en particulier lorsque vous prenez en charge un code qui ne vous est pas familier, que vous localisez une modification dans l'architecture du projet ou que vous vous familiarisez avec le contexte avant d'examiner une modification importante.
