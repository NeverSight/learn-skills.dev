Créez les notes de version et le guide de mise à jour pour une version de mariadb‑operator. À partir de la PR de version dont le corps répertorie chaque PR incluse dans la version, il récupère chaque PR, regroupe les changements par pertinence et génère `docs/releases/RELEASE_<version>_HEADER.md.gotmpl` et `docs/releases/UPGRADE_<version>.md` selon le format utilisé par les versions précédentes, puis ouvre une PR ciblant `release-<version>`. Si aucune PR de version n’est fournie, il demande la nouvelle version et déduit les changements à partir de l’historique Git depuis le dernier tag. Utilisez‑le chaque fois que l’utilisateur veut des notes de version, un guide de mise à jour/mise à niveau ou de la documentation pour une nouvelle version de mariadb‑operator — « créer les notes de version pour 26.10.0 », « écrire le guide de mise à jour », « documenter cette version », « préparer la documentation PR de version » — même s’ils ne mentionnent pas de PR de version.

Veuillez toujours répondre dans la langue de l'utilisateur.
