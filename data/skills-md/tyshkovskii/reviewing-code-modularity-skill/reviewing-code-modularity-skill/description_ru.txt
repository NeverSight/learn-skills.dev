Используйте при обзоре или изменении структуры кода, чтобы кодовая база была проще для понимания, изменения, тестирования или удаления — включая случаи, когда пользователь не использует структурную терминологию, например: «этот файл делает слишком многое», «это трудно протестировать», «я постоянно редактирую одно и то же в разных местах» или «это беспорядок». Охватывает границы модулей, разбиение файлов, публичные API/экспорты, направление зависимостей, связность/когезию, поверхностные слои, избыточную абстракцию, дублирование структурных решений, трудно тестируемые обработчики/компоненты, разбросанное сопоставление ошибок и рефакторинги, перемещающие код между модулями. Не используйте для обычных исправлений багов, форматирования, чистки только имён или локальных правок, не влияющих на структуру.
