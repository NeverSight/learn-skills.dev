Úselo al revisar o cambiar la estructura del código para que una base de código sea más fácil de entender, modificar, probar o eliminar, incluso cuando el usuario no emplea vocabulario estructural, por ejemplo: “este archivo hace demasiado”, “esto es difícil de probar”, “sigo editando lo mismo en muchos lugares” o “esto es un desastre”. Cubre los límites de los módulos, la división de archivos, las API/exports públicas, la dirección de dependencias, el acoplamiento/cohesión, capas superficiales, sobreabstracción, decisiones estructurales duplicadas, manejadores/componentes difíciles de probar, mapeo de errores disperso y refactorizaciones que trasladan código entre módulos. No lo use para correcciones de errores habituales, formateo, limpieza solo de nombres o ediciones locales que no afecten la estructura.
