コードベースを理解しやすく、変更しやすく、テストしやすく、削除しやすくするために、コード構造をレビューまたは変更する際に使用する——ユーザーが構造に関する語彙を使わない場合でも、例として「このファイルはやりすぎだ」「テストしにくい」「同じことを多くの場所で編集し続けている」「散らかっている」など。モジュール境界、ファイル分割、公開 API／エクスポート、依存関係の向き、結合度／凝集度、浅い層、過度な抽象化、重複した構造的決定、テストが困難なハンドラ／コンポーネント、散在するエラー対応、モジュール間のコード移動リファクタリングなどを対象とする。通常のバグ修正、フォーマット、名前のみのクリーンアップ、構造に影響しないローカルな編集には使用しない。
