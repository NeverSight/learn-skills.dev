Verwenden Sie es, wenn Sie die Code‑Struktur überprüfen oder ändern, damit ein Code‑Base leichter zu verstehen, zu ändern, zu testen oder zu löschen ist — auch dann, wenn der Nutzer keine strukturelle Fachsprache verwendet, z. B. „Diese Datei macht zu viel“, „Das ist schwer zu testen“, „Ich bearbeite immer wieder das Gleiche an vielen Stellen“ oder „Das ist ein Chaos“. Beinhaltet Modulgrenzen, Aufteilung von Dateien, öffentliche APIs/Exports, Abhängigkeitsrichtung, Kopplung / Kohäsion, flache Schichten, Über‑Abstraktion, duplizierte strukturelle Entscheidungen, schwer zu testende Handler/Komponenten, verstreutes Fehlermapping und Refactorings, die Code über Module hinweg verschieben. Nicht verwenden für gewöhnliche Bug‑Fixes, Formatierung, reine Namensbereinigungen oder lokale Änderungen, die die Struktur nicht betreffen.
