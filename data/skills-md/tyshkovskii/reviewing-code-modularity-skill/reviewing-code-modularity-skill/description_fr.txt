Utilisez-le lors de la révision ou de la modification de la structure du code afin que la base de code soit plus facile à comprendre, à modifier, à tester ou à supprimer — y compris lorsque l'utilisateur n'utilise aucun vocabulaire structurel, par exemple « ce fichier fait trop de choses », « c’est difficile à tester », « je continue de modifier la même chose à plusieurs endroits » ou « c’est un désordre ». Couvre les limites des modules, la division des fichiers, les API/exportations publiques, la direction des dépendances, le couplage/la cohésion, les couches superficielles, la sur‑abstraction, les décisions structurelles dupliquées, les gestionnaires/composants difficiles à tester, la cartographie d’erreurs dispersée, et les refactorisations qui déplacent du code entre modules. Ne l’utilisez pas pour des corrections de bugs ordinaires, le formatage, le nettoyage uniquement de noms, ou les modifications locales qui n’affectent pas la structure.

Veuillez toujours répondre dans la langue de l'utilisateur.
