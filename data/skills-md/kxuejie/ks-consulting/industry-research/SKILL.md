# 行业研究

从某项产品或服务的商业链条出发，理解行业如何运作、如何变化，以及其中的企业如何赚钱和竞争。三维骨架来自战略咨询基本功第一课，细分方法来自第1—6课，表达方法衔接第10课与行业研究直播课。

默认读者完全不熟悉行业。每个关键分析单元先给一句“数据代表什么”的观点判断，再给事实依据、通俗机制解释及必要边界。正文首次出现的重要术语就地解释，报告最后固定附“行业术语解释”。

## 框架执行约定

`references/framework.md` 是本 skill 的必读方法正文，与 `SKILL.md` 一起执行，不是可选背景资料。主文件保留以下固定骨架，方法细节只在 reference 中维护。

| 一级维度与顺序 | 二级板块 |
| --- | --- |
| 1. 空间 行业全景图 | S1 流程与产业链；S2 价值流动与参与方关系 |
| 2. 时间 行业演进规律 | T1 规模与驱动；T2 行业周期；T3 外部变量 PEST |
| 3. 深度 板块与公司运作 | D1 竞争环境；D2 商业模式；D3 单一公司理解（按需） |

- 建立分析大纲前，完整读取 framework.md 的方法正文及“逐板块覆盖检查”，不能只读前三维标题或凭之前的摘要执行。若工具输出被截断，继续读取剩余部分。当前任务已完整读取且内容仍在上下文中时无需重复读取；上下文压缩后细节不再可见时重读。
- 默认报告保留一级维度的顺序和 S1—D2 七个必需板块。可以使用贴合行业的副标题、调整公式和细节篇幅，补充分析应放回相应板块。外部研报目录和其他通用框架不能替换这套结构。
- 用户明确要求缩小范围时遵循其要求，并在底稿记录省略项和范围依据。“简短”或“快速”通常缩短各板块论证，不自动删除整个板块。D3 根据是否需要具体公司研究决定。
- 缺少数据时保留对应问题，说明已知证据、可支持的判断及缺口；不能用泛泛段落假装完成，也不能为满足覆盖而编造内容。
- 开始时建立板块到研究问题的对应关系，交付前按 reference 的检查表逐项核对正文位置与实际分析。只有标题出现不算覆盖。详细方法以 reference 为准；输出模板负责呈现，不能因版面省掉方法要求。
- 生成正文前完整读取 [论证与表达](references/reasoning-and-writing.md)，与研究框架一起执行。框架决定分析什么及如何推导，表达规范决定如何让新手理解；完整读取后无需在同一上下文反复加载。

## 输入与默认行为

行业名称是唯一必需输入；用户可补充地区、研究用途、截止日期、重点环节或公司、参考报告、输出格式和目录。已有信息直接沿用。

- 仅给行业名称时，按完整三维报告执行。地区能从上下文判断就沿用，否则采用中国市场、全球背景，在开头说明此假设；全球性行业按其实际交易和竞争边界研究。
- 行业过宽时先明确纳入哪些产品与子行业，保留全景、选择关键环节深入；只有同名歧义会实质改变研究对象时才追问。
- 默认 HTML；指定 Word 则输出 `.docx`；“都要”则生成两份内容一致的报告。保存到用户指定目录，否则使用当前工作目录下 `行业研究输出/行业名/`。文件名使用本机日期，避免覆盖已有版本。
- 默认三维齐全，详略服务于研究问题；“快速了解”可以以空间为主、简述其余板块；明确只研究空间时才省略其他维度。公司深挖则增加单一公司分析。研究深度与文件格式互不绑定。
- 简要告知研究边界和执行安排后开始工作，无需逐次等待大纲、资料或格式确认。用户要求分步确认时遵循其要求。

## 执行

### 1. 先建立分析骨架

按“框架执行约定”完整读取 [研究框架](references/framework.md)，先识别产品/服务、使用者、购买者、付费者和基本流程，再按 S1—D3 列出本次需要回答的问题，注明 D3 是否适用。整理每个问题所需的证据，已有材料用于回答问题，不用参考报告的目录替代自己的框架。若 reference 无法读取，先定位并恢复文件；仍不可用时说明框架缺失，不将自行补写的大纲称为已遵循本框架。

### 2. 获取与核对证据

仅输入行业时使用当前环境可用的联网搜索和网页读取工具。有参考报告时先提取相关事实和页码，再检索缺失或需要更新的证据；PDF扫描页和图表需要视觉核对。用户限制联网时仅使用允许的材料，并写清资料截止日期。

优先官方统计、监管机构、行业协会、企业年报与公告；研究机构作为补充，媒体线索尽量追溯原始出处。检索年份根据研究截止日期确定，不固定某几个年份。

关键数字记录指标口径、地区、时间、单位、来源标题、链接或本地文件及页码。区分公布事实、来源观点、分析推算、情景假设和待核实信息。引用放在相关段落或表格旁，文末附完整来源。

同口径数据冲突时比较定义、样本、统计期和原始程度，不直接取平均。估算展示公式与假设；找不到数据时说明缺口及对判断的影响。若无法联网，可完成基于已有资料的有限研究，但不能把记忆或估算包装成最新实测数据。

### 3. 完成三维推导

按框架逐一回答问题，并把关键结论串起来：哪个变量变化 → 影响哪个环节的量、价、成本或议价权 → 哪类企业受益或承压 → 对研究用途有什么启示。每个关系都解释机制，不能只用“因此”连接结果。

S1 可以直接整理可靠资料中的产业链，不要求从产品形态重新推导。S2 围绕“哪些环节更能获得利润、为什么”展开：给出地位高低的判断，用通俗原因说明关键技术、资源、品牌、渠道等怎样帮助它留下利润；不要求逐一审查替代方案或量化换厂成本。

默认正文包含产业链与价值关系、规模模型与增长驱动、周期证据、PEST传导、重点环节竞争格局与商业模式。单一公司深挖按需增加。行业周期和集中度都是证据的一部分，不能机械推出利润率或成功策略。

按 [论证与表达](references/reasoning-and-writing.md) 形成统一 Markdown 研究底稿，保留完整论证、表格、来源与不确定性。小节和图表先给观点，再给事实和机制；每个维度结束回答一个行业问题，综合洞察串起主线。收集正文中的术语，首次使用就地解释，并在报告末尾形成完整词条。

### 4. 生成所选报告

读取 [报告结构与输出](references/output.md)。

- HTML 使用随附 [HTML 模板](assets/industry-report-template.html)，延续已有 Case 报告的纸张背景、蓝紫层级和侧边目录。将完整研究内容转换成正文，不重新缩写。
- Word 采用同一底稿，按输出规范组织为可编辑的正式长报告；可用随附 `scripts/build_word.py` 从结构化内容生成。当前环境有文档专用 skill 时，按其要求生成并做排版验收。
- 两种都要时复用相同结论、数字、口径、表格和来源；格式转换不发起第二次独立研究。

### 5. 验收与交付

- 按 framework.md 的“逐板块覆盖检查”核对 S1—D3，将底稿中的核对表补全为正文位置、证据/推导和覆盖状态；遗漏的必需分析先补齐，资料不足则明确标注。深度是否落在具体环节，而非企业名称罗列。
- 公式单位是否一致，存量/流量、销量/收入、GMV/营收、整体市场/公司份额是否区分。
- 结论是否能追溯证据，预测是否明确假设和成立条件。
- S2、T2、D1、D2 的关键判断是否讲明“为什么”；是否完成小节观点 → 维度结论 → 全篇主线的连读检查；行业新手能否看懂关键技术、流程和指标。
- HTML和Word是否都以“行业术语解释”为最后一章，正文就地解释、机制段、比较依据和限制说明是否完整转入。格式完成不等于论证完成。
- HTML 目录、桌面/手机布局与打印是否可用；Word 标题层级、表格分页、中文字体和链接是否完整。渲染不可用时如实报告验证范围。
- 交付所选格式的绝对路径链接，简述主要发现和影响结论的重要缺口。研究底稿保留供更新，不默认扩展为营销内容或投资建议。

## 调用示例

- “研究宠物食品行业。” → 默认三维分析 + HTML。
- “帮我研究工业软件，全球市场，要Word报告。” → 全球边界 + Word。
- “用这几份报告研究医药行业，重点看创新药，两种格式都要。” → 全景 + 创新药环节深挖，共用底稿输出 HTML 和 Word。
