기존 에이전트가 사용하는 MCP 서버들을 redis‑iris를 이용한 하나의 Redis Iris Context Gateway 뒤에 두어, 에이전트가 각 서버와 비밀을 설정하는 대신 하나의 에이전트 키로 하나의 MCP 엔드포인트에 연결하도록 합니다. Gateway가 Redis Cloud에 있는지 자체 관리인지 물은 뒤, 다섯 가지 질문을 합니다(현재 에이전트가 가지고 있는 MCP 서버와 비밀은 무엇인지, 몇 개의 도구를 인식하고 있는지, 읽기 전용 도구 중 캐시될 수 있는 것은 어떤 것인지, 대용량 결과를 반환하는 도구는 무엇인지, 프레임워크 자체가 MCP를 지원하는지 여부). 자체 관리인 경우, 터미널에서 `iris context-gateway` 명령으로 Gateway와 그 업스트림을 프로비저닝하고 캐시 및 압축 정책을 설정합니다. Redis Cloud에서는 개발자가 콘솔에서 이를 생성합니다. 그 후, 어떤 프레임워크든 에이전트를 Gateway에 지정하고 `tools list`와 `tools call`로 확인합니다. 에이전트가 여러 MCP 서버를 하나씩 설정하고 서버당 하나의 비밀을 보유하거나, 프롬프트에 너무 많은 도구 스키마를 로드하는 경우, 또는 사용자가 Context Gateway, 하나의 MCP 엔드포인트, 도구 캐시, 결과 핸들 등을 요구할 때 사용합니다.
