既存エージェントが使用する MCP サーバーを redis-iris を使って 1 つの Redis Iris Context Gateway の背後に置き、各サーバーとシークレットを個別に設定する代わりに、エージェントは 1 つのエージェントキーで 1 つの MCP エンドポイントに接続します。Gateway が Redis Cloud 上かセルフマネージドかを確認し、続いて 5 つの質問を行います（現在エージェントが持っている MCP サーバーとシークレットは何か、ツールは何個認識しているか、どの読み取り専用ツールがキャッシュ可能か、どのツールが大きな結果を返すか、フレームワーク自体が MCP と通信できるか）。セルフマネージドの場合、ターミナルで `iris context-gateway` を使って Gateway とその Upstream をプロビジョニングし、キャッシュおよび圧縮ポリシーを設定します。Redis Cloud では、開発者がコンソール上でそれらを作成します。その後、任意のフレームワークでエージェントを Gateway に向けさせ、`tools list` と `tools call` で動作を確認します。エージェントが複数の MCP サーバーを個別に設定し、サーバーごとにシークレットを保持し、プロンプトに過剰なツールスキーマをロードしている場合、またはユーザーが Context Gateway、単一の MCP エンドポイント、ツールのキャッシュ、結果ハンドルを求めた場合に使用します。
