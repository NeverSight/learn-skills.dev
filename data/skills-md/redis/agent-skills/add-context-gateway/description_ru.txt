Разместите MCP‑серверы, которые использует существующий агент, за одним Redis Iris Context Gateway с помощью redis‑iris, чтобы агент подключался к одному MCP‑конечному пункту одним ключом агента вместо настройки каждого сервера и его секрета. Спрашивает, находится ли шлюз в Redis Cloud или управляется самостоятельно, затем задаёт пять вопросов (какие MCP‑серверы и секреты есть у агента сейчас, сколько инструментов он видит, какие инструменты только для чтения можно кэшировать, какие инструменты возвращают большие результаты, поддерживает ли фреймворк MCP напрямую). При самостоятельном управлении шлюз и его upstream‑ы создаются из терминала с помощью `iris context-gateway` и задаются политики кэширования и сжатия. В Redis Cloud разработчик создаёт их в консоли. Затем агент направляется к шлюзу в любой системе и проверяется командами `tools list` и `tools call`. Используйте, когда агент конфигурирует несколько MCP‑серверов по отдельности, хранит по одному секрету на сервер, загружает слишком много схем инструментов в запрос, или пользователь запрашивает Context Gateway, один MCP‑конечный пункт, кэширование инструментов или обработку результатов.
