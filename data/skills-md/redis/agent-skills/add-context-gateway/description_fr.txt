Placez les serveurs MCP qu’un agent existant utilise derrière un seul Redis Iris Context Gateway avec redis-iris, de sorte que l’agent se connecte à un point de terminaison MCP unique avec une clé d’agent au lieu de configurer chaque serveur et son secret. Demandez si le Gateway se trouve dans Redis Cloud ou en auto‑gestion, puis posez cinq questions (quels serveurs MCP et quels secrets l’agent possède aujourd’hui, combien d’outils il voit, quels outils en lecture seule peuvent être mis en cache, quels outils renvoient de gros résultats, si le framework parle MCP lui‑même). En auto‑gestion, il provisionne le Gateway et ses Upstreams depuis le terminal avec `iris context-gateway` et définit les politiques de cache et de compression. Dans Redis Cloud, le développeur les crée dans la console. Ensuite, il pointe l’agent vers le Gateway dans n’importe quel framework et le vérifie avec `tools list` et `tools call`. À utiliser lorsque l’agent configure plusieurs serveurs MCP un par un, porte un secret par serveur, surcharge l’invite avec trop de schémas d’outils, ou que l’utilisateur demande un Context Gateway, un point de terminaison MCP unique, la mise en cache des outils ou des handles de résultats.
