Setze die MCP-Server, die ein bestehender Agent nutzt, hinter ein Redis Iris Context Gateway mit redis-iris, sodass der Agent sich mit einem einzigen MCP-Endpunkt und einem Agentenschlüssel verbindet, anstatt jeden Server und sein Geheimnis zu konfigurieren. Frage, ob das Gateway in Redis Cloud oder selbst verwaltet ist, und stelle dann fünf Fragen (welche MCP-Server und Geheimnisse der Agent heute hat, wie viele Tools er sieht, welche schreibgeschützten Tools gecached werden dürfen, welche Tools große Ergebnisse zurückgeben, ob das Framework selbst MCP spricht). Bei selbst verwalteter Umgebung wird das Gateway und seine Upstreams über das Terminal mit `iris context-gateway` bereitgestellt und Cache‑ sowie Kompressionsrichtlinien gesetzt. In Redis Cloud erstellt der Entwickler sie in der Konsole. Anschließend wird der Agent in jedem Framework auf das Gateway ausgerichtet und mit `tools list` und `tools call` verifiziert. Verwenden, wenn der Agent mehrere MCP-Server einzeln konfiguriert, pro Server ein Geheimnis trägt, zu viele Tool‑Schemata in die Eingabe lädt oder der Nutzer nach Context Gateway, einem MCP-Endpunkt, Tool‑Caching oder Ergebnis‑Handles fragt.
