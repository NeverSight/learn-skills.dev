Il flusso di lavoro personale, Git e le regole di progettazione di Sawyer. Applicare ogni volta che si scrive, si rivede o si esegue il refactoring del codice; eseguire comandi git o generare commit; o iniziare qualsiasi attività non banale. Applica "mai git push", coautore solo su approvazione, ponendo da 1 a 5 domande chiarificatrici prima del lavoro, progettazione OOP DRY/modulare, suggerimenti di tipo completo e stringhe di documentazione e codice pulito e verboso. Si abbina all'abilità di stile di codifica per convenzioni specifiche della lingua.
