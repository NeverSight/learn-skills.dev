Личный рабочий процесс Сойера, Git и инженерные правила. Применяйте при написании, проверке или рефакторинге кода; запуск команд git или создание коммитов; или запуск какой-либо нетривиальной задачи. Обеспечивает принцип «никогда не git push», соавторство только после утверждения, задание 1–5 уточняющих вопросов перед работой, DRY/модульный ООП-дизайн, полные подсказки и строки документации, а также чистый, а не многословный код. Сочетается с навыками программирования для соблюдения соглашений, специфичных для языка.
