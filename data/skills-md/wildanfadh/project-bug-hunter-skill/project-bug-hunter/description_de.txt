Verwenden Sie diese Fähigkeit immer dann, wenn der Benutzer nach Bugs sucht, ein Projekt auditieren, Code auf Defekte überprüfen, das aktuell geöffnete Verzeichnis scannen, versteckte Fehler untersuchen, ein Projekt vor dem Deployment vorbereiten oder prüfen möchte, warum ein Projekt fehlschlagen könnte. Diese Fähigkeit dient dem breiten Bug‑Hunting im aktuellen Arbeitsverzeichnis und sollte bei Phrasen wie „cari bug di project ini“, „cek project ini“, „audit bug“, „review kode“, „temukan error tersembunyi“, „scan direktori sekarang“, „check this repo for bugs“ oder ähnlichen Anfragen ausgelöst werden, selbst wenn der Benutzer keine Sprache/Framework angibt. Sie erstellt zunächst einen evidenzbasierten Bug‑Report und darf Dateien nur dann ändern, wenn der Benutzer ausdrücklich um eine Korrektur bittet.

Bitte immer in der Sprache des Benutzers antworten.
