Migrar un proyecto existente que fue creado para otro host (Vercel, un servidor Node, un contenedor Docker, una pila docker‑compose) a Railcode. Úselo cuando el usuario tiene una aplicación funcional y desea ejecutarla en Railcode, incluyendo una app Next.js o un backend contenedorizado en cualquier lenguaje. Cubre tomar inventario de las dependencias del proyecto, mapear cada dependencia a un primitivo de Railcode, reconstruir las piezas que no tienen equivalente directo de otra manera, portar, probar con railcode dev, mantener o conectar la base de datos existente del proyecto (Postgres u otra) y dónde se ejecutan las migraciones de esquema, desplegar junto al original y reportar lo que Railcode aún no puede alojar. No lo use para una nueva app a partir de una idea, ni para mover una app Railcode v1 a apps v2 — ambas pertenecen a create‑railcode‑app.
