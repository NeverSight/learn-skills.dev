複数リポジトリにわたる GitHub Actions の `schedule` cron 式の概要を作成し、CPU 集中的なジョブ（Docker Compose、Testcontainers、Kind/k3s、マトリックスビルド）を競合の少ないスロットに分散させるのに役立ちます。ユーザーが「cron アクションはいつ実行されるのか？」や「スケジュールされたビルドは衝突しているか？」、「Testcontainers のビルドはいつ走らせるべきか？」と尋ねたり、リポジトリ全体の cron スケジュールの概要や分布レポートが欲しい場合に使用します。`gh` を使ってスキャン（ローカルのチェックアウトは不要）またはローカルのチェックアウトでも実行でき、UTC をローカルタイムゾーンに変換し、ジョブの負荷を分類し、時間別ヒストグラム、衝突、具体的な cron 再配布提案を含む Markdown レポートを作成します。
