# Goodcase UI

이 스킬은 재사용 자료를 포함한 배포본이다. Goodcase 원본 프로젝트 경로나 GitHub 접근 없이 사용한다. 아래 경로는 모두 **이 SKILL.md가 있는 폴더 기준**이다. 현재 작업 디렉터리를 기준으로 찾지 않는다.

## 자료 선택

1. 대상 프로젝트의 기술 스택, 디자인 토큰, 같은 책임의 공용 컴포넌트를 확인한다. 기존 컴포넌트로 해결할 수 있으면 그 구현을 확장한다.
2. [컴포넌트 목록](references/components.json)에서 필요한 항목을 선택하고 해당 `reference` 문서만 읽는다. 문서에는 동작 계약, 상태, 키보드 조작, 예제, 포함 코드와 외부 의존성이 있다.
3. 개별 문서의 ‘코드 위치’에 있는 파일과 행 위치를 이용해 필요한 export부터 읽는다. 구현은 컴포넌트별 파일로 나뉘고 index는 재수출을 담당한다. 개별 구현과 문서의 ‘포함 코드와 공유 스타일’에 나오는 직접 의존성을 함께 가져온다. 전체 자료를 먼저 읽지 않는다.

## 적용

- 디자인을 적용할 때 [디자인 원칙](references/design.md)과 [이식 지침](references/integration.md)을 읽는다.
- Goodcase 스타일을 요청하면 동봉된 참조 테마를 적용한다. 대상의 브랜드나 디자인이 이미 있거나 유지 요청이 있으면 `--gc-*` 토큰을 대상 프로젝트의 의미 토큰에 연결한다. 색상·글꼴·간격·모서리·밀도는 조정할 수 있다.
- React + TypeScript 프로젝트에는 `assets/src/`의 필요한 코드와 스타일을 복사하거나 기존 공용 구현에 통합한다. 목록의 `files`는 직접 관련 파일이다. 개별 문서의 ‘포함 코드와 공유 스타일’에는 상대 import와 공유 스타일까지 포함한 파일 목록이 있다. 경로 구조를 유지하면 상대 import를 보존할 수 있다.
- 다른 프레임워크에서는 참조 디자인과 동작 계약을 재구현한다. 동봉 React 코드를 그대로 실행할 수 있다고 설명하지 않는다.
- 갤러리와 로컬 데모는 포함되지 않는다. 예제의 데이터·상태·callback은 대상 프로젝트에서 제공하고 실제 API·라우터·업로드 서비스에 연결한다. 비동기 시뮬레이션을 만드는 경우 화면에 로컬 시뮬레이션임을 표시한다.
- 선택 확정, Escape 취소, 포커스 복귀, 중복 실행 차단, 실패 후 재시도 등 선택한 컴포넌트의 계약을 유지한다. 사용자 요구로 계약을 변경하면 대상 프로젝트의 설명과 검증도 함께 맞춘다.

## 확인과 보고

대상 프로젝트의 빌드·타입 검사를 실행하고 해당 계약의 마우스·키보드·터치 동작, 좁은 화면, 긴 텍스트, 오류·재시도를 실제 화면에서 확인한다. 수행하지 못한 확인은 구분해 보고한다. 적용한 컴포넌트, 디자인 변경, 확인한 동작과 배포본 `manifest.json`의 버전·내용 해시를 기록한다. 원본이 없는 환경에서 최신 여부를 추정하거나 자동으로 원격 코드를 내려받지 않는다.
