أنشئ، راجع وأدر دورة حياة المواصفات (`SPEC NN`) لميزة قبل كتابة سطر واحد من الشيفرة — المرحلة المتعمدة البطيئة في تدفق التصميم القائم على المواصفات. اطرح أسئلة سقراطية لملء كل قسم من `templates/SPEC.template.md` (السياق، الأهداف، غير الأهداف، الاعتمادات، المتطلبات الوظيفية، الواجهات والعقود، المتطلبات غير الوظيفية، حالات الحافة، معايير القبول، المخاطر، الأسئلة المفتوحة)، عيّن الرقم `NN` تسلسليًا، تحقق من مراجع `Depends on:`، وتولى التحكم في انتقالات الحالة من مسودة → تحت المراجعة → موافق عليها → منفذة → مهجورة (أو ما يعادلها بالإسبانية — Borrador → En revisión → Aprobado → Implementado → Obsoleto). استخدم هذه المهارة عندما يطلب المستخدم "escribamos el spec de..."، "necesito un spec para..."، "let's spec out..."، "write a spec for..."، "manda este spec a revisión"، "apruebo el SPEC 04"، "approve SPEC 04"، "¿qué dice el SPEC 02?"، "este spec quedó obsoleto"، أو يذكر صراحةً `specs/SPEC-NN`. لا تكتب أبدًا كود تطبيق ولا تبدأ تنفيذًا — فهذا عمل **bambu-spec-implement**، الذي يبدأ فقط عندما تصل المواصفة المقابلة إلى حالة Approved.
