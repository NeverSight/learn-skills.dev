Crea, rivedi e gestisci il ciclo di vita degli spec (`SPEC NN`) per una feature prima che venga scritta una sola riga di codice — la fase deliberatamente lenta di un flusso di design guidato dagli spec. Fa domande socratiche per riempire ogni sezione di `templates/SPEC.template.md` (contesto, goals, non-goals, dipendenze, requisiti funzionali, interfacce e contratti, requisiti non funzionali, edge cases, criteri di accettazione, rischi, domande aperte), assegna il numero `NN` sequenziale, valida i riferimenti `Depends on:`, e controlla le transizioni di stato Draft → In review → Approved → Implemented → Obsolete (oppure i loro equivalenti in italiano — Bozza → In revisione → Approvato → Implementato → Obsoleto). Usa questa skill quando l'utente chiede "escriviamo lo spec di...", "ho bisogno di uno spec per...", "let's spec out...", "write a spec for...", "manda questo spec a revisione", "approvo il SPEC 04", "approve SPEC 04", "cosa dice il SPEC 02?", "questo spec è diventato obsoleto", o menziona esplicitamente `specs/SPEC-NN`. Non scrive mai codice applicativo né avvia un'implementazione — quello è il compito di **bambu-spec-implement**, che parte solo quando lo spec corrispondente raggiunge Approved.

Rispondi sempre nella lingua dell'utente.
