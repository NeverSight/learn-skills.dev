Создавайте, проверяйте и управляйте жизненным циклом спецификаций (`SPEC NN`) для функции до того, как будет написана хотя бы одна строка кода — преднамеренно медленная фаза потока, основанного на спецификациях. Задавайте сократические вопросы, чтобы заполнить каждый раздел `templates/SPEC.template.md` (контекст, цели, не‑цели, зависимости, функциональные требования, интерфейсы и контракты, нефункциональные требования, крайние случаи, критерии приёмки, риски, открытые вопросы), назначайте последовательный номер `NN`, проверяйте ссылки `Depends on:` и контролируйте переходы состояний Draft → In review → Approved → Implemented → Obsolete (или их эквиваленты на испанском — Borrador → En revisión → Aprobado → Implementado → Obsoleto). Используйте этот навык, когда пользователь просит «escribamos el spec de…», «necesito un spec para…», «let's spec out…», «write a spec for…», «manda este spec a revisión», «apruebo el SPEC 04», «approve SPEC 04», «¿qué dice el SPEC 02?», «este spec quedó obsoleto» или явно упоминает `specs/SPEC-NN`. Никогда не пишите прикладной код и не начинайте реализацию — это задача **bambu-spec-implement**, которая запускается только после того, как соответствующая спецификация перейдёт в статус Approved.
