하나의 코드 한 줄도 작성하기 전에 기능에 대한 스펙(`SPEC NN`)을 생성·검토·관리합니다 — spec‑driven design 흐름의 의도적으로 느린 단계입니다. `templates/SPEC.template.md`의 각 섹션(컨텍스트, 목표, 비목표, 종속성, 기능 요구사항, 인터페이스 및 계약, 비기능 요구사항, 엣지 케이스, 수용 기준, 위험, 열린 질문)을 채우기 위해 소크라테스식 질문을 합니다. 순차적인 번호 `NN`을 할당하고, `Depends on:` 참조를 검증하며, 상태 전환 Draft → In review → Approved → Implemented → Obsolete(또는 스페인어 등가어 — Borrador → En revisión → Aprobado → Implementado → Obsoleto)를 제어합니다. 사용자가 “escribamos el spec de…”, “necesito un spec para…”, “let's spec out…”, “write a spec for…”, “manda este spec a revisión”, “apruebo el SPEC 04”, “approve SPEC 04”, “¿qué dice el SPEC 02?”, “este spec quedó obsoleto” 등이라고 요청하거나 `specs/SPEC‑NN`을 명시적으로 언급할 때 이 스킬을 사용합니다. 애플리케이션 코드를 작성하거나 구현을 시작하지 않습니다 — 이는 **bambu‑spec‑implement**의 작업이며, 해당 스펙이 Approved 상태가 된 뒤에만 시작됩니다.
