在尚未寫下一行程式碼之前，為功能建立、檢閱並管理 spec（`SPEC NN`）的生命週期——即 spec‑driven 設計流程中刻意緩慢的階段。透過蘇格拉底式提問，填寫 `templates/SPEC.template.md` 的每個章節（context、goals、non-goals、dependencias、功能需求、介面與合約、非功能需求、edge cases、驗收標準、風險、未解決問題），依序指派編號 `NN`，驗證 `Depends on:` 參照，並控制狀態轉換 Draft → In review → Approved → Implemented → Obsolete（或其西班牙文等價 Borrador → En revisión → Aprobado → Implementado → Obsoleto）。當使用者提出「escribamos el spec de…」、「necesito un spec para…」、「let's spec out…」、「write a spec for…」、「manda este spec a revisión」、「apruebo el SPEC 04」、「approve SPEC 04」、「¿qué dice el SPEC 02?」、「este spec quedó obsoleto」或明確提到 `specs/SPEC-NN` 時，使用此技能。絕不編寫應用程式碼或啟動實作——那是 **bambu-spec-implement** 的工作，僅在相應的 spec 達到 Approved 後才會開始。
