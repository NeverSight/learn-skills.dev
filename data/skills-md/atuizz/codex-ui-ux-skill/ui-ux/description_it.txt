Utilizzare come cancello di qualità UI/UX per il lavoro frontend che influisce materialmente sulle superfici dei prodotti web: progettazione/creazione/riprogettazione/revisione/lucidatura/refactoring di pagine o sistemi di componenti, critiche a screenshot/UX, salvataggio di UI dall'aspetto GPT/Codex, scelte di stack o di base dell'interfaccia utente, modelli shadcn/Tailwind/tabella/modulo, caricamento/vuoto/errore/mobile/stati di accessibilità o installazione di documenti di governance frontend come DESIGN.md, FRONTEND_CONTRACT.md, PAGE_BRIEF.md e norme relative al QA visivo. Attiva leggermente per piccole modifiche sensibili all'interfaccia utente utilizzando il cancello di modifica Tiny. Coordinarsi con le capacità di implementazione visiva quando viene richiesto di creare un'interfaccia raffinata; questa abilità fornisce cognizione del prodotto, giudizio UX, guardrail e verifica. Salta per modifiche pure al backend/API/dati/modello, test senza superficie dell'interfaccia utente, ridenominazioni meccaniche, attività di dipendenza o modifiche che non influiscono su layout, interazione, copia, comportamento visivo, accessibilità o regole del frontend.
