# Meishe Android Streaming SDK API

Use this skill to generate Android applications or patches that control Meishe Android Streaming SDK at API level. The bundled references are self-contained; do not use the original `SdkDemo` or `doxygen` folders as normal knowledge dependencies.

## Priority Rules

- When bundled official docs and demo-derived evidence conflict, follow the Demo for Android SDK 3.16.1.25 integration, call order, Gradle/Manifest wiring, state guards, permissions, and version-proven behavior. Use official docs for API semantics, parameters, limitations, and errors where they do not conflict.
- Keep `NvsStreamingContext` public APIs on the Android UI thread except `NvsVideoFrameRetriever.getFrameAtTime()`. Keep `NvsEffectSdkContext` public APIs on the UI thread and `NvsEffectRenderCore.initialize()`, `render()`, and other public APIs on the OpenGL thread that owns the GL context.
- Treat generated projects as runnable skeletons until the required proprietary license, AAR/JAR, native `.so`, models, media, and asset packages are present. Resolve only authorized external files; never invent credentials, licenses, private service addresses, or material APIs.
- The skill contains no material binaries. Before generating features that rely on materials, tell the user to obtain authorized resources from Meishe business. In this repository use `temp_assets/android-sample-assets`; elsewhere accept `--sample-assets-dir <bundle-root>` or generate an explicitly clean shell with `--no-sample-assets`.
- Do not infer `runtime_verified` from generation, compilation, Demo evidence, related APIs, or `partial` runs. Read `references/runtime-verification-matrix.json` and claim only the exact recorded device, SDK, resource, module, unit, API, and flow scope.
- Do not infer a visible AR/face result from model initialization, package installation, setter success, id readback, or a nonzero face callback. Use `references/ar-face-runtime-troubleshooting.md` and require physical-preview visual evidence; lack of a production license may mean trial/watermark behavior rather than a rendering block unless an explicit license API/error proves otherwise.
- For project creation or integration, tell the user that Gradle is handed back by default and provide one filled copy-paste build block after implementation. Do not execute Gradle by default; run it only when the user explicitly requests automatic execution.
- APK installation, device driving, UI-tree capture, screenshots, and screenshot analysis are optional. Recommend automatic physical-device screenshot analysis, disclose its added time and token cost, and accept manual validation. When the user explicitly opts in, warn once, batch changes, build only the final target, and keep evidence concise.

## Independence And Resource Boundary

- Normal lookup, composition, and generation do not require the original Demo or Doxygen folder. Only maintenance tools such as `scripts/extract_demo_simple_code.py --demo-root <SdkDemo>` may read external Demo/Doxygen sources.
- A user-provided official Android package root is an optional resource source, not a Skill knowledge dependency. Resolve it through the relative-path map; never retain the user's absolute extraction path.
- Generated apps still require authorized SDK/runtime artifacts and selected models/materials. Obtain Android LTS face resources from the official download route in `references/official-sdk-download-resources.md`; production application/package licenses and online material interfaces remain Meishe business questions.
- Do not copy full Demo source/assets, large unselected models, signing configs, analytics keys, FTP tasks, interface keys, release distribution settings, or private package names.

## Project Structure Rules

- Require explicit `MeisheTimelineOwnership` for incremental editors. `EDITOR_OWNED` may rebuild/remove its Timeline; `HOST_OWNED` must preserve host objects, must not call `removeTimeline`, and denies structural/editor rebuild unless `MeisheEditorHostContract` explicitly opts in.
- Treat incremental apply as a preflighted transaction. Identical files are idempotent no-ops; any differing host file stops before source, Manifest, or Gradle mutation. `--force` may refresh staging but never overwrites conflicting host source.
- Keep Timeline resolution, the visible LiveWindow container ratio, and `NvsLiveWindow.FILLMODE_PRESERVEASPECTFIT` consistent. A Trim action must choose a valid point inside the clip, convert Timeline time to source time, verify the SDK result, persist, and refresh.
- Read `references/project-structure-rules.md` for the remaining project structure, persistence, overlay, and editor-orchestration rules.

## Delivery Contract

- Before implementation, give the execution notice from `references/execution-and-qa-handoff.md` without blocking for a reply. After implementation, relay the generator's filled PowerShell or POSIX Gradle block when available; otherwise fill the real absolute project path, module, variant, failure exit handling, and APK lookup yourself. Do not leave `<project-path>`, `<module>`, or `<variant>` placeholders.
- Treat “create”, “integrate”, or “fix” as authorization to edit only the scoped project, not as consent to build, install, drive a device, or capture screenshots. Automatic execution begins only after an explicit request such as “自动执行”, “帮我构建并安装”, or an equivalent English instruction.
- When device QA is selected, install the final APK once, exercise a deterministic minimum flow, read the scoped crash buffer once, and capture only decision-relevant screenshots. Prefer assertions for Timeline/LiveWindow ratio, valid Trim, visible applied overlay, material apply/edit/delete, final-clip empty state, recording/export output, and requested AR action.
- Report exact evidence levels: generated, structurally validated, Java-compiled, Gradle-built, installed, flow-executed, and visually confirmed. Never collapse them into a single “verified” claim or generalize one SDK version, device, ABI, package, license mode, or subject condition to untested variants.

## Template Use

Read complete resource and generator recipes in `references/standalone-workflow.md`; inspect current flags with `scripts/create_android_project.py --help`.

Create a dependency-closed app from a blueprint and selected modules:

```powershell
python .\.codex\skills\meishe-android-streaming-sdk-api\scripts\create_android_project.py <output-dir> --package com.example.meisheapp --app-name 美摄创作台 --ui-language zh-CN --blueprint short-video-editor --modules caption-editor,sticker-editor,filter-editor,asset-center-service
```

Stage and inspect an additive patch for an existing Android app, then apply it explicitly:

```powershell
python .\.codex\skills\meishe-android-streaming-sdk-api\scripts\create_android_project.py <staging-dir> --mode incremental --host-project <host-project> --app-module app --package com.example.host.meishe --modules timeline-preview,caption-editor,capture-camera,asset-package-service,template-engine,export-compile
python .\.codex\skills\meishe-android-streaming-sdk-api\scripts\create_android_project.py <staging-dir> --mode incremental --host-project <host-project> --app-module app --package com.example.host.meishe --modules timeline-preview,caption-editor,capture-camera,asset-package-service,template-engine,export-compile --apply
```

Generate controllers plus a concrete API-level usage sample without an application shell:

```powershell
python .\.codex\skills\meishe-android-streaming-sdk-api\scripts\create_android_project.py <output-dir> --mode api-only --package com.example.host.meishe.api --modules timeline-preview,caption-editor,capture-camera,asset-package-service,template-engine,export-compile
```

Only apply optional overlays returned by `search_skill_index.py`/`compose_modules.py` or explicitly requested by the user. The nine blueprints are reference shells, not complete replicas of every Demo screen; host navigation and authorized runtime resources remain explicit inputs.
