Collectez un bundle de diagnostic local anonymisé (journaux, configuration, version, état) pour un transfert à un expert OpsMill. DÉCLENCHER lorsque : Infrahub est en panne/échoue/renvoie des erreurs, l'utilisateur demande de l'aide pour le débogage, souhaite collecter les journaux/diagnostics, prépare un transfert pour le support OpsMill, ou signale un crash/un délai d'attente/un problème de connexion (échec de mise à jour, branche bloquée, container CrashLoopBackOff, erreurs 500, OOM). NE PAS DÉCLENCHER lorsque : débogage d'un check, d'une transformation, d'un générateur, d'un menu ou d'un schéma dans le référentiel (utilisez les compétences infrahub-managing-*), un bundle a déjà été collecté et l'utilisateur veut qu'il soit analysé (utilisez infrahub-analyzing-diagnostics), dépôt d'une issue publique sur GitHub (utilisez infrahub-reporting-issues), exécution de requêtes opérationnelles (utilisez infrahub-analyzing-data), ou planification d'une mise à jour qui n'a pas encore été exécutée (utilisez infrahub-planning-upgrades).

Veuillez toujours répondre dans la langue de l'utilisateur.
